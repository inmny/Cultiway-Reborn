# 第0阶段-统一灵气与浊气入口

## 目标

先把现有天地灵气和浊气收拢到一个明确入口，再让灵脉接入。

当前 `WakanMap` 与 `DirtyWakanMap` 内容几乎相同，多处玩法直接修改二维数组，地图绘制还可能在另一个线程同时读取。若直接加入灵脉，供灵、修炼、潮汐、法宝和地图刷新会各自改变同一份数据，难以判断一次变化来自哪里。

本阶段不生成灵脉，但完成后现有灵气玩法仍可运行。

## 具体说明

### 建立世界灵气服务

在 `Source/Content` 中增加 `WorldWakanService`，由它持有当前世界的洁净灵气和浊气。

建议使用按格子编号排列的一维数组：

- `cleanByTile`：每格洁净灵气。
- `dirtyByTile`：每格浊气。
- `displayCleanByTile`：地图显示最近一次公布的洁净灵气。
- `displayDirtyByTile`：地图显示最近一次公布的浊气。
- `dirtyTileIds`：本轮发生变化、需要刷新地图的格子。
- 当前世界编号、地图宽高和是否已经初始化。

一维数组可以直接使用 `WorldTile.data.tile_id` 查询，也方便以后把一组变化格交给地图刷新。

完成迁移后删除 `WakanMap` 和 `DirtyWakanMap`，不保留旧入口或转发包装。

### 提供统一读写方法

建议最少提供以下方法：

| 方法 | 用途 |
| --- | --- |
| `InitializeWorld` | 清空旧世界，按新地图尺寸建立数组 |
| `ClearWorld` | 切换世界时释放全部数据 |
| `GetClean` | 读取某格洁净灵气 |
| `GetDirty` | 读取某格浊气 |
| `AddClean` | 增加洁净灵气并返回实际增加量 |
| `AddDirty` | 增加浊气并返回实际增加量 |
| `WithdrawClean` | 最多扣除指定洁净灵气并返回实际扣除量 |
| `WithdrawDirty` | 最多扣除指定浊气并返回实际扣除量 |
| `ScaleClean` | 潮汐等世界效果按比例改变某格灵气 |
| `PublishDisplayValues` | 把本轮结果公布给地图显示 |
| `CopyDirtyTileIds` | 返回本轮真正变化的格子编号 |
| `SumClean` / `AverageClean` | 世界灵气窗口使用的统计方法 |

所有写入都必须：

1. 把负数夹到零。
2. 应用统一上限，避免无穷大和无效数值。
3. 记录实际变化的格子。
4. 不直接刷新界面，由统一公布步骤批量刷新。

初始值从 `Tables/SpiritVein.csv` 的世界灵气设置读取：

- 洁净灵气背景值从 `10` 开始平衡。
- 浊气初始值为 `0`。

背景值和统一上限不散落在多个类中。后续阶段继续向同一张表增加灵脉规模、供灵和污染设置，不更换数据来源。

### 迁移现有灵气和浊气入口

以下现有代码必须改用统一服务：

| 文件或功能 | 当前行为 | 迁移结果 |
| --- | --- | --- |
| `CultivationResources` | 直接读取和扣除两个数组 | 使用 `Get` 与 `Withdraw` |
| `RestoreWakanSystem` | 自己计算并直接扣地块灵气 | 统一调用 `CultivationSettlementService.AbsorbAmbientWakan` |
| `CoreFormationEffectHandlers` | 法阵储灵直接扣数组 | 使用 `WithdrawClean` |
| `WorldBehs` | 潮汐直接乘算和加减数组 | 使用 `ScaleClean` 与 `AddClean` |
| `PatchActor` | 死亡直接增加浊气 | 使用 `AddDirty` |
| `SectResidencePlanner` | 直接读取数组 | 使用只读查询 |
| `MapModes` | 地图线程直接读取运行数组 | 读取地图显示值 |
| `WindowWorldWakan` | 分别访问两个单例 | 使用统一统计方法 |
| `WakanSpreadSystem` | 持有洁净灵气数组引用 | 通过服务完成一轮扩散 |
| `DirtyWakanSpreadSystem` | 持有浊气数组引用 | 通过服务完成一轮扩散并正式注册 |

迁移后搜索 `WakanMap.I.map` 和 `DirtyWakanMap.I.map` 应无结果。

`RestoreWakanSystem` 不再单独复制修炼结算公式。自然吸收与主动修炼都通过现有统一结算入口，确保地块只扣一次、角色只加一次。

### 整理扩散和潮汐顺序

扩散仍然负责把高值向邻格摊开，不负责创造或删除灵气。

建议运行顺序：

1. 世界来源增加灵气。
2. 自然吸收和主动修炼扣取灵气。
3. 洁净灵气扩散。
4. 浊气扩散。
5. 公布地图显示值。

本阶段先保留现有潮汐玩法，只把直接数组修改迁入服务。灵脉供灵完成后，再把潮汐调整为影响灵脉恢复和输出，避免长期保留随机格子凭空产灵的规则。

`DirtyWakanSpreadSystem` 当前没有加入运行系统，本阶段明确注册。洁净与浊气各自扩散，数值不会自动互相抵消。

扩散处理仍可以分散到多帧，但必须满足：

- 同一条相邻关系一轮只处理一次。
- 一次转移前后总量一致。
- 世界切换时立即停止。
- 不持有旧世界数组引用。

### 处理世界切换和地图显示

`WorldWakanService` 接入现有世界清理流程：

- 设置新地图尺寸时建立新数组。
- 地理生成期间可以读取背景值，但不能读取旧世界值。
- `MapBox.clearWorld` 时清空数组、变化格和显示数据。
- 世界编号不匹配时拒绝后台显示结果。

地图模式不直接读取正在变化的数组。模拟完成一轮后，把结果复制或交换到只读显示数组，再通知 `CustomMapModeManager`：

- 少量格子变化时只标记这些格子。
- 潮汐或首次初始化改变大范围时整图刷新。
- 切换世界时清空旧颜色。

这个显示边界同时供后续灵脉供灵和污染使用。

### 完成阶段检查

代码检查：

- 业务代码不再直接读写旧二维数组。
- `WakanMap` 和 `DirtyWakanMap` 已删除。
- 洁净灵气与浊气都有唯一读写入口。
- `DirtyWakanSpreadSystem` 已注册，或已被明确替代，不再是永远不运行的代码。
- 没有增加存档、迁移和兼容路径。

游戏内检查：

1. 新世界洁净灵气以低背景值开始，浊气从零开始。
2. 修士自然吸收后，角色所得与地块扣除一致。
3. 主动修炼、法阵储灵和死亡浊气仍然生效。
4. 灵气与浊气地图能及时更新。
5. 快速切换世界后没有旧世界数值或地图颜色残留。
6. 世界灵气窗口统计与地图实际数值一致。
