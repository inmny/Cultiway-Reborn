# 小世界-摘要

**版本**：v1.4
**状态**：纯内存设计基线
**最后更新**：2026 年 8 月 13 日
**当前范围**：共享领域核心、MainWorld/SubWorld 上下文适配器、会话内独立实例、原版 terrain 投影、实例时钟、参与者投影、typed item 值对象、主世界周边空间视图、底栏导航与常驻 Runtime 调度
**首个消费者**：[机缘道统](机缘道统-摘要.md)  
**明确不包含**：第二个原版 `MapBox`、完整文明模拟、复用原版 Actor/Building manager、自由地图编辑器、任意脚本热加载、跨世界联机、任何会话外状态

## 设计目的

小世界是 Cultiway 对同一套玩法领域能力提供的另一种世界上下文。每个实例拥有独立地图容器、时间、实体、事件、视觉和生命周期，不依赖原版 `World.world` 承载内部内容；terrain 直接使用原版 `TileTypeBase` 对象，技能定义、伤害公式、稳定物品身份与制造规则继续和主世界共享，不能在 SubWorld 下再造一套近似系统。

遗府、秘境、梦境、法宝内部、阵法空间等玩法只把主世界 Building 或 Actor 当作入口；进入后，参与者在可视化的小世界中真实移动、探索、战斗、取得物品并触发目标，而不是在主世界入口旁等待抽象计时条。

系统必须满足：

1. 小世界中的地形、单位、机关和奖励都是可观察的具体对象。
2. 每个实例可以选择自己的规则模块、时间比例和视觉主题。
3. 小世界按稳定槽位环绕排列在主世界地图四周，与主世界共用主相机；玩家可以连续拖动相机前往，也可以从底栏快速聚焦。
4. 主世界与小世界分别控制时间流速；底栏为当前聚焦实例提供局部暂停和倍速，不修改主世界全局倍速。
5. 主世界 Actor 不进入第二地图；小世界使用 Projection，进入与返回都在同一主线程边界内同步完成。
6. 小世界全部状态只属于当前游戏会话；切换世界、返回主菜单或 Mod 重载时统一销毁。
7. 多个实例可以并存并全部常驻内存；逻辑调度只区分 `Active` 与 `Warm`，视图是否与相机相交是独立状态。
8. 同一实例是否与主相机视野相交不能改变逻辑结果，只改变渲染和获得 CPU 时间片的时机；同一帧允许多个实例可见。
9. MainWorld 与 SubWorld 对相同输入必须使用同一领域定义和公式；差异只能来自明确的世界上下文能力与规则参数。

## 原版约束结论

不能通过创建第二个 `MapBox` 实现小世界：

- `World.world` 固定返回 `MapBox.instance`。
- `MapBox.Awake()` 会覆盖唯一实例并重新绑定 UI、相机和所有 manager。
- 地图宽高、GeneratorTool、MapGenerator、tile ID 和寻路存在静态全局状态。
- `WorldTile` 不持有所属世界，内部操作反查 `World.world`。
- Actor、Building、zone、chunk、batch 和路径均强绑定主世界 manager。

因此小世界不复用原版世界对象实例，但必须复用原版和 Cultiway 已有的稳定定义、Asset 字符串 ID、视觉资源、蓝图和值对象。需要接触 `Actor`、`WorldTile`、全局 `EntityStore` 或相机的部分留在上下文适配器中。小世界世界空间只扩展主相机可移动范围，不修改 `MapBox.width/height`、主世界 tile 数组或原版地图边界。

## 复用优先原则

实现任何 SubWorld 能力前按以下顺序处理：

1. 已有稳定值对象、Asset ID、sprite、atlas 或蓝图能直接表达时，直接复用。
2. 已有规则被 `Actor`、`WorldTile`、`World.world` 或某个 `EntityStore` 包住时，把确定性定义和公式抽到 `Shared Domain Core`，由 MainWorld 与 SubWorld 共用。
3. 查询对象、物化 Entity、提交生命、播放视觉和操作地图等环境行为只写 Adapter；Adapter 不拥有第二份规则。

分类含义固定为：`直接复用`共享现有定义或资源本身；`抽核心复用`把现有确定性公式移入无世界对象的领域核心；`仅环境适配`只处理 Actor/Entity/Grid/View 的读取、物化和提交，不新增领域语义。

| 原能力 | 分类 | 共享领域内容 | 仅环境适配内容 |
| --- | --- | --- | --- |
| 原版 `TileTypeBase`、Asset ID、`sprites.main` | 直接复用 | `TileType`、`TopTileType` 及其基类中的通行、伤害、图层、材质和视觉字段就是唯一 terrain 定义 | MainWorld 使用 `WorldTile/WorldTilemap`；SubWorld Grid 按格解析 Asset ID，WorldView 把共享的原版 Tile 放入主地图周边的私有 Tilemap |
| `SkillBlueprint` | 直接复用 | 同一蓝图 schema、签名、validator 和深拷贝定义 | MainWorld 与 SubWorld 从同一 definition registry 取得编译结果 |
| `SkillLibV3` | 抽核心复用 + 仅环境适配 | `SkillBlueprint` 只编译一次，产出唯一 `CompiledSkillDefinition`、能力声明和 shared ports 调用 | MainWorld Adapter 对接现有 SkillLibV3 Entity/Actor；SubWorld Adapter 对接 Projection、Grid、局部时钟和视图事件 |
| 共享伤害规则 | 抽核心复用 | 境界压制、元素抗性、最低伤害和最终伤害阶段形成无世界对象的共享伤害管线 | Adapter 提供攻防快照、显式随机源、状态端口，并把结果提交到 Actor 或 Projection |
| `SpecialItem` 与跨世界物品 | 直接复用 + 抽核心复用 | 稳定 `ItemId`、typed snapshot、物品固有定义、`MagicScrollSnapshot`、`TalismanSnapshot` 和 `CraftProcessSnapshot` | `ISpecialItemFactory` 接收明确 `EntityStore`；边界适配器在主线程同步捕获、移除源 Entity 并在目标 Store 物化 |
| 制造种类与工序 | 抽核心复用 | 稳定字符串 `ProcessKindId`、唯一 `ICraftProcessKindRegistry`、typed recipe/state 与 `ICraftProcessKindHandler<TRecipe,TState>` | MainWorld `BehCraft*` Adapter 和 SubWorld workbench Adapter 只构造上下文、调用共享领域并提交 commands |
| 炼丹能力 | 抽核心复用 | 材料固有快照到语义档案、丹方签名、槽位要求和效果组合公式 | MainWorld Adapter 从 SpecialItem Entity 取快照；SubWorld Adapter 从 typed snapshot 取相同输入 |
| 炼器能力 | 直接复用 + 抽核心复用 | `ArtifactBlueprint` 直接复用；材料选择、语义聚合、器形、atom、外观和能力组合改为纯快照公式 | Adapter 提供工匠属性、物品 Entity 和目标 `EntityStore`，装备与显化仍由各自环境执行 |

**禁止在 `Source/Core/SubWorlds` 下平行实现 terrain 定义、技能编译语义、伤害公式、SpecialItem payload、丹方生成或法宝组合。** terrain 也不建立共享 Core；SubWorld 只能新增世界容器、调度、上下文端口和环境表现。

## 玩家体验

以遗府为例：

1. 修士在主世界抵达遗府 Building。
2. 队伍通过入口进入对应小世界 Runtime。
3. 遗府 Runtime 出现在主世界地图周边的独立区域；玩家拖动主相机前往，或点击底栏遗府按钮快速聚焦，查看真实房间、路径、迷雾、修士投影、禁制和遗藏。
4. 小世界按自身 `LocalTime` 运行；玩家可以使用该实例允许的局部暂停和倍速，主世界保持自己的全局速度。
5. 修士自行探索，也可以接受玩法开放的玩家指令。
6. 不同队伍可能从不同入口进入，在内部相遇、合作或竞争。
7. 修士带着实际伤势、物品、技能和结果离开；死亡者在主世界执行正式死亡结算。

当实例区域离开主相机视野时，只禁用该实例的 Renderer 和视觉同步。Runtime 是否继续推进由参与者、规则状态和明确的局部暂停决定，不能由相机是否看见它决定。

## 总体架构

```text
原版 TileLibrary / TopTileLibrary              Cultiway 蓝图与领域定义
  TileType / TopTileType                                  │
  TileTypeBase 真实字段与 sprites.main                    ▼
               │                                  Shared Domain Core
               │ Asset ID 位于 MapData             CompiledSkillDefinition
               ▼                                  DamageResolution
   AssetManager.tiles.get(id)                     Portable Item Values
   AssetManager.top_tiles.get(id)                 Registry-routed Crafting
               │                                          │
               ▼                                          ▼
        SubWorldGrid 直接引用                       MainWorld/SubWorld Adapter
        Navigation / Environment                  Actor 或 Projection 上下文
               │                                          │
               ├───────────────┐                          ├─ ExpeditionBinding
               │               │                          └─ 主线程同步转移
               ▼               ▼                          ▼
          SubWorldRuntime   SubWorldWorldView         OutcomeDelta 即时应用
          EntityStore       近景 render_z Tilemap
          Clock/Random      远景索引纹理与调色板 Shader
         Rules/Objectives  主相机按世界包围盒可见性渲染
               │                    │
               ▼                    ▼
         SubWorldManager    SubWorldSpatialLayout
         会话内 Runtime 集合  环绕布局/相机边界/底栏导航
```

`TileTypeBase` 不进入 `Shared Domain Core`，也不转换成中间定义。`TerrainTraversalRules.Init()` 原地修改原版静态对象；SubWorld 在其执行后解析并持有这些对象，天然读取最终值。`Shared Domain Core` 不引用 `Actor`、`WorldTile`、`MapBox`、Camera 或任何固定 `EntityStore`；MainWorld Adapter 与 SubWorld Adapter 对技能、战斗、物品和制造使用同一份编译结果与公式，只分别完成上下文查询、Entity 物化、结果提交与视觉播放。

## 核心对象

### Template

`SubWorldTemplateLibrary` 按原版 `Asset`/`AssetLibrary` 机制持有所有静态 Template；其中的 `SubWorldTemplateAsset` 定义一种可创建的小世界：

```text
Id
GeneratorId
RuleSetId
ClockProfileId
VisualProfileId
WidthRange
HeightRange
ParticipantCapacity
LifecyclePolicy
```

Template 是静态内容配置。`GeneratorId` 通过 `SubWorldGeneratorLibrary` 解析为可执行的 `SubWorldGeneratorAsset`；实例创建时把 Template、Seed 和创建参数交给该资产生成 Runtime 场景，生成器本身不进入实例数据。

### Runtime

`SubWorldRuntime` 是当前会话中一个具体世界，也是该世界全部可变状态的直接所有者：

```text
InstanceId
TemplateId
Seed
State
MapData
EntityStore
SystemRoot
Grid
NavigationGrid
Clock
Random
RuleRuntime
CommandQueue
EventQueue
Revision
```

Instance ID 在当前主世界会话内唯一，不使用 ECS Entity ID。tile 使用紧凑数组，不为每个格子创建 ECS Entity；单位、机关、物品和 Projection 使用 Runtime 自己的 ECS。

Runtime 不持有：

- `WorldTile`、`Actor`、`Building`。
- `ActorBinder` 或指向主 `ModClass.I.W` 的 Relation。
- 原版 manager、batch、zone 和 pathfinder。
- Unity SpriteRenderer、Camera、Tilemap 等视图对象。

### Manager

`SubWorldManager` 是有状态运行时所有者，持有 `InstanceId -> SubWorldRuntime` 集合，并提供唯一外部入口：

```text
Create(templateId, anchor, seed, parameters)
Get(instanceId)
Destroy(instanceId)
Update(unscaledDeltaTime)
IssueCommand(instanceId, command)
FocusMainWorld()
Focus(instanceId)
```

`Create` 完成生成、Runtime 构造、空间槽位分配和 WorldView 创建后才返回；`Destroy` 同步销毁对应 WorldView、归还槽位并释放参与者占用、ECS 和队列；`Update` 统一推进全部实例。`FocusMainWorld/Focus` 只移动主相机和更新底栏当前目标，不切换或重建 Runtime。其他系统不能直接持有集合或替换 Runtime。

### View

每个 Runtime 对应一个 `SubWorldWorldView`。WorldView 只消费 Runtime 的只读视觉快照和命令接口，把 Runtime 局部坐标通过槽位 Origin 转换到主世界周边的 Unity 世界坐标；近景按原版 `WorldTilemap` 的 `render_z` 分层绘制 Tilemap，远景以 R8 地形索引纹理和共享调色板 Shader 绘制单一 Sprite，不持有 Camera 或 RenderTexture。

`SubWorldSpatialLayout` 把主地图 `Rect(0, 0, MapBox.width, MapBox.height)` 视为中央占用区，以“模板地图上限 `128` + 间隔 `32`”形成 `160x160` 固定槽位网格。槽位按包围中央占用区的矩形环逐圈生成，每圈从北边由西向东开始，再按东、南、西顺时针枚举。实例创建时取得最小空闲 SlotId，存活期间不移动；销毁后 SlotId 回到空闲集合供后续实例复用，其他实例不重排；会话清理时重置全部槽位。

布局只扩展 `MoveCamera.cameraToBounds()` 使用的相机移动矩形，使玩家可以从主地图连续拖动到已分配槽位。它不修改 `MapBox.width/height`、主世界 tile 数组、原版地图生成边界、缩放上限或小地图数据。主相机视野矩形与所有 WorldView 的世界包围盒逐帧求交，全部相交视图同时启用 Renderer 和视觉同步；不相交视图只停止 Renderer 与视觉同步，Runtime、Clock、ECS 和命令继续按自身状态推进。

## 地图与导航

首版采用正交矩形格子：

- 默认 `64x64`，验证后允许模板上限 `128x128`。
- `TileType` 与 `TopTileType` 均继承 `TileTypeBase`。通行、伤害、图层、材质和视觉字段全部直接读取原版对象。
- `TerrainTraversalRules.Init()` 原地修改 `TileLibrary`/`TopTileLibrary` 提供的原版对象。SubWorld Runtime 在其执行后解析，不复制，也不保留默认值。
- 当前 Runtime 的地图数据固定为：

```text
SubWorldMapData
  Width
  Height
  SubWorldTile[] Tiles
  int[] EntryTileIndices
  int[] ExitTileIndices

SubWorldTile
  MainAssetId
  TopAssetId
```

- `SubWorldTile` 是 map-local 逐格数据，不是原版 `TileTypeBase` 的复制定义；它只持有原版字符串 Asset ID。`MainAssetId` 必填，`TopAssetId` 为空表示没有 Top。
- `Tiles[index]` 使用 row-major：`index = y * Width + x`。`EntryTileIndices` 与 `ExitTileIndices` 是地图目标元数据，不进入 terrain 字段。
- Runtime 创建时，`SubWorldGrid` 对每格调用 `AssetManager.tiles.get(MainAssetId)`，并在 `TopAssetId` 非空时调用 `AssetManager.top_tiles.get(TopAssetId)`，在并行数组中持有直接的 `TileType`/`TopTileType` 引用。
- 任一必需 ID 缺失都会使 Template 创建失败；不得回退到 `soil_low`，也不得复制默认定义。
- 有效 gameplay terrain 固定为 `Top ?? Main`。Navigation、格伤害和视图直接读取该 `TileTypeBase` 的真实字段。
- 地图变化只修改对应 `SubWorldTile.MainAssetId/TopAssetId`；变更完成后刷新该格引用缓存并标记 dirty tile，不写入原版 Asset。
- 邻接采用模板选择的四向或八向规则。
- `SubWorldNavigationGrid` 从 Grid 缓存的直接对象和动态实体阻挡构建实例级通行成本。
- 路径请求携带 InstanceId、Runtime Revision、EntityId、起终点和移动画像。
- 路径结果只持有 tile index 数组，不持有 `WorldTile`。
- WorldView 在分配槽位中按原版 `Tilemaps` 的 `0.25` 缩放、`4x4` Grid 和 `render_z` 动态层创建私有 Tilemap/Renderer，直接使用原版对象的 Tile/Sprite 与共享材质；视图根节点只应用局部坐标到世界坐标的平移。

地图生成器必须由 Seed 确定；生成结束后的 `MapData` 直接属于 Runtime，后续地图变化在同一对象上推进。

## 规则模型

`SubWorldRuleSetAsset` 组合稳定 Rule Module ID 和参数：

| 模块 | 职责 |
| --- | --- |
| Movement | 通过 Grid 中直接解析的原版 `TileTypeBase` 解释邻接、通行、移动成本与特殊位移 |
| Visibility | 视野、迷雾、隐匿和发现 |
| Environment | 灵气、毒雾、火焰、潮汐、昼夜等格子影响 |
| Combat | 攻击关系和死亡由上下文处理；技能定义与伤害公式来自 Shared Domain Core |
| Interaction | 门、禁制、机关、容器和采集 |
| Objective | 目标、阶段、胜负和完成条件 |
| Exit | 允许撤离、强制结束和崩塌规则 |
| Outcome | 哪些结果能够同步回主世界 |

Rule Module 是无状态资产；实例状态放在 Runtime 组件、ObjectiveState 或 RuleRuntime 中。调用方不能在遗府代码里直接修改小世界内部实体来绕过规则。

首版只有固定步进实时模拟。需要回合制时仍通过“何时允许推进固定 tick”的 Clock Mode 实现，不建立第二套实体与战斗引擎。

## 时间模型

`SubWorldClockProfileLibrary` 持有时钟配置资产，每个实例按 Template 中的 Asset ID 绑定一个 `SubWorldClockProfileAsset`：

```text
FixedStep
DefaultLocalRate
BodyTimeRatio
RunsWhileParentPaused
BackgroundPolicy
AllowedLocalSpeedOptions[]
MaxTicksPerFrame
```

区分三种时间：

| 时间 | 含义 |
| --- | --- |
| ParentTime | 主世界实际经过的模拟时间，只用于运行中时间戳与返回结算 |
| LocalTime | 小世界环境、机关、战斗和目标使用的时间 |
| BodyTime | 参与者肉身年龄与生理变化使用的时间 |

`SubWorldClock` 使用 `Time.unscaledDeltaTime × DefaultLocalRate × LocalSpeed` 累积固定 tick。主世界继续由 WorldBox 全局时间控制驱动，因此两边可以同时运行且倍率不同。用户单独暂停主世界时，实例是否继续由 `RunsWhileParentPaused` 决定；相机聚焦或离开实例绝不暂停任一世界。

逻辑始终使用固定 tick。倍速只决定每帧推进多少固定 tick，不改变单 tick 数值。
实例逐个固定 tick 使用现有 `FramePriorityGovernor` 的 Cultiway 模拟预算；预算不足只延后执行，不消费实例 accumulator，也不改变 LocalTime 与 TickIndex。

## 参与者投影

### 入场

真实 Actor 到达主世界入口后，边界适配器在同一主线程调用内依次完成：

1. 校验入口、参与资格、目标 Runtime 和所有携带物的 typed materializer。
2. 捕获 `ActorProjectionBaseline`、typed portable item 与制造进程快照。
3. 标记 Actor 的 `ExpeditionBinding`，停止主世界 AI、战斗、移动和定时系统对其推进。
4. 解除携带物在主世界的 holder、装备和工序关系，回收源 Entity。
5. 在 Runtime 的 `EntityStore` 创建 Projection，并按稳定 `ItemId` 物化携带物。
6. 调用结束前完成入口放置与视图事件；过程中不允许另一帧模拟插入。

`ExpeditionBinding` 只是当前会话的 Actor 占用状态，记录 SourceActorId、InstanceId、ProjectionEntityId、Baseline、入场时间和当前阶段。一个 Actor 同时只能绑定一个实例。

绑定期间明确阻止：

- 普通 AI、移动、饥饿和自然年龄推进。
- 主世界攻击、受伤和死亡。
- 主世界修炼、资源回复、装备显化和其他 Cultiway 定时系统。
- 原版和 Cultiway status 时间自然流逝。

### Projection

Projection 只持有小世界需要的结构化数据：

```text
SourceActorId
Position
Faction
Health/Resources
CombatStats
CompiledSkillDefinitions
PortableItemSnapshots
Statuses

```

### 共享技能合同

技能只有一条定义管线：

```text
SkillBlueprint
  -> SkillBlueprintCompiler
  -> CompiledSkillDefinition（唯一规范形式）
  -> ISkillExecutionPorts
       MainWorldSkillAdapter -> SkillLibV3 / Actor / 主世界视觉
       SubWorldSkillAdapter  -> Projection / Grid / LocalClock / 小世界视觉
```

每份 `CompiledSkillDefinition` 声明 `RequiredCapabilities[]`。Adapter 明确公布 `SupportedCapabilities`；只有 required 集合完全满足时才能装入该世界。依赖主世界 Building、任意 `WorldTile` 回调或未声明全局状态的技能明确为不支持，不生成近似效果。

共享伤害管线接收纯数据 `DamageRequest`、显式随机源和状态端口，返回 `DamageResult`。MainWorld Adapter 和 SubWorld Adapter 只负责提供攻防快照、扣减各自生命并发布各自事件，不得拥有另一套最终伤害公式。

### 返回

小世界不覆盖整个 ActorData，而是在退出 tick 边界构造临时 `OutcomeDelta`：

- 当前生命和资源变化。
- 永久伤势、trait 增减。
- 通过 Blueprint 获得或失去的技能与物品。
- 修炼资源与气运变化。
- BodyTime 导致的年龄变化。
- 死亡和死亡来源。

返回适配器在同一主线程调用内冻结 Projection、捕获最终 typed item 值、销毁 SubWorld Entity、在 MainWorld Store 物化物品、应用 Actor 结果并解除 `ExpeditionBinding`。物品先处理，死亡最后处理；调用完成后不存在等待中的跨世界结果。

## Portable Item 与制造边界

所有跨 MainWorld/SubWorld 的 SpecialItem 都拥有稳定 `ItemId`。`ItemId` 不使用 ECS Entity ID，并在源 Entity、typed snapshot 和目标 Entity 之间保持不变。

```text
IPortableItemSnapshot（typed 内存值，包含 ItemId）
  ↕ Capture / Materialize
ISpecialItemFactory.Create(target EntityStore, snapshot)

CraftProcessSnapshot
  ProcessId / ProcessKindId / CrafterId
  InputItemIds[] / OutputItemId
  TypedRecipeSnapshot / TypedStateSnapshot
  Progress / RandomState
```

- transfer adapter 按明确 snapshot 类型注册，不复制任意 ECS 组件包，也不处理未知类型。
- `ISpecialItemFactory` 必须显式接收目标 `EntityStore`；禁止内部固定访问 `ModClass.I.ActorExtendManager.World`。
- MainWorld 和 SubWorld 的 Entity 是不同的物化实例；稳定 `ItemId` 与 typed snapshot 是同一次同步转移中的跨 Store 身份。
- `MagicScrollSnapshot` 与 `TalismanSnapshot` 是两个独立顶层值对象，只共享嵌套的 `StoredSkillPayloadSnapshot`。
- 快照不持有 `SkillContainer` Entity 或 `CompiledSkillDefinition` 副本；学习或施放时按 `SkillBlueprint/Signature` 从 `ISkillDefinitionRegistry` 解析唯一 definition。
- 唯一 `ICraftProcessKindRegistry` 按 `ProcessKindId` 注册 typed handler；首批 ID 为 `alchemy`、`artifact_refining`、`talisman_crafting`、`magic_scroll_crafting`。
- 动态 Blueprint 在进入另一 `EntityStore` 时深拷贝为 typed 值，当前会话中全局创作目录的后续编辑不会反向改写既有物品或工序。

## 生命周期与调度

实例状态：

```text
Created -> Ready -> Active -> Completing -> Completed
                     ↓              ↓
                  Collapsed <-------┘
```

全部状态都由 `SubWorldRuntime` 持有。Completed 实例可以在当前会话中保持只读供玩家查看，也可以由消费系统调用 `Destroy` 立即释放；Collapsed 实例完成参与者结算后遵循同样规则。

逻辑调度与视图可见性正交：

| 维度 | 状态 | 条件与行为 |
| --- | --- | --- |
| RuntimeTier | Active | 有参与者、战斗、即时事件、移动或固定步进工序；执行完整固定 tick |
| RuntimeTier | Warm | 没有即时行为，只有明确支持 elapsed 推进的环境、目标或自动工序；Runtime 与全部 Entity 常驻并低频推进 |
| ViewState | ViewVisible | WorldView 世界包围盒与主相机视野相交；启用 Renderer 并同步最新视觉状态 |
| ViewState | Culled | 两者不相交；禁用 Renderer 并跳过视觉同步 |

同一 Active 逻辑状态在 `ViewVisible` 与 `Culled` 下运行相同 TickIndex 必须产生相同结果。Warm 只能运行声明支持 elapsed 推进的模块；任意战斗、移动、玩家命令或手工制造会立刻回到 Active。调度器可以优先给相机内的 Active 实例分配帧预算，但不能改变 tick 顺序、累计时间或领域结果。

首版预算：

- 常驻实例：默认上限 8；任意数量可以同时与主相机视野相交，不设置单一前台名额。
- 所有小世界平均 CPU：每渲染帧 `1 ms`，硬停止 `2 ms`。
- 每实例事件与命令：每 tick 各处理最多 32 条。
- 每实例路径请求：每 tick 最多 2 条。
- 单实例 gameplay Entity 建议上限 512；全部相交视图共享的 SpriteRenderer 池上限 512。
- 稳态 UI 与渲染准备：每帧 0 B GC。

切换世界、返回主菜单或 Mod 重载时，生命周期入口停止 `SubWorldManager.Update`，依次销毁全部 Runtime、绑定、队列、WorldView、Tilemap、私有 Material、对象池和底栏动态入口，重置空间槽位与相机移动边界，并清空 Manager 集合。

## 可视化

世界空间结构：

```text
SubWorldViewsRoot
  SubWorldWorldView(instanceId) @ Slot.WorldOrigin
    Tilemaps (Grid)
      render_z TilemapLayer[]
    world_layer (远景索引纹理)
    Objects
      Walls
    Creatures
      Units
        Entity Sprite Pool
    Effect Pool
```

- WorldView 的地图、实体与特效统一使用主相机可见的世界层和稳定 sorting order；不同实例的私有材质只承载本地迷雾、昼夜和光照参数。
- 每帧在主相机移动完成后，以 `ViewportToWorldPoint` 得到视野矩形，并与全部已分配 WorldView 包围盒求交；相交集合可以是 0、1 或多个。
- 进入相交集合时应用累计 dirty tile 和最新 ReadModel，再启用对应 Renderer；离开时立即禁用 Renderer 并停止位置插值、动画和 VFX 同步，不改变 Runtime 状态。
- terrain 外观完全由 Template/Generator 选择的原版 Asset ID 决定；VisualProfile 只负责 FogColor、实例背景表面、局部光照、聚焦缩放、SubWorld 专属 overlay/VFX 和 EntityVisualProfile。

底栏结构：

```text
SubWorldNavigationBar
  MainWorld：聚焦主地图
  RuntimeButtons[]：按 InstanceId 稳定排列，聚焦对应 WorldView
  FocusedRuntimeControls：局部暂停、1x/2x/4x、观察队伍、目标状态
```

- 底栏使用原版 `PowerButton` 交互语义、图标和 Tooltip；实例按钮在 Runtime 存活期间持续存在，销毁时移除，不以隐藏视图代替销毁。
- 点击入口只调用 `FocusMainWorld/Focus`：清除原版 Actor 跟随，把主相机移动到目标包围盒中心并使用目标聚焦缩放；它不改变 RuntimeTier、ViewState、局部时钟或参与者状态。
- `FocusedRuntime` 只决定底栏局部时间控件、观察队伍和 Inspector 的目标。玩家自由拖动相机不会隐式切换它；点击另一小世界中的格子或实体时才把该实例设为当前目标。
- 主相机拖拽和滚轮缩放继续由原版 `MoveCamera` 处理。指针落在某个 WorldView 包围盒内时，输入路由器把世界坐标转换为该 Runtime 局部坐标并提交选择或命令，同时阻止主世界 Power/Tile 输入；落在主地图内时保持原版输入，落在空白间隔时只允许相机导航。
- Tilemap 只在近景提交 dirty tile；远景仅上传每格 1 byte 的地形索引并由共享 Shader 查调色板，隐藏 Tilemap、Pawn、实体和特效。不同 WorldView 共享只读远景材质与调色板，不共享索引纹理和其他可变视觉状态。

## 消费系统合同

消费系统只通过 `SubWorldManager` 使用小世界：

```text
Create(templateId, anchor, seed, parameters)
Get(instanceId)
Destroy(instanceId)
Update(unscaledDeltaTime)
IssueCommand(instanceId, command)
FocusMainWorld()
Focus(instanceId)
```

参与者加入、退出、实例崩塌和玩法操作都作为明确 command 交给 `IssueCommand`，由所属 Runtime 在边界阶段执行。

消费系统负责：

- 选择 Template、主世界 Anchor 和创建参数。
- 决定哪些主世界角色有资格进入。
- 解释 Objective 完成后对自身玩法的意义。
- 将小世界事件转成 WorldLog、宗门事务或其他外部结果。
- 在不再需要 Completed/Collapsed 实例时调用 `Destroy`。

消费系统不得：

- 直接访问 Runtime Store 修改组件。
- 把主世界 Actor 或 Building 放进 Runtime。
- 使用相机是否聚焦、WorldView 是否相交或底栏是否选中决定逻辑成功或暂停。
- 在 Manager 之外维护第二份实例状态。

## 最终完成标准

小世界平台完成后，消费系统只需要选择 Template、入口和参与者，就能在当前会话中获得一个拥有独立地图容器、时间、周边空间视图和返回结算的真实 Runtime。terrain 在 Runtime 中就是经原版 Asset ID 解析出的 `TileTypeBase` 对象；物品、四种制造、技能和伤害继续来自与主世界相同的共享领域核心，SubWorld 只替换上下文 Adapter。相机是否聚焦或看见实例不改变逻辑，主世界与各 SubWorld 保持独立时钟，主世界 Actor 在 `ExpeditionBinding` 期间不会并发变化；全部实例由 `SubWorldManager` 常驻持有并在会话边界统一销毁，任意结果都能追溯到小世界内发生的具体移动、交互、制造、战斗和目标事件。
