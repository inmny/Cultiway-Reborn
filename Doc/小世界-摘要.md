# 小世界-摘要

**版本**：v2.0
**状态**：遗迹优先设计基线
**最后更新**：2026 年 8 月 14 日
**当前实现**：阶段 1 步骤 1-5 已完成；地图、Runtime、独立时钟、周边 WorldView、共享异步寻路与固定 tick 移动已经接通
**当前唯一交付对象**：遗迹
**后续用途**：宗门驻地、完整独立世界
**统一生命周期边界**：全部小世界状态只存在于当前游戏会话，不写入或恢复世界存档

## 一句话定义

小世界是 Cultiway 自己持有地图、实体、时间和模拟状态的独立世界容器。它不是第二个原版 `MapBox`，也不只是主世界入口旁的一段抽象计时；玩家能够在主世界地图周边直接观察其中真实发生的移动、探索、战斗、交互和世界演化。

小世界最终服务三类用途，但当前不同时实现三套玩法：

| 用途 | 世界主体 | 与主世界的关系 | 核心玩法 | 当前定位 |
| --- | --- | --- | --- | --- |
| 遗迹 | 进入的修士 Projection、遗构、守卫、危险与机缘 | 一处主世界遗迹绑定一个共享 Runtime | 发现、进入、调查、冒险、取得机缘、撤离 | **当前唯一实现目标** |
| 宗门驻地 | 宗门成员、访客、建筑、资源与防御设施 | 由宗门拥有，通过入口往返 | 建设、生产、驻守、来访与攻防 | 遗迹发布后另立规划 |
| 完整独立世界 | 小世界原生生物、聚落、势力与文明 | 可有入口，也可作为纯观察世界存在 | 生态、人口、文明和事件自主演化 | 宗门驻地之后另立规划 |

三类用途只共享确实相同的世界容器能力。遗迹目标、宗门生产和文明模拟不得塞入一个按 `SubWorldKind` 分支的巨型 Runtime。

## 已确认的产品决策

| 决策 | 结论 | 设计影响 |
| --- | --- | --- |
| 遗迹操控 | 修士由 AI 自主探索 | 正式玩法不提供逐格移动、调查、领取或攻击指令；玩家负责观察、聚焦和时间控制 |
| 遗迹实例关系 | 同一处主世界遗迹共享一个 Runtime | 遗构调查、残阵变化、危险、守卫、机缘耗尽和地形变化会被后续队伍继承；每次远征不得重建副本 |
| 完整独立世界 | 长期目标包含原生人口、聚落和文明演化 | 未来必须支持不依赖主世界 Actor 的原生实体，但这不是遗迹前置能力 |
| 状态持久性 | 全部只属于当前游戏会话 | 不设计存档 DTO、恢复、迁移和跨会话稳定 ID；切换世界或重新载入时统一销毁 |

会话边界只约束 Site、Runtime、Binding、参与者知识和未结算战利品。修士已经安全返回后，物化到主世界的物品、生命变化和其他正式结果就是普通主世界状态，继续遵循项目现有存档行为。

## 当前问题与路线修正

现有代码已经完成阶段 1 步骤 1-5，但仍只是开发演示底座：

- 主世界与小世界已经共用同一个异步 `PathFinder` worker 池；小世界具备八向禁切角搜索和固定 tick 移动，移动实体允许重叠，但当前移动实体仍是测试 Pawn。
- Runtime 直接维护移动目标、未来路线 handle、已认领移动段和 terrain Navigation；请求真实状态由共享 `PathFinder` 的 `PathPollKind` 给出，不在实体上复制状态枚举。重新指定目标只替换当前段终点之后的路线，不重置连续 `Position`。
- Runtime 尚没有真实遗迹入口、Actor Projection、机关、遗藏、奖励或返回结算。
- 现有后续文档把六类物品、四类制造、完整技能重构和多实例调度放在首个遗迹之前，导致平台越来越宽，玩法闭环仍不存在。

新路线从阶段 1 步骤 6 继续纵向交付：先让一名真实修士自主调查一座手工开放遗迹，再按真实玩法需要增加地貌组合、战斗、战利品、多人争夺和多实例稳定性。

## 当前范围

### 必须完成

1. 补齐移动命令后的 Navigation、寻路和固定 tick 位移。
2. 建立一处主世界遗迹入口与一个开放的残破古修道场 Runtime。
3. 让一名真实 Actor 以最小 Projection 进入，小世界期间暂停其主世界推进。
4. 让 AI 只依据已知地貌、遗构和线索自主调查多个独立机缘节点，并自行决定继续深入或带着所得返回。
5. 把伤势和至少一种真实机缘收益同步结算回主世界。
6. 同一遗迹 Runtime 的地貌、残阵、危险和机缘耗尽状态对后续进入者持续生效。
7. 在后续阶段加入确定性开放地貌组合、遗构与线索分布、守卫战斗、死亡、两类真实战利品和多队伍争夺。
8. 保证相机聚焦、视图裁剪和主世界倍速不改变小世界逻辑结果。
9. 在切换世界、返回主菜单、重新加载世界或 Mod 重载时释放全部 Runtime、Binding、WorldView 和用途层索引。

### 当前明确不做

- 第二个原版 `MapBox`、`WorldTile`、Actor manager、Building manager、zone 或原版寻路器。
- 遗迹内炼丹、炼器、制符、卷轴制作、工作台和制造进程转移。
- 一次性覆盖全部 SpecialItem、装备、消耗品和技能载体。
- 为小世界复制一套 SkillLibV3、伤害公式、terrain 定义或物品定义。
- 通用规则模块市场、任意目标 DAG、脚本热加载和自由地图编辑器。
- BodyTime、梦境时间、独立昼夜和大量 VisualProfile。
- 未经实测就固定 Active/Warm、8 实例、1 ms 或其他平台级容量结论。
- 宗门建设、资源生产、原生生态、王国与文明演化。
- 存档、恢复、跨会话状态或兼容旧版本数据。
- 正式玩法中的玩家逐格操控；右键移动只保留为 Debug 验证工具。

## 职责边界

### 小世界 Core

`Source/Core/SubWorlds` 只负责不同用途确实共有的能力：

- `SubWorldTemplateAsset`、Generator、ClockProfile 与 VisualProfile 资产链。
- `SubWorldMapData`、`SubWorldTile[]`、`SubWorldGrid` 和原版 terrain Asset 解析。
- `SubWorldRuntime` 的 Store、SystemRoot、Clock、命令队列和 Revision。
- `SubWorldManager` 的创建、查询、更新、命令、销毁与会话清理。
- Runtime 内局部坐标、terrain Navigation、移动和确定性固定 tick。
- WorldView 所需的只读状态与用途无关的实体视觉事件。

Core 不持有 `Building`、`Sect`、主世界 `Actor`、遗迹目标、宗门库存或文明数据。

### 主世界边界适配

远征边界负责真实 Actor 与 Projection 的进入和返回：

- 以当前会话内 `SourceActorId` 建立唯一 Binding。
- 捕获首个遗迹实际需要的只读快照。
- 用内存索引阻止主世界 AI、移动、受伤、修炼和渲染继续推进该 Actor。
- 在退出边界应用明确的生命、资源、奖励或死亡结果。
- 不把原版 Actor、`ActorBinder` 或主世界 Entity 放入 Runtime Store。
- `SettlementStagingRegistry`、`ISubWorldSettlementCommitPort`、`DeathApplicationLedger` 与 death port 属于主世界边界；Runtime 只看到 Token、StagingId 和幂等结果，不持有 Actor、holder 或目标 Entity。

### 遗迹用途层

`Source/Content/SubWorlds/Ruins` 负责：

- `RuinSiteId -> InstanceId` 的当前会话绑定。
- 主世界入口、发现状态、进入资格和远征队伍。
- 遗迹地貌、遗构群、道痕线索、残阵、危险区、守卫、机缘节点和出入口。
- 自主调查 AI、独立机缘状态、战利品归属和遗迹逐步耗尽/崩塌。
- 将 Runtime 事件转成入口状态、WorldLog 和最终奖励。

`SubWorldManager` 不应知道“遗迹”是什么；遗迹用途层也不能绕过命令和事件边界直接改写 Runtime 内部集合。

### 后续用途层

- 宗门驻地以当前会话内 Sect ID 绑定 Runtime，拥有自己的建设、生产和驻守系统。
- 完整独立世界拥有小世界原生人口、生态和文明系统，不以主世界 Actor Projection 作为人口主体。
- 二者可以复用 Grid、Runtime、Navigation、View 和必要的访客边界，但不得复用遗迹的目标状态机或战利品规则来假装完成自身玩法。

## 身份模型

| 身份 | 所有者 | 作用域 | 规则 |
| --- | --- | --- | --- |
| `InstanceId` | `SubWorldManager` | 当前会话 | Runtime 技术身份；不等于遗迹、宗门或世界的业务身份 |
| `RuinSiteId` | 遗迹用途层 | 当前会话 | 一处主世界遗迹的业务身份；一对一绑定当前 Runtime |
| `ParticipantId` | 远征边界 | Runtime 生命周期 | 一次进入关系；同一 Actor 同时只能有一个 |
| `SourceActorId` | 主世界 | 当前主世界 | 退出时找到真实 Actor；不得用于 Runtime 热路径访问 Actor |
| `RuinLootId` | 遗迹用途层 | 当前 Runtime | 一件实际生成的遗迹战利品身份；原子领取和返回防重 |
| `SubWorldAnchor` | 当前用途层 | 当前会话 | 现有 Create 必需的主世界创建上下文；对遗迹表示入口位置，但不等于业务身份或所有权 |
| `SlotId` | `SubWorldSpatialLayout` | View 生命周期 | 只决定画在主地图周边哪里，不参与玩法与随机结果 |

切换世界或重新加载时这些身份全部失效。入口 Building 不得把旧 `InstanceId` 当作可恢复数据；发现孤立入口时由遗迹用途层删除或失效处理，不创建兼容回退 Runtime。未来完整独立世界若不需要主世界入口，应在其规划中把 Owner、Anchor 和 View Host 解耦；不能把当前遗迹 Anchor 或周边 Slot 当成独立世界身份，也不为此阻塞遗迹阶段。

## 核心运行结构

`SubWorldRuntime` 继续直接拥有运行状态：

```text
InstanceId / TemplateId / Seed / State / Revision
MapData / Grid / NavigationContext / PathWorldKey
EntityStore / SystemRoot
Clock
BoundaryCommandQueue / MoveCommandQueue
```

现有 `SubWorldGeneratedScene` 中“唯一测试 Pawn 出生点”是开发演示遗留，不应成为通用合同。Generator 只生成地图和用途需要的明确出生点；具体遗迹对象由遗迹 Generator/Bootstrap 以强类型组件安装到新 Runtime，不使用无类型 `Dictionary<string, object>` 参数包。

每个固定 tick 的顺序固定为：

1. 接收并验证边界命令。
2. 更新感知与参与者已知信息。
3. 自主 AI 选择一个当前行动。
4. 处理路径请求与 terrain 变化。
5. 推进移动并结算格子效果。
6. 处理交互；阶段 3 起在此之后处理战斗与死亡。
7. 评估独立机缘状态、战利品领取和退出资格。
8. 评估状态并生成只读视图状态。

相同 Seed、相同初始状态和相同不可变寻路请求快照必须得到相同 tile 序列；异步 worker 在哪个 local tick 发布结果不属于确定性承诺，因此不能把 ready tick 当作内容随机输入。`ViewVisible`、聚焦目标、Renderer 开关和渲染帧率不属于逻辑输入。

## 地图与 terrain

当前正确设计保持不变：

- 地图使用 row-major `SubWorldTile[]`，`index = y * Width + x`。
- `SubWorldTile` 只保存 `MainAssetId/TopAssetId`，不是 terrain 定义副本。
- Runtime 创建时由 `SubWorldGrid` 直接解析原版 `TileType/TopTileType`。
- 有效 terrain 固定为 `Top ?? Main`；通行、移动成本、格伤害、图层和视觉读取同一对象。
- 不创建 `WorldTile`，不修改 `MapBox.width/height`、主世界 tile 数组或原版 Asset。
- 地图变化必须通过一个 Runtime 结构变更边界调用 `Grid.SetTile`、更新动态导航并递增 Revision；不得让三个操作分散在调用方。
- 路径只保存 tile index，不保存 `WorldTile` 或 WorldView 坐标。

## 首个遗迹体验

首个正式模板是 `Cultiway.SubWorld.Template.RuinedDaoGround`，使用一张 `48x48` 连续开放地图。它表现一处残破古修道场，而不是由房间和走廊组成的地牢：

| 地貌/遗构 | 作用 | 是否强制经过 |
| --- | --- | --- |
| 山脚裂隙与残阶 | 入口、撤离点和第一批模糊道痕 | 只有出入必经 |
| 倾塌外院遗构 | 提供遮挡、岔路和可调查残碑 | 否 |
| 荒废药圃 | 一处可独立取得的 Ingredient 机缘 | 否 |
| 断裂阵带 | 持续危险区；可绕行，也可调查阵眼降低危险 | 否 |
| 山腰废殿与道台 | 提供较强线索和另一处悟道/遗物机缘 | 否 |

地貌与遗构锚点由手工布局保证可读性；Seed 只改变局部坍塌通路、道痕指向、危险强度、机缘内容和节点是否显露。地图不存在唯一“正确路线”，也不存在必须清完才能离开的核心宝箱。

首个闭环为：

1. 玩家通过正式世界神力投放古修道场入口，而不是依赖开发自动创建 Runtime。
2. 一名满足条件的修士由主世界 AI 发现并前往入口。
3. 到达后建立 Binding，在同一主线程边界创建 Projection。
4. Projection 观察地貌、灵气异常和道痕，只依据已知信息选择调查方向。
5. Projection 可以先调查残碑获得线索，也可以绕过断阵直接搜索药圃或道台。
6. 每个机缘节点独立进入 Exposed、Claimed、Exhausted；取得一个节点不会自动清空其他节点。
7. Projection 根据风险偏好、生命状态和当前所得，自行决定继续调查还是返回。
8. 返回时结算伤势与实际取得的机缘；后续修士进入同一 Runtime，继承已调查遗构、已稳定残阵和已耗尽节点，仍可寻找剩余内容。

首阶段没有战斗和死亡。危险区最多把 Projection 生命降到 1；战斗、生死和掉落在阶段 3 一次性补齐，避免出现两套临时死亡语义。

## 遗迹状态

### Site 状态

```text
Hidden -> Discovered -> Open -> Exhausted
                         \-> Collapsed
```

- `Hidden/Discovered` 是主世界入口知识状态，不由相机是否看到入口决定。
- `Open` 允许合格修士进入同一 Runtime；入口摘要可以派生显示“未探索/部分探索”，但不增加一套重复状态。
- 只有全部有限机缘都已 Exhausted 或被永久破坏时，Site 才进入 `Exhausted` 并停止接受新远征。
- `Collapsed` 表示实例因规则或入口销毁不可继续，先结算或清理参与者，再销毁 Runtime。

每个机缘节点独立推进：

```text
Unrevealed -> Clued -> Exposed -> ClaimedPendingSettlement -> Exhausted
                                      \-> Released
```

`Clued` 只给出方向、地貌或气息信息，不暴露精确坐标；`Released` 表示领取者放弃或结算回滚，节点重新允许争取。一个节点 Exhausted 不改变其他节点。

### Runtime 与单次远征

单个参与者退出不等于 Runtime 结束。遗迹是否 Exhausted 由用途层的 Site 状态表达；只取得部分机缘时 Runtime 继续 Running，保留剩余机会供后续队伍探索。整处遗迹不再需要运行时实例时，由用途层完成参与者结算后销毁 Runtime，使其进入 Collapsed。

单次远征状态为：

```text
Approaching -> Entering -> Exploring -> Returning -> Settling -> Settled
                                     \-> Dead（阶段 3）
                                     \-> Aborted
```

状态转换只发生在主线程边界或 Runtime tick 边界。任何失败都必须在调用返回前恢复为一个完整状态，不留下“Actor 已冻结但 Projection 不存在”或“奖励两边各一份”的中间态。

## 自主探索 AI

正式遗迹不接受玩家移动或交互命令。每个 Projection 只从以下信息决策：

- 自己和队友已经观察过的地形与遗构。
- 已感知的灵气异常、道痕方向、危险区、守卫和机缘节点状态。
- 当前生命、资源、已取得收益、返程成本和可到达路径。
- 自身风险偏好与调查能力；不得读取未显露节点坐标或 Generator 的完整布局。

首批行动优先级：

1. 生命低于撤离阈值，或当前所得达到自身满意阈值时返回入口。
2. 阶段 3 起先处理已感知且必须应对的威胁。
3. 邻接可调查遗构、道痕或机缘节点时执行对应交互。
4. 在已 Exposed 的机缘中按收益、风险、路程和自身相性选择一个。
5. 没有显露机缘时，沿最可信的 Clue 前往对应地貌范围调查。
6. 没有线索时前往最近的观察边界或显著遗构。
7. 连续无法得到新信息或没有安全路径时返回入口。

AI 可以带着部分所得主动结束远征；这不是失败。它不因 WorldView 被裁剪而获得额外信息、改变风险判断或停止思考。

## Projection 与返回

阶段 1 只捕获闭环实际使用的数据：

```text
SourceActorId
DisplayName / ActorAssetId / VisualVariant
Position / MoveSpeed / PerceptionRange
CurrentHealth / MaxHealth
CurrentWakan / MaxWakan
ExplorationRiskPreference
```

不捕获完整 `ActorData`、任意 ECS 组件包、全部状态、装备或制造进程。主世界携带物在首阶段保持原状且不能在遗迹内使用；Projection 的战斗快照和实际战利品在需要它们的阶段再增加。

Binding 期间通过当前会话内索引统一阻止主世界侧 AI、移动、攻击、受伤、修炼、恢复和 Cultiway 定时 System。禁止通过写入将被存档的“永久隐藏”字段表达 Binding。若玩家保存后重新加载，加载出的世界只保留入场前的主世界 Actor 状态，小世界及未结算成果全部消失，符合会话边界。

退出结算使用 Runtime Prepare/Commit/Rollback 命令和一个窄的主世界提交端口：

1. `PrepareSettlementCommand` 在 Runtime tick 边界校验参与者、claim owner 与 Revision，冻结 Projection/claim，并发布带 Token 的不可变结算快照。
2. `SubWorldExpeditionService` 只把 `SourceActorId/HolderId`、typed Outcome/Loot values、仅含标量/不可变 typed value 的 ActorOldValues、`MaterializerKey` 与纯数据参数写入会话内 `SettlementStagingRegistry`；禁止保存 Actor、Entity、Store、holder adapter、delegate、handler 或 Unity 对象。
3. 服务提交 `CommitSettlementCommand(Token, StagingId)`。Runtime 在 tick 边界预校验全部状态变化后，进入同一主线程的不可重入提交段，并调用窄接口 `ISubWorldSettlementCommitPort.TryPromote(StagingId)`。
4. MainWorld port 在该调用内创建/验证目标 Entity、绑定 holder、应用 Actor 字段并返回可逆 Receipt；随后 Runtime 执行无分配、无外部回调的 Opportunity/ownership/ledger/Projection 状态提交。
5. MainWorld promote 或 Runtime 最终提交任一步失败时，port 在退出提交段前按 Receipt 删除新 Entity、恢复 Actor 旧值，Runtime 同步恢复 Prepared 状态；不会留下跨 tick 可见的主世界半成品。
6. 两边成功后 Runtime 发布 CommittedEvent，服务移除 Binding 和 StagingRecord；Commit 之前的取消、入口删除或清理则删除 StagingRecord 并提交 `RollbackSettlementCommand(Token)`。
7. 阶段 3 起，Health 为 0 的参与者改走 DeadPendingSettlement/DeathSettlementToken/Acknowledge；`DeathApplicationLedger` 按 Token 幂等，死亡入口已生效后即使抛错也记 Applied，重复 Token 不再调用；不可判定的 Faulted 状态禁止重试并阻断发布。

保存、`clearWorld`、Mod 重载和普通事件派发都不能插入不可重入提交段；它们只能在提交前中止 staging，或在完整提交后观察正式主世界结果。用途层从不直接改 Opportunity、ownership、ledger、Projection 或 Runtime loot。

阶段 1 的奖励只支持一种现有 Ingredient。阶段 4 再为实际使用的奖励类型建立 typed 值与跨 Store 转移；不提前实现六类通用 PortableItem。

## 视图与 UI

当前“主地图周边稳定槽位 + 共用主相机”方案继续作为所有会话内小世界的展示宿主：

- Runtime 局部坐标与槽位世界坐标分离；`SlotId` 不参与玩法身份。
- 同一相机视野可以同时相交主世界和多个 WorldView。
- 离开视野只停止 Renderer 和视觉同步，不改变 Runtime 时钟与逻辑。
- WORLD 神力分区保留主世界/实例入口、局部暂停、1x/2x/4x 和聚焦参与者控件。
- 正式遗迹按钮只负责聚焦和显示状态，不负责创建、重置或领取奖励。
- 点击实体可打开已有信息/Tooltip 语义；不新增大型遗迹操作窗口。
- 所有状态文本本地化；图标按钮复用原版 `PowerButton`、`UiIcons` 和 Tooltip。
- 右键移动、强制交互和生成测试 Pawn 只在 Debug 配置出现。

入口世界 Overlay 至少区分 Hidden、Open、内部有人、部分探索、Exhausted 与 Collapsed；残碑线索、危险道痕、可取得机缘和安全撤离使用不同视觉，不用同一个闪光效果表达所有状态。

## 时间与调度

- 每个 Runtime 继续使用现有 `1/24s` 固定 tick 与独立 LocalSpeed。
- 首版只保留 LocalTime，不引入 BodyTime、梦境比例或独立年历。
- 主世界和小世界可以分别暂停/变速；相机聚焦不改变任一速度。
- Runtime 在 `FramePriorityGovernor` 预算内推进；预算不足时保留 accumulator，不跳过逻辑时间。
- 遗迹没有参与者且没有倒计时事件时可以不执行 gameplay System，但 Runtime 和物理状态仍常驻。
- 多实例容量与每帧预算在阶段 5 用真实遗迹负载测量后确定，不在设计阶段写死。

## 三类用途的能力差异

| 能力 | 遗迹 | 宗门驻地 | 完整独立世界 |
| --- | --- | --- | --- |
| 地图/Grid/Navigation/View | 需要 | 复用 | 复用 |
| 主世界访客 Projection | 核心 | 访客与部分成员可用 | 可选访客 |
| 小世界原生实体 | 守卫与机关 | 驻地设施、召唤物等 | 核心人口 |
| 独立机缘与逐步耗尽 | 核心 | 不使用遗迹机缘模型 | 不使用遗迹机缘模型 |
| 建设与生产 | 不做 | 核心 | 文明系统自行决定 |
| 生态与文明 | 不做 | 不做完整文明 | 核心 |
| 所有权 | 遗迹 Site | Sect | 独立世界自身 |
| 生命周期 | 机缘逐步耗尽或崩塌后结束 | 当前会话内长期存在 | 当前会话内长期存在 |
| 存档恢复 | 不做 | 不做 | 不做 |

宗门驻地开始前，遗迹阶段只需确保 Runtime 可以存在“访客 Projection”和“用途自有实体”两类实体，不需要提前实现驻地建筑或文明人口。

### 宗门驻地产品轮廓

宗门驻地是一处由 Sect 拥有、在当前会话内长期运作的小世界领地。其最小完整循环应是：宗门开辟驻地 -> 指派成员常驻 -> 建造/维护设施 -> 消耗与产出真实宗门资源 -> 接待访客或抵御入侵 -> 宗门或入口消失时有序撤离。

它在遗迹底座上新增：

- `SectId -> InstanceId` 所有权和宗门权限，而不是 `RuinSiteId`。
- 长期 Resident 关系；访客可继续用短期 Projection，但常驻成员不能用“远征 Returning/Settled”状态假装居住。
- 建筑放置、施工、耐久、占地和通行变化。
- 驻地库存、生产任务、维护消耗和明确资源流。
- 宗门成员调度、来访、攻防以及宗门解散/入口摧毁后的清退。

它不使用 Opportunity、Exhausted、遗迹线索、战利品 claim 或 Collapse 作为日常主循环。遗迹阶段也不提前建立这些驻地系统。

### 完整独立世界产品轮廓

完整独立世界是当前会话中真正自主演化的另一片世界，不以主世界访客为人口主体。其最小完整循环应是：创建地貌与资源 -> 生成原生生物/人口 -> 生存、繁衍和迁徙 -> 形成聚落与势力 -> 发生冲突、交流和兴衰 -> 玩家持续观察。

它在共享底座上新增：

- 没有 `SourceActorId` 的 NativeEntity 生命周期与繁衍。
- 本地资源、生态、人口、聚落、势力和文明时间推进。
- 小世界内部的长期空间所有权、建设、战争和事件。
- 可选的主世界入口与访客适配；没有入口时仍能被创建、模拟和观察。
- Owner、`SubWorldAnchor` 与 WorldView Host 解耦，不能把遗迹 Building 或周边 Slot 当作世界本体身份。

它不使用遗迹的逐步耗尽目标，也不能靠复用原版第二个 `MapBox` 假装完成。只有遗迹发布后已经证明 Grid、Runtime、Navigation、用途自有实体和多实例调度可靠，才开始设计原生文明；否则会再次得到一个只有平台名词、没有可玩世界的空计划。

## 最终完成标准

遗迹路线完成时，一处主世界遗迹对应一个当前会话共享 Runtime。修士能够由 AI 前往并进入连续开放的遗址，根据已观察地貌、遗构和道痕寻找多个独立机缘，在危险区与守卫之间权衡继续深入或带着部分所得返回。已调查遗构、已稳定残阵、死亡守卫、地形变化和已耗尽机缘由后续进入者继承；战利品只能由实际取得者带回且不会复制。

整个流程必须可由玩家在主相机下观察，但观察、聚焦和裁剪不改变结果。主世界 Actor 在 Binding 期间没有并发推进，退出后的伤势、奖励或死亡通过 Runtime Token 与主线程 Prepare/Commit/Rollback/Acknowledge 边界结算。切换世界或重新加载时全部小世界状态直接销毁，不恢复、不迁移、不保留孤立入口。完成这一产品后，宗门驻地和完整独立世界再分别复用已被遗迹验证的世界容器能力。
