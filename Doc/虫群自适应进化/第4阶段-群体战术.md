## 具体说明

### 步骤 1：活动候选

当前代码没有 `IActivityCandidateProvider`。虫群通过现有 `ActorJobSelectionRegistry.Register(TrySelectInsectJob, priority)` 接入工作选择，并在 `TrySelectInsectJob` 内部用只读领域候选比较效用，不把判断塞入 `PatchActor`。

领域内部候选：

```text
JobId
Category
Utility
Urgency
EstimatedDuration
Cooldown
ExclusiveGroup
Reason
CanStart
```

选择器只返回一个已经注册的 Job ID；具体阶段由现有 ActorJob/ActorTask 执行。多人攻城、护送和建立子巢继续使用现有 Coordination/集体活动服务，不把整个行动状态塞进单个 Job 选择器。

完整活动：

| 活动 | 主要参与者 | 触发条件 |
| --- | --- | --- |
| 照料幼虫 | 工虫 | BroodQueue 非空 |
| 搬运生物质 | 工虫 | 存在可达 Deposit |
| 修复巢核 | 工虫 | 巢核受损且有生物质 |
| 巢边警戒 | 兵虫、重甲虫 | 常态最低防御需求 |
| 区域巡逻 | 兵虫、翼侦虫 | 威胁低且人口充足 |
| 捕猎 | 兵虫、喷吐虫 | 生物质不足且有合法目标 |
| 召回防御 | 全战斗职虫 | 母巢威胁达到阈值 |
| 攻击建筑 | 攻城虫及护卫 | 建筑压力和战略需求足够高 |
| 建立子巢 | 建巢母虫及护卫 | 阶段 5 的分巢条件满足 |
| 孤虫归巢 | OrphanedInsect | 原母巢失效 |

每次选择保留稳定 `Reason`，用于调试和只读 UI。候选计算只读 Actor、Hive 和已编译表现型，不直接修改 Actor 工作或 ECS 结构；选择成功后由现有工作系统应用 Job。只有未来出现第二个无法由注册优先级和领域内部比较解决的真实冲突时，才另行设计通用活动候选协议。

### 步骤 2：编组与信息

虫群按母巢和战术职责建立稳定小队：

- 每组 6 到 12 个单位，只属于一座母巢。
- 组长按神经等级、职虫适配和稳定 Actor ID 决定。
- 重甲虫优先前排，喷吐虫和骨刺单位保持后排，普通工虫不进入攻击组。
- 成员出生、死亡和归巢变化时增量维护，不定期全量扫描所有虫族。
- `ICombatGroupProvider` 向通用战术层公开成员、组长和默认 Directive。

威胁共享仅限同一母巢：

```text
TargetHandle
LastKnownPosition
ObservedAt
ThreatSemantics
Confidence
```

信息随时间衰减，目标失效后移除。子巢不与母巢实时共享目标。分布式神经只能降低组长死亡导致的信息损失，不能跨巢共享。

### 步骤 3：战术策略

`HiveTacticalPolicyService` 每月或在巢核威胁显著变化时重算：

```text
GuardRatio
PatrolRatio
HuntRatio
RetreatHealthThreshold
MaxPursuitDistance
FocusFireEnabled
AntiAirPriority
ProtectWorkersPriority
ProtectHivePriority
```

这些值属于可快速撤销的行为可塑性，不写入 Genome。已固化 Doctrine 只改变策略允许范围、效用权重和战术能力。

Doctrine 行为要求：

| Doctrine | 可观察行为 | 明确代价 |
| --- | --- | --- |
| 猎空反射 | 对空目标保持，远程单位优先集火 | 地面近敌权重下降 |
| 焦点神经节 | 小队共享高威胁单体并集中攻击 | 对大量分散敌人反应变慢 |
| 分布式神经 | 组长失效后维持基础 Directive | 高级复杂指令效率下降 |
| 伤亡撤退反射 | 达阈值后放弃追击并回巢重组 | 可能错失即将完成的击杀 |
| 攻城协同 | 重甲护送、攻城虫破坏、工虫跟随回收 | 野外捕猎效率下降 |

Doctrine 验收以实际目标选择、位置和活动切换为准，不能只验证属性变化。

### 步骤 4：战斗系统接入

#### 防御规则

虫族个体器官不再注册虫族专用伤害规则。它们统一通过组合生灵共享层已经注册的入口执行：

```text
Dispatcher = CreatureOrganEffectDispatcher
Stage      = FinalDamageStage.Adaptation
Source     = CreaturePhenotype
```

Dispatcher 只读取已提交 `CreaturePhenotype` 和已编译固定效果数组，按 EffectFamily、Rank、Slot 和 Organ 稳定解析。它只能在当前调用栈内修改当前伤害上下文。脱壳、再生、破裂等结构或状态后果写入有界 `CreatureConsequenceQueue`，在伤害热路径和 ECS Query 之外提交。

具体虫群器官不得各自注册全局伤害回调。虫群压力观察器只消费已经结算的伤害事实，不参与共享器官减伤执行。

#### 主动能力

酸液、骨刺和跃击由共享 `CreaturePhenotypeActiveAbilityProvider` 暴露：

- `Collect` 只读取 Actor 当前已编译表现型能力数组。
- `CanPrepare` 检查器官、形态、资源、冷却和目标关系。
- `ResolveAiWeight` 使用器官静态 AI 画像、目标和通用战斗上下文。
- `ResolveTacticalProfile` 声明射程、用途、移动意图和目标类型。
- `TryUse` 通过 SkillV3 启动技能序列，不直接生成投射物。
- HiveTacticalPolicy 通过 Directive、角色、目标优先级和编组位置影响战斗，不让共享 Provider 反向依赖虫群领域。

实际 Ability 句柄：

```text
ProviderId = content.creature_phenotype
Source     = ActorExtend.E
EntryId    = SlotId + "/" + OrganId + "/" + AbilityId
```

当前代码没有 `SourceKind`、`ActorHandle` 或 `InstanceKey` 合同，不在虫群内新建同名平行模型。

孢子炮台不是 Actor 能力来源，不能把 Hive Entity 伪装成 `IActiveAbilityProvider` 的施法者。完成孢子炮台巢器官后，Hive 创建并拥有一个固定、不可繁殖的附着炮台 Actor；炮台通过 `HiveSporeTurretRelation` 归属母巢，并使用固定 Morph、共享孢子器官和同一 ActiveAbility Provider。巢器官拆除、母巢崩溃或世界清理时同步回收炮台 Actor 与关系。

#### 属性与 Status

- 共享属性 Contributor 读取 `CreaturePhenotype`，按已编译固定数组构建属性；虫群不重复注册器官 Stats Builder。
- 表现型变化只标记相关 Actor 的属性、语义、战斗和视觉缓存为脏。
- 永久器官不是 Status。
- Status 只表达腐蚀、中毒、脱壳脆弱期、蛹期和应激等运行时状态；需要随器官撤销的自身状态使用 `CreatureEffectStatusSource`。

#### 敌友与目标

- 同一技术 Kingdom 的不同母巢暂不互攻。
- 捕猎中立动物由捕食活动显式选择，不把自然生物全局设为敌国。
- 友军判断同时检查 Kingdom 和 HiveMembership。

### 步骤 5：攻城

新增固定职虫：

| 职虫 | 资产 ID | 基础职责 | 解锁 | 生物质 | 分化时间 |
| --- | --- | --- | --- | ---: | ---: |
| 攻城虫 | `Cultiway.InsectRavager` | 破坏建筑和固定目标 | 破城颚或攻城形态 | 32 | 5 个月 |

攻城活动必须满足：

- 存在已观察到且仍有效的建筑目标。
- 母巢保留最低护巢人口。
- 有足够护卫和预计返程资源。
- 攻城目标效用高于当前捕猎和防御需求。

重甲虫承担前排，攻城虫保持对固定目标的任务，喷吐虫压制守军，工虫只在战斗风险降低后回收。

### 步骤 6：母巢器官

巢器官由 Hive ECS 组件表达，不写 BuildingData，不是 Actor Trait。

| 器官 | 响应压力 | 实际作用 | 代价 |
| --- | --- | --- | --- |
| 厚壁巢核 | 母巢受损 | 改变 Building 防护与受击反应 | 孵化速度下降 |
| 多室孵化腔 | 生产不足 | 增加并行孵化槽 | 持续占用更多生物质 |
| 生物质储囊 | 资源溢出、远征 | 增加容量并降低腐败 | 更怕火焰 |
| 感知触须 | 突袭、发现不足 | 扩大威胁感知和召回范围 | 占用巢器官槽 |
| 孢子炮台 | 长期远程围攻 | 创建一只归属母巢的固定附着炮台 Actor，并表达共享孢子器官 | 与孵化和修复共享资源 |

巢器官建设使用生物质、模拟时间和独立槽位。厚壁、孵化腔、储囊和触须由 Hive Organ Contributor 影响 Hive/Building 领域状态；孢子炮台由 `HiveSporeTurretRelation` 管理附着 Actor 的唯一生命周期，避免让 Building/Hive Entity 绕过 Actor 主动能力合同。

### 步骤 7：诊断与验收

每次活动选择记录：Actor、Hive、候选数、获选活动、Utility、Urgency、Reason 和被拒原因。

验收：

1. 猎空反射使对空单位真实保持和集火飞行目标。
2. 伤亡撤退反射使小队真实放弃追击并返回巢核。
3. 焦点神经节在单体目标上形成共享目标，同时在分散敌人场景体现代价。
4. 组长死亡后，普通组失去高级协同，分布式神经组保持基础行为。
5. 攻城虫实际选择建筑、获得护送并使用破城能力。
6. 厚壁巢核改变实际受击结算，多室孵化腔改变实际并行队列。
7. 孢子炮台只创建一个有效附着 Actor，实际使用共享器官能力；母巢崩溃后同步回收。
8. 关闭相关 Doctrine、个体器官或巢器官后，对应行为和来源贡献被移除。
