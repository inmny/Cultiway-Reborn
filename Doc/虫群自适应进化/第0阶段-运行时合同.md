## 具体说明

### 步骤 1：世界清理边界

`MapBox.clearWorld()` 是唯一世界销毁边界。原版方法负责清理 WorldBox Actor、Building、地图模块和原版管理器；Cultiway 的两个长期 `EntityStore` 不会被原版识别，因此必须由 Mod 在同一边界显式清理。

现有 `Dispose -> TagRecycle -> RecycleDefaultEntitySystem` 只用于普通模拟期回收，不能承担世界清理：Actor 和 Book 的 `Dispose` 只向全局 `CommandBuffer` 写入标记，City 和 GeoRegion 也只是立即添加标记，真正删除要等后续 ECS 逻辑周期。世界切换期间调度器会停止，且 `StructuralChangeSystem` 和回收系统位于 GeneralLogic 后段；若等待新世界首个逻辑周期，旧实体和旧命令可能先被前面的系统观察或执行。Sect 库存根、世界根实体和通用 Event 队列也没有统一自动回收路径。

不新增 `WorldGeneration` 或 `WorldOwned`。世界级 ECS 状态按明确的组件和所属模块清理：

- Core 同步删除 `ActorBinder`、`CityBinder`、`BookBinder`、`GeoRegionBinder`、`SectInventoryBinder`、`WorldRecord` 和 Core 创建的世界期临时 Entity，而不是只清空 Manager 字典或添加 `TagRecycle`。
- InsectModule 同步删除 Hive、Trial、BiomassDeposit，并移除虫族个体组件和全部虫族关系。
- 各 Feature 清空自己的 Repository、运行时索引、Ingress、Command、Event 和延迟请求。
- LinkRelation 只表达引用，不负责删除目标；只有明确登记的 ChildEntities 才能按树形所有权级联清理。
- ApplicationScope 静态定义、Asset Library、`TagPrefab` Entity 和定义期 SourceGranted 技能容器不属于世界清理范围。
- 新增世界级 Entity 类型时，必须同时指定其 `clearWorld` 清理负责人；禁止把“下一次逻辑 Tick 会回收”作为清理实现。

清理顺序：

1. Prefix 停止模拟调度器和异步生产者，并拒绝新的 Ingress、Command 与 Event。
2. 清空 Feature 消息、Feature 结构请求以及全局 `ModClass.CommandBuffer`，使清理前尚未提交的旧世界操作失效。
3. 原版执行 `MapBox.clearWorld()`；原版对象 `Dispose` 期间仍可能向全局 `CommandBuffer` 写入旧世界回收标记。
4. Postfix 再次清空全局 `ModClass.CommandBuffer`，随后调用各 Feature 的 `ClearWorldState`，同步删除其实体并清空索引。
5. Core 同步删除剩余的通用世界 ECS Entity，重置 `WorldRecord` 等世界根对象，并清空 Actor、Book、City Manager 字典。
6. 在 `clearWorld` 返回后、任何新世界逻辑 Tick 之前，检查所有世界实体、关系、队列和结构请求计数均为零。

如果未来某个任务确实跨线程执行且不能在 Prefix 同步停止，可以捕获原版已有的 `MapBox.current_world_seed_id` 并在回调时比较；这只是异步任务的局部校验，不建立新的世界代次模型。

### 步骤 3：消息与查询合同

#### Ingress

Harmony Patch 和 WorldBox 回调只写入稳定输入：对象 ID、位置和已结算事实。它们不直接调用具体虫族服务。

初始输入类型：

```text
HiveCoreCreatedInput
HiveCoreDamagedInput
HiveCoreDestroyedInput
InsectActorCreatedInput
InsectDamageResolvedInput
InsectActorDiedInput
InsectActivityCompletedInput
```

#### Command

Command 表示领域变更请求，返回明确结果而不是模糊布尔值。阶段 0 只建立注册、排队、世界清理和执行合同，具体命令在对应玩法阶段增加。

完整命令族预留：Hive 生命周期、Membership、Biomass、Brood、Metamorphosis、Trial、Somatic Adaptation、Founder。

#### Event

Event 表示已经提交的事实。Handler 只能提出后续 Command，不能回滚原事务。Event 队列必须在 `clearWorld` Prefix 停止接收，并在清理流程中清空；阶段 0 需要为 `EventSystemHub` 建立统一清队列入口，不能只由个别 EventSystem 自行处理。

#### Query

Query 返回不可变 ReadModel：

```text
GetHiveOverview
GetHivePressureProfile
GetHiveGenome
GetActiveTrial
GetInsectPhenotype
GetBroodQueue
CollectHiveMembers
```

UI 和调试工具不能取得可写 Entity、组件数组或 Repository 内部集合。

### 步骤 4：系统执行顺序

| 阶段 | 职责 | 结构修改 |
| --- | --- | --- |
| Ingress | 消费 WorldBox 输入并转换为领域消息 | 禁止 |
| QueryAndPlan | 计算活动、生产和进化计划 | 禁止 |
| CommandExecution | 执行事务并修改现有组件 | 禁止直接改结构 |
| AbilityScheduling | 复用统一 Ability/Skill 调度 | 禁止 |
| ConsequenceExecution | 消费伤害、死亡和任务结果 | 禁止直接改结构 |
| StateTick | 处理模拟时间、衰减和到期事项 | 禁止直接改结构 |
| StructuralCommit | 创建/删除实体、组件、关系和执行形态转换 | 允许 |
| Maintenance/Recycle | 校验 Binder、关系和不变量并回收 | 仅通过提交边界 |

结构命令按进入队列的稳定顺序执行。ECS Query 内不得创建、删除组件或关系。

### 步骤 5：ECS 数据模型

#### Hive 实体

| 组件 | 核心字段 | 唯一写入者 |
| --- | --- | --- |
| `HiveTag` | 标记 | HiveLifecycleService |
| `HiveCoreBinder` | BuildingId | HiveLifecycleService |
| `HiveIdentity` | Serial、ParentSerial、GenomeGeneration、Seed、FoundedAt、State | HiveLifecycleService |
| `HiveBiomass` | Stored、Reserved、Capacity | HiveBiomassService |
| `HivePopulationState` | Total、Larvae、ByCaste、月均活跃人口 | HiveMembershipService |
| `HivePressureAccumulator` | Severity[]、Evidence[]、WorldMonth | HivePressureService |
| `HivePressureState` | Pressure[]、Evidence[]、HistoricalPeak[] | HivePressureService |
| `HiveSampleBank` | 有界语义样本数组 | HiveSampleService |
| `HiveGenome` | 职虫模板、巢器官、Doctrine、Memory | HiveEvolutionService |
| `HiveBroodQueue` | 固定容量环形队列 | HiveBroodService |
| `HiveTacticalPolicy` | 守巢、巡逻、捕猎和撤退参数 | HiveTacticalPolicyService |
| `HiveEvolutionSchedule` | 下次评估、序号、最后固化时间 | HiveEvolutionService |

#### Actor 虫族状态

| 组件 | 核心字段 |
| --- | --- |
| `InsectIndividual` | CasteId、MorphId、出生基因世代、BornAt、LifeStage |
| `InsectPhenotype` | Signature、固定五槽 ModuleIds、Version |
| `InsectFitnessState` | 伤害、击杀、职责、资源和失败指标 |
| `InsectObservationBudget` | 月份和个体压力贡献上限 |
| `InsectSomaticStress` | 主压力、严重度、濒死幸存、最后事件 |
| `InsectSomaticAdaptation` | AdaptationId、Potency |
| `InsectMetamorphosis` | 目标职虫、形态、完成时间和表现型签名 |

#### Trial 与临时实体

| 实体 | 组件 |
| --- | --- |
| Trial | `AdaptationTrial`、`TrialCohortMetrics`、`TrialDecision` |
| Deposit | `BiomassDeposit`：剩余量、过期时间、来源对象 ID |
| 携带者 | `BiomassCarrier`：携带量、来源 Deposit |
| 建巢母虫 | `FounderGenomePayload`：深拷贝快照和预留生物质 |
| 孤虫 | `OrphanedInsect`：原母巢序号和孤立时间 |

数组在实体创建时按固定上限分配；服务不得把共享临时数组写入组件。

#### 关系

```csharp
public struct HiveMembershipRelation : ILinkRelation
{
    public Entity Hive;
    public HiveMemberRole Role;
    public int GroupIndex;
    public Entity GetRelationKey() => Hive;
}

public struct HiveActiveTrialRelation : ILinkRelation
{
    public Entity Trial;
    public Entity GetRelationKey() => Trial;
}

public struct TrialCohortRelation : ILinkRelation
{
    public Entity Trial;
    public TrialGroup Group;
    public Entity GetRelationKey() => Trial;
}
```

- 一个 Actor 最多属于一座 Hive 和一个 Trial。
- 一座 Hive 最多指向一个活动 Trial。
- PopulationState 是增量缓存，Incoming Membership Links 是归属权威。
- AbilityGrant 和 StatusRelation 继续复用通用关系，不建立虫族平行所有权。

### 步骤 6：WorldBox 适配边界

`InsectWorldboxAdapter` 是唯一 WorldBox 转换入口，负责 Building/Actor 生命周期、伤害事实、位置和资产解析，以及领域命令要求的 WorldBox 生成操作。

- `ActorBinder` 继续由 ActorExtendManager 管理。
- `HiveCoreBinder` 只保存 Building ID 和可丢弃缓存。
- `HiveRepository` 只保存 `BuildingId -> Hive Entity` 可重建索引。
- 延迟任务保存稳定 ID，不保存裸 Actor、Building 或 Entity 引用；真正跨线程的任务额外捕获 `MapBox.current_world_seed_id`。
- Binder 失效时提交生命周期命令，不直接修补领域状态。

固定 ActorAsset 承担 `flying`、水陆强制属性、基础动画、体型碰撞和基础攻击骨架。ECS 承担属性贡献、伤害适应、Ability、Status、AI、生物质和遗传状态。

### 步骤 7：诊断与验收

诊断至少输出：

```text
ActorBinderEntityCount
CityBinderEntityCount
BookBinderEntityCount
GeoRegionBinderEntityCount
HiveCount
TrialCount
DepositCount
MembershipRelationCount
TrialRelationCount
HiveRepositoryCount
PendingIngressCount
PendingCommandCount
PendingEventCount
```

不变量：

1. 每个活动 Hive 能解析有效巢核 Building。
2. 每座 Hive 最多一个活动 Trial。
3. 每个 Trial 恰好被一座 Hive 指向。
4. 已结束 Trial 不再拥有 Cohort IncomingLinks。
5. 已回收 Hive 不再被 Actor、Trial 或 Founder Payload 引用。

验收流程：连续创建并清理世界至少三次，每次都在 `clearWorld` 返回后且新世界逻辑尚未运行时检查所有上述计数归零；清理前排队的请求和全局结构命令不会在新世界执行，ApplicationScope 定义、Prefab 和 SourceGranted 技能容器保持有效。

### 存档范围

当前版本明确不实现持久化：

- 不写 `ActorData`、`BuildingData`、`ModSaveManager`、JSON、SQLite 或自定义文件。
- 不为已保存的虫族 Actor/Building 增加无状态重建规则。
- 不设计版本号、迁移或兼容层。

未来持久化必须另写世界级快照设计，不改变当前 ECS 权威图。
