# 第0阶段-运行时合同

本阶段只确定虫群数据如何创建、运行和清理，不增加可见玩法，也不另建一套初始化、消息或全局调度框架。共享身体框架按[组合生灵与妖兽](../组合生灵与妖兽-摘要.md)阶段 0、1 独立实施；虫群阶段 0 可以先建立母巢运行合同，但在阶段 1 创建首个幼虫和实际身体（`CreaturePhenotype`）前，必须完成两个共享阶段。

## 具体说明

### 步骤 1：世界清理边界

`MapBox.clearWorld()` 是销毁旧世界的唯一入口。原版会清理自己的生物、建筑和地图，但不认识模组保存的两处长期运行数据，所以模组必须在同一次清理中把自己的数据全部删干净。

虫群模块在世界结束时清理自己的母巢、对照试验、尸体生物质残留、个体数据、归属关系、请求队列和索引。共用静态定义继续保留。

归属关系只表示谁属于哪座母巢；清理母巢时一并删除它拥有的子记录。

### 步骤 2：接入现有模块生命周期

不建立独立的功能注册器。`InsectModule` 只实现 `ICanInit`，由现有 `Content.Manager` 扫描和初始化，作为虫群服务、能力来源和处理流程的总入口。

定义和系统继续使用现有机制：

- 生物单位、建筑、阵营、工作、工作步骤和协同行动定义继续放在现有 `ExtendLibrary` 分部类（partial）中，通过 `OnInit`、`PostInit`、`GlobalPostInit` 和统一语义链接流程完成注册。
- 虫群处理流程组成一个 `InsectSystemGroup`，由 `InsectModule.Init()` 挂到现有 `ModClass.I.GeneralLogicSystems` 的明确位置。
- 持有世界状态的处理流程实现 `IWorldStateClearable`，由 `WorldSystemLifecycle` 统一发现和清理。
- 没有处理流程负责的少量索引才使用 `PatchMapBox.RegisterActionOnClearWorld`；不为清理再保存处理流程的全局实例。
- 阶段 0 不增加通用 `OnWorldCreated` 多播入口。当前不实现持久化，也没有需要在新世界恢复的虫族数据；出现真实需求后再接入现有世界生成事件或对应处理流程。

依赖方向作为虫族新代码的局部规则，不宣称由框架强制保证：

```text
虫群展示 -> 虫群只读资料 + 共用界面基础
虫群玩法 -> 共用身体规则 + 战斗 / 持续状态 / 生物特征 / 运行基础
共用身体规则 -> 核心；不能反向依赖虫群玩法
原版游戏转接 -> 虫群玩法 + 原版游戏
运行基础 / 核心 -X-> 虫群玩法
共用界面基础 -X-> 虫群玩法
```

运行时通用能力不得放进虫族目录形成平行框架。身体方案、固定形态、器官、身体组合编译和生物单位器官表达由 `Source/Content/CreatureCompositions/` 拥有；虫族目录只保存压力、对照试验、遗传模板、职虫、母巢经济、群体战术及其玩法转接代码。

### 步骤 3：玩法输入与只读边界

不建立独立的输入入口、修改请求、事件或只读查询总线。虫族按具体用例复用现有事件系统、玩法服务和运行记录增删请求。

#### 输入与事件

- 需要延迟处理的 WorldBox 输入，通过 `EventSystemHub` 发布有明确类型的事件；事件只保存稳定对象编号、位置、数值和已结算事实。
- 必须同步修改返回值或立即参与 WorldBox 生命周期的 Harmony 补丁，可以直接调用 `InsectWorldboxAdapter`，不强制绕过事件队列。
- 虫群事件表示已经发生的事实。处理器可以调用现有服务或提出虫族后续请求，但不建立第二套事件分发器。
- 本阶段只增加实际玩法需要的事件类型，并沿用现有事件系统。

首批事件类型随对应玩法实现，不在阶段 0 预建空类型。预计会覆盖巢核创建、巢核受击、巢核销毁、虫族生物单位创建、伤害结算、死亡和协调活动完成等事实。

#### 修改玩法数据与增删运行记录

虫群玩法请求与 `ModClass.CommandBuffer` 含义不同：前者说明想怎样改变虫群数据，后者只负责增删运行记录、组件和归属关系。

- 只有首个真实事务需要排队时，才在 `InsectSystemGroup` 内增加局部虫群玩法请求队列，不建设全局修改请求注册框架。
- 入队后由对应服务完成工作，并发布完成事实或结果记录。
- 服务修改现有组件；创建、删除运行记录、组件和归属关系时使用当前查询处理流程的命令缓冲区或现有全局 `ModClass.CommandBuffer`。

#### 只读访问

不建立查询总线。虫族服务提供普通同步查询方法，返回复制后的数据副本、数组和标量。界面只能读取运行记录的展示资料，不能直接修改虫群数据。

`HiveOverview`、`HivePressureProfile`、`HiveGenomeView`、`ActiveTrialView`、`InsectPhenotypeView` 和 `BroodQueueView` 等展示资料在对应界面需要时再增加。

### 步骤 4：接入现有系统执行顺序

不建立新的全局八阶段调度器。虫族系统挂到现有 `GeneralLogicSystems`，继续复用已有事件、技能、结构提交和回收阶段。

`InsectSystemGroup` 只规定虫族内部的确定顺序：

```text
InputConsumption
DomainUpdate
DomainRequestExecution
TimedUpdates
Maintenance
```

只在出现对应职责时增加处理流程，不为凑齐阶段表而创建空流程。技能通过现有 `IActiveAbilityProvider` 和 SkillV3 队列调度；战斗通过现有战斗能力来源与 `CombatWorldService`；协调活动和集体工程分别接入现有能力来源、行动计划器和执行器。

运行记录增删遵循现有提交机制：

- 结构请求写入当前查询处理流程的命令缓冲区，或在需要跨系统汇总时写入 `ModClass.CommandBuffer`。
- 只保证单个队列或单个 `SystemGroup` 内的稳定顺序，不承诺所有结构修改存在一个全局 `StructuralCommit` 总序。
- 后续系统必须观察提交后的结构时，将前后职责拆进相邻子组，利用现有处理组边界执行。

### 步骤 5：运行记录结构

#### 母巢运行记录

| 组件 | 核心字段 | 唯一写入者 |
| --- | --- | --- |
| `HiveTag` | 标记 | `HiveLifecycleService` |
| `HiveCoreBinder` | `BuildingId` | `HiveLifecycleService` |
| `HiveIdentity` | `Serial`、`ParentSerial`、`GenomeGeneration`、`Seed`、`FoundedAt`、`Phase` | `HiveLifecycleService` |
| `HiveBiomass` | `Stored`、`Reserved`、`Capacity` | `HiveBiomassService` |
| `HivePopulation` | `Total`、`Larvae`、`ByCaste`、月均活跃人口；供生产和压力折算直接读取 | `HiveMembershipService` |
| `HivePressure` | `WorldMonth`、`MonthlyEvidence[]`、`Pressure[]`（含当前值和衰减后的证据量）、`HistoricalPeak[]` | `HivePressureService` |
| `HiveSampleBank` | 有界语义样本数组 | `HiveSampleService` |
| `HiveGenome` | 各职虫的共享 `CreaturePhenotypePlan`、巢器官、群体策略、`Memory` | `HiveEvolutionService` |
| `HiveBroodQueue` | 固定容量环形队列 | `HiveBroodService` |
| `HiveTacticalPolicy` | 守巢、巡逻、捕猎和撤退参数 | `HiveTacticalPolicyService` |
| `HiveEvolutionSchedule` | 下次评估、序号、最后固化时间 | `HiveEvolutionService` |

#### 生物单位上的虫群数据

| 组件 | 核心字段 |
| --- | --- |
| `InsectIndividual` | `CasteId`、出生遗传代数、`BornAt`、`LifeStage`；虫群身份，不重复保存形态 |
| `CreaturePhenotype` | 共享权威身体记录：`BodyPlanId`、`MorphId`、按槽位排序的 `Organs`（元素类型为 `CreatureOrganEntry`）、`Signature`、`Revision` |
| `InsectObservationBudget` | 月份和个体压力贡献上限 |
| `InsectSomaticStress` | 主压力、严重度、濒死幸存、最后事件 |
| `InsectSomaticAdaptation` | `AdaptationId`、`Potency` |
| `InsectMetamorphosis` | 目标职虫、固定形态、完成时间和身体组合编号 |

#### 对照试验和临时记录

| 记录 | 组件 |
| --- | --- |
| 对照试验 | `AdaptationTrial`、`TrialCohortMetrics`、`TrialDecision`；参试虫的受伤、死亡和职责产出直接累计到甲组或乙组成绩 |
| 生物质残留 | `BiomassDeposit`：剩余量、过期时间、来源对象编号 |
| 携带者 | `BiomassCarrier`：携带量、来源生物质残留 |
| 建巢母虫 | `FounderGenomePayload`：随身遗传资料副本和预留生物质 |
| 孤虫 | `OrphanedInsect`：原母巢序号和孤立时间 |

数组在运行记录创建时按固定上限分配；服务不得把共享临时数组写入组件。

#### 关系

```csharp
public struct HiveMembershipRelation : ILinkRelation
{
    public Entity Hive;
    public HiveMemberRole Role;
    public int GroupIndex;
    public Entity GetRelationKey() => Hive;
}

public struct HiveActiveTrialRelation : ILinkRelation
{
    public Entity Trial;
    public Entity GetRelationKey() => Trial;
}

public struct TrialCohortRelation : ILinkRelation
{
    public Entity Trial;
    public TrialGroup Group;
    public Entity GetRelationKey() => Trial;
}
```

- 一个生物单位最多属于一座母巢和一个对照试验。
- 一座母巢最多指向一个活动对照试验。
- 人口组件（`HivePopulation`）放在母巢运行记录上，随成员加入、退出和职虫变化更新；生产与压力折算直接读取它，不反复遍历全部成员。
- 只有带 `TrialCohortRelation` 的参试虫会向所属 `AdaptationTrial` 的 `TrialCohortMetrics` 累计成绩；普通虫子不挂成绩组件，也不保存试验成绩。
- 器官主动能力由共享能力来源 `CreaturePhenotypeActiveAbilityProvider` 根据生物单位当前实际身体提供；当前代码没有 `AbilityGrant` 关系，不为虫群另造一套能力归属。
- 状态继续使用现有 `StatusRelation`；需要随器官撤销的自身状态由共享 `CreatureEffectStatusSource` 标记来源。

### 步骤 6：WorldBox 适配边界

`InsectWorldboxAdapter` 是唯一 WorldBox 转接入口，负责建筑和生物单位的创建、销毁、伤害事实、位置和定义解析，以及虫群玩法操作需要的 WorldBox 生成行为。

- `ActorBinder` 继续由 `ActorExtendManager` 管理。
- `HiveCoreBinder` 只保存建筑编号 和可丢弃缓存。
- 母巢索引（`HiveRepository`）只保存“建筑编号到母巢运行记录”（`BuildingId -> Hive Entity`）的可重建对应关系。
- 延迟任务保存稳定编号，不保存裸生物单位、建筑或运行记录引用。
- 绑定记录（Binder）失效时向虫群处理组提交生命周期请求，不直接修补玩法状态。

固定 `CreatureMorphAsset` 映射的生物单位定义（`ActorAsset`）承担 `flying`、水陆强制属性、基础动画、体型碰撞和基础攻击骨架。共享实际身体（`CreaturePhenotype`）承担器官属性、语义、伤害适应、主动能力和视觉；虫群自己的运行记录承担自动行为、生物质、压力、对照试验和遗传数据。

### 存档范围

当前版本明确不持久化虫群玩法数据，但必须保证原版存档不会保存半套对象：

- 不写 `ActorData`、`BuildingData`、`ModSaveManager`、`JSON`、`SQLite` 或自定义文件。
- 所有虫群幼体、职虫、建巢母虫和附着炮台的生物单位定义（`ActorAsset`）设置 `skip_save = true`。
- 在 `SavedMap.create` 收集建筑的边界增加精确过滤，只跳过虫群巢核及其虫群专属附属建筑；不临时删除世界对象，也不改写其他模组建筑。
- 不为虫族生物单位和建筑增加无数据重建规则，因为它们根本不能进入新存档。

保存过滤后，地图中不会留下失去母巢数据的虫群对象；其他生物单位和建筑正常保存。
