## 具体说明

### 步骤 1：初始对象与职虫

正式玩法只提供“放置原始母巢”神力按钮，不暴露直接生成职虫的正式按钮。

| 对象 | 程序编号 | 职责 | 初始可用 |
| --- | --- | --- | --- |
| 原始母巢 | `Cultiway.InsectHive` | 生产、资源、归巢中心 | 是 |
| 幼虫 | `Cultiway.InsectLarva` | 等待分化，无战斗能力 | 是 |
| 工虫 | `Cultiway.InsectWorker` | 采集、搬运、修复、照料 | 是 |
| 兵虫 | `Cultiway.InsectWarrior` | 近战、捕猎、巡逻、护巢 | 是 |

虫族使用一个不参与文明玩法的技术阵营（`KingdomAsset`）。三种职虫共享虫族公共特性（`Trait`）；以后可替换的器官不能写成永久出生特性。

### 步骤 2：生命周期

#### 母巢创建

1. WorldBox 创建巢核建筑。
2. WorldBox 转接层（`InsectWorldboxAdapter`）提交 `HiveCoreCreatedInput`。
3. 母巢生命周期服务（`HiveLifecycleService`）创建且只创建一个母巢运行记录。
4. 添加巢核绑定、身份、生物质、人口、孵化队列和初始遗传模板；程序组件见 `HiveCoreBinder`、`HiveIdentity`、`HiveBiomass`、`HivePopulation`、`HiveBroodQueue`、`HiveGenome`。
5. `HiveRepository` 建立可随时重建的“巢核编号到母巢记录”索引。
6. 写入初始生物质并开始第一批幼虫。

巢核建筑不保存母巢运行记录编号，避免地图对象和运行记录互相锁死。

#### 个体出生

1. 孵化队列（`HiveBroodQueue`）冻结职虫、成本和基础身体计划。
2. 孵化服务（`HiveBroodService`）消耗已预留生物质并生成幼虫。
3. 生物单位扩展记录（`ActorExtend`）获得 `InsectIndividual` 和共享 `CreaturePhenotype`；普通个体不添加成绩组件。
4. `HiveMembershipRelation` 指向母巢。
5. 到期后提交蜕变请求，在虫群处理组（`InsectSystemGroup`）允许统一增删数据的时机切换为工虫或兵虫，并通过 `CreatureExpressionService` 一次性完整应用已经确定的身体计划。

原版生物单位存档（`ActorData`）不保存职虫、母巢或实际身体数据。

#### 个体死亡

死亡适配器只提交事实。服务依次移除成员归属、更新人口，并按尸体价值创建生物质残留（`BiomassDeposit`）。如果死者带有 `TrialCohortRelation`，本次死亡再直接累计到所属试验的 `TrialCohortMetrics`；普通个体不保存死亡成绩。重复死亡或直接删除不能重复产生资源。

#### 母巢摧毁

- 母巢进入 `Collapsing`，停止生产。
- 未完成队列取消，预留生物质按规则损失。
- 成员解除归属关系并获得孤虫状态（`OrphanedInsect`）。
- 阶段 1 孤虫不会建立子巢；找不到兼容巢时野化并逐渐死亡。
- 所有关系解除后回收母巢运行记录。

### 步骤 3：生物质经济

生物质只存在于 `HiveBiomass`：

```text
Stored
Reserved
Capacity
```

约束始终为：

```text
Stored >= 0
Reserved >= 0
Stored + Reserved <= Capacity
```

生物质残留（`BiomassDeposit`）字段：

```text
SourceObjectHandle
WorldPosition
RemainingAmount
CreatedAt
ExpiresAt
ReservedByActor
```

循环：

1. 敌方或中立生物死亡后创建生物质残留。
2. 工虫预留一个可以到达的生物质残留。
3. 到达后提取不超过携带上限的生物质。
4. 工虫返回母巢范围并提交 `DeliverBiomassCommand`。
5. 生物质服务（`HiveBiomassService`）增加 `Stored`，并释放预留。
6. 生物质残留耗尽、过期或世界结束时回收。

虫族尸体只回收基础价值的 30%，避免死亡循环增殖。尸体对象消失不删除已创建的 生物质残留。

初始成本：

| 职虫 | 生物质 | 孵化/分化时间 |
| --- | ---: | ---: |
| 工虫 | 8 | 1 个月 |
| 兵虫 | 12 | 2 个月 |

### 步骤 4：生产与归巢

`HiveBroodQueue` 是容量 8 的固定队列：

- 入队时预留资源并冻结计划。
- 出生成功后正式消费，取消时按原因释放或损失预留。
- 队列只由 `HiveBroodService` 修改。
- 幼虫是可受击的真实生物单位，停留在巢核附近。
- 幼虫死亡造成真实生产损失。
- 只读查询内不能调用 `TransformInPlace`。

阶段 1 使用固定人口目标：基础容量 64，工虫 40%，兵虫 60%。人口不足时先恢复工虫，再补兵虫；尚不启用压力驱动比例。

成员归属规则（`HiveMembershipRelation`）：

- 一个个体最多属于一座母巢。
- 加入和退出只能通过 `HiveMembershipService`。
- 母巢人口（`HivePopulation`）随加入、退出和职虫变化更新，成员关系同时指向所属母巢。生产和压力折算直接读取这份数量，不反复遍历所有成员。

### 步骤 5：最小自动行为

| 活动 | 职虫 | 触发条件 | 完成事实 |
| --- | --- | --- | --- |
| 照料幼虫 | 工虫 | 队列非空 | BroodCareCompleted |
| 搬运生物质 | 工虫 | 存在可达且未预留的生物质残留 | `BiomassDelivered` |
| 巢边警戒 | 兵虫 | 常态 | GuardCycleCompleted |
| 捕猎 | 兵虫 | 生物质不足且存在合法目标 | EnemyKilled/InsectDied |
| 召回防御 | 工虫、兵虫 | 巢核受袭 | RecallCompleted |
| 孤虫归巢 | 孤虫 | 原母巢失效 | JoinHive/Failed |

阶段 1 只做最小活动候选，不加入编组、集火、撤退群体策略或攻城。

### 步骤 6：只读表现

CreatureInfo 注册“虫群实际身体”页面，只通过复制后的只读资料展示：

- 所属母巢。
- 出生遗传代数。
- 当前生命阶段和职虫。
- 固定形态。
- 基础共享身体组合编号。
- 当前职责。

未实现的五槽、个体终身适应和对照试验行显示明确空状态。界面不持有运行记录或可写数组。
