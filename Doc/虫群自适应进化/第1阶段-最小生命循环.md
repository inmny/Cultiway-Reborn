## 具体说明

### 步骤 1：初始对象与职虫

正式玩法只提供“放置原始母巢”神力按钮，不暴露直接生成职虫的正式按钮。

| 对象 | 建议资产 ID | 职责 | 初始可用 |
| --- | --- | --- | --- |
| 原始母巢 | `Cultiway.InsectHive` | 生产、资源、归巢中心 | 是 |
| 幼虫 | `Cultiway.InsectLarva` | 等待分化，无战斗能力 | 是 |
| 工虫 | `Cultiway.InsectWorker` | 采集、搬运、修复、照料 | 是 |
| 兵虫 | `Cultiway.InsectWarrior` | 近战、捕猎、巡逻、护巢 | 是 |

虫族使用一个技术性非文明 Kingdom。三种职虫共享虫族公共 Trait；任何未来可替换器官都不能写成永久出生 Trait。

### 步骤 2：生命周期

#### 母巢创建

1. WorldBox 创建巢核 Building。
2. Adapter 提交 `HiveCoreCreatedInput`。
3. HiveLifecycleService 创建且只创建一个 Hive Entity。
4. 添加 Binder、Identity、Biomass、Population、BroodQueue 和初始 Genome。
5. Repository 建立可重建索引。
6. 写入初始生物质并开始第一批幼虫。

Building 不保存 Hive Entity ID。

#### 个体出生

1. BroodQueue 冻结职虫、成本和基础表现型方案。
2. HiveBroodService 消耗已预留生物质并生成幼虫 Actor。
3. ActorExtend Entity 获得 `InsectIndividual`、共享 `CreaturePhenotype` 和 `InsectFitnessState`。
4. `HiveMembershipRelation` 指向母巢。
5. 到期后提交蜕变请求，在虫群 SystemGroup 的结构提交边界切换为工虫或兵虫，并通过 `CreatureExpressionService` 原子表达冻结计划。

ActorData 不保存职虫、母巢或表现型数据。

#### 个体死亡

死亡适配器只提交事实。服务依次结算基础 Fitness、移除 Membership、更新人口，并按尸体价值创建 BiomassDeposit。重复死亡或直接删除不能重复产生资源。

#### 母巢摧毁

- Hive 进入 `Collapsing`，停止生产。
- 未完成队列取消，预留生物质按规则损失。
- 成员解除 Membership 并获得 OrphanedInsect。
- 阶段 1 孤虫不会建立子巢；找不到兼容巢时野化并逐渐死亡。
- 所有关系解除后回收 Hive Entity。

### 步骤 3：生物质经济

生物质只存在于 `HiveBiomass`：

```text
Stored
Reserved
Capacity
```

约束始终为：

```text
Stored >= 0
Reserved >= 0
Stored + Reserved <= Capacity
```

BiomassDeposit 字段：

```text
SourceObjectHandle
WorldPosition
RemainingAmount
CreatedAt
ExpiresAt
ReservedByActor
```

循环：

1. 敌方或中立生物死亡后创建 Deposit。
2. 工虫预留一个可达 Deposit。
3. 到达后提取不超过携带上限的生物质。
4. 工虫返回母巢范围并提交 `DeliverBiomassCommand`。
5. HiveBiomassService 增加 Stored，并释放预留。
6. Deposit 耗尽、过期或世界结束时回收。

虫族尸体只回收基础价值的 30%，避免死亡循环增殖。尸体对象消失不删除已创建的 Deposit。

初始成本：

| 职虫 | 生物质 | 孵化/分化时间 |
| --- | ---: | ---: |
| 工虫 | 8 | 1 个月 |
| 兵虫 | 12 | 2 个月 |

### 步骤 4：生产与归巢

`HiveBroodQueue` 是容量 8 的固定队列：

- 入队时预留资源并冻结计划。
- 出生成功后正式消费，取消时按原因释放或损失预留。
- 队列只由 HiveBroodService 修改。
- 幼虫是可受击的真实 Actor，停留在巢核安全范围。
- 幼虫死亡造成真实生产损失。
- Query 内不能调用 `TransformInPlace`。

阶段 1 使用固定人口目标：基础容量 64，工虫 40%，兵虫 60%。人口不足时先恢复工虫，再补兵虫；尚不启用压力驱动比例。

Membership 规则：

- 一个个体最多属于一座 Hive。
- 加入和退出只能通过 HiveMembershipService。
- PopulationState 增量更新，并可用 IncomingLinks 校验。
- 关系与人口缓存不一致时记录诊断，不静默覆盖关系。

### 步骤 5：最小 AI

| 活动 | 职虫 | 触发条件 | 完成事实 |
| --- | --- | --- | --- |
| 照料幼虫 | 工虫 | 队列非空 | BroodCareCompleted |
| 搬运生物质 | 工虫 | 存在可达未预留 Deposit | BiomassDelivered |
| 巢边警戒 | 兵虫 | 常态 | GuardCycleCompleted |
| 捕猎 | 兵虫 | 生物质不足且存在合法目标 | EnemyKilled/InsectDied |
| 召回防御 | 工虫、兵虫 | 巢核受袭 | RecallCompleted |
| 孤虫归巢 | 孤虫 | 原母巢失效 | JoinHive/Failed |

阶段 1 只做最小活动候选，不加入编组、集火、撤退 Doctrine 或攻城。

### 步骤 6：只读表现

CreatureInfo 注册“虫群表现型”页面，只通过 Query ReadModel 展示：

- 所属母巢。
- 出生基因世代。
- 当前生命阶段和职虫。
- 固定形态。
- 基础共享表现型签名。
- 当前职责。

未实现的五槽、体细胞适应和 Trial 行显示明确空状态。UI 不持有 Entity 或可写数组。

### 步骤 7：验收

1. 放置母巢后只创建一个 Hive Entity。
2. 初始资源能够生产幼虫，并稳定分化为工虫与兵虫。
3. 新生 Actor ECS Entity 获得正确 Membership。
4. 工虫可采集 Deposit、运回并增加 HiveBiomass。
5. 兵虫能捕猎并产生新的 Deposit。
6. 母巢摧毁后停止孵化并处理全部成员关系。
7. 初始 `CreaturePhenotype` 能由共享编译器解析，且虫群身份、母巢和基因世代不进入表现型签名。
8. 清理世界后 Hive、Deposit、Membership、共享动态编译缓存和索引计数归零。
9. 单巢在无玩家干预下可以持续维持基础人口和生物质循环。
