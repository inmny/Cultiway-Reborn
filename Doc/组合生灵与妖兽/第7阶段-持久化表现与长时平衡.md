## 具体说明

### 步骤 1：持久化

#### Actor 级数据

`YaoPersistence` 对拥有非零 `YaoAwakeningPotential`、潜伏 `YaoGenome` 或正式 `Yao` 的 Actor 写入当前 Schema；普通候选只保存启灵积累，潜伏凡兽只保存 Potential/Genome 与谱系摘要，不能伪造空妖丹、Form 或生态状态：

```text
YaoAwakeningPotential (when nonzero)
Yao (when awakened)
YaoIdentity (when awakened or lineage-carrier metadata exists)
YaoBodyState (all authoritative Form plans + ActiveFormId, when awakened)
YaoOrganProvenance
YaoGenome
YaoDigestion
YaoCore
YaoEcologyState
YaoTribulationState
NirvanaState
CreatureLifecycleState reservation/counters
有界冷却与失败记忆
```

保存规则：

- 只保存稳定 ID、值类型、有界数组和世界模拟时间，写入 `ActorData.custom_data_string["cultiway.yao"]`，不覆盖其他 Feature 的键。
- `CreaturePhenotype` 整体、`CompiledIndex`、静态 Asset、SkillContainer、Sprite、Entity 和 Actor 引用不保存；当前共享快照从 `YaoBodyState` 重建。
- 当前 Job、路径、尸体对象、劫云和粒子不保存。消化队列中已经领取的语义碎片属于 Actor 状态并保存；未领取精华加载后消失。
- 所有 Form Plan 和基因数组深拷贝，不能共享反序列化数组；同步 `YaoBirthPayload` 不进入存档。
- 每个 JSON 块有当前 SchemaVersion；本项目不保留旧 Schema 兼容或迁移分支。

#### 加载顺序

1. `Actor.prepareForSave` 前缀在原版 SavedMap 收集同一 ActorData 时写入 `cultiway.yao` 当前快照。
2. 原版 `ActorManager.loadObject` 返回有效 Actor 后，先恢复可选启灵积累和潜伏基因；仅对已启灵快照恢复 `Yao`、身份、妖丹、`YaoBodyState` 和其他领域状态。
3. 校验所有静态 ID；缺失定义时记录完整错误并终止该 Actor 的妖兽恢复，不猜测替代器官。
4. `YaoFormPlanService` 重新编译 `YaoBodyState` 的当前和备用 Form Plan。
5. 从 ActiveForm 计划原子重建 `CreaturePhenotype`，刷新属性、语义、能力和视觉。
6. Preparation 继续使用 Actor 状态；Tribulation/Nirvana 根据已保存阶段和序号重建尚未发生的世界表现，或按定义执行一次中断结算，不能重放已经结算的落雷/保命消费。
7. 所有 Actor 加载完成后，从恢复的权威组件重建稀有谱系数量、领地候选、精华去重窗口和低频调度时间。

#### 世界级数据

首版不保存第二份妖兽世界文档，也不把运行时 StoreRoot 当作持久化载体：

- 未领取 `YaoEssenceDeposit`、劫云、落雷、粒子、路径和视觉租约都是短期世界对象，不保存。
- 天劫、涅槃、准备和已经领取的消化碎片由所属 Actor 的有界状态保存；加载后按阶段/序号重建尚未发生的表现。
- 稀有谱系数量、出生预算、领地和调度索引从恢复后的 Yao Actor 重建，不保存静态 Dictionary。
- 因而不接入当前全局 `ModSaveManager`，不产生存档槽、世界 ID 和原版 SavedMap 之间的双事务问题。

虫群当前仍不恢复 Hive、Trial 和 Biomass 状态；其自定义 Actor 使用 `skip_save`，巢核和附属 Building 在 SavedMap 收集时过滤。共享 `CreaturePhenotype` 的重建能力不能被误当作完整虫群存档。

### 步骤 2：UI 与日志

开始实现前遵守 `Prompts/UI.md`。UI 只消费不可变 ReadModel，不持有 ECS Entity、可写数组或静态 Asset 的可变引用。

#### 妖躯详情页

CreatureInfo 增加“妖躯”页：

| 区域 | 内容 |
| --- | --- |
| 总览 | 境界、妖力、原始物种、当前形态、领地状态 |
| 身体 | BodyPlan、Morph、复杂度使用和稳定度 |
| 器官 | 有序槽位、Rank、来源、收益、代价、当前是否休眠 |
| 血脉 | 主/隐性血脉、纯度、显性/隐性等位、代数 |
| 吞噬 | 三个消化条目、候选、进度、排异与抑制 |
| 妖丹 | 模式、品质、元素、稳定度、裂痕和神通 |
| 天劫/化形 | 准备、挑战波次、证据、备用形态和切换冷却 |
| 生态 | 当前 Job、目标原因、栖息地、食性和繁殖状态 |

布局要求：

- 复用现有 CreatureInfo 页面、`UiScrollPane`、分段条、池化 Row 和 Tooltip。
- 器官、血脉和消化列表使用稳定高度 Row，不在卡片内嵌套卡片。
- 超长器官名、本地化说明、八槽满载、无血脉、无妖丹、天劫中和形态休眠都有明确状态。
- 正式 UI 不显示稳定种子、未压缩公式、缓存索引和完整评分数组。
- 正式 UI 没有安装、替换、提升器官的按钮。

#### Tooltip

器官 Tooltip 展示：

- 类别、Rank、占用槽位和兼容形态。
- 实际属性、语义、主动能力和反应。
- 来源、固化状态和是否可遗传。
- 资源、稳定度、速度或环境代价。

Tooltip 绑定到固定图标或字段，不能绑定滚动 Row 根节点。

#### WorldLog

记录：

- 凡兽启灵。
- 稀有器官炼化、严重排异和固血。
- 凝丹、裂丹、渡劫成功与死亡。
- 血脉返祖、首次蛟化、化形。
- 涅槃、九尾代命等稀有生命周期事件。
- 稀有血脉出生和谱系断绝。

日志必须包含主体、原因和结果，例如“青涧灵蛇在雷劫中以水息肺卸去劫火，凝成下品水行妖丹”，不能只输出资产 ID。

### 步骤 3：资源表现

视觉只表现已提交事实：

- 器官 Rank、Morph 和当前 Form 由共享视觉解析器决定。
- 消化、排异、天劫和涅槃由对应状态决定。
- 动画回调不能修改基因、器官、资源、伤害或进阶结果。
- 外观热重载可以刷新视觉；结构定义和身体 Rig 改动要求重新开始世界。

必须覆盖的动画：

| 动画 | 对象 | 触发 |
| --- | --- | --- |
| 启灵 | 凡兽 | `YaoAwakenedEvent` 已提交 |
| 吞噬/消化 | 妖兽 | Job 阶段与消化状态 |
| 器官显化 | 妖兽 | 新表现型已提交 |
| 凝丹/裂丹 | 妖兽 | 核心结算完成 |
| 天劫 | 妖兽与劫云 | Challenge 状态 |
| 返祖 | 妖兽 | 返祖表现型已提交 |
| 化形/返真 | 妖兽 | Form 切换完成 |
| 涅槃 | 凤凰系 | Nirvana 状态与结算 |
| 尾命代死 | 九尾狐系 | 生命周期后果已提交 |

### 步骤 4：性能预算

设计负载：

- 4096 个虫群组合个体。
- 1024 个活动妖兽，其中最多 128 个妖丹境及 16 个同时处于长期准备过程。
- 每个共享表现型最多 12 槽、三层可见覆盖层。
- 每个妖兽最多三个消化条目、两个血脉、八个位点和三个 Form Plan。
- 当前世界最多 8192 个独特已编译表现型。

复杂度目标：

| 操作 | 目标复杂度 |
| --- | --- |
| 一次属性缓存重建 | O(当前固定槽位数) |
| 一次伤害器官反应 | O(已编译被动效果数)，常数上限 |
| 主动能力枚举 | O(已编译主动能力数)，最多固定上限 |
| 一次表现型表达 | O(槽位 + 静态贡献)，只在结构变化时 |
| 一次启灵候选处理 | O(1) 事实摘要，按预算分片 |
| 一次消化结算 | O(符合样本的静态候选)，低频预算 |
| 一次遗传 | O(8 个位点) |
| 单个妖兽 ReadModel | O(自身有界状态) |

初始每帧预算：

| 工作 | 数量 |
| --- | ---: |
| 启灵候选评估 | 8 |
| 妖兽常规低频 Tick | 16 |
| 消化完成结算 | 4 |
| 表现型提交 | 8 |
| 后果队列 | 16 |
| 领地/繁殖评估 | 4 |
| 天劫推进 | 2 |
| 覆盖层仅处理 | 当前可见组合 Actor |

禁止：

- 每帧遍历所有动物寻找启灵候选。
- 在伤害、Ability Collect 或 Renderer 中编译表现型。
- 每帧为妖兽构建完整 `SemanticProfile` 或详情 ReadModel。
- 每个器官注册全局委托或拥有常驻 GameObject。
- 为混血、器官组合或形态组合动态创建 ActorAsset/BloodlineAsset。
- UI 关闭时构建妖兽详情、谱系或消化列表。

### 步骤 5：诊断

开发命令：

```text
creature.phenotype.dump <actorId>
creature.phenotype.verify <actorId>
creature.cache.stats
yao.dump <actorId>
yao.awakening.add <actorId> <value>
yao.awaken <actorId>
yao.essence.add <actorId> <fragmentId>
yao.digestion.resolve <actorId>
yao.progression.try <actorId>
yao.tribulation.resolve <actorId> <result>
yao.atavism.try <actorId>
yao.form.switch <actorId> <formId>
yao.verify
```

不变量：

1. 一个 Actor 最多一个 `CreaturePhenotype`，Signature 与计划重算一致。
2. `CompiledIndex` 能解析到相同 Signature，热路径无缓存缺失。
3. 每槽最多一个活动器官，多槽占用与容量一致。
4. 一个 Actor 最多一个 `Yao`、`YaoCore`、活动天劫和生命周期状态。
5. 消化队列不超过三项，同一尸体精华最多领取一次。
6. 主/隐性血脉纯度和位点权重不超过预算。
7. 当前 Form 必须存在于 `YaoBodyState` 且其权威计划已经编译；派生 `CreaturePhenotype` 的签名必须与 Active Form 一致，休眠器官不贡献能力。
8. 所有主动能力都有静态 Skill、AI 画像、目标关系和资源通道。
9. 覆盖层租约只属于可见且有效的当前表现型。
10. 加载后所有静态 ID 有效，领域索引可从权威组件重建。
11. 世界清理后妖兽实体外状态、请求、后果、Deposit、劫云和视觉池租约归零。

开发构建发现不变量失败时输出 Actor、表现型、槽位、来源和领域状态，不静默修复权威数据。

### 步骤 6：边界与平衡

| 场景 | 处理 |
| --- | --- |
| 凡兽直接删除 | 清理候选，不产生启灵或精华 |
| 妖兽被直接删除 | 清理领域状态，不伪造死亡/渡劫证据 |
| 消化时死亡 | 未完成样本丢失或按静态规则生成低阶精华 |
| 器官定义缺失 | 加载失败并诊断，不猜测替代器官 |
| 形态目标不可用 | 保留当前 Form，进入冷却 |
| 天劫时保存/加载 | 恢复 Challenge 或执行定义的中断结算 |
| 涅槃时世界清理 | 同步删除状态和视觉，不在新世界复生 |
| 血脉双亲死亡 | 已冻结出生 Payload 保持有效 |
| 妖丹裂痕达到上限 | 核心神通停用并触发明确修复/退化路径 |
| 结构定义热重载 | 要求重新开始世界 |
| 本地化/纯视觉热重载 | 允许 |
| 世界暂停 | 所有妖力、消化、进阶和天劫时间停止 |
| 世界倍速 | 模拟时间加快，每帧预算不变 |

平衡参数集中到 `CreatureCompositionBalanceProfile` 和 `YaoBalanceProfile`，共享结构上限与妖兽领域参数分开。

长期调优同时观察：

- 凡兽启灵率和达到各境界的时间分布。
- 器官多样性、替换率、排异率和主动能力使用率。
- 稀有血脉出生、稀释、返祖和断绝比例。
- 天劫成功率、裂丹率、死亡率和玩家干预影响。
- 妖兽捕食对普通生态的压力和种群承载。
- 各身体方案、谱系和形态的实际短板是否存在。

不能只按单挑胜率平衡，也不能用降低稀有度掩盖无代价的能力叠加。

### 步骤 7：最终验收

#### 共享表达

- 虫群和妖兽使用同一 BodyPlan/Morph/Organ/Phenotype 编译与表达服务。
- 替换器官或形态后旧属性、语义、能力、Status 来源和视觉全部撤销。
- 相同实际组合跨领域得到相同签名和编译结果。

#### 妖兽循环

- 普通蛇可自主启灵、捕食、吞噬、炼化、进阶、渡劫、返祖和蛟化。
- 所有结果来自真实事实、静态候选和有代价结算，不复制目标代码或全部能力。
- 妖兽 AI 会使用新能力，并在资源、目标或形态不合适时回退。

#### 遗传与神话内容

- 两代遗传不继承总属性、不回溯无限祖先、不创建动态血脉。
- 九尾狐、凤凰、玄武、饕餮和鲲鹏由相同原子与生命周期设施表达。
- 涅槃、尾命、双形和蛇尾都满足唯一 Actor、有限状态和中断规则。

#### 存档

- 在启灵、消化、凝丹准备、天劫、返祖、化形和涅槃各阶段保存加载后，`YaoBodyState`、领域状态与派生表现型一致恢复，或按明确规则中断。
- `CreaturePhenotype`、编译索引、Renderer、Entity 和动态容器不进入存档；没有第二份外部妖兽世界文档。

#### 性能

- 4096 个虫群个体加 1024 个妖兽下无逐帧全体扫描。
- 普通伤害、能力枚举和不可见单位不会产生组合编译或 ReadModel。
- 低频任务遵守每帧预算，世界清理无旧状态残留。
