# 第0阶段-共享表现型合同

本文所说的**表现型**，就是“这只生物当前真正长出来并生效的身体”。本阶段只搭建虫群和妖兽都能使用的身体组合底座：定义身体零件、保存当前身体、按照身体规则整理组合、生成组合指纹并缓存整理结果。本阶段不增加妖兽玩法、器官技能或外观附加图层。

## 具体说明

### 步骤 1：模块与目录

新增一个共用模块，由现有内容管理器自动发现和初始化。它只负责把定义库、组合整理器和后续共用系统接起来，不另造玩法注册中心或消息系统。

程序对应：

```text
CreatureCompositionModule : ICanInit
Content.Manager
```

建议目录：

```text
Source/Content/CreatureCompositions/
  CreatureCompositionModule.cs
  Components/       // 当前身体等运行时数据
  Libraries/        // 身体方案、形态和器官定义
  Models/           // 只在程序中传递的普通数据
  Services/         // 整理、缓存和提交服务
  ActiveAbilities/  // 阶段 1 按需增加
  Combat/           // 阶段 1 按需增加
  Persistence/      // 出现真实存档需求后再增加
  Presentation/     // 界面数据
  Systems/          // 逻辑系统
  Visuals/          // 阶段 1 的外观附加图层
```

本阶段只创建真正使用的目录和类型，不能为了目录整齐预建空系统。

依赖规则：

```text
Insects -> CreatureCompositions -> Core
Yao     -> CreatureCompositions -> Core
CreatureCompositions -X-> Insects / Yao
```

直白地说：虫群和妖兽可以使用共用身体规则；共用身体规则不能反过来读取虫群母巢或妖兽修炼数据。它可以使用项目已有的通用生物特征和技能定义，但不能引用以下玩法专属类型：

```text
HiveGenome
InsectAdaptationProfile
YaoGenome
YaoCore
```

### 步骤 2：静态定义

#### 身体方案

身体方案说明“一类身体能长什么”。它规定槽位、允许的固定形态、身体可承受的复杂度和外观锚点。

程序对应：

```text
CreatureBodyPlanAsset
  Id
  SlotIds[]
  AllowedMorphIds[]
  BaseComplexityCapacity
  MaximumOverlayLayers
  VisualRigId
  Tags[]

CreatureBodySlotAsset
  Id
  AcceptedCategoryMask
  Capacity
  SymmetryMode
  VisualChannel
  Required
```

规则：

- 同一身体方案中的槽位编号不能重复，并按定义顺序形成固定顺序。
- 一个身体方案最多 12 个槽位；单个槽位容量为 1 到 8。
- 对称规则只说明器官是单个、成对还是合并展示，不能为了左右器官无限增加子槽。
- 外观通道只决定附加图层的竞争和前后顺序，不能参与器官成长选择。
- 虫群可以使用五槽，妖兽可以使用八槽，共用代码不能把其中一种数量写死。

#### 固定形态

固定形态负责那些必须由完整生物单位模板决定的内容，例如飞行、能否下水、碰撞、基础动画、体型和基础攻击。器官可以要求或解锁某个固定形态，但不能仅靠加属性就把这些底层能力改掉。

程序对应：

```text
CreatureMorphAsset
  Id
  BodyPlanId
  ActorAssetId
  LocomotionKind
  LockedSlots[]
  AddedSlotCapacity[]
  BaseComplexityModifier
  VisualRigId
  Tags[]
```

其中 `ActorAssetId` 指向原版或模组已经制作好的生物单位模板。

#### 器官

器官定义说明“这个器官长出来后会发生什么”，包括占用哪些槽位、能装在哪些身体上、提供哪些属性与能力、有什么冲突，以及如何显示。

程序对应：

```text
CreatureOrganAsset
  Id
  Category
  AllowedBodyPlanTags[]
  AllowedMorphTags[]
  SlotRequirements[]
  PrerequisiteOrganIds[]
  ConflictOrganIds[]
  RankIds[]
  Semantics
  EffectFamilyIds[]

CreatureOrganRankAsset
  Id
  Rank
  ComplexityCost
  StatValues[]
  SkillContainerIds[]
  EffectRanks[]
  VisualLayerIds[]
  UpkeepDescriptor
```

必须遵守：

- 器官只描述生效结果，不保存虫群压力、对照试验、样本需求、妖力、血脉纯度或天劫条件。
- 占多个槽位的器官必须预先声明具体占用和容量，装上后不能临时扩张数组。
- 属性使用稳定编号和值；复杂能力引用预先制作的效果或技能，不能保存任意程序类型名、反射方法或脚本字符串。
- 维护代价只是一份供虫群或妖兽读取的说明。共用层只统计，不直接扣生物质或妖力。

### 步骤 3：运行时数据

虫群或妖兽先提交一份不可修改的身体组合方案：

```text
CreaturePhenotypePlan
  Version
  BodyPlanId
  MorphId
  Organs[]

CreatureOrganEntry
  SlotId
  OrganId
  Rank
```

生物单位在运行时挂一份“当前真正生效的身体”，它不进入存档：

```text
CreaturePhenotype : IComponent
  Version
  BodyPlanId
  MorphId
  Organs[]
  Signature       // 组合指纹
  Revision        // 第几次身体变更
  CompiledIndex   // 当前世界中的整理结果编号
```

整理后的结果供属性、能力、战斗和外观直接读取：

```text
CompiledCreaturePhenotype
  Signature
  Morph
  OrderedOrgans[]
  Stats[]
  Semantics[]
  ActiveAbilities[]
  PassiveEffects[]
  VisualLayers[]
  ComplexityUsed
```

所有数组必须满足：

- 创建时分配，之后只归一个拥有者使用。
- 从模板、父母、母巢或存档建立时必须完整复制，不能共用同一数组。
- 查询、受伤和绘制时只能读取，不能原地增删。
- 替换身体时要先建立一份全新的完整记录，再整体提交；旧数组不能继续被其他对象引用。

当前世界中的整理结果编号只用于加快查找，不放进组合指纹和存档。读档后根据组合指纹重新整理并写回编号。

妖兽在后续阶段还会有一份永久身体总表 `YaoBody`。它保存全部真身和人形方案，也是妖兽永久身体的唯一记录。这里的 `CreaturePhenotype` 只表示当前正在生效的一个形态，供属性、战斗、能力和外观快速读取；它不进入存档，也不能反过来改写 `YaoBody`。

共用的 `CreatureOrganEntry` 只包含槽位、器官和等级。器官来自先天、血脉、吞噬还是返祖，不属于共用身体效果。妖兽把来源放在 `YaoBody` 对应形态的器官资料里，虫群放在自己的遗传资料里。

### 步骤 4：身体整理与组合指纹

身体整理器 `CreaturePhenotypeCompiler` 在生成身体时直接遵守全部身体规则，不再单独设置校验服务，也不让多个入口重复检查。

整理顺序：

1. 读取身体方案和固定形态，按身体方案中的槽位顺序处理。
2. 把器官放入允许的槽位，并遵守单槽容量、多槽占用、锁定槽和形态限制。
3. 处理前置器官与冲突器官，确保总复杂度不超过当前身体容量。
4. 合并属性和生物特征，并按预定规则整理主动能力和被动反应。
5. 每个外观通道只保留最终显示的图层。
6. 生成组合指纹、整理结果和当前世界缓存编号。

虫群和妖兽各自负责生物质、境界、血脉纯度和身体稳定度等成长条件；共用整理器只处理身体本身的槽位和组合规则。

组合指纹按固定顺序生成：

```text
Version
BodyPlanId
MorphId
for slotId in BodyPlan.SlotIds:
  slot.Id
  organs = 以 OrganId、Rank 排好的本槽器官
  organs.Count
  for organ in organs:
    organ.OrganId
    organ.Rank
```

组合指纹只记录身体方案、固定形态、器官和等级，不记录生物单位编号、名字、器官来源、母巢、对照试验、妖力、妖丹、冷却和临时状态。程序字段仍使用 `Signature`。

整理结果 `CompiledCreaturePhenotype` 供属性、能力、战斗和外观直接读取。缓存使用组合指纹作为键，因此相同身体可以共用同一份整理结果。

缓存规则：

- 只保存静态定义引用和不可修改的小数组，不保存生物单位、建筑或玩法对象。
- 只在出生、蜕变、器官替换、返祖、固定形态切换和读档恢复时整理。
- 受伤、自动能力选择和绘制只读取现成结果。
- 当前世界最多保存 8192 种不同的整理结果；达到上限时淘汰最久未用的整理结果，腾出空间给新的身体组合，不能拒绝新的身体组合。
- 清理世界时清空组合缓存，静态定义继续保留。

共用层不能修改母巢遗传模板、孵化计划或妖兽血脉。调用方提交独立的身体方案，整理器返回只读结果。

程序对应：

```text
CreaturePhenotypeCompiler
CompiledCreaturePhenotype
CompiledIndex
Signature
```

### 步骤 5：生命周期

初始化时依次注册身体定义库、当前世界整理缓存和世界清理回调。属性、生物特征、技能、战斗和外观的实际接入由第 1 阶段完成。

清理世界时，直接清空本模块的整理结果缓存；当前身体随现有运行实体一起清除，静态身体、形态和器官定义继续保留。
