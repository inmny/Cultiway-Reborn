# 第6阶段-化形神通与神话谱系

本阶段让妖兽真正拥有“真身”“人形”和少数特殊的第二真身。玩家能看到蛟龙由蛇化蛟、鲲鹏在海空之间换形、凤凰涅槃、九尾狐以尾代命，而不是只看到属性数字变化。

九尾狐、蛟龙、凤凰、玄武、饕餮、鲲鹏等小说想象，仍然由同一套身体、器官、血脉、妖丹和神通规则组合出来。新增一种神兽时，不能再复制一套只供它使用的底层系统。

## 具体说明

### 步骤 1：形态与化形

一只妖兽可以拥有以下形态：

- **真身**：原始兽形或返祖后得到的主要兽形。
- **人形**：渡过化形劫后获得的固定人身。
- **第二真身**：只给鲲鹏等少数血脉使用，例如鲲形和鹏形。

无论妖兽拥有几种形态，同一时刻都只能使用一种。它的身份、血脉、妖丹、父母关系和修炼境界始终是同一份，不会因为变身而变成另一只单位。身份、境界、妖力和保命次数都保存在 `Yao` 中。

妖兽全部身体方案的唯一记录是 `YaoBody`。器官升级、返祖、换形和永久伤损都先写入 `YaoBody`，当前画面和能力再从中生成。不能把屏幕上正在使用的形态当成另一份永久记录。

与实现对照时，数据结构如下：

```text
YaoBody                              // 这只妖兽全部身体方案的唯一记录
  Forms[]                            // 它可以使用的形态
    FormId                           // 形态编号
    Kind                             // 真身、人形或第二真身
    BodyPlanId                       // 身体结构
    MorphId                          // 固定形态
    Organs[]                         // 妖兽自己的永久器官资料
      SlotId                         // 身体位置
      OrganId                        // 器官编号
      Rank                           // 器官等级
      Origin                         // 先天、血脉、吞噬、突破或返祖
    RequiredRealm                    // 所需境界
    RequiredBloodline                // 所需血脉
    Cooldown                         // 再次切换前的等待时间
  ActiveFormId                       // 当前正在使用的形态
  LastSwitchAt                       // 上次切换时间
  LockedUntil                        // 被封锁到何时
```

程序中的形态类别 `Kind` 对应：

- `TrueForm`：真身。
- `HumanForm`：人形。
- `AlternateTrueForm`：第二真身。

具体规则：

- 当前外观、属性和能力是从活动形态重新生成的快速读取结果，程序中称为 `CreaturePhenotype`。它来自 `YaoBody.Forms[ActiveFormId]`，不是第二份永久身体记录。
- `YaoBody` 中的每份器官资料保存位置、器官、等级和来源；器官列表统一叫 `Organs`。生成当前共用身体时，再转换成不带来源的 `CreatureOrganEntry`。
- 所有永久器官、器官等级、来源、返祖和形态变化，都由 `YaoFormPlanService` 写入 `YaoBody`。它同时更新受影响的其他形态。
- 器官在人形中的处理分为“保留”“显化”“休眠”，程序对应 `Retained`、`Manifested`、`Dormant`。
- `CreatureExpressionService` 只负责把当前形态显示和应用到游戏中，不保存备用形态。
- 当前形态不能使用的器官进入休眠：器官不会丢失，但不提供属性和能力。
- 临时伤势、冷却和资源默认跟随妖兽跨形态保留；只有规则明确说明时才例外。
#### 化形

对玩家来说，化形不是按一下按钮换贴图，而是妖丹境妖兽的一次大境界突破。它要准备人形方案、承受化形劫，并承担失败留下伤势的风险。

实现上，化形是妖修体系 `Yao` 从妖丹进入化形的重大进阶，程序类型为 `ProgressionKind.Major`。

#### 化形条件

- 已经凝结稳定妖丹，裂痕没有超过上限。
- 妖丹品质、妖力、灵智和身体稳定度达到要求。
- 已有可用的人形方案，程序资产为 `HumanFormRecipeAsset`。
- 当前没有挂着正在进行的 `YaoTribulation`、`Nirvana`，也不处于器官排异等禁止变身的过程。
- 特殊血脉还要满足自己的额外条件。

#### 人形会保留什么

人形使用一套真正可行走、攻击和受伤的固定动画，不会把真身图片直接缩成人形。

真身器官分三类处理：

- **保留**：灵瞳、灵窍、妖丹神通等在人形中继续生效，对应 `Retained`。
- **显化**：角、尾、翼等平时收起，需要时显示为有限的外观层或主动神通，对应 `Manifested`。
- **休眠**：巨口、完整龟甲和巨大体型等在人形中不再提供全部物理效果，对应 `Dormant`。

人形方案与实现字段的对照如下：

```text
HumanFormRecipeAsset                 // 人形方案定义
  ActorAssetId                       // 使用哪套可动画的人形单位资产
  BodyPlanId                         // 人形身体结构
  VisualProfileId                    // 外观方案
  RetainedOrganRules[]               // 保留哪些器官
  ManifestedAbilityRules[]           // 哪些器官改为显化神通
  StatConversionRules[]              // 真身属性怎样换算到人形
```

化形成功后，`YaoFormPlanService` 创建稳定的人形方案，并一次性加入 `YaoBody`。人形的总强度不能超过真身、境界和转换规则允许的上限。

#### 化形劫

化形劫要实际检验妖丹、灵智和身体重构，不是一次简单的随机判定：

- 妖兽要在劫难中维持新形态，并承受真实劫伤和妖力消耗。
- 失败可能损失准备、留下化形伤，或在一段时间内无法维持人形。
- 化形成功只代表获得人形，不会自动加入城市、文化、宗门或人类文明。

实现上，化形劫沿用进阶过程与天劫运行流程，程序入口为 `ProgressionStage`。

### 步骤 2：形态选择

妖兽根据环境和危险自主选择合适形态，不需要玩家逐只操作：

- 鲲形适合深水、长距离潜行和吞噬。
- 鹏形适合跨海、追击飞行目标和脱离包围。
- 蛟龙真身适合战斗和渡劫，人形更适合狭窄地形以及未来的社交玩法。
- 玄武真身适合正面防守；人形不能保留完整玄甲的减伤。

程序中的 `YaoFormDecisionService` 会隔一段时间比较以下因素，而不是每一帧反复计算：

```text
TerrainCompatibility       // 地形是否适合
CombatRole                  // 当前战斗职责
ThreatRange                 // 威胁距离
EscapeNeed                  // 是否急需逃生
ResourceCost                // 切换消耗
SocialContext               // 当前社交环境
CooldownPenalty             // 冷却惩罚
CurrentFormStickiness       // 继续保持当前形态的倾向
```

约束：

- 每种形态都有最短保持时间和切换冷却，不能在连续判断中来回闪烁。
- 战斗中切换是一个能被打断、会消耗妖力的主动神通。实现时由主动能力系统执行，程序接口为 `Active Ability`。
- 自主战斗判断必须真正理解新形态的射程、用途和代价，不能只换贴图。程序中通过 `ResolveAiWeight` 和战术说明完成。
- 玩家正式界面保持只读，不提供强制安装器官或逐只指定形态的编辑功能。玩家以后可以通过神力或改变环境间接影响妖兽选择。

### 步骤 3：保命神通

涅槃、尾命等能力都必须有次数、资源和恢复条件。涅槃累计次数和九尾剩余尾命直接保存在 `Yao` 中，不再建立通用生命次数数据。每只单位同一时刻最多启用一种此类能力，不能把多个保命规则无限叠加。

实现上，这些规则由 `CreatureLifecycleEffectAsset` 定义，并由共享后果队列执行后续变化。这里的“生命周期效果”是指会改变死亡、重生或身体阶段的规则。

#### 凤凰涅槃

玩家看到的完整过程是：凤凰受到致命伤时立刻消耗涅槃机会，化为可被破坏的涅槃体；若时间、资源和涅槃体完整性都满足要求，原凤凰在原地重生，否则真正死亡。

致命伤必须在造成死亡的当场拦住，绝不能先让单位死亡，再从稍后的队列中把它复活。实现流程如下：

```text
最终伤害阶段 FinalDamageStage.Survival 当场确认这次伤害会致命
  -> 当场检查涅槃心、剩余次数、妖力和冷却
  -> 在 Yao 中增加涅槃累计次数并扣除本次机会
  -> 当场把这次伤害改为不致命或无效
  -> 向 CreatureConsequenceQueue 写入后续处理请求
  -> 在妖兽单位上添加 Nirvana，进入不可行动的涅槃体阶段
  -> 检查经过时间、剩余资源和涅槃体完整性
  -> 原地恢复身体与能力，或者真正死亡
  -> 涅槃结束后移除 Nirvana
```

- `Survival` 是最终伤害流程中的“保命阶段”；它必须同步消费或预留资源，并立即改写本次伤害。
- `CreatureConsequenceQueue` 是稍后执行外观、状态和结构变化的后果队列。它不能承担“阻止这次死亡”本身。
- `Nirvana` 只在涅槃过程进行时挂在妖兽单位上，过程结束即移除；保存发生在涅槃期间时，它跟随该单位一起保存和读取。
- 每个大境界有涅槃次数上限，使用次数越多，下一次成本越高。
- 涅槃不会复制装备、妖丹或血脉。

#### 九尾代命

- 尾冠只分为 1、3、6、9 尾四个等级。程序中称为四个静态 `Rank`，不会创建九个独立器官。
- 遭受致命伤时，必须同样在 `FinalDamageStage.Survival` 当场从 `Yao` 扣除一个剩余尾命并拦住本次死亡，然后才能由后果队列进入短暂保命状态。
- 尾命格恢复需要世界时间、妖力和境界条件。
- 外观按 1、3、6、9 尾使用一张组合好的尾冠图片，不为每条尾巴创建一个绘制对象。

#### 饕餮吞天

- 深渊巨口、吞天胃和吞噬灵窍共同解锁吞天能力。
- 拉拽、吞尸和炼化共用三个消化位置和总容量，程序状态为 `YaoDigestion`。
- 活体吞噬只能对体型、生命和控制抗性符合条件的目标生效。
- 吞噬不会复制目标技能，最多产生已经登记的精华碎片。

#### 玄武蛇尾

蛇尾是主体身上的异质附肢，提供一层外观和一次附加攻击。它不是第二只会独立思考的单位，必须与玄武主体共享目标、冷却和伤害来源。

### 步骤 4：神话配方

| --- | --- | --- | --- | --- |
| 蛟龙 | 蛇形 -> 蛟形 -> 龙形 | 龙鳞、行云肺、雷角、龙瞳 | 蛟龙血脉、水/雷妖丹 | 行云布雨、雷息；换形和天劫成本高 |
| 九尾狐 | 狐形 + 人形 | 月华皮毛、尾冠、幻梦灵瞳、狐火腺 | 月狐血脉、阴火/幻梦妖丹 | 狐火、幻域、尾命格；正面承伤较弱 |
| 凤凰 | 鸟形 + 人形 | 火羽、真火灵窍、涅槃心 | 凤凰血脉、真火妖丹 | 炎域、涅槃；重生资源与次数严格受限 |
| 玄武 | 龟形 + 人形 | 玄甲、玄水肺、蛇尾、镇岳灵窍 | 玄武血脉、水土妖丹 | 玄甲姿态、黑水法域；速度和追击差 |
| 饕餮 | 重兽形 | 深渊巨口、吞天胃、吞噬灵窍 | 饕餮血脉、混沌妖丹 | 拉拽、吞噬、炼化；消化位置有限且饥饿代价高 |
| 鲲鹏 | 鲲形 <-> 鹏形 | 虚空胃、扶摇翼、风水灵窍 | 鲲鹏血脉、风水妖丹 | 海空双形、长距迁徙；切换冷却长且消耗大量妖力 |
| 白泽 | 鹿/兽形 + 人形 | 洞察灵瞳、辨邪角、记忆灵窍 | 白泽血脉、神识妖丹 | 识别并反制亲眼见过的能力；不能读取尚未发生的隐藏技能 |
| 穷奇 | 翼兽形 | 凶翼、裂风爪、噬战心 | 穷奇血脉、风煞妖丹 | 高速突击和追猎；恢复与群体协作较弱 |

表中的“固定形态”在程序中称为 `Morph`。每个配方至少有一个明确短板；神话名称不能免除器官槽、身体承载、资源消耗、自主判断和保命次数等限制。

### 步骤 5：新增神话内容

策划新增一种谱系时，只需要选择身体、器官、血脉、妖丹、形态、生态习惯和已有神通规则，不应先写一套新程序。

策划内容与程序资产的对照如下：

```text
BodyPlan / Morph 引用             // 身体结构与固定形态
Organ 与 Rank 引用                // 器官与器官等级
BloodlineAsset                    // 血脉定义
CorePatternAsset                  // 妖丹路线
FormRecipeAsset                   // 化形或第二真身方案
LifecycleEffectAsset 引用         // 涅槃、尾命等生命规则
EcologyProfile                    // 栖息地和行为倾向
本地化与资源
```

只有以下情况才需要新增 C# 代码：

- 现有技能系统 `SkillV3` 无法表达新的目标、释放方式或结果。
- 现有生命周期效果类别（程序中称为 `Effect Family`）无法表达已经明确的玩法。
- 现有自主战斗规则无法让生物正确使用该能力。

新增代码必须先做成可以复用的效果或能力，再交给谱系引用。禁止创建 `NineTailFoxSystem`、`PhoenixCombatPatch` 等只服务一个物种的平行底层系统。程序中的 `Effect` 指可复用效果规则，`Ability` 指可主动使用的能力。
