# 第2阶段-凡兽启灵垂直切片

本阶段实现第一条可玩的妖兽闭环：普通蛇在真实环境中自主启灵，获得妖修体系、基础身体组合、捕食行为、妖力资源和最小存档。暂不加入吞噬夺器官、血脉繁衍、妖丹和化形。

## 具体说明

### 步骤 1：基础内容

首个种族只选择原版 `snake`，避免一开始同时处理哺乳、鸟类、鱼类和大型单位的动画差异。

| 定义 | ID | 作用 |
| --- | --- | --- |
| 妖兽身体方案 | `yao.serpentine` | 妖兽八槽基线；蛇形暂未使用的槽位保持空值，不另造五槽遗传映射 |
| 凡蛇形态 | `yao.serpentine.base` | 映射原版 `snake` ActorAsset，不改变原版移动骨架 |
| 灵蛇形态 | `yao.serpentine.awakened` | 仍使用蛇形主动画，只增加有限体色/眼部覆盖层 |
| 表被器官 | `yao.scale.basic` | 小幅防护和鳞片视觉 |
| 天生武器器官 | `yao.venom.fang` | 近战毒牙能力与 AI 画像 |
| 感知器官 | `yao.spirit.sense` | 发现猎物和灵地的语义/行为加成 |
| 妖修体系 | `Yao` | 初始只有“启灵”境界和后续路线占位 |

灵蛇仍是蛇，不在本阶段创建蛇形 × 器官的动态 `ActorAsset`。形态变化只通过共享表现型和有限覆盖层表达。

### 步骤 2：启灵

#### 候选来源

凡兽不预先持有妖修组件。只为允许启灵的原版动物维护有界 `YaoAwakeningPotential`：

```text
YaoAwakeningPotential
  ActorId
  ExposureScore
  SurvivalScore
  HuntScore
  SpiritSiteScore
  LastEvaluatedAt
```

候选数据只由真实事实增加：

- 在有灵气地块持续生存。
- 捕食或击杀真实目标。
- 从濒死状态脱离战斗。
- 接触已注册的灵物或灵气区域。

不扫描全世界单位的隐藏 Trait、Skill 或理论战力。低频系统按稳定 Actor ID 分片，每次只处理有界候选数。

#### 启灵条件

首批基线：

```text
Age >= 2 年
ExposureScore >= 12
SurvivalScore >= 3
HuntScore >= 2
当前没有其他冲突修炼体系
当前存活且不在化形/夺舍状态
```

启灵条件只作为 `Yao` 体系的准入规则。候选通过后：

1. 创建 `Yao` 组件并设为启灵初始等级。
2. 创建 `YaoIdentity`、`YaoEcologyState` 和只含一个真身计划的 `YaoBodyState`；没有潜伏血脉时创建初始 `YaoGenome`，已有 `YaoGenome` 时深拷贝并按启灵规则表达。
3. `YaoBodyState.TrueForm` 使用蛇形身体方案、灵蛇形态和首批先天器官，其他妖兽基线槽位保持空值。
4. 由 `YaoFormPlanService` 把当前真身计划提交给 `CreatureExpressionService` 原子表达。
5. 给出初始妖力，不直接恢复满生命或重置年龄。
6. 发布 `YaoAwakenedEvent` 并写入 WorldLog。

启灵不是一次性全局扫描，也不会让附近所有蛇同时升级。

### 步骤 3：妖修基础

#### 独立体系

新增 `CultisysAsset<Yao>`，注册到现有 `ProgressionService`。它复用通用进阶的查询、准备、挑战、自然结算、授予和生命周期事件，但不复用 `Xian`、`XianBase`、`Jindan` 或 `Yuanying` 组件。

本阶段只激活一条等级：

| 等级 | 名称 | 作用 |
| ---: | --- | --- |
| 0 | 启灵 | 灵智、妖力、器官表达和妖兽 Job |

后续等级在对应阶段追加，不为未来空机制提前增加假的属性。

#### 妖力

`Yao` 组件最小字段：

```text
level
yao_power
awakened_at
progression_seed
```

新增 `MaxYaoPower` 与 `YaoPowerRegen` 统计项，以及一个 `SkillCastResourceAsset`：

- `IsAvailable` 只对有 `Yao` 的 Actor 为真。
- 读写 `Yao.yao_power`，所有变化经过 `YaoResourceService`。
- 技能消耗由 SkillV3 的资源报价决定。
- 妖力恢复使用世界模拟时间，暂停不推进，倍速不改变每帧工作预算。

妖力不是把 `Xian.wakan` 复制一份改名。两者共享 SkillV3 资源接口，但余额和所有权完全独立。

#### 属性贡献

`Yao` 的境界基础属性和妖力统计由妖修领域的单一 Contributor 提供；器官属性仍由共享表现型 Contributor 提供。两者不能在两个 Builder 中重复加同一项。

### 步骤 4：生态 AI

妖兽不加入 City、Culture、Clan 或普通文明建筑队列。它先使用现有 Job/Task 选择边界：

```text
ActorJobSelectionRegistry.Register(TrySelectYaoJob, priority)
```

`TrySelectYaoJob` 在领域内部按固定候选顺序和效用选择一个 Job，保存稳定的 `YaoDecisionReason` 供诊断和 UI 使用。此阶段不创建不存在的 `IActivityCandidateProvider`。

最小 Job：

| Job | 触发 | 完成事实 |
| --- | --- | --- |
| 灵地休整 | 妖力低且附近有安全灵气地块 | `YaoMeditationCompleted` |
| 捕食 | 饥饿或需要进阶证据，存在合法猎物 | `YaoPreyKilled` |
| 进食 | 有自身击杀的普通尸体 | `YaoFed` |
| 领地巡行 | 妖力和饥饿稳定 | `YaoTerritoryPatrolCompleted` |
| 逃离威胁 | 当前生命低或目标强度过高 | `YaoRetreated` |

行为规则：

- 只选择 Actor 已经能到达或已经观察到的目标。
- 不把所有动物改成敌国；捕食通过显式目标判定完成。
- 同一妖兽每次只保留一个主 Job，避免 Job 与 Combat takeover 互相覆盖。
- 有主动毒牙能力时，普通战斗规划通过 `IActiveAbilityProvider` 发现并使用；没有目标或妖力不足时回退原版攻击。
- 同类妖兽首版不建立族群外交，不共享隐形情报。

### 步骤 5：表现与观察

新增 `YaoBodyState` 和 `YaoFormPlanService`：从本阶段起，前者是妖兽永久身体计划的唯一权威，后者是唯一写入者。阶段 2 只保存一个 `TrueForm` 计划和 `ActiveFormId`；共享 `CreaturePhenotype` 是当前计划的可重建表达结果，不反向成为妖兽存档或切形态的权威。

启灵表现计划：

```text
BodyPlanId = yao.serpentine
MorphId = yao.serpentine.awakened
OrganStates =
  scale.basic rank 1
  venom.fang rank 1
  spirit.sense rank 1
```

共享表达层负责：

- 鳞片色调和眼部覆盖层。
- 毒牙主动能力与攻击画像。
- 表被静态防护和语义。
- 感知语义供妖兽目标选择读取。

新增只读 `Yao ReadModel`，不持有 ECS Entity：

- 是否已启灵、境界和妖力。
- 原始物种与启灵时间。
- 当前身体方案、形态和八个有序槽位；蛇形未使用槽显示为空。
- 每项器官的收益、代价和来源“先天”。
- 当前 Job、领地摘要和最近三条行为原因。

详情页沿用 `CreatureInfoPages` 和公共滚动结构，正式 UI 不显示内部种子和候选公式。

### 步骤 6：存档

从本阶段起，凡兽启灵积累和妖兽 Actor 级状态都必须可跨存档恢复。使用现有 `Actor.prepareForSave` 与 `ActorManager.loadObject` 补丁模式，新增 `YaoPersistence`；它处理拥有非零 `YaoAwakeningPotential`、潜伏 `YaoGenome` 或正式 `Yao` 的 Actor。

保存内容只允许：

```text
SchemaVersion
YaoAwakeningPotential when nonzero
Yao component values when awakened
YaoIdentity stable values when awakened
YaoBodyState one true-form plan, active form and stable IDs when awakened
YaoGenome initial/latent bounded values when present
YaoEcologyState bounded values when awakened
```

禁止保存：

- ECS Entity、Actor、Delegate、动态 SkillContainer 和 SpriteRenderer。
- 编译索引、缓存引用和临时目标引用。
- 当前路径对象和已经失效的尸体对象。

加载顺序：

1. 原版 Actor 已创建并可取得 `ActorExtend`。
2. 读取当前 Schema；缺失或损坏时记录错误并丢弃该妖兽扩展状态，不伪造半恢复对象。
3. 先恢复可选 `YaoAwakeningPotential` 和潜伏 `YaoGenome`；只有存档中已启灵时才恢复 `Yao`、身份、`YaoBodyState` 和生态状态。
4. 对已启灵 Actor，通过 `YaoFormPlanService` 校验当前 Form，并调用共享编译器/表达服务重建 `CreaturePhenotype`；凡兽候选不创建表现型。
5. 重建只读索引和下一次行为时间。

### 步骤 7：验收

1. 普通蛇在没有足够真实经历时不会随机启灵。
2. 同一世界不同灵气区域的蛇，达到启灵的时间分布不同。
3. 启灵后只有该 Actor 获得 `Yao`、妖力和组合表现型。
4. 灵蛇能在妖力不足时休整，在有猎物时捕食，在受伤时撤退。
5. 毒牙能力被战斗系统真实选择并消耗妖力，不能只在详情页显示。
6. 替换或清理表现型后所有共享来源正确对账。
7. 保存、重新加载和继续模拟后，境界、妖力、`YaoBodyState`、派生器官表达、形态和行为状态一致。
8. 清理世界后没有 Yao 候选、领域请求、渲染租约和临时索引残留。
9. 一次处理预算不会逐帧遍历所有 `ActorAsset.units`。
