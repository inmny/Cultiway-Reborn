# 第2阶段-凡兽启灵垂直切片

本文所说的**表现型**，就是“这只生物当前真正长出来并生效的身体”。本阶段实现第一条能实际游玩的妖兽循环：一条普通蛇根据真实生存经历自主启灵，获得基础妖修、身体组合、捕食行为、妖力和最小存档。本阶段暂不加入吞噬夺取器官、血脉繁衍、妖丹和化形。

## 具体说明

### 步骤 1：基础内容

启灵范围直接开放原版动物：蛇、狼、熊、龟、狐、鳄鱼、蛙、兔、鼠、鸡、羊、企鹅和龙。蛇形真身保留毒牙特色，其余动物统一使用兽形方案，肉食物种额外获得兽牙；这些动物共用同一套八槽身体规则，不再逐物种处理动画差异。

| 玩家和策划看到的内容 | 程序编号 | 作用 |
| --- | --- | --- |
| 蛇形身体方案 | `yao.serpentine` | 使用妖兽八槽基线；蛇暂时不用的槽位保持为空，不另做五槽遗传规则 |
| 凡蛇固定形态 | `yao.serpentine.base` | 使用原版蛇的生物单位模板，不改变原版移动和动画骨架 |
| 灵蛇固定形态 | `yao.serpentine.awakened` | 仍使用蛇形主动画，只增加有限体色、眼部和鳞片附加图层 |
| 基础鳞片 | `yao.scale.basic` | 提供少量防护和鳞片外观 |
| 毒牙 | `yao.venom.fang` | 提供近战毒牙能力和自动使用倾向 |
| 灵觉 | `yao.spirit.sense` | 帮助发现猎物和灵气地点 |
| 妖修体系 | `Yao` | 本阶段只有“启灵”境界，并为后续境界保留正式路线 |

灵蛇仍然是一条蛇。本阶段不能为了每种器官组合创建新的生物单位模板，身体差异只通过共用当前身体数据和数量受限的附加图层表现。

程序对应：

```text
ActorAsset = snake
CreatureBodyPlanAsset = yao.serpentine
CreatureMorphAsset = yao.serpentine.base / yao.serpentine.awakened
CreatureOrganAsset
```

### 步骤 2：启灵

#### 哪些凡兽进入候选

普通动物不会预先拥有妖修组件。只有允许启灵且已经积累过真实经历的动物，才保存一份启灵总分：

```text
YaoAwakeningPotential
  TotalScore             // 启灵总分，不区分分项
  NextSurvivalEligibleAt // 濒死幸存判定的冷却
```

只有以下真实事件可以增加总分：

- 在灵气浓度高的地块持续生存（按所在地块的灵气浓度低频加分，不要求地块存在灵脉）。
- 实际捕食或击杀合法目标（一次加一大截）。
- 从濒死状态中脱离战斗并活下来（一次加一大截，有冷却防止连续刷分）。

系统不能扫描全世界生物的隐藏原版特性、技能或理论战斗力。低频系统按稳定生物单位编号分批处理候选，每次只检查有限数量。

#### 首批启灵条件

```text
启灵总分至少 20（灵气接触、生存与捕食共同累加，不设分项门槛）
一次濒死幸存 +4 分，一次捕食 +4 分
灵气接触按所在地块的灵气浓度加分，浓度越高涨得越快
没有其他冲突的修炼体系
当前存活，且不处于化形或夺舍过程
```

这些条件只决定是否可以进入妖修体系。满足条件后按以下顺序启灵：

1. 创建 `Yao`，写入原始物种、启灵时间、稳定种子、启灵初阶和初始妖力；不能恢复满生命或重置年龄。
2. 创建只含一个真身的 `YaoBody`。真身采用蛇形身体方案、灵蛇固定形态和首批先天器官，每个器官条目的来源写为“先天”。
3. 没有潜伏血脉时建立初始 `YaoGenome`；已有潜伏血脉时完整复制并按启灵规则表达。
4. 妖兽身体服务从 `YaoBody` 取出当前真身，转换成共用身体方案，一次性让外观和能力生效。
5. 发布“妖兽已经启灵”的事实，并写入世界日志。

程序对应：

```text
Yao
YaoGenome
YaoBody.Forms[true_form]
YaoFormPlanService
CreatureExpressionService
YaoAwakenedEvent
WorldLog
```

启灵不能通过一次全世界扫描完成，也不能让附近所有蛇因为同一事件同时升级。

### 步骤 3：妖修基础

#### 独立修炼体系

新增一套独立妖修体系，并登记到现有进阶服务。它沿用项目已有的进阶查询、准备、挑战、自然结算、直接授予和完成事件，但不复用仙道的练气根基、金丹或元婴数据。

本阶段只启用一个等级：

| 等级 | 名称 | 玩家能看到的变化 |
| ---: | --- | --- |
| 0 | 启灵 | 获得灵智、妖力、器官表达和妖兽自动工作 |

后续等级在对应阶段正式加入，不能提前用空机制或虚假属性占位。

程序对应：

```text
CultisysAsset<Yao>
ProgressionService
Xian
XianBase
Jindan
Yuanying
```

#### 妖力

`Yao` 是这只妖兽自己的主数据，直接挂在生物单位扩展记录上：

```text
Yao
  OriginalSpeciesId     // 启灵前的原始物种
  AwakenedAt            // 启灵时间
  StableSeed            // 这只妖兽长期使用的稳定种子
  Level                 // 当前境界
  YaoPower              // 当前妖力
  NirvanaUses           // 凤凰等内容解锁后使用，首版初始为 0
  TailLives             // 九尾等内容解锁后使用，首版初始为 0
```

不再建立独立的妖兽身份组件，也不建立通用生命过程组件。原始物种、启灵时间、稳定种子、境界、妖力和首版保命次数都归 `Yao`。

新增妖力上限和妖力恢复两项属性，并登记一种现有技能系统可以消耗的妖力资源。

规则：

- 只有拥有妖修状态的生物单位才能使用妖力。
- 所有妖力读写都经过统一妖力服务，不能随意直接改字段。
- 技能消耗由现有技能系统的资源报价决定。
- 妖力恢复使用世界模拟时间；暂停时不恢复，世界加速不会增加每一帧的处理数量。

妖力不是把仙道灵气余额复制后换个名字。两者只共用技能资源接口，余额和所有权完全独立。

程序对应：

```text
MaxYaoPower
YaoPowerRegen
SkillCastResourceAsset
YaoResourceService
SkillV3
Xian.wakan
```

#### 属性来源

妖修境界和妖力属性由妖兽玩法的单一属性入口提供；器官属性由共用身体属性入口提供。两边不能重复增加同一项属性。

程序对应：

```text
Yao Contributor
CreaturePhenotypeStatsContributor
```

### 步骤 4：生态自动行为

妖兽不会加入城市、文化、家族组织或普通文明建筑队列。它先接入项目现有的工作与行动任务系统，不创造一套不存在的通用活动协议。

程序入口：

```text
ActorJobSelectionRegistry.Register(TrySelectYaoJob, priority)
```

妖兽玩法每次选择工作时，直接读取生物当前位置、饥饿和生命、妖力、当前身体、原版繁殖资料与附近环境，然后返回一个已经登记的工作编号。选择结果可以附带一条简短原因供当前界面显示，但不保存成独立生态组件。

首批工作：

| 工作 | 何时考虑 | 完成后记录的事实 |
| --- | --- | --- |
| 灵气地点休整 | 妖力低，附近存在安全灵气地块 | `YaoMeditationCompleted` |
| 捕食 | 饥饿或需要修炼经历，附近存在合法猎物 | `YaoPreyKilled` |
| 进食 | 存在由自己击杀的普通尸体 | `YaoFed` |
| 附近巡行 | 妖力和饥饿稳定，当前没有更紧迫需求 | `YaoPatrolCompleted` |
| 繁殖 | 原版繁殖条件满足，附近存在合适同类 | 原版繁殖结果 |
| 逃离威胁 | 当前生命过低或敌人明显过强 | `YaoRetreated` |

自动行为规则：

- 只能选择已经观察到且实际能够到达的目标。
- 不能把所有动物都设成敌对阵营；捕食由当前捕食工作明确选择目标。
- 同一只妖兽一次只保留一个主要工作，避免工作系统和战斗接管相互覆盖。
- 有毒牙主动能力时，现有战斗规划会发现并使用；没有合法目标或妖力不足时，退回原版普通攻击。
- 首版同类妖兽不建立族群外交，也不共享自己没有观察到的目标情报。

程序对应：

```text
Job / Task
TrySelectYaoJob
IActiveAbilityProvider
Combat takeover
```

当前代码没有 `IActivityCandidateProvider`，本阶段不能引用或新建一个同名平行接口。

### 步骤 5：身体与观察

从本阶段开始，妖兽永久身体只保存在 `YaoBody`。妖兽身体服务负责修改它。本阶段只保存一个真身方案和当前形态编号。

共用当前身体数据只是活动真身的派生结果，用于属性、能力、战斗和外观。它可以在读档时重新建立，不能反过来成为妖兽存档或切换形态的权威。

程序对应：

```text
YaoBody                        // 全部永久身体
YaoFormPlanService             // 唯一写入者
CreaturePhenotype              // 当前生效身体，可重建
Forms[]
ActiveFormId
```

启灵后的身体方案：

```text
YaoBody
  ActiveFormId = true_form
  Forms[]
    true_form
      BodyPlanId = yao.serpentine
      MorphId = yao.serpentine.awakened
      Organs[]
        scale.basic rank 1 origin innate
        venom.fang rank 1 origin innate
        spirit.sense rank 1 origin innate
```

`YaoBody` 中的器官资料保存槽位、器官、等级和来源。交给共用身体系统时，转换成只含槽位、器官和等级的 `CreatureOrganEntry`；来源只用于妖兽成长和界面，不进入组合指纹。

共用身体系统负责：

- 显示鳞片色调和眼部附加图层。
- 提供毒牙主动能力及其自动使用倾向。
- 提供基础鳞片防护和长期生物特征。
- 提供灵觉特征，供妖兽目标选择读取。

#### 只读详情

详情界面只读取一份不可修改的数据副本，不直接持有运行时对象。它显示：

- 是否启灵、当前境界和妖力。
- 原始物种和启灵时间。
- 当前身体方案、固定形态和八个有序槽位；蛇形没有使用的槽位显示为空。
- 每个器官的收益、代价和“先天”来源。
- 当前工作，以及本次选择工作时得到的简短原因。
- 从当前位置和附近环境即时整理出的栖息与繁殖摘要。

正式界面沿用现有生物详情页和公共滚动容器，不显示内部随机种子和完整候选公式，也不提供器官编辑按钮。

程序对应：

```text
YaoReadModel       // 妖兽界面只读资料
CreatureInfoPages // 生物详情页
Entity            // 运行时记录
```

### 步骤 6：存档

从本阶段开始，普通动物已经积累的启灵条件、潜伏血脉和启灵后的妖兽长期数据都必须跨存档恢复。

保存入口沿用现有生物单位保存和加载补丁模式。只有拥有非零启灵积累、潜伏血脉或正式妖修状态的生物单位需要写妖兽数据。

程序对应：

```text
Actor.prepareForSave
ActorManager.loadObject
ActorExtend
YaoPersistence
YaoAwakeningPotential
YaoGenome
Yao
Entity / Actor / Delegate
SkillContainer / SpriteRenderer / CompiledIndex
```

只允许保存：

```text
SchemaVersion
YaoAwakeningPotential // 仅普通凡兽有非零启灵积累时保存
Yao                   // 已启灵时保存原始物种、启灵时间、稳定种子、境界、妖力和首版保命次数
YaoBody               // 已启灵时保存一个真身、当前形态，以及带来源的器官资料
YaoGenome             // 有初始或潜伏血脉时保存，列表必须有上限
```

本阶段尚未加入消化和妖丹，因此不会创建 `YaoDigestion` 与 `YaoCore`。后续阶段加入后，妖兽长期数据也只会从 `Yao`、`YaoBody`、`YaoGenome`、`YaoDigestion` 和 `YaoCore` 这五类中按需添加。

不保存生态状态。妖兽加载后第一次选择工作时，重新读取当前位置、饥饿和生命、妖力、当前身体、原版繁殖资料和附近环境。

禁止保存：

- 运行时对象、生物单位引用、程序委托、动态技能容器和绘制对象。
- 整理结果编号、缓存引用和临时目标引用。
- 当前路径对象和已经失效的尸体对象。

加载顺序：

1. 原版生物单位完成创建后，读取妖兽存档。
2. 恢复启灵积累和潜伏血脉；已经启灵的生物再恢复 `Yao`、`YaoBody` 和 `YaoGenome`。
3. 妖兽身体服务读取当前真身，去掉器官来源后交给共用整理与提交服务，重建 `CreaturePhenotype`。
4. 安排下一次自动行为；生态行动在实际选择时重新计算。

不保存另一份全局妖兽世界文件。当前身体整理结果、短期目标和绘制对象都在加载后重建。

清理世界时，直接清空启灵候选、妖兽请求、当前世界索引和外观租用。
