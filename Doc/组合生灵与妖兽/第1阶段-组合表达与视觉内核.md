## 具体说明

### 步骤 1：表现型提交

`CreatureExpressionService` 是 `CreaturePhenotype` 派生快照的唯一写入者。虫群出生/蜕变直接提交冻结计划；妖兽启灵、炼化、返祖、形态切换和存档恢复必须先由 `YaoFormPlanService` 更新/读取 `YaoBodyState` 权威计划，再由它调用共享表达服务。任何领域都不能直接写组件字段。

提交顺序固定：

1. 校验并编译新的 `CreaturePhenotypePlan`。
2. 冻结旧表现型和旧编译结果。
3. 如 Morph 变化，先执行受控固定形态转换。
4. 整体替换 `CreaturePhenotype` 深拷贝快照。
5. 对账并移除旧来源拥有的运行时状态。
6. 标记 Actor 属性、语义、技能发现、战斗规划和图形缓存为脏。
7. 写入视觉刷新请求。
8. 发布只读 `CreaturePhenotypeExpressedEvent`。

提交要么全部成功，要么保持旧表现型。任何定义、形态或运行时校验失败都不能留下“外观已经换了但能力还是旧的”中间状态。

查询和渲染系统不能调用提交服务。领域 AI 先形成完整候选，在自身事务边界之外提交。

### 步骤 2：属性与语义

#### 属性

共享模块只注册一次：

```text
ActorExtend.RegisterCachedStatsBuilder(
  CreaturePhenotypeStatsContributor.Contribute)
```

Contributor：

- 检查 Actor 是否有 `CreaturePhenotype`。
- 通过 `CompiledIndex` 读取已编译固定属性数组。
- 按稳定顺序合并到调用方 `BaseStats`。
- 不查领域状态，不构建临时 Dictionary，不在回调中编译。

表现型提交后调用 `MarkCultiwayStatsDirty()`。单个器官不得注册自己的 Stats Builder。

#### 语义

`CreaturePhenotypeSemanticContributor : IActorSemanticContributor` 以稳定 `Id = content.creature_phenotype` 和确定性 `Priority` 注册到 `SemanticContributorService`，完整实现 `Contribute(ActorExtend, SemanticProfileBuilder)`：

- 形态与器官提供 `SemanticScope.Intrinsic` 长期语义。
- 现有 `SemanticSourceRef` 只有 Contributor ID、一个 Asset ID 和可选 Entity；本阶段把来源规范编码为 `BodyPlanId/MorphId/SlotId/OrganId` 的单个稳定 `asset_id`，不扩展 Core 来源结构。
- 临时排异、劫伤和消化不进入表现型语义，由 Status 或妖兽领域贡献器负责。
- 表现型替换后只标记语义缓存为脏，不主动扫描消费者。

### 步骤 3：主动能力

器官引用的 SkillV3 容器在定义初始化时以 `SkillContainerBuildMode.SourceGranted` 构建并由 `SourceGrantedSkillRegistry` 持有。禁止为每个 Actor、每次出生或每次能力枚举创建新容器。

共享创建一个 `CreaturePhenotypeActiveAbilityProvider : IActiveAbilityProvider, ISourceGrantedSkillProvider` 实例并分别调用：

```text
ActiveAbilityService.Register(provider)
SourceGrantedSkillService.Register(provider)
```

该实例实现两个不同的 `Collect` 重载：

- `IActiveAbilityProvider.Collect(ActorExtend, ICollection<ActiveAbilityHandle>)` 只读已编译能力条目。
- `ISourceGrantedSkillProvider.Collect(ActorExtend, ICollection<SourceGrantedSkillPresentation>)` 只读追加用于技能页展示的静态容器与本地化说明。

句柄合同：

```text
ProviderId = content.creature_phenotype
Source     = ActorExtend.E
EntryId    = SlotId + "/" + OrganId + "/" + AbilityId
```

Provider 必须完整实现：

- `Collect`：只读已编译能力数组，不同步表现型或修改结构。
- `GetChannels`：区分 Combat 与 World；首版器官能力主要使用 Combat。
- `Describe`：读取本地化名称、图标、目标模式与施法移动约束。
- `CanPrepare`：检查器官仍表达、资源、冷却、形态和目标关系。
- `CanUse`：检查实际射程、目标和当次运行时条件。
- `ResolveAiWeight`：结合静态能力画像和当前目标，不只返回固定高权重。
- `ResolveTacticalProfile`：向 `CombatWorldService` 公开输出、防御、控制、资源和范围。
- `ResolveRange`：只读编译条目的静态施法距离，不查询路径或临时构建技能。
- `ResolveEffectRadius`：只读编译条目的静态影响半径；无固定范围预览时返回 0。
- `TryUse`：通过 SkillV3 启动技能序列，不直接生成投射物或结算伤害。

同一 Effect Family 的能力按静态 `StackPolicy` 处理：

- `HighestRank`：只保留最高阶来源。
- `MergePotency`：保留一个句柄并合并受限强度。
- `Independent`：仅在资产明确允许且总主动能力上限未超出时分别暴露。

妖兽首版每个个体最多两个常规战斗主动能力；虫群可由身体方案设置更低上限。

### 步骤 4：被动反应

共享层只为所有组合器官注册一组稳定入口：

- `FinalDamageStage.Adaptation`：常规适应与器官减伤。
- `FinalDamageStage.Survival`：在 Shield/Cap 后确认致命性并执行常规保命预留。
- `FinalDamageStage.LastResort`：在常规保命失败后执行明确声明的最后手段。
- 实际伤害结算完成
- 造成伤害
- 击杀
- 死亡
- 技能施放完成
- 低频生命周期 Tick

`CreatureOrganEffectDispatcher` 从已编译 `PassiveEffects[]` 中按：

```text
EventKind -> EffectFamilyId -> Rank -> SlotId -> OrganId
```

稳定分发。单个器官不得独立注册全局委托。

可以在当前调用栈内完成的纯数值变化直接写伤害上下文。会阻止本次致命伤的效果必须在 `Survival` 或 `LastResort` 同步完成以下步骤：重新确认本次伤害致命、校验来源和次数/资源、在预先存在的 `CreatureLifecycleState` 中原子预留一次激活、把本次伤害改为非致命或无效。不能把“阻止死亡”本身延迟到 Queue。

预留成功后，涉及以下结构操作的后续部分进入有界 `CreatureConsequenceQueue`：

- 增删 ECS 组件或关系。
- 切换形态或替换器官。
- 创建 Status、召唤物或世界对象。
- 涅槃、脱壳、断尾和死亡后复生。
- 需要在伤害结算完成后执行的资源变化。

Queue 条目保存稳定 Actor ID、表现型 Revision、Effect Family、来源槽位、目标 ID、生命周期预留序号和已结算数值。执行前重新解析 Actor，并检查预留仍未提交；如果来源随后消失，已经同步消费并阻止致命伤的预留按 Effect 规则完成或转为失败后果，不能免费返还后再次触发。每个 Actor 同类未提交后果最多一条，世界清理时同步清空。

#### Status 来源

为需要跟随器官撤销的自身状态增加：

```text
CreatureEffectStatusSource
  OwnerActorId
  PhenotypeRevision
  SlotId
  OrganId
  EffectFamilyId
  RemovalPolicy
```

`RemovalPolicy`：

- `PersistUntilExpiry`：已经施加给敌人的毒、燃烧等继续自然到期。
- `RemoveWhenSourceMissing`：甲壳姿态、蓄能、临时翼化等在来源消失时移除。

不能假设现有 `StatusRelation` 已经提供模块来源键。

### 步骤 5：固定形态切换

复用 `ActorTransformationService` 的身份、关系、物品和资源比例保留能力，但组合形态切换必须先补充明确选项：

```text
ActorTransformationOptions
  ApplyTargetBirthTraits
  ReconcileOwnedTraits
  RecheckCultisyses
```

组合 Morph 的规则：

- 形态机制不依赖不可撤销的出生 Trait，优先由共享表现型 Contributor 表达。
- 共享层记录自己授予的 Morph Trait，并只移除自己拥有的旧来源。
- 不能按 Trait ID 粗暴删除角色可能从其他来源获得的同名 Trait。
- 切换目标资产后重新设置 Subspecies、飞行、阴影、主图形和原版属性缓存。
- `RecheckCultisyses` 对妖兽形态默认关闭；化形不能因为目标人形资产配置而意外获得仙道或其他体系。
- 转换后保留 Actor ID、家庭、阵营、装备、领域 ECS 状态、妖丹、血脉、Hive Membership 和 Trial 关系。

形态切换失败时恢复旧 ActorAsset、Subspecies、资源比例和表现型，不能触发死亡流程。

### 步骤 6：视觉表达

新增 `CreatureOverlayRenderSystem`，只查询同时拥有 `ActorBinder` 与 `CreaturePhenotype` 的当前可见单位。

渲染结构：

```text
CreatureVisualRigAsset
  FrameSetId
  AnchorsByBaseFrame[]
  LayerOrder[]

CreatureVisualLayerAsset
  Id
  RigCompatibility[]
  Channel
  FramesByBaseFrame[]
  Anchor
  Offset
  Scale
  TintPolicy
```

实现要求：

- 每个基础动画帧通过预链接索引取得覆盖层帧，不在每帧拼路径或搜索资源。
- 覆盖层同步 Actor 当前主 Sprite、位置、翻转、缩放、跳跃高度、可见性和渲染排序。
- 只为可见单位从 `MonoObjPool` 取得 SpriteRenderer；不可见、死亡或离开视野后归还。
- 每个单位最多三层可见覆盖层，同一通道按 Rank、优先级和稳定 ID 选一个胜出者。
- 九尾、巨翼、龟甲、蛇尾等使用聚合覆盖层，不按器官数量创建多个对象。
- 武器腺主要通过攻击前摇、发射点、弹体和命中特效表现；内部代谢器官默认只在详情页显示。
- Trial、来源和候选状态不进入永久覆盖层，只在选中或开发模式显示轻量标识。

UI 预览和世界渲染共用同一只读视觉解析结果，但各自使用适合的 Renderer，不让 UI 依赖世界池。

### 步骤 7：验收

建立最小测试内容：

- 一种甲壳器官：提供属性、语义和可见覆盖层。
- 一种酸液/毒液腺：提供 AI 可用的 SkillV3 主动能力。
- 一种濒死反应器官：通过后果队列创建短期自身状态。
- 两个固定 Morph：验证安全切换。

必须验证：

1. 安装甲壳后属性、语义和覆盖层同时出现。
2. 替换甲壳后旧属性、语义、来源状态和视觉全部撤销。
3. 毒液能力能被 `CombatWorldService` 发现、选择、接近目标并实际释放。
4. `Collect`、伤害热路径和渲染热路径不产生表现型编译或结构修改。
5. 同效果族按声明合并，不因器官注册顺序改变结果。
6. 一次致命伤在 `Survival/LastResort` 同步预留且最多被一个效果拦截，后果队列不会在正常死亡提交后才尝试复活。
7. 形态往返不累积出生 Trait、不丢失领域组件和关系，也不错误获得修炼体系。
8. 一个不可见 Actor 不持有覆盖层 Renderer；世界清理后池租约、生命周期预留和后果队列归零。
9. 4096 个组合个体受伤时，不为每次命中构建语义档案、ReadModel 或托管字典。
