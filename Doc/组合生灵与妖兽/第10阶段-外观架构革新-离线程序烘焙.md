# 第10阶段：妖兽外观架构革新——离线程序烘焙

> 历史方案：当前实现已由[第11阶段](第11阶段-身体帧合成与合理组合.md)取代，以下保留当时的决策记录。

> 状态：路线已定案（四轮 subagent 像素级评审，第四验通过）。本文档为架构决策记录与落地路线。

## 1. 背景与决策原因

第 9 阶段的"运行时图像拼接"方案（手绘器官 PNG + 运行时缩放旋转 + 逐帧锚点轨道）
经三轮评审后确认两个结构性死穴：

1. **风格不同源**：器官贴图自带独立色板（描边 #4a3f2a 通用暖棕），与各物种身体
   描边语言（狼 #2f2f34 冷灰 / 熊 #221d13 暖暗棕 / 羊 #322919 / 狐 #533228——
   "极暗、低饱和、色相向体色倾斜"的逐物种语言）不同族，怎么调都"突兀"；
2. **调参无底洞**：14 物种 × 4 帧 × 14 图层的锚点/缩放/旋转逐个手调不可持续，
   自动化到 80 分后剩 20 分的"雅致度"只能人肉消耗。

## 2. 原版机制调查结论（支撑决策的实勘）

- **同物种多外观是引擎一等公民**：zombie 皮肤 = 加载期克隆物种资产、贴图路径指向
  平行表（`generateZombieAssets`，42/42 物种齐备、与 main 表逐帧同分辨率）；
  变异皮肤通道（`SubspeciesTrait is_mutation_skin`）整套换装且可按亚种生效，零 Harmony；
- **官方挂件先例**：王冠/头盔 = 独立头帧表 + 编译进精灵分件的每帧挂点数据，
  由动态图集合成——"数据驱动挂点"是原版自己的做法；
- **工作量真值**：单只动物成体变体最小 6 帧（3 walk + 3 swim，idle 复用 walk_0）；
  原版愿意用"通用帧牺牲物种辨识"（mutation_skin_void），妖兽要保留物种辨识度，
  故完整手绘图集只适合招牌物种精修，不适合作为组合系统主架构。

## 3. 架构决策：E 混合（B′ 离线烘焙为核心）

```
烘焙工厂 Scripts/organ_gen/（离线，已建成）
  ├─ style_rules.py  风格规则器：逐物种实测描边/体色 → 派生器官调色板
  │   （描边=身体描边实测值；亮部=固定骨色向体色偏 12% 色相；暗部=亮部向描边混 28%）
  ├─ shape_specs.py  形状规格：物种无关的参数化像素生成（角=收尖后弯、尾=100° 三叶扇楔）
  └─ bake.py         烘焙器：逐帧实测解剖（颅顶/臀位/体长）→ 逐帧位姿与尺寸 → 成品 PNG
交付路线（按优先级）：
  ① 产物进现有叠加系统（FramesByBaseFrame 已在数据模型，未启用）——组合灵活性保留
  ② 烘焙合成整帧 → 官方变异皮肤通道（按亚种换装）——运行时零叠加
表面效果层（淡染/发光/势力色，MaskToBody）→ 原样保留，已验证有效
招牌物种精修 → 整套手绘图集（变异皮肤通道），未来按需
```

**为什么治两大痛点**：突兀——颜色同源是生成器不变量（描边逐像素等于身体描边，
四物种硬数据验证），逐帧烘焙姿态消灭运行时旋转插值（原版像素语言无旋转）；
调参慢——形状规格写一次物种无关，锚点/尺寸由轮廓实测自动拟合，
加新器官 = 一份规格 + 一次烘焙 + 一轮画廊评审，不碰运行时代码。

## 4. 验收记录（subagent 像素级评审，四轮）

| 轮 | 结论 | 关键修正 |
|---|---|---|
| 一 | 不通过 | 尾俯角太低压进遮挡区；角被整圈描边增肥成厚板；角锚点误取鼻尖（改取头段最高点列） |
| 二 | 不通过（角过） | 角减宽 1.6→1.05、锚点修正、尾扇抬到 30~86°——尾仍读作钩爪 |
| 三 | 不通过（角定稿） | 缺口透空方向正确但半宽 0.30 过头：56° 张角装不下三叶（几何硬约束） |
| 四 | **通过** | 张角 20~120°、缺口半宽 0.17 且按半径自适应 clamp(1.2/r, 0.12, 0.20)、sway -4/-8/-12 |

硬数据：四物种描边逐像素同源（#2f2f34/#221d13/#322919/#533228）；角/尾与手调标杆
并排不落下风（颜色与尺寸占优）；熊/羊/狐零手调适配成立；三帧无跳变。

非阻塞打磨项（后续并入）：狼 walk_0 第三叶偏短；扇叶直边缺口可加 1px 圆角。

### 实施中发现并修复的环境问题
- NML 编译会扫描模组文件夹内所有非点开头的 .cs（.GameSource 因带点前缀被忽略），
  评审用的 `Temp/snapshot/*.cs` 快照曾被编入导致类型重复定义——已清理，
  后续评审产物一律放 `Temp/` 下带点前缀的子目录或直接删除；
- DebugToolbox 客户端为 win-x64 宿主，Linux 下需用户级 .NET 10 运行时
  （`~/.dotnet10`）以 `dotnet ...Client.dll` 方式运行。

## 7. 规矩（防止新架构劣化）

- 规格只管形状与姿态；**颜色永远由 style_rules 派生**，禁止在规格里写死色值；
- 任何一帧不满意 → pixel_text 手改矩阵重烘（逃生舱），不运行时修补；
- 新器官先过"与手调标杆并排不落下风"验收再进库（subagent 评审闭环沿用）；
- 描边派生规则若要改动，先跑 `--survey` 批量普查再改，不拍脑袋。
