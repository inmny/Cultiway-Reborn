# 第3阶段-吞噬炼化与个体异变

本阶段让玩家真正看到妖兽“吃什么，就可能朝什么方向变化”：妖兽必须走到猎物尸体旁吞食，尸体精华会进入最多三格的消化队列；消化结束后，它可能获得妖力、短时适应，或得到一个与猎物特征相符的器官候选。炼化成功会改变能力、行动方式和外观，失败则会排异、受伤，甚至死亡。

吞噬只读取明确允许的猎物特征，不会整套复制目标单位。

## 具体说明

### 步骤 1：精华与样本

#### 玩家会看到什么

生物死亡后，尸体不会立刻把能力送给附近妖兽。妖兽必须亲自走到尸体旁完成吞食，才有机会取得精华。同一具尸体的同一次死亡只能提供一份精华；两只妖兽争抢时，先完成吞食的一只获得，另一只不能重复领取。

如果尸体很快消失，精华可以在原地短暂保留一个可见痕迹；到期或被领取后立即消失。

#### 程序对应

一次领取记录使用 `YaoEssenceClaim`：

```text
YaoEssenceClaim
  SourceActorId
  SourceDeathSequence
  ClaimedByActorId
  ClaimedAt
  SemanticFragments[]
```

`SourceActorId + SourceDeathSequence` 共同表示这一具尸体和这一次死亡。同一个组合只能领取一次精华。

如果原版尸体不能一直保留，就在原地创建短时间存在的精华 `YaoEssenceDeposit`，保存位置、到期时间和领取标识。精华被领取或到期后消失。

#### 只提取白名单特征

玩家获得的结果必须能从猎物身上看懂。例如，吃水生生物可能得到水息肺，吃硬壳生物可能得到鳞甲；不能因为猎物恰好会某个技能，就把整套技能复制过来。

允许提取的内容由静态定义 `YaoEssenceProfileAsset` 明确登记：

```text
ProfileId
SourceSemantics[]
ExtractedFragmentId
StrengthRange
AllowedCategories
ForbiddenBloodlines[]
```

首批精华碎片：

| 碎片 | 必须来自的真实特征 | 可以提出的变化方向 |
| --- | --- | --- |
| 水生呼吸 | 实际能在水中生存或呼吸 | 水息肺、两栖囊 |
| 毒性腺体 | 实际使用毒素攻击或造成中毒 | 毒腺升级、滤毒表皮 |
| 火焰亲和 | 实际参与火元素交互 | 火心、火羽表被 |
| 硬质表被 | 实际拥有高防护、硬壳或硬鳞 | 鳞甲、甲壳 |
| 愈合组织 | 实际拥有再生能力或长期伤后恢复 | 低阶再生组织 |
| 飞行附肢 | 实际能够飞行 | 翼化候选，只能解锁固定翼形态 |

提取时读取已登记的特征档案（`SemanticProfile`）和有限映射。禁止复制目标的特性（`Trait`）、技能（`Skill`）、单位定义（`ActorAsset`）、运行时组件、装备或全部属性。

### 步骤 2：消化

#### 玩家会看到什么

每只妖兽最多保存三份待消化精华。界面应显示每格精华来自什么猎物、正在等待还是正在消化、还需多久，以及可能承担的成本。

同一时间只有一格真正推进，另外两格排队。队列已满时，妖兽不会继续吞走新的精华。这样既能让玩家看懂成长过程，也能防止妖兽无限囤积尸体能力。

#### 运行规则

- 只有妖兽自己的吞噬工作可以改动队列，程序对应 `YaoDevourJob`。
- 完成进食后，先锁定样本，再占用队列空间并支付最低妖力成本。
- 妖兽死亡时，未完成的消化条目按玩法规则损失。
- 消化按世界模拟时间推进；暂停世界时不推进。
- 同时只处理一项，其余项目等待。
- 三格已满时不能领取新精华。

消化资料保存在 `YaoDigestion`，固定最多三项：

```text
Queue[3]
  FragmentId
  SourceActorId
  Strength
  StartedAt
  CompleteAt
  Cost
  Phase
```

消化阶段使用以下名称：

```text
Queued
Digesting
Ready
Resolved
Rejected
```

#### 消化结果

每份精华只会结算为以下一种结果：

1. 转化为有限妖力或进阶积累，程序对应 `PowerGain`。
2. 获得一次短时、不可遗传的身体适应，程序对应 `SomaticShift`；它使用现有持续状态表达，不写入 `YaoBody`，到期后直接消失。
3. 生成一个静态器官候选，程序对应 `OrganCandidate`。

妖兽根据饥饿、妖力、当前主要威胁、身体容量和血脉倾向自行选择。正式玩法不提供手动选择菜单。

### 步骤 3：候选

#### 玩家会看到什么

消化产生器官变化时，最多保留三个候选。每个候选都要说明它为什么出现、能带来什么、会替换哪个部位，以及速度、妖力或稳定度方面的代价。被淘汰的候选也要保存简短原因，供只读界面解释。

#### 候选必须满足的条件

器官候选服务（`YaoOrganCandidateService`）只从静态器官目录中选择，并同时检查：

1. 精华碎片与器官需要的特征一致。
2. 目标槽位存在且容量足够。
3. 当前固定形态和身体结构兼容，程序对应 `CreatureMorphAsset` 与 `CreatureBodyPlanAsset`。
4. 妖兽境界、身体稳定度和血脉限制满足要求。
5. 不与现有器官冲突，或者明确属于替换关系。
6. 该妖兽不处于同类失败后的抑制期。

评分只读取以下固定资料：

```text
SampleStrength
BodyCompatibility
BloodlineAffinity
CurrentNeed
Synergy
ComplexityCost
StabilityCost
ReplacementCost
FailureMemoryPenalty
```

候选最多三个。系统使用妖兽的稳定种子和消化序号加入很小且可重复的差异，不能每帧重新随机选择。

首批候选：

| 样本 | 器官 | 槽位 | 玩家能看到的收益 | 明确代价 |
| --- | --- | --- | --- | --- |
| 水生呼吸 | 水息肺 | 代谢 | 能在水域生存并进行两栖寻路 | 陆地恢复下降 |
| 毒性腺体 | 强化毒腺 | 吐息腺 | 毒素更强、持续更久 | 妖力消耗提高 |
| 硬质表被 | 细鳞甲 | 表被 | 获得有限物理减伤 | 移动速度下降 |
| 愈合组织 | 低阶再生 | 代谢 | 脱离战斗后恢复 | 持续消耗妖力 |

飞行碎片只能提出“翼化结构”候选，而且必须存在可用的固定翼形态。本阶段不实现飞行形态，不能只靠一个器官把地面单位改成飞行单位。

### 步骤 4：炼化结算

#### 玩家会看到什么

炼化成功时，新器官会真正改变妖兽的外观、能力和行动方式；旧器官的效果会完整撤销。炼化失败时，玩家会看到样本损失、虚弱、排异、器官暂时失效或身体受损，而不是免费回到尝试前。

#### 身体资料的唯一来源

`YaoBody` 是妖兽全部永久身体方案的唯一来源，`YaoFormPlanService` 是唯一允许改写这些方案的入口。当前正在显示的 `CreaturePhenotype` 只是活动形态的表达结果，任何系统都不能反过来直接修改它。

每个形态直接保存自己的器官资料，器官来源也放在同一条资料里，不再建立独立的来源组件：

```text
YaoBody
  Forms[]
    FormId
    BodyPlanId
    MorphId
    Organs[]
      SlotId
      OrganId
      Rank
      Origin       // 先天、血脉、吞噬、固血、返祖等
```

程序处理顺序：

```text
读取 YaoBody 中的活动形态方案和 Organs
  -> 计算妖力、稳定度和排异结果
  -> 成功后由 YaoFormPlanService 按既定槽位和形态规则生成新方案
  -> 一次性写回所有受影响的形态
  -> 如果改的是活动形态，再提交 CreatureExpressionService
```

吞噬所得器官默认写入真身。已经存在的人形或其他真身，必须按静态规则同步处理：保留、显化或休眠，程序对应 `Retained`、`Manifested`、`Dormant`。备用形态也要同步更新，避免下次切换时丢失刚获得的永久变化。

#### 成功结果

- 把新器官资料的 `Origin` 标记为吞噬所得，程序值为 `Digested`。
- 消耗样本和妖力。
- 增加短暂稳定期或代谢负担。
- 发布器官炼化完成事件 `YaoOrganDigestedEvent`。事件只说明哪只妖兽的哪个形态、槽位和器官发生了变化，以及来源为 `Digested`；真正的长期结果已经写在 `YaoBody` 中。

#### 失败结果

| 失败等级 | 玩家会遇到的后果 |
| --- | --- |
| 轻微排异 | 样本损失、妖力下降、短时虚弱 |
| 严重排异 | 当前槽位器官暂时失效、生命受损、进入冷却 |
| 结构崩溃 | 旧器官保留，新候选销毁，身体稳定度下降 |
| 致命失败 | 仅用于高阶或强行炼化，造成实际死亡或永久损伤 |

失败不能自动改写血脉，也不能把失败候选加入永久能力。失败历史按器官编号和失败类型有限地放在 `YaoDigestion` 中，并随时间衰减，不再增加新的失败记录组件。

吞噬所得器官默认不能遗传。只有大境界突破时的“固血”规则，才能把最多一个兼容器官写入 `YaoGenome`，详见阶段 5。

### 步骤 5：行为表达

新器官必须改变实际玩法，不能只在详情页增加一行文字：

- 水息肺改变水域可达性、溺水判断和目标选择，而不是只增加“水生”标签。
- 强化毒腺在真实攻击中通过共享主动能力入口使用技能系统（`SkillV3`），并受到妖力和冷却限制。
- 细鳞甲进入最终伤害适应阶段，实际降低有限物理伤害，同时降低移动速度。
- 低阶再生只在脱离战斗后的周期中申请恢复，不能每帧直接加血。

妖兽没有独立的生态组件。每次选择工作时，直接读取当前生物单位、`YaoBody` 的活动形态、`Yao` 的妖力、`YaoDigestion` 和周围环境。共享身体整理结果提供以下有限行动摘要，程序对应 `Affordance`：

```text
CanBreatheWater
CanUseVenom
CanRecoverOutOfCombat
PreferredTerrainTags
```

这些摘要只能来自器官静态定义，妖兽据此选择适合当前身体和环境的行动。本阶段不会因为吞噬玩法再增加身份、生态或器官来源组件；消化内容只放在按需存在的 `YaoDigestion` 中。
