# 元婴夺舍-摘要

**状态**：首版闭环已实现并通过 Debug 构建，待游戏内矩阵验证
**目标版本**：首版自然触发的元婴夺舍闭环
**身份规则**：夺舍者身份延续，宿主只提供肉身

## 已确认决策

| 决策项 | 结论 |
| --- | --- |
| 成功后的身份 | 保留夺舍者的 Actor ID、姓名、宗门、亲属、师徒和历史关系 |
| 首版触发方式 | 仅在肉身将受到致命伤、且已有保命规则均未生效后自动触发 |
| 首版宿主范围 | 存活、有魂、有灵根、低于元婴的智慧生物 |
| 失败规则 | 每次出逃只有一次正式夺舍机会；对抗失败后元婴魂灭 |
| 夺舍后的修炼归属 | 下层炼气、仙基、金丹采用宿主；主修功法、掌握度和已学技能保留原主 |
| 元婴后续 | 原元婴转为休眠 `YuanyingSeed`；宿主金丹九转后确定性唤醒，不重新随机结婴 |
| 重修期出逃 | 休眠种子在唤醒前仍可出逃，成功后继续使用同一份种子 |

## 设计目标

元婴不再只是属性组件。元婴修士的肉身死亡时，人物可以暂时以元婴形态存活，在有限时间内寻找合适宿主并进行一次神魂对抗。成功后原人物以宿主肉身继续存在；失败、超时或元婴形态被击杀后，人物才真正死亡。

首版必须形成以下可观察闭环：

1. 元婴修士遭遇致命伤。
2. 现有灵胎、混沌归墟、雷铸神兵等保命效果先结算。
3. 致命伤仍成立时，原 Actor 原地转为元婴形态，肉身装备留在原地。
4. 元婴在限时内自动寻找合法宿主。
5. 元婴抵达宿主后只进行一次夺舍对抗。
6. 成功时保留原人物身份并采用宿主肉身；失败时原人物真正死亡。
7. 世界日志、状态图标和人物元婴页能解释发生了什么。

## 明确不做

- 首版不支持健康状态主动出窍或玩家手动选择宿主。
- 首版不允许夺舍另一名元婴，不处理双元婴共存或反夺舍。
- 首版不做伪装、身份识破、宿主残魂、人格争夺和长期侵蚀。
- 首版不继承宿主的姓名、社会关系、人格和记忆；当前炼气、仙基、金丹等下层修炼数据例外，按宿主采用。
- 首版保留夺舍者的主修功法、掌握度和已学技能，但这些技能的可用境界限制按当前宿主修为计算。
- 首版不新增独立窗口、神力按钮或配置项。
- 首版不实现夺舍 ECS 状态的存档与读档恢复；出逃中的元婴单位直接跳过世界存档。
- 首版不建立轮回、转世或跨人物 ID 的灵魂谱系系统。

## 身份与肉身所有权

夺舍实现必须先拆开“人物身份”和“当前肉身”。同一个 Actor 继续代表夺舍者，避免重建或重定向原版及 Mod 中大量按 Actor ID 建立的关系。

| 数据 | 成功后来源 | 处理规则 |
| --- | --- | --- |
| Actor ID、姓名、收藏状态 | 夺舍者 | 原对象不变 |
| 宗门、师徒、亲属、氏族、国家、城市、文化、语言、宗教 | 夺舍者 | 首版保持原关系，不冒用宿主社会身份 |
| 主修功法、掌握度、已学技能 | 夺舍者 | 知识与技能关系随神魂保留；实际境界限制仍按当前宿主修为 |
| `CultivationPracticeState` | 夺舍者 | 作为功法实践与元素暴露记录保留 |
| `Xian`、炼气状态、`XianBase`、`Jindan`、当前 `PowerLevel` | 宿主 | 深拷贝宿主当前下层修炼轨迹，作为夺舍后的活动境界和战力基准 |
| `CultivationResourceState` 与当前 Wakan | 宿主 | 按宿主当前修炼资源接续，换体后按新肉身上限校正 |
| 原 `Yuanying` 与原元婴 `PowerLevel` | 夺舍者 | 深拷贝为休眠 `YuanyingSeed`；唤醒时恢复元婴战力基准，不在低境界阶段直接提供元婴属性 |
| 元婴种子的名称、品阶、元素构成、原子、转数和谱系 | 夺舍者 | 宿主金丹九转后唤醒，不重新随机结婴 |
| 种族 ActorAsset、Subspecies | 宿主 | 精确采用宿主当前肉身，不重新随机亚种 |
| 性别、头部、表型、色调 | 宿主 | 作为肉身外观快照采用 |
| 原版显示年龄 | 宿主 | 保留夺舍者 `created_time`，重算 `age_overgrowth` 使 `getAge()` 等于宿主肉身年龄；神魂年龄由原出生时间计算 |
| ElementRoot | 宿主 | 灵根视为肉身资质；休眠元婴与新灵根的相性影响唤醒强度 |
| body、physique、health、appearance、protection 特质组 | 宿主 | 移除夺舍者旧肉身特质，再复制宿主对应组 |
| mind、spirit、cognitive 等非肉身特质 | 夺舍者 | 保留原主精神和人格特质 |
| 原肉身原版装备 | 原肉身所在地 | 交给当地城市；无合法接收者时沿用原版死亡物权，不随元婴飞行 |
| Mod 特殊物品与已绑定法宝 | 夺舍者 | 首版视为神魂可携带资产，继续属于原 ActorExtend |
| 宿主装备与物品 | 宿主死亡流程 | 按宿主正常死亡物权处理，不自动复制给新肉身 |

## 状态机

```text
正常肉身
  └─ 致命伤且常规保命失败
      ├─ 不符合出逃条件 -> 真正死亡
      └─ 进入元婴出逃
          ├─ 被击杀/超时/无合法宿主 -> 真正死亡
          └─ 锁定宿主并接近
              ├─ 宿主失效且尚未结算 -> 重新寻主
              └─ 开始夺舍对抗（消耗唯一机会）
                  ├─ 失败 -> 元婴魂灭，宿主神魂受创
                  └─ 成功 -> 原身份采用宿主肉身，当前修炼切换为宿主下层轨迹，原元婴进入休眠种子状态
```

`YuanyingSoulState` 只在出逃期间存在；成功或真正死亡时立即移除。神魂出生时间继续使用夺舍者不变的 `data.created_time`，目标只保存稳定 Actor ID，不长期持有 Actor 引用。首版不实现夺舍状态存档；`Actors.YuanyingSoul.skip_save = true`，保存世界时直接忽略正在出逃的元婴。

## 元婴种子与当前境界

夺舍成功后，原主的 `Yuanying` 深拷贝为 `YuanyingSeed`，当前活动的 `Xian` 与炼气、仙基、金丹组件改为宿主版本。只要 `YuanyingSeed` 尚未唤醒，当前境界就按宿主显示和计算：无仙道为炼气，宿主筑基则为筑基，宿主金丹七转则为金丹七转。

休眠种子不参与当前境界属性，但仍是神魂核心。肉身在宿主重新结婴前再次死亡时，`CanEscape` 以 `YuanyingSeed` 作为出逃资格；成功换体后继续保留同一个种子并累积夺舍损耗。

宿主达到金丹九转并满足满 Wakan 条件时，`xian.form_yuanying` 走“唤醒种子”分支：不重新调用 `ResolveYuanying`，直接恢复原元婴的品阶、名称、元素构成、原子、转数和谱系，再根据宿主金丹承载力与灵根相性计算当前强度。唤醒后移除种子、生成活动 `Yuanying`，当前境界恢复为元婴。

## 核心规则

### 出逃资格

同时满足以下条件才触发：

- Actor 存活且本次最终伤害足以致命。
- 拥有有效活动 `Yuanying`，或拥有尚未唤醒的 `YuanyingSeed`。
- 原始出逃时必须达到元婴；重修阶段由 `YuanyingSeed` 继续提供资格。
- 当前不是元婴出逃形态，也不处于夺舍后的神魂衰竭期。
- 死因不是 `AttackType.Divine` 或 `AttackType.Metamorphosis`；这两类结果不增加元婴出逃，其他既有保命规则仍按自身合同结算。

自然寿终使用原版 `getHitFullHealth(AttackType.Age)`，会进入同一最终伤害流程，因此无需另补一套寿终分支。

### 结算顺序

在 `FinalDamageStage.Survival` 之后新增通用的最终保命阶段 `LastResort`。元婴出逃只注册到 `LastResort`：

1. 护盾、减伤和伤害上限先执行。
2. 灵胎、混沌归墟、雷铸神兵等现有保命效果先执行。
3. 伤害仍致命时才尝试元婴出逃。
4. 只有元婴形态转换完整成功后才把本次伤害改为 0；转换失败则保留原伤害并正常死亡。

这样不依赖委托注册先后顺序，也不会一次致命伤同时触发两套保命。

### 初始平衡值

首版把参数集中在一个规则类中，不增加设置页面：

| 参数 | 初始值 | 说明 |
| --- | ---: | --- |
| 元婴存续时间 | 12 个月 | 超时后真正死亡 |
| 寻主半径 | 120 格 | 只在低频寻主时查询 |
| 夺舍引导时间 | 1 个月 | 提供可观察的过程和打断窗口 |
| 成功率下限/上限 | 10% / 95% | 保留风险，也避免绝对随机锁死 |
| 成功后生命 | 新肉身最大生命的 25% | 夺舍后处于脆弱期 |
| 成功后灵力 | 宿主新活动体系最大 Wakan 的 10% | 需要按宿主路线重新蓄养，不能立即唤醒或继续进阶 |
| 元婴强度损失 | 10% 至 35% | 相性越差，永久损失越大 |
| 肉身不合 | 1 年 | 降低速度、伤害和神识，并禁止再次出逃 |
| 失败后的宿主神魂创伤 | 2 年 | 降低 MaxSoul 与 DivineSense |

这些值先用于闭环验证，之后只根据真实世界样本调整，不提前做玩家配置。

## 神魂对抗

夺舍成功率由专门的纯计算 `SoulContestResolver` 产生解释性结果，不在 AI 行为中散落公式。

```text
进攻值 A = log(1 + 元婴神识)
         + log(1 + 元婴魂量上限)
         + 2 × log(1 + 元婴强度)
         + 元婴品阶修正

抵抗值 D = log(1 + 宿主神识)
         + log(1 + 宿主魂量上限)
         + 宿主战力等级修正
         + 强韧心智修正

基础概率 = A / (A + D)
最终概率 = Clamp(基础概率 × 灵根相性倍率, 10%, 95%)
```

灵根相性倍率由元婴形成的五行构成与宿主 ElementRoot 构成计算，范围为 0.8 至 1.2。Resolver 同时返回进攻值、抵抗值、相性和最终概率，供日志、调试和 UI 使用。

## AI 选主

第一阶段只选择半径内距离最近的合法宿主，以尽快跑通闭环。第二阶段改为一次低频评分：

```text
候选价值 = 成功率 × 肉身价值 - 距离成本 - 社会关系代价
```

肉身价值考虑剩余寿命、基础生命、灵根相性和肉身特质；同宗、亲属、师徒和同城只降低评分，不作为绝对禁止条件。元婴在正式对抗前可以因目标死亡、失效或离开范围而重新选主；一旦 Resolver 进行随机结算，就消耗本次唯一机会。

## 总体验收标准

- 非元婴按原逻辑死亡，现有保命效果行为不变。
- 元婴只在已有保命效果未阻止致命伤时出逃。
- 出逃者始终保留原 Actor ID、姓名、宗门和关系。
- 成功后精确采用宿主种族、亚种、外观、年龄、灵根和肉身特质。
- 成功后当前境界、PowerLevel、炼气、仙基和金丹数据来自宿主；原主功法技能继续保留，原元婴进入休眠种子。
- 宿主重新达到金丹九转后，能够确定性唤醒原元婴，不重新随机结婴。
- 休眠种子在唤醒前的再次出逃会继续使用同一元婴，不复制或重置核心。
- 每次出逃只结算一次夺舍；失败、超时或元婴被杀都会真正死亡且只清理一次。
- 目标中途失效不会复制角色、吞掉目标或留下半完成换体。
- 选中、收藏、玩家控制、领袖、宗门借物和死亡物权均有明确结果。
- `dotnet build Cultiway.csproj -c Debug` 通过，并完成阶段 3 的游戏内矩阵验证。
