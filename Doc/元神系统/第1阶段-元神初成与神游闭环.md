## 阶段目标

本阶段只做一个完整闭环：九转元婴通过煞风劫成为元神，修士能将唯一命魂显化为地图实体，前往明确指定的地点并安全归返；肉身在心神外放时按份额变弱，肉身毁灭后原人物以元神形态继续存在。首版没有自动探测或后台范围查询。

本阶段完成后，元神已经是可观察、可操作、有风险的玩法，而不是化神属性说明中的一个名词。

## 本阶段不做

- 不生成普通分念；地图上同时最多只有一个外放临时命魂人物。
- 不实现自动探测、范围扫描、节点战斗、完整度伤害和神魂压制；节点战斗留到后续阶段按明确接触规则实现。
- 不实现九层自然进阶、多任务、控宝和节点施法，留到第 3 阶段。
- 不实现夺舍、重塑肉身和备用锚点；无肉身元神可以存续和行动，但暂时不能获得新肉身。
- 不实现任何存档、读档、迁移或兼容处理。

## 具体说明

### 建立元神成果

新增 `Yuanshen` 长期成果组件，并在 `CoreFormationRealm` 中加入元神成果类型。组件首版只保存元神形成快照，不提前放入节点、锚点、任务或玩家控制状态。

化神成功时，从九转 `Yuanying` 确定性生成元神快照：

1. 只深拷贝九转时已经觉醒的元素构成、形成原子和语义，避免数组共享，也不把未觉醒潜能凭空带入。
2. 将继承原子标记为继承，并把元神境内 `awakening_stage` 设为 0，保证元婴三、六、九转已经生效的能力不会在元神 0 层重新失效。
3. 精确继承元婴 `strength`、谱系词干与品阶，不重新调用随机组合选择，也不按煞风劫剩余生命改变永久强度。
4. 把来源签名、来源名称、来源九转和来源品质写为元婴数据。
5. 将当前成果类型改为元神，蕴养层数从 0 开始。
6. 为元神成果补齐原子适用范围、境界名称、统计、语义和效果解析，再重新计算当前结果。
7. 显示名沿用原谱系名称并附加元神身份，不生成第二套随机名称。

煞风劫通过、境界提交、元神创建和劫难清理必须在一次进阶提交中完成。失败时不得留下半个元神。

直接授予或同步化神时沿用同一规则：先补齐有效九转元婴，再确定性生成元神。不得为授予路径写另一套简化元神。

### 固定形成权威

调整当前形成解析顺序：

- 化神及以上：只接受有效 `Yuanshen`。
- 元婴：只接受有效 `Yuanying`。
- 金丹及以下：保持现有规则。

元婴、金丹和仙基继续作为历史成果存在，但化神时不再参与当前属性、语义、被动和主动能力解析。

同步发现“境界为化神但缺少元神”时，应通过统一化神规范化补齐；不在形成解析器里添加元婴回退。这样错误状态只在一个入口修复，不会长期隐藏。

### 建立元神会话与临时命魂人物

建立集中式元神会话服务，以人物稳定编号为索引。普通在体状态不创建临时人物；只有命魂出窍、无肉身续存或正在归返时才建立相应运行状态。

出窍时在原人物当前位置生成唯一临时命魂人物。它只携带位置、动画、碰撞、局部目标、局部状态和魂体完整度，不创建姓名归属之外的社会数据，不持有修炼、技能、物品、法器或资源副本。原人物保留全部身份、装备、技能、资源、冷却和击杀归属。

临时命魂人物使用专用魂体资产，跳过工作、繁殖、进食、掉落和普通社会逻辑；世界清理、归一或失效时由 `YuanshenTravelService` 统一回收。普通分念、法相、化身和显圣仍使用模组节点，不与命魂共用载体路径。

人物与临时命魂人物通过所有者编号、会话编号和代次双向校验。任一校验失败时能力、战斗和生命周期入口都拒绝继续，不回退到旧载体。

### 实现心神份额与肉身状态

首版使用三个稳定姿态，不要求玩家手工输入百分比：

| 姿态 | 命魂外放 | 肉身保留 | 两个载体的行动权限 |
| --- | ---: | ---: | --- |
| 守一 | 40% | 60% | 肉身与命魂都可完整战斗 |
| 均衡 | 60% | 40% | 肉身与命魂都可完整战斗 |
| 尽出 | 90% | 10% | 肉身仍可行动和战斗，但效果明显变弱 |

命魂留在肉身时，人物不需要划分这三种份额。选择姿态只决定下一次出窍和外放期间的默认分配。

首版也必须遵守完整守恒：命魂在体时，肉身持有的全部可用心神就是命魂所在份额；命魂离体时，临时命魂人物份额与无命魂肉身残留份额合计为百分之百。出窍提交必须在一次原子状态转换中同时从肉身扣除、向临时命魂人物写入，归返则执行相反转换，不能出现一帧重复份额或丢失份额。

肉身和命魂都是真实战斗载体。份额只线性缩放伤害、治疗、护盾、魂体生命和其他明确可缩放效果，不因份额较低而失去目标、移动或战斗权限。局部状态分别保存在各自人物上；技能资源、装备、技能列表和冷却仍读取原人物总账。

### 建立最小统一神识预算

统一神识预算必须在第一次出窍出现时就成为唯一权威，不能等多分念阶段再推翻临时判断。第 1 阶段先接入已经实际存在的两类需求：

- 现有受控法器的连续神识负荷与分念槽。
- 命魂离体后仍独立行动的肉身始终所占 1 个分念槽；三种姿态都一样。

当前命魂所在的主念不占分念槽。普通分念尚未开放，因此首版预算服务不创建任务、控宝请求或未来能力占位，只提供总量查询、原子预留、释放和阻断原因。

出窍前必须先冻结一次预算结果：

1. 法器调度提交当前真实负荷和槽位占用。
2. 元神服务提交活动肉身需求。
3. 预算足够时一次性预留并开始出窍。
4. 预算不足时返回明确的法器或肉身占用原因，不先创建临时命魂人物。
5. 神识下降导致超载时，让低优先级法器按现有规则降级；仍不足时强制命魂归返，使肉身恢复为唯一载体。

法器规划器必须读取同一个预算结果，不能继续假设完整 `DivineSense` 全部属于法器。第 3 阶段只扩展普通分念、复杂任务与远程控宝需求，不再更换预算权威。

### 实现定点神游

临时命魂人物只接受明确地面坐标作为移动目标。玩家或人工智能已经明确指定地点后，载体移动到目标并待命；没有目标时保持当前位置。系统不扫描周围单位、建筑或隐藏效果，也不通过位置自动发现对象。

目标必须限制在地图有效范围和肉身牵引上限内。超出范围的命令直接阻断；肉身移动导致越界时，命魂进入归返，而不是自动搜索附近目标。命魂和肉身各自保留局部战斗目标，后续不会互相覆盖。

### 实现出窍与归返

出窍流程：

1. 检查人物是化神、拥有有效元神、存活、有肉身且没有现存临时命魂人物。
2. 检查当前灵气、神识负荷、姿态和场景条件。
3. 冻结本次姿态与初始份额，支付启动灵气。
4. 在肉身位置创建临时命魂人物并建立牵引。
5. 命魂前往明确地点，肉身继续使用自己的目标和战斗逻辑。
6. 两个载体分别读取本地位置和状态，共享原人物技能、资源、装备和冷却。

归返流程：

1. 临时命魂人物停止当前移动命令并向肉身位置移动。
2. 距离达到 `0.75` 格后立即完成归一并回收临时人物。
3. 超距、维持资源不足、载体失效或牵引切断时进入强制归返；有备用法器时按锚点规则处理。
4. 归一只合并份额和运行状态，不复制技能、装备或人物身份。

肉身毁灭时不要求先归返：原人物直接接收命魂载体位置，转为无身元神，再回收临时人物。

### 实现肉身毁灭后的元神续存

化神人物的最终伤害流程必须在元婴出逃之前识别有效元神。

普通肉身致死时：

- 命魂在肉身：释放肉身物权后，把同一个人物转换为无肉身元神形态，并停留在死亡位置。
- 命魂在外：释放肉身物权，把同一个人物移动到临时命魂人物位置并转换为无肉身元神形态，然后回收临时命魂人物。
- 原人物编号、姓名、收藏、关系、功法、技能、`Xian`、`Yuanshen`、历史元婴和法器祭炼归属不变。
- 不创建 `YuanyingSeed`，不覆盖为宿主下层境界，也不设置元婴存续期限。
- 其他普通分念尚未开放，因此首版不涉及多节点清理。

无肉身元神使用专用人物形态，是原人物本身，不是代理节点。它能够移动、使用允许的元神能力并被玩家控制，但不能执行依赖肉身的城市工作、繁殖、普通装备攻击和修炼行为。

无肉身形态从本阶段起就是稳定终态，而不是等待后续修复的占位状态：

- 原人物生命字段只承载和显示命魂完整度，不再表示肉身生命。
- 普通近战、箭矢、疾病、饥饿、毒和环境伤害对无身元神无效。
- 只有明确神魂伤害，或由技能、法器直接提交的含阴攻击可以进入命魂受击与真正死亡入口；毒素自带的阴属性不算。
- 第 2 阶段的节点魂系命中继续复用同一人物伤害入口，不新增第二条生命或死亡管线。
- 人工智能前往所属城市、宗门或一个已经明确知道的安全地点；没有安全目标时原地待命，不搜索附近区域。
- 世界清理只清除运行会话和效果，不把原人物误当临时命魂人物删除。

无身元神或临时命魂完整度归零时进入魂体生死流程，不把它误判成一次普通肉身毁灭；真正死亡仍只能由统一命魂生命周期入口提交。

### 接入人工智能与玩家控制

#### 人工智能

首版只在以下场景主动出窍：

- 人物位于所属城市、宗门安全区域或附近有足够友方护卫。
- 已经知道附近存在威胁、失联友方或需要确认的战斗。
- 当前灵气充足，神识没有被法器占满。
- 肉身没有正在被攻击、移动、突破或执行重要行为。

首版神游目标只能来自人物已经知道的地点、当前行为目标或明确命令，不能查询附近或全图最佳目标。

以下任一条件触发归返：

- 载体超出肉身牵引距离。
- 维持出窍的灵气不足。
- 目标失效、明确命令归返或世界状态失效。
- 牵引持续受阻并达到切断条件。

肉身受到普通攻击不会单独召回命魂；两个载体可以在不同位置继续独立战斗。

#### 玩家

在统一主动能力栏中提供：

- 神游姿态命令。
- 归一命令。
- 守一、均衡、尽出三段姿态。
- 当前控制载体的移动、目标和技能操作。

选择临时命魂人物时，能力列表、资源、装备和冷却读取原人物；技能出生位置、自身效果和局部状态使用当前命魂人物。取消选择后控制回到原人物，不建立第二套能力栏。

## 阶段验收

### 形成矩阵

- 自然九转元婴通过煞风劫后生成有效元神并进入化神。
- 煞风劫失败时不生成元神。
- 直接授予和同步化神能补齐同样的元神结果。
- 元神名称、品阶、元素和形成原子与来源元婴确定对应。
- 元神初始强度精确继承九转元婴；九转时已觉醒原子在元神 0 层继续生效，原子适用范围不会把它们意外过滤。
- 化神属性不同时叠加元婴和元神两份形成效果。

### 神游与预算矩阵

- 三种姿态分别产生正确份额和肉身行为，命魂与肉身残留份额在每次转换后严格合计为百分之百。
- 范围扫描和自动探测均不存在，临时命魂人物只响应明确移动目标、普通局部选敌和归返命令。
- 活动肉身和现有法器从首版起读取同一神识预算；预算不足时不会先创建临时命魂人物。
- 法器规划器不能占用已经预留给活动肉身的神识与分念槽。
- 同一人物不能重复创建第二个临时命魂人物。
- 临时命魂人物移动、超距、归返、受阻和世界清理不会留下残影或空会话。
- 人工智能只在安全且有当前明确行为目标时出窍；肉身受到攻击时两边仍可维持各自战斗，只有超距、资源不足或明确命令才归返。
- 玩家可选择临时命魂人物、移动和取消选择，控制对象不会永久错位。

### 生死矩阵

- 命魂在体时肉身毁灭，原人物在原地转为无肉身元神。
- 命魂在外时肉身毁灭，原人物在临时命魂人物位置继续存在。
- 原身份、关系、技能、元神和化神境界保留。
- 不生成 `YuanyingSeed`，不进入元婴夺舍任务，不重复处理死亡。
- 无身人物的生命字段只承载命魂完整度；普通物理、疾病、饥饿和环境伤害不能扣减。
- 明确神魂伤害或含阴伤害仍能经唯一命魂入口造成真正死亡。

### 工程验证

- `dotnet build Cultiway.csproj -c Debug` 通过。
- 世界创建、清理、切换和重复开关神游无残留实体。
- 100 名化神同时在体时不创建空闲临时命魂人物，也不产生额外逐帧扫描开销。
- 桌面常用分辨率与较小分辨率下，元神页和 HUD 无重叠、截断或失效按钮。
