# 组合生灵与妖兽-摘要

**状态**：设计基线

**实施顺序**：先搭好共用的身体组合规则，再让组合真正影响能力和外观，然后完成第一条妖兽玩法，最后逐步扩展生态与神话内容

**共享对象**：虫群个体、妖兽个体，以及未来确实需要自由组合身体的生物

**明确不做**：复制任意程序行为、无限制拼接外观、提供玩家器官编辑器、把虫群与妖兽做成同一种成长玩法

## 设计目标

本文所说的**表现型**，就是“这只生物当前真正长出来并生效的身体”，包括它正在使用的身体方案、固定形态和器官。计划中增加一套虫群与妖兽共用的身体组合规则，再在它之上增加独立的妖兽玩法。

共用规则只负责一件事：一个身体组合已经确定后，按照槽位、容量、冲突和复杂度规则整理它，并让它影响属性、能力、战斗反应和外观。至于为什么会获得这个组合，仍由各玩法自己决定：

- 虫群根据母巢受到的压力、收集到的样本、同代对照试验和后续繁殖来改变身体。
- 妖兽根据凡兽启灵、个体经历、吞噬炼化、修炼突破、血脉遗传和返祖来改变身体。
- 共用规则不处理母巢、生物质、职虫、妖力、妖丹、血脉或天劫。

这样可以让虫群与妖兽共用器官表达、能力和外观代码，又不会把两种完全不同的成长方式硬塞进同一个进化系统。

## 已确定方向

1. 妖兽以自主生态为主。玩家主要通过灵气环境、猎物结构、灾害和神力间接影响它们。
2. 正式界面只用来观察，不提供器官编辑器，也不允许逐项指定成长结果。
3. 外观采用“固定身体方案和主形态 + 数量受限的器官附加图层 + 技能与粒子特效”。
4. 妖修沿用项目现有的进阶、能力、战斗和持续状态基础，但使用独立的妖修体系与境界路线。
5. 第一条完整路线覆盖凡兽启灵、吞噬炼化、器官异变、妖丹天劫、血脉遗传、返祖和化形。
6. 飞行、游泳方式、体型和整套动画发生重大变化时，必须切换到预先制作好的固定形态。普通器官不能把任意地面动物临时改成能飞的生物单位。

## 总体结构

```text
虫群玩法                                      妖兽玩法
压力 / 样本 / 对照试验                        启灵 / 吞噬 / 修炼 / 血脉 / 天劫
        |                                              |
        +-------------- 形成身体组合方案 --------------+
                                      |
                                      v
                         共用的身体表达规则
       按身体规则整理 -> 生成组合指纹 -> 一次性生效 -> 清理旧来源
               |              |              |              |
              属性           生物特征        能力           外观图层
```

程序对应：

```text
HiveGenome / YaoGenome
  -> CreaturePhenotypePlan
  -> CreaturePhenotypeCompiler
  -> CreatureExpressionService
  -> CreaturePhenotype
```

代码依赖方向：

```text
Insects -> CreatureCompositions -> Core
Yao     -> CreatureCompositions -> Core
CreatureCompositions -X-> Insects
CreatureCompositions -X-> Yao
Core                 -X-> CreatureCompositions
```

共用实现放在 `Source/Content/CreatureCompositions/`。它属于多种玩法都能使用的内容基础，不放进最底层核心代码，也不另建第二套运行时数据、消息、技能、持续状态、战斗或存档系统。

## 哪些共用，哪些不共用

| 内容 | 共用规则负责 | 虫群负责 | 妖兽负责 |
| --- | --- | --- | --- |
| 身体方案、固定形态、器官定义 | 是 | 引用 | 引用 |
| 按槽位、容量、兼容、冲突和复杂度整理身体 | 是 | 提交组合 | 提交组合 |
| 组合指纹和整理结果缓存 | 是 | 使用 | 使用 |
| 属性、生物特征、能力、战斗反应和外观 | 是 | 使用 | 使用 |
| 压力、环境证据和同代对照试验 | 否 | 是 | 否 |
| 母巢、职虫、生物质、分巢和群体策略 | 否 | 是 | 否 |
| 启灵、妖力、吞噬、妖丹和天劫 | 否 | 否 | 是 |
| 双亲遗传、血脉纯度、返祖和化形 | 否 | 否 | 是 |
| 巢器官 | 否 | 是，作用于母巢或建筑 | 否 |
| 妖丹 | 否 | 否 | 是，它是独立核心，不是可拆换的普通器官 |

共享边界必须保持不变：共用层只负责“按身体规则整理组合，并让组合生效”，不能替虫群或妖兽决定成长结果。

## 身体组合的基本零件

| 玩家和策划看到的概念 | 程序类型 | 作用 |
| --- | --- | --- |
| 身体方案 | `CreatureBodyPlanAsset` | 规定这类身体有哪些槽位、能用哪些形态、能承受多少复杂器官 |
| 身体槽位 | `CreatureBodySlotAsset` | 独立登记的槽位配置，规定能放什么、容量多少，以及外观画在哪一层 |
| 固定形态 | `CreatureMorphAsset` | 对应一个预制生物单位模板，决定移动、碰撞、基础动画、体型和基础攻击 |
| 器官 | `CreatureOrganAsset` | 规定器官类别、等级、占槽、兼容关系、属性、能力、反应和外观 |
| 器官等级 | `CreatureOrganRankAsset` | 独立登记的器官等级配置，规定这一级的强度、代价、技能和视觉变化 |
| 外观锚点 | `CreatureVisualRigAsset` | 规定每一帧动画中头、背、腹、尾等位置在哪里 |
| 器官反应 | `CreatureOrganEffectAsset` | 规定器官在受击、濒死、击杀等事件中如何生效和叠加 |

第一版上限：

- 任一身体方案最多 12 个槽位。
- 虫群使用甲壳、运动、武器腺、代谢、神经五槽。
- 妖兽基准使用表被、运动、天生武器、吐息腺、感知、代谢、异质附肢、灵窍八槽。
- 高阶器官可以占用多个槽位，但不能绕过身体容量。
- 妖丹、灵魂、修炼体系和临时持续状态不算普通器官槽。

## 当前身体与组合指纹

系统需要同时描述“准备采用的身体组合”和“这只生物当前正在生效的身体”。前者用于提交变化，后者只在运行时快速读取。程序对应如下：

```text
CreaturePhenotypePlan             // 准备采用的身体组合
  BodyPlanId                      // 身体方案
  MorphId                         // 固定形态
  Organs[]                       // CreatureOrganEntry：槽位、器官、等级

CreaturePhenotype                 // 当前真正生效的身体
  Version
  BodyPlanId
  MorphId
  Organs[]
  Signature
  Revision                       // 第几次变更
```

组合指纹只记录真正会改变身体效果的内容：身体方案、固定形态，以及按槽位固定顺序排列的器官和等级。以下内容不能放进组合指纹：

- 生物单位编号、名字、出生时间和当前冷却。
- 母巢编号、对照试验编号、分组和基因世代。
- 器官来自血脉、吞噬还是个体适应。
- 妖力、妖丹裂痕、消化进度和临时状态。

器官来源不进入共用身体和组合指纹。妖兽把来源直接保存在 `YaoBody` 对应形态的器官资料中；虫群仍保存在自己的遗传资料中。界面展示时再把来源与当前身体合并。这样同一种实际身体可以共用同一份整理结果，也不会因为来源标签变化而重置能力。

## 器官能力的组合方式

器官能力必须由有限、预先定义的零件组成：

```text
能力 = 何时触发 + 作用目标 + 如何送达 + 产生什么效果 + 消耗 + 冷却 + 自动使用倾向 + 视觉
```

- 首批触发方式：主动使用、命中、受击、最终承伤、击杀、濒死、死亡、定期触发和进入特定环境。
- 首批送达方式：自身、近战、冲撞、投射物、吐息、光束、光环和地面范围。
- 首批效果：伤害、持续状态、位移、屏障、恢复、资源转移、形态切换和数量受限的召唤。

必须遵守：

- 主动器官能力使用现有技能系统，不另造一套技能执行方式。
- 不能让每个器官各自挂一个全局受伤、击杀或定时回调；所有器官通过一个共用入口处理。
- 脱壳、涅槃、断尾等需要改变身体结构的后果，要排进数量受限的后果队列，在伤害计算和数据查询结束后处理。
- 能阻止死亡的器官必须在伤害流程的“保命”或“最后手段”阶段立刻确认次数与资源，并立刻把这次致命伤改成非致命或无效。不能等生物单位已经死亡后再尝试复活。
- 永久器官不是原版特性、已学技能或持续状态。持续状态只用来表示中毒、脱壳期、排异、消化和劫伤等有时限或层数的效果。

程序对应：

```text
SkillV3
IActiveAbilityProvider
CreatureOrganEffectDispatcher
CreatureConsequenceQueue
FinalDamageStage.Survival
FinalDamageStage.LastResort
Status
```

## 外观规则

WorldBox 的生物单位主体使用逐帧图片，因此组合外观分为三部分：

1. 固定形态决定主体图片和整套基础动画。
2. 共用外观系统只给当前可见的生物单位绘制器官附加图层，每只最多三层。
3. 技能、持续状态和生命过程负责吐息、雷劫、妖火、涅槃等短期特效。

附加图层要跟随主体当前动画帧、位置、大小、左右翻转和前后遮挡。九尾、巨翼、龟甲等大结构使用按等级制作的整张组合图片，不能为每条尾巴或每片甲壳单独创建一个绘制对象。

禁止为“身体方案 × 器官 × 等级 × 颜色”的每一种组合创建独立生物单位模板。只有蛇变蛟、鱼变鸟、真身变人形这类会改变基础动画、碰撞或移动方式的变化，才切换固定形态。

程序对应：

```text
CreatureMorphAsset
ActorAsset
CreatureOverlayRenderSystem
CreatureVisualRigAsset
```

## 妖兽数据放在哪里

每只已经启灵的妖兽最多长期保存五类数据。它们都挂在这只生物自己的扩展记录上，不再建立独立的妖兽身份、生态状态和器官来源组件。`Yao` 与 `YaoBody` 在启灵后必有；`YaoGenome`、`YaoDigestion` 和 `YaoCore` 只在真正出现血脉、消化或妖丹内容时添加，不创建空组件。

| 玩家和策划看到的内容 | 程序类型 | 作用 |
| --- | --- | --- |
| 妖兽自身 | `Yao` | 保存原始物种、启灵时间、稳定种子、当前境界、妖力、凝丹等突破准备，以及凤凰涅槃次数、九尾尾命等首版保命次数 |
| 身体总表 | `YaoBody` | 保存真身、人形、特殊第二真身和当前形态；每个形态的器官资料同时保存器官来源 |
| 血脉 | `YaoGenome` | 保存数量受限的器官遗传位、主血脉、隐性血脉和纯度 |
| 消化 | `YaoDigestion` | 最多保存三个尸体精华样本、进度和候选结果 |
| 妖丹 | `YaoCore` | 保存品质、元素、稳定度、裂痕和渡劫次数 |

普通凡兽在启灵前可以只有 `YaoAwakeningPotential`，记录已经积累的启灵条件。天劫和涅槃不是长期常驻数据：正在渡劫时临时添加 `YaoTribulation`，正在涅槃时临时添加 `Nirvana`，过程结束后移除。

`YaoBody` 是妖兽全部永久身体的唯一记录。每个形态中的器官资料保存槽位、器官、等级和来源；生成共用身体时只取槽位、器官和等级，来源不进入组合指纹。

`CreaturePhenotype` 仍然保留，但它只是当前活动身体的快速读取结果，供属性、战斗、能力和外观使用。它不进入存档，读档或换形后从 `YaoBody` 重新生成，所以不会与 `YaoBody` 形成两份永久身体资料。

妖兽不保存独立生态状态。每次选择行动时，直接读取生物当前位置、饥饿和生命、妖力、当前身体、原版繁殖资料和附近环境，决定捕食、休整、逃跑、繁殖或附近巡行。

妖修首版境界：

| 境界 | 玩家能观察到的变化 |
| --- | --- |
| 启灵 | 获得灵智、妖力、捕食炼化和自主修炼能力 |
| 炼血 | 淬炼先天结构，开始显出血脉和低阶器官 |
| 妖躯 | 可以完整替换器官，身体稳定度提高 |
| 妖丹 | 经准备和真实天劫凝成妖丹，神通获得稳定能源 |
| 化形 | 经化形劫得到固定人形，可在真身和人形之间切换 |
| 大妖 | 只保留后续内容位置，首版不预建空玩法 |

化形不会自动加入城市、文化、宗门、人类繁殖或外交。首版化形妖兽仍使用妖兽自己的自动行为和原有阵营关系。

## 吞噬与器官夺取

```text
真实猎杀或发现尸体
  -> 独占并消耗一次尸体精华
  -> 只提取允许使用的生物特征样本
  -> 放入最多三个条目的消化队列
  -> 转为妖力 / 临时适应 / 器官候选之一
  -> 根据身体相容、境界、稳定度和代价产生结果
  -> 成功替换器官，或炼化失败并发生排异
```

系统只读取预先登记的生物特征，例如水中呼吸、火焰腺体、硬质表被、飞行附肢和再生。禁止复制猎物的任意原版特性、技能、生物单位模板、运行时组件、总属性或程序回调。

血脉专属器官不能靠普通吞噬完整获得。没有凤凰血脉，只能炼出普通火心，不能直接得到完整涅槃心；没有鲲鹏血脉，只能获得降阶巨翼或水生代谢，不能复制双形神通。

## 血脉与返祖

- 血脉来自预先制作的静态定义，不能为每个始祖或混血组合临时创建新血脉。
- 每只妖兽最多一个主血脉和一个隐性血脉，纯度总和必须限制在 `0..1`。
- 每个器官遗传位最多保存一个显性和一个隐性结果。
- 子代出生时只读取当次复制出来的双亲血脉，不扫描祖先，也不继承境界、装备、临时状态、总属性或默认后天器官。
- 低纯度后代可以只携带潜伏血脉，仍作为凡兽等待启灵；条件再好也只能从启灵初阶出生，不能继承父母境界。
- 后天器官默认不能遗传。每次跨越大境界时，最多把一个兼容的后天器官稳定写入血脉。
- 返祖只在出生、启灵或跨越大境界时判断一次。成功后替换一个器官或进入一条预制形态路线，不能额外叠加整套祖先属性。

程序对应：

```text
YaoBloodlineAsset
YaoGenome
PatchBabyMaker.makeBaby_postfix
```

## 神话想象如何落地

| 想象 | 身体与器官组合 | 必须遵守的专属规则 |
| --- | --- | --- |
| 九尾狐 | 狐形、月华皮毛、尾冠、幻梦灵瞳、狐火腺 | 尾冠只做 1/3/6/9 尾四级；消耗尾命格保命 |
| 蛟化龙 | 蛇形 -> 蛟形 -> 龙形、鳞甲、行云肺、雷角 | 血脉纯度、妖丹和天劫共同解锁固定形态 |
| 鲲鹏 | 巨鱼真身、巨鸟真身、虚空胃、扶摇翼 | 同一只妖兽的两个固定真身共享妖丹和血脉，器官按当前形态生效 |
| 饕餮 | 兽形、深渊巨口、吞天胃、吞噬灵窍 | 拉拽、吞尸和炼化共用最多三个条目的消化队列 |
| 凤凰 | 鸟形、涅槃心、火羽、真火灵窍 | 致命伤在保命阶段触发唯一涅槃过程；成本递增，失败即真正死亡 |
| 玄武 | 龟形、玄甲、玄水肺、蛇尾 | 玄甲占多个槽；蛇尾是附加图层和攻击部位，不是第二个独立生物单位 |

这些神话生物都是静态配方、血脉和生命规则的组合，不能各自复制一套成长框架。

## 性能与数量上限

设计负载为 4096 个虫群个体加 1024 个活动妖兽。

- 每个当前身体最多 12 个槽位；虫群 5 个，妖兽基准 8 个。
- 每只妖兽最多两个常规战斗主动能力、一个防御反应和一个生命过程能力。
- 每个可见生物单位最多三层器官附加图层。
- 每只妖兽最多三个消化条目、两个血脉和每个遗传位两个结果。
- 只在出生、蜕变、器官替换、返祖、固定形态切换和读档恢复时重新整理身体效果。
- 普通受伤过程只读取已经整理好的固定数据，不能临时建立完整生物特征、界面数据、动态集合或字典。
- 枚举主动能力时只能读取现有结果，不能同步或修改当前身体。
- 妖兽详情界面关闭时，不持续建立详情数据。

程序对应：

```text
CreaturePhenotypeCompiler
IActiveAbilityProvider.Collect
ReadModel
```

## 与现有代码的对应关系

可以直接沿用：

- 属性缓存入口：`ActorExtend.RegisterCachedStatsBuilder`

- `IActivityCandidateProvider`

- 通用伤害规则注册表、通用事务 `Outbox`、全局 `StructuralCommit`
- 通用器官附加图层系统
- 能自动移除旧形态出生特性的转换服务

自动工作由虫群或妖兽先在自己的玩法内比较，再通过现有工作选择入口返回一个工作。只有以后真的出现多个玩法无法协调的冲突时，才设计新的通用候选协议。

## 存档边界

- 共用静态定义、整理结果缓存和 `CreaturePhenotype` 都不保存。妖兽读档后从 `YaoBody` 中保存的形态和器官资料重新建立当前身体。
- 从第一条可玩阶段开始，普通动物已经积累的启灵条件、潜伏血脉，以及启灵后的境界、身体总表、妖丹、消化等长期数据，都写入该生物单位自己的存档数据。
- 未领取的精华、劫云、粒子和其他短期世界对象不另做存档。正在进行的天劫或涅槃跟随所属妖兽保存，读取后继续原有过程；稀有血脉数量和调度索引从已恢复的生物单位重新统计，领地按当前位置重新产生。
- 妖兽存档只保存稳定编号、普通数值和有上限的数组，不保存运行时对象、生物单位引用、动态技能容器或静态定义对象。
- 虫群当前仍不保存母巢世界状态。所有虫群生物单位模板标记为不进入存档；巢核、炮台建筑和依赖对象在原版存档收集时过滤，读档后不能留下失去母巢状态的残缺对象。
- 不保留旧存档结构的兼容或迁移代码；结构变化时直接更新当前格式。

程序对应：

```text
ActorData.custom_data_string
ActorManager.loadObject
Entity / Actor / SkillContainer / Asset
ActorAsset.skip_save = true
SavedMap
```

## 首条实现路线

第一条完整内容采用“凡蛇化蛟”：

1. 普通蛇在高灵气水域长期存活并经历真实捕食后启灵。
2. 它获得妖力、领地捕食行为和基础毒牙能力。
3. 它吞食水生猎物，炼出水息肺候选，并替换一个兼容器官。
4. 它完成炼血和妖躯积累，准备凝结低阶妖丹。
5. 雷劫在世界中真实发生；成功后凝丹并切换蛟形，失败则裂丹、退化、重伤或死亡。
6. 后代继承一个显性和一个隐性结果，可能在启灵或突破时返祖。
7. 保存并重新加载世界后，原始物种、启灵时间、境界、身体、器官来源、血脉、妖丹和当前形态都能恢复。

这条路线依次用到共用身体规则、妖兽自动行为、吞噬、进阶、天劫、形态切换、遗传和存档。完成后，再按同一方法扩展更多小说中的妖兽想象。
