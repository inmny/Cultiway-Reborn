# 组合生灵与妖兽-摘要

**状态**：设计基线

**实施顺序**：共享表现型合同 -> 表达与视觉内核 -> 妖兽垂直切片 -> 领域扩展

**共享对象**：虫群个体、妖兽个体，以及未来确实需要组合身体的生物

**明确不做**：任意 C# 行为复制、无约束像素拼接、玩家器官编辑器、把虫群与妖兽合并成同一进化领域

## 设计目标

本规划增加“组合生灵”共享层和“妖兽”玩法域。共享层只回答一个问题：**一个已经确定的身体方案、形态和器官组合，如何被稳定校验、编译并表达为属性、语义、能力、战斗反应和外观。**

组合来源仍由各领域自行决定：

- 虫群通过母巢压力、样本、A/B Trial 和后续新生代固化组合。
- 妖兽通过凡兽启灵、个体经历、吞噬炼化、妖修突破、血脉遗传和返祖改变组合。
- 共享层不理解母巢、生物质、职虫、妖力、妖丹、血脉或天劫。

这样既能消除现有虫群设计中过度专用的器官表达代码，又不会把完全不同的成长逻辑塞进一个巨型 Mutation 系统。

## 已确定方向

1. 妖兽以自主生态为主，玩家主要通过灵气环境、猎物结构、灾害和神力间接影响。
2. 正式 UI 只读，不提供器官编辑器或逐项指定成长结果。
3. 外观采用“固定身体方案/主形态 + 有界器官覆盖层 + 技能与粒子特效”。
4. 妖修复用 `ProgressionService`、语义、SkillV3、战斗和状态基础设施，但使用独立 `CultisysAsset<Yao>` 与独立境界路线。
5. 第一条完整路线覆盖凡兽启灵、吞噬炼化、器官异变、妖丹天劫、血脉遗传、返祖和化形。
6. 重大运动能力和动画骨架变化必须切换固定 `ActorAsset` 形态；普通器官不能在运行时把任意地面动物直接改造成可飞行资产。

## 总体架构

```text
虫群领域                                      妖兽领域
压力 / 样本 / Trial                           启灵 / 吞噬 / 妖修 / 血脉 / 天劫
HiveGenome                                    YaoGenome + YaoProgression
        |                                              |
        +------------ 产出 CreaturePhenotypePlan ------+
                                      |
                                      v
                        组合生灵共享表达层
          校验 -> 稳定签名 -> 编译 -> 原子提交 -> 来源对账
             |          |          |          |          |
            属性       语义      主动能力    被动反应    视觉覆盖层
             |          |          |          |          |
         ActorExtend  Semantics   SkillV3   Combat     RenderSystem
```

依赖方向：

```text
Insects -> CreatureCompositions -> Core
Yao     -> CreatureCompositions -> Core
CreatureCompositions -X-> Insects
CreatureCompositions -X-> Yao
Core                 -X-> CreatureCompositions
```

共享实现位于 `Source/Content/CreatureCompositions/`。它是多个 Content 领域共享的内容基础，不下沉到 `Source/Core`，也不建立第二套 ECS、消息总线、技能、状态、战斗或存档框架。

## 共享静态定义

| 类型 | 职责 |
| --- | --- |
| `CreatureBodyPlanAsset` | 定义身体族、允许形态、有序槽位、基础复杂度和视觉 Rig |
| `CreatureBodySlotDefinition` | 定义槽位 ID、接受的器官类别、容量、对称与覆盖层通道 |
| `CreatureMorphAsset` | 映射固定 `ActorAsset`、运动模式、基础动画、碰撞、基础攻击和锁定槽 |
| `CreatureOrganAsset` | 定义器官类别、等级、槽位消耗、兼容、冲突、属性、语义、能力、反应和视觉 |
| `CreatureOrganRankDefinition` | 定义一个器官等级的强度、代价、技能与视觉变化 |
| `CreatureVisualRigAsset` | 定义每类基础动画帧的嘴、头、背、侧、腹、尾等锚点 |
| `CreatureOrganEffectAsset` | 定义静态效果族、触发事件、合并规则和代码处理器 |

共享层不把槽位数量写死。第一版约束为：

- 全局身体方案最多 12 个槽位。
- 虫群身体方案继续使用甲壳、运动、武器腺、代谢、神经五槽。
- 妖兽基准身体方案使用表被、运动、天生武器、吐息腺、感知、代谢、异质附肢、灵窍八槽。
- 一个高阶器官可以锁定多个槽位，但不能绕过身体方案容量。
- 妖丹、灵魂、修炼体系和临时 Status 不属于器官槽。

## 共享运行时快照

```text
CreaturePhenotypePlan
  BodyPlanId
  MorphId
  OrganStates[]       // SlotId + OrganId + Rank
  Signature

CreaturePhenotype
  Version
  BodyPlanId
  MorphId
  OrganStates[]       // 组件独占的深拷贝数组
  Signature
  Revision
```

签名只包含会改变实际表达的稳定内容：身体方案、形态、按槽位稳定排序的器官 ID 与等级。签名明确不包含：

- Actor ID、名字、出生时间和当前冷却。
- 母巢 ID、Trial ID、Baseline/Variant 分组和基因世代。
- 器官来自血脉、吞噬还是体细胞适应等领域来源说明。
- 妖力、妖丹裂痕、消化进度和临时状态。

领域来源由虫群或妖兽自己的状态保存，展示时与共享快照组合。这样同一实际身体能够命中同一个编译缓存，也不会因为 Trial 或来源标签变化重置能力。

## 能力表达语法

器官能力使用有限、可验证的组合语法：

```text
能力 = 触发 + 目标 + 投送 + 效果载荷 + 消耗 + 冷却 + AI 画像 + 视觉
```

- 允许的首批触发：主动、命中、受击、最终承伤、击杀、濒死、死亡、周期和进入环境。
- 允许的首批投送：自体、近战、冲撞、投射、吐息、光束、光环和地面范围。
- 允许的首批载荷：伤害、Status、位移、屏障、恢复、资源转移、形态切换和有配额召唤。

实现约束：

- 主动能力复用静态来源授予 SkillV3 容器与 `IActiveAbilityProvider`。
- 每种器官不得独立注册全局伤害、击杀或 Tick 回调。
- 共享层为全部组合器官注册一个稳定事件分发入口，按效果族和稳定 ID 处理。
- 需要脱壳、涅槃、断尾等结构后果时写入有界 `CreatureConsequenceQueue`，在 ECS Query 和伤害热路径之外提交。
- 会阻止本次致命伤的器官先在 `FinalDamageStage.Survival/LastResort` 同步校验并预留次数/资源、修改本次伤害；Queue 只提交随后形态、Status 和涅槃状态。
- 永久器官不是 Trait、LearnedSkill 或 Status。
- Status 只表达中毒、脱壳期、排异、消化、劫伤等有持续时间或层数的状态。

## 视觉模型

WorldBox 单位主体由固定逐帧精灵驱动，因此组合视觉分为三层：

1. `CreatureMorphAsset` 选择主形态和完整基础动画。
2. `CreatureOverlayRenderSystem` 为当前可见单位绘制最多三层器官覆盖层。
3. SkillV3、Status 和生命周期系统绘制吐息、雷劫、妖火、涅槃等短期特效。

覆盖层按 `CreatureVisualRigAsset` 的帧锚点同步位置、缩放、翻转和遮挡顺序。九尾、巨翼、龟甲等大结构使用分级聚合贴图，不为每条尾巴或每片甲壳创建独立 Renderer。

禁止创建“身体方案 × 器官 × 等级 × 色板”的 `ActorAsset` 笛卡尔积。只有蛇形到蛟形、鱼形到鸟形、真身到人形等改变基础动画、碰撞或移动方式的变化才切换固定形态。

## 妖兽领域模型

| 状态 | 作用 |
| --- | --- |
| `Yao` | 当前妖修境界、妖力和进阶资源 |
| `YaoIdentity` | 原始物种、启灵时间、稳定种子、当前生态阶段 |
| `YaoGenome` | 有界器官等位、主血脉、隐性血脉和纯度 |
| `YaoOrganProvenance` | 每槽器官来自先天、血脉、吞噬、突破或返祖 |
| `YaoDigestion` | 最多三个尸体语义样本、炼化进度和候选结果 |
| `YaoCore` | 妖丹品质、元素、稳定度、裂痕和劫数 |
| `YaoBodyState` | 妖兽身体计划的唯一权威：真身、人形/特殊双形计划、当前 Form 与切换冷却 |
| `YaoEcologyState` | 栖息地、领地、食性、迁徙和繁殖行为状态 |
| `YaoTribulationState` | 当前天劫阶段、实际承伤、完成条件和失败后果 |

妖修首版境界：

| 境界 | 核心变化 |
| --- | --- |
| 启灵 | 获得灵智、妖力、捕食炼化和自主修炼能力 |
| 炼血 | 淬炼先天结构，开始显化血脉和低阶器官 |
| 妖躯 | 开放完整器官替换并提高身体稳定度 |
| 妖丹 | 经准备和真实天劫凝结妖丹，神通获得稳定能源 |
| 化形 | 经化形劫获得固定人形方案，并可在真身与人形间切换 |
| 大妖 | 作为后续内容上限，首版只保留定义位置，不预建空机制 |

化形不自动加入城市、文化、宗门、人类繁殖或外交。首版化形妖兽仍使用妖兽生态 AI 和原有阵营关系。

## 吞噬与器官夺取

```text
真实猎杀或发现尸体
  -> 独占并消耗一次尸体精华
  -> 提取白名单语义样本
  -> 进入最多三个条目的消化队列
  -> 妖力 / 临时适应 / 器官候选三选一
  -> 相容、境界、稳定度和代价检查
  -> 替换槽位、炼化失败或排异
```

系统只读取注册过的语义切片，例如水生呼吸、火焰腺体、硬质表被、飞行附肢和再生。禁止复制目标的任意 Trait、Skill、ActorAsset、ECS 组件、属性总值或 C# 回调。

血脉专属器官不能靠普通吞噬完整获得。没有凤凰血脉只能炼出普通火心，不能直接获得完整涅槃心；没有鲲鹏血脉只能获得降阶巨翼或水生代谢，不能复制双形神通。

## 血脉与返祖

- 血脉使用静态 `YaoBloodlineAsset`，不为每个始祖或混血组合动态创建 Asset。
- 每个个体最多一个主血脉和一个隐性血脉，纯度总预算归一化到 `0..1`。
- 每个器官位点最多一个显性和一个隐性等位。
- 子代在现有 `PatchBabyMaker.makeBaby_postfix` 中只读取当次深拷贝的双亲 `YaoGenome`，不扫描祖先，也不继承境界、装备、临时状态、总属性或默认后天器官。
- 低纯度后代可以只携带潜伏 `YaoGenome` 并继续作为凡兽等待启灵；高条件后代也只能从启灵 0 级出生。
- 后天器官默认不遗传；每次大境界突破最多把一个兼容器官固化入血。
- 返祖只在出生、启灵或大境界突破时判定，成功后替换一个器官或切换一条预制形态路线，不额外叠加整套祖先属性。

| 饕餮 | 兽形、深渊巨口、吞天胃、吞噬灵窍 | 拉拽、吞尸和炼化共用有界消化队列 |

## 性能与数量上限

设计负载为 4096 个虫群个体加 1024 个活动妖兽。

- 每个共享表现型最多 12 个槽位；虫群 5 个，妖兽基准 8 个。
- 每个妖兽最多两个常规战斗主动能力、一个防御反应和一个生命周期能力。
- 每个可见单位最多三层器官覆盖层。
- 每个妖兽最多三个消化条目、两个血脉和每位点两个等位。
- 表现型编译只发生在出生、蜕变、器官替换、返祖或切换固定形态时。
- 伤害热路径只读取已经编译的固定数组，不构建语义画像、ReadModel、LINQ 集合或动态字典。
- `IActiveAbilityProvider.Collect` 只读，不同步或修改表现型。
- UI 关闭时不构建妖兽详情 ReadModel。

## 现有基础设施适配

可以直接复用：

- `ActorExtend.RegisterCachedStatsBuilder`
- `SemanticContributorService`
- `IActiveAbilityProvider`、`SourceGrantedSkillService` 和 SkillV3
- `FinalDamageStage` 与 `ActorExtend.RegisterActionOnFinalDamage`
- `ICombatGroupProvider` 和 `CombatWorldService`
- `ActorTransformationService`，但组合形态切换前必须补足来源化 Trait 对账选项
- `ActorJobSelectionRegistry`
- `ProgressionService` 的 Preparation、Challenge、Resolution 和提交事件
- `ActorData.custom_data_string` 与 Actor 加载补丁模式
- `MapBox.clearWorld()` 和 `WorldEntityLifecycle`

不能假设已经存在：

- `IActivityCandidateProvider`
- `AbilityGrant`、`SourceKind`、`ActorHandle` 或 `InstanceKey`
- 通用伤害规则注册表、通用事务 Outbox 或全局 `StructuralCommit`
- 通用器官覆盖层渲染器
- 能自动移除旧形态出生 Trait 的转换服务

工作选择先由妖兽或虫群自己的选择器在领域内比较效用，再通过 `ActorJobSelectionRegistry` 返回一个 Job。只有未来出现第二个无法由现有优先级机制解决的真实冲突时，才另行设计通用活动候选协议。

## 存档边界

- 共享定义、编译缓存和 `CreaturePhenotype` 派生快照不保存；加载后从妖兽 `YaoBodyState` 的静态 ID 和计划重建。
- 妖兽从第一个可玩阶段起，将非零启灵积累、潜伏 Genome，以及启灵后的 `Yao`、`YaoBodyState`、Core、Digestion 等长期领域状态写入自身 `ActorData`，并在 `ActorManager.loadObject` 后恢复。
- 未领取精华、劫云、粒子和其他短期世界对象不另建外部存档；加载后按 Actor 过程状态重建或执行明确中断结算。稀有谱系数量、领地和调度索引从已恢复 Actor 重建。
- 妖兽存档只保存稳定 ID、值类型和有界数组，不保存 Entity、Actor、动态 SkillContainer 或静态 Asset 引用。
- 虫群当前规划仍保持“不实现 Hive 世界级存档”的既定范围；所有虫群 ActorAsset 标记 `skip_save`，巢核/炮台 Building 或依赖对象在原版保存收集阶段被过滤，读档后不得残留失去 Hive 状态的对象。
- 当前实现不保留旧 Schema 兼容路径；结构变化时直接更新当前格式和测试存档。

## 首个纵向验收场景

首个可玩切片采用“凡蛇化蛟”：

1. 普通蛇在高灵气水域长期存活并经历真实捕食后启灵。
2. 它获得妖力、领地捕食行为和基础毒牙能力。
3. 它吞食水生猎物，炼化出水息肺候选，并替换一个兼容器官。
4. 它完成炼血和妖躯积累，准备凝结低阶妖丹。
5. 雷劫以真实世界过程发生；成功后凝丹并切换蛟形，失败则裂丹、退化、重伤或死亡。
6. 后代继承一个显性和一个隐性位点，可能在启灵或突破时返祖。
7. 保存并加载世界后，身份、境界、身体、器官、血脉、妖丹和当前形态一致恢复。

这条切片同时验证共享表现型、妖兽自主 AI、吞噬、进阶、天劫、形态切换、遗传和持久化，之后再按配方扩展到其他小说想象。
