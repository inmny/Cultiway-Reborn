# 东人皮肤风格名称-摘要

## 一句话目标

东人文化切换到哪个服饰风格（春秋/唐/宋/元/明/清/现代/扶桑/朝鲜），之后新建的单位、城市、王国、文化、氏族、家族、语言、宗教就按对应风格取名。

## 背景

- 东人目前有 10 种服饰风格，按文化存储、通过神力循环切换（见 `Source/Content/Const/EasternHumanSkinStyles.cs`）。
- 但名称系统与服饰无关：东人的名称集合只是克隆原版西方风格（斯拉夫、日耳曼、罗马等），生成的是音节拼凑名，与东方题材完全不搭。
- 原版所有名称（单位/城市/王国/文化/氏族/家族/语言/宗教）最终都经过同一个入口：`NameGenerator.generateName(Actor, MetaType, 种子, 性别)`，在这里按文化的服饰风格分流即可覆盖全部 8 类。

## 已确认的设计决策

| 决策点 | 结论 |
| --- | --- |
| 名称类型范围 | 全部 8 类：单位、城市、王国、文化、氏族、家族、语言、宗教；追加亚种名（独立入口 `Subspecies.generateName`，风格跟随出生地城市文化，其次任意东人文化，无文化时用“通用”词库） |
| 切换风格后的行为 | 仅新实体生效，已有实体不改名 |
| 各风格语言取向 | 通用~清=中文（朝代用字与取名习惯有差异）；现代=现代中文；扶桑=日式；朝鲜=韩式 |
| 词库存放 | `Content/Names/EasternHuman/<风格>.json`，代码显式加载，便于扩充修改 |
| 依赖第三方模组 | 不依赖（本机「中文名」模组的词库仅供参考格式） |

## 技术方案概览

1. **数据**：每个服饰风格一个 JSON 词库文件，包含 8 类名称所需的词组（姓氏、名、地名前后缀、国号、宗教后缀等）。
2. **加载**：`EasternHumanNameLibrary` 在初始化时读取全部词库文件到内存字典。
3. **组名**：`EasternHumanNameComposer` 按"名称类型 + 风格 + 性别"从词组中拼出名字（例如：单位=姓+名，城市=前缀+后缀，王国=国号+可选后缀）。
4. **接入**：Harmony 前置补丁挂在 `NameGenerator.generateName`：
   - 种族是东人 → 用组名器生成并跳过原版逻辑；
   - 文化未创建时（世界生成建国/建城早于建文化），依次回退双亲文化、单位种族判断；
   - 其余情况（非东人、词库缺失、词组为空）→ 交还原版，保证零破坏；
   - 从未换过装的文化默认按“通用”词库命名。

## 兼容性说明

- 名称在实体创建时生成并随存档保存；旧存档里的名字不受影响，无需手动迁移。
- 不修改原版名称资产，其他种族/模组种族的命名行为不变。
