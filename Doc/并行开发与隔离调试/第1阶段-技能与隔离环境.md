## 实际入口

技能：[develop](../../.agents/skills/develop/SKILL.md)。脚本：[dev.py](../../.agents/skills/develop/scripts/dev.py)。

在所属 worktree 中执行：

```bash
# 首次提供本机依赖路径，后续 setup 会记住它们。
python3 .agents/skills/develop/scripts/dev.py setup --game <游戏目录> --toolbox <DebugToolbox目录>
dotnet build Cultiway.csproj -c Debug
python3 .agents/skills/develop/scripts/dev.py start
python3 .agents/skills/develop/scripts/dev.py run <验证脚本.script>

# 暂停或保存重启：保留测试资料。
python3 .agents/skills/develop/scripts/dev.py stop
python3 .agents/skills/develop/scripts/dev.py start

# 正式交付：代码已提交推送，PR 已创建或更新。
python3 .agents/skills/develop/scripts/dev.py finish --pr <完整PR地址>
```

需要 Python 3.11 以上、GNU cp、Git 和本机 .NET SDK；现有纯资料检查使用 .NET 10。PR 核对使用已登录的 `gh`。客户端在独立工具缓存中构建，玩家安装与相邻 DebugToolbox 仓库的输出不被改写。

默认资料位于 `~/.local/state/cultiway-dev`：`config.json` 记录本机来源；`environments/` 记录各环境；`evidence/` 保留交付证据。生成的 `.cultiway-dev.props` 只属于本机，不提交到仓库。

`exec -- <已有验证命令>`让旧入口继承同一环境。已经接入 `common.py`、演示清单及基线入口；基线配置和固定构造输入另存到所属环境，不要求私有游戏携带开发文档。

`clean` 用于结束试用或放弃任务，同样先归档再回收游戏，不删除代码。`reap` 只读核对合并状态和本地修改；应用管理的 worktree 使用应用归档，普通 Git worktree 可再加 `--remove-worktree`。

## 已完成的验证

| 场景 | 实际结果 |
|---|---|
| 任意位置构建 | 应用 worktree 与 `/tmp` 下另一个 worktree 都完成开发构建；保留项目既有警告，无编译错误 |
| 纯资料转换 | 现有 WorldSaveTests 通过；引用直接来自 setup 设置的游戏位置 |
| 两个游戏同时运行 | 两个进程分别加载所属私有模组，使用不同会话文件、端口和资料目录 |
| 错误会话 | 临时将甲会话文件换成乙的，命令在修改资料前被拒绝；两边测试资料均未变化 |
| 单独退出 | 甲退出后，乙仍能正常运行游戏脚本 |
| 保存重启 | 新进程读取旧进程保存的环境资料，进程与启动编号确实变化，资料目录保持相同 |
| 旧演示入口 | 通过 exec 取得实际游戏登记的清单，输入输出位于所属环境 |
| 旧基线入口 | 通过 exec 执行 none 场景的 prepare 与 run；正式保存和再次加载均通过，固定输入在独立目录中比较一致 |
| 回收边界 | 自动检查覆盖外部进程、符号链接越界、归档失败、未交付修改、未合并 PR 和主目录保护 |

环境编号为 `bedc1ab3f0ac-default` 和 `a9ab7b575f56-default`。独立验证索引位于运行根目录 `evidence/isolation-validation-20261117.json`，每次脚本和命令的输入、响应及截图随环境证据归档。

可复核的最小实机脚本是 [smoke.script](../../.agents/skills/develop/scripts/smoke.script) 和 [smoke_restart.script](../../.agents/skills/develop/scripts/smoke_restart.script)。前者登记所属进程、日志和测试资料并截图，后者在真正重启后核对保留资料。无需为环境工具新建战斗场景。

## 当前限制

本机硬件 OpenGL 上下文不可用，本轮明确使用 `setup --software-rendering`，设置只作用于所属游戏进程。截图证明游戏已实际运行，结果用于流程和功能验证，不用于性能或最终外观验收。

Windows 存档隔离、其他旧验证脚本的固定路径，以及远端合并后立即无人值守回收，仍按后续需要处理。没有增加常驻服务或修改客户端生命周期设置。

原版源码不复制进游戏环境；worktree 缺少 `.GameSource` 时，从本机已有参考目录读取。测试失败或程序异常退出后保留登记和证据，下一次操作可恢复或回收。
