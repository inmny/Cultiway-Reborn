## 具体说明

### 步骤1

新建 `Content/Names/EasternHuman/` 目录，每个风格一个 JSON：`common.json`（通用，对应风格 key `1`）、`chunqiu.json`、`tang.json`、`song.json`、`yuan.json`、`ming.json`、`qing.json`、`modern.json`、`fusang.json`、`chaoxian.json`。

结构（第 1 阶段每个数组先放 10~20 个词）：

```json
{
  "style": "tang",
  "unit": {
    "surnames":    ["李", "王", "张"],
    "given_male":  ["承", "玄礼"],
    "given_female":["婉", "采薇"]
  },
  "city": {
    "prefix": ["长", "洛", "金"],
    "suffix": ["安", "阳", "州"]
  },
  "kingdom": {
    "names":    ["唐", "梁", "岐"],
    "suffixes": ["朝", "国"]
  },
  "clan": {
    "suffixes": ["氏", "氏族"]
  },
  "family": {
    "suffixes": ["家", "府"]
  },
  "culture": {
    "names": ["中原", "关陇"]
  },
  "language": {
    "names": ["雅言"]
  },
  "religion": {
    "names":    ["玄", "太清"],
    "suffixes": ["教", "道", "宗"]
  }
}
```

组合规则（组名器按此拼）：

| 名称类型 | 组合方式 |
| --- | --- |
| 单位 | 姓 + 名（按性别取 `given_male`/`given_female`；朝代差异在第 2 阶段通过词表本身体现，例如先秦单名占比高就在 `given_*` 里多放单字） |
| 城市 | prefix + suffix |
| 王国 | name，40% 概率追加 suffix |
| 氏族 | 随机姓（复用 unit.surnames，含复姓）+ clan.suffixes |
| 家族 | 随机姓 + family.suffixes |
| 文化 | culture.names 随机 + "文化" |
| 语言 | language.names 随机 + "语" |
| 宗教 | religion.names 随机 + religion.suffixes 随机 |
| 亚种 | subspecies.names 随机 + subspecies.suffixes 随机；重名时按原版规则追加结尾音节 |

### 步骤2

新建 `Source/Content/Names/EasternHumanNameLibrary.cs`：

- 静态类，`Load()` 用 `Path.Combine(ModClass.I.GetDeclaration().FolderPath, "Content/Names/EasternHuman")` 读取全部 JSON（参考 `SpiritVeinSettings` 的加载方式）。
- 解析为 `Dictionary<string, NameStyleData>`（key=风格 key，与 `EasternHumanSkinStyles` 的 key 一致）。
- `TryGet(string styleKey, out NameStyleData)` 供组名器查询；文件缺失或字段缺失时记日志并返回 false，不抛异常。
- 数据类 `NameStyleData` 内嵌在该文件或同目录，字段与 JSON 一一对应。

### 步骤3

新建 `Source/Content/Names/EasternHumanNameComposer.cs`：

- 入口：`string Compose(NameStyleData data, MetaType type, ActorSex sex)`。
- 用 `Randy`（游戏全局随机）取词，保持与原版一致的随机习惯。
- 返回前把长度截到 30 字符以内（对齐原版 `OnomasticsData.MAX_NAME_LENGTH`）。
- 词组为空时返回 `null`，由补丁层决定回退原版。

### 步骤4

新建 `Source/Patch/PatchNameGenerator.cs`（类名以 Patch 开头自动安装）：

- `[HarmonyPrefix, HarmonyPatch(typeof(NameGenerator), nameof(NameGenerator.generateName))]`
- 流程：
  1. 解析种族与文化来源：单位自身文化 → 双亲文化（世界生成建国/建城早于建文化，对齐原版无文化回退）→ 单位自身种族；种族不是东人 → 返回 true。
  2. 从文化数据读 `ContentCultureDataKeys.SkinID_int`，经 `EasternHumanSkinStyles.TryGetKey` 解析风格；未选过风格时默认“通用”。
  3. `EasternHumanNameLibrary.TryGet(styleKey, out data)` 失败 → 返回 true。
  4. `Compose(data, pType, pSex)` 返回 null → 返回 true。
  5. 否则 `__result = 名字; return false`。
- 注意 `generateName` 的签名以游戏源码为准（`(Actor pActor, MetaType pType, long pSeed, ActorSex pSex)`），种子参数本阶段不强依赖。
