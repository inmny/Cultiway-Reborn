## 具体说明

### 数据所有权与存读档顺序

| 信息 | 唯一持有者 | 保存内容 |
| --- | --- | --- |
| 村庄月历与编制模板 | 村庄数据 | 12月标记、三层名称、指挥称谓、数量与默认命名格式 |
| 营、小队 | 村庄编制记录 | 稳定编号、上级、名称、正式指挥者和成员槽位编号 |
| 原版 Army | 原版 ArmyData | Army身份、军队名称、原版统领及成员归属 |
| 后备候选 | 村庄名单 | 人物编号，不重复保存其职业和当前任务 |
| 个人军功 | ActorData 中的模组数值 | 军功整数，随人物保存 |
| 执行中的操练、阵位和路径 | 运行期服务 | 不把对象引用或寻路请求写进永久数据 |

所有本功能内容随原版世界存档保存。采用项目已有的数据扩展方式，不增加另一份跨世界全局人员名册，也不同时把同一关系存进村庄、Army和人物三处。

读档顺序：恢复原版村庄、人物及 Army → 读取村庄策略与下级编制 → 解析实际现役与后备 → 清理无效关系并补任空缺 → 按当前月份和仍有效军令恢复任务。

读档不重放历史击杀、不重复补发军功、不沿用旧对象引用。角色已死亡、转村或不再属于该 Army 时清除其失效下级关系；保留其个人军功。

### 生命周期

| 变化 | 处理 |
| --- | --- |
| 人物死亡 | 从所属小队或后备名单移除，留下空位；指挥者死亡触发本单位继任 |
| 士兵修炼入门 | 显示改为特殊者，现役和军职保留，退出强制日常勤务 |
| 成为领主或国王 | 释放普通军事职位，按管理者行为生活，原部下补任 |
| 转村、退役、国家变化 | 在原版归属变化后更新相关村庄索引，取消失效命令与旧阵位 |
| 村庄易主 | 月历和本地编制模板随村庄保留，军令重新验证国家归属 |
| 原版 Army 解散 | 清除旧 Army 的运行期任务；村庄保留策略和可重新使用的命名设置 |
| 村庄毁灭 | 清理本村编制、后备和协调行动；人物军功仍归人物所有 |
| 乘船或乘车 | 保留现役与队伍身份，暂停阵位约束；到达安全结束点再执行休息、改编或补缺 |
| 切换世界 | 清空所有运行期索引、活动、路径和窗口绑定 |

原版城市当前会随机尝试征兵、按人口和粮食校验士兵上限。需把“补缺候选选择”和“编制上限”放进原版征兵入口，防止后备刚恢复工人身份就被无缺额地再次征回。

村庄现役可少于自定义编制上限，粮食与原版可征兵额度不足时允许缺编。后备人员不能被用来伪造原版现役人数，也不能为了达到自定义数量绕过既有征兵规则。

铁路运输仍按原版 Army 身份组织军令批次；新营、小队是其下属信息，不把第三层拆成多个 Army。需要验证取消军令、到站后休息与同一小队分批乘车的恢复过程。

### 更新与寻路预算

采用事件加有界轮询：

- 月份变化只将相关村庄的作息状态标记为待处理，分批通知在岗人员。
- 死亡、军籍、村庄归属和修行身份变化只更新受影响人物与单位。
- 军功增加只更新个人数值和排序标记，不扫描全世界或立刻重选全军指挥者。
- 只为有实际任务的普通小队或接令小队创建协调活动；上级负责命令和布局，不重复创建演员执行记录。
- 阵位依据配置和槽位缓存，领队移动达到阈值、方向改变或任务版本改变时才重请求路径。
- 人数不足、空位、缺粮和不可达状态使用冷却重试；地形或命令变化可提前唤醒相关单位。
- UI读取已发布统计和当前可见条目，不每帧统计全村、重新整编或检测所有阵位可达性。

建议以新增普通帧主线程耗时约1毫秒以内作为性能目标，而非已测结果；大规模改编、读档恢复和整军集合必须分批推进。每帧处理量设预算，加速跨过多个月时直接计算当前状态，不补跑已经过去的每个月任务。

站位受阻只做有限范围查询，复用现有寻路与连通数据。禁止为每个成员持续进行全城或全图搜索；空间不足应显示无法成阵原因并改变任务或等待。

### 整体验收

| 场景 | 必须观察到的结果 |
| --- | --- |
| 普通工人跨入休息月 | 不再领取强制生产岗位，当前可分割任务结束，能够自主生活 |
| 普通士兵跨入休息月 | 释放日常操练与巡逻，但仍属于同一Army与小队 |
| 全年休息 | 不偷偷恢复工作；明确军令仍可依法集结士兵 |
| 管理者 | 不因月份或自动军职任命失去自由活动 |
| 特殊者与特殊军职者 | 平时继续修炼、研究或宗门事务；只有明确军令接管军职人员 |
| 三层自定义 | 名称、称谓和数量生效；顶层始终只有一个原版Army |
| 缺编与超额 | 缺编可以行动；超额者真实恢复工人或特殊身份，没有现役统计残留 |
| 后备补缺 | 无缺额不入伍；有缺额且原版资格满足后才进入Army和具体小队 |
| 军功 | 各种有效击杀只加一次，助攻与队友不冒领；退役、转村与读档不清零 |
| 军功任命 | 新任命按规定排序，原版随机统领选择不覆盖，新增1点军功不即时换将 |
| 特殊指挥者 | 日常代理能带普通士兵行动，正式军令集结后正确恢复指挥关系 |
| 默认10人队 | 指挥者在前，9人在后方3×3格点，无重复演员或自跟随 |
| 整营与整军 | 下级矩形占位不重叠，兼任者只出现一次，转向和缺员不造成目标冲突 |
| 接敌与撤退 | 方阵允许战斗动作，Army撤退、攻击、到期及撤销指令传到所有下级 |
| 运输与改编 | 在途成员保持归属，安全结束点才转后备或恢复勤务，不把乘客留在旧阵位 |
| 存读档与切世界 | 名称、月历、军功和编制正确恢复，没有幽灵成员、重复军队或任务泄漏 |
| 大村庄与加速 | 可见改编逐批推进，岗位、阵位、任命不每帧引起全城扫描或重复寻路 |

实现时先完成每个阶段的必要检查，整体验收集中验证跨系统边界。设计阶段不运行游戏变更、编译或大规模性能测试来代替未来实现验收。
