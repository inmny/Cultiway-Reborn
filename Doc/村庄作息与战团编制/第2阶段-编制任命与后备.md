## 具体说明

### 唯一第三层

第三层直接对应 `city.army`。名称沿用原版 Army 命名与自定义名称，统领直接对应 `Army.getCaptain()`／`setCaptain()`，军队成员仍由原版关系维护。

新建的营和小队是这个 Army 的下级记录，保存编号、名称、上级、指挥者和成员关系，不作为另一个 `Army` 注册进原版军队管理器。

没有现役兵员时允许原版城市暂时没有 Army 实例；弹窗显示“未成军”并保留村庄编制设置。第一批兵员入伍后由原版流程创建唯一 Army，再恢复下级编制，不能为展示空树生成幽灵军队。

### 三层自定义

| 层级 | 默认名称 | 数量字段 | 建议默认 |
| --- | --- | --- | --- |
| 第一层 | 队 | 每队总人数，包含队长 | 10人 |
| 第二层 | 营 | 每营最多下辖多少队 | 10队 |
| 第三层 | 团／原版 Army | 这支 Army 最多下辖多少营 | 10营 |

三层均允许修改层级名称、指挥称谓；已经创建的营和小队可以单独命名。第三层实例名称修改原版 Army 的自定义名称。

数量要求输入正整数，总容量为三项乘积。乘积采用足够大的整数计算，越界或不可表示的输入在提交前说明原因。

允许缺编，创建多少实际下级单位取决于人数；空缺不自动生成士兵。用户设置很大容量时不预建所有空队、空营或所有阵位。

建议由下级指挥者兼任上级指挥者，每个人只计一次人数。默认1000人总编制包含全部指挥者。兼任者的移动点位按第3阶段处理，不重复放置人物。

日常伤亡不重排整个编制：保留队伍编号和成员槽位，优先填补原缺口。玩家修改编制时才计算新的分队方案，预览人数、缺额、需转后备者和任命变化。战斗、登船或在途运输中的人员在该段结束后改编。

### 指挥者任命

先核对存活、归属、军籍及本层级候选范围，再比较：

1. 个人军功，较高者优先。
2. 原版军事能力 `warfare`，较高者优先。
3. 当前等级，较高者优先。
4. 稳定人物编号，确保同分不反复互换。

小队长从本队现役成员中选；营长从所属小队长中选；第三层统领从所属营长中选。兵员很少时同一人可以兼任三层。

特殊者有军职时也参加比较，任命不会取消其全年自由活动规则。管理者不进入自动军事任命候选。

任命发生在建军、职位空缺、正式重编及玩家“按军功重新评定”时。现任合格时不会因为另一人刚获得1点军功而立即被替换。死亡、退役、叛变、转村或升任管理者会使原职位失效并触发继任。

原版 `Army.findCaptain()` 默认会随机或就近找统领，必须与本方案选任统一：对已接管的村庄军队使用军功结果，不能让两个流程轮流覆盖。任命调用原版 `setCaptain()`，保留旗帜、统领历史和军队界面的语义。

原版建军还会先随机选人创建 Army。应在真实成员完成登记后统一进行初始任命，不把创建时的临时人选永久保留下来，也不在军队尚空时选入没有军籍的人。

特殊指挥者不参加日常勤务时，从本单位当前可执勤成员中按相同军功顺序选择代理领队。代理只负责该次任务，正式军职不变；明确军令下再由可到场的正式指挥者带队。全部成员均豁免日常勤务时不启动强制操练。

### 后备释放与补缺

后备名单归村庄管理，只表示优先补缺的候选资格。

| 状态 | 普通人员 | 特殊人员 |
| --- | --- | --- |
| 未入伍、列为后备 | 工人，按村庄作息领取任务 | 特殊者，继续自身活动 |
| 补缺征召成功 | 士兵，进入原版 Army 和一个小队 | 特殊者，获得军籍和小队位置 |
| 再次退为后备 | 释放军籍和军职，恢复工人生活 | 释放军籍和军职，恢复原有活动 |

后备不计入 `Army.units`、现役人数、军事阵位和日常操练参与人数。其军功与个人能力保留，不因等待补缺被清空。

补缺顺序：

1. 死亡、退役等事件产生实际缺额，标记所属小队需要补员。
2. 优先从本村后备中筛选；不足时再按原版允许的普通居民征兵入口补足。
3. 在合格候选中按军功、军事能力、等级、稳定编号排序。
4. 通过原版征兵资格、世界规则、粮食、资源、征兵间隔和兵力上限检查。
5. 成功征召后写入原版职业和军队关系，再进入确有空位的小队，最后重新评定空缺军职。

和平时建议工作月补缺，休息月保留缺额；紧急防卫或明确军令下可立即尝试。没有缺额不从后备名单征召，也不为了军功高而不断让工人入伍、让现役退伍。

总编制上限与原版允许兵力共同约束征兵，不能通过直接设置 `army` 绕过原版资格。征召使用原版城市征兵流程；释放使用 `stopBeingWarrior()`、`removeFromArmy()` 等生命周期入口，维护人数、职业和统领检查，避免只修改列表。

玩家缩小编制时，优先保留新结构中仍有合法岗位的现任指挥者，再按军功等规则选择其余保留者。若新结构连原有指挥岗位也无法容纳，按同一任命顺序保留可容纳者，其余解除军职。超出人数在安全结束点释放为后备。正在交战或运输中的人显示“待转后备”，不能突然从战场或车船中移走。

## 数据与落点

| 建议数据 | 保存位置与职责 |
| --- | --- |
| 月历、三层名称和数量模板 | 村庄数据 |
| 营、小队编号、名称、上级和成员槽位 | 村庄的军事编制记录，绑定当前原版 Army |
| 顶层成员、统领和 Army 实例名称 | 原版 Army 与 ArmyData，保持单一来源 |
| 后备人物编号 | 村庄候选名单；只保存编号，不保存永久对象引用 |
| 军功 | 人物数据，与编制和后备状态分离 |
| 代理领队、临时集结和路径 | 运行期任务状态 |

建议内容服务放 `Source/Content/VillageMilitary/`，分别处理编制、任命、补缺和原版 Army 的适配。常规更新只处理受影响的村庄和小队。

## 验收

- 同一村庄始终只有一个原版 Army；三层名称、数量独立修改有效。
- 默认1000人中指挥者不重复计数，缺编小队可以行动。
- 超额者真实恢复工人或特殊者身份；补缺后才出现在 Army 和编制树中。
- 后备人员不会被原版随机征兵绕过容量限制，缺粮时不会每帧反复申请。
- 军功影响所有层级任命；原版随机统领选择不覆盖结果。
- 特殊指挥者自由活动期间代理能够带队；明确军令能正常集结。
- 兵员迁移、易主、叛变和全部阵亡后没有重复归属或幽灵成员。
