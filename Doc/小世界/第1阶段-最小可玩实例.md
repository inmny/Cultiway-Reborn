# 第1阶段-最小可玩实例

本阶段建立一个不依赖 `World.world` 运行对象的最小可玩实例：地图在 Runtime 中直接复用原版 `TileTypeBase` 的最终 terrain 字段与 `sprites.main`，`SubWorldManager` 持有会话内 Runtime，格子、时钟、移动单位和非模态浮窗彼此独立。

## 具体说明

### 设计边界

- 不创建第二个 `MapBox`、`WorldTile`、原版 Actor 或 Building。
- 不创建 SubWorld 专属基础 terrain ID、通行字段副本、地面 sprite、墙体 sprite 或共享 terrain Core；静态语义和视觉资源直接来自原版对象。
- 原版 `WorldTile`、`WorldTilemap`、Quantum sprite 运行逻辑、原版 A*、hashset、`current_tiles` 和 `index_id` 不进入 SubWorld；只复用 `TileTypeBase` 最终对象及其 Tile/Sprite Asset。
- 不接入真实主世界角色；第二阶段才实现参与者投影。
- 不加入战斗、物品、迷雾和复杂机关。
- 只提供一个内部验证 Template，一名测试 Pawn 从入口移动到出口。
- Runtime、Manager、浮窗和销毁流程在本阶段形成完整会话生命周期。
- 浮窗打开时主世界保持可见、可操作并继续按自己的速度运行。

### 步骤 1：直接复用原版 TileTypeBase 并建立地图数据

#### 原版对象使用规则

`TileType` 与 `TopTileType` 均继承 `TileTypeBase`。SubWorld 不建立中间定义，直接使用基类已经提供的全部 terrain 字段与视觉引用：

```text
block / block_height / walk_multiplier
damage_units / damage
ground / liquid / wall
layer_type / render_z
material / sprites
```

`TileLibrary`、`TopTileLibrary` 提供原版静态对象，Cultiway `TerrainTraversalRules.Init()` 直接原地修改这些对象。SubWorld Runtime 在该初始化完成后创建，因此持有对象时天然得到最终值，不冻结 terrain 快照，不复制默认定义，也不修改 `TerrainTraversalRules.cs` 增加初始化步骤。

运行时解析只留在 `SubWorldGrid` 和 `SubWorldViewHost` 内，不新增 `Source/Core/Terrain/`、public interface、definition 类型或独立解析器。字符串 Asset ID 属于当前 Runtime 的 `MapData` 和 Template 配置，实际 terrain 就是原版 `TileType`/`TopTileType` 对象。

#### MapData

tile 采用紧凑数组：

```text
SubWorldMapData
  Width
  Height
  SubWorldTile[] Tiles
  int[] EntryTileIndices
  int[] ExitTileIndices

SubWorldTile
  MainAssetId
  TopAssetId
```

tile index 规范为：

```text
index = y * Width + x
```

规则固定如下：

- `SubWorldMapData` 和 `SubWorldTile` 是当前 `SubWorldRuntime` 的地图数据，不是原版 `TileTypeBase` 的复制定义。
- `SubWorldTile` 只持有原版字符串 Asset ID。`MainAssetId` 必填，`TopAssetId` 为空表示没有 Top；重复出现的 Asset ID 仍按格直接写在数组中。
- `Tiles[index]` 严格使用上述 row-major 公式。`EntryTileIndices` 与 `ExitTileIndices` 是地图目标元数据，不能混入 terrain 字段。
- Runtime 创建时，`SubWorldGrid` 对每个 `SubWorldTile` 直接调用 `AssetManager.tiles.get(MainAssetId)`，并在 `TopAssetId` 非空时调用 `AssetManager.top_tiles.get(TopAssetId)`。Grid 在并行数组中缓存逐格直接 `TileType`/`TopTileType` 引用，不新增 catalog、resolver 或其他间接层。
- 任一必需 Asset ID 缺失都会使 Template 创建失败；不回退到 `soil_low`，不复制默认定义。
- 有效 gameplay terrain 固定为 `Top ?? Main`。Navigation、格伤害和视图分别读取有效对象真实的 `block`、`block_height`、`walk_multiplier`、`damage_units`、`damage`、图层与 `sprites.main` 等字段。
- 地图变化只修改对应 `SubWorldTile.MainAssetId/TopAssetId`；变更完成后刷新该格的直接引用缓存并标记 dirty tile，不写入原版 Asset。
- 所有坐标转换和邻接由 `SubWorldGrid` 提供，不在调用方重复计算。

本步验证：`TerrainTraversalRules.Init()` 后由 `AssetManager.tiles.get("mountains")` 取得的对象应直接呈现 Cultiway 最终语义 `block=false`、`walk_multiplier=0.45`、`damage=1`，Grid 缓存的是同一原版对象；`MapData` 中只有逐格 `MainAssetId/TopAssetId` 和独立入口出口数组，不出现对象、index/hash 或 `WorldTile`。

### 步骤 2：建立 Template、最小 Runtime 与 Manager

新增 `Source/Core/SubWorlds/`，静态 Template 与有状态 Runtime 职责明确分开。不存在实例数据中间层；实例身份、地图、实体、时钟和随机状态直接属于 Runtime。

#### Template

```text
SubWorldTemplateAsset
  Id
  Width
  Height
  GeneratorId
  ClockProfileId
  VisualProfileId
```

由 `SubWorldTemplateLibrary` 注册内部模板：

```text
Cultiway.SubWorld.Template.TestSubWorld
```

Template 通过 Asset ID 引用 `SubWorldGeneratorAsset`、`SubWorldClockProfileAsset` 与 `SubWorldVisualProfileAsset`。三类资产分别由 `SubWorldGeneratorLibrary`、`SubWorldClockProfileLibrary` 和 `SubWorldVisualProfileLibrary` 注册；`Standard` 表示当前阶段提供的基础 Profile 配置，不属于 `SubWorldManager` 的运行时状态。

#### Runtime

每次创建实例都会产生完整对象：

```text
SubWorldRuntime
  InstanceId
  TemplateId
  Seed
  State
  MapData
  EntityStore
  SystemRoot
  Grid
  Clock
  Random
  CommandQueue
  EventQueue
  ObjectiveState
  Revision
```

`InstanceId` 由 Manager 的会话内递增序列生成，不使用 ECS Entity ID。`Revision` 每次地图或实体结构变更完成后递增，用于拒绝过期路径结果和命令。

首阶段测试 Pawn 只复用项目通用 ECS 组件：

```text
Position
```

`Position` 使用小世界局部连续坐标，入口格中心为 `(x + 0.5, y + 0.5, 0)`；需要 tile index 时由 `SubWorldGrid` 根据坐标计算，不维护重复位置组件。Runtime 身份由 Store 所属的 `SubWorldRuntime` 表达，不写入每个 Entity。tile 不创建 Entity。每个 Runtime 拥有独立 Store、Root、Grid、Clock、Random 和 system 对象，共享项目唯一 `ParallelJobRunner`，不为实例创建线程池。

#### Generator

`TestSubWorldGeneratorAsset` 由 `SubWorldGeneratorLibrary` 以 `Cultiway.SubWorld.Generator.TestSubWorld` 注册，直接逐格写入 Runtime 的 `SubWorldMapData`。首版所有格以原版 `soil_low` 作为 Main，墙格以原版 `wall_ancient` 作为 Top，其余格的 `TopAssetId` 为空；入口和出口写入独立 tile index 数组与 SubWorld overlay，不注册新的基础 terrain。

1. 生成外围 `wall_ancient` 阻挡。
2. 在左侧选择入口。
3. 在右侧选择出口。
4. 放置有界阻挡。
5. 生成一名测试 Pawn。

Generator 先在创建调用内构造完整场景并验证，成功后才交给 Runtime。相同 Template、Seed 和创建参数必须得到结构一致的 `MapData`、入口出口与初始实体。

#### Manager

`SubWorldManager` 是有状态运行时所有者，内部持有：

```text
Dictionary<InstanceId, SubWorldRuntime> Runtimes
SubWorldFloatingPanel
SubWorldViewHost
```

对外只提供：

```text
Create(templateId, anchor, seed, parameters)
Get(instanceId)
Destroy(instanceId)
Update(unscaledDeltaTime)
IssueCommand(instanceId, command)
ShowFloatingPanel(instanceId)
```

- `Create` 解析 Template、运行 Generator、构造完整 Runtime 并加入集合，然后返回 InstanceId。
- `Get` 取得当前会话中已经存在的 Runtime，供只读查询和 Manager 内部协作使用。
- `Destroy` 解绑当前 View，销毁对应 Store、Root、队列和实例级对象，并从集合移除。
- `Update` 是全部 Runtime 的统一帧入口，按实例时钟推进完整 tick。
- `IssueCommand` 只把命令送入指定 Runtime 的边界队列；调用方不直接写组件。
- `ShowFloatingPanel` 把唯一浮窗绑定到指定 Runtime，不改变它的逻辑状态。

切换世界、返回主菜单或 Mod 重载时，生命周期入口停止 Manager 更新，并对集合中的每个 InstanceId 执行同一销毁逻辑。不会把 Runtime 移出内存后继续保留实例。

本步验证：同一 Seed 创建的 `MapData.Tiles` 和入口出口数组一致；逐格 ID 在两个 Runtime 中都解析到同一批原版 Asset 对象，但两个 Runtime 的 Store、Grid、Clock、Random 和 Entity 互不引用。调用 `Destroy` 后对应 Store、队列和视图绑定立即消失，其他 Runtime 不受影响。

### 步骤 3：实现实例级固定时钟与命令队列

扩展步骤 2 已注册的首个 ClockProfile Asset：

```text
Cultiway.SubWorld.Clock.Standard
FixedStep = 0.1 local seconds
AllowedLocalSpeedOptions = Paused / 1x / 2x / 4x
DefaultLocalRate = 1
RunsWhileParentPaused = true
```

`SubWorldClock` 使用 `Time.unscaledDeltaTime × DefaultLocalRate × LocalSpeed` 累计时间。主世界继续使用 WorldBox 自己的时间控制；打开浮窗不修改 `World.world._is_paused` 或全局倍速。用户单独暂停主世界时，本验证 Profile 仍允许小世界按局部按钮推进。

规则：

- 每次只推进完整固定 tick。
- 单渲染帧最多补算 4 tick，剩余累计时间留到后续帧。
- Pause 不清空 accumulator。
- 倍速只增加待执行 tick 数，不改变 FixedStep。
- TickIndex 每完成一次逻辑 tick 加 1。

#### 命令

首阶段支持：

```text
MoveToTileCommand
PauseCommand
SetLocalSpeedCommand
```

移动命令包含 InstanceId、Revision、EntityId 和目标 tile。命令在 tick 边界验证并进入领域队列；UI 不直接写 Position。

Manager 每个渲染帧先处理各 Runtime 边界队列中的最多 32 条命令，再累计实例时钟。这样 Pause 和 SetLocalSpeed 在没有待执行逻辑 tick 时仍可恢复实例；MoveToTile 只在边界验证 InstanceId、Revision、EntityId 和目标格，并进入 Runtime 私有移动领域队列，步骤 5 才消费该队列执行寻路与位移。

待执行固定 tick 逐个通过 `FramePriorityGovernor` 申请 Cultiway 模拟预算；预算不足时不消费 accumulator。禁用帧优先调度器时仍遵守 Profile 的单实例单帧 tick 上限。

每 tick 最多处理 32 条命令和 32 条事件，超出部分留待后续 tick。

本步验证：在主世界 1x、暂停和其他倍率下分别运行小世界 Pause/1x/2x/4x，只有目标 Runtime 的 `LocalTime`、`TickIndex` 和 Pawn 位移速度变化。

### 步骤 4：实现 RenderTexture 小世界浮窗

实施遵守 `Prompts/UI.md`。小世界视图归类为 HUD/世界覆盖层：新增 `SubWorldFloatingPanel`，挂到核实过的主世界 HUD Canvas 节点，不使用 `ScrollWindow`、`AbstractWideWindow`、原版窗口历史或模态遮罩。

#### 结构

```text
FloatingPanel  默认停靠右上
  DragHeader  高 28
    实例名
    折叠
    关闭
  Toolbar  高 28
    Pause
    1x / 2x / 4x Segmented Control
    居中视图
  Viewport  16:9
    RawImage
  Inspector  可折叠
```

浮窗默认视口为 `560x315`，RenderTexture 保持 `640x360`。面板受屏幕安全边距约束，可以拖动但不能移出屏幕；低分辨率下等比缩小视口。首版不提供最大化、全屏或自由拉伸，避免遮住主世界主要操作区域。

#### 非模态行为

- 打开、切换、折叠或关闭浮窗都不暂停主世界，不修改主世界速度。
- 指针位于浮窗 Header、Toolbar、Viewport 或 Inspector 内时由浮窗消费；位于其外时继续选择、拖动和缩放主世界。
- 点击主世界不会关闭浮窗，也不会改变当前绑定实例。
- 折叠只保留 Header，并停止 Camera.Render；Runtime 的 LocalTime 继续按当前局部速度运行。
- 同时只存在一个 `SubWorldFloatingPanel`，切换实例时复用 ViewHost 和 RenderTexture。

#### 渲染对象

`SubWorldViewHost` 创建：

- 独立正交 Camera。
- 独立 Unity Layer。
- `640x360` ARGB32 RenderTexture。
- 私有 Main/Top Tilemap、TilemapRenderer 和 Material 实例。
- SubWorld 状态 overlay Tilemap 与测试 Pawn SpriteRenderer 池。

ViewHost 直接消费 `SubWorldGrid` 缓存的原版对象。每格 Main Tilemap 放入 Main `TileTypeBase.sprites.main`；`TopAssetId` 非空时，Top Tilemap 直接放入 Top 的 `sprites.main`，否则清空该格。首版只使用原版 `main` Tile，不做变体选择，不创建私有 Tile 复制品。Tile/Sprite Asset 与主世界共享；Tilemap、Renderer、由原版材质来源创建的 Material 实例、Camera 和 RenderTexture 归 ViewHost 私有。

基础地面和墙体不走 `GameResources/cultiway/sub_world/`，也不调用主世界 `WorldTilemap` 或 Quantum。该逻辑直接留在 ViewHost，不新增 terrain 视觉 adapter 文件。

Camera 默认 disabled，由 ViewHost 以最高 30 FPS 手动 `Render()`。浮窗隐藏或折叠时不 Render；RT 重建时先解绑、Release 并 Destroy 旧对象。

#### 输入

RawImage 输入控制器实现：

- 左键选择格子或 Pawn。
- 右键向格子提交移动命令。
- 中键或左键空白拖拽平移。
- 滚轮缩放，并保持光标下的小世界坐标不跳动。
- “居中视图”图标按钮聚焦可控 Pawn。

不复用 `MoveCamera`、主世界 Camera 或 PlayerControl。

本步验证：主世界与浮窗同时显示 `soil_low/wall_ancient` 时，浮窗 Tilemap 中的 Tile 与 `AssetManager.tiles.get("soil_low").sprites.main`、`AssetManager.top_tiles.get("wall_ancient").sprites.main` 是相同原版 Asset；两边 Tilemap、Renderer、Material 实例、Camera 和渲染开关是不同对象，折叠浮窗不改变任一世界时钟。

### 步骤 5：实现移动、寻路与出口目标

#### 导航

`SubWorldNavigationGrid` 为 Runtime 私有对象。它按 `Top ?? Main` 从 Grid 取得直接的原版 `TileTypeBase` 对象，以最终 `block`、`block_height` 与 `walk_multiplier` 构建通行和成本；门、单位等动态阻挡以后由实体规则叠加，不写回原版 terrain 对象。首阶段采用四向邻接。

`SubWorldPathfinder` 使用有界 A*：

- 请求携带 Runtime Revision。
- 单实例每 tick 最多接受 2 个新请求。
- 路径结果是 tile index 数组。
- 地图 Revision 变化后旧结果作废。
- 不引用原版 `EpPathFinding.Node`、原版 A* 或 `WorldTile`。

#### 移动

Pawn 按固定 tick 沿路径移动。逻辑位置复用通用 `Position` 的小世界局部连续坐标，当前格由 Grid 换算；View 只做插值，不回写逻辑坐标。

#### 目标

测试目标为“从入口抵达出口”：

1. Pawn 到达 Exit tile。
2. Objective 进入 Completed。
3. Runtime 状态进入 Completing。
4. 完成当前 tick 后进入 Completed，不再接受移动命令。
5. 浮窗显示完成状态，允许查看当前结果或由 Manager 销毁实例。

本步验证：Pawn 能按 `wall_ancient` 原版对象的最终 `block=true` 绕行；把测试格改为 `mountains` 后可通行，且路径成本按 `walk_multiplier=0.45` 高于 `soil_low`，证明导航直接读取原版字段。`damage=1` 由同一有效对象直接读取，本阶段只验证格伤害输入，不提前实现战斗伤害。

### 步骤 6：完成最小实例验收

提供仅在 Debug 配置显示的“创建测试小世界”入口，用于调用 Manager 创建 TestSubWorld 并打开浮窗。正式消费系统接入后，该入口不进入普通 World Tool 列表。

本步验证：从 Debug 入口完成“创建实例 -> 同屏分别变速 -> 移动到出口 -> 查看 Completed -> 销毁实例”的单条流程；随后再次创建两个实例并切换浮窗，最后触发世界切换清理。期间不创建或访问第二个原版世界对象，Manager 集合与全部 SubWorld 资源在清理结束后为空。

## 验收标准

### Runtime 与 Manager

- 创建两个实例时，各自 Store、Clock、Random、MapData 和 Entity 完全隔离。
- `SubWorldRuntime` 直接持有 InstanceId、TemplateId、Seed、State、MapData、EntityStore、Clock、Random 和 Revision。
- `SubWorldManager` 是 Runtime 集合唯一所有者，只提供 Create/Get/Destroy/Update/IssueCommand/ShowFloatingPanel。
- 不修改 `MapBox.instance`、静态地图尺寸或 `World.world`。
- `SubWorldGrid` 在 `TerrainTraversalRules.Init()` 后直接持有原版对象；`mountains/summit/snow_block/snow_summit` 与主世界引用相同对象并使用相同通行、伤害与视觉字段。
- `SubWorldMapData` 只包含 `SubWorldTile[] Tiles` 和独立 `int[] EntryTileIndices/int[] ExitTileIndices`；入口出口不进入 terrain 字段。
- `SubWorldTile` 是 Runtime 的 map-local 逐格数据，只持有原版 `MainAssetId/TopAssetId`，不复制 `TileTypeBase`；Main 必填，Top 为空表示没有 Top。
- 重复 Asset ID 逐格直接出现，生成和单格修改都对应同一个 `Tiles[index]`。
- Template 的任一必需 ID 缺失时创建失败，不以 `soil_low` 或复制定义继续运行。
- 通行、格伤害和视觉都严格按 `Top ?? Main` 使用同一有效 terrain。
- 修改单格时只更新对应 `SubWorldTile.MainAssetId/TopAssetId`；随后刷新该格 Runtime 缓存与 dirty tile，原版 Asset 保持不变。
- Pawn 能绕开阻挡抵达出口，旧 Revision 路径不会写入新地图。
- Pause、1x、2x、4x 均只改变当前实例。
- 主世界全局倍速不因小世界工具栏改变。
- `Destroy` 一个实例不会影响其他实例；世界切换、返回主菜单或 Mod 重载后 Manager 集合为空。

### 可视化

- 基础地面和墙体直接使用原版 `TileTypeBase.sprites.main`，没有新增同义 SubWorld terrain 资源或私有 Tile 复制品。
- View 使用私有 Main/Top Tilemap、Renderer、Material、Camera 和 RenderTexture；Tile/Sprite Asset 与原版共享，修改局部材质或停止局部 Camera 不影响主世界。
- View 不实例化或调用原版 `WorldTilemap` 与 Quantum sprite 运行逻辑。
- 浮窗默认尺寸和低分辨率约束尺寸下 RawImage 不拉伸地图比例。
- 平移、缩放和光标坐标转换准确。
- 浮窗外的点击、拖动和滚轮继续由主世界接收，浮窗内输入不会穿透到主世界。
- 浮窗隐藏或折叠后不继续调用 Camera.Render，但 LocalTime 不因此停止。
- RT 多次 resize 后没有旧 Texture 和 Camera 对象残留。
- Tilemap 只更新 dirty tile，Pawn 移动不触发整张 Canvas rebuild。

### 生命周期

- Completed Runtime 保持只读，直到消费系统调用 `Destroy`。
- 切换世界、返回主菜单或 Mod 重载时，Runtime、Store、SystemRoot、ViewHost、RT、Camera、队列和对象池全部销毁。
- `dotnet build Cultiway.csproj -c Debug` 无错误。
