# 第1阶段-最小可玩实例

本阶段建立一个不依赖 `World.world` 运行对象的最小可玩实例：地图直接复用原版 `TileTypeBase` 的最终 terrain 语义和 sprite/atlas，运行容器、格子、时钟、移动单位、非模态浮窗和世界槽位存档保持独立。

## 具体说明

### 设计边界

- 不创建第二个 `MapBox`、`WorldTile`、原版 Actor 或 Building。
- 不创建 SubWorld 专属基础 terrain ID、通行 flags、地面 sprite 或墙体 sprite；静态语义和视觉资源来自原版 Asset 字符串 ID。
- 原版 `WorldTile`、`WorldTilemap`、Quantum sprite 运行逻辑和原版 A* 仍不进入 SubWorld；只复用 `TileTypeBase` 最终定义与 sprite/atlas。
- 不接入真实主世界角色；第二阶段才实现参与者投影。
- 不加入战斗、物品、迷雾和复杂机关。
- 只提供一个内部验证 Template，一名测试 Pawn 从入口移动到出口。
- 逻辑、浮窗、保存和读档在本阶段已经形成完整闭环。
- 浮窗打开时主世界保持可见、可操作并继续按自己的速度运行。

### 步骤 1：建立原版 terrain 目录与地图合同

#### 只读 terrain 定义目录

在原版 `TileLibrary`、`TopTileLibrary` 和 Cultiway `TerrainTraversalRules.Init()` 全部完成后建立 `IWorldBoxTerrainCatalog`。目录按原版字符串 Asset ID 捕获最终 `TileTypeBase` 语义，不在 SubWorld 中重新推导或复制一份配置表。

```text
WorldBoxTerrainDefinition
  AssetId
  SourceLayer = Main | Top
  Block / BlockHeight / WalkMultiplier
  Ground / Liquid / Wall
  DamageUnits / Damage
  LayerType / RenderZ
  CanBeFrozen / FreezeToAssetId
```

`TerrainTraversalRules` 对 `mountains`、`summit`、`snow_block`、`snow_summit` 的改动属于目录输入。目录冻结后，MainWorld Adapter 和 SubWorld Adapter 都读取这份最终快照；SubWorld 不保留一份旧的原版默认值。

#### 只读 terrain 视觉目录

`IWorldBoxTerrainVisualCatalog` 使用相同的 `SourceLayer + AssetId` 键，只读暴露原版 `TileTypeBase.sprites` 对应的 sprite/atlas、变体数量、渲染层和材质键。它不返回 `WorldTile`、`WorldTilemap` 或 Quantum 运行对象。

SubWorld View 可以共享不可变 Sprite/Atlas 引用，但必须创建自己的 `UnityEngine.Tilemaps.Tile`、Tilemap、Material 和 Camera。变体选择只使用 `VariantSeeds[index]` 和 visual catalog，不调用原版 Quantum 或 `WorldTilemap.getVariation()`。

#### MapRecord

tile 采用紧凑数组：

```text
SubWorldMapRecord
  Width
  Height
  TerrainPalette[]
    MainAssetId
    TopAssetId
    FrozenAssetId
  ushort TerrainRefs[]
  DynamicFlags[]
  VariantSeeds[]
  EntryTileIndices[]
  ExitTileIndices[]
```

tile index 规范为：

```text
index = y * width + x
```

规则固定如下：

- `TerrainRefs[index]` 是实例内 `TerrainPalette` 的 `ushort` 引用；Palette 保存原版字符串 Asset ID。
- 存档不保存 `TileTypeBase.index_id`、Asset hash、原版数组下标、`WorldTile` 或 Sprite 引用。
- 有效 terrain 按 `Frozen > Top > Main` 解析。Frozen 由 `DynamicFlags[index]` 决定；没有 Frozen 时才看 Top，最后使用 Main。
- `DynamicFlags` 只保存 Frozen 等可变格子状态。`Walkable`、`BlocksVision` 和伤害来自有效 terrain 定义，`Entry/Exit` 来自独立数组。
- 所有坐标转换和邻接由 `SubWorldGrid` 提供，不在调用方重复计算。

本步验证：冻结目录后读取 `mountains` 应得到 Cultiway 最终语义 `Block=false`、`WalkMultiplier=0.45`、`Damage=1`；MapRecord JSON 中只能看到 terrain 字符串 ID 和 palette ref，不能出现 index/hash/`WorldTile`。

### 步骤 2：建立 Archive、Template 与最小 Runtime

新增 `Source/Core/SubWorlds/`，数据合同分为静态资产、存档 DTO 和运行时三层。

#### Archive 与 Template

```text
SubWorldArchive
  SchemaVersion
  NextInstanceSequence
  Instances[]

SubWorldTemplateAsset
  Id
  Width
  Height
  GeneratorId
  ClockProfileId
  VisualProfileId
```

Archive 是当前主世界所有小世界的权威目录，保存到 `MapStats.custom_data`，不写入全局 `ModSaveManager`。注册内部模板：

```text
Cultiway.SubWorld.Template.ProvingGround
```

#### InstanceRecord

```text
InstanceId
TemplateId
Seed
RandomState
State
LocalTime
TickIndex
LocalSpeed
LocalPaused
MapRecord
EntityRecords[]
ObjectiveRecord
Revision
```

ID 使用主世界内递增序列加世界随机前缀，不使用 ECS Entity ID。`Revision` 每次完整事务提交后递增，用于拒绝过期路径和命令结果。

#### Generator

`ProvingGroundGenerator` 只从 `IWorldBoxTerrainCatalog` 选择 terrain。首版 Palette 使用原版 `soil_low` 作为 Main、原版 `wall_ancient` 作为 Top 阻挡；入口和出口是独立 tile index 数组与 SubWorld overlay，不注册新的基础 terrain。

1. 生成外围 `wall_ancient` 阻挡。
2. 在左侧选择入口。
3. 在右侧选择出口。
4. 放置有界阻挡。
5. 使用 catalog 最终通行语义验证入口与出口存在路径。
6. 生成一名测试 Pawn。

地图生成完成后保存完整 MapRecord。读档直接使用记录并按字符串 ID 解析目录，不重新运行 Generator。

#### Runtime

每个加载实例创建：

```text
SubWorldRuntime
  EntityStore
  SystemRoot
  Grid
  NavigationGrid
  Clock
  Random
  CommandQueue
  EventQueue
```

首阶段 ECS 组件：

```text
SubWorldIdentity
SubWorldPosition
SubWorldMoveState
SubWorldVisual
SubWorldControllable
```

tile 不创建 Entity。每个 Runtime 拥有独立 Store、Root 和 system 对象，共享项目唯一 `ParallelJobRunner`，不为实例创建线程池。

#### 唯一服务入口

`SubWorldService` 首阶段提供：

```text
CreateInstance(templateId, seed)
LoadRuntime(instanceId)
SuspendRuntime(instanceId)
IssueCommand(instanceId, command)
ShowFloatingPanel(instanceId)
CompleteInstance(instanceId)
```

其他系统不直接修改 Archive 或 Runtime Store。

本步验证：同一 Seed 创建的 MapRecord palette、refs、变体种子和入口出口数组一致；两个 Runtime 的 Store、Grid、Random 和 Entity 互不引用。

### 步骤 3：实现实例级固定时钟与命令队列

注册首个 ClockProfile：

```text
Cultiway.SubWorld.Clock.Standard
FixedStep = 0.1 local seconds
AllowedLocalSpeedOptions = Paused / 1x / 2x / 4x
DefaultLocalRate = 1
RunsWhileParentPaused = true
```

`SubWorldClock` 使用 `Time.unscaledDeltaTime × DefaultLocalRate × LocalSpeed` 累计时间。主世界继续使用 WorldBox 自己的时间控制；打开浮窗不修改 `World.world._is_paused` 或全局倍速。用户单独暂停主世界时，本验证 Profile 仍允许小世界按局部按钮推进。

规则：

- 每次只推进完整固定 tick。
- 单渲染帧最多补算 4 tick，剩余累计时间留到后续帧。
- Pause 不清空 accumulator。
- 倍速只增加待执行 tick 数，不改变 FixedStep。
- TickIndex 每完成一次逻辑 tick 加 1。

#### 命令

首阶段支持：

```text
MoveToTileCommand
PauseCommand
SetLocalSpeedCommand
```

移动命令包含 InstanceId、Revision、EntityId 和目标 tile。命令在 tick 边界验证并进入领域队列；UI 不直接写 Position。

每 tick 最多处理 32 条命令和 32 条事件，超出部分留待后续 tick。

本步验证：在主世界 1x、暂停和其他倍率下分别运行小世界 Pause/1x/2x/4x，只有当前实例的 `LocalTime`、`TickIndex` 和 Pawn 位移速度变化。

### 步骤 4：实现 RenderTexture 小世界浮窗

实施遵守 `Prompts/UI.md`。小世界视图归类为 HUD/世界覆盖层：新增 `SubWorldFloatingPanel`，挂到核实过的主世界 HUD Canvas 节点，不使用 `ScrollWindow`、`AbstractWideWindow`、原版窗口历史或模态遮罩。

#### 结构

```text
FloatingPanel  默认停靠右上
  DragHeader  高 28
    实例名
    折叠
    关闭
  Toolbar  高 28
    Pause
    1x / 2x / 4x Segmented Control
    居中视图
  Viewport  16:9
    RawImage
  Inspector  可折叠
```

浮窗默认视口为 `560x315`，RenderTexture 保持 `640x360`。面板受屏幕安全边距约束，可以拖动但不能移出屏幕；低分辨率下等比缩小视口。首版不提供最大化、全屏或自由拉伸，避免遮住主世界主要操作区域。

#### 非模态行为

- 打开、切换、折叠或关闭浮窗都不暂停主世界，不修改主世界速度。
- 指针位于浮窗 Header、Toolbar、Viewport 或 Inspector 内时由浮窗消费；位于其外时继续选择、拖动和缩放主世界。
- 点击主世界不会关闭浮窗，也不会改变当前绑定实例。
- 折叠只保留 Header，并停止 Camera.Render；实例 LocalTime 继续按当前局部速度运行。
- 同时只存在一个 `SubWorldFloatingPanel`，切换实例时复用 ViewHost 和 RenderTexture。

#### 渲染对象

`SubWorldViewHost` 创建：

- 独立正交 Camera。
- 独立 Unity Layer。
- `640x360` ARGB32 RenderTexture。
- 私有 Ground 与 Overlay Tilemap、`Tile` 缓存和 Material 实例。
- 测试 Pawn SpriteRenderer 池。

`WorldBoxTerrainVisualAdapter` 按 MapRecord 的 `SourceLayer + AssetId + VariantSeed` 从 `IWorldBoxTerrainVisualCatalog` 取得原版 Sprite/Atlas 引用，并写入 ViewHost 私有 `Tile`。基础地面和墙体不走 `GameResources/cultiway/sub_world/`，也不调用主世界 `WorldTilemap`、Quantum 或共享可变 Material。

Camera 默认 disabled，由 ViewHost 以最高 30 FPS 手动 `Render()`。浮窗隐藏或折叠时不 Render；RT 重建时先解绑、Release 并 Destroy 旧对象。

#### 输入

RawImage 输入控制器实现：

- 左键选择格子或 Pawn。
- 右键向格子提交移动命令。
- 中键或左键空白拖拽平移。
- 滚轮缩放，并保持光标下的小世界坐标不跳动。
- “居中视图”图标按钮聚焦可控 Pawn。

不复用 `MoveCamera`、主世界 Camera 或 PlayerControl。

本步验证：主世界与浮窗同时显示 `soil_low/wall_ancient` 时引用相同原版 Sprite 资源，但两边 Tilemap、Tile、Material、Camera 和渲染开关是不同对象；折叠浮窗不改变任一世界时钟。

### 步骤 5：实现移动、寻路与出口目标

#### 导航

`SubWorldNavigationGrid` 为实例对象。它按 `Frozen > Top > Main` 取得 `WorldBoxTerrainDefinition`，从最终 `Block` 与 `WalkMultiplier` 构建通行和成本；门、单位等动态阻挡以后由实体规则叠加，不写回 terrain 静态语义。首阶段采用四向邻接。

`SubWorldPathfinder` 使用有界 A*：

- 请求携带 Runtime Revision。
- 单实例每 tick 最多接受 2 个新请求。
- 路径结果是 tile index 数组。
- 地图 Revision 变化后旧结果作废。
- 不引用原版 `EpPathFinding.Node`、原版 A* 或 `WorldTile`。

#### 移动

Pawn 按固定 tick 沿路径移动。逻辑 Position 使用格子和格内进度；View 只做插值，不回写逻辑坐标。

#### 目标

测试目标为“从入口抵达出口”：

1. Pawn 到达 Exit tile。
2. Objective 进入 Completed。
3. Instance 状态进入 Completing。
4. 完成当前 tick 后写回 DTO。
5. 浮窗显示完成状态，允许重新查看同一只读结果或销毁实例。

本步验证：Pawn 能按 `wall_ancient` 的最终 `Block=true` 绕行；把测试格改为最终 `mountains` 语义后可通行，且路径成本按 `WalkMultiplier=0.45` 高于 `soil_low`，证明导航没有使用自制 flags。`Damage=1` 只在 catalog 快照中验收，本阶段不提前实现战斗伤害。

### 步骤 6：接入主世界存档和读档恢复

固定 key：

```text
Cultiway.SubWorlds
```

#### 保存

扩展 `FinishSimulationBeforeSave`：

1. 停止接收新命令。
2. 每个 Runtime 完成当前 tick。
3. 将 Grid、Entity、Clock、RandomState 和 Objective 投影为 DTO。
4. 校验 `TerrainRefs` 均指向 Palette，并只写入 Main/Top/Frozen Asset 字符串 ID。
5. 写回 Archive。
6. 序列化到 `MapStats.custom_data`。

不保存：

- ECS Entity、`TileTypeBase`、Sprite 和其他运行时对象引用。
- 已计算路径、相机位置和对象池对象。
- 命令与事件队列中的派生消息。

尚未执行且具有玩法意义的用户命令必须先在 tick 边界执行或明确拒绝，不能静默丢弃。

#### 读档

- 加载 MapStats 后先恢复 Archive，不立即为全部实例创建 Runtime。
- 玩家打开实例或消费系统请求激活时按需 LoadRuntime。
- 读档后的第一个视觉帧从 DTO 重建 Tilemap 与 Pawn。
- 已完成实例保持 Completed，不重复触发目标事件。

本步验证：分别在移动中、Frozen 动态状态、局部暂停和 Completed 状态保存读档，Palette 字符串 ID、TerrainRefs、DynamicFlags、VariantSeeds、入口出口、位置和时钟完全恢复。

### 步骤 7：完成最小实例验收

提供仅在 Debug 配置显示的“创建测试小世界”入口，用于创建 ProvingGround 并打开浮窗。正式消费系统接入后，该入口不进入普通 World Tool 列表。

本步验证：从 Debug 入口完成“创建实例 -> 同屏分别变速 -> 移动到出口 -> 保存 -> 读档查看 Completed”的单条流程，期间不创建或访问第二个原版世界对象。

## 验收标准

### 运行时

- 创建两个实例时，各自 Store、Clock、Random 和 Entity 完全隔离。
- 不修改 `MapBox.instance`、静态地图尺寸或 `World.world`。
- `IWorldBoxTerrainCatalog` 捕获的是 `TerrainTraversalRules` 应用后的最终值；`mountains/summit/snow_block/snow_summit` 与主世界使用相同通行和伤害语义。
- MapRecord 只保存 `TerrainPalette[]`、`ushort TerrainRefs[]`、独立 `DynamicFlags[]/VariantSeeds[]/EntryTileIndices[]/ExitTileIndices[]`，没有 `TerrainIds+Flags` 合并合同。
- terrain 存档只出现原版 Asset 字符串 ID，不出现 `index_id`、hash、原版数组下标或 `WorldTile`。
- Frozen、Top、Main 同时存在时，通行、伤害和视觉都严格按 `Frozen > Top > Main` 使用同一有效 terrain。
- Pawn 能绕开阻挡抵达出口，旧 Revision 路径不会写入新地图。
- Pause、1x、2x、4x 均只改变当前实例。
- 主世界全局倍速不因小世界工具栏改变。
- 浮窗打开时主世界年、Actor AI 和地图操作继续推进；主世界变速也不覆盖实例 LocalSpeed。
- 主世界与小世界可以分别处于暂停、1x 和其他允许倍率组合。

### 可视化

- 基础地面和墙体引用原版 sprite/atlas，没有新增同义 SubWorld terrain 资源。
- View 使用私有 Tile、Tilemap、Material 和 Camera；修改局部材质或停止局部 Camera 不影响主世界。
- View 不实例化或调用原版 `WorldTilemap` 与 Quantum sprite 运行逻辑。
- 浮窗默认尺寸和低分辨率约束尺寸下 RawImage 不拉伸地图比例。
- 平移、缩放和光标坐标转换准确。
- 浮窗外的点击、拖动和滚轮继续由主世界接收，浮窗内输入不会穿透到主世界。
- 浮窗隐藏或折叠后不继续调用 Camera.Render，但 LocalTime 不因此停止。
- RT 多次 resize 后没有旧 Texture 和 Camera 对象残留。
- Tilemap 只更新 dirty tile，Pawn 移动不触发整张 Canvas rebuild。

### 存档

- 在 Pawn 移动途中、局部暂停和目标完成状态分别保存读档，位置、时间、随机状态和目标一致。
- 读档不重复创建出口完成事件。
- 切换主世界后 Archive、Runtime、ViewHost、RT 和对象池全部清理。
- `dotnet build Cultiway.csproj -c Debug` 无错误。
