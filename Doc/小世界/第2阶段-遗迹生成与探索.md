# 第2阶段-遗迹生成与探索

本阶段把第一阶段的单张开放古修道场扩展为可重复游玩的遗址生成与调查系统。生成单位是连续地貌、遗构锚点、危险场、线索关系和独立机缘，不是房间、走廊和门锁图。

本阶段只实现一个具体内容配置 `RuinedDaoGroundGenerationConfig`。先用真实消费者证明这套开放地貌合同成立，再在阶段 4 实现远古战场后，按两种内容实际重复出现的字段提取共享 Archetype 资产；不为一个消费者提前支付通用注册器成本。

## 具体说明

### 设计边界

- 不生成矩形房间、走廊树、钥匙门或“入口到 Boss”的关键路线。
- Region 只是地貌与内容分布语义，不是带墙边界的玩法容器。
- 本阶段只有残破古修道场一个具体内容配置；变化来自手工布局族、锚点池、危险强度、线索关系和机缘内容。
- 不建立任意脚本、通用 Rule Module、目标 DAG 或无类型配置包。
- Terrain 继续直接使用原版 Asset ID；具体 GenerationConfig 只选择已有 terrain，不复制定义。
- AI 不能读取完整 `RuinedDaoGroundPlan`。Plan 只供 Generator、验证器和 Debug 诊断使用。
- 物理变化属于 Runtime；知识属于参与者/队伍；玩家视图只呈现已经被参与者公开发现的秘密内容。
- 本阶段仍无战斗与死亡，危险场保持非致命。

### 步骤 1：建立古修道场具体 GenerationConfig 与 Plan

#### 具体配置

新增只服务首个消费者的强类型 `RuinedDaoGroundGenerationConfig`，不注册通用 `RuinArchetypeAsset`：

```text
TemplateId
TerrainAssetIds
LayoutVariants
LandmarkAnchorSet
HazardDefinitions
OpportunityDefinitions
VisualProfileId
SeedAttemptLimit
```

它只选择已存在的原版 terrain Asset ID 和古修道场自己的内容定义，不包含宗门驻地、独立世界、制造或战斗规则字段。`RuinSiteService` 在本阶段直接选择这一具体配置；`SubWorldManager` 仍只接收 Template 与创建参数。

#### 具体生成计划

Generator 先产出纯内存 `RuinedDaoGroundPlan`，验证通过后再物化为 MapData 和 Runtime Entity：

```text
Width / Height
TerrainPatchPlan[]
LandmarkPlacement[]
ApproachPoint[]
HazardFieldPlan[]
OpportunityPlacement[]
ClueLink[]
EntrySpawnPoint
GenerationSignature
```

- `TerrainPatchPlan` 表示山地、林地、裸地、水洼、废墟覆盖等连续 mask。
- `LandmarkPlacement` 表示残碑、废殿遗构、药圃、阵眼、道台、尸骸或断裂器物等具名锚点。
- `ApproachPoint` 是 AI 观察一个地貌范围的候选点，不是隐藏机缘精确坐标。
- `ClueLink` 连接线索来源与机缘，但只保存可转成 bearing/distance/confidence 的关系。

Plan 不进入 Runtime 热路径；创建完成后只保留 MapData、强类型实体与必要的 GenerationSignature。

### 步骤 2：实现手工布局族与 Seed 内容组合

#### 布局族

`RuinedDaoGroundLayoutFamily` 提供至少 3 个手工开放底图，每个底图都包含相同语义区域但地貌关系不同：

| 底图 | 地貌特点 | 路线差异 |
| --- | --- | --- |
| 山脊道场 | 入口在低处，遗构沿弧形山脊分布 | 山脊捷径危险，缓坡路线安全 |
| 谷地道场 | 废殿与药圃分列谷地两侧，道台在高处 | 中央残阵短路，两侧均可绕行 |
| 林中道场 | 遗构被林地和水洼分割 | 视线受限，但不存在唯一窄口 |

这里的“底图”是 terrain mask 与锚点池，不固定具体机缘内容。所有底图都保持连续开放视野，不绘制封闭室内结构。

#### Seed 组合顺序

Generator 使用独立 `GenerationRandom` 按固定顺序：

1. 选择一个手工底图。
2. 选择对应底图的坍塌/植被 variation。
3. 从每类 Landmark anchor pool 中选出实际锚点。
4. 选择 HazardField 的范围、强度与阵眼位置。
5. 从 OpportunityTable 抽取 3-5 个独立机缘并分配到兼容锚点。
6. 选择 2-4 个 ClueSource，建立至少一条指向每个非显露机缘的线索关系。
7. 生成收益、调查难度和视觉变体。
8. 运行步骤 3 的验证器，成功后物化；失败则按同一 Seed 的确定性 attempt 序列尝试下一个 variation。

最多尝试 16 个 variation。全部失败时 Template 创建失败并输出 Seed、LayoutId 和违反的约束；不得回退到固定安全地图。

#### 内容兼容

Opportunity 声明需要的锚点语义，例如：

- 灵植只进入药圃、湿地或灵脉渗出点。
- 石碑传承只进入残碑、道台或废殿遗构。
- 阵法机缘只进入阵眼、阵基或灵脉节点。
- 遗物只进入尸骸、断器或坍塌遗构。

Generator 不把内容随机放到任意空格。没有兼容锚点时该组合失败，而不是忽略语义。

### 步骤 3：验证开放通路、地标分散与线索可解

新增只服务首个配置的 `RuinedDaoGroundValidator`。每个生成结果必须满足：

#### 通路

- Entry 本身可站立，周围至少有两个可离开方向。
- 每个 Opportunity 的至少一个 ApproachPoint 从 Entry 可达。
- 至少一半 Opportunity 存在两条不完全重合的可行接近路线。
- 任一单个 HazardField 被视为不可进入时，仍至少有一个未耗尽 Opportunity 可达。
- 不允许一格宽的单一 chokepoint 同时控制全部机缘。
- 任一 Opportunity 不得以前一 Opportunity 完成、守卫清空、门/区域解锁或另一个 Opportunity 的状态作为前置；生成计划的 Opportunity prerequisite graph 必须为空。
- 返回路径与进入路径使用同一通行规则验证，不假设单向传送。
- 固定 Seed 必须输出全图俯视诊断图、Opportunity 前置关系图和 Entry 到各 Opportunity 的独立可达性结果；前置关系图必须为空。

“路线不完全重合”按去除 Entry 周围固定半径后的 tile 集合差异判断，不要求严格图论边不相交，避免为小地图过度建模。

#### 地标分散

- 两个 Opportunity 不得占用同一锚点。
- 所有 Opportunity 不得集中在同一四分之一地图区域。
- ClueSource 与目标不能在同一可见半径内，否则线索没有意义。
- 至少一个显著 Landmark 在入口初始视野中，用来给 AI 第一个调查方向。
- 危险场不能完整覆盖 Entry、Exit 或所有安全返程路线。
- 不得出现由遗构、危险带和守卫排列成的“战斗区 -> 奖励区”串联；每个机缘都要有不依赖清除其他机缘/守卫的调查入口。

#### 线索可解

对每个初始 Unrevealed Opportunity：

1. 至少存在一个可达 ClueSource。
2. Clue 产生的 bearing 与 distance band 覆盖至少一个可达 ApproachPoint。
3. AI 在该范围内的 PerceptionRange 足以通过移动观察 Expose 节点。
4. Clue 不直接给精确 tile，也不会把范围扩大到整张地图。

验证器生成结构化 `RuinGenerationDiagnostics`；只在 Debug 展示。正式创建失败只记录简洁错误，不显示隐藏坐标。

本步测试至少覆盖：全阻塞、单 chokepoint、机缘过度集中、线索错误指向、危险封死返程、非空前置关系图、串联战斗区伪装和同 Seed signature。

### 步骤 4：完善观察、道痕、调查与参与者知识

#### 三层信息

遗迹信息分为：

| 层 | 示例 | 谁持有 |
| --- | --- | --- |
| 物理事实 | terrain、废殿位置、残阵是否稳定、机缘是否耗尽 | Runtime |
| 队伍知识 | 看过哪些格、知道哪些危险、有哪些 Clue、调查失败记录 | `RuinKnowledgeState` |
| 玩家公开观察 | 至少一个参与者曾公开发现的 Landmark/Opportunity 摘要 | `RuinPublicDiscoveryState` |

玩家可以看到完整基础地貌和显著遗构，保持类似主世界的观察感；隐藏机缘、潜伏守卫和精确危险强度只在参与者发现后渲染。玩家公开观察不会自动写回新队伍 Knowledge。

#### 观察更新

`RuinPerceptionSystem`：

- 只在 Projection 跨格、视野属性变化或遮挡变化时重算。
- terrain 与大型遗构参与视线阻挡。
- 观察显著 Landmark 只需进入其远距观察半径；调查仍需到达 ApproachPoint。
- 道痕/灵气感知产生 Clue，不等同于视觉发现。
- 已 Exposed 的物理对象对进入其可见范围的后续队伍正常可见，不需要重复隐形。

#### 调查结果

`InvestigateLandmarkCommand` 在邻接/ApproachPoint 验证后开始 `RuinInvestigationState`：

```text
ParticipantId
LandmarkId
StartTick
RequiredTicks
Progress
AttemptSeed
```

移动、受伤或主动撤离会中断进度。完成时使用固定 AttemptSeed 和 Projection 的明确调查快照，结果只能是：

- RevealClue
- ExposeOpportunity
- StabilizeHazard
- GainOutcome
- NoFinding

同一参与者对同一 Landmark 的同一调查方式只结算一次；NoFinding 记录在 Knowledge 中，不能通过原地反复点击刷 RNG。其他队伍仍可用自己的能力尝试。

### 步骤 5：实现遗构变化、危险场与长期物理状态

#### 遗构状态

首批可变化物理对象：

- 残碑：Uninvestigated -> Investigated。
- 阵眼：Active -> Stabilized 或 Destroyed。
- 药圃：Available -> PartiallyHarvested -> Exhausted。
- 道台：Dormant -> Exposed -> Exhausted。
- 坍塌通路：Blocked -> Cleared；只在明确调查/破坏结果发生时改变。

变化通过 Runtime command 提交并发布事件。用途层和 View 不直接改组件。

#### 危险场

`RuinHazardField` 支持首批两种无战斗危险：

| 类型 | 效果 | 可应对方式 |
| --- | --- | --- |
| ResidualFormation | 范围内每 tick 生命/灵气损失 | 绕行、快速穿越、调查阵眼稳定 |
| CorruptedWakan | 累积灵气扰动，降低后续调查效率 | 绕行或带着已有所得撤离 |

本阶段 CorruptedWakan 只写 Projection 的临时 `WakanDisturbance`，退出时清除，不新增永久 status。阶段 3 再决定哪些伤势能带回。

HazardField 的 Active/Stabilized/Destroyed 状态属于 Runtime。后续队伍进入时继承状态，但自己的 KnownHazards 仍需观察后建立。

#### Site 摘要

`RuinSiteSummary` 从真实组件派生：

```text
DiscoveredLandmarkCount
TotalOpportunityCount
ExhaustedOpportunityCount
ActiveHazardCount
ParticipantCount
HasUnsettledClaims
```

不保存第二份可写进度。入口 Tooltip 和导航按钮只读取摘要。

### 步骤 6：完善自主调查、记忆与返程决策

#### 候选行动

AI 每个 DecisionInterval 构造候选：

- ReturnToEntry
- ObserveArea
- InvestigateLandmark
- FollowClue
- ClaimOpportunity
- StabilizeHazard

每个候选包含明确输入：路径是否可达、实际路程、可观测危险的具体效果、预期收益区间、信息增益、返程余量和当前所持收益。评分不读取 Generator Plan 或隐藏实体。

首版不把危险压成每格固定分数，也不建立统一的线性效用公式。决策先排除生命、资源或返程条件无法承受的候选，再由具体行动按自身目标比较距离、收益和信息；性格只参与对应行动的选择规则，不作为通用风险倍率。正式 UI 不显示内部决策数值。

#### 返程条件

任一条件成立时 Return 候选强制优先：

- 生命低于个体安全阈值。
- 返程最坏估算会把生命降到安全阈值以下。
- 已取得价值达到 DesiredGainThreshold。
- 当前没有正效用候选，且连续两个决策周期没有新信息。
- Site 进入 Exhausted/Collapsed 或入口要求清退。

取得部分收益后继续探索是允许结果，不要求“拿到一个就走”；是否继续由个体阈值和剩余候选决定。

#### 记忆与防循环

Knowledge 记录最近 16 个目标与结果。AI 不得：

- 连续选择刚返回 NoFinding 的同一 Landmark。
- 在两个不可达观察点间无限切换。
- 对同一已知 Hazard 每 tick 重复重算路线。
- 因 Renderer 不可见而清空记忆。

连续 8 个决策周期无位置进展时，取消当前候选并重建；三次恢复仍失败则返程并记录 `ExplorationStalled`。

### 步骤 7：完成多 Seed 与接续探索验收

#### 固定 Seed 套件

至少保存 20 个测试 Seed，覆盖三种底图与边界组合。每个 Seed 验证：

- MapData、RuinedDaoGroundPlan、Landmark、Hazard、Opportunity、Clue 与收益 signature 可重复。
- 入口到每个 ApproachPoint 可达。
- 至少一半机缘有两条不同接近路线。
- 每个隐藏机缘至少有一条可完成 Clue 链。
- AI 不通过隐藏坐标直接寻路。
- 所有参与者都可安全返回，除非其自己选择穿越已知高风险区。

#### 古修道场内容合同

本阶段在 20 个 Seed 验收时建立第一版 `RuinContentAcceptance`，它是具体内容的验收合同，不是提前注册的通用资产：

- 每个机缘独立可调查、独立可取得、独立可放弃；前置关系图为空。
- 不要求清空守卫、解除某扇门或完成另一个机缘才能接近目标。
- 至少两个机缘各有两条不同接近路线；至少一个机缘有明确非战斗应对。
- 地貌、遗构、线索和危险必须能从全图俯视诊断图读出空间关系；不能只靠运行时日志证明“开放”。
- 线索提供方向/距离/气息等调查信息，不直接暴露隐藏坐标。
- 修士可以取得部分机缘后安全返回，后续参与者继承物理变化但不自动继承他人的精确 Knowledge。
- 同一 Seed 的 Plan、结果、公开状态和接续探索行为可复现。

阶段 4 实现远古战场后，先分别通过这份合同，再只抽取两种遗迹真正重复的字段；没有重复证据的字段留在具体配置中。

#### 接续探索

对每个 Seed 运行三轮不同 Snapshot：

1. 保守修士取得第一个低风险机缘后返回。
2. 激进修士穿越危险场、稳定阵眼并取得另一个机缘。
3. 第三名修士进入时只剩最后节点，能依据剩余线索找到它。

验证三轮共用同一 Runtime，物理变化与 ExhaustedCount 累积；各队 Knowledge 独立；全部机缘耗尽前 Site 不进入 Exhausted。

#### 可见性差分

同一 Seed、同一 Snapshot、同一 tick 数：

- Runtime 始终与相机相交。
- Runtime 始终 Culled。
- 相机每 10 秒往返。

三种运行的 Position、Knowledge、Hazard、Opportunity、Outcome、RandomState 和决策日志签名一致。

#### 性能与清理

- `48x48`、5 个机缘、12 个 Landmark、2 个 Hazard、1 个 Projection 的感知/AI/寻路不得每 tick 全图分配集合。
- 稳态逻辑和渲染准备目标为每帧 0 B GC；真实性能预算留到阶段 5 测量。
- 销毁 Runtime 后 Plan、Knowledge、investigation、hazard、clue 和 public discovery 引用全部释放。
- `dotnet build Cultiway.csproj -c Debug` 无错误。
