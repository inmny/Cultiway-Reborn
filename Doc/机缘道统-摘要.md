# 机缘道统-摘要

**版本**：v1.0  
**状态**：设计基线  
**最后更新**：2026 年 8 月 9 日  
**当前范围**：古修遗府、坐化洞府、战殁残迹、真实小世界探索、秘密传播、传承择主、宗门寻访、道统谱系与气运  
**明确不包含**：新增修炼境界、境界灌顶、夺舍轮回、宗门战争改造、第二个原版 `MapBox`、小世界文明模拟、机缘专属炼丹炼器规则

## 设计目的

机缘道统系统让修士死亡后留下的功法、法术、法宝与未竟传承继续参与世界演化。强者不再只在死亡日志中消失；其道统会形成可发现、可进入、可争夺、可继承、可改良并可能再次失传的世界对象。遗府内部统一建立在[小世界平台](小世界-摘要.md)上，不在主世界入口旁用计时条模拟探索。

系统不是随机宝箱、固定副本或高境界奖励表，而是一套由真实人物和已有内容生成故事的长期循环：

1. 有资格的修士留下来源明确的道统。
2. 道统在主世界以入口存在，内部生成完整遗府或残破遗地小世界。
3. 位置信息先由少数角色掌握，再沿师徒、宗门和目击关系扩散。
4. 修士与宗门根据收益、距离、实力和相性决定是否寻访，并在抵达入口后投影进入同一实例。
5. 参与者在内部真实移动、破禁、战斗和拾取；外围遗藏可以被多人取得，核心道统只选择一名传人。
6. 继承人可以继续传授或改良功法，使同一道统形成历代与支脉。
7. 玩家既可以观察自然演化，也可以用神力投放古修遗府或显露天机。

## 玩家可观察的故事

- 一名寿元将尽的元婴离开宗门，在故国边境封存一生所学；数十年后由敌宗外门弟子发现。
- 金丹修士战死，法宝被仇敌夺走，残卷却留在战场；后来者修成与原主不同的支脉。
- 散修发现遗府后试图独吞，因自身无法破禁而求助师父，消息随后传入宗门。
- 两个宗门同时派队伍开启遗府；最先抵达者取得外围资源，核心功法却选择了灵根更契合的弱小弟子。
- 一部功法历经数代改良，分成正宗与旁支；正宗失传后，旁支通过残篇重新推演出新的版本。

## 已确认设计

### SubWorld 共享领域合同

| 领域 | 共享所有者 | 机缘道统消费方式 |
| --- | --- | --- |
| terrain | SubWorld 第 1 阶段的 `IWorldBoxTerrainCatalog`/`IWorldBoxTerrainVisualCatalog` 与原版 `TileTypeBase` | 遗府 Template 只选择 catalog 中的 Asset 字符串 ID，并提供稀疏 `TerrainThemeOverrideId`；override 只替换遗府内的视觉绑定，不复制地面、墙、水域等基础 tile 定义，也不改变 catalog 的通行与环境语义 |
| 物品 | SubWorld 第 2 阶段的稳定 `ItemId`、`IPortableItemSnapshot`、`IPortableItemCodec`、`ItemLease`、`OutcomeDelta`、`CommitId` 与 `SubWorldOutcomeCommitService` | `SubWorldItemRecord` 用 `StableItemId`、typed `ContentRef<TSnapshot>` 和 Holder/Ground 表示实体物品；首批可进入类型为 `IngredientSnapshot`、`ElixirRecipeBlueprint`、`ElixirItemSnapshot`、`ArtifactInstanceSnapshot`、`MagicScrollSnapshot`、`TalismanSnapshot` 六种顶层 codec，以后只按已注册 portable codec 扩展 |
| 制造 | 唯一 `ICraftProcessKindRegistry`、共享 `ICraftDomainService`、`CraftProcessSnapshot` 与 `CraftProcess`，MainWorld/SubWorld 各自提供上下文 port | 遗府 Template 的工作台用 `CraftCapabilities[]` 保存 `alchemy`、`artifact_refining`、`talisman_crafting`、`magic_scroll_crafting` Kind ID；配方、资源扣减、进度、品质和 typed 产物都由同一 registry/domain 处理，机缘系统只决定工作台位置、能力与可发现内容 |
| 技能 | `SkillBlueprint -> CompiledSkillDefinition`、`ISkillDefinitionRegistry`、`ISkillExecutionPorts` 与 shared capability 核心 | 道统继续持久化 `SkillBlueprint`；角色恢复、代表技能授予、Projection 能力和内部试炼都解析同一个 `CompiledSkillDefinition`，不建立 Legacy 或 SubWorld 专属解释器 |
| 战斗 | 共享 `DamageResolver`，MainWorld/SubWorld ports 提供目标、规则和状态上下文 | 遗府守卫、敌对 Projection、试炼伤害和主世界战斗走同一伤害阶段；机缘 RuleSet 只能提供规则参数，不能复制伤害公式 |

#### 跨世界返回合同

`OutcomeDelta` 是 Projection 退出或实例结算时冻结、等待提交的数据值，包含资源增量、角色状态、技能与机缘扩展字段、portable item 所有权变化和死亡结果；它只描述 MainWorld 应发生的变化，不执行提交。

`PendingOutcome` 表示尚未完成的提交状态，持有冻结的 `OutcomeDelta` 与稳定 `CommitId`。读档或失败重试只能用同一 `CommitId` 继续这份 `OutcomeDelta`；返回合同不另设独立的提交对象类型。

`SubWorldOutcomeCommitService` 是按稳定 `CommitId` 幂等提交 `OutcomeDelta` 的唯一服务。顺序固定为：先卸载本次返回涉及的 SubWorld Runtime item materialization，Archive 与 `PendingOutcome` 继续权威持有最终 snapshot/holder；存活物品通过原 `IPortableItemCodec.Materialize(targetStore, snapshot, factory)` 在 MainWorld 创建同一 `ItemId` 并绑定目标 holder，已消耗或销毁物品不 Materialize；再提交角色状态、资源和机缘扩展字段，死亡最后。服务在同一主线程提交边界持久化 `CommitId` 与 MainWorld ownership；之后才删除对应 Archive item record/snapshot 引用、移除 `PendingOutcome`，释放本次 `ItemLease` 和参与者的 `ExpeditionLease`。重试按 `ItemId + CommitId` 识别已经物化并绑定的结果，不重复创建。

`LegacyOutcomeAdapter` 只由 `SubWorldOutcomeCommitService` 调用，用于应用 `OutcomeDelta` 中的功法持有、代表技能、Winner 摘要、机缘历史等字段。它不创建或物化物品，不独立提交 `OutcomeDelta`，也不维护自己的幂等状态。

已有 MainWorld 物品进入遗府时，所有权路径固定为：当前所有者持有稳定 `ItemId` -> 对应 `IPortableItemCodec.Capture()` 导出 typed snapshot -> 持久化 Archive snapshot、`SubWorldItemRecord` 与 `ItemLease` -> 在同一主线程提交边界移除 MainWorld holder/equipment/craft 关系并回收源 Entity -> Archive 成为唯一权威，Runtime 可按 snapshot Materialize SubWorld Entity -> 撤离时把最终 snapshot、holder 与存活/消耗状态冻结进 `OutcomeDelta` -> 先卸载 SubWorld Runtime materialization -> 存活时用同一 codec 在 MainWorld Materialize 同一 `ItemId` 并绑定新所有者，消耗或销毁时不 Materialize -> 持久化 `CommitId` 与 MainWorld ownership 后删除 Archive 引用并释放 Lease。入口提交边界前失败不得移除源；边界后恢复只依赖 Archive 与 Lease。SubWorld 内新生成或制造的物品在场景或工序提交时取得 `StableItemId`，以 Archive 为初始权威且不预先取得 Lease，开始返回提交时才取得 Lease并走相同流程。任一时刻同一 `ItemId` 只能有一个有效 Lease，也只能由一个权威世界拥有有效 Entity；`LegacySiteRecord` 从不保存 ItemId、snapshot、ContentRef 或 Lease。

### 遗产来源

- 元婴修士必定具备留道资格。
- 金丹修士通常具备留道资格，但仍需拥有可传承的功法、法术或个人法宝。
- 炼气、筑基修士只有在自创功法、掌握独有法术或持有重宝时才形成小型遗藏。
- 寿元将尽者生前寻地布置完整洞府；突然战死者在死亡地点附近形成残破遗地。
- 玩家神力可以创建来源为“古修”的完整遗府，不伪造当前世界人物经历。
- 后续可让覆灭宗门的藏经阁与宝库形成宗门遗址，但不阻塞个人道统闭环。

### 完整与残缺

| 来源 | 地点形态 | 知识完整度 | 物品规则 |
| --- | --- | --- | --- |
| 生前布置 | 完整遗府 | 保存完整功法蓝图和代表法术 | 只封存实际交付给洞府的个人物品 |
| 突然战死 | 战殁残迹 | 保存残篇、代表法术或不完整功法 | 击杀者已夺取的法宝不重复生成 |
| 玩家投放 | 古修遗府 | 由有效蓝图生成完整古修道统 | 物品为该古修遗藏首次物化 |
| 宗门覆灭 | 宗门遗址 | 保存宗门真实收录内容 | 只接管覆灭时仍属于宗门的资产 |

完整度影响可学内容、功法属性、法术领悟、试炼难度和后续修复空间，不直接用统一倍率削弱所有奖励。

### 消息传播

- 遗府存在与角色是否知道它是两个独立事实。
- 未显露遗府不会进入普通 AI 的候选池，也不会显示完整 Tooltip 或小地图标记。
- 发现者首先独自掌握消息；当其无法独立探索、主动求援、与师徒交流或加入宗门队伍时，消息才扩散。
- 宗门获得消息后，只向参与决策与行动的成员开放，不让全世界立即知道。
- 队伍集结、多人抵达和长时间开启遗府会提高泄密程度，最终可能变成公开机缘。
- 玩家使用“显露天机”只改变玩家可见性，不自动把消息写入所有角色记忆。

### 外围与核心

- 外围遗藏以 SubWorld 容器、typed `ContentRef` 物品和道痕交互点存在，可以被不同到访者实际发现并依次取得；没有已注册 `IPortableItemCodec` 的具体类型不能进入实例。
- 核心传承由 SubWorld 唯一目标持有，包括主功法、代表法术与 `ContentRef<ArtifactInstanceSnapshot>` 镇府法宝，只提交一次唯一胜者；法宝仍须被 Winner 实际拾取并撤离。
- 外围与自然遗物允许 `ContentRef<MagicScrollSnapshot>` 和 `ContentRef<TalismanSnapshot>`。二者共享嵌套 `StoredSkillPayloadSnapshot { SkillBlueprint, Signature, Strength, PowerLevel }`，但分别保留魔法卷轴资格、学习/施放、寿命与符箓仙道资格、使用者力量换算、一次性施放语义。
- 遗府 Template 可以放置炼丹炉、炼器台、符台或魔法卷轴工位。参与者必须在内部找到对应 typed recipe、`IngredientSnapshot` 并具备 `CraftContext` 所需资源，使用共享 `CraftProcess` 完成制造，再拾取带稳定 `ItemId` 的 `ElixirItemSnapshot`、`ArtifactInstanceSnapshot`、`TalismanSnapshot` 或 `MagicScrollSnapshot` 产物并撤离。
- 第一个抵达者只负责激活实例并开始探索，不自动成为传人。
- 核心择主先检查境界与最低灵根要求，再综合元素相性、道途语义、内部破禁、守藏试炼和实际探索贡献。
- 最终采用高分候选中的加权选择，强者与先到者有优势，但不能稳定垄断全部机缘。

### 传承边界

- 传承功法知识时，为继承人建立对应掌握记录；功法和代表技能继续保存 `SkillBlueprint`，恢复时经共享编译器取得唯一 `CompiledSkillDefinition`，再由 MainWorld skill port 建立掌握关系，不直接搬运死者的 `SkillMasterRelation`。
- 法宝是唯一物品；当前世界修士留下的个人法宝必须通过 `ArtifactInstanceSnapshot` portable codec、稳定 `ItemId`、Archive record 与 `ItemLease` 从原持有者唯一转出。古修自然生成法宝以 Archive 为初始权威，没有 MainWorld 来源，退出提交前不取得 Lease。
- 法宝历任所有者与来源属于通用 `ItemProvenance`，随 `ArtifactInstanceSnapshot` 保存，不属于机缘私有字段或 codec。
- 宗门借用法宝和带 `SectTreasureRelation` 的物品不属于个人遗产。
- 不接管原版装备死亡分配，避免与 `Actor.newKillAction()` 和城市装备回收冲突。
- 不复制修炼境界、真气、仙基、金丹或元婴成果。境界灌顶属于另一套夺舍或轮回玩法。

### 道统演化

- 每个根道统拥有稳定 `LineageId`。
- 每次内容发生实质变化时生成新的 `RevisionId`，并记录 `ParentRevisionId`。
- 同一版本被继续传授只增加传承代数，不生成新修订。
- 改良功法、从残卷独立补全或融合外来法术会生成支脉。
- 根本、续修、支脉与残篇根据谱系关系和完整度推导；“正宗”只表示某个 Sect 奉行的修订，不作为全世界唯一结论。
- 祖师、改良者死亡后仍保留姓名、世界年份和来源地点快照；运行时角色 ID 只用于当前世界解析。

## 核心循环

```text
有资格的修士临终或战死
        ↓
冻结可持久化的道统快照
        ↓
创建主世界入口与休眠的小世界归档
        ↓
路过修士发现线索并决定保密、求援或上报
        ↓
个人或宗门前往入口，取得 Lease 并投影进入实例
        ↓
在内部移动、破禁、战斗、拾取并完成核心目标
        ↓
退出实例，冻结 OutcomeDelta 并由 SubWorldOutcomeCommitService 提交收获与代价
        ↓
继承人修炼、传授、改良或失去道统
        ↓
形成新的传承、支脉、遗府与世界历史
```

## 地点状态

| 状态 | 含义 | 可执行行为 |
| --- | --- | --- |
| `Dormant` | 入口与小世界归档已经存在但无人知晓 | 近距离感知、神力显露 |
| `Known` | 至少一名角色掌握入口消息 | 保密、求援、上报、前往 |
| `Opening` | 首位参与者已经进入小世界 | 其他知情者进入、内部探索 |
| `Contested` | 多名候选或多个队伍处于同一实例 | 破禁、战斗、拾取、目标竞争 |
| `Claimed` | 内部核心目标已有唯一胜者 | 撤离、结算、查看历史 |
| `Exhausted` | 可取得内容已经耗尽 | 转为不可寻访的原版废墟或纪念遗址 |

这些状态只是主世界入口摘要，必须由小世界归档中的实例、目标和参与者状态推导。完整遗府和战殁残迹入口在可交互阶段都保持 `BuildingState.Normal`；原版 `BuildingState.Ruins` 只用于 `Exhausted` 后的终态。

## 与小世界平台的边界

- `LegacySiteRecord` 管入口，保存 `SubWorldId`、来源修订、消息、玩家显露状态和外部摘要。
- `SubWorldArchive` 管内部，保存由原版 terrain catalog 生成的地图、实体、六种 typed ContentRef、稳定 ItemId、容器、Projection、带稳定 `ProcessKindId` 的 `CraftProcess`、试炼进度、目标和唯一胜者。
- 主世界 Actor 抵达入口后取得 `ExpeditionLease`，本体暂停并隐藏；实例内只创建 `ExpeditionProjection`，不移动或删除原 Actor。
- 探索收益与伤亡先写入 Projection；MainWorld 来源 portable item 保持入场 `ItemLease`，Archive 原生物品在开始返回提交时才取得 Lease。只有从出口撤离或实例完成结算时，才冻结最终 snapshot/holder 到 `OutcomeDelta` 并建立 `PendingOutcome`，再由 `SubWorldOutcomeCommitService` 按稳定 `CommitId` 幂等提交回 MainWorld；`CommitId` 与 MainWorld ownership 持久化并删除相应 Archive 引用后，才释放本次完成的 `ItemLease`，Actor 的 `ExpeditionLease` 最后释放。
- 机缘系统只向 SubWorld 平台注册 Template、terrain 主题 override、规则参数、typed ContentRef、炉台放置和目标，不自行维护另一套内部计时器、参与者表、物品 codec、制造规则、技能解释器或伤害公式。

## 数据所有权

### 世界存档

机缘道统与小世界平台使用四层原版世界数据保存不同生命周期的事实：

| 宿主 | 保存内容 | 生命周期 |
| --- | --- | --- |
| `MapStats.custom_data` | `LegacyWorldDocument`：道统蓝图目录、谱系修订和历史传承记录 | 整个世界 |
| `MapStats.custom_data` | `SubWorldArchive`：实例归档、内部地图、实体记录、参与者、typed item snapshot、SubWorldItemRecord、必要的 ItemLease、CraftProcess、目标，以及持有冻结 `OutcomeDelta` 与稳定 `CommitId` 的 `PendingOutcome` | 整个世界 |
| `BuildingData.custom_data_string` | `LegacySiteRecord`：入口状态、关联修订、消息、`SubWorldId` 和外部结果摘要 | 遗府建筑存在期间 |
| `ActorData.custom_data_string` | `ActorLegacyHoldings`：角色当前掌握的修订 ID、掌握度和主修选择 | 角色存在期间 |

运行时服务按 Building ID、SubWorld ID、Lineage ID 和 Actor ID 建立索引，但索引必须能够在读档后由上述数据重建。遗府耗尽或入口被移除后，道统蓝图仍由 `LegacyWorldDocument` 保留，小世界归档保留探索历史；角色读档时可据其持有的修订 ID 重建动态功法和技能。

遗府存档不得保存：

- Friflo ECS `Entity.Id` 或 `Entity.Pid`。
- `ActorExtend`、`ActorBinder` 或其他运行时对象引用。
- 第二个 `MapBox`、`WorldTile` 或原版 Actor/Building 的内部副本。
- 只存在于全局万法阁、百宝阁文件中的索引位置。
- 无法通过稳定 Asset ID 或 Blueprint 重建的对象。

### 传承快照

```text
LegacyDoctrineSnapshot
  SchemaVersion
  LineageId
  RevisionId
  ParentRevisionId
  FounderSnapshot
  OriginKind
  Integrity
  CultibookBlueprint
  RepresentativeSkillBlueprints[]
```

`CultibookBlueprint` 保存功法的稳定字段，并把 `CultibookAsset.SkillPool` 中的运行时技能实体导出为现有 `SkillBlueprint`。加载时先验证全部稳定 Asset ID，再由共享编译器把每个蓝图解析为按内容签名唯一的 `CompiledSkillDefinition`；MainWorld 恢复功法、授予代表技能和 SubWorld 构建 Projection capability 都引用该定义，不各自编译另一种能力描述。

道统快照创建成功后先注册进 `LegacyWorldDocument`，入口只保存对应 `RevisionId` 和 `SubWorldId`。法宝与外围奖励属于具体实例，保存为 `SubWorldArchive` 中带稳定 `ItemId` 的 typed ContentRef、snapshot、holder 和 `SubWorldItemRecord`；只有 MainWorld 来源或已经开始返回提交的物品持有 ItemLease，所有待提交变化都在 `PendingOutcome` 中，不写进可共享的功法修订或入口记录。同一道统被多个角色掌握时共享不可变的修订蓝图，各角色只保存自己的掌握度，不在每个 ActorData 中重复整份功法 JSON。

### 全局馆阁

- 万法阁和百宝阁使用 `Saves/global`，不按世界槽位隔离。
- 遗府不能只保存馆阁条目 ID，否则不同世界会错误共享道统来源。
- 功法蓝图深拷贝保存在世界道统目录，并通过共享 `SkillBlueprint` compiler/validator 取得 `CompiledSkillDefinition`。地点专属法宝统一由已注册 `IPortableItemCodec<ArtifactInstanceSnapshot>` 导出，通用 `ItemProvenance` 跟随实例快照进入对应 `SubWorldArchive`。

## 现有代码基础

## 全局约束

- 每个阶段完成后都必须形成可进入游戏验证的可用增量，不建立长期不可玩的基础层。
- `LegacySiteService` 只能修改入口、消息和外部摘要；内部状态只能由对应 `SubWorldRuntime` 修改。
- 核心胜者只能由小世界唯一目标提交一次，再由结算事件回写入口摘要和道统历史。
- 不创建第二个原版 `MapBox`，不把 MainWorld Actor 移出或删除；所有参与行为经过 `ExpeditionLease`、Projection、冻结的 `OutcomeDelta` 和唯一 `SubWorldOutcomeCommitService`。
- 功法导出与重建只能通过 Blueprint codec，调用方不得手工复制部分字段。
- 遗府 Generator 只能引用 `TileTypeBase terrain catalog` 和主题 override，不能注册一套 Legacy 基础 terrain 定义。
- 只有存在已注册 `IPortableItemCodec` 的具体 typed snapshot 类型才能成为外围、核心或内部制造物品；动态丹药、通用 `SpecialItem` 不再按类别作结论，具体对象没有 codec 就不能进入。
- MainWorld/SubWorld 的技能、伤害和 `alchemy`、`artifact_refining`、`talisman_crafting`、`magic_scroll_crafting` 分别通过共享 `CompiledSkillDefinition`、`DamageResolver` 与唯一 registry/domain；Legacy 目录下不得出现平行解释器、伤害公式、Process Kind registry 或制造规则。
- 跨世界物品提交必须保持同一稳定 `ItemId`；typed snapshot 与 Stable ItemId 是跨物化身份，Archive 或已提交的 MainWorld ownership 只能有一个成为权威。`ItemLease` 只记录跨世界转移与幂等状态，提交动作只由 `SubWorldOutcomeCommitService` 执行；SiteRecord 不得保存任何物品事实。
- 死亡处理必须幂等；尸体销毁时第二次进入 `Actor.die` 不能重复生成遗府。
- 自然遗产不能复制已经被击杀者或宗门取得的唯一物品。
- 发现扫描按活跃角色的低频工作选择执行，不逐帧扫描全世界建筑与角色笛卡尔积。
- 同一地区的活跃遗府数量有上限；已耗尽地点及时转为低成本终态。
- 随机只在合格候选中决定结果，不绕过最低境界、相性、距离、敌对关系和真实行动。
- 所有玩家可见文本必须本地化；地图表现优先复用 WorldBox 建筑、Tooltip、小地图和力量按钮语义。

| 阶段 | 文档 | 直接消费的 SubWorld 合同 | 完成标志 |
| --- | --- | --- | --- |

| 3 | [秘密传播与传承择主](机缘道统/第3阶段-秘密传播与传承择主.md) | 第 2 阶段六种 portable item 与返回合同、第 3 阶段 registry/domain、第 4 阶段 compiled skill/`DamageResolver` | 多名知情者真实发现四类制造输入与两类技能载体、制造、拾取并撤离，核心只有一名胜者 |

## 最终完成标准

系统完成后，一个世界应能在没有玩家持续操作的情况下自然产生以下闭环：强者留下来源明确的遗产；消息在少数人物和宗门之间传播；个人与队伍真实前往入口并投影进入遗府；参与者在内部移动、破禁、战斗，按内容需要发现配方、材料、魔法卷轴与符箓，运行四种共享 CraftProcess，拾取带稳定 ItemId 的产物并撤离；玩家通过非模态浮窗同时观察主世界与遗府，二者依靠独立时钟按各自速度运行；核心传承按相性与完成的试炼择主；技能、战斗、物品和四类制造结果都由共享领域核心提交；继承人继续修炼、传授和改良；数代之后仍能从人物、功法、入口、SubWorld 历史和世界日志追溯同一道统的兴衰。
