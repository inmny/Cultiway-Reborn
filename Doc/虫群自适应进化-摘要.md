# 虫群自适应进化-摘要

**版本**：v1.0  
**状态**：设计基线  
**最后更新**：2026 年 8 月 8 日  
**当前范围**：自主巢群、AI 自适应、巢群基因库与个体差异  
**共享依赖**：[组合生灵与妖兽](组合生灵与妖兽-摘要.md)阶段 0、1；必须在本规划阶段 1 创建首个虫族 Actor 前完成

**明确不包含**：存档、读档恢复、完整文明、玩家手动编辑基因

## 设计目的

虫族是一套能够观察真实环境、尝试有代价的变异、比较同代适应度并把有效变化遗传给后代的自主巢群系统。它不是固定单位包，也不是依靠击杀逐级升级的文明。

系统必须同时满足：

1. 玩家能从外观、移动、攻击、队伍组成和巢穴行为看出进化结果。
2. 每次候选、固化和淘汰都能指出压力、证据、收益和代价。
3. 一次受击不会使全族立即免疫，遗传变化必须经过积累、试验和新生代传播。
4. 器官受槽位、复杂度、生物质和副作用限制，不存在无限叠加。
5. 相同初始基因的母巢可以在不同环境中形成不同生态型。
6. 伤害观察为 O(1) 有界记录，低频进化计算按预算执行。

## 已确定方向

### 阵营与控制

- 虫族首先实现为自主巢群，不建立 `City`、`Culture`、`Clan`、外交或普通建筑队列。
- 使用技术性的非文明 `KingdomAsset` 接入原版敌我、伤害和目标搜索。
- 进化完全由 AI 决定；玩家通过改变环境间接影响结果。
- 正式 UI 只读，不提供器官编辑器或手动进化按钮。
- 第一版不同母巢彼此友好。

### 遗传层级

- 母巢保存已固化基因模板、遗传记忆和当前试验。
- 新生虫从母巢模板生成表现型，不从父母 Actor 继承。
- 个体最多形成一次有界体细胞适应，不直接写回母巢。
- 同代同职虫的基准组与变异组决定候选是否固化。
- 子巢深拷贝建立时的基因快照，之后独立演化。

### 数据所有权

- Hive、Trial、BiomassDeposit 是独立 ECS 实体。
- 个体虫群身份、适应度和体细胞状态附着于 `ActorExtend` 对应 ECS Entity；实际身体组合使用共享 `CreaturePhenotype`。
- `HiveGenome` 针对各职虫保存共享 `CreaturePhenotypePlan` 模板和虫群专属遗传元数据。
- LinkRelation 表达归巢和试验分组；器官能力由共享表现型 Provider 按当前 Actor 解析，不建立虚构的 AbilityGrant 关系。
- WorldBox Actor 与 Building 只负责宿主、渲染和物理，通过 Binder 解析。
- Repository 只允许作为可重建索引，不是权威状态。
- 不向 `ActorData`、`BuildingData`、`ModSaveManager` 或外部文件写入虫族世界状态；虫群 ActorAsset 使用 `skip_save`，原版保存收集时过滤巢核、附着炮台和依赖对象，保证读档不会留下无 Hive 状态的残件。

## 核心循环

1. 玩家放置原始母巢。
2. 母巢用初始生物质孵化幼虫，并分化为工虫和兵虫。
3. 工虫采集尸体，兵虫捕猎、巡逻和护巢。
4. 真实战斗、饥饿、水域和生产结果形成有衰减的环境压力。
5. 虫群先调整生产比例、活动和战术，解决短期问题。
6. 长期压力触发预定义遗传候选。
7. 一批同代个体被稳定分为基准组和变异组。
8. 系统比较目标压力缓解、一般生存、职责产出和资源效率。
9. 成功候选进入后续新生代，失败候选进入抑制记忆。
10. 母巢成熟后产生建巢母虫，子巢继承快照并独立演化。

## 三种反应速度

| 层级 | 时间尺度 | 修改基因 | 例子 |
| --- | --- | --- | --- |
| 行为可塑性 | 秒到月 | 否 | 召回、集火、撤退、调整职虫比例 |
| 个体体细胞适应 | 月到一个生命周期 | 否 | 应激硬化、弱滤毒、低耗代谢 |
| 遗传进化 | 多个世代 | 是 | 器官替换、固定形态、巢器官、神经策略 |

遗传进化必须经过候选、Trial 和固化；一座母巢同时最多进行一个 Trial。

## 全局约束

- 不复制任意敌人的 Trait、Skill、ActorAsset 或代码行为。
- 不使用机器学习、神经网络或不可解释的遗传算法。
- 身体方案、固定形态、器官定义、表现型签名、属性/语义/能力/视觉表达复用[组合生灵共享层](组合生灵与妖兽-摘要.md)；压力、候选、Trial、固化和职虫生产仍由虫群拥有。
- 不为器官组合动态创建 ActorAsset；飞行、水陆属性等资产级变化使用少量共享 `CreatureMorphAsset` 固定形态。
- 虫群 BodyPlan 定义甲壳、运动、武器腺、代谢、神经五个固定槽位；共享框架本身不硬编码五槽。
- 表现型签名只包含身体方案、形态、按槽位排序的器官 ID 与等级，不包含母巢、基因世代、Trial 或分组。
- 压力来自已经发生的交互，不扫描全世界敌人的隐藏能力。
- 每类虫群领域状态只有一个领域服务能够修改；共享表现型只能由 `CreatureExpressionService` 原子提交。
- Query 只读期间不进行结构修改；结构变化使用当前 SystemGroup 或现有 `ModClass.CommandBuffer`，不假设存在全局 `StructuralCommit`。
- 所有计时使用世界模拟时间，暂停时不推进，倍速不改变每帧预算。
- `MapBox.clearWorld()` 是唯一世界销毁边界；Core、组合生灵共享层与各 Feature 在该边界同步删除各自的世界级 ECS Entity、关系、队列、编译缓存和索引，不新增 `WorldGeneration` 或 `WorldOwned`，也不把清理延迟到新世界首个逻辑 Tick。

## 术语

| 术语 | 含义 |
| --- | --- |
| Hive | 母巢 ECS 聚合根，对应一个 WorldBox 巢核 Building |
| Genome | 母巢针对各职虫保存的共享表现型计划与虫群遗传元数据 |
| Phenotype | 共享 `CreaturePhenotype`，表示个体实际表达的身体方案、固定形态和器官集合 |
| Pressure | 由真实事件结算出的近期适应需求 |
| Evidence | 支撑压力与候选判断的事件强度和数量 |
| Sample | 已经交互过的生物结构或能力语义切片 |
| Trial | 同代同职虫基准组与变异组的对照过程 |
| Commit | 候选写入母巢模板并影响后续新生代 |
| Genetic Memory | 被替换模块的有衰减熟悉度 |
| Doctrine | 改变目标、编队和撤退规则的群体神经策略 |

## 架构结论

虫群自适应由六个互相约束的部分构成：真实事件形成有衰减且按人口归一化的压力；行为先响应短期问题；虫群适应定义从共享器官目录选择候选；同代 A/B Trial 决定遗传结果；固化结果写入职虫表现型计划并只影响后续新生代；Hive ECS 与 Actor ECS 承担全部权威状态。共享层只负责组合校验与表达，不参与进化决策。由此实现“越打越会应对”，但不会因为一次受击立即免疫，也不会最终叠满全部能力。
