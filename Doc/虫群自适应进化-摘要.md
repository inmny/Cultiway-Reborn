# 虫群自适应进化-摘要

**版本**：v1.0
**状态**：设计基线
**最后更新**：2026 年 8 月 8 日
**当前范围**：自主巢群、自动适应环境、母巢遗传模板与个体差异
**共享依赖**：[组合生灵与妖兽](组合生灵与妖兽-摘要.md)阶段 0、1；必须在本规划阶段 1 创建首个虫族生物单位前完成

**明确不包含**：保存和恢复虫群数据、完整文明、玩家手动编辑基因

## 设计目的

虫族是一套能观察真实环境、尝试有代价的变化、比较同代成果，并把有效变化传给后代的自主巢群系统。它不是一组固定单位，也不是依靠击杀逐级升级的文明。

系统必须同时满足：

1. 玩家能从外观、移动、攻击、队伍组成和巢穴行为看出进化结果。
2. 每次提出候选、保留变化或淘汰变化时，都能说明压力、证据、收益和代价。
3. 一次受击不会使全族立即免疫；遗传变化必须经过积累、对照试验和新生代传播。
4. 器官受槽位、身体承载力、生物质和副作用限制，不允许无限叠加。
5. 初始遗传模板相同的母巢，可以在不同环境中形成不同生态型。
6. 每次伤害只做固定数量的记录，耗时较大的进化计算按限额分批执行。

## 已确定方向

### 阵营与控制

- 虫族首先实现为自主巢群，不建立城市、文化、家族、外交或普通建筑队列。程序仍使用非文明阵营定义（`KingdomAsset`）接入原版敌我、伤害和目标搜索。
- 进化完全由自动行为决定；玩家通过改变环境间接影响结果。
- 正式界面只供观察，不提供器官编辑器或手动进化按钮。
- 第一版不同母巢彼此友好。

### 遗传层级

- 母巢保存各职虫已经固定的身体方案、遗传记忆和当前对照试验。
- 新生虫从母巢模板生成实际身体，不从父母生物单位继承。
- 每个个体最多形成一次有限的终身应激变化，不直接写回母巢。
- 同代同职虫的基准组和变异组决定候选是否保留。
- 子巢带走建立时的完整遗传副本，之后独立演化。

### 数据归属

- 母巢、对照试验和尸体生物质残留是独立运行记录，程序分别使用 `HiveTag`、`AdaptationTrial` 和 `BiomassDeposit` 等组件表示。
- 个体身份和终身应激变化放在生物单位扩展记录（`ActorExtend`）上；实际身体使用共享组件 `CreaturePhenotype`。
- 参加对照试验的虫子把受伤、死亡、战斗和职责产出直接累计到所属试验的甲组或乙组成绩（`TrialCohortMetrics`）；普通虫子不保存试验成绩。
- 母巢遗传模板（`HiveGenome`）为每种职虫保存共享身体计划（`CreaturePhenotypePlan`）和虫群专属的进化资料。
- 归巢和试验分组使用归属关系（`LinkRelation`）；器官能力由共享能力来源 `CreaturePhenotypeActiveAbilityProvider` 按当前实际身体提供。
- WorldBox 的生物单位和建筑只承担地图对象、渲染和物理表现；程序通过绑定记录（Binder）找到虫群运行数据。
- 快速索引可以随时重建，不是权威数据。
- 虫群数据不写入 `ActorData`、`BuildingData`、`ModSaveManager` 或外部文件。虫群生物单位定义使用 `skip_save`，保存地图时过滤巢核、附着炮台和依赖对象，保证读档后不会留下失去母巢数据的残件。

## 核心循环

1. 玩家放置原始母巢。
2. 母巢用初始生物质孵化幼虫，并分化为工虫和兵虫。
3. 工虫采集尸体，兵虫捕猎、巡逻和护巢。
4. 真实战斗、饥饿、水域和生产结果形成会逐渐减弱的环境压力。
5. 虫群先调整生产比例、工作和战术，解决短期问题。
6. 长期压力触发预先写好的遗传候选。
7. 一批同代个体被稳定分为基准组和变异组。
8. 系统比较压力是否缓解、一般生存情况、职责产出和资源效率。
9. 成功候选进入后续新生代，失败候选进入暂时抑制记录。
10. 母巢成熟后产生建巢母虫，子巢带走遗传副本并独立演化。

## 三种反应速度

| 层级 | 时间尺度 | 修改遗传模板 | 例子 |
| --- | --- | --- | --- |
| 行为调整 | 秒到月 | 否 | 召回、集火、撤退、调整职虫比例 |
| 个体终身适应 | 月到一个生命周期 | 否 | 应激硬化、弱滤毒、低耗代谢 |
| 遗传进化 | 多个世代 | 是 | 器官替换、固定形态、巢器官、神经策略 |

遗传进化必须经过候选、对照试验和固定结果；一座母巢同时最多进行一个对照试验。

## 共享边界

共享身体层只负责以下事情：

- 定义身体方案、固定形态、器官和外观挂点。
- 按槽位、身体承载力和冲突规则安排器官。
- 根据身体方案、形态、器官编号和等级生成稳定组合编号。
- 把已经确定的身体组合表达为属性、语义、主动能力、受击反应和外观。

虫群仍独立负责以下事情：

- 收集并衰减环境压力。
- 记录真实交互证据和样本。
- 选择候选并进行同代对照试验。
- 决定是否固定变化，以及何时影响后续新生代。
- 管理母巢、生物质、职虫生产、群体战术、巢器官和分巢。

共享层不得读取母巢压力、试验分组、生物质或生产目标；虫群也不得重复实现身体组合、属性、能力和外观表达。

## 全局约束

- 不复制敌人的任意特性（`Trait`）、技能（`Skill`）、生物单位定义（`ActorAsset`）或代码行为。
- 不使用机器学习、神经网络或无法解释的遗传算法。
- 不为每种器官组合动态创建生物单位定义；飞行、水陆限制等会改变基础动画或物理行为的变化，只使用少量固定形态（`CreatureMorphAsset`）。
- 虫群身体方案有甲壳、运动、武器腺、代谢、神经五个固定槽位；共享框架本身不把所有生物都限制为五槽。
- 组合编号只包含身体方案、固定形态、按槽位排序的器官编号和等级，不包含母巢、遗传代数、对照试验或分组。
- 压力只来自已经发生的交互，不扫描全世界敌人的隐藏能力。
- 每类虫群数据只有一个服务可以修改；共享实际身体只能由 `CreatureExpressionService` 整体提交。
- 结构变化使用当前处理组的命令缓冲区或 `ModClass.CommandBuffer`。
- 所有计时使用世界模拟时间；暂停时不推进，倍速不改变每帧处理上限。
- `MapBox.clearWorld()` 是世界清理入口。核心层、共享身体层和虫群模块在这里删除各自的世界记录、归属关系、队列、编译缓存和索引。

## 程序对应表

正文优先使用左侧的通俗名称；实现时使用右侧的真实程序名。

| 通俗名称 | 程序名称 | 含义 |
| --- | --- | --- |
| 母巢运行记录 | `HiveTag`、`HiveIdentity` | 一座母巢的主要运行数据，对应一个巢核建筑 |
| 遗传模板 | `HiveGenome` | 母巢为各职虫保存的共享身体计划和虫群进化资料 |
| 实际身体 | `CreaturePhenotype` | 个体当前真正表达的身体方案、固定形态和 `Organs`（`CreatureOrganEntry[]`） |
| 身体计划 | `CreaturePhenotypePlan` | 出生或蜕变前冻结的一整套身体组合 |
| 母巢人口 | `HivePopulation` | 保存幼虫和各职虫数量，供生产和压力折算直接读取 |
| 环境压力 | `HivePressure` | 统一保存本月证据、当前压力和历史峰值 |
| 交互证据 | `Evidence` | 支撑压力和候选判断的事件次数与强度 |
| 语义样本 | `HiveSampleBank` | 已经交互过的生物结构或能力摘要 |
| 对照试验 | `AdaptationTrial` | 同代同职虫基准组和变异组的比较过程 |
| 固定结果 | `TrialDecision.Committed` | 候选写入母巢模板并影响后续新生代 |
| 遗传记忆 | `GeneticMemory` | 被替换模块留下、会逐渐减弱的熟悉度 |
| 群体策略 | `HiveDoctrineAsset` | 改变目标、编队和撤退规则的神经策略 |
| 归属关系 | `HiveMembershipRelation` | 生物单位属于哪座母巢及其职责 |
| 组合编号 | `CreaturePhenotype.Signature` | 只由实际身体内容生成的稳定编号 |

## 架构结论

虫群自动适应由六个互相约束的部分构成：真实事件形成会衰减、会按人口折算的压力；自动行为先解决短期问题；虫群规则从共享器官目录选择候选；同代甲乙两组对照试验直接汇总参试虫的表现并决定遗传结果；固定结果只写入后续职虫的身体计划；母巢、对照试验和生物单位各自保存自己真正需要的数据。共享层只负责整理和表达身体组合，不参与压力、试验、生产或战术决策。这样可以做到“越打越会应对”，但不会因为一次受击立即免疫，也不会最终叠满所有能力。
