# 基础动作与握持接触适配

对应2.17。沿用共同骨架、动作时钟、挂点及作用区，制作能够声明适用条件和调整范围的资料。

## 实施顺序与完成条件

1. 握持资料先提供完整方向、柄粗及允许尺寸；真实持剑使用同一对齐结果生成显示和作用形状，以剑、镜、双柄炉及不同尺寸验证。
2. 基础动作声明实际部位、支撑点、阶段及允许的速度、距离、方向和体型调整，原地发力、持物动作及非人部位分别提供输入。
3. 双方接触资料提供对应部位、接触阶段及解除点，结合支撑和握持验证同一姿态与作用。完整抓投与双方运行控制继续按4.23至4.26接入。

三部分资料均有实际取样及两种显示证据后才完成2.17。资源制作与完整人物玩法分开记录，不将单次对齐当成完整抓持或全部身体适配。

## 动作、支撑与接触资源设计

| 资源与动作 | 实际输入、支撑及接触资料 |
|---|---|
| 巨神发掌 | 共用palm_press，双足在动作中保持支撑；掌面在contact至recover阶段可与对方掌面配对 |
| 巨神架势 | 共用brace，双足支撑及左掌接触帧，声明架势阶段；不把资源取样算成格挡结算 |
| 灵臂握持 | 共用grasp，新增实际掌内握点；closed至release阶段可对齐剑、镜或炉把手，无脚部不声明落脚 |
| 灵臂发掌 | 共用palm_press，实际掌面与对方身体表面配对；声明接触及解除阶段 |
| 水鲸摆尾 | 制作独立tail_sweep动作，尾鳍的真实挂点与作用区随同一骨架；非人部位不映射成人手，无落脚支撑 |

每份动作声明模型尺寸、播放速度与转向范围。单次取样改变实际共同姿态与完整世界变换，接触时段使用调整后的同一时间。距离由双方实际接触帧和明确容差检查，越界时报告未对齐；不拉长骨骼来冒充触达。

支撑点记录挂点、开始及解除阶段和允许误差。取样以实际支撑点计算整体偏移，并核对其余支撑的一致性。双方接触资料记录本方挂点、对方部位用途、接触时段、位置及方向容差；握柄采用完整握持帧。对方配对只生成几何结果与候选放置，不直接取得人物控制，真实抓投、移动、受力及解除仍由4.18至4.26落实。

## 第一部分资源设计

| 资源 | 握持资料及用途 |
|---|---|
| 剑 | 原握点、柄长轴与柄粗；允许相对身体尺寸范围，接入真实持剑 |
| 铜镜 | 原握柄及柄长轴；柄粗和可用尺寸独立于剑，不按模型名称猜方向 |
| 双柄炉 | 左右把手分别提供握持帧和柄粗；单点对齐可复用，双手共同约束留在后续接触资料 |
| 掌形 | 原腕点和掌内握点继续使用；内容适配明确手部尺寸和可闭合范围，接合与碰撞读取同一矩阵 |

握点的前向沿柄长轴，另一个方向确定绕轴朝向。原有挂点的方向可能表示施法出口，握持资料只补自己的绕轴方向，不改变其他附着语义。尺寸范围按器物缩放与身体高度之比声明；柄粗随器物真实缩放，不能通过忽略柄粗让物件穿过手掌。

制作源保留资料，经过原有Unity导入和发布格式加载。运行只使用已经解析的数值和索引。新的资源字段不加入mod.json，正式存档仍保存稳定形体和握持编号。


## 握持部分实现与证据

发布格式6新增`Grips`，剑、镜及炉的左右把手共四项资料经过制作源、Unity导入与正式资源加载。每项保存原挂点、绕柄方向、实际最大柄粗与允许的模型缩放/体高范围；运行只保留复制的数值和已经解析的控制。分件保留自己的握持，刃部不会借用握柄资料。

`FormGrip.Align`同时对齐握点、柄轴和绕轴方向，并支持随同一骨架姿态变化的握点。真实持剑由`BodyActionBinding`使用该矩阵，显示和胶囊作用继续共用。内容适配当前使用手模型缩放/体高0.7、剑0.42，手部模型可闭合范围0.035至0.08；剑柄实际最大直径0.13。原手缩放0.4导致掌部尺寸不足，现连同手指及真实作用一起修正，腕点仍准确连接前臂。

Linux私有游戏45808经NML加载最终代码，34项专项通过。此前游戏42843通过25项原版身体挂点和63项资源结构/失败重载回归；随后仅修正开始时握持版本的选择，并在最终专项中补充真实新旧绑定检查。专项覆盖四种握持、三种使用者尺寸、三个方向、实际持剑四个方向、柄粗和范围拒绝、分件及输入复制。最大位置误差约0.00000048，方向误差0；真实持剑的腕点和作用矩阵检查通过。临时将新版剑柄直径改为5后，新绑定被拒绝，旧绑定继续使用开始时的柄粗并保持有效；检查结束恢复原文件并重新加载。这里的三种尺寸是用于握持对齐的纯数值体高参数，完整不同种族、体型及非人身体的实际动作还要继续验证。

## 动作、支撑与双方接触实现

发布格式7增加`Actions`，沿用现有制作动作及其阶段标记。巨神发掌与架势、灵臂握持与发掌、水鲸横扫共五份动作声明允许的模型尺寸、速度和绕制作上向的转向；接触资料声明本方挂点、对方部位用途、开始及解除标记、世界距离和完整朝向容差。灵臂补实际掌内握点，巨神补躯干接触挂点，水鲸横扫使用独立的连续脊柱与尾鳍动作，不套用人的手脚。

`FormAction`在完整资源加载时复制范围、阶段及接触数值，解析挂点和支撑参考位置。`Create`核对请求范围，为一次动作分配可重复使用的姿态；`Sample`让调整后的同一动作时间驱动骨架、支撑、作用区和显示。双足支撑取第一个实际支撑点求整体修正，再核对其他支撑；冲突时明确报告失败。无落脚的灵臂和水鲸声明空支撑集合，不虚构脚部。这里没有承诺任意地面上的全身平衡、步法或任意距离的肢体重定向，这些继续按第4工作包实现。

`Bind`只接受对方挂点实际所属部件的用途。接触帧与握持帧使用同一控制混合，保持实际位置与完整方向，去掉表面混合带来的剪切。`TryAlign`在有效接触阶段提供候选放置；`Matches`根据双方实际姿态检查距离及方向。对方为剑、镜或炉把手时读取其完整握持帧。解除时刻立即退出；身体和器物本身的移动、控制权、握紧、碰撞反应及抓投仍留给4.18至4.26，不把几何对齐当成已完成这些玩法。

动作和配对保持各自资源版本。取样只处理独占数值姿态，不查询网格或游戏人物；分件不继承完整身体的动作、支撑和双方关系。制作输入、Unity导入和发布说明共同保存所有新资料，没有逐招运行类或新增玩家设置。

## 本批验证

Linux私有游戏54184经NML加载本批代码，71项动作专项通过；同一进程34项完整握持及真实持剑回归通过。专项覆盖五份动作的八组尺寸、速度与转向边界、巨神双足原位支撑、互相冲突的支撑、独立输入复制、缺少挂点或阶段、分件边界、错误部位拒绝，以及八种真实部位配对的距离、方向、接触前和解除检查。水鲸实际尾鳍挂点横向移动超过一个模型单位，同一骨架带动真实作用轴线；独占动作在工作线程取样通过。

1280×720、12帧/秒、192帧、16秒技术录像展示原版和Worldfall中的五份动作；接触时段显示对方实际资源，灵臂依次对齐剑、镜与炉柄。已查看两种显示的动作中间阶段及三种器物。录像不作为自然交战、完整不同种族适配或最终美术验收。首次执行只在输出报告时发生Unity向量循环序列化错误，改为数值数组后通过；不是运行姿态失败。

三平台资源构建成功，仅Linux实际运行；SDK0错误、16条已有警告，按项目DotSettings整理。没有新增GameResources贴图、玩家设置及世界存档字段，玩家无需手工迁移。第2工作包的基础资源资料至此具备；完整动作构造、身体接管和实际受力按后续编号推进。
