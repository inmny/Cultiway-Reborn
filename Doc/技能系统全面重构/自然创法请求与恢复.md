# 自然创法请求与恢复

本批落实7.01与7.18，继续7.05、7.07及正式保存相关任务。它扩展自然触发和工作处理，不把当前几类生成结构等同于完整的自由创法范围。

## 从实际活动提交请求

原路径只在按月修炼系统中尝试，已学任意一项构造后不再自然创作。现在功法领悟成功或修炼分派成功后检查本人物，主动打坐、植物式修炼和功法的按月或事件修炼共用入口。自然仙道突破成功提交后另给一次机会；直接授予等级及未改变等级的状态同步不伪造自然突破。

- 普通修炼每个世界月最多检查一次机会，概率沿用1.5%。重复修炼和高频伤害不会连续重抽。
- 自然突破的额外机会概率为25%，等待中的人物不重复受理。
- 已经掌握构造后仍可继续创作；沿用128项已学、100000项世界目录的正式保存上限。
- 同一世界最多等待256项请求，每个共同逻辑周期只处理一项，不另建线程池。
- 队列满时记录原因并等待下次机会；生成或编译失败记录具体原因，不当场无限重试。

机会选择和创作种子分开取样，避免“随机选择成功”把后续生成结构锁死在同一分支。人物机会序号、确定的创作种子和来源都可复现；创建时仍用同一构造编译器检查，成功后才登记和授予。

## 固定输入及自然入口

| 入口 | 实际用途 |
|---|---|
| `TryComprehendSkill` | 成功领悟功法法术后使用同一普通机会与等待，不因重复学习额外抽取 |
| `CultivateMethods.TryDispatch` | 成功修炼后尝试本人物机会；不在每帧另扫全部修士 |
| `ProgressionLifecycle` | 已提交自然突破观察，不修改进阶结算和奖励 |
| `ConstructedAbilityService.Generate(actor, seed)` | 生成独立草稿；不登记、学习或修改已有构造 |
| `TryQueueCreation(actor, seed)` | 受理固定输入并走相同有限队列，适合复现自然请求 |
| `Create(actor, seed)` | 请求处理与固定输入共用的即时生成、编译及学习入口 |

当前生成结构移到`ConstructedAbilityGeneration.cs`，请求、限量、自然入口和保存位于`ConstructedAbilityCreation.cs`；构造运行和显示继续沿用原有共用框架。这里没有恢复固定连招或组合配方。

## 正式保存

新增人物区段`ability_creation`第一版，保存机会序号、下一次普通机会的剩余世界时间、待处理标记、确定种子、来源、最近正式能力及失败原因。旧世界没有该区段时使用空状态，不改写已有构造或已学关系。

载入时按原种子恢复未完成请求，不重新抽选。已经完成的请求保存为非等待，反复存读档不重复授予。切世界清空旧队列；请求只保存长期人物编号，处理时重新取得当前人物。队列容量或局部资料无效时，仅报告受影响请求，其余资料继续恢复。

## 本轮验证

`verify_creation_requests.script`在独立世界检查固定输入、独立草稿、正式学习、一次一项、同月去重、真实世界等待、自然突破观察、关闭再启用、128项掌握上限、257名实际人物排队及局部保存错误；末尾用原版世界文件保存一项尚未执行的确定请求。

`verify_creation_timed.script`使用真实功法与按月修炼分派，检查请求受理、重复结算去重、未支持活动不触发及正式授予。`verify_creation_comprehension.script`通过真实功法领悟检查原法术学习、创法受理、已学不重复领悟，以及同月成功领悟另一术时共享等待。

真正退出并重启游戏后运行`verify_creation_requests_restart.script`，检查原人物、原输入、剩余等待、原构造与已学关系，以及待处理请求完成后再次存读档不重复生成。

本批没有新增外观资源。大规模长期增长、结构近似去重、灵根／功法／性格倾向、基于已有法术继续创作、更多战技和功能过程仍在对应TODO内；它们不能被请求队列或512个输入通过编译代替。

## 实际结果
