# 资料边界与稳定编号

对应全程 TODO **0.04**。本页固定完整框架的资料职责和身份规则，并标明当前实现落在哪里。它不把尚未实现的过程输出、通用关联或完整对象选择提前算作完成。能力与来源分别沿用[登记表](全部能力登记表.md)、[调用入口](各能力调用与保存入口.md)。

## 定义、编译、运行和世界事实

| 层次 | 可以保存什么 | 身份与边界 |
|---|---|---|
| 构造定义 | 明确结构、引用、参数、条件、取得来源及改造结果 | `AbilityDefinition.Id`、`Revision` 和资料 `Version`。不得混入人物对象、网格、当前目标、碰撞结果或本次进度 |
| 编译计划 | 名称解析后的索引、有限展开、控制与作用绑定、纯数值参数、资源引用 | `CompiledAbility` 对完整构造内容及当前资源组编译。同一计划共用，不写回可编辑定义，不作为正式存档 |
| 单次运行 | 本次来源与控制权、目标输入、世界时间、真实姿态、当前材料、过程进度、已发生结果 | 一次施放和展开部位的临时编号。不取代构造、人物或世界材料的长期编号 |
| 已交接的世界事实 | 地形、天气、世界材料、宗门、节点、关系等实际玩法状态 | 交给原有玩法保存，具有自己的拥有者和版本；施放结束不重置世界结果 |

代码位置：[定义](../../Source/Core/Skills/AbilityDefinition.cs)、[编译](../../Source/Core/Skills/AbilityCompiler.cs)、[运行](../../Source/Core/Skills/AbilityCast.cs)、[世界材料](../../Source/Content/Skills/WorldMaterialService.cs)、[天气](../../Source/Content/Skills/ConstructedRainClouds.cs)。生命周期继续遵守[控制归属与结束合同](控制归属与结束合同.md)。

`Version` 是资料读写格式，`Revision` 是能力内容修订，`FormResources.Version` 是本次进程的资源组序号，模组版本是发布版本。这四个数字不能互相替代。当前编译缓存还比较完整内容，不会只凭同一编号和修订误用另一份计划；修改内容仍应产生新修订，衍生新术使用新能力编号及 `Parent` 来路。

## 九类资料分别负责什么

| 类别 | 完整框架的边界 | 当前落点与编号 | 后续接入范围 |
|---|---|---|---|
| 形体 | 可组合的几何、控制、命名部位、挂点、可用动作及初始作用形状。提供“能怎样变”，不写成一整招的无条件录像 | `FormDescription.Id`，由 `ConstructionNode.Form` 引用；`Content/Forms/*.json` 发布格式2 | 2.04—2.07继续扩充控制、分枝和曲面制作；新增完整造型不需要新增整招执行器 |
| 部位 | 一个有名字、可被选择及绑定的局部单位。构造节点、模型分件、骨架控制、挂点、作用形状各有类型，不能因为名字一样就互换 | `ConstructionNode.Id` 在同层唯一；模型 `Parts/Controls/Anchors/Contacts` 各自在一个形体内命名 | 部位标签、集合选择及运行新增结构继续在3、5包完善；不把当前前缀匹配冒充完整选择语言 |
| 材料 | 实际性质及明确实现的伤害、守恒、转化、反应规则；与颜色和纹理分开 | `AbilityMatter.Id`、`ConstructionNode.Matter`，由内容层登记 | 新材料必须提供实际规则；名称不会自动带来燃烧、导电、折射、灵魂或空间作用 |
| 物态 | 同一种材料当前采用的实际状态，决定哪些形变和作用成立 | `(Matter, State)` 共同解析；缺省 `State` 取已登记默认 | 物态变化继续同一材料身份及来源；规则可改变材料时也明确声明输出，不按外观猜测 |
| 运动 | 位置、朝向、速度及空间参照的变化，包含身体、持物、飞行、曲线与骨架动作 | `Fly/Spin/Animate`、`ConstructionPath`、`BodyActionDefinition`；制作动作由同一形体内 `Clip` 名称引用 | 完整步法、握持及双方关系继续在4包实现；运动不会自动产生伤害或改变物态 |
| 过程 | 有输入、进度、输出和结束事实的持续变化，如生长、聚合、碎解、流散、回收和维持。实际结果可供后续过程使用 | 当前为节点上的 `Operations`、`Activation`、`Hold` 及相应运行状态；种类数字固定见下表 | 3.03—3.04、5.01—5.13扩展具名过程与输出连接。当前数组顺序不是跨修订过程身份 |
| 关联 | 明确连接两端，约定跟随、姿态、控制、来源、维持、作用传递和断开后果。关联自身不暗中复制主体或制造材料 | 当前为根 `Binding`、父子挂点、事件 `Source`、身体借用及世界拥有者；没有通用关系图 | 组合、映像、两端通行及网络需要后续通用关系。各玩法既有关系仍由原玩法维护 |
| 作用 | 对明确对象和真实接触结果施加伤害、推拉、转化或世界原理。使用距离、选取范围、真实作用区及纯显示范围分别描述 | `ConstructionImpact`、`ConstructionWorldEffect.Action`、实际接触用途及频率 | 更完整对象选择属于0.06；通用作用输出及交互属于3—6、11包。视觉出现不能自动触发实际作用 |
| 条件 | 读取已经确认的状态或结果，决定开始、变化、传递或结束；不直接拥有动作和伤害 | `ConstructionCondition`、`ConstructionChangeTrigger`、阈值、延迟、材料筛选；当前支持九类实际事件 | 联合条件、过程输出及世界条件继续在3、5、11包实现；没有把名称解释成规则的入口 |

这些边界允许一项能力同时有身体、器物、多个生成形体和功能过程，也允许功能过程不产生可见网格。跨形态改造需要补齐真实载体、运动、作用、支付和结束，不能只给原地掌击贴一段追踪特效。实现不能依赖“鲸招”“剑树”这样的整招名称判断。

| 编号 | 保证什么 | 不可使用什么代替 |
|---|---|---|

| 修订 | 同一能力明确内容的修订。引用具体原版本时记录 `Id + Revision`；衍生结果自足，不要求父术仍存在 | 模组版本、资源组序号、每次读取时重新随机生成的内容 |
| 形体及表面 | 各自目录中的稳定字符串。现有短编号继续有效；扩展使用所属内容的明确前缀，避免占用别人的编号 | 文件扫描顺序、Unity实例编号、某次资源包中的对象地址 |
| 材料/物态 | `Matter + State` 共同决定实际规则；`water/solid` 与 `ice/solid` 是两个已保存的入口，当前伤害相同也不合并编号 | 染色、材质名、伤害枚举或材料在列表中的位置 |
| 构造节点 | 能力及修订内的声明路径；同层 `Id` 不重复。绝对根路径固定为 `root`，不取根声明的 `Id` | 展开数组下标、模型分件下标、显示对象编号 |
| 模型成员 | `形体Id + 成员类型 + 成员Id`。例如 `sword/Part/blade`、`sword/Anchor/grip` 各自定位 | 把同名挂点当作实体、把第0块网格当作跨版本的稳定部位 |
| 动作及阶段 | `形体Id + 动作Id`，阶段标记再受所属动作限定；身体末端使用已支持的 `hand.right/hand.left` | 曲线数组行号、实际帧率、屏幕朝向或另一个形体的同名动作 |
| 世界对象与拥有者 | 人物、器物、世界材料、组织及网络由所属玩法保存自己的长期身份，构造保留引用和来源 | 原版内存对象、临时ECS编号、工作线程中的数组下标 |
| 临时执行索引 | 只在当前编译计划、施放或工作批内定位，可按性能需要重新排列 | 不能写入长期定义，也不能成为读档后重新寻找旧过程的依据 |

### 局部引用语法的现状

当前[事件编译](../../Source/Core/Skills/AbilityCompiler.Activation.cs)接受：`.` 为自身，`..` 为父体，`../` 可逐级向上，`body` 为真实身体，`root` 或 `root/...` 为绝对展开路径；其他名称相对当前节点。找不到来源、越过根部、引用不提供对应事件的部位会在编译时拒绝。

子节点按挂点集合展开后，实例路径形如 `root/blade@tip_0`；同一声明路径仍为 `root/blade`。例如 `branch` 的 `tip_*` 分布是一个子声明产生三个实例，不能拿三份实例下标冒充三个长期声明。`Anchor` 的末尾 `*` 当前只匹配前缀，`When.Source` 不接受任意查询或集合表达式。

新制作的局部名称使用字母、数字、下划线及短横线；`/`、`@`、`*`、`.`、`..`、`body` 等路径或保留记号不用于新局部名。当前校验尚未对所有旧字段统一禁止这些字符，不能声称已能无歧义解析任意旧名称；统一检查和引用转换属于后续编译与选择任务，不在读取正式旧档时擅自改名。

### 过程、关联、作用及条件的具名扩展

完整框架使用**能力编号、修订、所属声明路径、资料类别、局部名**共同定位可被引用的过程、关联、作用和条件；不同类别可以同名，同一作用域同一类别不得重名。类别分别为 `process`、`relation`、`effect`、`condition`，这些是资料作用域标签，不是已经登记的操作或新的游戏开关。

当前内联资料没有独立 `ProcessId/RelationId/ConditionId` 字段，也没有跨过程输出寻址：仅能由所属节点、字段位置和固定修订中的操作顺序定位。该顺序只能用于同一份不可变资料的编译，不能当成未来跨修订的长期编号。一旦提供跨过程引用，就须增加明确局部名、输入输出和转换；重排数组不得静默把引用接到另一过程。具体字段与执行在3.03—3.04、5.13落实，本页不增加无人使用的空登记层。

关联的两端保存各自的有类型引用；来源、目标、连接、空间映射、控制与作用传递分别明确。断开连接不会自动结束已独立的过程，也不转移材料拥有权，除非相应规则明确交接。过程结束与世界后果仍遵守现有结束合同。

## 更新、缺失与正式保存

1. 资源补细节可保留编号，必须保持既有部位、挂点、动作及作用含义。重排资源数组要同步按成员Id重建索引；不能只改网格顺序而让作用绑到另一块。
2. 改变语义、删除部位或改变通配符展开结果，先判定是否改变既有构造。不能悄悄复用旧Id做另一种资源；需要新编号或明确资料转换。当前资源运行组会保留正在施放的旧引用，并不等于已经解决所有跨版本资源语义迁移。
3. 正式保存转换先处理数据再按当前规则编译。格式、原理或资源缺失时，沿用保存系统的原档保留和局部恢复报告，不按颜色、近似名称或其他操作兜成另一法术。
4. 新增字段的缺省值必须保留正式旧档含义。已实现的 `Use/Binding/Matter/State` 等缺省规则按现有编译及所属版本读取；不把新默认值直接套回原有语义。
5. 世界对象、长期材料和领域关联的保存继续使用所属区段及逐版本转换。能力编号不能代替世界对象编号；同一法术多次施放也不能共用一个可变过程状态。

## B35：复合状态及明确刷新

属性计算结果为空时，仍须执行同一声明的周期；有旧同类状态时，明确的空属性刷新也必须能清掉旧值。对于已登记周期状态，新的完整接触声明省略`Tick`表示本次周期量为零，而不是沿用前次命中遗留的量；旧共享状态调用入口仍保留原调用语义。省略属性表沿用模板，因此只有周期的诅咒会清除先前攻防覆盖。零值参数以本次完整声明为准，不延续旧回调偶然留下的作用。

每作用面的状态声明上限从8调整为16，容纳原九种接触状态共同使用，仍在编译边界拒绝超过上限的输入。状态字段、合并数字及能力资料版本不变，无新存档区段或手动迁移；正式冷启动及完整编辑、创作继续5.05 C。


## B36：恢复对象及接触余力恢复

普通`ConstructionRestoration`增加可省略的`Target`及`HealthPerForce`。恢复对象的稳定数字为`Contact=0`（实际接触人物，缺省）和`Controller=1`（该部位当前有效控制人物）；反射后沿用已有控制权交接，失效人物或对象池新身份不接受恢复。比例为有限非负量，在编译边界与固定恢复量一样检查并独立复制。即时恢复为原固定量加上“接触余力×实际传播衰减×比例”的取整结果；比例量取整为零时不触发至少一点的共享治疗规则。原固定恢复的小数规则不变。

原慈悲在七条已接管的攻击来源中转换：原本体减强只应用一次，接触后恢复当前控制人物；人物伤害倍率、屏障耐久倍率及独立效果倍率按原术基准换算，不把耐久容量当成恢复强度。爆发只在后段恢复，纯防御面无接触作用时不附带治疗。状态和恢复共用`ContactEffectMigration`，不增加整招回调或恢复更新循环。

实际恢复继续`CombatResourceEffects.RestoreHealth`：普通人物恢复生命，合法命魂恢复完整度，不据命魂身份给原主加血。原主与空间载体分离的旧来源仍由原入口处理，本批不扩充其来源接管范围。能力资料仍为版本1，无新存档区段或手动迁移；完整编辑、创作和正式冷启动继续5.05 C。
