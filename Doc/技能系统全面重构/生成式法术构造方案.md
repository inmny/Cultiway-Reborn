# 生成式法术构造方案

**状态：架构讨论稿，尚未实现。** 本方案回应“框架怎样自然构造已讨论攻击，甚至生成其他法术”。[攻击法术构想](攻击法术构想与制作要求.md) 是检验表达能力的用例，不是十三个需要分别写死的技能类。

## 核心方向

将法术定义为可组合、可变换的构造。内容制作、玩家词条与轨迹改造、规则生成共用这份描述，再生成一次完整能力。

代码职责、定义与运行状态的边界，以及模型、部位、动作和两种显示的接入方式，见[代码结构与模型接入设计](代码结构与模型接入设计.md)。

底层需要能描述形体如何形成、由什么材料组成、怎样运动和变化、与什么对象关联、在什么条件下产生作用。单纯把“生成弹丸、移动、扣血”改写成节点，仍然表达不了这批攻击。

## 六类构造要素

| 要素 | 负责什么 | 例子 |
|---|---|---|
| 形体与结构 | 骨架、表面、体积、部位、部件及其连接 | 鲸体、树枝、剑刃、炉口、镜面、兵器群 |
| 材料与物态 | 表面质感、形变、流动、凝结、燃烧或破碎的默认方式 | 水、熔金、木体、冰、雷霆、影质 |
| 运动与空间分布 | 路径、转向、排列、聚集、附着、局部空间映射 | 跃出翻转、环绕、沿根部生长、在目标表面分布 |
| 变化过程 | 生长、聚形、压缩、分裂、解体、侵蚀、转化及回收 | 残兵聚成巨剑、冰层开裂、水体散为奔流 |
| 关联 | 本体与副本、部位与挂点、来源与结果、两个空间或过程之间的联系 | 镜中映像对应真身、影身跟随目标、门户两端 |
| 作用与条件 | 伤害、推力、束缚、转化、过程改变及实际触发条件 | 接触后压碎、闭合时切割、裂击映像后向本体传递作用 |

“构造操作”是可复用的执行能力，例如构形、分布、附着、聚合、解体、流散、映照、转化、施加作用。每个操作明确输入、输出、可改变的数据及所需资源。操作实现不能只留下一个名字，必须接通相应玩法和表现。

形体具有可寻址的部位，如鲸腹、尾鳍、树根、剑刃、炉口和镜面。操作可以作用于整个形体、某个部位、部件集合或一次生成过程，扩大组合空间。

## 结构可以嵌套，操作可以递进

构造不是固定的“形体栏选一个、材料栏选一个”。一个结构可以包含其他构造：树的末梢长出剑片，剑片由冰凝成，剑片内部又保留裂解过程。子结构有自己的材料、部位和运动，并继承父结构的必要位置、速度与来源。

同一操作应能接受符合要求的不同输入。例如“分布”可以把剑片放在树枝末梢、鲸体表面或旋转球壳上；“解体”解除实际连接，让脱落部分继承运动；“生长”沿结构推进，同时建立新的可作用部位。它们不必认识“剑树”“剑鲸”这些技能名称。

递进变化保留来路：聚合输出的结构可以继续形变、分裂或被映照；映照得到的关联对象可以继续被施加作用；变化产生的残留也可参与后续过程。施放者、来源材料、部位对应与实际结果随过程传递，不能每到一个阶段就重置成无来源的新特效。

结构层级、部件数量和递进深度在编译及执行时有预算。远景可合并显示，实际需要独立交互的部件才成为独立执行对象，不要求每片叶子都有完整模拟。

## 三种攻击怎样构造

以下是结构示意，不是已实现的脚本语法。

### 天鲸覆城

- 选取鲸形结构，以水材质凝形，放在目标下方。
- 将起跃、翻转和覆压运动绑定到形体的骨架与重心。
- 起跃阶段的实际接触产生托举，压落阶段产生撞击。
- 接触地面或完成压落后，鲸体解体，剩余水量进入流散过程。
- 流散继续影响真实覆盖区域，并产生对应碎沫、奔流与残留。

其中鲸形是资源，凝形、运动、接触作用、解体和流散是通用操作。换用不同的形体、材料、运动和结束方式，可以产生其他攻击，而不新增整套鲸类技能代码。

### 剑冢开天

- 选择或生成残兵部件，分布在地面或指定空间。
- 沿目标巨剑的结构聚集部件，建立可解开的连接。
- 整体按斩落运动推进，刃部承担实际攻击。
- 接触或受力达到设定条件时解除部分连接。
- 脱落部件继承对应运动，分别产生作用并进入落地或消散。

聚集成形可用于兵器、岩块、骨片等；连接与解体也可用于木甲、拼合巨像、分裂护持。具体输入决定外形和材料变化。

### 镜中碎身

- 取得目标形体或表面的对应映像，将它放入镜面空间。
- 建立映像与本体的关联，明确哪些作用可以传递。
- 向映像施加裂解过程，镜内裂纹按实际进度发展。
- 将允许传递的裂击作用映射到本体，真实结果再反馈到两端表现。
- 结束关联并收束碎影。

映像、关联和裂解分别可用。将裂解替换为生长、冻结或压缩，可构造新的间接攻击；是否产生对应伤害、形变或状态，由明确的作用定义决定，不凭显示变化自动推断。

## 生成新的法术

| 改变构造 | 可产生的新攻击方向 |
|---|---|
| 鲸形由水改为熔金，压落后采用凝壳与碎裂 | 熔金巨鲸跃落，落点形成炽热硬壳，随后裂成滚落金片 |
| 树形的叶片和末梢分布剑形部件，根群向上、树冠向下生长 | 倒悬剑树逐渐成形，枝体合拢时剑叶沿生长方向刺入 |
| 将镜内裂解改为镜内生长，并把允许的生长作用传向本体 | 镜中先长出枝体，现实目标随后出现对应缠绕和根刺 |
| 将兵器聚合结构改为旋转球壳，再压缩和定向解体 | 万兵聚成转动的金属天体，裂开后沿不同方向释放刃片 |
| 将材料侵蚀作用附着到目标所经过的位置 | 路径上留下短期侵蚀痕迹，后续经过的兵器或对象受影响 |
| 将同一生长过程作用于甲片、地面或区域节点 | 分别形成寄生木甲、地面根刺或连片生长的根网 |

这些是单个法术的构造变体，不是几个成品技能顺序释放。新攻击应主要通过数据描述、资源和共用操作产生。遇到新的原理，扩充一个可复用操作；遇到新的造型，扩充形体资源，随后可参与其他构造。

## 自然构造需要规则补全

播放器不能只照抄零散参数。构造器需要依据所选要素补齐必要过程：

1. 近身作用加入追踪时，补上离手载体、目标、运动和释放动作。
2. 凝成流体形体时，绑定对应表面流向、形变和终止后的流散规则。
3. 改为金属等材料时，更新表面、体块和默认破碎方式；若另外选择流化，则采用相应物态，而不因“金属”固定禁止流动。
4. 复制或分布结构时，同步产生实际执行体、成本、作用区与显示布局。
5. 改变时间、空间或关联时，修改相关过程和作用位置，保持来源、目标及结束关系明确。

默认规则用于补齐，不取代玩家明确选择。多个改造的先后和覆盖顺序要固定；如果缺少部位、资源或必要能力，给出具体缺失项。

例如“在倒生树的末梢生成冰剑，遇到接触后脱落”可以按以下方式展开：

1. 找到树体的末梢部位，绑定剑形子结构及冰的材料状态。
2. 将子结构的成形进度接到对应枝条的生长进度，朝向跟随末梢方向。
3. 依据剑形的刃部建立作用形状，而不是复制整个树冠的范围。
4. 接触结果满足条件时解除该子结构连接，继承当时速度，并切换为独立运动。
5. 冰剑碎裂时使用已有碎裂过程；树枝仍继续执行自己的生长或收拢。

这里补齐的是有明确输入与结果的连接规则，不靠技能名称猜测。共同规则先展开，玩家明确改造再按固定优先次序覆盖；无法满足的结构要在创建时指出，不拖到战斗中临时猜测。

规则生成的输入可以是内容定义，也可以是玩家的改造结果。战斗中修士直接自主释放已生成、已编译的能力，不需要临时调用语言模型，也不需要玩家编排节点或多招连招。

## 变化依据状态与结果继续

构造描述同时包含过程和条件，不能全部退回固定秒数的动画时间表。起跃可以由动作推动，压落由实际位置推进；接触地面、结构破裂、材料冻结或维持来源失效，再触发相应变化。只有纯装饰才可以独立按寿命消失。

交互规则读取实际性质和状态。例如某段水体满足冻结条件，可以转为冰态，继承原有形体和运动，再按冰态的规则继续；某块聚合兵器被击断连接，脱落的是对应部件。这些规则服务于所有具备相应性质的构造，不为每对技能单写分支。

规则必须明确适用对象、触发条件、改变内容和消耗，新增反应逐项验证；材料名称本身不自动赋予全部现实物理。时间、空间、灵魂等特殊作用由对应玩法明确实现，也可参与构造。

## 灵活和精致共同依赖资源合同

形体资源应是可变化、可驱动的基础形体，而非整招录像。鲸体提供骨架、控制点、部位、表面坐标和可用动作；树体提供主干与分枝结构；剑与炉器提供可调轮廓和能力出入口。

材料资源负责局部明暗、纹理、透明、物态和变化方式。动作资源提供连续姿态与约束，按距离、速度、尺度和接触状态调整；分布、聚形和破碎读取真实部件结构。

生成规则还要维持主次、尺度和运动的可读性。强度、数量和材料可以变化，但形体应保持完整，次生效果与装饰有层次。已有制作工具需完整导出这些信息，不能只导出顶点和颜色。

有限的资源和操作不会自动表达所有未知原理。开放性体现在能持续加入新的共用能力，并让新能力与已有构造结合；具体新组合的画面仍要实际检查。

## 实际作用与显示如何一致

构造产物同时提供逻辑对象、可作用部位、控制结构和显示资料。骨架、控制点、路径及生长进度共同驱动模型与作用区。

例如水鲸的腹部下压，实际作用区域就随同一腹部控制结构下压；树根生长到哪里，哪里才启用抓持或穿刺；镜内裂纹通过关联产生作用时，两端读取同一结果。

精确程度可按尺度选择简化形状，不要求每片装饰都参与碰撞。简化规则要保证主体与有效区域能互相解释，不能重新让复杂鲸体只剩中心一个无关球形判定。

原版和 Worldfall 消费相同的构造状态及资源含义，分别完成材质、空间和遮挡绘制。两端均是实际验证的一部分。

## 执行、性能与资料

- 创建或编辑时展开生成描述、补齐规则、校验引用与关系，再编译为紧凑执行数据；战斗中不逐帧解释整份构造。
- 按操作种类批量计算，同类生长、运动和作用区更新可以跨多个法术一起处理；游戏对象变化有序提交。
- 形体与材料共用资源、可变实例单独保存状态；部件分布使用实例数据，避免每帧复制全部几何。
- 接触、地形过程、世界条件按自身语义选择更新方式，共用时间与真实结果。
- 关联和重复过程需要明确次数、持续与去重规则，避免同一作用在镜像或反射关系中无限往返放大。
- 存档保存生成描述、稳定编号、必要种子与真实长效结果；编译缓存、绘制句柄和工作线程状态不入档，旧资料经版本转换接入。

## 怎样判断框架真的灵活

第一轮至少满足：

- 同一套资源与操作能生成原始攻击和两种结构或行为明显不同的变体。
- 至少一种变体在共用操作和资源冻结后才提出，再通过改描述生成，检查是否仍偷偷依赖预先写好的整招分支。
- 变体通过修改描述、规则参数或资源产生，无需新增对应的完整技能类，也不按技能编号追加每帧判断。
- 材料改变后有对应的表面与变化过程；运动、作用和收尾仍连贯。
- 至少验证一种间接关联作用及一种无投射物的功能或世界过程。
- 原版与 Worldfall 的关键画面、实际作用和改造结果一致。
- 记录生成与编译成本、稳态执行开销及资源复用情况，性能结论以实测为准。

这比先写完十三个独立技能更能检验重构方向。具体的操作划分、资源格式和规则补全范围仍需通过小规模实现收敛。
