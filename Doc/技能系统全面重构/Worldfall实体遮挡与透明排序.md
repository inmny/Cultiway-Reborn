# Worldfall实体遮挡与透明排序

本批完成全程TODO的1.06，并处理1.07、1.08和13.10中的部分问题。没有修改技能作用、支付和存档格式。

## 问题与接入方式

原实现把金属、木材、皮肤等实体与水、冰一起提交到Worldfall前景颜色层。该层虽然读取场景深度，但没有更新场景资料。后处理仍用后方树木、人物或地形的深度及类别处理实体覆盖的像素，因而会出现剑身上浮出后方树木轮廓的现象。

当前接入直接使用发布的网格、表面坐标、蒙皮及实例属性，保留本模组的表面着色，不再转换成外部面色槽：

| 内容 | 实际提交位置 | 写入内容 |
|---|---|---|
| 不透明部件 | `GpuSprites.DrawSolid`之前；场景颜色及资料目标仍绑定 | 颜色、真实硬件深度、观察深度、普通模型类别 |
| 水、冰、泡沫及实例半透明色 | `GpuRenderer.FlareOpen`之前；前景颜色与共同场景深度绑定 | 从远到近叠加颜色，读取实体深度，不写深度 |
| 原版观察 | 原有投影通道 | 禁用两个Worldfall专用通道，避免重复提交 |

实体资料采用核对过的外部约定：普通模型类别3、无人物拾取编号0、无独立光晕0。观察深度按实际普通／透视／陡视相机规则计算，不用贴图像素位置代替世界距离。

透明排序使用完成姿态的部件边界中心；普通观察使用该次收集的平面前方，透视和独立视眼读取绘制器当前实际相机。相同深度保留发布顺序。显式实例颜色的透明度也决定分层，不仅根据材料名称猜测。两个列表重复使用，切世界清空，并保持所属资源版本引用，避免重载后提前销毁网格或材质。

## 检查及复现

`Scripts/SpellDemos/verify_surface_depth.script`在游戏真实图形设备上创建独立绘制缓冲，检查实体双目标输出、实体遮挡、透明读取共用深度、透明不写深度、实际接入分层、前后排序、独立视眼反转及清理。它不推进世界、不修改地形、不制造伤害。

```bash
dotnet ../DebugToolbox/Client/bin/Debug/net10.0/DebugToolbox.Client.dll run Scripts/SpellDemos/verify_surface_depth.script 60000
```

12项检查通过。实测设备NVIDIA GeForce RTX 3050 Ti Laptop GPU，Linux OpenGLCore。场景资料实际读回为`[10,0,3,0]`；近处实体挡住后提交的远实体与透明体；两个半透明层实际叠加透明度为0.75。检查报告在`artifacts/skill_rebuild/surface-depth/checks.json`。

三平台资源包重新构建，Linux游戏经NML实际编译加载；Windows和macOS只完成离线构建，不等同于当地游戏验证。开发构建0错误、16项已有警告。

## 本批边界

- 排序针对本模组共同形体的透明部件。交叉或互相包裹的透明曲面仍可能需要进一步处理，尚未与Worldfall所有透明精灵、天气及粒子共同排序。
- 没有改动Worldfall全局像素化、抖动、灯光或风格参数；原模组的像素表现仍然存在。
- 普通模型类别及观察深度解决当前轮廓与雾效资料错配，不代表完整接入其阴影、受灯、拾取或自发光。
- 冰水辨识、木纹尺度、材质细节、薄层边缘、原版投影遮挡及近裁剪等仍在对应待办中。
- 大剑只是遮挡检查几何，没有将展示场景称为战斗功能或最终美术验收。
