# 共用形体发布格式与绘制选择

本页落实全程TODO的1.12，记录当前已经运行验证的资源与绘制路线。后续制作沿用这一条链路；新增语义或效果时扩展共同资料和表面，不为每招另建播放框架。玩法完整性与美术质量继续按各自任务验收。

## 制作与发布格式

采用现有Three.js制作源输出JSON，再由Unity离线构建发布网格与资源包。当前不在游戏中引入通用模型导入器。

| 环节 | 已采用的内容 | 实际入口 |
|---|---|---|
| 制作 | 顶点、法线、表面坐标、分区、控制点、四项权重、挂点、作用形状和动作取样 | `Scripts/CombatModelStudio/forms.mjs` |
| 离线交换 | 可读取的JSON制作资料，顶点和控制资料保留原三轴 | `artifacts/skill_rebuild/form_sources/`，生成产物不进发布包 |
| 发布说明 | 第3版形体说明：稳定编号、语义部位、连接、生成输入、变化声明、网格、表面、挂点、作用绑定、控制骨架与动作 | `Content/Forms/`、`FormDescription`及[结构索引](版本化形体说明与结构索引.md) |
| 发布几何 | 网格位置、法线、三角形，表面坐标通道0、控制索引1、权重2、厚度及泡沫3 | Unity形体资源包 |
| 纹理和着色 | 共用细节纹理、自定义表面；实际材料与仅显示染色分开 | `FormSurface.shader`、`FormResource.Surface` |
| 平台构建 | Linux、Windows、macOS分别构建，游戏按实际平台读取 | `Scripts/ShaderBuild/build_forms.sh`与`BuildFormBundles.cs.txt` |
| 运行计算 | 加载时把命名绑定解析为索引，采集纯数值几何和姿态资料 | `FormRig`、`FormContactBinding`等共同计算资料 |
| 运行显示 | 发布同一完成姿态，显示不推进作用或动画时钟 | `FormVisualScene`及各视角绘制入口 |

制作与逻辑均使用地图横向、纵深、高度三轴。运行状态以共同绝对高度表示；原版显示减去同一地表后投影，Worldfall直接使用绝对三维位置。动态浅层曲面来自实际流散状态，仍通过同一发布入口和表面显示，不另造一套视觉水量。

资源以完整版本加载，旧施放保持所属资源引用，新施放使用新版本；失去引用后在主线程释放。资源对象和编译缓存不直接进入正式世界存档。当前说明版本只接受已经支持的格式，未知版本或缺失网格、坐标、权重和作用绑定会在加载边界给出具体原因。

## 两种显示的选定路线

| 视角 | 采用路线 | 依据与限制 |
|---|---|---|
| 原版 | 共同三维姿态投影到原版空间，使用独立表面材质和排序 | 已有身体、曲面、厚薄和动作录像；完整交叉遮挡、透明排序及近裁剪继续验证 |
| Worldfall | 直接提交共同网格及实例属性，使用它实际的视点、地面和深度 | 实体写场景双目标，透明体按视眼排序并读取共同深度；保留纹理、骨架及自定义表面 |

不再把这些形体转换为外部面色槽：该转换不能保留当前使用的表面坐标、局部透明、厚度和自定义表面。也不依赖普通Unity场景中的MeshRenderer自动进入Worldfall，它有独立收集、命令和后处理过程。

实体不能只覆盖前景颜色而沿用后方场景资料；已经用高遮挡体实机验证并修正该路线。资源重载也不能原地改写正在使用的共享网格和材质，当前按版本保持和释放。
