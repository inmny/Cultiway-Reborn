## 具体说明

### 确定能力用途和尺度

以 [能力版图与尺度设计](能力版图与尺度设计.md) 的创意检查实际需求。每项说明它在生活、生产、探索、修炼、交通、救灾或战斗中有什么真实用途。

个人、局部、城市和世界的差别包括对象、传播、持续、维护、关系和后果，不只包括半径。顶尖修士可以发动天地变化，也可以精细处理单个对象。阵法、法宝和多人仪式提供其他承载方式，不预先作为世界级能力的唯一来源。

创意储备需要进一步选定具体制作项；首批不等于全部内容，但必须覆盖不同用途与运行尺度，防止基础结构再次只适合攻击。

[攻击法术构想](攻击法术构想与制作要求.md)用于检验复杂意象；[生成式法术构造方案](生成式法术构造方案.md)用于检验是否能复用形体、材料、变化与关联产生其他能力。共用合同不能以列全十三个技能类作为完成。

### 明确作用过程与资料归属

控制、维持、借用、长期事实与各种结束方式的具体合同见[控制归属与结束合同](控制归属与结束合同.md)。该合同不等于对应运行和迁移已经完成。

每项能力至少回答：

| 内容 | 必须说明 |
|---|---|
| 来源 | 谁施展、由什么物件或设施维持，来源消失后会怎样 |
| 对象与联系 | 作用于人物、器物、地块、过程、区域、网络或世界条件；是否产生新联系 |
| 真实改变 | 改了什么，哪些对象受到何种作用，怎样判断成功 |
| 发生与维持 | 瞬时、分段传播、持续、条件触发、永久结果分别怎样运行 |
| 形状与尺度 | 接触体、路径、区域、连接拓扑或世界范围怎样表达 |
| 改造 | 词条、轨迹、目标和条件改变后，需要同步改变什么 |
| 使用入口 | 战斗、工作、旅行、修炼、救灾、维护或玩家使用怎样触发 |
| 表现 | 启动、传播、局部响应、整体变化、收束与残留怎样读懂 |
| 世界归属 | 哪个玩法维护事实、保存进度与条件，怎样避免重复修改和保存 |
| 结束与后果 | 完成、解除、中断、维持失效后，哪些结果继续存在 |

通用能力层编排执行、目标、过程和结果；地形、空间、生态、生产、信息等玩法负责自己的事实和规则。新增想法需要对应玩法时，应允许新增或重构模块，不因现有代码缺少它就从想象范围排除。

### 用不同能力检验同一合同

首批合同验证建议包含以下情况，具体内容在接口核对后收敛：

| 验证项 | 核心问题 |
|---|---|
| 掌击改追踪飞掌 | 一次近身作用能否跨形态，动作、运动、判定与表现一致 |
| 同一资源与操作生成不同构造 | 嵌套部位、材料和变化能否重组，未预先写好的变体能否主要通过资料生成 |
| 修士自主创法 | 游戏内生成的新构造能否成为正式能力，学习、自主使用、改造、保存和恢复是否使用同一份资料 |
| 塑石修桥或其他可用结构 | 能否真实改变生活和通行，施法结束后结果继续可用 |
| 引水或地域改造过程 | 能否分区推进，画面对应已完成部分，城市需求得到实际收益 |
| 天地灵流等世界条件 | 能否作用于整图范围的实际过程，登记与维护不靠每帧遍历全部对象 |
| 门户、收纳或类似持久联系 | 能否表达连接和对象归属，并由对应玩法正确保存与恢复 |

世界条件可先核对现有灵气或地形入口，选择可实测的内容；这不等于已经拥有完整气候、洞天或世界回溯。关系和过程也不能仅在资料中有字段，最后仍被编译成攻击实体。

通过条件是上述需求在数据、调用和保存上有明确可行路径，再进入资源制作与运行实现。实际功能、资源质量和性能继续由后续阶段验证，不以纸面类型齐全作为完成。

## 资源说明

| 资料或资源 | 设计要求 |
|---|---|
| 能力用途表 | 功能、战斗、对象、尺度与实际后果明确 |
| 过程示意 | 个人接触、地域传播、设施维持和世界条件各有完整过程 |
| 关系示意 | 入口与出口、收纳对象、网络节点和维护来源可定位 |
| 原型资源设计 | 精细小术、局部动作、城市结构和世界现象分别定义轮廓与运动 |
| 保存与恢复说明 | 长期世界事实、维护条件和进度有唯一负责方 |
