# 9.28 剑冢开天

整项交付条件：剑冢的残柄、刃片先从地表起出，沿真实布局合成有厚脊、明刃和断口的巨剑；整体完成一次蓄势重斩，外层片体从斩势中脱落，保留脱离点的实际运动并清楚落地或收回。至少一份结构改造能保存重开。原版和 Worldfall 各有覆盖整个过程的常速实机录像。全部验证后才勾选并合并推送 `codex/dev`。

| 分段 | 需要改变的玩法和画面 | 必要验证 |
| --- | --- | --- |
| A · 起兵、合刃与重斩 | 从实际可用的模型部件组成盾外可读的残兵。先起出再扣合；脊与刃有厚度，落斩有蓄势、刃面扫过和止势。起兵和聚合期无攻击；接触跟随实体位置。 | 复用现有平地、施放者和靶子。核对部件起出、向布局收拢、固定接缝；正式一次收费，在落斩窗内命中而外侧不受伤，收尾后再次受理。 |
| B · 脱片、破坏与回落 | 外刃在实际交锋或条件发生后脱开，继承自己脱离点的速度和朝向。片体和主剑用同一个接触组与有限作用量；未扣合部分遇中断直接落下，没有攻击。 | 同一场地验证真实盾拦与合刃前来源失效。核对脱片再接触、共有目标只结算一次、剩余量没有增加，并检查落稳、结束和重放。 |
| C · 重组与交付 | 共用规则定稳后制作一份改变聚合布局、斩向或脱片走向的完整变体，用明确的材料和碎解规则表现差异；保存后仍是可编辑结构。 | 复用同一人物和世界验证原招及变体，存档重开核对原资料和变体。集中录制两个视角，记录原构造、变体、代码、录像和复验入口。 |

首个构造使用随施放生成的可分件金属，不取走世界里的装饰残兵或真实装备。以后用实际库存残兵替换时，仍需要已有的库存输入和归还约定。第一段不扩身体、装备和世界样本；已验证过的共用规则只在本招确实影响它时补测。

## A · 起兵、合刃与重斩

[可编辑构造](构造输入/剑冢开天.json)由厚脊和两块有不同断口的外刃构成。两片先各自抬起，再等本片的抬升完成，沿同一个随剑身转动的接缝扣合。铁刃是有侧面的实体，铜脊、护手和扣件保持自己的材质。三处攻击都读取对应实体的外沿、厚度和当前姿态；铜饰不会扩大伤害。蓄势和扣合时没有有效攻击面，落斩窗结束即撤去作用，再沉回地表。

实机中，两片刃扣合后与主脊共用接缝。两只正面的靶分别在第 1.89 秒左右和第 1.90 秒左右扣血各一次，外侧不受伤。每次正式施放只支付一份真元，自然结束后没有残留部位，再施放也正常结束。前两次失败分别保留：首次资料漏写接缝名；第二次脚本把所有目标的累计编号看成单个目标的次数，同一脚本的 `finish` 段已修正。实现过程中对照原版截图，修正了剑身材料盖住铜饰的问题。实机截图、核对结果和失败记录索引：`~/.local/state/cultiway-dev/evidence/sword-grave-928/progress-a.json`。

## B · 脱片、破坏与回落

主剑实际确认接触后，右刃沿自己当时的姿态和点速度脱离；铜扣一起落下但没有伤害。脱片前的预留部位不占有额外作用量，脱片只移交原右刃的余量，仍沿用巨剑的接触组。顺带修复了带名称的原条件操作无法正式登记的问题：创法比较按原声明位置取条件，不再把步骤编号当成独立操作的标记。

实机中，主剑在约 1.89 秒触发脱片，碎刃在约 1.93 秒独立打掉侧靶 22 点生命，正面目标也只受伤一次。脱片前后总余力均为 98.56，断开姿态没有跳变；实刃约到第 2 秒已落稳，随后撤去，能够再次施放。强盾在约 1.77 秒耗尽主剑，受保护的靶没有受伤。各段证据和失败记录见 `~/.local/state/cultiway-dev/evidence/sword-grave-928/progress-b.json`。

来源在约 0.65 秒死亡时，两块外刃从各自的实际位置下落，贴地停稳后清理，未形成攻击碎片或新增伤害。构造中的 `InterruptFall` 只保留部位的最后可见形状和材质；落物沿用已有的下落与地面停止规则，不继承力量、材料份额或控制关系，也不改变攻击范围和费用。缺省仍直接结束，旧资料无需手动迁移。普通施放和强盾拦截仍走原来的结算路径。

## C · 逆锋与交付

[逆锋](构造输入/剑冢开天·逆锋.json)把远处的左刃留到右刃扣合后才汇入。实机在 0.95 秒时，原招左刃距接缝约 0.20 格，逆锋的左刃仍距约 3.58 格；两者都在重斩前扣合。原招让右侧铁刃飞落，逆锋让左侧金刃脱开，并采用不同的飞散速度、旋转和下落。世界保存再打开后，两份完整构造、派生关系和人物学会的招式均保留；仍可改逆锋的碎解重力，原招保持原样。

原版与 Worldfall 各录 3.42 秒的连续实机画面，同一镜头内覆盖残兵抬升、巨剑扣合、主剑命中、侧靶吃到碎刃及落稳清场。这两段录的是正常施放；中断落地另有实机截图和数值记录。最终复验按段通过。录像、正式存档、失败记录和构建报告见 `~/.local/state/cultiway-dev/evidence/sword-grave-928/delivery.json`；复验入口为 `Scripts/SpellDemos/verify_sword_grave.py`。
