## A的接口与必要验证

子结构可选`Distribution`，与旧`Anchor`互斥。选择来源为父形体挂点或父模型空间中的命名点；命名点可由其他制作或构造过程提供，不绑定某个技能。共同规则按候选次序先跳过`First`个，再每隔`Every`个取一份，最多`Maximum`份。挂点按资源原顺序，明确点按作者原顺序，资源重载时由完整计划版本隔离；原定义不写入本次运行对象。

## A交付：集合选择与真实完整子树

`ConstructionNode.Distribution`已接入同一嵌套编译。`Source=Anchors`（数值0）读取父资源的挂点，`Selectors`可合并明确名称及末尾前缀，按父资源原顺序去重；`Source=Points`（数值1）读取父模型空间中的`Points`，每点含稳定`Id`、`Position`与非零`Direction`，后者缺省沿正纵轴。两类输入共同使用`First`、`Every`、`Maximum`，根部和旧`Anchor`不能同时指定这一分布。明确点属于父模型空间，不冒充跟随某一蒙皮表面；实际部位和表面绑定继续B。

以下是取挂点并集后每隔一个取一份、最多两份的普通子结构字段，不是新增整招或专用执行类型：

```json
"Distribution": {
  "Source": 0,
  "Selectors": ["tip_*", "tip_0"],
  "First": 0,
  "Every": 2,
  "Maximum": 2
}
```

原挂点名称及星号资料含义不变，挂点控制和成形门槛继续原通道。每份子树实际展开，声明路径如`root/blade`，挂点实例如`root/blade@tip_0`，明确点实例如`root/blade@point.left`，不以数组下标替代稳定名称。公共计划只保留已解析位置、方向及绑定资料，修改原集合不会改变已开始施放；没有新逐帧选点、绘制或碰撞执行器。
