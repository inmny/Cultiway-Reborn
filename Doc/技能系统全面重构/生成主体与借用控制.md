# 生成主体与借用控制

对应4.03。生成主体归本次施放管理，借用法宝、身体部位及原装备只取得临时控制。两者在实际运行中有明确身份和释放入口，不按显示对象是否消失来猜测原物应该如何处理。

## 接入方式

| 实际来源 | 取得与运行 | 结束处理 |
|---|---|---|
| 共同构造的生成形体 | 运行实例拥有数值主体及本次显示资料，已有实际作用和回收记录继续使用原规则 | 结束移除本次实例及显示，不把来源人物或原装备当作生成物删除 |
| 剑阵等实际新建实体 | `TryBindSpawnedBody`同时登记生成所有权、关系用途和当前控制者 | 仅当前拥有者可以把该实体交给统一回收 |
| 飞剑借用法宝原物 | `TryBorrowBody`取得原法宝实体；显示、轨迹及实际作用仍读取这个本体 | 召回或结束只解除本次关系和控制，保留法宝及库存归属 |
| 共同身体动作及持剑 | `BodyControlLease`记录这次取得的实际身体部位；持剑仍引用人物原有的同一个装备对象 | 收势、取消或未受理失败释放这次凭据，不销毁身体或原装备 |

生成和借用实体共用现有的执行关系。生成实体也登记控制者，避免另一施放借走临时实体后，旧执行仍按生成物删除它。已有借用关系不能再改为生成所有权；结束、待回收的施放及真正的预制原型不能取得主体。新实例的预制标签可能在帧末才移除，按实际资产原型身份区分，避免误拒绝刚生成的飞剑或剑阵剑影。

## 取得与释放时点

飞剑在改变法宝的世界状态之前取得控制。争用失败不改写原法宝的显示、位置或运行设置；取得后若初始化抛错，保留原错误，立即释放本次关系，再通过统一回收移除未完成的执行体。

共同实体生成入口的初始化失败也调用相同释放函数，再把未完成的执行体交给统一回收。新实例的帧末命令完成之前保持其实体身份，避免回放访问已删除的实体。该函数移除本次登记的关系，只对仍由自己控制的生成物标记回收；借用原物始终保留。回收系统先收集待结束执行体，再在实体遍历之外修改关系和控制组件。

身体部位的占用由每次取得的独立凭据释放。重复释放、已归还动作的旧引用、或世界切换前留下的凭据，都无法释放后来取得同一部位的另一动作。主线程取得及释放控制，其他线程只读取已经发布的不可变凭据数组，不访问人物或实体。

## 资料与后续工作

控制凭据、执行体关系和人物对象仅在运行时存在，没有新增长期保存字段。现有身体构造及法宝定义继续提供实际动作和来源；本次不复制原物作为长期替身。

4.04继续处理全身、局部动作、离手能力和独立法宝之间的并行选择；4.05继续完善阶段与跨步标记；4.11、4.12负责长期来源失效和不同结果的结束规则。完整能力内容迁移及画面验收仍按各自工作包推进。
