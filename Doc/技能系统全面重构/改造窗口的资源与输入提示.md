# 改造窗口的资源与输入提示（8.10）

本项完成条件：

- 万法阁沿用公共搜索、选项、滚动和弹层。人物、资源和部位选择共用这套入口；没有可选项时，说明当前缺少哪种输入。常用操作、空列表与本项新增错误均有中英文文案。
- 资源引用失败时，显示失败的资源种类、名称和可修的声明位置。预览无法开始时分别说明缺施法者、目标不符、超出距离、缺身体资料或没有可用法宝。只判断已有规则，不新增可用条件，也不把程序异常当成缺资源。
- 复用一个已有构造和测试世界：先从公共搜索选择目标或资源，再验证一处真实资源缺失和一处输入缺失，修复或重选后恢复正常。保留复验入口和中英文证据。窗口极端布局和反复开关集中到 8.12，身体与装备资料补齐归 8.14。

## 交付与复验

资源检查在原编译位置保留种类、原编号和声明路径，窗口用这些资料拼出中英文提示。形体缺失时，改造页仍保留更换形体的入口，可用原编号或显示名搜索。预览的人物目录使用正式施放的目标关系；缺施法者、未选目标、目标不可用、越界、缺身体资料、部位条件不符和缺可用法宝各自提示。没有可用候选与搜索不到匹配项使用不同提示，仍沿用公共弹层和滚动区。

实机复用 8.09 的世界和水剑，改为必须明确选人。未选目标时只有提示，不出现空白的预览画布。搜索无结果时显示通用提示，选中实际目标后恢复播放。另用同一份草稿故意引用不存在的形体，核对中英文中相同的编号和 `root/Form` 路径；点击定位后从形体目录换回原件，保留材料、选人规则和其余参数，窗口恢复可编译和正常关闭。

复验：启动独立 WorldBox 后运行 `dev.py exec --timeout 210 -- python3 Scripts/SpellDemos/verify_compiled_use.py --section diagnostics`。原版窗口、软件渲染，本项只验输入提示和修复，不重复前项的伤害与范围检查。结果及三张截图位于 `~/.local/state/cultiway-dev/evidence/editor-inputs-810/`；首次没有等公共菜单布局结束的失败现场保存在 `first-attempt/`。重新运行使用同一场景并等待菜单显示后读取实际文字。
