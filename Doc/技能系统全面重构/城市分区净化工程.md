# 城市分区净化工程（11.14）

## 完成条件

- 常规净化发现同一座城内两个以上有实际污染、能够单独施法处理的分区时，生成同一工程的有序分区。沿用原版城市规划、成员认领、站位、正式施放、各次付费和世界验收。应急净化继续使用原请求。
- 主节点是当时真实存在的城市篝火，分区节点是实际有污染的地块。只按现有城市分区选择相连路线。当前分区的地块归属、来源和连接在施法前及实际接触时核对，当前这一步失去连接就等待。重新接通后只做未验收的部分。
- 一个分区实际净化并通过世界验收后，记录完成和下一分区。旧轮次不能确认新轮次，也不会覆盖已完成部分。原篝火失效时终止待做部分，已完成的净化保留。同一工程全部分区完成后才写整项完成历史。
- 使用 11.03 的原城、已有修士和已验证净土实际入口。实机只准备两个需要净化的合法分区，核对两次实际扣费、第一次验收后断开、恢复连接、最后完成。正式在中断点保存并读回，确认源节点、已完成序号、未完成目标与实际地块都保留。大型传播和宏观录像由后续编号负责。

## 接入

常规净化先用同一套已学法术评价各污染地点。至少两个实际分区能独立处理时，冻结当时的篝火、污染节点及途经的本城分区。先处理近处，再按地块编号保持顺序。没有可组成的分区时，原单项净化继续提交。每轮仍以本轮实际施放、地块足迹和污染降幅验收。

工程队列在各轮之间保有同一个工程编号。下一轮重新检查原范围归属和途中分区，只有实际行动时允许接触本轮分区。失去连接时待做阶段留在计划中；原篝火失效时终止。已经实际发生并确认的净化不会被后续计划扫描覆盖。完成序号和路线放在已有的城市工程存档内，每轮认领和执行凭据由当前进程分配。

## 原版实机

原城 1、原工人 56 和真实篝火 229 共同执行工程 5。第一轮只净化地块 9788，第二个分区的地块 9804 仍有污染。确认第一轮的真实作用后，通过原版城市接口取下中间分区 9796，工程保留已验收一处的状态。待做地块仍归原城，连接缺失期间没有第二轮施放。原篝火真实移除后，未完成部分终止，已净化地块保持。

在断开的状态正式保存并读回后，用原版重新加入中间分区。同一个工程通过实际工作入口继续，第二轮只净化地块 9804。两次各扣 3 法力，由原上限 100 变成 97。原轮次编号 1 尝试提前确认时被拒绝，轮次 3 经实际世界验证后完成，整项历史只记一次。首次跨档复验暴露了旧轮次编号复用，修正后按原世界和同一路径通过。
