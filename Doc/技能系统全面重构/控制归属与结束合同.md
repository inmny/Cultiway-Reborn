# 控制归属与结束合同

本页落实总表0.07与0.08的设计约定。它规定后续实现和迁移应遵守的行为；运行、长期保存和全部来源接入仍由4、10、11、12等工作包分别验证。当前代码已覆盖实际身体借用、部分器物借用、临时生成形体和逐部位反射，尚未覆盖本页全部情况。

## 必须分清的身份

| 身份 | 含义与边界 |
|---|---|
| 构造作者 | 谁创造这份法术说明，用于知识和传承；不自动成为每次施放的攻击者 |
| 最初施放者 | 谁实际启动这一次能力；反射、转手和来源死亡都不改写该记录 |
| 当前控制者 | 现在谁能改变这一部位或过程的运行，并决定当前敌我与作用归属 |
| 资源提供者 | 本次资源由人物、器物储备、设施或已实现的其他来源支付；不能因反射再扣原攻击资源 |
| 维持来源 | 过程继续存在所需的人物、物件、设施或条件；与最初施放者分别记录 |
| 事实维护者 | 真正修改及保存器物、身体、地形、状态、网络或工程的玩法；技能只提交明确请求并读取确认结果 |

当前控制者按部位或独立过程记录。仍连接的从属部位随控制交接，已脱离的兄弟分支不随整招转手。反射保留最初来源、同一次施放、已经消费的总预算及剩余作用量，并改变当前归属及必要的追踪目标。

人物和物件均使用稳定编号。运行中的对象引用必须核对编号，不能把对象池里的新人物当成旧控制者。跨存档只保存编号和需要延续的事实，不保存游戏对象引用、编译计划或显示对象。

## 四类主体分别由谁维护

| 主体 | 技能取得什么 | 谁维护真实归属 | 结束时发生什么 |
|---|---|---|---|
| 本次生成的临时主体 | 本次生成、控制及回收权 | 技能运行维护临时主体，作用结果交给目标玩法 | 依维持与结束规则停止作用、解除连接并回收临时显示；已经确认的伤害不撤销 |
| 借用法宝或兵器 | 在明确时段控制实际物件及需要的运动、挂点 | 法宝、物品、持有与装备玩法维护实体、持有人和库存 | 解除本次控制；不复制一把器物、不无条件回收入背包，也不销毁原物件 |
| 借用身体部位 | 占用明确部位、支撑与动作控制 | 人物、身体及器官玩法维护真实身体 | 解除本次占用和姿态接管；不删除肢体，不恢复本次真实受到的伤害 |
| 长期设施、领域或网络 | 启动或维护一个有实际归属的工程、节点或过程 | 对应设施、宗门、地域、网络或长期工程玩法 | 停止本次施法不自动拆掉设施；继续运行取决于设施与维护条件 |

法宝产生的临时剑气属于生成主体，法宝本体属于借用器物，二者不能合并为一份销毁规则。器官发出毒息同理：毒息可以独立存续，真实器官仍由身体玩法维护。

器物脱手、夺取、损坏或身体断肢必须经过对应玩法确认。确认后更新持有、连接、控制和显示；技能不能仅把模型挪走便宣布真实物件已经转手。

## 维持条件必须明确

维持方式写入构造或所属过程，不单凭“正在飞行”“有粒子”或某个流派名字推断。

| 维持方式 | 来源失效后的行为 |
|---|---|
| 已完成支付并独立运行 | 按剩余能量、运动和寿命继续；最初施放者死亡不补伤害、不强制消失 |
| 由人物持续维持 | 人物失去维持条件时执行明确的停止、脱落或收束；身体控制立即解除 |
| 由实际器物维持 | 器物损毁、供能耗尽或失去所需连接时结束相应过程；持有人变更由物品玩法决定是否允许继续 |
| 由设施或网络维持 | 检查实际供能、节点和拓扑；启动者死亡不等于设施损毁 |
| 由明确世界条件维持 | 条件解除后按该过程的规则结束；不能靠施放者身上一个永久状态冒充世界条件 |

同一招可以有不同维持方式的部位。例如人物停止维持树干时，已经释放且付清能量的冰剑继续飞行，未脱离的枝体结束或按真实连接脱落。没有定义来源失效行为的过程不得被自主创法或玩家改造受理。

正式旧资料缺省维持行为继续沿用其原有语义，升级不能擅自让原本依赖人物的攻击变成死后继续存在的新能力。后续增加独立存续字段时，在资料升级和迁移说明中分别明确。

## 来源与目标变化

| 变化 | 必须保持的行为 |
|---|---|
| 控制者仍存在且改变阵营 | 以后续确认时的真实控制及敌我规则为准；已确认的过去结果不回放 |
| 控制者死亡，过程允许独立存续 | 保留最后有效身份与必要的阵营资料，继续已有明确规则；不改认新生人物，也不无条件攻击所有对象 |
| 原版已经移除攻击者对象 | 模组记录仍保留稳定来源；普通受击不能冒用别人作为攻击者。原版无法记录的归属由模组事实保留 |
| 原目标失效 | 跟随、追踪、指定及关联分别执行资料规定的停留、继续或结束；不随意选择全世界新目标 |
| 身体被中断或支撑失效 | 停止依赖该身体的动作及作用，解除占用；已经独立且允许存续的生成部位继续 |
| 换器、脱手或器物毁坏 | 依实际器物编号及确认结果解除借用，旧模型不继续作为仍被持有的兵器结算 |
| 世界切换 | 当前世界的临时执行、控制及显示全部清理，旧计算结果不能写入新世界；需要延续的事实只通过正式保存恢复 |

阵营资料不能代替完整目标规则。明确的友方恢复、搬运、信息传递或地形工程仍使用各自的目标条件；不因为具有当前控制者就一律当成敌对伤害。

## 五种结束分别处理

| 结束 | 代表什么 | 不应顺带结束什么 |
|---|---|---|
| 动作结束 | 身体收势完成，释放本次身体与握持控制 | 已经离手且允许继续的形体和过程 |
| 施放结束 | 不再由这次出手继续启动新部分或支付后续施放成本 | 已转交维护的过程、已释放的独立主体及已确认世界结果 |
| 临时主体结束 | 该主体不再作用并回收临时资料和显示 | 其他独立主体、已发生伤害及永久工程结果 |
| 持续过程结束 | 停止维护、传播或条件触发，解除它登记的联系和条件 | 过程已经完成且由其他玩法维护的事实 |
| 永久结果 | 已经成为世界、器物、身体或工程的实际事实 | 不受原施放寿命回滚；以后仍可由正常玩法破坏、修复或转移 |

技能运行容器可以在人物收势后继续维护尚存的临时形体，但不能通过无限延长一个施放实例维护整座城市数年的工程。长期过程在受理时交给其事实维护者，技能保留必要的关联和结果记录。

纯装饰残留没有攻击、阻挡、供能或条件作用，可以使用独立显示寿命。承担真实作用的残留仍是主体或过程，必须有相应维持、结束和保存规则。

## 各种事实只由一个玩法保存

| 事实 | 维护与保存职责 |
|---|---|
| 可学习构造、人物掌握和必要冷却 | `ConstructedAbilityService`的正式构造与知识保存；后续继续扩展完整创法资料 |
| 实际身体、生命与器官 | 人物及组合身体玩法；瞬时动作不按录像进度恢复 |
| 实际法宝、物品、持有与库存 | 法宝、物品及`WorldObjectSaveService`对应资料；技能仅解除借用 |
| 城市长期工程进度 | 已有集体工程玩法及`CollectiveProjectSaveContent`对应资料；能力负责请求与表现 |
| 永久地形、建筑及世界对象 | 原版世界或相应玩法的正式事实；不能再保存一份会重复施工的技能副本 |
| 独立生成材料及其后续回收 | `WorldMaterialService`维护唯一材料、水量、原支付余量和独立过程，原施放接受后清零；不再保存第二份施放账本 |
| 新增门户、领域、传播网络或世界条件 | 相应玩法先实现唯一维护及保存，再接入技能；当前没有实现的部分保持未完成状态 |

恢复长期事实后再重建必要联系与显示，不重放启动伤害、再次扣费或重复发放成果。无法转换的局部资料按用户约定保留原档、提示并丢弃受影响部分，继续加载其他内容。

## 对应实施验证

本合同完成后，运行任务仍须验证：人物死亡及对象池重用、法宝丢失与转手、目标死亡、连接断开、独立部位存续、设施失去供能与启动者死亡、部分永久结果已完成时中断、长期过程保存及真正重启、切世界清理，以及同一事实不被技能与原玩法重复修改。

这些检查对应4.11、4.12、4.23至4.33、10、11、12及14的相应条目。合同确认与运行通过分别记录，不能用本文代替实现和实机证据。

4.11已完成当前构造执行的[来源失效与独立存续](来源失效与独立存续.md)：旧资料来源失效后结束，可选逐部位独立规则保留已付作用；真实身体、握持、任务边界和世界切换分别处理，133项实机检查通过。设施供能、抓投双方关系、其余来源迁移及长期保存不由该项代替，仍按所属任务验证。
