## 具体说明

### 建立制作质量基准

先制作并观察三类差别明显的内容：身体发掌与离手飞掌、连续翻卷的浪体、具有器身与接触表面的法宝护持。它们检验不同能力，不能都被做成换色发光体。

每类记录轮廓、材质、运动、接触、生效区域和结束方式。静帧要能辨认材质和形体；常速观看要能看清发力、加速、接触、回弹或破碎。近景、常用距离、城市范围远景均需检查。原版人物可用精灵姿态、肢体挂点等适合现有身体的方式，三维端需与真实身体和器物对齐。

这些身体与材料验证之外，还要用小型功能变化、城市分区过程和世界条件检验表达能力。例如可用桥体真实通行、引水逐段改变地域、世界灵流条件影响实际过程。具体接口在第0阶段核对；首轮不能仅凭三类战斗模型通过就认为已覆盖全部技能。

资源需能参与[生成式构造](生成式法术构造方案.md)。用同一主体改变材料、部位布局或运动后检查两端画面，确认骨架、部位和材质可重组。第一阶段验证资源可变性，第二阶段再验证规则展开和新变体；不能把每个通过用例封成独立整招动画。

这一步不增加固定连招，也不恢复全量录制。几段短而完整的实机画面过关后才扩展制作。

### 验证资源完整导出

核对现有 Three.js 工具、共同模型加载器和 Unity 资源构建。资源需携带实际使用的几何、材质分区、表面坐标、遮罩、挂点与动作；不能只保留预览中的形体和颜色。

资源格式根据双端试验选择：可共用的数据由明确版本的资料描述，平台相关的 Mesh、Material、Shader、纹理等通过现有资源构建路径打包。动画采用姿态曲线、骨架或连续形变中适合该主体的形式，不预设所有主体都用同一种动画。

先保证一份资源能正确进入游戏，再推广导出器。动作、模型和显示缓存不写入世界存档。

### 打通两种显示

当前原版将三维顶点投影后使用自定义表面材质；Worldfall 接入将面色与材料类别转换到它的模型。这会丢失表面坐标、自定义材质效果及局部透明信息。

需要实际验证两条接入路线：能否扩展其现有模型与材料提交；或能否在其实际三维绘制过程中加入本模组的绘制步骤，并取得相同视点与深度。Worldfall 有独立场景收集与 GPU 绘制，不能假定添加一个普通 Unity MeshRenderer 就能正确遮挡。

验证项目包括：半透明重叠、与人物及地形互相遮挡、近裁剪、正反面、夜景受光、自发光、坡面挂点、第一人称持物与肢体。当前提供包的版本单独登记；不承诺未经验证的版本。

城市和世界尺度另查传播过程、近远景切换与实际结果的一致性：远景有清楚的整体结构，近处能看到真实水路、设施或地表变化，不能让整图光效代替实际功能。

若某种材质无法保留，明确列出差异并调整接入方案，不能继续用条带或网点效果宣称兼容完成。

### 确认性能与线程入口

记录基线场景和设备，分别测无技能、单招、双向交锋的游戏开销。测量与截图录制分开，避免把录制开销或截图频率当作游戏性能。

使用相同纯数值任务比较已有工作池与 Friflo 并行任务；检查现有模拟阶段、全局锁、线程预算与结构修改限制。只选择能融入当前调度的方法，不新增独立时间系统。

本阶段通过条件是材质、动作、空间对齐有实际画面，线程接入有明确执行边界，后续数据格式能表达已验证的内容。

## 资源说明

| 资源 | 具体制作与验证 |
|---|---|
| 身体发掌动作 | 肩肘手连接、蓄势前送回收、真实接触与落空；两端挂点一致 |
| 飞掌主体 | 有掌心、指部和厚度，离手后独立运动；追踪转向不挤成椭圆 |
| 浪体 | 浪背、浪唇、破碎部位连续变化，表面流向稳定；落水有承接 |
| 法宝护持 | 器身清楚，实际防御表面可定位，接触处有局部反应 |
| 水与灵力材质 | 完整透明渐变、局部明暗和受光，检查两端差异 |
| 接触碎沫与碎屑 | 从真实接触位置产生，不靠整张命中烟雾覆盖问题 |
| 对照资料 | 同时刻静帧及短段常速录像，记录作用区域和加载版本 |
