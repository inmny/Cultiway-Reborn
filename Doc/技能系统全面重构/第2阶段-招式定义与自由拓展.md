## 具体说明

### 拆开作用投送与动作

基础招式声明作用、目标、投送方式、默认运动、动作、表现及可扩展部位。原有技能编号不再决定“永远只能近身或贴地”。

玩家改造、法宝材料或其他来源产生的变化，先形成一份明确的招式资料，再编译成供执行使用的紧凑数据。需要的开发操作包括产生执行体、沿轨迹运动、启用作用区、定时作用、遇接触反馈和结束；不先实现通用可视化编程语言。

同一能力可以有多个执行体和持续区域，但仍是一次招式。多个已学技能的独立释放沿用自主施法目标，不建立跨技能固定配方。

### 编译跨形态和词条

以原地掌击改追踪飞掌作为必过的改造路径：

1. 保留伤害、击退等作用，投送方式变为离手飞行。
2. 选择追踪目标，生成飞掌主体、运动和对应作用形状。
3. 身体播放发掌动作，到释放时点产生飞掌；飞掌独立追踪和接触。
4. 巨大同步改变形体、作用形状和所需挂点偏移；齐射产生多个真实执行体；急速同步调整相关动作标记及运动参数。
5. 真实成本、冷却、持续、数量、重复命中和结束规则一次性确定。

不能只更换轨迹组件，留下原有近身判定和手部外观。跨形态应由可复用的改造规则完成，避免每帧按技能编号判断。

校验检查目标、执行体、作用区、动作和表现是否齐备。缺失时说明缺少哪项能力，不因旧类别不同直接拒绝。自由改造不等于宣称所有逻辑冲突都能自动生成合理画面；需要的资源和转换规则必须实际提供。

除掌击转飞掌外，至少再验证水浪改为环绕浪体、固定领域改为随执行体移动。作用保持还是改变必须明确：环绕浪体不会因改了轨迹就凭空获得护盾能力。轨迹、投送和作用的改造可联动，但不能悄悄混淆。

同一形体需有适合手持、离体、推进或区域形式的表现规则，尺寸、轨迹和时长连续变化时仍能维持轮廓与材质。跨形态验证不能靠为一个技能编号写特例通过。

### 接入游戏内自由拓展

保留万法阁选词条、轨迹及参数的使用方式。必要时提供清楚的投送方式和作用说明；跨形态产生的变化由编译结果回显，玩家不需要手工连接节点。

预览、实际施放、能力消耗、范围说明和保存使用同一编译结果。运行中的施放固定使用原版本，编辑只影响之后的出手。新增词条或轨迹通过登记自身改变的数据接入，不在所有法术中逐一追加判断。

界面沿用公共控件、候选搜索和本地化；本阶段不新增组合编辑器，不向 mod.json 堆叠开发选项。

### 定义版本转换

保持正式能力、蓝图、词条、轨迹等稳定编号。旧资料按相邻版本转换成新定义，并保留玩家修改、已学关系和资源要求。旧运行对象、模型句柄和线程状态不入档。

资料已删除或无法转换时，遵守既有约定：保留原档、提示并仅丢弃受影响部分，其他世界内容继续读取。版本转换完成后运行当前实现，不长期维护两套旧新行为。

验证包含改造保存再载入、历史蓝图迁移、来源专属能力、部分无法转换及原档不被回写。

| 招式定义 | 作用、投送、目标、运动、动作、表现及版本明确 |
| 改造规则 | 声明输入需求与输出变化，定义相互覆盖和计算顺序 |
| 飞掌资源 | 使用第一阶段实际通过的主体、动作和材质 |
| 变化说明 | 能说明从近身到飞行、目标与作用时点的变化 |
| 旧资料夹具 | 覆盖已学法术、玩家改造、法宝来源和旧轨迹 |
