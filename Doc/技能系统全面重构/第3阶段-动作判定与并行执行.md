## 具体说明

### 建立施放与动作状态

一次施放拥有编号、资料版本、来源、目标、阶段、时间、执行体及结束策略。身体动作、法宝姿态、运动和作用区从同一过程读取。阶段跨过释放或接触标记时处理一次，即使游戏加速，也不能跳过或重复产生作用。

动作占用区分全身、手部与可独立运行的法术、法宝。全身重击需要合理占用，已经离手的法术可以继续运行，其他不冲突能力也能释放。不能用一个“忙碌”标记把全部法术串行化。

死亡、中断、目标失效、失去法宝和切换世界的处理由招式规则定义。飞出的法术是否继续、尚未释放是否取消等属于玩法状态，不由视觉对象是否还存在决定。

### 统一作用形状和结果

按需求支持圆、线段扫掠、扇形、沿路径区域和持续区域；身体或兵器接触读取真实挂点和动作。目标受击边界统一定义，清理旧“至少一格”等隐含容差，调整前明确其玩法影响。

坐标统一记录地面位置与离地高度，招式明确高度是否参与作用。地面区域、空中执行体和浮空目标使用清楚的高度规则；人物、武器和法术的受击边界随真实姿态更新。地表承托与 Worldfall 显示高度的换算在第一阶段实测，不能由两个视角各猜一套身体位置。切换视角不得切换伤害规则。

每次确认结果包含：来源、目标、接触时点、位置、方向、接触面、作用形状、实际伤害或吸收、格挡或穿透结果，以及后续状态变化。受击、破碎、反弹与声音消费这份结果，不重新猜测命中。

法术相撞需分清可碰撞类别、单次接触去重、贯穿、消耗、反射和终止。无害装饰不进入战斗碰撞。

接触之外还需支持直接指定、事件触发、过程推进和规则登记。作用结果统一记录物件转化、地形进度、连接建立与解除、过程改变等事实，不能要求功能能力伪造一次命中来借用反馈入口。

### 划分并行与提交

每个模拟步采用下列顺序：

| 阶段 | 内容与限制 |
|---|---|
| 读取 | 主线程取得所需对象编号、位置、受击边界、阵营及数值，形成只读数组和空间索引 |
| 并行计算 | 分块更新轨迹、形状和候选接触；线程独立写入自己的结果区，不调用游戏对象或内容侧任意回调 |
| 合并确认 | 按接触时点、施放编号、目标编号等稳定规则处理冲突，确认护盾剩余量、穿透和元素消耗 |
| 游戏提交 | 检查对象编号和代次仍有效，统一调用原版伤害、状态、死亡、地形和资源接口 |
| 发布显示 | 输出完整模拟步的动作、执行体、区域和结果，供两个视角读取 |

候选接触可以并行，最终对同一对象的变化不能无序竞争。例如第一发击碎护盾后，第二发必须按真实剩余防御继续处理，不能因为两条线程都看到了旧耐久而重复吸收。

显示读取上一份已完成状态，工作线程写入另一份结果，完成后再交换。切换世界时先结束或取消当前任务，原世界的结果不得写入新世界。并行得到的是接触候选；死亡、格挡、反射和原版回调对后续作用的影响仍需按确认顺序处理。

空间筛选避免所有法术互相两两比较；使用当前作用区覆盖的空间分区与碰撞类别，缓存稳定的地形资料，复用数组和结果区。小批量直接顺序计算，超过测得阈值才并行。

接入现有固定模拟步、协作调度和线程预算。工作执行期间不持有全局 EntityStore 写锁等待任务；也不在工作线程中结构性增删共享实体。已有 Friflo 文档要求结构命令在主线程提交，具体执行方式由第一阶段选定。

地域和世界作用按照真实语义采用不同更新方式：精确接触保持及时处理；地形与水路分区推进；长期世界条件通过登记、事件与所需查询参与玩法。原版对象修改仍有序提交，画面以实际已完成区块和生效时点为准。若能力设定为瞬间全域生效，就必须验证其真实提交开销，不能暗中改为画面先完成、作用慢慢补。

时间能力改变被选定过程的速度、暂停或延期规则，不用修改全局界面和镜头时钟来冒充真实作用。具体过程的事实和保存由其所属玩法维护。

### 接通显示采样

显示读取已发布的前后状态，在动作曲线与已确认路径之间平滑采样。人物、持物、飞掌和碰撞区域使用一致时刻与挂点。暂停、切换镜头和录制不推进战斗，也不重复触发命中。

原版和三维使用同一战斗状态，但分别正确处理坐标、地面高度、透明和深度。材质运动跟随世界与招式时间，不能另外按真实墙钟持续播放。

验证包括单线程与并行对照、同盾多弹、相撞先后、高速扫掠、加速跨阶段、暂停、打断、目标复用、施法者死亡、切世界及连续回收。稳定输入下技能结果应一致；不能扩大为对整个原版世界或所有第三方回调的确定性保证。
