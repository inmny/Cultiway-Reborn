# 作用、资源与生命周期合同

**对应0.10，属于设计合同。** [逐项清单](制作与验证条目.csv)的682个覆盖项均补入真实作用、资源支付、动作占用、开始条件、维持、结束/保留、事实拥有者和缺失支持。本文确定需要实现什么，现有支持与待实现部分分别说明；运行、美术、存档及用户验收状态保持独立。范围及资源制作见[制作与验证覆盖表](制作与验证覆盖表.md)，后续实施仍按[统一TODO](全程实施TODO.md)顺序推进。

## 每行合同怎样读取

| 字段 | 约定 |
|---|---|
| 真实作用约定 | 要改什么实际对象、何时确认、由哪个过程产生后果；模型出现本身不是生效 |
| 资源与支付 | 真正由哪个人物、器物、物品或领域承担，哪些材料/能量是输入；规则编号见下表 |
| 动作与占用 | 成形、有效、接触和收势，以及实际身体部位、握持、支撑和双端关系的占用 |
| 开始条件 | 知识/来源、真实对象、目标角色、空间/支撑、资源和所需原理；缺项应拒绝并说明 |
| 维持约定 | 独立、人物、器物、设施、条件或有限工作；不从流派名字或动画时长推断 |
| 结束与保留 | 正常完成、中断、源/目标失效后停什么、释放什么、哪些结果继续存在 |
| 事实维护者 | 唯一拥有者负责真实对象、进度、控制、长期保存；临时技能不保存一份重复成果 |
| 未完成支持／支持任务 | 具体差距及要实现的TODO，见G表；不能用合同签定代替这些任务完成 |
| 合同继承 | 127个旧变体继承其SRC原术的同名字段，行内补充本变体约束；按父行解析，不复制另一份生命周期 |

现有411项的作用以[0.03资料](各能力调用与保存入口.json)中该项的具体字段、实际作用回调和源码定义为迁移基线；不是把同组别的默认效果当成本项效果。技能资产保留伤害开关、命中/周期定义；法宝保留主动/事件/生命周期；状态保留属性、周期和真实持有者；原子及来源只经实际成果触发。旧回调对应的效果需转成共同确认，不能直接绕过共同接触再次执行旧伤害序列。

回调引用确定现有语义的来源，未宣称它已适配新框架。后续改效果要明确新修订及正式资料转换；不能在迁移中悄悄改变旧费用、来源依赖或读档后的含义。

## 资源、工作量与本次费用

资源来自已有登记，不新增“技能能量”等第二套余额。新创修士显化及功能术以实际真元通道为默认制作合同；同一构造由法宝、妖兽、骑士或物品承载时，明确按真实来源绑定并重新检查条件，不能为人物补造修炼体系。普通身体动作使用原版体力，额外劲力再用对应真实来源；已有骑士和其他旧能力继续其原费用语义。

一次需求和一次报价分开：新构造本次费用仍为实际资源的`Quote(实际支付者, 已编译需求)`，原有通道的可用性、整数精度、余额及容量由资源玩法处理。旧容器先按原词条/范围计算需求，内部派生、预付物品或已预付步骤不再次扣费；资产默认资源和`baseDemand`只作为迁移定位，不能冒充实际费用。

新操作的需求分量必须明确为：新增实际材料量、发力/搬运工作、对象/过程的有效作用、建立/维持连接以及永久工作；只计本构造声明的分量，纯装饰网格和粒子不产生攻击或可回收本金。瞬时段有本次总预算，分枝/脱片/转换共享余量；持续段按实际世界时间或明确工作量计，不按渲染帧数扣费。整数资源累积到可表示费用后在确认窗口结算，不能通过把连续工作切成免费小段规避消耗。

本合同确定费用的来源、需求因子、支付时机和不重复原则；各新操作的数值权重由3.09与实际资源绑定一起实现、版本化并实测，不在这里编造尚无玩法的固定“每城真元价格”。当前构造只保存单个`Resource/Cost`，并不会自动从体积或网络大小算出上述需求；这属于G03的明确缺口。保留已有Cost语义，后续转换不能无版本改写旧数值。

新工作的正式确认按同一逻辑时点处理：核对输入/来源与可支付量，确认本段投入和实际结果，记录本次已消费量；失败不产生未付费结果，重复确认不重复扣费或施工。尚未受理的取消不消费新资源；已付瞬时段的打断不无条件退款。材料回收只认原支付者、原通道、合法剩余量与实际本金，不能把已经造成的伤害、免费输入或敌方损耗当退款。原来源的提前支付/消费时点继续按P0/P11保留。

规模、强度、精度、数量、持续和永久程度分别成为实际参数；顶尖个体不能因境界高就让小术失控外溢。城市/世界用法按足迹、前沿、节点或条件索引工作，画面只能表现已确认部分。不能在全图上做一次扣血并播放大模型来替代分区过程。

## 维持与结束的选择

| 规则 | 正常推进及来源失效 |
|---|---|
| H0 | 迁移本项原有生命周期；动作、序列、状态/领域和永久后果分别结束，不把旧依赖改成独立存续。 |
| H1 | 已付清的独立主体按剩余作用量、寿命和真实运动继续；施术者停止动作或死亡不补伤害、不重扣费。 |
| H2 | 人物持续维持；每段世界时间先确认供能与所需来源，再推进该段工作，来源/资源失效停止新增，已独立部分依自身规则处理。 |
| H3 | 实际器物维持；按其生命周期供能、冷却及充能推进，器物损毁或所需控制丢失结束对应过程。 |
| H4 | 设施/网络按真实供能、节点和连接维持；启动者退出不等于设施被毁，断开的分区停止未来传播。 |
| H5 | 登记世界条件并由其唯一拥有者维护；无效或不再支付时解除相应条件，不修改世界总时钟。 |
| H6 | 有限真实工作；以已确认进度推进，每次提交先确认投入；完成、需求消失或中断停止新增工作，已完工部分交给所属玩法。 |
| H7 | 真实承载关系维持；容量、容器与目标身份持续有效，失效按预先确认的安全出口释放或保管，不静默删除对象。 |
| H8 | 纯资料或被动没有独立施放寿命，随真实拥有者、来源资格、事件和状态期限维护。 |

同一构造可以让不同部分选择不同维持方式，例如炉体由人物维持，已倒出的熔流独立冷却；根系生长需要供能，完工桥梁由结构维护。改造必须同时修改依赖、成本和结束，不能只换一条轨迹后沿用不成立的抓持或供能。

H0不是含糊的新默认：它要求逐项保留该旧来源当前的具体生命周期，定位在0.03该项及其实际源码；转换后共同运行承担等效过程，不保留两份旧/新执行并发。新能力必须选H1至H8的实际方式，不得用“沿原定义”掩盖尚未定义的行为。

动作结束、施放结束、临时主体结束、持续过程结束与永久结果遵守[控制归属与结束合同](控制归属与结束合同.md)。身体中断先释放实际占用；真实器物只是解除借用，不能销毁；失效目标不随意换成全世界新目标。换世界清理临时控制及旧计算结果，长期事实只经正式恢复。

**现有`ConstructionHold`仅在动作时钟的一个姿态增加停留时间。** 它既不读取资源也不代表“施术者每秒供能”。`ConstructedAbilityTime`提供共同逻辑时点，也不是操控目标老化/生产速率的时间法术。这两类能力分别由G03、G11补齐，不能用已有类名提前认领功能。

作用角色遵守[对象选择与作用合同](对象选择与作用合同.md)：攻击敌方器物/节点不要求它属于自己，借用、控制、储存、修补和受托工作有各自权限；不能拿友方使用授权阻止合法战斗对抗。救灾和功能需求也不能一律套敌人选择。原版地块、世界材料、城市工程、元神锚点和新空间网络分别持有自己的事实，不因为都有“连接”就自动合并。

每个城市/世界长期过程保存足迹或范围语义、输入/剩余量、已确认进度、所属身份及维持来源；恢复不重新支付已完成步骤、不再发收益。世界条件用登记和行为查询，传播过程用前沿/分区调度；明确登记全图语义不等于每帧遍历全图。性能测量仍由11、13包完成。
