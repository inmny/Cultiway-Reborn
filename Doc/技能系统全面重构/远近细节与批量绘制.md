# 远近细节与批量绘制

对应2.14。按实际屏幕占用选择显示细节，主体越大越保留轮廓；玩法姿态、接触、挂点及体积不随显示等级改变。

## 实施顺序

1. 离线生成近、中、远网格，保留原顶点的法线、表面坐标、骨架、厚度和成形通道；先核对接合边、动作及两种显示。
2. 两种显示按同资源、网格、表面及共同环境归组，批量提交独立姿态与实例参数；验证结果、真实批次数及清理。

两部分均成立后才完成本条目。依赖[meshoptimizer原工具](https://github.com/zeux/meshoptimizer/tree/master/js)做离线减面，避免另写通用减面器；不在游戏运行中引入制作依赖。

## 资源合同

| 资料 | 实际用途与保留内容 |
|---|---|
| 近景 | 原完整网格；制作及实际作用继续以此为准 |
| 中景 | 保留部件边界及属性的简化网格，控制偏差，适合中等屏幕占用 |
| 远景 | 进一步减少内部三角形，保留有效轮廓和细长主体，不用点或线替代 |
| 原有低面数资源 | 保留原网格，不为凑等级强行降质或复制相同资源 |
| 骨架和成形 | 各级沿用原控制、权重和进度，不另外推进动画 |
| 动态水层 | 曲面仍来自真实格网，保持实际湿润边界；不丢弃仍有作用的细小水域 |
| 批量实例 | 共用几何和表面，独立传入根姿态、骨架、颜色及成形；不同实际网格不虚称可以合并 |

原版使用实际相机像素尺度；Worldfall从当前绘制的真实投影取得屏幕占用，兼顾普通三维和第一人称，不沿用上一帧投影。资料缺失或格式未知按现有边界报告，世界存档继续保存稳定形体编号。

## 近中远制作与选择

第5版形体说明使用`Parts[].DetailMeshes`保留中、远网格。原网格继续作为实际作用、控制范围和制作依据，分件沿用所属版本的细节资源。完整资源组加载时核对所有等级，统一拥有和释放，绘制不读取磁盘。

离线锁定边界、轴向极值及挂点和接触端附近顶点，简化时同时考虑法线、表面、厚度、成形、权重及少量实际动作姿态。中景目标为原三角形50%、误差0.004；远景目标18%、误差0.012。实际不能满足误差的部件保留更多三角形，不为了比例强行损坏轮廓。误差相对模型尺度，具体算法见[原工具说明](https://github.com/zeux/meshoptimizer/tree/master/js)。

屏幕最大跨度达到160像素使用近景，达到48像素使用中景，否则使用远景。两种显示都使用实际绘制边界；Worldfall在本帧投影确定后选择，跨越视眼时保留完整几何。静态网格在切换等级时更换共享引用，动作继续使用共同骨架。动态水层保留真实曲面，不套用静态模型。此阶段不降低玩法更新频率。

实机检查发现原根藤封口增加顶点后沿用短一项的法线数组，Unity会丢弃整份法线通道。已修正制作源，让共同导出重算完整法线，并在导入边界拒绝数量不符的数据；不在运行中猜测补齐。

城市及世界规模性能继续按第13工作包验收。批量提交及对应实机结果见下文。

## 共用批量提交

两种显示共用`FormDrawBatch`。按实际网格、完整共享材质、地表纹理及绘制通道归组；不同版本的材质和不同动态格网继续分开。每项保留世界矩阵、法线矩阵、颜色、染色、成形、承托及封闭光程参数。相同发布骨架由同帧多个部件共用，只上传一次。

| 连续参数 | 内容 |
|---|---|
| 每实例12个四项向量，共192字节 | 两个显式行矩阵、实例色、染色、成形、承托及骨架起点 |
| 去重的骨架行 | 同一发布姿态只存一份，实例通过起点取自己的骨架；不受常量数组1023实例上限影响 |
| 组共享资料 | 实际网格、材质、地表和绘制通道；实例色和动作不阻止合批 |
| 原版 | 不透明形体与原版精灵共享深度，透明形体继续进入共同累加；原视图保留图层、边界与检查所需姿态 |
| Worldfall | 本帧投影选择几何后归组，实体与透明分别进入实际通道，独立相机保留原投影和深度 |

整帧参数排完后统一上传，再记录所有组的绘制命令，避免前面的命令读到最后一组参数。组列表与缓冲按实际峰值复用；每帧解除旧实例引用。原版不再向每个部件重复复制整份骨架属性块。换世界、相机停用及游戏退出明确释放缓冲。

使用[Unity显式实例绘制接口](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Rendering.CommandBuffer.DrawMeshInstancedProcedural.html)，材质开启实例绘制，按[官方着色器实例约定](https://docs.unity3d.com/2022.3/Documentation/Manual/gpu-instancing-shader.html)取得实例编号。实例变体要求4.5级功能，常规变体保留原要求；不支持实例或结构缓冲的设备使用同一资料逐件提交。本机通过选择常规路径作对照，不能代替低配置设备实测。

内部`UseInstancing`用于设备选择及开发对照，没有新增玩家设置、mod.json字段或存档字段。两种提交方式均使用同一实际姿态。完整城市及世界规模的帧耗时、并行和瓶颈分析继续按第13工作包验收。


## 批量提交实机结果与结束条件

游戏4075553经NML加载最终代码，29项专项通过；7项实际重载、切世界检查通过，实际退出检查通过。此前同一绘制实现的游戏4068517通过50项三视角往返和19项水冰、透明遮挡回归；随后只补退出释放回调并移除原版重复骨架属性复制，最终游戏再次通过专项、重载与退出检查。三平台资源包构建成功，仅Linux实跑，SDK0错误、16条已有警告，代码按仓库DotSettings整理。

| 检查 | 实际结果 |
|---|---|
| 8个独立姿态、颜色与成形 | 不同实例均保留自己的参数；同网格表面从8次提交合为1次 |
| 不同水冰表面、地表或网格 | 8次合为2次，不混用实际环境或几何 |
| 同一实例着色变体逐件与合批 | 水冰两种显示逐像素最大误差均为0 |
| 常规单件与实例着色变体 | 原版不透明与地表误差0；三维不透明最大约0.0000068。水冰因不同变体数值运算出现小差异：原版最大0.003095，三维最大0.015715，三维全图平均0.0000777；不声称全部变体逐像素完全相同 |
| 1100实例 | 实际单批绘制，稳定帧复用原生缓冲，容量约256.5KiB；不声称同等帧率提升 |
| 混合资源实际场景 | 18个独立构造产生111至114个部件；原版19次、Worldfall19至24次形体提交，各入口缓冲峰值96KiB |
| 重载 | 原、新剑体同时保留有效网格和实际提交，不将不同版本材质混为一批 |
| 切换真实世界 | 两种显示的缓冲及旧实例计数归零，新世界重新建立有效缓冲 |
| 实际退出 | 退出前三维仍持有1040字节缓冲；退出回调后两种入口均为0，记录来自同一真实进程 |

原版与Worldfall各6秒，共144帧、12秒、1280×720技术录像，展示多份巨神发掌、水鲸游动及根藤成形，独立姿态和染色同场，已查看关键阶段。世界暂停，只推进验证构造，仍按最终任务另行验收自然交战及流派美术。
