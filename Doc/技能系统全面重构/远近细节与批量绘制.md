# 远近细节与批量绘制

对应2.14。按实际屏幕占用选择显示细节，主体越大越保留轮廓；玩法姿态、接触、挂点及体积不随显示等级改变。

## 实施顺序

1. 离线生成近、中、远网格，保留原顶点的法线、表面坐标、骨架、厚度和成形通道；先核对接合边、动作及两种显示。
2. 两种显示按同资源、网格、表面及共同环境归组，批量提交独立姿态与实例参数；验证结果、真实批次数及清理。

两部分均成立后才完成本条目。依赖[meshoptimizer原工具](https://github.com/zeux/meshoptimizer/tree/master/js)做离线减面，避免另写通用减面器；不在游戏运行中引入制作依赖。

## 资源合同

| 资料 | 实际用途与保留内容 |
|---|---|
| 近景 | 原完整网格；制作及实际作用继续以此为准 |
| 中景 | 保留部件边界及属性的简化网格，控制偏差，适合中等屏幕占用 |
| 远景 | 进一步减少内部三角形，保留有效轮廓和细长主体，不用点或线替代 |
| 原有低面数资源 | 保留原网格，不为凑等级强行降质或复制相同资源 |
| 骨架和成形 | 各级沿用原控制、权重和进度，不另外推进动画 |
| 动态水层 | 曲面仍来自真实格网，保持实际湿润边界；不丢弃仍有作用的细小水域 |
| 批量实例 | 共用几何和表面，独立传入根姿态、骨架、颜色及成形；不同实际网格不虚称可以合并 |

原版使用实际相机像素尺度；Worldfall从当前绘制的真实投影取得屏幕占用，兼顾普通三维和第一人称，不沿用上一帧投影。资料缺失或格式未知按现有边界报告，世界存档继续保存稳定形体编号。

## 近中远制作与选择

第5版形体说明使用`Parts[].DetailMeshes`保留中、远网格。原网格继续作为实际作用、控制范围和制作依据，分件沿用所属版本的细节资源。完整资源组加载时核对所有等级，统一拥有和释放，绘制不读取磁盘。

离线锁定边界、轴向极值及挂点和接触端附近顶点，简化时同时考虑法线、表面、厚度、成形、权重及少量实际动作姿态。中景目标为原三角形50%、误差0.004；远景目标18%、误差0.012。实际不能满足误差的部件保留更多三角形，不为了比例强行损坏轮廓。误差相对模型尺度，具体算法见[原工具说明](https://github.com/zeux/meshoptimizer/tree/master/js)。

屏幕最大跨度达到160像素使用近景，达到48像素使用中景，否则使用远景。两种显示都使用实际绘制边界；Worldfall在本帧投影确定后选择，跨越视眼时保留完整几何。静态网格在切换等级时更换共享引用，动作继续使用共同骨架。动态水层保留真实曲面，不套用静态模型。此阶段不降低玩法更新频率。

实机检查发现原根藤封口增加顶点后沿用短一项的法线数组，Unity会丢弃整份法线通道。已修正制作源，让共同导出重算完整法线，并在导入边界拒绝数量不符的数据；不在运行中猜测补齐。

城市及世界规模性能继续按第13工作包验收。批量提交尚待本条目的第二步验证。


## 第一部分实机结果

Linux私有游戏4055901通过NML加载，383项专项检查通过，覆盖75个可见部件，其中50个提供两档简化网格。289339次顶点检查确认所有等级的法线、表面坐标、骨架、厚度及成形通道取自原完整顶点；接合边保留，显示等级不改变实际材料姿态与作用资料。

| 资源 | 近景三角形 | 中景 | 远景 |
|---|---:|---:|---:|
| 巨神 | 34504 | 17870 | 7048 |
| 灵臂 | 21384 | 11500 | 4662 |
| 水鲸 | 13196 | 7812 | 3056 |
| 水浪 | 25744 | 12872 | 4632 |
| 全部可见资源合计 | 135224 | 76624 | 31580 |

远景三角形为近景约23.4%，不据此声称相同幅度的帧率提升。原版和Worldfall各自实际提交近中远三档；三维绘制由验证脚本临时观察正式提交返回，结束即解除，避免读取外部下一次收集刚重建的待提交队列。初次导入失败及取样时机误报的输入与报告均保留。

巨神发掌、水鲸游动两种显示共144帧、12秒技术录像，1280×720、12帧/秒，已查看关键阶段。三个主体采用不同尺寸来检验屏幕占用；不是自然交战或最终美术验收。三视角往返50项与当前形体结构63项回归通过；SDK0错误、16条原有警告。三平台资源构建成功，仅Linux实跑；按仓库DotSettings整理代码。没有新增GameResources图片、玩家设置或世界存档字段，玩家无需手工迁移。
