# 按需求补全规则

落实3.06。入口仍是`ConstructionDefinitionLayers.Resolve`：先合成基础、来源和玩家选择，再填调用方默认，最后按当前结构的实际需求补缺项，生成普通`AbilityDefinition`。补全不在战斗帧中运行，不引入第二套技能执行或整招模板。

## 依据什么补齐

| 当前实际需求 | 缺项补全 | 保留的边界 |
|---|---|---|
| 身体动作同时选择根部飞行 | 空手取掌形，持物取该动作的器物形体；腕部连接、随动、体高；释放取有效动作结束，含维持时间；沿真实出手方向的速度；身体与显化共用接触组 | 已有形体、连接、时点、速度、接触组均优先；必要形体明确为空时报告错误 |
| 独立根部飞行 | 来源为起点、朝向出手方向；没有路径及速度时补局部前向速度 | 明确地图速度、连接或曲线保持原选择；不会根据技能名称猜轨迹 |
| 选择流化 | 只在未指定物态时选择该材料已登记的液态，并补流散参数 | 金属可流化；明确固态、空值和自定参数不被覆盖；不存在的材料物态报告缺项 |
| 液态主体未提供操作 | 补普通流散操作，沿用实际形体体积与同一水格作用 | 明确空操作列表保留凝聚形体，不擅自加流散 |
| 生长、碎解、留置 | 补所需参数；生长及碎片时长限制在剩余窗口；明确留置才默认在世界中保留10秒 | 真实分件仍从资源读取，缺失即拒绝；永久留置的明确零值不改写 |
| 初始或操作输出材料 | 解析已登记的物态；表面继续跟随实际材料及转换结果 | 染色不改变材料；不把当前默认表面写死，妨碍后续冻结、熔化或换材 |
| 主体作用及结束 | 作用形状继续绑定实际资源和共同姿态；身体显化默认在释放后有效、接触后结束；未指定存在终点时取整次寿命 | 不复制原术的大圆范围；不把普通结束变成永久世界结果 |

已有部位操作与命名步骤采用相同参数补全。步骤的`part`输入可沿之前步骤追溯原部位；集合、实际输出类型、依赖循环及事件能否完成，仍由正式编译入口核对。动态输入不能保证在身体收势前就绪时，必须提供真实解除连接或事件位置规则，不能假定它按预估秒数完成。

明确的`null`、零值、关闭和空列表都遵守3.05。补全只写不存在的字段，不会把非法明确值修成“看似能用”。无法推导的形体、制作动作名或关系由正式编译报告，不替用户猜整招。

## 接入与保存

现有`BodyConstructionEdits.Project`保留原有操作、支付和寿命参数，把形体选择、连接、有效时点及共用接触规则交给同一补全入口。因此实际玩家显化改造、修士自主显化及其派生共同使用该规则，不只服务于开发示例。

完成后的普通构造才登记、学习和保存。正式旧资料不重新补全，不在读档时重抽默认；保存格式和转换版本没有变化。完整草稿保留已确定字段，创建新部分资料时才按缺项展开。成本、数量、冷却和结构预算的完整推导分别继续按3.09和3.10实现。

## 复现资料

复现命令：`python3 Scripts/SpellDemos/verify_construction_completion.py`，使用独立游戏配置，结果在`artifacts/skill_rebuild/construction-completion/`。

- [追踪离体掌](补全输入/追踪离体掌.json)：与已有真实身体动作合成，只选择材料、转角及追踪操作，不逐项手写掌形、连接、速度和释放过程。
- [液态金属流路](补全输入/液态金属流路.json)：选择金属和流化，未手写物态或流散工作参数。
- [有限裂片](补全输入/有限裂片.json)：选择真实分件形体与碎解时点，补齐有界后续运动和结束。

这些文件是创建时的部分输入；正式保存的是补齐后的完整构造。没有新增模型或图片，显示和实际作用继续使用同一资源、姿态及水格，不在本项重复制作美术。

## 本轮结果

Linux私有游戏128097经NML加载最终代码。24项专项通过，包含实际身体连接及离手、动作结束后继续运动、液态金属的共同水格及材料表面、真实八片碎解、明确空值保护、命名步骤补全、正式登记学习支付及同进程正式构造部分恢复。保存的是确定结果，不在恢复时重新运行规则；没有新增保存字段或升级版本，未重复世界冷启动验收。

21项合成次序、31项实际身体编辑及命中、20项来源创法回归通过，后者包含64组结构变化及身体原术显化。旧身体脚本中关于早期三类生成器的固定种子抽样不适用于当前生成器，本轮复用其真实编辑、支付、近身去重及远距命中段；未将该脚本后半段的自主创法检查算作通过。当前完整自主创作、训练和使用仍按第7工作包验收。

首次专项的三项失败来自数值检查：单次大步被寿命截断后，累计浮点时间停在终点前约千万分之一秒；碎片时长的重复相减也有同量级差异。现在按实际连续模拟再推进下一步，并只对时长计算采用百万分之一秒容差；仍严格要求最终结束、可见物清空和八个真实碎片。没有为此扩大修改整个运行器。

SDK0错误、16条已有警告，按仓库DotSettings整理。三维兼容层及显示资源未改变；本项验证共同数值执行，最终美术和各流派录像继续在对应工作包。
