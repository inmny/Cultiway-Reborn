# 结构展开与执行预算

对应3.10。创建、玩家改造、修士创法和正式恢复共用编译边界，以完整展开结果为准。先拒绝超过容量的描述，再分配执行资料；不在战斗中临时复制整招来绕过容量。

## 容量与计数

| 项目 | 当前规则 |
| --- | --- |
| 实际部位 | 整次最多128个，组织中心、隐式真实碎片、事件后段和复制结果全部计入 |
| 嵌套 | 根为零，最多16层；对象循环也会在序列化前被有限展开拒绝 |
| 原操作 | 每部位最多32项，在分配数组和解析资源前检查；原有各操作内部上限仍保留 |
| 条件与命名执行 | 每部位最多16项，共享已有实际状态容量 |
| 跟踪步骤 | 命名原操作输出与独立步骤合计最多128项；集合展开后的每个执行都计数 |
| 整次工作量 | 4,194,304，统计实际数值格、控制骨架、变化及操作；沿用共同调度的工作量单位 |
| 生成主体的实际作用形状 | 最多262,144，动态流散按计算格及最多作用形状预留，不拿显示三角形数代替；当前单次身体借用仍由已有固定绑定管理 |
| 持续 | 沿用最多3600世界秒，所有条件分支和循环仍受整次截止约束 |
| 路径 | 沿用最多64曲段、相邻关键点至少0.001秒及曲率采样预算；循环复用相同曲段，不复制数组 |
| 重复接触 | 沿用最小1/120世界秒间隔，以及共享组的每人和总次数；重入须真实离开后再进入 |
| 编译缓存 | 最多4096份完整修订，按进入顺序回收；不删除正在施放者或内容目录持有的计划 |

`CompiledAbility.Budget`公布本次实际部位、操作、跟踪步骤、曲段、流散格、作用形状和工作量，供已有开发工具读取。没有新增玩家配置。

32项原操作容量保留原有物态变化及条件上限，不能把条件数、原操作数或输出名数量相互替代。16份最大64×64流散可以成立，再增加一份会在分配单次运行状态前报告整次容量。场景尺寸和计算格数分开，不能为了更宏大而无限加密网格。

## 截止与递进

编译按真实输入依赖检查最早可执行时点：直接定时、身体自然收势、等待前一步开始或完成使用各自含义。确定已经无法在整次或固定存在时段内开始的后段，创建时报具体步骤；不会把永远等待当作已经实现的联动。

循环制作动作保留循环能力，但没有自然完成输出。后续可以接它实际开始后的部位或明确事件，不能等待一个运行中不会产生的自然完成事实。普通两段动作等待真实完成、再继续维持仍然允许。

原节点维持、原操作内维持、条件及命名维持都检查实际存在截止。在动作末帧维持时，维持实际用完之前不发布正常完成输出。依赖关系中的动作时长和维持共同参与最早完成检查。

事件出生的具体时刻仍由游戏决定。编译只使用可靠的开始下界，不能把未知出生当作固定零时刻、错误拒绝合法后段；实际运行继续受自己的存在窗口和整次截止限制。有限部位每次施放最多开始一次，条件执行最多接受一次；结束通知、实际碎片预留和步骤状态继续复用已有一次性记录，不在事件里重新展开无限结构。

历代创作可以继续。当前来源记录只保存上一术的编号与修订，不递归执行完整祖先描述；每个新结果独立编译。已有世界目录100,000份、单人已学128份、待处理创法256项和每轮处理一项的容量继续有效，不另设固定传承代数。

## 继承运动与共同空间

来源旋转、控制骨架的连续动作和聚合会给附着点带来运动，脱落后不能把这些速度视为零。候选范围现在统计相应切向速度、平移和可继续的路程；曲线采用解析导数的控制速度上界，而非用总长度充当瞬时速度。多次改向和实际碎片分散仍保留各自声明的有限容量。

事件后段按真实来源关系计算空间，独立出生采用自己的尺度；不能强行借用声明树上已经结束的父姿态。随体高缩放的布局与继承速度，和独立世界速度分别保留，防止重复乘体高。组合后的缩放、运动和空间必须仍是可表示的有限数，明确填写选取距离也不能绕过该检查。

目标相对路径可能带Worldfall地面高差，目标轴与竖直偏移并不一定垂直。路程和导数预算以分量长度之和覆盖这个情况，不能按平面直角坐标低估。

这些仍是声明构造的候选及运行容量，不承诺对移动目标必然命中。来源人物在未来怎样移动、外部玩法怎样施加新速度，以及完整施放中断反馈，分别由真实输入及后续施放、身体和交锋任务处理。世界级能力的最终性能和画面另按第13至15工作包验收。

## 复现

运行`python3 Scripts/SpellDemos/verify_construction_budget.py`。专项结果在`artifacts/skill_rebuild/construction-budget/`；同一独立游戏继续检查动作维持、资源需求、操作输出、创法和正式首版资料。测试不改写原资源或正式世界夹具。

本批没有新增模型、贴图、UI或保存字段。预算从当前已编译资料重建，旧构造费用不重新计算；超出支持容量的单条旧资料继续通过既有正式恢复报告隔离，原档保留。

## 实机结果

Linux私有游戏175261由NML加载最终代码，34项专项通过。有效边界包括128部位、16层、32项原操作、64份复制、真实碎片容量和16份最大流散；越界在展开或分配运行状态前拒绝。末帧维持不提前完成，循环制作动作可传递实际部位，但不提供不存在的自然完成输出。组合缩放溢出即使填有明确距离也被拒绝。

实际旋转脱落后的作用端点最远约14.65525格，候选预算约17.96996格；曲线脱落后最远约31.60483格，预算约68.262格。检查使用实际推进后的共同胶囊端点，不只比较参数。随体高变化的旋转继承也通过；预算偏宽不承诺任意目标必然命中。

4097次额外编译后缓存保持4096份，原施放继续推进，被回收资料可以重建。测试发现并修正世界清理只清字典、未清回收顺序列表的问题。资源真正重载后，新计划使用新资源版本，旧施放仍持有原计划并提供真实作用形状。

同一代码另通过动作范围30项、需求35项、输出绑定33项、操作约定27项、来源创法20项及正式首版资料256项，合计435项；包含64组创法变化、实际远距离支付命中及同进程正式恢复。旧创法断言已按实际范围与结构需求更新，不再假定增加布局的两份构造恰好两倍费用。地面检查先执行真实采集以建立采样器，不依赖其他测试先运行。

SDK0错误、16项已有警告；代码和调试脚本按仓库DotSettings整理，整理前后有效代码一致。没有新增存档字段，因此本批没有重复整个世界的冷启动；上一批重启证据保留。3.10收尾，统一进度105/328，下一项严格为3.11。
