# 可重复基线场景

对应1.02，已通过四个正式世界的准备、两轮八次重载实跑，以及真正重启后的飞掌/雨云读取。性能测量属于下一项1.03，各流派最终画面仍按9和16包验收。

## 使用入口

在项目根目录运行，使用已经安装的DebugToolbox客户端：

```bash
python3 Scripts/SpellDemos/baseline_scenarios.py list
python3 Scripts/SpellDemos/baseline_scenarios.py prepare --launch
python3 Scripts/SpellDemos/baseline_scenarios.py run --scenario all --repeat 2
python3 Scripts/SpellDemos/baseline_scenarios.py run --scenario apex
python3 Scripts/SpellDemos/baseline_scenarios.py quit
```

`prepare`从固定种子生成并正式保存的干净原版基底世界准备所选场景，并通过正式入口保存到独立目录。`run`每次重载已经准备好的同一份世界，不在上轮已经受损或消耗的世界上接着测。`--scenario`支持`none`、`ordinary`、`apex`、`process`和`all`；`--repeat`为1至10。`list`只读资料，不连接或启动游戏。命令按顺序执行，不与同一配置的其他载档/录像任务并发。

脚本、配置见[Python入口](../../Scripts/SpellDemos/baseline_scenarios.py)、[游戏内场景](../../Scripts/SpellDemos/baseline_scenarios.script)及[固定输入](../../Scripts/SpellDemos/baseline_scenarios.json)。构造原型使用[追踪飞掌资料](构造输入/掌击改追踪飞掌.json)。基底采用原版新世界入口、种子1099和128×128平地；旧完整存档样板保留用于迁移测试，不作为可删人物的空白场地。

## 独立配置

所有文件在`artifacts/skill_rebuild/baseline/`，不使用玩家的存档槽，也不载入当前其他调试会话。游戏和客户端共享本测试的`TMPDIR`，会话写到`temp/DebugToolbox/`；`XDG_CONFIG_HOME`指向`profile/`。连接时核对实际进程编号、环境与Unity存档目录，游戏内在载档前再核对配置边界。

本机启动显式设置Doorstop/BepInEx参数，并按原版允许的配置格式启用实验模组和当前支持的WorldBox版本。空配置默认不加载NML，不能以启动了游戏窗口冒充载入模组。关闭窗口预加载、自动存档和垂直同步，固定1280×720、60帧上限、x1世界速度、场地和镜头；帧上限是输入条件，不是已经测得的性能结论。

就绪超时保留实际进程和日志，重新执行连接会观察同一进程。只有权威状态表明进程退出后才重新启动；不会因一次轮询没响应另开一份游戏。修改源代码或资源后需按正常加载规则真正退出并重新启动，不能用文件更新冒充内存里已经加载新代码。

## 四种场景

| 编号 | 固定角色与输入 | 实际运行 | 通过证据 |
|---|---|---|---|
| none | 八个人物，种子1100，不接入仙道；测试期间关闭技能总开关 | 原版角色可正常移动/近战，模组仍加载，用作无技能对照 | 没有新构造启动或旧技能序列；不把此场景称为“完全卸载模组的原版” |
| ordinary | 八位金丹修士（内部境界索引2），种子1101，战力参数3，真实学习火球和水箭 | 设置敌对双方后由原版决策自主交战，脚本不循环代放法术 | 实际启动旧法术序列，保留角色结果和新构造事件记录 |
| apex | 两位化神修士（内部境界索引4），种子1102，威力参数12，学习原型追踪飞掌，主体尺寸乘2 | 双方从同一保存起点自主交锋；真实知识、动作、支付及接触按当前框架运行 | 双方都有自主施放，并发生人物接触或法术相撞的实际损耗；这套原型不算城域美术完成 |
| process | 一位金丹修士（内部境界索引2），种子1103，学习有限雨云构造 | 正式主动入口启动0.8秒构造，天气持续45世界秒，观察12秒 | 施放已正常结束，而原版天气仍真实推进；云龄和来源保留 |

测试角色使用原版高生命特质以延长观察；境界、威力和实际恢复后的数值均写入结果，不能只靠场景名称推测战力。准备时从同一干净基底重载，统一场地区域土层及植被，固定人物布局和来源；原版地图其他区域保持同一基底输入。长期天气通过正式世界作用创建，不直接贴一朵云图。

## 保存、版本与复现边界

每个场景有`worlds/<编号>/`正式世界和`baseline.json`。后者保存实际人物身份、名称、位置、生命、伤害、境界、资源及种子。正式重载后逐项核对起点，再开始本轮运行。脚本记录保存版本、代码/资源内容与地图/构造输入；只改提交号不影响复用，输入内容改变则要求重新准备，避免旧存档悄悄对应新参数。

原版重载会把无城市的人形重新归入流民，因此敌对分组和攻击目标在核对保存数据后按固定角色顺序建立，属于每轮一致的启动条件；不在脚本里代替修士释放攻击。配置的战力不得低于其真实境界下限，否则正式读取会按原玩法校正，无法作为相同起点。

角色创建及运行前调用原版`Randy.resetSeed`。这保证明确输入和原版随机起点可重复，不宣称第三方世界所有并行回调在每个帧率下逐位一致。运行结果仍记录真实事件、对象和时间，用于后续判断差异，而非强行覆盖成预期值。

每次运行输出到`runs/<时间>/`，包含连接、配置、内容版本、输入和逐场景结果。实际开始、结束、命中/相撞及角色结果另存观察记录，失败也保留；法术在途中真实抵消属于交锋结果，不能因人物未扣血便误判没有作用。`game.log`及`game-console.log`保留实际NML加载、启动异常和环境信息。失败直接报告对应条件，不能用重新准备一个更简单世界消除失败记录。

离线分析以`*-observations.json`中的完整事件为准；调试通道返回的对象句柄不会跨重启保留。重载比较采用与正式写出相同的数字表示，仍要求逐字段一致，不以放宽误差掩盖实际数值改变。

## 本轮实测

两轮完整运行共46项场景检查通过：无技能场景没有任何技能序列；普通修士实际自主启动134/140次旧术序列；顶尖双方各轮合计启动20次共同构造，各发生16次真实相撞、消耗222.4份实际作用量；天气在0.8秒施放结束后继续推进，运行12秒时仍保留真实云龄和余下寿命。两轮均从相同保存起点恢复。

进程3564971退出后，进程3580688重新通过NML实际加载，飞掌和雨云分别再从正式世界读取运行，13项检查通过。独立核对还确认33项覆盖、输入、来源、正式世界、真实运行与冷启动条件。结果和输入/输出指纹见[核对结果](../../artifacts/skill_rebuild/baseline/verification.json)，完整八次运行位于[本轮目录](../../artifacts/skill_rebuild/baseline/runs/20261024-015709/metadata.json)，冷启动记录见[飞掌](../../artifacts/skill_rebuild/baseline/runs/20261024-020155/apex-0.json)与[天气](../../artifacts/skill_rebuild/baseline/runs/20261024-020300/process-0.json)。

本轮修正的是测试准备和取证：空配置需要显式启用实验模组；原版窗口预加载卡住时使用固定关闭配置；完整存档迁移样板不作为空白战场；等待人物列表刷新后保存；战力不低于真实境界下限；敌对分组作为固定运行启动条件；法术互相抵消时读取实际相撞损耗。此前失败记录保留，未通过删除检查或只看动画冒充成功。
