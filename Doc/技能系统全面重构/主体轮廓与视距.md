# 主体轮廓、材质与视距（9.02）

本项先打磨下表明确记录的五处问题，最后检查第 5 章留给本项的其他既有主体，例如护盾、水幕、剑气及各类飞行和落地主体。按形体和读图问题归类复验，不为共用规则重复搭建场景。后续流派和复杂攻击有新主体时，按同一标准验收。这里不补动作、声音、通用反馈或第 9 章的其他玩法。

| 子批 | 本次要改的行为 | 必要验证 |
|---|---|---|
| A 近距光束 | 灵光从亮芯到半透边逐渐变弱，阳光保留较紧的金色分脊，避免近处像硬柱。短段、常用长度和词条放大时，能分清亮芯、有效外缘与无伤余光。 | 复用 `verify_beams.py` 的修士、近处点和侧边对象。在一个短段上查有效区内外和自然结束，对比正常长度与放大截图。确认过去正式保存的构造不因替换同名接触资源而改变作用范围。 |
| B 连锁雷 | 雷体有错开的亮段、少量粗细不同的支梢和可看清的击中端点。支梢是否接触由同一份范围决定；纯装饰支梢收在真实范围内。 | 复用 `verify_chain.py` 的短链，确认只有实际命中才有下一段，一名分支旁的对象保持原状态。比较近处接点与远处链路，检查结束后无残存雷段。 |
| C 土墙 | 主墙有厚断面、叠层与承重岩块，边缘凸出量可读；临时土墙的实际阻挡边界随主体。详细碎裂动作归 9.03 和土系制作。 | 复用 `verify_wall_migration.py --section earth`，核对挡住正面、边缘外能绕过和结束撤墙。近景看岩层，拉远时确认墙的宽度和缺口仍能看清。 |
| D 龙卷和玄阴 | 龙卷从地面进风、腰部卷动、顶部泄流，避免整张风壳；玄阴用可辨认的包裹边与内层阴影，保留开口、深浅和对象轮廓。二者不能只靠改色区分。 | 复用 `verify_remaining_fields.py` 对应外观与实际作用段：各选一处明确边界及自然结束，比较两种主体在同一环境中的近、中、远景。 |

近景检查主体截面、材质过渡和端部接缝；常用战斗距离检查能分清攻击、护持和空隙；远处检查整体方向及开口，不要求保留微细纹理。凡外观改变会改变有效边界的，要在实机确认至少一个区内结果和一个刚好区外的对象，不用看起来差不多的代理体代替。对同一规则已通过的用例不再铺开身体、装备或多个世界。

A 开工时的旧资源：灵光和阳光都用封闭圆端网格，阳光有三道重叠的光脊。射线的最短生效长度直接跟接触半径走，节点放大也会放大横截面。所以缩窄外壳若不跟作用同步，会留下不可见的厚伤害圈；动到作用资料又要保留旧正式构造的结果。A 先用现有端点与作用观测把两种情况分开。若需要新接触范围，给新形体稳定标识，旧名和旧费用保留。

每个子批交付制作源、发布资源、一个可复验入口和实际截图，改接触时附边界结果。制作预览用来快速看形体，数值与视觉一致性以实机为准。原版与 Worldfall 的连续取景集中到 9.10，最终验收视频按总表第 16 章交付。等本表及视距检查都通过，再关闭 9.02 并合并到 `codex/dev`。

## A：把光束从实体柱改成有厚度的光

灵光是单束蓝白亮芯与蓝绿半透边。阳光的明黄核心较紧，两侧有偏橙色的光脊，叠在一起仍能看见场景背景。亮芯仅补显示，半透边的每条光脊才有真实接触；世界时钟带动光流沿实际伸展后的轴移动。两者沿用原来的起点、末端控制、支付和有效时段。

原 `spirit_ray`、`solar_ray` 的编号、尺寸和接触说明保持原样。新版原技能施放分别选用 `spirit_ray_luminous` 和 `solar_ray_luminous`；亮边与接触半径从同一数值生成。灵光每个局部截面从 0.60 改为 0.30；阳光三脊的单脊半径从 0.25 改为 0.15，侧脊偏移由 0.20 改为 0.12。实际世界尺寸仍随技能及其词条变化。

复验命令：`dev.py exec --timeout 315 -- python3 Scripts/SpellDemos/verify_beams.py --section appearance`。复用 B18 的世界和人物准备，以当时的两份正式转换定义和记录半径检查旧资料，再在同一世界核对新束体。结果保存在独立环境的 `output/beams-appearance-*`。

实机分两段通过：四次已学施放均有真实命中、侧边样本无伤、自然结束后接触与主体同时消失；旧 B18 构造的实测半径仍为灵光 1.38 格、阳光每脊 0.575 格。短束新版灵光实测半径 0.69 格，内侧对象损失 99 点血、紧邻外侧为 0。阳光常用距离的每脊半径为 0.345 格；放大后两种主体的有效半径分别为 0.966 格和每脊 0.483 格。

初次施放的截图被三维镜头或树遮挡，在同一世界和人物上另拍原版俯视图。 当轮独立安装没有复制测试世界目录，实际是在原版生成的测试世界内布置同一批人物和坐标；接触与照片来自同一进程。复验入口现直接读取仓库内的固定世界文件。近景分别能看清蓝白亮芯和半透边，阳光在远景仍可读出施放端、方向和命中端。两段的结果、截图和中间尝试保存在独立开发证据 `luminous-beams-902a/delivery.json`。三平台资源已生成，实机结果来自 Linux 软件渲染；完整双视角录像仍按 9.10 与第 16 章验收。

## B：让连锁雷像分段放电

沿用 `thunder_channel` 的编号、挂点和 0.12 格基础接触半径，不改变跳转、支付、持续时间，也不增加命中次数。外层只有一层弱紫蓝光，提示原来的有效宽度；内部银蓝雷芯沿三维方向折转，粗细交错，两道渐尖的分梢从主芯分出。主芯和分梢都使用同一对端点变形，所有顶点留在原接触体内。水面传导和已有自创连线引用同一个编号，也继续使用各自原有的宽度设置。

复验命令：`dev.py exec --timeout 210 -- python3 Scripts/SpellDemos/verify_chain.py --section appearance`。复用 B19 的测试世界和人物，观察一次实际短链及近远双图。没有接触时后段保持未启动；确认首击和下一跳各自在顺序中扣血，分梢旁未选中的人无伤，结束时一起清理。完整 B19 的词条、失败退款、恢复测试仍走原入口。

实机使用固定世界和 B19 已通过的四段路线。一次正式使用仍发两次，每发依次命中四人。两发累计扣血为 200、144、128、102，与 B19 的原普通版本记录一致；首段旁的未选中对象扣血为 0。每段仍只用原接触体，结束后场上没有残存雷段或接触。近景可读出折芯、宽窄与短分梢；拉远后四个接点和线路仍清楚。`thunder-channel-902b/delivery.json` 保留两张截图、完整通过记录以及测试准备中失败的三次尝试。未改任何存档资料。
