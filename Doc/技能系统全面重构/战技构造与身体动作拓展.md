## 当前缺口

本次核对的骑士战技有守卫、枪骑和决斗家三个流派，共九项登记。`KnightTechniqueAsset` 用专用回调描述执行，具体文件分别安排动作、延迟攻击和状态；`KnightTechniqueSkills` 不开放编辑，旧档恢复也只接受固定轨迹及没有词条的描述。

既有待办包含战技迁移、身体发力和掌击跨形态，但不足以保证动作本身可以重组。本补充将战技从“迁移九个固定技能”扩大为可生成、可改造的身体及兵器能力，覆盖骑士、修士、非人身体和现有其他来源。骑士的斗气、取得和掌握方式仍由骑士玩法维护。

## 战技的构造要素

| 要素 | 可变化的内容 | 实际影响 |
|---|---|---|
| 身体与部位 | 手、肘、肩、膝、足、头、角、尾等实际可用部位 | 谁完成动作、哪里接触、哪些动作同时占用 |
| 支撑与重心 | 落脚点、转体、前压、腾起、下坠、恢复平衡 | 发力过程、真实位移、接地及姿态 |
| 器物与握持 | 刃、尖、杆身、锤面、盾面，单手或双手等可用握持 | 触达、接触方向、承力、连接及脱手 |
| 动作过程 | 蓄势、刺入、横扫、挑起、拍落、回转、收势等连续动作 | 部位路径、作用时段和结束方式 |
| 步法与移动 | 进退、侧移、冲撞、跃落和转向 | 实际人物位置、障碍接触与作用路径 |
| 发力与作用 | 推、拉、挑、压、扭、穿、震、传导和卸力 | 真实受力、姿态、损耗与后续过程 |
| 接触与关系 | 碰撞、抵住、拨开、抓持、借力及解除 | 双方约束、格挡、失衡、抓投及控制归属 |
| 力量承载 | 身体、器物、斗气、真元或其他已实现来源 | 成本、维持、离体或延伸时需要的主体 |

动作可包含内部阶段、有限重复及接触后的变化。多个完整技能之间仍按既有自主出手规则运行，不增加固定多招配方和复杂衔接规划。

## 共用动作构造如何工作

构造器以命名身体部位、支撑点、接触面和动作资源为输入，生成连续姿态及过程。身体位置、肢体和器物变换共同产生作用形状，实际结果再决定收势、失衡、阻挡或分离。

共用动作可以接受不同输入。例如“刺入”使用尖端及轴向，“横扫”使用接触面和旋转支撑，“抓持”建立双方实际部位的关系。剑、枪、角、爪或尾是否能够参与，取决于已提供的结构、动作及能力，不能仅凭外观名称判断。

动作生成需要优质姿态资源和调整范围。制作的蓄势、转体、送肩、步伐和回收可按握持、距离、方向、速度及尺度适配；只随机关节角度无法保证合理动作。非人身体提供自己的部位和支撑映射，不套用固定的人类手脚。

用受控轨迹、姿态约束和明确受力规则满足玩法，不以完整现实物理模拟作为前提。抓持或架住武器需要双方共同关系，不能只在施术者身上播放动作。关系中断、目标死亡、脱手、撞墙或被击退后，双方都应正确解除控制和继续运行。

## 自由改造与自主创作

战技和其他能力共用构造、编译、版本及保存入口。改造可以改变接触部位、运动、发力、步法、目标、作用条件和内部动作阶段，不能只有伤害、速度或拖尾变化。

近身作用可改为离体劲体、延伸接触或由法宝承载，补齐离手主体、动力、作用区及真实消耗。抓投等双向关系的改造必须提供对应载体与连接规则，不能只换轨迹就保留一个没有来源的抓持效果。

自主创作既可从身体及器物能力构造，也可改写已学战技。生成器选择动作过程、部位、步法和作用关系，再交共用编译器处理；不局限于从九个名字中抽取。功法、熟练程度和使用经历可影响选择倾向与动作质量。

命名和传承保存真实构造及版本。相同资源可以产生动作结构不同的战技，并与材料、映照、时间、空间等已实现能力结合；特殊原理需要实际操作及资源支持。

## 表达范围与检验例子

以下用于核对不同能力，不分别写成封闭运行类，也不是固定多招组合。

| 方向 | 要表达的实际过程 |
|---|---|
| 短促穿劲 | 肩肘掌短程发力，接触后沿明确对象或路径传导，身体完成回收 |
| 沿刃旋切 | 步法及转体推动真实刃面扫过目标，接触、格挡和收势随结果变化 |
| 杆身拨压 | 长兵器用杆身拨开来袭或压住目标，接触部位及双方受力明确 |
| 抓持摔投 | 真实抓持后移动或转体，目标被带动、释放并与地面或障碍接触 |
| 卸力与反送 | 接触后将允许的部分受力引向指定方向或支撑，实际剩余作用被保留 |
| 角撞尾扫 | 非人身体使用真实角部或尾部，动作路径、惯性表现和有效部位一致 |
| 城域或世界武道 | 顶尖个体通过接触、发力传播、地层或明确空间关系产生宏大作用，仍能读出来源动作 |
| 功能性运力 | 扛运、劈石开路或锻打塑形改变真实物件与通行，不只攻击敌人 |

顶尖战技仍可精细施展。规模扩大需要相应传播及玩法支持，不能只把手臂放大、增加一圈特效或把所有动作转成远程投掷。

## 首轮与完整验收

首轮模型接入和执行验证中，至少包括一项没有离体投掷物的真实接触战技，并通过共用动作及部位生成动作或作用明显不同的变体。先验证身体、持物、接触、落空和回收，粒子和拖尾关闭时动作仍应成立。

完整验收覆盖徒手、短兵、长兵、重兵、防御、步法、抓投及非人身体。检查正常动作、目标移动、格挡、中断、失去支撑、器物变化和控制解除。相关反击是单项能力依据实际接触触发，无需固定连招系统。

自主创作、玩家改造、原版、Worldfall 与第一人称、保存恢复、长期执行和并行结果均需实际验证；动作的身体与器物资料不能在兼容转换中丢失。

## 代码与资源接入

核心动作构造、部位关系及数值推进接入 `Source/Core/Skills/`；具体武道、斗气、真元和内容规则归内容层。模型的身体、器官、握持及支撑资料按[模型接入设计](代码结构与模型接入设计.md)加载。重用共同姿态、接触和结果，不再给每个战技另外铺一套延迟动作与结算入口。

| 基础动作资源 | 刺、扫、劈、挑、拍、挡、拨、抓、投及步法，声明所需部位和调整范围 |

| 验收资料 | 动作常速近景、关闭装饰的接触验证、城域或世界规模、两种显示与保存恢复 |

## 7.20 开工范围与验收条件

- [x] 独立创作有一条近身战技方向。现有受理入口采集能接管的实际身体，有已适配的手持器物就能使用真实握点与选定接触面；空手仍用真实部位，非人身体使用自己存在的命名部位和承托。分别生成准备、发力、运动、有效接触和收势，得到可以检查的完整动作资料，不抽取骑士战技编号，不增加另一套执行器。原术派生及现有学习入口保留。
- [x] 手部、步法的时钟和身体占用一致；脚底随实际承托换步，器物至少有两种可区别的接触选择。换下器物或无法绑定时由原规则拒绝，不凭空借用物件。正式请求冻结此次动作；旧等待输入不会按当前人物和新规则重抽。
- [x] 复用同一现成世界、一个修士和一件真实兵器。先核对少量固定种子的不同动作、接触面、落脚和价格；正常战技至少验证一份新构造的付费、实际移动、接触和收势，以及取走器物后的拒绝或结束。非人仍走此前已经验证过的命名部位执行，只补核新创法确实能选到适配来源。用新旧正式等待档核对冻结动作及结果。训练、传承和全套视角录像按后续对应条目交付。

## 7.20 实机交付

人物领悟时先取实际可控制的身体，以及当前手持物能用的握点和接触面。空手可从手、肘、肩、头等实际部位发力，非人动作从已存在的部位和命名足选择。发力路线、落脚、有效接触和收势共用同一段动作；出手仍由现有规则检查场地、控制占用与当前器物。正式等待区段升至 36，新请求使用规则 35；上一版按原规则保留完整输入。无需玩家手动迁移。

实机分段验证。生成段用空手修士、同一把铁剑和一个狼形检查来源与完整构造。实战段的剑尖招式支付 5 点体力，人物实际换步，近战队列确认扣除 77 点生命，收势归还身体控制并保留原剑；取下原剑后施放被拒且无扣费。另起游戏进程恢复规则 34 的真实旧等待档与规则 35 的新剑刃等待档，两份都保持完整成品和原报价、各授予一次。已学剑尖动作也随世界恢复。

## 7.21 实机验证

城市操练沿用原任务、步法和身体控制。只练一人能完成的近身动作；需要另一人配合、材料或改变世界的整招仍在正式施放时使用。开始操练会支付原体力，成功收势才增加既有使用经历。书仍引用世界里的同一正式版本，无需玩家迁移存档。

实机从 7.20 的正式档取出原剑尖战技。原作者通过现有书库传授，重读不重复授予；学习者没佩剑时无法启动该训练。佩剑后走到原假人旁，用原动作支付了 5 点体力，收势时归还身体控制和原铁剑，旁人及假人未受伤。中途退出也归还控制，不增加使用经历。

另一个游戏进程从同一份正式档读回作者、动作、书中版本、学习关系及使用经历，恢复报告未丢弃资料。退出训练留下的冷却正常保留；冷却自然结束后，未附体的学习者对真实敌方自主选中原剑技，支付 5 点体力，正常收势归还身体控制。
