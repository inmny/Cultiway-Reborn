# 具体缺项与关系检查

落实3.07。创建、编辑预览、正式登记和恢复继续共用正式编译与内容检查入口；没有新的类别交集总开关。错误直接说明构造中的位置、缺失的实际内容及资源本身提供的原因，不用另一份默认形体掩盖失败。

## 创建时可以确定的内容

| 资料 | 检查与提示 |
|---|---|
| 能力头部 | 稳定编号、版本、修订、主体或身体、寿命、费用、冷却、作用量和选取距离分别指出实际字段 |
| 真实部位 | 部位编号、形体、材料、子结构和操作集合；明确空值与空列表分别处理 |
| 模型、表面、动作与阶段 | 保留资源自己的缺失编号和可用项，补上实际`Form`、`Surface`、操作`Clip`或阶段字段路径 |
| 父子挂点 | 指出子部位、父形体、未找到的挂点选择及父体的可用挂点 |
| 事件与输出 | 检查真实来源、其能否产生所选事件、依赖循环、输出种类和实际父连接；条件提示保留原操作索引和`When/Source`位置 |
| 身体与持物 | 动作关键点定位到索引及具体坐标字段；内容侧核对已实现的手部和持剑适配、完整握点及资源，不能把永远不可用的动作当作登记成功 |
| 资源与目标方式 | 说明未知支付通道、缺失回收容量、整数支付限制及未实现的目标选取方式 |

例如子剑选择不存在的挂点时，提示包含`root/edge/Anchor`、实际父形体、请求的挂点及可用挂点。第二个操作等待不存在的事件来源时，指向`root/Operations[1]/When/Source`，不再用条件操作在另一列表中的序号冒充作者输入位置。

资源引用错误保留原异常作为原因，只增加构造中的引用位置。没有捕获后返回成功、默认资源或空计划的路径。

## 必须在当次施放检查的内容

具体人物是否仍活着、是否符合关系，以及地图位置是否合法，必须等到使用时核对。创建时只确认选择方式和结构依赖，不把未来的目标写死。

公开的数值施放入口只要求当前结构确实需要的输入：身体动作需要真实身体姿态；根连接需要连接输入；目标相对路径需要目标位置。实际需要的位置须有限，朝向连接须有非零方向，体高缩放须有正体高。没有目标依赖的固定主体无需伪造目标，地点能力不需要伪造人物。

正式人物或地点选取失败会在支付前返回拒绝。现有运行时可用状态仍使用统一主动能力入口；本项不新增界面或更换阻断状态体系。

## 支持边界与保存

普通生成主体可以自由跨形体、材料和已实现过程组合，实际资源与关系成立即可。比如火质鲸体、冰质铜镜形体不因旧流派分类被整体否决。借用身体则必须具有实际适配；当前内容只接通左右手及持剑，其他身体和器物的接管仍按第4工作包实现，缺失时直接说明。

没有改变正式保存格式。恢复时沿用逐构造隔离，坏构造报告具体缺项，有效构造继续读取，原保存输入不被改写；完整世界读取仍由现有保存管理器保留原档和读取报告。

复现：`python3 Scripts/SpellDemos/verify_construction_requirements.py`。结果在`artifacts/skill_rebuild/construction-requirements/`，包含字段缺项、真实目标与支付、跨形体材料，以及混合有效和无效构造的正式恢复检查。回归现有补全、命名输出、全部操作及正式资料合同；不将本项当作新美术或最终视频验收。
