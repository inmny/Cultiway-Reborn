# 多项改造与冲突定位（8.08）

本项完成条件：

- 沿用 [3.05 的资料覆盖顺序](构造合成优先次序.md)：来源先改，玩家最后明确选择，默认只补缺项。部位操作及步骤的明确选择不因重新打开、撤销、保存或播放被重排。时间和已确认的依赖先决定可执行性；同一时点允许的连续换材仍按声明顺序。依赖步骤可以写在生产者前面，执行仍等实际结果。
- 同一部位的单份过程不能被另一个入口悄悄覆盖。统一检查定时、事件、命名步骤的流散、碎解、留置、收束、射线的互斥声明；保留不同部位及允许分阶段相接的操作。不新增调度层，不更改已工作的触发规则。
- 在万法阁的失败提示中给出嵌套目标、当前过程和冲突的另一处。能跳往当前或另一处查看和修改。非法草稿不可保存；撤销或明确删除冲突后恢复。命名引用循环要指出链条。
- 复用现有独立游戏与世界。限定验证一个嵌套构造的重复收束、定位两处、恢复保存，以及同一成品真实施放时的合法同点和依赖顺序。拒绝的草稿不改正式构造。代码、复验入口与证据齐后关闭编号才合并。

实际规则：普通定时、附条件以及命名步骤共享同一部位的独占检查。重复收束等声明不能互相覆盖；同一主体上的射线与留置、流散、碎解，以及射线与其他事件骨架动作，也会指出另一处。玩家可在状态栏选择“定位问题”，跳到普通过程或命名步骤查看，原法术不会因为无效草稿被改写。

实机用同一个三层剑形法术验证。首次已通过重复收束拒绝、普通与命名两处跳转、循环链提示和撤销；脚本在后续点错页签，保留失败记录，只补验受影响的保存段与新补的射线提示。副本重开后仍保留明确消耗和声明顺序。实际施放扣除已保存的 3 点，先完成同一时点的熔铁、冻结，再按已产出的依赖先换成木、后化成水，最后正常收束退出。
