# 地点施放与日常需求

## 范围与顺序

继续7.11及11.21。本批先补齐“正式构造无需活体也能对环境地点施放”，再让已有世界材料产生真实回收需求，触发修士已学的普通回收构造。工作、旅行、修炼、救灾及维护的全部功能内容仍按后续任务逐步接入，不能以这一个用途勾选整个条目。

## 地点与人物

可选`Use`声明战斗、世界或两者，以及本人、人物、地点或人物／地点。缺省继续使用原有战斗和人物选取，本人作用的旧资料保持本人选取。选择类别决定本次输入是否跟随人物；实际接触作用关系仍由原有`Impact`维护。

地点选取不生成临时人物，不要求地点存在敌人。它使用共同地图横纵坐标和离地高度，受地图边界、有限数值、实际选择距离、资源、自身冷却及身体占用约束。已受理的地点固定，人物选取仍按已有规则跟随实际目标。运行、玩家入口和后续日常需求共用正式执行计划。

新增字段为可选资料，旧构造、原有正式存档及待完成创法输入保留原来行为；比较构造实际内容时将缺省规则归一，不因显式填写旧规则就视为另一种新术。

## 第一个真实日常需求

原支付者存在临时留置材料、原资源有可用容量，并且掌握可对地点使用的世界回收构造时，才形成资源回收机会。自主使用要求实际回收操作声明`TemporaryOnly`，永久留置和设施不会被该回收选择拿走；其他支付者的材料也不能被拿走。原有手动回收缺省仍按原规则处理，不能在自主使用时偷改它的实际选择。自主选择使用实际形状预估是否能选中材料及是否有净回收收益；真正选择、逐步收束和资源入账继续由已有世界材料维护者完成。

需求由材料变化或实际学习唤醒，按原支付者排队，限制每轮处理量和重试间隔。无需逐帧扫描地图或所有人物。来源被玩家控制、冻住自主行为、正在交战或已有回收过程时等待；材料结束、已经回收、来源死亡或没有可用的相关知识时移除需求。重载从真实世界材料和已学构造重建机会，不保存临时队列或重复支付。

## 验证要求

检查旧人物和本人选择、有效地点、边界与非法数值、距离和成本、地点固定与人物跟随、角色死亡和实际材料作用。检查没有敌人的修士真实自主选择并支付回收能力，其他人、永久材料、无收益、资源已满及需求结束均不误施放。正式保存后真正重启恢复，世界材料的原支付者、资源份额及已学规则保持，需求不能重放已完成回能。

本批不制作新的美术资源。录像用于检查地点和真实资源过程，不代替流派、城域或最终美术验收。

## 资料接入例子

以下字段写进普通构造，使用现有世界用途和地点枚举，不登记新的整招运行类：

```json
"Use": { "Channels": 2, "Target": 3 }
```

`Channels`的1表示战斗、2表示世界、3表示两者；`Target`的1表示本人、2表示人物、3表示地点、4表示人物或地点。现阶段不接受空类别及尚未实现的面积选择声明。接触的敌我关系和伤害仍分别声明在`Impact`。

日常资源回收读取普通回收操作。以下参数中的临时筛选也用于真正执行，不只用于自主评分：

```json
"Recovery": { "Efficiency": 0.75, "WorldMaterials": true, "TemporaryOnly": true }
```

临时材料来源、位置、回收的原资源和余额读取真实世界记录；已处在世界回收过程中的人物不会再被重复排入同类施放。现有资料未声明新字段时保留原行为。

复现入口为`Scripts/SpellDemos/verify_world_use.script`和`verify_world_use_restart.script`，后者要求另一个游戏进程，并重建测试用静止状态后再读取前者写出的正式保存。准备阶段压低行走速度而没有冻结实际自主验证段，避免普通闲逛离开选取距离。录像过程中只解除等待并观察，不代替人物选择或施放。
