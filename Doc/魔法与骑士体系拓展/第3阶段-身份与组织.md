## 具体说明

### 已确认决策

- 法师学院和骑士团是**王国级职业组织**，在王国内的一座城市设置总部。
- 第一版每个王国最多拥有一个法师学院和一个骑士团，不在同一王国内生成同类组织竞争。
- 角色可以同时加入一个法师学院和一个骑士团，并继续保留现有宗门身份。
- 学派是学院内部的知识方向，由创始人的主元素和法术语义动态生成，不创建第三种组织。
- 每个角色仍然最多只有一位师父；同一师徒关系可传授修仙、魔法和骑士内容。
- 0 至 2 环魔法、骑士觉醒、训练假人和已有九个战技保留个人成长路径；高阶新法术、学院课程、骑士集训和组织权限由组织承担。
- 已经掌握的法术、骑士流派和战技属于个人知识。退出组织或组织覆灭不会删除个人所学。
- 宗门与职业组织保持领域对象平行，但统一使用组织角色、权限、贡献、人事评定和作用域鉴权内核；领域资格由各自 Policy 判断。
- 本阶段只建立当前世界运行期的职业组织基础，不实现世界存档序列化与载入恢复。

### 设计边界

本阶段实现：

- 王国级法师学院与骑士团。
- 宗门、学院和骑士团共用的角色、权限、贡献、人事评定与继任内核，并将现有宗门一次性迁移到该内核。
- 城市总部、迁驻、解散与负责人继任。
- 学院和骑士团相互独立的成员身份、贡献、等级、职司和权限。
- 学院动态学派、课程档案、共同研究和高阶法术教学。
- 骑士团核心流派、训练场、集体操练和同团战术协同。
- 单一师父关系的跨体系资格、教学和出师。
- 组织列表、组织详情、角色组织身份和只读人事展示。

本阶段不实现：

- 同一王国内多个学院、多个骑士团、分院、分团或内部派系分裂。
- 学派独立建制、学派合并、学派战争或学派属性伤害加成。
- 独立领地、跨国招募、组织外交、组织战争和组织联盟。
- 组织库存、制式装备发放、家传武器和组织宝物。
- 誓言、荣誉、背叛、黑骑士、传奇称号和死亡遗产。
- 独门战技、战技改良、法术作者史和知识失传。
- 仪式魔法、区域结界、骑士领域、盾牌、坐骑、远征、灾害和遗迹。
- 玩家手动编辑组织人事或课程；首版由世界 AI 运行，UI 负责观察。
- 职业组织、学院课程、成员槽和师徒关系的世界存档序列化与载入恢复。

第四阶段处理传奇身份与传承，第五阶段处理世界级内容、组织对外行动和远征。本阶段的继任只保证组织岗位连续，不提前生成传奇遗产。

### 总体架构

#### 领域对象平行，人事权限统一

新增 `ProfessionalOrganization` 与 `ProfessionalOrganizationManager`，用 `ProfessionalOrganizationKind` 区分 `MageAcademy` 和 `KnightOrder`。两类职业组织共享王国归属、总部、成员索引和生命周期，学院课程与骑士训练分别由内容层服务组合。

`ProfessionalOrganization` 不继承 `Sect`，`Sect` 也不改造成覆盖所有领域的巨型组织基类。宗门的独立驻地、藏经、宝库、道统和事务仍属于宗门；职业组织的城市总部、课程和集训仍属于职业组织。

统一发生在二者已经真实重复的人事与权限部分：角色槽、角色资产、权限资产、贡献账户、名额、初始任命、晋升、作用域鉴权和继任排序。通用内核通过 Context 读写不同组织的成员状态，通过 Policy 判断修仙、魔法或骑士领域资格，不直接依赖 `Sect`、`Magic` 或 `Knight`。

#### 统一人事与权限内核

| 类型 | 通用职责 |
|---|---|
| `OrganizationPersonnelSchemaAsset` | 定义组织人事 Schema、启用的角色槽、各槽默认角色和本地化槽位名称 |
| `OrganizationRoleSlot` | 统一 `Rank`、`Office`、`Title` 三种角色槽 |
| `OrganizationRoleAsset` | Schema、槽位、排序、权威、显示、默认角色、初始/自动任命、`clearsRank`、通用评分门槛、名额、前置等级/职司和权限 ID |
| `OrganizationPermissionAsset` | 权限名称、说明、图标和 UI 分组 |
| `OrganizationPersonnelScore` | 能力、任期、累计贡献、领域服务证据及总分 |
| `OrganizationPersonnelProfile` | 加入组织时需要授予的初始角色组合 |
| `OrganizationPersonnelEvaluation` | 一次评定在各启用槽位上的目标角色 |
| `IOrganizationPersonnelContext` | 提供组织 ID、Schema、成员列表以及成员角色、贡献和任期的读写入口 |
| `IOrganizationPersonnelPolicy` | 计算领域评分、判断领域资格并提供继任优先级 |
| `OrganizationPersonnelService` | 初始任命、逐级晋升、名额校验、人事评定和通用继任排序 |
| `OrganizationAuthorizationService` | 在指定组织上下文中汇总角色权限并完成鉴权 |
| `OrganizationContributionService` | 增加累计贡献、消费可用贡献和查询余额 |

三个 Schema 的槽位配置：

| Schema | 启用槽位 | 领域显示 |
|---|---|---|
| `Sect` | `Rank`、`Office`、`Title` | 门阶、职司、头衔 |
| `MageAcademy` | `Rank`、`Office` | 学院等级、职司 |
| `KnightOrder` | `Rank`、`Office` | 团员等级、职司 |

学院和骑士团不注册虚假的默认头衔。通用服务只遍历 Schema 启用的槽位；权限取各槽角色权限的并集，权威取各槽角色权威的最大值，不把多角色权威相加。组织等级默认不限人数，职司按 `baseSlots` 和 `membersPerExtraSlot` 计算名额。

角色资产只保存通用行政规则。领域资格不塞入 `OrganizationRoleAsset`：

| Policy | 领域资格 |
|---|---|
| `SectPersonnelPolicy` | 修仙境界、师徒关系、宗门特性、主修功法和衣钵优先级 |
| `AcademyPersonnelPolicy` | 魔法等级、课程掌握、研究/教学证据和学派契合 |
| `KnightOrderPersonnelPolicy` | 骑士等级、核心流派、集训、教学与有效防卫证据 |

物理成员存储不强行统一：`SectPersonnelContext` 继续读取现有 `ActorExtend.sect` 与 `ActorData` 中的宗门角色、贡献和任期；`ProfessionalOrganizationPersonnelContext` 读取 `ProfessionalMemberships` 的学院或骑士团槽。两者向通用服务暴露同一合同，但宗门存档能力不会因职业组织暂不做存档而丢失。

#### 组织作用域权限

权限必须绑定一次具体组织成员关系，统一入口为：

```csharp
OrganizationAuthorizationService.HasPermission(actor, organizationContext, permission);
```

禁止提供不带组织上下文的全局 `HasOrganizationPermission`。同一角色可能同时属于宗门、学院和骑士团；学院院长的招募权限不能用于骑士团，宗门长老的藏经权限也不能用于学院课程。

通用权限使用统一 ID，例如招募成员、人事评定、提拔成员和管理组织；领域权限继续使用各自命名空间：

| 范围 | 首批权限示例 |
|---|---|
| 通用 | `RecruitMember`、`EvaluatePersonnel`、`PromoteMember`、`ManageOrganization`、`RelocateHeadquarters` |
| 宗门 | 阅读/编写藏书、管理宝物、带徒入宗、处理宗门事务 |
| 学院 | `LeadResearch`、`TeachCourse`、`ApproveCourse` |
| 骑士团 | `LeadDrill`、`CommandFormation`、`EvaluateService` |

通用动词可以复用同一个权限资产，但鉴权结果始终由传入的组织 Context 决定。

#### 职业组织数据

| 对象 | 运行时字段 | 职责 |
|---|---|---|
| `ProfessionalOrganizationData` | 类型、王国 ID、总部城市/建筑 ID、创始人与负责人信息、创建时间、生命周期状态 | 组织身份与稳定引用 |
| `AcademyDoctrineData` | 主元素语义 ID、最多两个重点语义 ID、显示名称片段、课程记录 | 学派身份、课程查询和高阶授权 |
| `KnightOrderDoctrineData` | 核心 `KnightStyleAsset.id`、显示名称片段 | 集训内容和战术职责来源 |
| `ProfessionalMembershipData` | 组织 ID、角色 ID、加入时间、累计/已消费贡献、行为证据与最近集训时间 | Context 的职业组织成员状态 |
| `ProfessionalMemberships` | 学院槽与骑士团槽 | 允许同一角色同时加入两类职业组织 |
| `ProfessionalOrganizationIndex` | 王国到两类组织、组织到成员、建筑到组织的映射 | 有界查询与生命周期清理 |

角色运行时使用一个包含两个明确成员槽的 ECS 组件：学院槽和骑士团槽。它们不能复用 `ActorExtend.sect`、宗门角色 ID 或宗门贡献字段，也不能用一个互斥的“当前职业组织”字段代替。

组织等级只表达成员在组织中的资历和访问权，`Magic.CurrLevel` 与 `Knight.CurrLevel` 仍是角色力量等级的唯一来源。职司只表达讲师、教官、院长、团长等职责，不再增加一套组织战力等级。

宗门迁移必须一次性完成：`SectRoles` 与 `SectPermissions` 保留为宗门内容目录，但注册通用角色/权限资产；原 `SectPersonnelEvaluator` 的通用算法进入 `OrganizationPersonnelService`，宗门专有资格进入 `SectPersonnelPolicy`。不得长期保留新旧两套评定、权限或贡献算法。

#### 运行时状态边界

第三阶段不实现职业组织及其依赖状态的世界存档。组织、学院课程、两个成员槽、组织贡献、师徒关系扩展和集训记录都以当前世界会话中的 Manager 与 ECS 状态为准。

因此本阶段不新增：

- `SavedMap`、`SaveManager` 或自定义数据中的职业组织保存/载入补丁。
- 职业组织存档格式、版本迁移和载入恢复逻辑。
- 为保存目的复制现有法术、骑士流派或师徒长期状态的代码。

运行时基础必须满足：

1. `ProfessionalOrganizationManager` 维护每个王国每类组织唯一性，并提供按组织 ID、王国和类型查询的稳定入口。
2. 加入、退出、角色死亡和角色改变王国时，成员槽与组织成员索引原子更新。
3. 总部建筑创建、移除和转属时，建筑索引与组织生命周期状态同步更新。
4. 组织解散时清除全体成员的对应槽、任务认领、课程所有权和总部绑定，不影响另一职业组织、宗门或个人知识。
5. `MapBox.clearWorld()` 时清空组织 Manager、课程 Registry、成员索引、师徒索引和协调组，不能把旧世界引用带入新世界。
6. 周期校验只处理已标脏组织，不通过逐组织扫描全世界角色和建筑来修复索引。

保存并重新载入世界后的职业组织恢复不属于本阶段范围和验收标准。

### 核心玩法闭环

#### 法师学院

1. 王国内出现满足资格的中阶法师与同伴。
2. 王国在候选城市完成学院总部建设并成立学院。
3. 创始人的主元素与法术语义生成一份稳定学派画像。
4. 学员通过基础讲习、研究协助和城市魔法工程获得贡献。
5. 研究团队在学院共同研究与学派相符的高阶魔网条目，形成首门高阶课程。
6. 研究员消费可用贡献学习课程；成功学习后法术永久属于个人。
7. 讲师把课程传给后续成员，研究成果和教学结果继续产生贡献。
8. 成员按魔法等级、累计贡献和真实研究/教学证据晋升，最终形成院长继任序列。

学院的价值是汇集、筛选、生产和传播高阶知识，不是给全体成员增加元素伤害、魔力或研究速度光环。

#### 骑士团

1. 王国内出现中阶骑士、兵营和训练假人。
2. 王国完成骑士训练场建设，创始人的一个已掌握流派成为骑士团核心流派。
3. 新成员继续通过原有训练假人自由操练，也可在教官带领下集体掌握核心流派。
4. 同团成员完成真实集训，记录一段有限期的编队准备状态并获得贡献。
5. 三名以上准备充分的同团骑士在战斗中组成协调组。
6. 守卫、枪骑和决斗家依据现有九个战技承担保护、突击和单挑职责，AI 调整目标与招式权重。
7. 训练、首次传授流派和有效防卫产生贡献，成员按等级、贡献和服役证据晋升。
8. 教官、队长和团长负责后续训练、招募和继任。

骑士团的价值是规模化训练和集体战术，不增加隐藏攻击、防御、命中或斗气恢复倍率，也不回锁第二阶段已经开放的战技。

### 共享组织规则

#### 数量与归属

- 每个存活文明王国最多一个学院和一个骑士团。
- 组织始终归属创建它的王国；总部只是驻地，不决定组织效忠。
- 成员可以居住在所属王国的其他城市，高阶课程、正式集训和人事评定必须前往总部。
- 角色离开所属王国时自动退出该王国的学院和骑士团。
- 城市在同一王国内迁移或角色在本国城市间迁居不改变成员身份。

#### 创立条件

以下数值是第一轮实机调参起点：

| 条件 | 法师学院 | 骑士团 |
|---|---|---|
| 王国限制 | 尚无学院 | 尚无骑士团 |
| 最低人数 | 至少 3 名成年魔法师 | 至少 3 名成年骑士 |
| 创始人 | 魔法 3 级，掌握至少 2 个基础法术族 | 骑士 3 级，掌握至少 1 个流派 |
| 总部城市 | 人口至少 60、一级大厅、至少 2 名常住法师 | 人口至少 50、一级大厅、兵营和可用训练假人 |
| 启动校验 | 学派画像在魔网中存在至少 1 个可研究的 3 至 4 环候选 | 至少 2 名候选成员持有核心流派兼容武器 |
| 建设结果 | 完成 `MageAcademy` 后创建组织 | 完成 `KnightTrainingGround` 后创建组织 |

创立条件不得要求组织贡献、组织职司、现成高阶导师或组织课程，避免第一个组织无法产生。

候选创始人按职业等级、知识/流派覆盖、领导属性、城市稳定性和稳定角色 ID 确定；候选总部按本类职业者数量、人口、建筑条件和与王国其他城市的平均距离确定。相同输入必须得到稳定结果。

#### 生命周期

| 事件 | 处理 |
|---|---|
| 负责人死亡、退会或改变王国 | 立即按职司、等级、累计贡献、职业等级、任期和角色 ID 选继任者 |
| 无完全合格继任者 | 最高分成员成为代理负责人；可维持招募和迁驻，不放宽高阶课程资格 |
| 总部建筑被毁 | 进入 `Relocating`，暂停高阶课程和正式集训，启动本国新总部工程 |
| 总部城市被敌国占领 | 组织仍效忠原王国，解除旧建筑绑定并迁往原王国其他城市 |
| 原王国暂时没有合法总部城市 | 保持迁驻状态并给予 5 年恢复期 |
| 王国覆灭 | 解散组织，清除成员身份和组织任务，保留个人法术、流派和战技 |
| 连续 10 年没有成员 | 若王国内无可招募职业者则解散；否则先任命代理负责人并重启招募 |
| 被占领的旧总部 | 清除组织绑定，按普通城市建筑或废墟处理，不生成第四阶段遗产 |

所有征服、毁灭和迁驻事件只标记组织待协调；下一逻辑帧由 `ProfessionalOrganizationLifecycleService` 在原版城市与王国状态稳定后统一结算，不能在原版转属调用栈中直接迁移成员和建筑。

- 宗门外门、内门、亲传、执事、长老、掌门和衣钵传人的门槛、名额、权限与继任行为保持不变。
- 宗门、学院和骑士团均通过同一个人事与权限内核完成角色查询、贡献读写和鉴权。

- 调试入口能够创建两类职业组织、让一个角色同时加入两者，并验证退出、解散和清空世界不会破坏其他成员关系。

### 步骤 2：实现组织创立、总部与生命周期

新增两类城市总部建筑：

| 建筑 | 定位 | 必须具备的功能 |
|---|---|---|
| `MageAcademy` | 学院总部 | 共同研究、课程讲授、人事评定和课程档案地点 |
| `KnightTrainingGround` | 骑士团总部 | 集体操练、教官授课、人事评定和协调组集结地点 |

两者都是原版城市建筑，参与城市征服、毁灭和寻路。不得复用 `AsSectBuilding()`，因为宗门建筑明确脱离城市所有权，与本阶段“王国组织、城市总部”的决策相反。

创立流程：

1. 年度 `ProfessionalOrganizationFoundingPlanner` 扫描尚缺组织的王国。
2. 分别校验创始人、同伴、候选城市和启动知识/武器条件。
3. 通过 `CollectiveProjectService` 创建唯一总部建设工程。
4. 工程完成后创建组织，绑定王国、城市、建筑和创始成员。
5. 生成组织名称与领域画像，任命负责人并写入创始成员槽。
6. 发出世界日志，开放招募和组织任务。

名称使用确定性模板和现有本地化词素：

- 学院名由王国/总部名、主元素和重点语义组成，例如“白焰塑能学院”。
- 骑士团名由王国/总部名与核心流派组成，例如“北境守卫骑士团”。
- 创立后名称和学派画像保持稳定；创始人死亡、换法术或换武器不重算。

本步骤同时接入负责人继任、总部迁驻、组织解散、角色改变王国和总部建筑移除事件。迁驻期间成员身份保留，但所有需要总部的任务返回明确的不可执行原因。

### 步骤 3：实现成员、贡献、晋升与继任

#### 成员规则

- 招募对象必须成年、存活、与组织同王国并拥有对应 `Magic` 或 `Knight`。
- 学院成员不妨碍加入骑士团，骑士团成员不妨碍加入学院，两者都不妨碍宗门身份。
- 已有师父不是拒绝组织招募的理由；组织讲师和教官也不会自动成为个人师父。
- 同类成员槽已有其他组织时不能加入；首版每王国同类组织唯一，因此通常只在王国转属清理异常中出现。
- 退出时清空该槽的等级、职司和组织贡献，不触碰另一成员槽、宗门贡献或个人知识。

#### 组织等级

| 组织 | 等级 | 初始门槛 | 主要权限 |
|---|---|---|---|
| 学院 | 学员 | 加入学院 | 基础讲习、研究协助、提交知识 |
| 学院 | 研究员 | 魔法 3 级、累计贡献 30、完成至少 1 次研究协助 | 学习 3 环以上课程、参与课程立项 |
| 学院 | 高阶研究员 | 魔法 6 级、累计贡献 120、掌握至少 2 门高阶课程并完成 1 次有效研究 | 候选讲师、教务长和院长 |
| 骑士团 | 见习团员 | 加入骑士团且掌握至少 1 个流派 | 基础集训、服务任务 |
| 骑士团 | 正式团员 | 骑士 3 级、累计贡献 30、完成至少 3 次有效集训 | 正式编队、候选教官 |
| 骑士团 | 资深团员 | 骑士 7 级、累计贡献 120、掌握核心流派并完成至少 1 次教学或有效防卫 | 候选队长和团长 |

组织等级不设人数名额。岗位满员不能阻止成员等级晋升、课程学习或继续获得贡献。

#### 组织职司

| 组织 | 职司 | 名额与前置 | 职责 |
|---|---|---|---|
| 学院 | 讲师 | 每 6 名成员 1 名；研究员、贡献 60 | 讲授课程、带领基础研究 |
| 学院 | 教务长 | 1 名；高阶研究员、贡献 180、曾任讲师 | 人事评定、课程审核、代理院长 |
| 学院 | 院长 | 1 名 | 招募、课程、迁驻和完整管理权限 |
| 骑士团 | 教官 | 每 6 名成员 1 名；正式团员、贡献 60、掌握核心流派 | 教授核心流派、带领集训 |
| 骑士团 | 队长 | 每 12 名成员 1 名，至少 1 名；资深团员、贡献 180、曾任教官 | 组织协调组、代理团长 |
| 骑士团 | 团长 | 1 名 | 招募、训练、迁驻和完整管理权限 |

负责人创立时使用一次明确的 `OrganizationPersonnelProfile`：首任院长获得研究员等级与院长职司，首任团长获得正式团员等级与团长职司，不要求先取得尚不存在的组织贡献或活动证据。其他创始成员仍从最低等级加入，后续晋升与继任不使用这个创立例外。

#### 权限与领域资格

等级主要表达课程、集训和晋升资格，不负责组织管理；职司通过 `OrganizationRoleAsset.permissionIds` 授予管理行为：

| 组织 | 职司 | 首批权限 |
|---|---|---|
| 学院 | 讲师 | `TeachCourse`、`LeadResearch` |
| 学院 | 教务长 | `EvaluatePersonnel`、`PromoteMember`、`ApproveCourse` |
| 学院 | 院长 | `ManageOrganization`、`RecruitMember`、`RelocateHeadquarters` 及全部学院权限 |
| 骑士团 | 教官 | `LeadDrill` |
| 骑士团 | 队长 | `EvaluatePersonnel`、`PromoteMember`、`CommandFormation` |
| 骑士团 | 团长 | `ManageOrganization`、`RecruitMember`、`RelocateHeadquarters` 及全部骑士团权限 |

课程环位、魔法等级、骑士等级、流派和行为证据由对应 Policy 校验，不伪装成权限。一次操作必须同时满足成员属于传入组织、角色授予所需权限和领域服务自身的业务前置。

#### 贡献账本

`OrganizationContributionService` 通过当前组织 Context 读写 `TotalContribution` 与 `SpentContribution`：

- 每一份组织成员关系拥有独立账户；宗门、学院和骑士团互不共享。
- 晋升和职司判断只读取累计贡献。
- 课程或特殊训练只消费可用贡献 `Total - Spent`。
- 消费贡献不会降级，也不会影响角色的其他组织。
- 所有贡献必须来自已完成且产生领域结果的事件，不能按待机时长、站在建筑内或空放技能发放。

首轮贡献值：

| 行为 | 学院贡献 | 骑士团贡献 | 防刷约束 |
|---|---:|---:|---|
| 完成一次有效基础研究/集训 | 参与者 2 | 参与者 3、负责人 6 | 同角色每年最多 6 次 |
| 首次让成员学会一门课程/核心流派 | 学员 6、讲师 8 | 学员 8、教官 8 | 按成员与知识 ID 只结算一次 |
| 共同研究形成一门新课程 | 主持 15、参与者 6 | - | 重复结构、失败研究不给贡献 |
| 改良并录入学派相符的新法术 | 12 | - | 按结构签名只结算一次 |
| 完成已验收的城市魔法工程 | 10 | - | 按工程 ID 只结算一次 |
| 击败战力不低于自身 30% 的敌人 | - | 2 | 仅敌对战争/防卫；每年上限 20 |
| 完成一次总部或本国城市有效防卫 | - | 12 | 按战斗事件只结算一次 |

研究员学习高阶课程时，成功结算后消费 `4 + 2 × 环位` 可用贡献；学习失败不消费。骑士在训练场首次通过教官直接掌握核心流派时消费 10 可用贡献，普通训练假人仍可免费按现有规则自行掌握流派。

`OrganizationPersonnelService` 每年对三个 Schema 分别执行一次评定，只允许逐级晋升。通用服务处理角色顺序、名额、通用评分和前置等级/职司，领域 Policy 检查职业等级与真实证据。已有合格任职者不会因为出现更高分成员被频繁撤换，只有空缺、失格或负责人继任时重新任命。

继任使用同一排序管线：领域 Policy 优先级、角色最大权威、人员总分、任期、稳定角色 ID。宗门 Policy 可把衣钵传人置于最前；学院优先教务长，骑士团优先队长。

### 步骤 4：实现法师学院、动态学派与高阶课程

#### 基础与高阶边界

| 环位 | 个人路径 | 组织路径 |
|---|---|---|
| 0 至 2 环 | 继续允许魔网自学、卷轴研读、个人师父教学和个人改良 | 学院可讲授但不垄断 |
| 3 至 12 环 | 已掌握法术可继续施放；不能在组织外取得新的高阶版本或让改良跨入高阶 | 必须由有效学院课程授权，并满足个人等级、亲和、容量和贡献要求 |

新增 `MagicSpellLearningAccessService` 作为所有“获得新法术版本”的统一入口。`MagicWebStudyPlanner`、`MagicScrollStudyService`、个人改良、学院课程和魔法师父教学都调用该服务，不能分别复制高阶判断。

`MagicSpellKnowledgeSource` 同步增加学院课程与个人师承来源；来源只记录知识历史，不绕过统一准入，也不改变技能容器所有权。

规则：

- 角色退出学院后保留已经学会的高阶法术并可正常施放。
- 组织外的个人改良只能产生 0 至 2 环结果；会跨入 3 环以上的候选必须转为学院共同研究。
- 高阶卷轴必须先被学院研究并录入课程，不能由个人直接绕过课程学习。
- 高阶同族升级和全新法术族都需要课程授权。
- 课程学习继续服从现有最大环位、元素亲和与法术容量；容量已满时复用既有严格替换规则。

#### 动态学派画像

学院创立时生成一份 `AcademyDoctrineData`：

1. 使用创始人灵根的主元素语义作为 `PrimaryElementSemanticId`。
2. 聚合创始人已掌握法术的效果、角色和轨迹语义，排除通用语义与元素重复项。
3. 按出现次数、法术环位和魔网高阶候选覆盖率选择最多两个 `FocusSemanticIds`。
4. 要求该画像在魔网中至少覆盖一项创始人可理解的 3 至 4 环候选，否则不满足学院创立条件。
5. 记录语义资产 ID 和名称词素；创立后不随个人状态自动漂移。

课程契合分数采用简单可解释规则：主元素匹配记 2 分，每个重点语义匹配记 1 分，至少 2 分才允许录入课程。该分数只选择知识，不修改伤害、法力或研究速度。

第一版每个学院只有一个学派画像。学派分裂、合并、休眠和新学派建制留到后续阶段。

#### 课程档案

每个 `AcademyCourseRecord` 在当前世界会话中记录：

- 由课程 Registry 持有的不可变 `SkillContainer` 实体。
- 法术结构签名以及冻结的环位、主元素与语义档案。
- 提交者角色 ID/名称、录入时间和来源。
- 已成功学习的成员 ID 集合，用于防止重复教学贡献。

课程录入时克隆候选为课程专属不可变容器，并由 `AcademyCourseRegistry` 持有其生命周期。魔网动态条目过期不能回收仍被课程持有的容器；学院解散时释放课程所有权，已经由角色掌握的版本继续由角色技能所有权维持。

#### 首门高阶课程

首门课程不能要求现成高阶导师：

1. 院长从符合学派画像、环位 3 至 4 且不重复的魔网条目中选择候选。
2. 至少 1 名魔法 3 级主持人与 2 名学院成员在总部参与 6 至 18 个月共同研究。
3. 研究进度由参与者智力、元素亲和与候选难度持续结算，不在结束时进行一次纯随机判定。
4. 完成后克隆并冻结课程容器、录入课程，并让符合容量条件的主持人学习。
5. 课程成为后续讲师教学的稳定来源。

学院后续可以录入成员改良法术、研究合格卷轴或继续研究魔网条目；三条入口最终共用同一课程审核和去重服务。

### 步骤 5：实现骑士团、训练场与集体战术

#### 核心流派

骑士团创立时从创始人已掌握流派中选一个 `KnightStyleAsset.id`：

- 当前真实武器匹配的流派优先。
- 多个候选并列时按流派展示顺序和稳定 ID 决定。
- 创立后核心流派不随团长换武器或继任自动改变。
- 核心流派只决定训练和组织战术倾向，不删除成员的其他流派。

原有训练假人规则保持不变：角色仍可携带斧锤、矛或剑自行解锁守卫、枪骑或决斗家；0、3、7 级战技仍按第二阶段规则自动开放。

#### 训练场集训

| 集训 | 人数与条件 | 结果 |
|---|---|---|
| 核心流派入门 | 1 名教官、2 至 7 名见习成员；学员持兼容真实武器 | 完成后首次掌握核心流派，结算教学贡献 |
| 编队操练 | 1 名教官/队长、至少 3 名正式成员；成员掌握任一当前武器匹配流派 | 记录最近有效集训时间，开放有限期同团战术协同 |
| 防卫复盘 | 战后 1 名队长、至少 2 名参战成员 | 只记录服务证据和贡献，不提供属性加成 |

集训使用现有 `CoordinatedActivityService`，成员真实前往训练场并执行原版武器训练动作。换装为不兼容武器、离开组织、负责人失效、总部迁驻或成员进入真实战斗时取消尚未完成的训练。

最近一次编队操练在 5 个游戏年内有效。该期限记录在骑士团成员槽，不创建独立状态实体。

#### 同团战术协同

满足以下条件时建立临时协调组：

- 至少 3 名同一骑士团成员处于相近战区。
- 成员的最近编队操练仍有效。
- 至少一名队长、教官或最高资历正式成员可以担任临时指挥者。
- 所有成员仍持有能够使用其当前流派的真实武器。

协调组只向既有战术 AI 提供目标和权重信号：

| 当前流派 | 组织职责 | 额外决策信号 |
|---|---|---|
| 守卫 | 稳定阵线、保护同团低血成员 | 提高格挡、震退和守护壁垒对受威胁同伴的权重 |
| 枪骑 | 打开缺口、攻击后排或敌群中心 | 由指挥目标与直线路径共同提高冲锋、坠击权重 |
| 决斗家 | 截击孤立强敌和敌方高价值角色 | 避开守卫控制区中的普通目标，优先孤立目标 |

不得给协调组增加攻击、防御、闪避、命中、斗气恢复或技能倍率。普通 AI、战术 AI 和玩家主动施放仍共用第二阶段执行入口；组织只影响 AI 如何协同选择已有动作。

### 步骤 6：将师徒系统泛化到修仙、魔法与骑士

#### 单一关系合同

保留“弟子最多一位师父”，重构 `MasterApprenticeRelation`：

- `Master` 使用运行时 Entity 关系，并由 `MentorshipIndex` 维护反向索引。
- `RelationTypeId`、`Intimacy`、`ApprenticeTime` 和 `IsSuccessor`。
- `PrimaryDomain`：`Xian`、`Magic` 或 `Knight`，用于招募资格与出师判断。
- `SuccessfulTeachingCount` 与必要的领域教学证据。

移除核心关系资产中的宗门门阶映射，也不在通用 `OrganizationRoleAsset` 中增加师徒专用字段。`SectPersonnelPolicy` 通过 `SectMentorshipPolicy` 判断宗门角色所需的师徒层级；学院和骑士团的角色 Policy 不依赖宗门角色 ID。

#### 师父资格

| 主教学方向 | 最低资格 | 可传内容 |
|---|---|---|
| 修仙 | 维持现有金丹、主修功法和掌握度要求 | 功法及现有修仙教学内容 |
| 魔法 | 魔法 3 级，掌握至少 3 个法术族 | 双方满足准入的基础法术；同学院课程中的高阶法术 |
| 骑士 | 骑士 3 级，掌握至少 1 个流派 | 在训练假人或骑士训练场通过真实武器教授流派 |

多体系角色的最大弟子数取其最强合格方向对应容量，不把三个体系容量相加。首轮容量仍采用 2、5、10 三档。

招募要求：

- 双方存活、成年、同王国且弟子尚无师父。
- 至少存在一个师父真正能教、弟子尚未掌握的共同方向。
- 双方若属于不同宗门，继续遵守现有跨宗门限制。
- 基础教学不要求职业组织；高阶学院课程必须同学院，骑士团正式集训必须同骑士团。
- 组织讲师、教官和集体课程不会自动创建个人师徒关系。

#### 教学 Provider

将 `BehTeachApprentice` 中只选择主修功法的逻辑替换为三个明确 Provider：

| Provider | 候选与结算 |
|---|---|
| `XianMentorshipTeachingProvider` | 复用现有功法掌握和传授效率 |
| `MagicMentorshipTeachingProvider` | 按法术族、环位、亲和、容量和学院课程授权选择法术 |
| `KnightMentorshipTeachingProvider` | 选择师父已掌握、弟子未掌握且弟子当前武器兼容的流派，完成真实联合训练后授予 |

通用 Planner 按弟子知识缺口、主教学方向、当前地点和教学成本选择一次内容。成功教学统一增加亲密度和教学计数，不能由行为与领域服务重复结算。

师徒反向查询改由 `MentorshipIndex` 维护，不再让 `GetApprentices()` 每次扫描全部存活角色。

#### 出师

弟子满足以下条件时可以出师：

- 关系至少达到正式层级且亲密度不低于 30。
- 至少完成一次有效教学。
- 弟子已经达到其 `PrimaryDomain` 的师父资格。

出师删除运行时师徒关系并更新反向索引，但不删除已学知识、组织身份和历史教学证据。衣钵、死亡传承和传奇师承仍属于第四阶段。

### 步骤 7：接入组织 AI、跨城调度与事件贡献

新增统一 `ProfessionalOrganizationDuty` 工作和领域任务 Planner，不为每种课程、训练和贡献来源创建永久 ActorJob。

候选任务：

| 类型 | 任务 | 参与者 |
|---|---|---|
| 学院 | 基础讲习、课程学习、共同研究、课程审核、城市魔法工程 | 学员、研究员、讲师、负责人 |
| 骑士团 | 核心流派入门、编队操练、防卫复盘、招募与评定 | 团员、教官、队长、负责人 |
| 共享 | 招募、人事评定、总部迁驻建设、负责人继任协调 | 拥有相应权限的成员 |

跨城成员通过现有城市旅行能力前往总部；任务完成、取消或总部失效后清理目标，不把角色永久迁入总部城市。

双组织成员采用单一活动认领状态：

1. 紧急防卫和总部迁驻优先。
2. 已经开始的有效研究或集训优先完成。
3. 普通候选按最长未参与时间、预期领域收益和稳定组织类型顺序选择。
4. 完成组织任务后设置短冷却，防止学院或骑士团长期占满角色日常工作。
5. 组织任务不能抢占真实战斗、生育和明确的生存需求。

贡献由领域事件服务结算，不由 AI 行为末尾直接增加：

- 学院监听课程录入、学习成功、法术发布和城市工程验收。
- 骑士团监听集训成功、首次流派教学、有效敌对击杀和城市防卫结果。
- 每个事件携带稳定事件键，由成员槽的结算记录或年度计数防止重复。

战斗 AI 只读取已经形成的骑士团协调上下文，不直接查询总部、贡献或晋升逻辑。

### 步骤 8：补齐组织 UI、本地化与视觉资源

#### UI

新增统一职业组织窗口，学院和骑士团共用窗口壳并按类型替换领域页：

- **概览**：名称、类型、所属王国、总部、状态、创始人、负责人、创建时间和领域画像。
- **成员**：等级与职司分组、职业等级、累计/可用贡献、任期和当前状态。
- **学院课程**：学派主元素、重点语义、课程环位、法术详情、提交者和学习人数。
- **骑士训练**：核心流派、最近集训、当前教官/队长和可形成的协调组。

入口：

- 信息 Tab 增加职业组织列表，使用“学院 / 骑士团”分段页。
- 王国详情增加职业组织入口，显示该王国当前两类组织与总部状态。
- 角色信息增加组织身份页，分别显示学院、骑士团、等级、职司和贡献；宗门页保持独立。
- 点击组织名或固定图标打开组织详情；列表 Row 根节点不绑定 Tooltip。

实现遵循 `Prompts/UI.md`：使用 `UiTabbedWindowAdapter`、`UiScrollPane`、`UiSegmentedTabs`、`UiListRowChrome`、对象池 Row 和原版窗口返回历史；不创建巨型 UI 工厂，不在业务窗口硬编码公共颜色、间距或原版 sprite 路径。

将现有宗门人事分组展示抽成 `UiOrganizationPersonnelElement`，通过 `IOrganizationPersonnelContext` 和 Schema 渲染启用槽位、角色、权威与权限。宗门窗口、学院窗口和骑士团窗口共用列表与角色 Tooltip，课程、训练、藏经和宝物等领域页保持独立。

首版 UI 只读。晋升、课程审核和迁驻由 AI 服务执行，不放置尚未实现的管理按钮。

- 动态学派画像。

- 数值调整、组织灾难恢复、世界清理和大世界性能验证。

## 验收标准

### 人事与权限内核

- 宗门、学院和骑士团分别注册 `Sect`、`MageAcademy`、`KnightOrder` Schema，并共用角色、权限、贡献、人事评定与鉴权 Service。
- 宗门启用 `Rank/Office/Title`，学院和骑士团只启用 `Rank/Office`；未启用槽位不创建虚假默认角色。
- 宗门现有外门、内门、亲传、执事、长老、掌门和衣钵传人的初始授予、晋升门槛、名额、显示顺序、权限与继任结果保持一致。
- 权限检查必须携带组织 Context；同一角色的宗门、学院和骑士团权限不能互相满足另一组织的操作。
- 成员权限取当前组织启用槽位角色权限的并集，权威取最大值而不是相加。
- `OrganizationPersonnelService` 只处理通用行政规则；修仙师徒、学院课程和骑士服役资格分别只存在于对应 Policy。
- 三份成员关系各自拥有累计/已消费贡献；任何组织的增加、消费和清除都不改变另外两份账户。
- 原 `SectPersonnelEvaluator`、`HasSectPermission` 和宗门子系统中不再保留第二套角色排序、名额、贡献或权限算法。
- 共用人事 UI 能按 Schema 显示正确槽位名称和角色分组，宗门领域页面与学院/骑士团领域页面仍相互独立。

### 组织与成员

- 每个王国每类组织最多一个；并发创立检查不会生成重复总部或重复组织。
- 同一角色可以同时拥有学院、骑士团和宗门身份，三套贡献、职司和任务状态互不覆盖。
- 角色改变王国后退出原王国职业组织，但保留个人法术、流派和战技。
- 组织等级没有名额限制；职司满员不会阻塞个人等级晋升。
- 消费可用贡献后累计贡献不下降，也不会导致降级。
- 负责人死亡、退会或转国后在一个组织逻辑周期内产生确定性继任者或代理人。
- 总部被毁或被敌国占领后进入迁驻，原王国仍存在时可在其他城市恢复。
- 王国覆灭后组织、成员槽、组织任务和建筑绑定全部清理。

### 学院

- 无学院角色可以从魔网、卷轴、个人改良和师父处取得 0 至 2 环法术。
- 3 环以上的新法术版本不能通过魔网、卷轴、个人改良或个人师父绕过学院课程。
- 两名只掌握基础法术的助手与一名魔法 3 级主持人可以共同形成学院第一门高阶课程。
- 学派画像由真实元素和法术语义生成，创立后保持稳定且不提供属性加成。
- 重复结构、超出环位、亲和不足、容量不合法或不符合学派的候选不能录入课程。
- 学院课程由课程 Registry 持有独立不可变容器；魔网动态条目过期不会回收仍在使用的课程。
- 退出学院后已经学会的高阶法术仍可施放，但不能继续取得未授权高阶版本。

### 骑士团

- 原有训练假人仍能按真实武器解锁三个流派，0、3、7 级战技开放规则不变。
- 教官集训只在学员携带兼容真实武器且完成完整训练后授予核心流派。
- 普通训练假人路径不消费骑士团贡献。
- 三名以上近期完成编队操练的同团成员可以形成协调组；过期、退会或换为不兼容武器后立即退出。
- 协调组只改变已有战技的目标与 AI 权重，不修改角色属性、技能倍率或玩家主动施放结果。
- 守卫、枪骑和决斗家在混合编队中分别出现保护、突击和截击行为。
- 击杀弱敌、非敌对对象、空放技能和重复训练不能无限刷取贡献。

### 师徒

- 一个弟子任何时刻最多存在一个有效师父关系。
- 修仙、魔法和骑士角色都能按各自资格收徒，混合体系角色的弟子容量不叠加。
- 魔法师父不能在不同学院间传授高阶课程，骑士教官不会自动成为个人师父。
- 一次成功教学只结算一次亲密度、教学证据和组织贡献。
- `GetApprentices()` 使用反向索引，不随全世界人口线性扫描。
- 出师只删除关系，不删除个人知识和组织身份。

### 运行时与性能

- 创建、加入、退出、角色死亡、转国和组织解散会原子更新成员槽与全部反向索引。
- 负责人、总部、成员或课程引用失效后，在一个组织逻辑周期内完成清理，不持续报错。
- 学院解散会释放课程 Registry 所有权；仍被角色掌握的技能容器不会被误回收。
- `MapBox.clearWorld()` 后，组织 Manager、课程 Registry、成员/师徒索引、任务认领和协调组均为空。
- 1000 名职业角色、20 个王国和两类组织并存时，年度评定、成员索引和师徒查询不产生逐组织全人口重复扫描。
- 100 名同团骑士参与持续战斗时，协调组、任务认领和事件去重记录不会持续累积。

### UI 与资源

- 组织列表在空列表、单项、一页边界和长列表下保持统一留白与可用滚动条。
- 学院/骑士团分段页、组织详情各页、王国入口和角色身份页均可重复开关且返回历史正确。
- 总部迁驻、负责人空缺、课程为空、成员为空和组织解散前状态都有明确只读展示。
- 中文、英文和长名称不会覆盖图标、贡献值或右侧状态区。
- 两座建筑的主图、缩略图、废墟和建造状态均能正确加载。

### 构建与游戏验证

- `dotnet build Cultiway.csproj -c Debug` 无错误。
- 回归验证宗门建宗、招募、师徒门阶、贡献晋升、职司名额、藏经/宝物权限、人事评定和掌门继任。
- 为同时拥有宗门、学院和骑士团身份的角色逐项验证权限作用域，确认管理操作不能跨组织执行。
- 新世界从无组织自然形成学院和骑士团，且首个高阶课程、首次正式集训都能自然完成。
- 手动验证总部城市被占领、建筑被毁、负责人死亡、角色转国、王国覆灭、组织解散和清空世界。
- 分别验证只有学院、只有骑士团、双组织成员、同时拥有宗门以及魔法骑士角色。
- 至少运行 100 个游戏年，确认组织数量、课程数量、任务认领和贡献记录保持有界。

## 提交拆分建议

1. `refactor(organization): 统一宗门人事与权限内核`
2. `feat(organization): 建立职业组织基础`
3. `feat(organization): 增加总部、成员与组织晋升`
4. `feat(magic): 增加学院学派与高阶课程`
5. `feat(knight): 增加骑士团集训与战术协同`
6. `feat(mentorship): 泛化跨体系师徒教学`
7. `feat(ui): 完善职业组织展示与资源`

每个提交保持可构建；批次 A 完成后必须先通过宗门全量人事权限回归，以及职业组织创建、加入、权限隔离、退出、解散和清空世界验证。批次 B 和批次 C 分别形成可独立实机验证的学院与骑士团闭环。
