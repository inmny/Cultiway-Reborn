## 具体说明

### 设计边界

本阶段实现以下内容：

- 守卫、枪骑、决斗家三个初始流派。
- 每个流派三个战技，共九个。
- 流派训练、永久解锁和武器自动切换。
- `Vigor` 支付、独立冷却、真实武器伤害和临时战斗状态。
- 普通 AI、战术 AI 和玩家控制共用的主动能力入口。
- 战技在角色技能来源页面中的只读展示。

本阶段不实现盾牌槽、坐骑、骑士团、流派选择 UI、战技学习书或战技改良。守卫不是持盾职业，枪骑也不假装角色已经骑乘；它们分别表达重武器守御和长枪冲阵。完整盾卫与重骑在装备和坐骑基础完成后再扩展。

### 核心规则

#### 流派与武器

| 流派 ID | 显示名 | 兼容武器组 | 战斗定位 |
|---|---|---|---|
| `Cultiway.KnightStyle.Guardian` | 守卫 | `axe`、`hammer` | 承伤、震退、保护队友 |
| `Cultiway.KnightStyle.Lancer` | 枪骑 | `spear` | 破甲、冲锋、跨距打击 |
| `Cultiway.KnightStyle.Duelist` | 决斗家 | `sword` | 单挑、反击、连续压制 |

弓、杖、火器和未知武器组不匹配首批流派。角色可以解锁全部三个流派，Provider 合并当前武器匹配的所有已掌握流派战技。首批三个流派的武器组互不重叠；后续即使多个流派兼容同一武器，也不需要增加“当前流派”状态。

#### 解锁档位

| 骑士等级 | 档位 | 含义 |
|---|---|---|
| 0 | 基础 | 形成流派最基本的战斗动作 |
| 3 | 中阶 | 获得改变站位或攻防节奏的核心招式 |
| 7 | 高阶 | 获得能够决定局部战局的招式 |

流派只需训练解锁一次。角色达到 3 级或 7 级后，对应高阶战技自动开放，不要求重复训练。

#### 斗气和冷却

当前等级表是逐级累加的，因此 0、3、7 级的累计斗气上限约为 `100`、`900`、`7350`。三档技能的初始总成本采用对应上限约 5%：

| 档位 | 总斗气成本 | 设计结果 |
|---|---|---|
| 基础 | `5` | 低阶骑士可以稳定使用，但不能连续无脑释放 |
| 中阶 | `45` | 一个月和平训练所得斗气大致支持一次同阶招式 |
| 高阶 | `360` | 只应在强敌、包围或保护任务中使用 |

成本是固定值。角色升级后，旧招式相对变便宜，体现斗气控制能力成长。战技与突破共用斗气；释放后如果斗气低于突破阈值，角色必须重新积累。

每个战技拥有独立 `SkillContainer`，冷却由容器 PID 区分。冷却只在施放序列成功启动后开始，支付失败不进入冷却。短时格挡、反击和冷却属于运行时状态，读档后清除；流派解锁属于角色持久数据，随世界存档保存。

### 步骤 1：建立流派、战技和主动能力基础

步骤 1 采用“流派资产 + 战技资产 + 技能执行资产”的三层组合。流派和战技是可持续增加的领域资产，`SkillEntityAsset` 继续只负责 SkillLibV3 的执行体、轨迹和命中。

新增两个内容资产类型：

| 文件 | 职责 |
|---|---|
| `Source/Content/Libraries/KnightStyleAsset.cs` | 定义 `KnightStyleAsset` 与 `KnightStyleLibrary` |
| `Source/Content/Libraries/KnightTechniqueAsset.cs` | 定义 `KnightTechniqueAsset`、主动使用画像与 `KnightTechniqueLibrary` |

新增 `Source/Content/KnightCombat/`，承载资产注册和通用适配：

| 文件 | 职责 |
|---|---|
| `KnightStyles.cs` | 注册守卫、枪骑、决斗家三个 `KnightStyleAsset` |
| `KnightTechniqueSkills.cs` | 注册九个 `SkillEntityAsset`，只配置执行体、轨迹、碰撞和 SkillLibV3 资源需求 |
| `KnightTechniques.cs` | 注册九个 `KnightTechniqueAsset`，关联流派、技能执行资产和主动使用画像 |
| `KnightTechniqueCatalog.cs` | 为每个战技建立唯一来源容器，并预构建按 ID、流派和容器 PID 的只读索引 |
| `KnightStyleMasteryService.cs` | 查询和写入角色永久掌握的流派 |
| `KnightTechniqueAccessService.cs` | 统一判断角色是否获得战技；本阶段只读取流派掌握，后续可接组织或师承授权 |
| `KnightTechniqueAbilityProvider.cs` | 将 Catalog 中的资产无分支地适配到 `IActiveAbilityProvider` 与 `ISourceGrantedSkillProvider` |

#### `KnightStyleAsset` 边界

`KnightStyleAsset` 保存：

- 稳定 ID、名称 key、描述 key、图标和展示顺序。
- 默认兼容武器组。
- 最低骑士等级。
- 可选的额外装备条件，用于未来的盾牌、坐骑、法器或特殊铠甲流派。

`KnightStyleAsset` 不保存角色是否掌握、当前流派、冷却、技能容器、组织关系或任何短时战斗状态。流派与战技的关系以 `KnightTechniqueAsset.Style` 为唯一来源，由 Catalog 建立反向索引，不在流派注册代码中手写第二份战技列表。

#### `KnightTechniqueAsset` 边界

`KnightTechniqueAsset` 与 `SkillEntityAsset` 使用组合而非继承。它保存：

- 来源流派和对应 `SkillEntityAsset`。
- 最低骑士等级、总斗气成本和冷却。
- 主动能力的频道、目标模式、施放模式和移动约束。
- 距离、作用半径、AI 权重、战术画像和施放入口的无状态回调。
- 可选的战技级额外装备条件。

资产上的回调接收临时 `KnightTechniqueContext`，其中包含施法者、战技资产、Catalog binding、当前武器和目标。该 context 是一次方法调用期间使用的值类型，不保存到角色或全局运行表。

具体战技通过静态方法配置这些回调。通用 Provider 只解析 handle、构造 context 并转发，不按九个战技 ID 编写 `switch`。后续新增流派和战技时，只注册新资产及其行为，不修改 Provider。

#### Catalog 与访问规则

每个 `KnightTechniqueAsset` 在 Catalog 中对应一个规范 binding：

```text
KnightTechniqueAsset + SkillEntityAsset + 唯一 SourceGranted SkillContainer
```

主动能力句柄、技能来源展示和冷却都引用这一个容器。Catalog 初始化后提供：

- 按战技 ID 查 binding。
- 按流派查有序 binding 数组。
- 按容器 PID 解析主动能力 handle。

`Collect()` 是战斗热路径。Catalog 预构建索引后，Provider 每次只读取一次 `Knight`、当前武器和武器组，再顺序检查候选数组；其中不使用 LINQ、不创建容器、不扫描完整资产库，也不拼接字符串。

`KnightStyleMasteryService` 根据稳定流派 ID 生成 ActorData flag：

```text
cw.content.knight_style.<KnightStyleAsset.id>
```

`KnightTechniqueAccessService` 是未来授权来源的稳定入口。本阶段的规则只有“永久掌握来源流派”；第三阶段可以在其后增加骑士团成员、师承、誓言或装备临时授权。同一战技由多个来源授予时仍只输出 Catalog 中的同一 binding，避免重复技能和重复冷却。

#### 数据约束

- `Knight` 组件仍只保存 `level` 和 `vigor`，不加入九个技能布尔值或当前流派字段。
- 角色可以永久掌握多个流派；当前武器匹配的全部流派战技取并集。
- 角色只保存流派掌握信息，不保存由此推导出的战技列表。
- 资产不保存世界内 `Entity` 或容器 PID；这些值只存在于当前世界的 Catalog binding。
- 九个技能容器使用 `SkillContainerBuildMode.SourceGranted`，不进入学习、命名和改良系统。
- 来源展示 Provider 枚举角色已经解锁且达到等级要求的战技，不要求当前正装备对应武器。
- 主动能力 Provider 枚举当前武器匹配的所有已掌握流派战技。

通用资格检查由 AccessService、Catalog binding 和资产回调共同完成，并在 `Collect`、`CanPrepare`、`CanUse` 和序列开始钩子重复调用同一入口。换装不需要 Harmony Patch；`ActiveAbilityService.Collect()` 每次都会重新查询 Provider。持续招式保存施放开始时的真实武器，武器改变后终止剩余步骤且不返还已经支付的斗气。

步骤 1 不创建通用 `KnightTechniqueRuntime`、巨型 `KnightTechniqueRules` 或战技 ID 分发表。格挡、反击和壁垒在实现时使用共享状态实体；冲锋和坠击在各自步骤引入局部位移会话；冷却继续完全由 `SkillCooldownService` 管理。

所有造成武器伤害的战技必须：

1. 将技能资产设置为不使用通用基础伤害。
2. 按当前武器构造 `AttackData`。
3. 在 `AttackDamageScaleContext` 中设置本次倍率。
4. 调用 `MapBox.checkAttackFor()`。

这样可以保留原版暴击、武器攻击类型、装备攻击效果、击杀回调和骑士击杀斗气，避免用固定技能强度绕过武器系统。

### 步骤 2：让训练假人解锁流派

#### 建筑

`Architectures.cs` 已经映射原版 `training_dummy`，但 `BuildingOrders.Classic` 没有建造该建筑。本阶段把训练假人加入 `Classic`：

- 每城最多 1 个。
- 要求城市已有兵营和一级大厅。
- 建议人口门槛 30、建筑门槛 8。
- 只接受已经完成建造且仍属于角色城市的训练假人。

#### 训练任务

将 `DailyKnightTrain` 从原地计时改为以下行为序列：

1. 查找本城已完成的训练假人。
2. 前往训练假人的主地块。
3. 播放原版训练攻击动作。
4. 按现有 `PracticeVigorGainRatioPerMonth` 继续积累斗气。
5. 完成一个游戏月的训练后，根据当前武器组解锁流派。
6. 斗气已满时结束训练，交给通用突破任务。

训练解锁写入角色 `ActorData` flag：

| 流派 | Flag |
|---|---|
| 守卫 | `cw.content.knight_style.Cultiway.KnightStyle.Guardian` |
| 枪骑 | `cw.content.knight_style.Cultiway.KnightStyle.Lancer` |
| 决斗家 | `cw.content.knight_style.Cultiway.KnightStyle.Duelist` |

流派 flag 的统一前缀在 `ContentActorDataKeys` 中声明，具体 key 由 `KnightStyleMasteryService` 根据资产 ID 生成。ActorData 由世界存档保存，因此不依赖当前尚未统一解决的 ECS 动态关系存档。

训练规则：

- 一个角色可拥有多个 flag。
- 重复训练已解锁流派只增加斗气，不重复授予。
- 无武器或武器组不兼容时仍可操练并获得斗气，但不解锁流派。
- Warrior、Leader 和 King 使用相同城市安全检查；城市处于直接危险时不进入训练任务。
- 没有训练假人的城市不能通过和平操练解锁流派，也不能使用新的建筑训练收益。

### 步骤 3：实现三个基础战技

先实现每个流派的 0 级战技，打通完整垂直流程：

- 守卫：格挡架势。
- 枪骑：破甲突刺。
- 决斗家：蓄势重击。

本步骤必须同时完成：

- 来源技能展示。
- 当前武器动态过滤。
- `Vigor` 一次性支付。
- 独立冷却。
- 玩家主动使用。
- 普通 AI 和战术 AI 候选生成。
- 武器伤害、暴击、攻击附效和击杀回调。
- 支付失败不启动技能、不启动冷却。

实现本步骤时新增 `KnightTechniqueStatuses.cs`。格挡通过 `CombatStatusEffects.ApplyStateStatus()` 创建共享状态实体，持续时间、来源和一次性消费都由状态实体承担，不写入角色 Runtime。破甲复用 `CombatStatusEffects.ApplyStatus(..., StatusEffects.ArmorBreak, ...)`。蓄势重击只改变当前一次武器攻击倍率，不创建常驻属性加成。

实现第一个武器攻击战技时再新增 `KnightWeaponStrikeResolver.cs`，不要在只有资产和 Provider 的步骤 1 中预建。

完成本步骤后，三个流派都已经可训练、可展示、可战斗，后续步骤只在这个闭环上增加战术能力。

### 步骤 4：实现三个中阶战技

#### 震退

- 使用单个近身范围执行体，`HitOncePerTarget=true`。
- 对每个真实敌对目标分别走武器伤害结算。
- 击退和短暂震慑复用现有 `CombatStatusEffects` 与原版 force 接口。
- 不把武器自身多目标数量再次乘入技能目标数，避免范围重复放大。

#### 破阵冲锋

`SkillLibV3` 的轨迹只移动技能执行体，不能移动施法者。因此实现冲锋时新增只服务位移战技的 `KnightMovementCastService`，其中的短生命周期 `KnightChargeSession` 承担：

1. 施放开始时记录角色、目标、武器和起始方向。
2. 通过角色 force 接口向目标方向移动。
3. 到达命中距离后执行一次武器攻击并结束会话。
4. 目标死亡、角色死亡、武器变化或超过最大持续时间时结束会话。

冲锋仍通过 `IActiveAbilityProvider` 暴露，不为单个招式扩展通用技能轨迹协议。

#### 反击架势

- 接入最终伤害阶段，识别有真实攻击者的近战武器伤害。
- 先将本次伤害降低 50%，再清除反击状态。
- 在当前伤害结算结束后排入一次 `1.0x` 武器反击。
- 反击伤害带有骑士战技来源标记，不能再次触发反击，避免双方反击递归。

### 步骤 5：实现三个高阶战技

#### 守护壁垒

- 选取施法者和范围内生命比例最低的 3 名友军。
- 为每个目标添加同源 `GuardianBulwarkState`，持续 4 秒。
- 在最终伤害阶段乘以 `0.75`。
- 同一施法者重复施加只刷新时间，不叠乘；不同来源也只保留剩余时间最长的一份。
- AI 战术画像同时标记防御和支援用途。

#### 苍穹坠击

- 使用独立位移会话，不复用普通冲锋会话的水平命中逻辑。
- 角色向目标位置跃进，落点时结算主目标和周围敌人。
- 主目标使用 `1.6x` 武器攻击；范围冲击对其他目标使用 `0.45x`。
- 只以地面角色或建筑为目标，不追踪飞行目标。
- 落地前目标失效时仍在原目标位置完成范围冲击。

#### 传奇连斩

- 使用固定三步计划，不调用通用 `CreatePlan()` 扩张步数。
- 每步斗气需求设置为 `120`，启动前一次性支付，总成本 `360`。
- 三步共享同一目标；目标失效时取消剩余步骤。
- 每步重新验证当前武器仍是施放开始时的剑。
- 冷却在整个三步序列成功开始时启动一次。

### 步骤 6：接入普通 AI 与战术 AI

#### 通用候选条件

任何战技进入候选池前都必须满足：

- 角色持有 `Knight`。
- 对应流派已经训练解锁。
- `Knight.CurrLevel` 达到要求。
- 当前武器组匹配。
- 技能冷却结束。
- 当前斗气足以支付完整动作。
- 目标关系、目标类型和距离满足招式要求。

普通攻击当前基础权重为 6。骑士战技的权重采用情境值：条件不成立时为 0，普通机会为 3 至 5，真正符合战术用途时为 6 至 10。通常战况下只允许 1 至 3 个战技具有非零权重，防止高阶骑士停止普通攻击。

#### 资源判断修正

当前战术规划器只比较体力和法力比例，不能正确评估斗气。为主动能力画像增加两个可选的标准化值：

- `NormalizedResourceCost`：本次动作总成本 / 当前最大资源。
- `AvailableResourceRatio`：当前资源 / 当前最大资源。

`ActiveAbilityCombatActionProvider` 优先使用能力提供的标准化值；未提供时保持现有法力、体力算法。骑士 Provider 分别报告总斗气成本比例和当前斗气比例。不要把 `Vigor` 硬编码进全局战术快照，也不要让其他资源 Provider 依赖骑士类型。

#### 战技画像

战技强度必须根据真实武器伤害和固定攻击段数计算，不能使用通用技能默认强度 `100`。

| 战技 | 主要用途 | 关键决策信号 |
|---|---|---|
| 格挡架势 | 防御 | 自身伤势、近期攻击者数量 |
| 震退 | 控制、防御 | 近身敌人数、被包围程度 |
| 守护壁垒 | 防御、支援 | 自身和友军最低生命、接近敌人数 |
| 破甲突刺 | 进攻、控制 | 目标护甲、目标是否已有破甲 |
| 破阵冲锋 | 进攻 | 与目标距离、目标是否可冲锋 |
| 苍穹坠击 | 进攻、控制 | 远距强敌、落点敌群密度 |
| 蓄势重击 | 进攻 | 目标是否孤立、目标剩余生命 |
| 反击架势 | 防御、进攻 | 最近近战攻击者、自身生命 |
| 传奇连斩 | 进攻 | 目标战力、目标是否孤立、剩余斗气 |

AI 不对明显弱于自己的普通目标使用高阶战技。生命低于 35% 时，格挡、反击和壁垒可以忽略通常的斗气保留倾向；其他情况下，高阶战技只对同级强敌、首领或足够密集的敌群开放。

普通 AI、战术 AI 和玩家控制只改变选择来源，不改变技能支付、冷却和效果执行逻辑。

## 验收标准

### 功能

- 0、2、3、6、7、9 级骑士只能获得符合等级边界的战技。
- 斧锤、矛、剑分别激活守卫、枪骑、决斗家；换装后下一次能力查询立即变化。
- 同一角色可以依次训练并保存三个流派。
- 无训练假人、训练假人未完成或城市处于直接危险时不能解锁流派。
- 每个战技精确扣除表中总斗气；斗气不足时不产生效果和冷却。
- 九个战技冷却彼此独立。
- 释放战技后斗气低于 80% 时，通用突破任务不再满足前置条件。
- 武器攻击战技保留暴击、攻击类型、装备命中特效、击杀回调和敌对判断。
- 格挡、壁垒和反击不增加额外闪避率。
- 中途换装会终止冲锋、坠击或连斩的剩余步骤。
- 保存并读档后流派 flag 保留；短时架势和冷却清除。

### AI

- 普通战斗 AI 和战术战斗 AI 都能选择九个战技。
- AI 不对弱小单体使用苍穹坠击或传奇连斩。
- 枪骑近身时不反复尝试冲锋。
- 守卫未被攻击且附近没有友军危险时不空放防御技。
- 决斗家被多人包围时降低蓄势重击和连斩权重，优先普通攻击或脱离。
- 斗气不足时战术规划器不把技能当作可执行动作。
- 常见战况中非零战技候选不超过三个，普通攻击仍持续出现。

### 构建与游戏验证

- `dotnet build Cultiway.csproj -c Debug` 无错误。
- 分别验证玩家控制、普通 AI 和战术 AI 三条入口。
- 分别验证角色目标、建筑目标、飞行目标和目标施放中死亡。
- 让至少 100 名混合流派骑士参与持续战斗，确认没有技能实体、位移会话或临时状态持续累积。
- 检查九种特效在常速、加速和暂停恢复后与实际伤害时点一致。
