# 家庭矩形农田与风车加工

状态：基础版已实现并完成游戏内功能验证。已替换耕地选址、农民目标、原粮加工和原版农田衰退入口，并加入两季麦作与农闲临时支援。

## 已确定的规则

1. 农田不再围绕风车固定半径生成，改为同村家庭开垦、管理矩形田块。
2. 作物收获后仍须送到风车加工，风车不再决定田地能开在哪里。
3. 农田进入内城范围后立即停止耕种。**已经成熟的作物可收取一次，然后恢复地面；未成熟作物不等待长成。** 此处理方式已确认。
4. 沿用村庄作息和职业人数：普通农民工作月劳动，休息月自由活动；特殊者和管理者不强制务农。
5. 冬小麦9–11月播种，实际生长7个月，次年5–6月收获；春小麦3–4月播种，实际生长4个月，当年7–9月收获。达到月龄但尚未到收获月份时继续留田。
6. 农时优先：当季播种、收获及本次收粮收尾可打断休息；其他农活、加工和临时支援仍遵守作息。
7. 小麦生长且没有可执行农活时，普通农民可临时参与其他生产，保留农籍和家庭田地。农时到来后在安全时机召回，不打断运送中的材料。
8. 新田以城区为中心向外铺开，完整田块不得超过城区边缘外32格；同尺寸田块按宽、高各加一格排列，田块之间共用一格田埂。同户另开的田块也需留间隔，完整合并旧田时除外。
9. 每株未成熟小麦可消耗1份肥料施肥一次，收获原粮翻倍。春麦、冬麦和未登记麦类都适用；施肥不改变生长期和收获月份，成熟后不再补施。

## 建议采用的家庭与田块规则

- 复用原版 `Family`，按“村庄编号＋家庭编号”登记本地农户，不以整个氏族、宗门或国家作为一个家庭。
- 家庭里有实际农民，才申请耕地；面积按参与耕作的人数计算，不按儿童、士兵和修炼者的总人数分田。
- 默认一个参与耕作的人先开6×8格，默认每户上限48格，多人同户仍共用该上限。村庄可以修改起步宽高和每户面积上限，宽高为1至12，每户最多144格。
- 优先城区附近、同村同岛的土地，按距离由近到远查找；不再随机跳到远处。风车的距离影响搬运效率，不再是一条“超出距离不能种”的规则。
- 矩形完整检查地形、现有建筑、道路、铁路预留带、其他田块和内城范围。障碍多时换位置或缩小矩形，不把田块拉成细长零散条带。
- 田块由家庭经营，收成进入村庄公共生产与仓储体系；本版不增加一套家庭私有仓库和税收制度。
- 农田地表允许房屋和公共建筑选址，不因预留田块或空田阻挡城市发展。建筑放置后，已有土地检查会从田块中剔除实际占地，其余部分保留。

## 完整生产流程

家庭农民领地 → 清理与翻土 → 播种 → 生长期间按需施肥增产 → 收获原粮 → 运到可达风车 → 加工为可用粮食 → 沿用村庄食品配方与供给。

建议第一版由农民兼顾运粮和加工，风车按工位限制同时加工的人数，其余农民继续种植和收割。原粮不计入可直接食用库存；没有风车时可以耕种、收获并积存原粮，但不能跳过加工。村庄仍需通过采集、狩猎补充食物，并在具备材料时优先补建风车。

## 对现有派工的衔接

村庄先根据实际普通劳动力、可食用粮食库存和工作需求计算农民人数，再把农民分配到家庭。家庭田块面积影响可做的工作量，不能直接把田格数量当成农民人数。

农民的任务优先处理成熟收获、告急粮食加工和已有田块补种，最后才是继续扩大耕地。原粮积压而可食用粮食不足时，应转向运粮加工，不能仍把大量劳动力投入开新田。

内城更新只使覆盖的格子退耕，未覆盖部分保留，并整理成一个或多个矩形子块。打掉一段城墙不等于取消内城规划，不会立即重新出现农田。

## 农田消失问题

原版 `WorldBehaviourActions.updateFarmDecay` 会删除不在临时农业缓存中的田地。新田刚翻土尚未刷新缓存时，以及已播种田漏出空田缓存时，都可能被误删。现在衰退周期直接核对家庭田块和土地合法性，合法家庭田地持续保留；内城、道路、铁路预留带和建筑覆盖仍正常退耕，不靠不停重画地表维持。

## 2026-11-18 收获延误排查

在玩家当时运行的世界采样，东京有43名农民、166株成熟小麦，其中151株冬小麦已错过5—6月收获期。其他村庄也存在已成熟多年、所属家庭已无农民的作物。连续观察20秒、约4.09个游戏月，没有新增异常，但东京在5—6月仅完成3次收割。

本次修正：

- 当季成熟作物优先于闲逛、社交、制作物品和继续开垦；可以召回正在室内制作的普通农民，睡眠、进食、战斗、运输和玩家命令继续保留。
- 村庄确实断粮时，农民不再被“饥饿就不派工”阻挡。已经有食物时仍先满足进食需求。
- 收割先照顾自家田，再帮收同村同岛的其他家庭田块。开垦、播种和土地所有权不变，目标仍按地格认领，收割结算继续核对作物编号、月份和归属。
- 每村领取待加工原粮最多同时两人，并扣除已经认领的批次数量，减少多人跑向同一份原粮后空手返回。
- 高倍速下每格农活从8个逐帧步骤缩减为5个，去掉额外等待，把结算、生活需求检查和下一轮调度合在一起；仍有真实移动与两次劳动动作，连续劳动上限仍由原版12次需求检查控制。

编译通过，0错误、27项原有警告。原有61项职业规则加12项抢收调度检查共73项通过。目标选择方法从修改后源码提取后在当时世界执行，未改变人物、作物或时间；该次样本没有可领取的成熟目标，不能据此认定同村帮收及长时间产量已实测通过。排查期间没有主动重启或保存玩家世界。随后检测到游戏新进程41620，调试通道已确认本次新增的抢收接口实际加载成功。

新世界在35秒内推进约40.48个月，相当于约6倍速，原本5—6月的收获期只剩约1.7秒现实时间。原版人物每次更新只执行一个行为节点，8个节点加移动和劳动等待会进一步挤压收获能力。5步调整已通过调试通道接入当前进程，与源码使用相同的结算和需求检查顺序，不需要再次重启。

5步调整后的35秒自然观察记录到收割、运粮和加工，也仍有农时边界及目标变化造成的拒绝结算；前后场景与速度不固定，不能由收割数量比较宣称产能已提高。随后用户确认采用每月30日、每年12月的新日历，最终调整为每日12时，并让一天沿用旧一年的流速。农作物月龄、播收月份和村庄作息已同步新日历，细节见[世界日历与时钟](世界日历与时钟.md)。

原始采样、20秒观察和调度检查记录存放于[本次验收目录](家庭矩形农田与风车加工/验收/20261118)。原有32项农田功能检查来自前一轮受控测试，不替代本次修改加载后的复测。

## 2026-11-18 城区周边铺田与供粮测算

选址改为全村共用的有序候选：每户每轮至多检查16个新位置，仍沿用每村每轮最多两个家庭的限制。城区范围或田块设置变化后重新排列；空位释放后重新从近处找地。地形、内城、道路、建筑、铁路预留带及同岛要求继续生效，障碍和旧田碎片周围不承诺全部田埂都恰好一格。

远处已有作物的田块停止补种和继续开垦，作物生长与当季收获保留；整块收完后，家庭下一次申请土地时释放原田，再改在城区附近选址。此处理不使用内城退耕的“立即清除未成熟作物”规则。

验证结果：20项规则检查通过，包含500种原有不规则覆盖样本，以及候选距离顺序、一格步长、地图边缘和找地预算。另在真实地形中用独立土地记录执行修改后的占地检查，5项同户间隔和扩大合并检查通过，未向玩家田块登记测试数据。编译0错误、27项原有警告；当前游戏进程17308已接入选址及农活目标限制。

玩家切换到玉集后，20秒自然运行推进约504个模拟秒，新增完整6×8田块位于城区边缘外4至5格，同列相邻田块间隔一格；末次样本全部登记田块位于近城范围内，距离城区边缘最远9格，没有新增异常。已有田块被建筑覆盖后形成的碎片继续按原有规则整理。

供粮核对使用一天12秒、每月30天、每年12月。普通人物每15个模拟秒消耗1点饱食，一年需要288点；每格成熟小麦收1份原粮，风车按1:1加工为麦粮。麦粮恢复50点，若实际进一步制成面包则恢复100点。冬麦占田期间已覆盖春麦播种期，不能把同一格按稳定一年两收计算。

## 施肥增产

原版农民的肥料资源由直接催熟改为单株增产：每株限施一次，消耗1份肥料，基础1份原粮变为2份。增产标记保存在该株原版建筑资料中，读档后继续生效；收割时结清，新播种的作物重新开始。收割加成接在共同的作物资源提取入口，不改写全局作物资产的基础产量，家庭农田与原版收割流程都能获得加成。

农民工作月处理未成熟的本户小麦，原有抢收、补种和缺粮加工优先级保持。按单株需要从可用仓库取1份肥料，避免批量余料阻碍农闲转岗。有可执行施肥任务和可领取肥料时，临时支援者会在安全时机回农业；没有肥料时仍可农闲支援。农田页面增加说明，不增加一套设置窗口或新资源。

19项运行中单株检查通过，覆盖春麦、冬麦、扣料、重复施肥、作物资料序列化恢复、原版收割资源发放、一次性增产、新一株重置和无肥料情形。检查使用未注册到世界的原版人物与作物对象，不改动玩家的作物、库存和世界时间；测试对象的画面移除被跳过，不能据此声称已经完成整个农业周期的持续产能验收。

自然运行检查中发现先前临时接入的选址前置处理仍会覆盖施肥目标；该重复入口已移除，新实现保留同样的近城、归属和合法土地检查。随后20秒自然观察记录到3次实际施肥，未出现新增异常。观察期间没有施肥作物成熟收割，增产数量由上述单株收割检查验证。
