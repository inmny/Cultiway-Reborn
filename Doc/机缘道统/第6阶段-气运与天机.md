# 第6阶段-气运与天机

本阶段把现有未接通的 `Qiyun` 补成可初始化、可保存、可消费的角色资源，并让它在发现入口和 SubWorld 内部试炼失利时提供有限转机。进入实例后使用 Projection 气运快照，返回时把最终值冻结进 `OutcomeDelta`，由 `SubWorldOutcomeCommitService` 在角色资源步骤提交，不能越过 `ExpeditionLease` 直接修改暂停中的 MainWorld Actor。

## 具体说明

### 设计边界

气运是“关键机会中的有限资源”，不是全属性幸运值：

- 不提高功法元素相性或语义相性。
- 不绕过境界、灵根、修炼体系和路径可达性门槛。
- 不直接提高战斗暴击、闪避、掉落或突破成功率。
- 不指定永久天命主角。
- 不允许杀死高气运角色后直接夺取其全部气运。
- 不接入因果、轮回、命格和国运；这些属于独立后续系统。
- 不用气运跳过内部移动、交互、战斗或撤离；转机只能改变下一次具体行动机会。

气运只在一个遗府的一次入口发现、一次内部试炼转机和一次核心争机中消费。普通 AI 不会每月持续把气运花在同一个失败地点。

### 当前问题

现有实现只有：

- `Qiyun { MaxValue, Value }` ECS 组件。
- `RestoreQiyunSystem` 每月恢复 `MaxValue / 12`。
- 角色信息窗口显示已经存在的组件。
- 丹药词条修改 `WorldboxGame.BaseStats.MaxQiyun`。

当前没有：

- 组件初始化入口。
- ActorData 存档与读档恢复。
- 消费入口。
- 组件容量与最终 `MaxQiyun` 属性之间的一致定义。
- 恢复后同步 ActorData 的主线程事务。

因此本阶段必须先完成资源模型，不能直接在遗府概率公式里读取一个通常不存在的组件。

### 步骤 1：统一气运容量与当前值模型

将组件语义明确为：

```text
Qiyun
  BaseCapacity
  Value
```

`BaseCapacity` 是角色自身提供给 `WorldboxGame.BaseStats.MaxQiyun` 的基础容量。最终有效上限为角色完整属性计算后的：

```text
EffectiveMax = actor.stats[MaxQiyun]
```

因此：

- `BaseCapacity` 默认 `100`。
- 丹药、功法、状态和其他属性修正继续作用于 `MaxQiyun`。
- `Value` 始终限制在 `0..EffectiveMax`。
- 属性变化导致上限降低时立即截断当前值。
- 上限提高时只增加容量，不免费填满新增部分。

`ActorExtend.RebuildCultiwayStatsCacheIfDirty()` 只把 `BaseCapacity` 合并到属性，不把已经包含修正的 `EffectiveMax` 再写回组件，避免循环叠加。

首阶段只为拥有仙道修炼体系的角色创建 Qiyun。普通生物、纯骑士和纯法师不因为世界存在遗府而自动获得气运资源。

### 步骤 2：实现角色初始化、存档与恢复

#### ActorData

在 `ActorData.custom_data_float` 保存两个稳定 key：

```text
Cultiway.Qiyun.BaseCapacity
Cultiway.Qiyun.Value
```

#### 新生角色

角色首次获得仙道体系时：

1. 创建 `Qiyun { BaseCapacity=100 }`。
2. 标记角色属性缓存失效并刷新最终 `MaxQiyun`。
3. 将 `Value` 初始化为当前 `EffectiveMax`。
4. 同步写入 ActorData。

气运随仙道体系授予而创建，不依赖 `Actor.newCreature()`，确保中途获得仙道的角色也能初始化。

#### 读档角色

`ActorExtend` 首次创建时：

- ActorData 已有气运记录：按记录恢复组件，再按当前属性截断 Value。
- ActorData 没有记录但角色已有仙道：按新角色规则初始化。
- 角色没有仙道：不创建组件。

恢复入口只执行一次，不把每次 `GetExtend()` 都当作读档。

#### 失去体系与死亡

当前项目不支持角色主动放弃仙道，因此不增加删除组件流程。角色死亡后 ActorData 不再作为存活对象保存，Qiyun Entity 随现有 `ActorExtend.Dispose()` 回收。进入遗府时只把有效上限与当前值复制到 `ProjectionQiyun`，不把主世界 ECS Entity 或组件引用写入小世界归档。

### 步骤 3：建立唯一消费与恢复入口

新增 `QiyunService`，提供：

```text
Initialize(actor)
GetEffectiveMax(actor)
TrySpend(actor, amount, reason, siteId)
Restore(actor, amount)
SetBaseCapacity(actor, value)
Sync(actor)
CaptureForExpedition(actor)
ApplyExpeditionOutcome(actor, qiyunDelta)
```

调用方不能直接修改 `Qiyun.Value`。所有成功消费与恢复都在同一主线程事务中：

1. 读取并按有效上限截断。
2. 检查或修改 Value。
3. 写回 ECS 组件。
4. 同步 ActorData。
5. 记录需要的主世界消费原因，不写普通 WorldLog。

Lease 生效时，`CaptureForExpedition()` 生成：

```text
ProjectionQiyun
  EffectiveMax
  Value
```

`ExpeditionLease` 期间 MainWorld `RestoreQiyunSystem` 不处理该 Actor。Projection 的恢复按实例 `BodyTime` 使用同样的一年回满节奏；内部消费、恢复和最终值由 SubWorld RuleSet 记录并冻结进 `OutcomeDelta`，返回时由 `SubWorldOutcomeCommitService` 在 portable item 之后、死亡之前调用 `ApplyExpeditionOutcome()` 一次提交。

#### 每月恢复

保留“一年从空恢复到满”的当前节奏：

```text
MonthlyRestore = EffectiveMax / 12
```

`RestoreQiyunSystem` 不再用 `RunParallel()` 直接改组件。它改为收集当前月需要恢复的角色，再由主线程调用 `QiyunService.Restore()`，保证 ActorData 与 ECS 一致。

暂停时不推进恢复；游戏倍速按世界模拟月份推进，不按现实帧数额外恢复。

### 步骤 4：让气运影响机缘发现

普通发现首先完整执行第三阶段的智力、神识、Perception 与距离判定。失败后，`QiyunOpportunityPolicy` 才评估是否抓住转机。

#### 消费条件

- 角色当前气运至少为有效上限的 50%。
- 目标遗府的境界范围、传承内容和距离对角色具有实际价值。
- 角色尚未在该 Site 使用过发现转机。
- 角色没有被硬门槛排除。

满足后可以消费：

```text
DiscoveryCost = EffectiveMax * 0.15
```

消费后只获得一次强化发现重试：

- 重试仍读取神识、感知和距离。
- 重试失败时气运不返还。
- 重试成功后正常创建私密 `Location` 消息。
- SiteRecord 保存该 Actor 已使用发现转机，防止下月重复消费。

气运不会让角色隔着世界知道遗府，也不会凭空解决不可达路径。

### 步骤 5：让气运提供试炼与择主转机

#### 试炼转机

Projection 在神识封禁、道痕危险区或悟法台的实际交互中失败，但距离合格阈值较近时，小世界 `LegacyQiyunRule` 可以发出一次转机命令并消费：

```text
TrialTurnCost = EffectiveMax * 0.25
```

结果是：

- 清除该 Projection 对当前试炼对象的一次个人失败锁定。
- 保留一半个人共鸣进度；封禁实体已经受到的真实作用量保持不变。
- 允许角色重新接近并再次执行交互、穿越或悟法行为。
- 不传送角色、不直接把 TrialResult 改为合格。
- 不恢复已经承受的内部伤势，也不复原已经消耗的物品。

每个 Actor 每个 Site 最多使用一次试炼转机。明显不相容、境界不足或主动退出者不能消费气运强行重试。

#### 核心争机

已经真实到达核心并进入 `Qualified` 的 Projection，才可以在 `SelectUniqueWinnerObjective` 冻结候选前消费：

```text
ContestCost = EffectiveMax * 0.10
```

消费后只提高本次随机权重，最高增幅为 10%，不修改 Recognition 数值。候选即使最终落选也不返还气运。

`LegacyQiyunRule` 只在以下情况选择争机：

- 该道统相对当前主修有明确提升。
- 角色 Recognition 已处于有效竞争范围。
- 支付后仍保留至少 20% 有效上限。

最高相性者可以不花气运仍然获选，较弱者也不能仅靠满气运压过完全不匹配的候选。

#### 使用记录

入口发现记录仍保存在 SiteRecord；内部两类记录保存在 SubWorld Participant RuleData：

```text
SiteRecord
  DiscoveryFortuneUsedByActorIds[]

LegacyParticipantRuleData
  TrialFortuneUsed
  ContestFortuneUsed
  TotalQiyunSpent
  LastFortuneActionId
```

内部消费只修改 `ProjectionQiyun.Value`，退出时把最终值冻结进 `OutcomeDelta` 并由 `PendingOutcome` 持有，不直接调用 `QiyunService.TrySpend(actor)`。读档后 Site 与 SubWorldArchive 中的记录分别保持，同一 `CommitId` 由 `SubWorldOutcomeCommitService` 幂等处理，不能重复触发同阶段转机或扣费。

### 步骤 6：完善天机神力、人物展示与反馈

#### 玩家神力

保留第一阶段两个正式力量：

- “古修遗府”创建由玩家主动加入世界的机缘；第五阶段后优先使当前世界的失传修订重新出世。
- “显露天机”只向玩家揭示地点，不为任何角色支付或增加气运。
- 玩家打开小世界浮窗只获得观察权限，不替 Projection 揭开迷雾、触发转机或改变目标权重，也不暂停主世界时间。

本阶段不增加直接填满角色气运的正式按钮，避免玩家力量列表继续膨胀。调试需要通过现有 Debug 工具完成。

#### 人物展示

人物信息中的气运展示改为稳定的当前值/有效上限：

```text
气运 65 / 100
```

道统页额外显示：

- 本次遗府是否使用过发现、试炼或争机转机。
- 因气运获得的是重试还是权重机会，不显示内部随机数。
- 上一次气运消费的世界年份与原因。

角色处于 Lease 中时，人物页显示归档中的 Projection 当前值；返回提交后重新显示 ActorData 当前值，不能同时显示两套可消费余额。

#### 世界反馈

- 发现转机成功时，在角色附近播放一次短促天机波纹。
- 试炼转机在对应小世界对象上播放道纹先破裂再重新闭合的反馈。
- 核心争机不提前播放效果，只在最终获选且气运确实参与时在 Winner Projection 上增加一道轻微反馈。

routine 恢复和普通消费不写 WorldLog。只有失传道统因角色使用气运而重新被发现，并最终完成继承时，才在既有继承日志中增加“得天机相助”的描述。

### 步骤 7：完成长期平衡与验收

#### 初始数值

| 行为 | 消耗 | 每 Site 上限 | 作用 |
| --- | ---: | ---: | --- |
| 发现转机 | 有效上限 15% | 1 次 | 强化重试一次 |
| 试炼转机 | 有效上限 25% | 1 次 | 保留部分进度并重试 |
| 核心争机 | 有效上限 10% | 1 次 | 最终权重最多提高 10% |
| 每月恢复 | 有效上限 1/12 | 每月一次 | 一年由空恢复到满 |

单次遗府最多消耗有效上限的 50%。角色从空恢复到满需要一年，因此不能连续对大量遗府保持全部转机。

#### 诊断

Debug 统计只记录聚合数据：

- 气运初始化角色数。
- 每月消费与恢复总量。
- 三类转机触发次数和成功次数。
- 因气运改变最终发现或获选结果的次数。

不在正式 UI 显示全世界概率和内部评分。

## 验收标准

### 资源模型

- 首次获得仙道的角色拥有 `BaseCapacity=100` 且当前值为有效上限。
- 读档已有仙道但没有气运记录的角色会完成一次初始化。
- `MaxQiyun` 属性修正改变有效上限，不循环叠加 BaseCapacity。
- 上限降低时 Value 被截断，上限提高时不免费补满。
- 每月恢复精确使用有效上限的 1/12，并同步 ActorData。
- 暂停不恢复，切换世界不保留上个世界的组件或计时器。

### 机缘使用

- 普通发现判定先于气运转机执行。
- 境界、灵根或路径硬门槛失败时不能消费气运绕过。
- 同一 Actor 对同一 Site 每类转机最多使用一次。
- 试炼转机只允许 Projection 对具体内部对象重试，不自动合格、传送或恢复伤势。
- 核心争机最多提高 10% 权重，不改变 Compatibility 和 Recognition。
- 落选、重试再次失败时已经支付的气运不返还。
- 保存读档后不会重复扣费，也不会重置 Site 的发现次数或 Participant 的内部使用次数。
- `ExpeditionLease` 期间 MainWorld 与 Projection 不会同时恢复或消费气运；`SubWorldOutcomeCommitService` 成功提交 `OutcomeDelta` 并持久化 `CommitId` 后两边数值一致。

### 长期游戏验证

- 让至少 100 名修士运行 100 个游戏年，统计气运均值、消费率和空值比例。
- 比较关闭气运消费与启用气运消费的遗府结果，确认它增加少量逆转但不改变硬门槛分布。
- 验证丹药 `MaxQiyun` 修正、人物页显示、遗府 Tooltip 和三类反馈。
- `dotnet build Cultiway.csproj -c Debug` 无错误。
