# 第6阶段-气运与天机

本阶段把现有未接通的 `Qiyun` 补成可初始化、可消费并按游戏时间自然恢复的角色资源，让它在发现入口和 SubWorld 内部试炼失利时提供有限转机。气运组件、使用记录和 Projection 数值都只存在于当前会话内存；角色进入实例后，由常驻 `SubWorldRuntime` 持有其可消费数值，离开时由 `SubWorldManager` 在主线程直接写回 MainWorld Actor。

切换世界、返回主菜单或 Mod 重载时，气运组件、地点使用次数、Projection 数值和相关计时全部清空。新会话根据当前角色是否拥有仙道体系重新初始化，不继承上一次会话的余额或使用记录。

## 具体说明

### 设计边界

气运是“关键机会中的有限资源”，不是全属性幸运值：

- 不提高功法元素相性或语义相性。
- 不绕过境界、灵根、修炼体系和路径可达性门槛。
- 不直接提高战斗暴击、闪避、掉落或突破成功率。
- 不指定永久天命主角。
- 不允许杀死高气运角色后直接夺取其全部气运。
- 不接入因果、轮回、命格和国运；这些属于独立后续系统。
- 不用气运跳过内部移动、交互、战斗或撤离；转机只能改变下一次具体行动机会。
- Actor 位于 SubWorld 时只允许对应 Projection 消费气运，MainWorld 侧由 occupancy 排除模拟。

气运只在一个遗府的一次入口发现、一次内部试炼转机和一次核心争机中消费。普通 AI 不会每月持续把气运花在同一个失败地点。

### 当前基础与缺口

现有实现只有：

- `Qiyun { MaxValue, Value }` ECS 组件。
- `RestoreQiyunSystem` 每月增加 `MaxValue / 12`。
- 角色信息窗口显示已经存在的组件。
- 丹药词条修改 `WorldboxGame.BaseStats.MaxQiyun`。

当前缺少：

- 角色首次获得仙道体系时的组件初始化入口。
- 唯一消费入口。
- 组件容量与最终 `MaxQiyun` 属性之间的一致定义。
- MainWorld Actor 与 Projection 之间的同步转移规则。
- 每个 Actor、Site 与内部对象的会话内使用次数。

因此本阶段必须先完成资源模型，再接入遗府概率公式。

### 步骤 1：统一气运容量与当前值模型

将组件语义明确为：

```text
Qiyun
  BaseCapacity
  Value
```

`BaseCapacity` 是角色自身提供给 `WorldboxGame.BaseStats.MaxQiyun` 的基础容量。最终有效上限为角色完整属性计算后的：

```text
EffectiveMax = actor.stats[MaxQiyun]
```

因此：

- `BaseCapacity` 默认 `100`。
- 丹药、功法、状态和其他属性修正继续作用于 `MaxQiyun`。
- `Value` 始终限制在 `0..EffectiveMax`。
- 属性变化导致上限降低时立即截断当前值。
- 上限提高时只增加容量，不免费填满新增部分。

`ActorExtend.RebuildCultiwayStatsCacheIfDirty()` 只把 `BaseCapacity` 合并到属性，不把已经包含修正的 `EffectiveMax` 再写回组件，避免循环叠加。

首版只为拥有仙道修炼体系的角色创建 Qiyun。普通生物、纯骑士和纯法师不因为世界存在遗府而自动获得气运资源。

### 步骤 2：实现当前会话初始化与清理

#### 首次初始化

角色首次获得仙道体系时：

1. 创建 `Qiyun { BaseCapacity=100 }`。
2. 标记角色属性缓存失效并刷新最终 `MaxQiyun`。
3. 将 `Value` 初始化为当前 `EffectiveMax`。
4. 把角色加入 `QiyunSessionState.ActiveActorIds`。

气运随仙道体系授予而创建，不依赖 `Actor.newCreature()`，确保中途获得仙道的角色也能初始化。

当前世界开始运行机缘系统时，对已经拥有仙道体系但尚无 Qiyun 的存活角色执行一次相同初始化。`GetExtend()` 不承担重复初始化职责。

#### 失去体系与死亡

当前项目不支持角色主动放弃仙道，因此不增加主动删除流程。角色死亡后 Qiyun Entity 随现有 `ActorExtend.Dispose()` 回收，同时从会话状态中移除该 Actor 的地点使用记录。

#### 会话结束

`QiyunSessionState.Clear()` 清除所有 Actor 气运组件、Site 使用次数、内部转机记录和恢复计时。若 Actor 正被 `SubWorldRuntime` 绑定，`SubWorldManager` 先解除 binding/occupancy，再销毁 Projection 气运状态。下一会话重新按首次初始化规则赋予数值。

### 步骤 3：建立唯一消费与自然恢复入口

新增 `QiyunService`，提供：

```text
Initialize(actor)
GetEffectiveMax(actor)
TrySpend(actor, amount, reason, siteId)
Restore(actor, amount)
SetBaseCapacity(actor, value)
MoveToProjection(actor, runtime, projection)
ApplyFromProjection(actor, runtime, projection)
```

调用方不能直接修改 `Qiyun.Value`。MainWorld 中的成功消费与自然恢复都在主线程完成：

1. 读取并按有效上限截断。
2. 检查或修改 Value。
3. 写回 ECS 组件。
4. 更新会话内消费原因与地点使用次数。

#### Projection 气运

Actor 进入遗府时，`SubWorldManager` 建立 Runtime binding，并创建：

```text
ProjectionQiyun
  EffectiveMax
  Value
```

绑定生效后：

- `SubWorldRuntime` 中的 `ProjectionQiyun` 是唯一可消费数值。
- MainWorld Qiyun 组件保留但不参与消费或自然恢复。
- `RestoreQiyunSystem` 通过 Actor 的 `ExpeditionBinding` 排除正在小世界中的 Actor。
- Projection 按实例 `BodyTime` 使用同样的一年回满节奏。
- Projection 离开时，`SubWorldManager` 在同一主线程把最终 Value 直接写回 Actor，再解除 binding/occupancy。

该同步和角色、物品转移使用同一退出流程，不生成中间结果对象。

#### 每月自然恢复

保留“一年从空回满”的当前节奏：

```text
MonthlyRestore = EffectiveMax / 12
```

`RestoreQiyunSystem` 收集当前月需要增加气运的未绑定角色，再由主线程调用 `QiyunService.Restore()`。暂停时不推进；游戏倍速按世界模拟月份推进，不按现实帧数额外增加。

### 步骤 4：让气运影响机缘发现

普通发现首先完整执行第三阶段的智力、神识、Perception 与距离判定。失败后，`QiyunOpportunityPolicy` 才评估是否抓住转机。

#### 消费条件

- 角色当前气运至少为有效上限的 50%。
- 目标遗府的境界范围、传承内容和距离对角色具有实际价值。
- 角色尚未在该 Site 使用过发现转机。
- 角色没有被硬门槛排除。

满足后可以消费：

```text
DiscoveryCost = EffectiveMax * 0.15
```

消费后只获得一次强化发现重试：

- 重试仍读取神识、感知和距离。
- 重试失败时气运不返还。
- 重试成功后正常创建私密 `Location` 消息。
- `LegacySiteRuntimeState.DiscoveryFortuneUsedByActorIds` 标记该 Actor 已使用发现转机，防止下月重复消费。

气运不会让角色隔着世界知道遗府，也不会凭空解决不可达路径。

### 步骤 5：让气运提供试炼与择主转机

#### 试炼转机

Projection 在神识封禁、道痕危险区或悟法台的实际交互中失败，但距离合格阈值较近时，小世界 `LegacyQiyunRule` 可以发出一次转机命令并消费：

```text
TrialTurnCost = EffectiveMax * 0.25
```

结果是：

- 清除该 Projection 对当前试炼对象的一次个人失败锁定。
- 保留一半个人共鸣进度；封禁实体已经受到的真实作用量保持不变。
- 允许角色重新接近并再次执行交互、穿越或悟法行为。
- 不传送角色、不直接把 TrialResult 改为合格。
- 不恢复已经承受的内部伤势，也不复原已经消耗的物品。

每个 Actor 每个 Site 最多使用一次试炼转机。明显不相容、境界不足或主动退出者不能消费气运强行重试。

#### 核心争机

已经真实到达核心并进入 `Qualified` 的 Projection，才可以在 `SelectUniqueWinnerObjective` 冻结候选前消费：

```text
ContestCost = EffectiveMax * 0.10
```

消费后只提高本次随机权重，最高增幅为 10%，不修改 Recognition 数值。候选即使最终落选也不返还气运。

`LegacyQiyunRule` 只在以下情况选择争机：

- 该道统相对当前主修有明确提升。
- 角色 Recognition 已处于有效竞争范围。
- 支付后仍保留至少 20% 有效上限。

最高相性者可以不花气运仍然获选，较弱者也不能仅靠满气运压过完全不匹配的候选。

#### 使用记录

入口与内部使用次数都只存在于当前对象：

```text
LegacySiteRuntimeState
  DiscoveryFortuneUsedByActorIds[]

LegacyParticipantRuleData
  TrialFortuneUsed
  ContestFortuneUsed
  TotalQiyunSpent
  LastFortuneActionId
```

`LegacyParticipantRuleData` 由常驻 `SubWorldRuntime` 直接持有。内部消费立即修改 `ProjectionQiyun.Value`，目标再次评估时直接读取这些标记。实例结束或当前会话清理后，全部使用记录随 Runtime 一起删除。

### 步骤 6：完善天机神力、人物展示与反馈

#### 玩家神力

保留第一阶段两个正式力量：

- “古修遗府”创建由玩家主动加入当前世界的机缘；第五阶段后优先使当前会话中的失传修订重新出世。
- “显露天机”只向玩家揭示地点，不为任何角色支付或增加气运。
- 玩家聚焦或直接拖动主相机查看小世界只获得观察权限，不替 Projection 揭开迷雾、触发转机或改变目标权重，也不暂停主世界时间。

本阶段不增加直接填满角色气运的正式按钮。调试需要通过现有 Debug 工具完成。

#### 人物展示

人物信息中的气运展示改为稳定的当前值/有效上限：

```text
气运 65 / 100
```

道统页额外显示：

- 本次遗府是否使用过发现、试炼或争机转机。
- 因气运获得的是重试还是权重机会，不显示内部随机数。
- 上一次气运消费的世界年份与原因。

角色处于 Runtime binding 中时，人物页通过 `SubWorldManager` 定位 Projection，并显示 `ProjectionQiyun` 当前值；返回后显示 Actor 的 Qiyun 当前值。界面始终只显示当前可消费的一套数值。

#### 世界反馈

- 发现转机成功时，在角色附近播放一次短促天机波纹。
- 试炼转机在对应小世界对象上播放道纹先破裂再重新闭合的反馈。
- 核心争机不提前播放效果，只在最终获选且气运确实参与时在 Winner Projection 上增加一道轻微反馈。

日常自然恢复和普通消费不写 WorldLog。只有失传道统因角色使用气运而重新被发现，并最终完成继承时，才在既有继承日志中增加“得天机相助”的描述。

### 步骤 7：完成长期平衡

#### 初始数值

| 行为 | 消耗 | 每 Site 上限 | 作用 |
| --- | ---: | ---: | --- |
| 发现转机 | 有效上限 15% | 1 次 | 强化重试一次 |
| 试炼转机 | 有效上限 25% | 1 次 | 保留部分进度并重试 |
| 核心争机 | 有效上限 10% | 1 次 | 最终权重最多提高 10% |
| 每月自然恢复 | 有效上限 1/12 | 每月一次 | 一年由空回满 |

单次遗府最多消耗有效上限的 50%。角色从空回满需要一年，因此不能连续对大量遗府保持全部转机。

#### 诊断

Debug 统计只记录当前会话聚合数据：

- 气运初始化角色数。
- 每月消费与自然恢复总量。
- 三类转机触发次数和成功次数。
- 因气运改变最终发现或获选结果的次数。

不在正式 UI 显示全世界概率和内部评分。
