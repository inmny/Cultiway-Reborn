# 第5阶段-道统谱系与分支演化

本阶段让功法传承在当前会话中形成可追溯历史。普通传授延续同一修订，真实改良产生子修订；残篇可以被补全，失传道统也可以在本次会话中重新出世。经由遗府取得的传承关联实际入口、常驻 `SubWorldRuntime` 和核心目标，使玩家能够查询来源与分支关系。

谱系、修订、人物持有、书籍关联、宗门认定、来源索引和历史事件都只存在于 `LineageSessionRegistry`。`CultibookBlueprint`、LineageId、RevisionId 和 ContentSignature 是当前会话内值对象。切换世界、返回主菜单或 Mod 重载时整个注册表清空，不把任何谱系状态带入下一会话。

## 具体说明

### 设计边界

- `Lineage` 表示共同祖源，`Revision` 表示一套确定的功法内容，`TransmissionGeneration` 表示人物间传了多少代。
- 同一修订从师父传给弟子不会克隆功法资产或创建新 Revision。
- 名称变化但内容签名不变时不创建新修订。
- 功法属性、语义、元素要求、修炼方式或法术池发生实质变化时才创建子修订。
- “正宗”不是世界级真理；Sect 可以把某个修订奉为本宗正传，其他宗门可以有不同认定。
- 不建立复杂可编辑谱系图，不允许玩家手工改父子关系或指定正宗。
- 不向 ActorData、BookData 或世界文档写入谱系字段；运行时对象只通过 `LineageSessionRegistry` 查询关联。
- 小世界来源只指向当前仍常驻的 `SubWorldRuntime`。实例结束或会话清理后，对应运行时跳转随之失效。

### 步骤 1：完善道统、修订与人物代数模型

#### 根道统

`LineageSessionRegistry` 维护 `DoctrineLineageState`：

```text
LineageId
RootRevisionId
CanonicalName
FounderSnapshot
CreatedAt
OriginKind
```

根道统只表达共同身份和祖师，不重复持有功法内容。

#### 修订

每个 `DoctrineRevisionState` 包含：

```text
RevisionId
LineageId
ParentRevisionId
ContentSignature
CreatedBySnapshot
CreatedAt
Integrity
SemanticDrift
CultibookBlueprint
SourceRevisionIds[]
```

`ContentSignature` 只包含影响修炼和法术的规范字段，不包含：

- 功法显示名与描述。
- 创建者姓名和 Actor ID。
- 创建年份、来源遗府和宗门认定。
- 掌握度和当前持有人。

因此同一内容被抄写、改名或重新装订时仍是同一 Revision。已经注册的 `CultibookBlueprint` 在当前会话内不可变，内容变化必须创建新 Revision。

#### 人物持有

`LineageSessionRegistry.ActorHoldings` 以 ActorId 关联 `ActorLegacyHolding`：

```text
RevisionId
Mastery
TransmissionGeneration
TeacherActorId
AcquisitionKind
SourceSiteId
SourceSubWorldId
SourceBookId
AcquiredAt
IsMainCultibook
```

人物代数独立于修订深度：

- 自创根功法者为第 0 代。
- 从人物、书籍、宗门讲法或遗府继承时，在来源代数基础上加 1。
- 同一人物改良功法后仍保留自己的传承代数，但持有新的 Revision。
- 不知道直接传授者的残篇继承，以遗府祖师代数加 1，并关联当前 Site、SubWorldId 与核心 Winner。

Actor 死亡、书籍销毁、Sect 解散或 Runtime 目标耗尽时，注册表立即移除相应引用并重新计算道统状态。

### 步骤 2：接入功法生成与改良事件

#### 自创功法

接入 `CultibookGeneratedEventSystem`。当角色成功接受一部尚未登记的自创功法时：

1. 使用 `CultibookBlueprintExporter` 导出完整 Blueprint。
2. 创建新的 Lineage 与根 Revision。
3. 为角色增加第 0 代、`AcquisitionKind=Created` 的持有状态。
4. 将运行时功法 Asset ID 绑定到 RevisionId。
5. 向当前会话事件列表加入自创历史。

生成草稿失败、没有被角色接受或无法通过 Blueprint 验证时不创建空道统。

#### 改良功法

接入 `CultibookImprovedEventSystem` 的接受结果：

1. 找到角色原功法对应的 Parent Revision。
2. 导出改良后的完整 Blueprint。
3. 计算 ContentSignature。
4. 与 Parent 签名相同则只更新显示名或描述，不创建子修订。
5. 签名不同则创建同一 Lineage 下的新 Revision。
6. 将角色持有状态切换到新 Revision，旧 Revision 仍可被其他当前持有人引用。

如果原功法尚未进入注册表，先以原功法创建根 Revision，再把改良结果作为子 Revision。不能把改良版错误登记为没有父级的全新道统。

### 步骤 3：让师徒、书籍和藏经阁保留修订关系

#### 师徒传授

扩展现有 `TeachCultibook()`：

- 通过运行时功法 Asset ID 解析 RevisionId。
- 接收者继续 `Master(asset, mastery)`，同时更新会话内 Actor Holding。
- `TeacherActorId` 指向真实师父。
- `TransmissionGeneration = teacher.Generation + 1`。
- 重复传授同一 Revision 只增加掌握度，不增加代数。

普通讲法和师徒传授不创建 Blueprint 深拷贝，也不增加 Revision 引用之外的动态资产。

#### 功法书

写书时由 `LineageSessionRegistry.BookRevisionBindings` 建立：

```text
BookRuntimeId
RevisionId
WriterGeneration
WrittenAt
```

读书时按 BookRuntimeId 解析 Revision，再从会话注册表取得功法。书籍销毁时同步移除绑定。书籍本身继续使用原版 `Book` 与现有 `BookExtend`，不创建第二套“传承卷轴”对象。

#### 宗门藏经阁

`SectScriptureCollection` 收录功法书后，在 `LineageSessionRegistry.SectRevisionBindings` 建立 Sect 对该修订的知识来源。宗门讲法从该绑定解析同一 Revision，并把讲法者或书籍作为接收者来源。

每个 Sect 可以在当前会话中认定：

```text
LineageId -> CanonicalRevisionId
```

这表示“本宗奉此修订为正传”，只影响宗门展示、讲法优先级和命名，不修改全局谱系关系。Sect 解散时移除该宗门的知识引用和正传认定。

### 步骤 4：实现支脉判定与残篇补全

#### 内容差异

新 Revision 相对 Parent 计算：

- 元素需求方向变化。
- 语义余弦相似度。
- 修炼方式是否改变。
- 属性集合与数值变化。
- 法术池新增、移除和替换比例。
- 完整度变化。

由这些事实推导展示类型：

| 类型 | 条件 |
| --- | --- |
| 根本 | 没有 Parent 的完整 Revision |
| 续修 | 内容保持同一方向，完整度不下降，差异未达到分支阈值 |
| 支脉 | 语义方向、修炼方式或法术池发生明显分化 |
| 残篇 | `Integrity < 1.0` |
| 复原 | Parent 为残篇且新 Revision 的完整度显著提高 |

类型由当前事实计算，不维护可能与内容冲突的手工枚举。

#### 同父分支

同一个 Parent 出现两个及以上内容不同的子 Revision 时，谱系自然形成分叉。系统不选择唯一正确答案；Sect 可以分别认领其中一支为正传。

#### 残篇补全

角色满足以下条件时可进入 `Cultiway.RestoreDoctrineFragment` 工作：

- 掌握一个残篇 Revision 达到指定熟练度。
- 同时掌握同 Lineage 的另一残篇、父修订线索或足够多兼容法术。
- 神识、智力和当前境界达到残篇修复要求。

修复调用现有功法改良规则，以残篇为 Parent 生成新 Revision：

- `Integrity` 只能根据实际补回的属性和法术池提高。
- 两份来源残篇都进入 `SourceRevisionIds`，但主 Parent 仍为当前修炼残篇。
- 完整度达到 `1.0` 时显示为复原版本，不自动等同于过去出现过的完整 Parent。
- ContentSignature 与当前会话中的旧完整 Revision 相同时，复用旧 RevisionId 并增加“复得”事件，不创建重复版本。

### 步骤 5：实现活跃、留存、沉寂、失传与复出

`LineageSessionRegistry` 根据当前内存中的真实引用推导每个 Revision 的状态：

| 状态 | 当前仍存在的来源 |
| --- | --- |
| `Active` | 至少一名存活角色正在掌握 |
| `Preserved` | 没有存活持有人，但存在功法书或 Sect 藏经绑定 |
| `Secluded` | 只存在于常驻 `SubWorldRuntime` 的未完成核心目标或宗门遗址实体中 |
| `Lost` | 注册表中仍有 Blueprint，但角色、书籍、Sect 和 Runtime 都不再引用 |

Actor、Book、Sect、Site 和 `SubWorldRuntime` 的创建、转移、销毁及目标变化通过事件直接更新会话内引用集合。状态查询只扫描这些当前对象或读取内存索引，不从外部数据重建，也不承诺跨会话保持。

#### 失传

Revision 首次从非 Lost 进入 Lost 时增加一次会话内历史。只有根道统或曾经形成重要分支的修订写公开 WorldLog，普通短命改良版不刷屏。

失传不会立即删除当前会话中的 Blueprint，因此本次会话后续仍可以让它重新出现。会话清理时 Blueprint、状态和历史一起清空。

#### 复出

以下行为可以让 Lost Revision 在当前会话中重新出现：

- 玩家投放古修遗府时，优先从当前 Lost 修订中选择内容。
- 当前仍常驻的覆灭宗门遗址中存在对应书籍或核心目标。
- 残篇修复的 ContentSignature 与旧 Revision 完全相同。

复出复用当前会话中的 RevisionId，增加新的来源事件，不克隆成同内容新版本。

### 步骤 6：增加人物与道统只读页面

实施前继续遵守 `Prompts/UI.md`，复用当前 CreatureInfoPages、Foundation、Controls 和原版窗口行为。

#### 人物道统页

在人物信息中增加“道统”页，展示：

- 当前主修修订及所属根道统。
- 传承代数、直接师承或来源遗府实例。
- 掌握度、完整度和功法类型。
- 当前人物亲自创建的改良修订。
- 跳转到当前仍存在的来源人物、书籍、Sect 或遗府入口。
- 来源 Runtime 仍活跃时，通过 `SubWorldManager` 打开实例并定位核心房间。

页面只读取该人物的会话内持有状态，不扫描无关谱系。

#### 道统谱系窗口

新增代码构建宽窗口，采用：

- 顶部搜索与 `现世 / 沉寂 / 失传` Segmented Tabs。
- 左侧可滚动根道统目录。
- 右侧单层详情区展示祖师、当前状态和按父级缩进的修订列表。
- 选中 Revision 后展示内容差异、重要事件和当前来源。
- 遗府来源事件显示 Site 名、SubWorldId、核心目标状态和 Winner，不展示已经失效的运行时 Entity ID。

不实现可拖拽节点图、自由缩放画布或卡片嵌套。谱系父子关系用稳定缩进、连接符和状态图标表达。

#### 功法与书籍 Tooltip

现有功法、技能来源和书籍 Tooltip 增加：

- 根道统名。
- 修订类型和完整度。
- 创建者或改良者。
- 当前人物传承代数。
- Sect 正传认定仅在查看对应 Sect 内容时显示。

### 步骤 7：补齐当前会话历史与资源

公开日志只记录：

- 世界中出现新的根道统。
- 某位重要修士开创明显支脉。
- 重要道统彻底失传。
- 失传道统重新出世。
- Sect 正式把某个修订奉为正传。

普通师徒传授只更新持有状态，不逐次生成 WorldLog。人物普通传授历史由当前 Actor Holding、书籍关联和重要事件共同表达，不记录每次讲法的听众列表。
