## 具体说明

### 设计边界

本阶段只实现一种来源和一种探索规模：

- 玩家在合法地块投放一座完整古修遗府。
- 遗府从当前已经注册且可完整导出的功法中构造古修道统。
- 附近修士可以独立发现入口、前往、生成 Projection 并完成探索。
- 同时只允许一名预约探索者，不实现消息传播、多人试炼或宗门集结。
- 实例固定包含入口、封禁、外围室、核心室和出口；角色必须在内部移动并与目标交互。
- 核心奖励至少包含完整功法和一项代表法术；镇府法宝只在已注册 `IPortableItemTransferAdapter<ArtifactInstanceSnapshot>` 能完整导出时，以 typed `ContentRef<ArtifactInstanceSnapshot>` 和稳定 `ItemId` 物化为内部唯一物品。
- 外围遗藏可以包含已注册 transfer adapter 的 `ContentRef<MagicScrollSnapshot>` 与 `ContentRef<TalismanSnapshot>`；两种载体分别使用真实 typed snapshot，不用通用技能载体替代。
- 道统、入口、角色掌握关系和实例内部状态都只属于当前会话。

阶段结束时，玩家可以投放一个真实改变角色成长的机缘，而不是只看到建筑和日志。

### 步骤 1：建立运行时不可变功法蓝图

新增 `CultibookBlueprint` 及唯一 exporter。蓝图只包含稳定值与稳定 Asset ID，不包含运行时 `Entity`：

```text
CultibookBlueprint
  BlueprintId
  SourceAssetId
  Name
  Description
  Level
  Stats[]
  Semantics[]
  ElementRequirement
  ElementAffinityThreshold
  MinLevel
  MaxLevel
  CultivateMethodId
  SkillPool[]
  ConflictConditions[]
  SynergyConditions[]
```

`CultibookBlueprint` 是当前会话内的不可变值对象，用于深拷贝已有功法、计算内容签名、物化动态功法以及向 SubWorld Projection 投影能力。它不是外部数据格式。

`Stats` 按 Stat Asset ID 排序，`Semantics` 直接复制 `SemanticContribution`。`SemanticQueryExpression` 只包含 `all/any/none` 三组字符串 ID，可以直接深拷贝。

每个 `SkillPoolBlueprintEntry` 包含：

```text
SkillBlueprint
BaseChance
MasteryThreshold
LevelRequirement
```

#### 导出规则

1. 读取 `CultibookAsset` 的全部稳定字段。
2. 对每个法术池 Entity 调用现有 `SkillBlueprintExporter`。
3. 使用 `SkillBlueprintValidator` 验证本体、轨迹、资源与词条 Asset ID。
4. 任意法术池条目无法导出时，整部功法不能成为遗府内容；不能静默丢掉法术。
5. 规范化数组顺序并深拷贝，计算只基于内容的结构签名。
6. `SourceAssetId` 只记录本次会话中的来源，不作为动态功法身份。

#### 运行时物化规则

1. 验证修炼方式、属性、语义和全部技能蓝图。
2. 使用共享 Skill compiler 按结构签名把每个 `SkillBlueprint` 解析为唯一 `CompiledSkillDefinition`；MainWorld 角色和 SubWorld Projection 必须引用同一定义。
3. MainWorld skill port 根据 compiled definition 建立 SkillLibV3 技能容器并添加 `TagOccupied`；SubWorld skill port 只暴露同一 definition 的 capability。
4. 以道统 `RevisionId` 作为动态 `CultibookAsset.id`，避免覆盖原始功法资产。
5. 写入全部稳定字段，调用功法规则合成器完成规范化。
6. 将动态功法加入 `CultibookLibrary`，由当前会话中的角色掌握关系引用。
7. 中途失败时释放本次已经创建的 MainWorld 技能容器，不向动态库留下半成品。

同一 `RevisionId` 在当前 `LegacyWorldState` 中只物化一次。多个角色掌握同一修订时共享同一个不可变 `CultibookAsset`，各自拥有独立掌握度。

### 步骤 2：建立道统目录与角色掌握状态

#### 道统目录

`LegacyWorldState` 是当前会话中机缘道统的顶层状态：

```text
LegacyWorldState
  DoctrineRevisions: Dictionary<RevisionId, DoctrineRevision>
  ActorHoldings: Dictionary<ActorId, ActorLegacyHoldings>
  Sites: Dictionary<SiteId, LegacySiteState>
  HistoryEntries: List<LegacyHistoryEntry>
```

每个 `DoctrineRevision` 持有：

- `LineageId`、`RevisionId`、`ParentRevisionId`。
- 古修祖师姓名值、来源类型和创建年份。
- 完整度；首阶段固定为 `1.0`。
- `CultibookBlueprint`。
- 代表法术在法术池中的索引。

`LegacyWorldState.RegisterRevision()` 是修订注册的唯一入口。它按当前会话唯一的 `RevisionId` 去重，并更新内存索引。世界生命周期结束时整个状态对象直接清除。

#### 角色掌握状态

角色获得道统后，在 `LegacyWorldState.ActorHoldings` 中建立 `ActorLegacyHoldings`：

```text
ActorLegacyHoldings
  Holdings[]
    RevisionId
    Mastery
    IsMainCultibook
    LearnedRepresentativeSkillIds[]
    AcquiredAt
    SourceSiteId
```

该状态只引用当前 `LegacyWorldState` 中的修订，不重复整份功法蓝图。角色获得传承时，`LegacyMasteryService` 解析对应修订，经共享 compiler 和 MainWorld skill port 调用 `Master()`、设置主修并授予代表法术。角色死亡或世界生命周期结束时，对应运行时关系按正常对象清理流程移除。

### 步骤 3：注册完整遗府入口与常驻实例

在 `Buildings` 中注册 `Cultiway.LegacyEstate`，从原版 `monolith` 克隆并改为非城市建筑：

- 可在合法陆地单点放置。
- 不属于城市或文明，不参与建筑升级和城市建造队列。
- 可被世界灾害摧毁。
- 活跃期间保持 `BuildingState.Normal`。
- `has_ruin_state=true`，耗尽或摧毁后才进入原版废墟状态。
- `auto_remove_ruin=false`，让本次会话中已经发生的历史留在地图上。

每个入口在 `LegacyWorldState.Sites` 中对应一个 `LegacySiteState`：

```text
LegacySiteState
  SiteId
  BuildingId
  RevisionId
  SubWorldId
  State
  Integrity
  PlayerRevealed
  CreatedAt
  Discoverers[]
  ReservedActorId
  WinnerActorId
  ClaimedAt
```

`LegacySiteState` 只持有入口和查找运行时实例所需的状态，不持有内部地图、实体、容器、物品、Projection 或目标数据。

创建入口与内部实例在同一主线程调用中完成：

1. `LegacyAncientDoctrineFactory` 生成不可变道统修订值。
2. `LegacyWorldState.RegisterRevision()` 注册修订。
3. 创建 `Cultiway.LegacyEstate` Building 与 `LegacySiteState`。
4. 调用 `SubWorldManager.Create()`，以 Template `Cultiway.Legacy.AncientEstate` 立即生成 `SubWorldRuntime`。
5. Generator 立即创建地图 Grid、封禁门、容器、typed 物品、核心目标和出口，并把它们直接写入 Runtime 的地图与 ECS EntityStore。
6. 把 Runtime 的 `SubWorldId` 写入 `LegacySiteState`，加入 Site ID、Building ID 和空间分桶索引。

任一步失败时，在本次调用中销毁已经创建的 Building、Runtime 和未被其他地点引用的修订值。成功返回后入口与 Runtime 同时可用。

首个模板采用确定性布局：

```text
入口 -> 封禁门 -> 外围室 -> 核心室 -> 出口
```

Generator 逐格写入 `SubWorldTile` 的原版 Asset ID：石室首版把 `soil_low` 写入每格 `MainAssetId`，把 `wall_ancient` 写入墙格 `TopAssetId`，其他格的 `TopAssetId` 为空。入口和出口只写入 `SubWorldMapData.EntryTileIndices/ExitTileIndices`，不混入 terrain 字段。

`SubWorldGrid` 对每格调用 `AssetManager.tiles.get(MainAssetId)`，并在 `TopAssetId` 非空时调用 `AssetManager.top_tiles.get(TopAssetId)`，直接缓存原版对象。`Cultiway.Legacy.AncientEstate` 只注册房间布局、独立封禁/目标 overlay 与非 terrain VisualProfile；WorldView 在稳定周边槽位中的私有 Main/Top Tilemap 分别直接使用原版对象的 `sprites.main`。没有 Top 时对应格为空，不注册 Legacy 基础 terrain，也不按 terrain ID 替换 Sprite 或 Material。

首阶段状态为：

```text
Hidden -> Known -> Opening -> Claimed -> Exhausted
```

`LegacySiteState` 是入口与消息状态的唯一写入口；`SubWorldRuntime` 是内部状态唯一写入口。内部无人活动时 Runtime 降低 tick 频率，但仍常驻 `SubWorldManager`。

遗府基础建筑使用低调的封石或山岩画面。`PlayerRevealed=false` 时不显示 Tooltip 详情、小地图颜色或额外世界标记；不依赖切换 BuildingAsset 表达显露状态。

### 步骤 4：实现古修遗府与显露天机神力

注册两个正式 World Tool：

| God Power ID | 显示名 | 点击语义 |
| --- | --- | --- |
| `Cultiway.PlaceAncientLegacyEstate` | 古修遗府 | 在合法地块创建一座完整且对玩家已显露的古修遗府 |
| `Cultiway.RevealLegacySites` | 显露天机 | 显露笔刷范围内已经存在的遗府，不把消息授予角色 |

两个 Power 都通过 `WorldboxGodPowers.SetupWorldToolPower` 注册，`hold_action=false`。显露天机设置固定 Brush 范围，复用原版光标高亮。

`LegacyAncientDoctrineFactory` 创建古修来源：

1. 从当前 `CultibookLibrary` 中筛选能够完整导出的功法。
2. 排除法术池为空、修炼方式失效或 Blueprint 验证失败的候选。
3. 从合格集合选择一部作为内容来源，导出后赋予新的 `LineageId` 与 `RevisionId`。
4. 生成古修祖师姓名和简短来源描述，不将其伪装成当前世界角色。
5. 若内容目录中存在可由已注册 portable transfer adapter 完整物化的法宝、魔法卷轴或符箓，分别生成稳定 `ItemId` 与 typed snapshot，作为 Runtime 创建参数。
6. `SubWorldManager.Create()` 让这些物品直接首次物化在对应容器或核心室；两个技能载体只携带嵌套 `StoredSkillPayloadSnapshot`，不复制 SkillContainer Entity 或 `CompiledSkillDefinition`。
7. 完成修订、Building、`LegacySiteState` 与 Runtime 创建后返回成功；前置条件不足时不消耗地块，并显示本地化原因。

玩家投放、自然死亡和未来宗门遗址必须共用 `LegacySiteFactory.Create()` 与 `SubWorldManager.Create()`，不能各自复制入口和实例创建逻辑。

### 步骤 5：实现单人发现、寻访与进入实例

#### 发现

在 `ActorJobSelectionRegistry` 注册低频遗府 selector。只有满足以下条件的角色进入发现检查：

- 已经拥有仙道修炼体系。
- 当前不在战斗、突破、集体活动或不可中断任务中。
- 附近空间桶存在 `Hidden` 或 `Known` 遗府。
- 角色尚未出现在该 Site 的知情集合中。

发现概率首阶段只使用现有能力：

- 智力。
- 神识。
- `Effect.Perception` 语义净分。
- 与遗府的实际距离。

不读取尚未初始化的 `Qiyun`。发现成功后向 `LegacySiteState.Discoverers` 添加当前 Actor ID，状态从 `Hidden` 进入 `Known`，并写发现日志。

#### 单人预约

首阶段不允许多人同时开启。遗府从已发现且满足最低境界与元素要求的存活角色中选择一名预约者：

- 基础相性采用现有元素契合与功法语义契合。
- 距离和当前任务只决定是否能够出发，不进入道统相性。
- 预约写入 `ReservedActorId`；其他角色保留消息但暂不前往。
- 预约者死亡、失去修炼体系或连续超时后释放预约。

预约者获得 `Cultiway.SeekLegacyEstate` 工作，设置 `beh_building_target` 并复用 `BehGoToBuildingTarget`。角色抵达入口后，由 `LegacyEntryService.TryEnterSingle()`：

1. 检查入口仍指向当前 `SubWorldManager` 中的目标 Runtime。
2. 建立纯运行时 `ExpeditionBinding`，关联 MainWorld Actor、`SubWorldId` 与即将创建的 Projection。
3. 在 Runtime 入口格创建 `ExpeditionProjection`，复制探索所需属性和 compiled capability。
4. 暂停并隐藏主世界本体，使年龄、饥饿、伤害、AI 和模组定时逻辑不再推进该 Actor。
5. 把入口摘要切换为 `Opening`，Projection 开始使用小世界探索 AI。

入口 `step_action` 不推进封禁、不授予奖励。`ExpeditionBinding` 只存在于当前会话内的 `LegacyEntryService` 与 Runtime 参与关系中。

### 步骤 6：实现内部探索、核心目标与同步返回

首阶段核心资格：

```text
境界在功法 MinLevel..MaxLevel 内
ElementReq.Check(root) == true
综合相性 >= 0.3
```

综合相性复用现有解析器：

```text
Compatibility = 0.7 * ElementAffinity + 0.3 * SemanticAffinity
```

Projection 使用小世界导航和交互系统执行最小探索序列：

1. 从入口移动到封禁门，使用 `ISkillDefinitionRegistry` 解析的 `CompiledSkillDefinition` 神识/破禁 capability 执行交互；Legacy 不建立试炼技能解释器。
2. 进入外围室，自行决定是否打开容器、拾取法宝、魔法卷轴、符箓或其他已注册 typed 物品。
3. 到达核心室，与 `LegacyCoreObjective` 交互并检查境界、元素与综合相性。
4. 通过后由目标锁定唯一 Winner，并在 Projection 的运行时结果组件中写入功法 Revision ID、代表技能索引和初始掌握度。
5. 若核心室存在镇府法宝，Winner 仍需走到物品旁拾取；拾取只改变 Runtime ECS 中该实体的 Holder 关系，核心目标不能远程发放物品。
6. Projection 到达出口后，由 `ExpeditionReturnCoordinator` 在同一主线程调用中完成返回。

`ExpeditionReturnCoordinator` 的顺序固定为：

1. 从 Projection 与 Runtime ECS 捕获角色伤势、资源变化、掌握结果，以及其背包中每件物品的 typed snapshot、稳定 `ItemId` 和目标 Holder。
2. 对全部目标 transfer adapter、MainWorld EntityStore 与 Holder 进行一次确定性准备检查。
3. 对每件物品依次移除 SubWorld 源物化，再通过同一 transfer adapter 在 MainWorld 创建相同 `ItemId` 的目标物化并绑定接收者。
4. 某件目标创建失败时，先清理其不完整目标，再用已捕获值重新创建 SubWorld 源物化，并按逆序把本次已经移出的其他物品同步移回 Runtime；Projection 与 Binding 保持原状。
5. 全部物品转移成功后，调用 `LegacyResultApplier` 授予功法与代表技能、应用伤势和资源，再销毁 Projection 并解除 `ExpeditionBinding`。
6. 最后更新 `LegacySiteState.WinnerActorId`、`ClaimedAt` 和当前会话历史。

`LegacyResultApplier` 只处理机缘字段：

1. 从 `LegacyWorldState` 解析修订，其中全部 `SkillBlueprint` 先解析为共享 `CompiledSkillDefinition`。
2. 调用 `ActorExtend.Master()` 写入初始掌握度。
3. 从代表技能中选择与角色语义最匹配的一项，经 `MainWorldSkillAdapter` 授予同一 compiled definition 对应的运行时技能。
4. 仅当新功法对当前灵根的修炼效率高于现有主修时，调用 `SetMainCultibook()`。
5. 更新 `ActorLegacyHoldings`、入口 Winner 摘要和当前会话历史。

`LegacyResultApplier` 不创建物品，也不维护独立提交状态。初始掌握度按相性映射到 `10..30`，不能直接满掌握。传承给予修行入口和一项代表法术，不替代后续修炼。

返回完成后遗府进入 `Claimed`。Runtime 中不再存在可拾取内容且没有参与者时，入口进入 `Exhausted` 并转为原版废墟表现；对应 Runtime 可由 `SubWorldManager.Destroy()` 立即释放，地点摘要与当前会话道统关系留在 `LegacyWorldState`，直至整个世界生命周期结束。

### 步骤 7：补齐日志、Tooltip 与地图表现

#### WorldLog

首阶段注册两类高价值日志：

- 某修士发现某古修遗府。
- 某修士在某地获得某道统传承。

日志绑定当前 Actor，并记录地块坐标，允许从日志跳转。预约、赶路和资格不足不写 WorldLog，避免刷屏。

#### Tooltip 与地图

- 光标位于已显露遗府时，通过原版 `RawTip` 显示名称、完整度、当前阶段和道统名称。
- 未显露时不显示遗府身份，只保留低调建筑画面。
- `mini_0.png` 只在 `PlayerRevealed=true` 时返回状态颜色。
- 已显露遗府使用对象池世界标记，样式复用现有 Realm Indicator 的渲染生命周期。
- 状态变化后标记占用地块 dirty，立即刷新小地图。
- Tooltip 提供“聚焦内部”命令，调用 `SubWorldManager.Focus(SubWorldId)` 把主相机移动到遗府 WorldView；主世界继续运行，玩家观察不替角色揭开迷雾。

### 会话结束清理

切换到另一主世界、返回主菜单或 Mod 重载时，按以下顺序清理：

1. 解除所有 `ExpeditionBinding`，丢弃 Projection 尚未带回的运行时结果。
2. `SubWorldManager.Clear()` 销毁全部遗府 Runtime、内部 EntityStore、地图、WorldView、空间槽位与底栏入口。
3. 清除地点 Repository、空间桶、动态功法物化缓存和技能引用。
4. `LegacyWorldState.Clear()` 清除修订、角色掌握、地点与历史。

这些边界之后，上一主世界的 `RevisionId`、`SiteId` 与 `SubWorldId` 均不可再解析。
