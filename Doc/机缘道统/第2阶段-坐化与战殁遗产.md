# 第2阶段-坐化与战殁遗产

本阶段让当前世界中的真实修士自然留下道统。寿元将尽者生前寻地安排完整遗府，突然战死者只留下未被夺走的遗物与残缺知识；两者都会创建来源、布局和规则不同的常驻 `SubWorldRuntime`，而不是只改变入口建筑和奖励表。本阶段建立在机缘道统第 1 阶段之上，直接消费原版 `TileTypeBase` 复用、稳定 ItemId、typed portable item、共享技能与战斗，以及 `SubWorldManager` 的纯运行时实例管理。

## 具体说明

### 设计边界

本阶段新增三种自然结果：

| 角色状态 | 死亡情况 | 结果 |
| --- | --- | --- |
| 已完成临终准备 | 任意死亡 | 在预定地点创建完整遗府入口与完整内部 Runtime，不再生成核心战场残卷 |
| 未完成准备但寿终 | `AttackType.Age` | 在合法附近地点形成完整度略低、规模较小的临终洞府 Runtime |
| 未完成准备且突然死亡 | 战斗或其他非寿终死亡 | 在死亡地点附近形成破损、危险且局部坍塌的战殁残迹 Runtime |

本阶段仍沿用第一阶段的单人进入与内部探索，不加入多人争夺和宗门行动。重点是来源、模板参数、typed 值与物权正确性。人物、准备、道统、入口和实例都只存在于当前游戏会话。

### 死亡物权处理顺序

当前 `Actor.checkDeath()` 会先进入击杀者 `newKillAction()`，随后才进入 `Actor.die` 与 `ActorExtend.Dispose()`。若等到 `Actor.die` Prefix 才处理遗物，城市、击杀者或 Dispose 已可能先改变和回收源 Entity。本阶段把遗物选择与转移前移到同一主线程死亡物权窗口：

1. 判定死亡类型、遗产资格、宗门借物与击杀者/城市既有分配规则，明确哪些个人物品进入遗府，哪些继续交给原死亡流程。
2. 完成道统 Blueprint、人物来源值、合法地点和 Template 参数计算。
3. 创建 Building、`LegacySiteState` 与空的目标 `SubWorldRuntime`；Generator 已经创建对应容器槽位。
4. 对每件选定遗物调用对应 `IPortableItemTransferAdapter.Capture()`，取得 typed snapshot、稳定 `ItemId` 与来源 Holder 值。
5. 在当前调用中移除死者 Holder、装备和工序关系，销毁 MainWorld 源物化，再用同一 transfer adapter 在 Runtime EntityStore 创建相同 `ItemId` 的目标物化并绑定容器槽位。
6. 目标创建失败时清理不完整目标，并立即用捕获值在 MainWorld EntityStore 重新创建源物化；该物品继续由原死亡流程处理。
7. 成功转入 Runtime 的 Item ID 加入本次调用的 `TransferredItemIds`，击杀者、城市和 Dispose 只处理其余物品。

任一时刻同一 `ItemId` 最多存在一个有效物化。步骤 1 至步骤 3 失败时不接触源物品；单件物品转移失败不会复制或吞掉原物品，也不会阻止仍有有效核心内容的遗府成立。

`Actor.die` Prefix 仍可捕获人物、功法与死亡来源值，但不再假定 portable item Entity 仍属于死者。战殁残迹所谓“击杀者取得的物品不重复生成”，由步骤 1 的唯一分配决定。

同一个 Actor 的尸体销毁阶段还会再次调用 `die(pDestroy:true)`。遗产入口要求 `actor.isAlive()`，只响应首次真实死亡。

### 步骤 1：建立留道资格与遗产值规则

#### 资格规则

资格不使用声望或随机抽奖，而由实际成就决定：

| 境界 | 留道规则 |
| --- | --- |
| 元婴 | 只要存在可导出的主修功法即具备资格 |
| 金丹 | 主修功法可导出，并满足功法掌握、代表法术或个人法宝中的任一成就条件 |
| 筑基、炼气 | 必须拥有自创或改良功法修订，或者拥有达到指定品质且能由已注册 portable transfer adapter 完整转移的个人法宝 |

`LegacyWorthEvaluator` 读取以下实际内容形成可解释结果：

- 当前仙道境界。
- 主修功法掌握度。
- 功法是否属于角色创建或改良的动态修订。
- 已学且可导出的代表法术数量。
- `CoreFormationSnapshot.quality_score` 与代表法术。
- 完全属于个人且可由 `IPortableItemTransferAdapter<ArtifactInstanceSnapshot>` 捕获的法宝品质。

Evaluator 返回 `Eligible`、主要理由和建议遗府规模，不返回难以解释的总声望值。元婴的境界资格不能绕过“必须存在可传承内容”。

#### 人物来源值

遗产使用不可变 `LegacyFounderValue` 描述祖师：

```text
LegacyFounderValue
  ActorId
  Name
  RaceAssetId
  KingdomId
  CityId
  SectId
  Realm
  CoreFormationName
  MainCultibookName
  CreatedAt
  DiedAt
  DeathKind
```

Actor、City、Sect 对象引用不进入该值。ID 只用于当前世界内尝试解析，姓名与关键描述在对象消失后仍可供本次会话的日志、Tooltip 和谱系展示。

#### 道统来源

如果角色主修功法已经属于 `LegacyWorldState` 中的某个修订，遗产沿用其 `LineageId` 和 `RevisionId`。普通静态或尚未登记的动态功法先完整导出为 `CultibookBlueprint`，再创建新的根道统。

完整洞府引用完整修订；战殁残迹根据原修订创建一个残篇子修订：

- 保留相同 `LineageId`。
- 新建 `RevisionId`，`ParentRevisionId` 指向死亡时的完整修订。
- 只保留部分法术池条目。
- 使用固定 Fragment Composer 按完整度缩减属性和法术领悟率。
- 持有 `Integrity`，供后续补全和谱系展示。

残篇变化必须由明确 composer 完成，不能在死亡处理代码里散落随机删字段。完整与残篇 Blueprint 都是当前 `LegacyWorldState` 中的不可变内存值。

### 步骤 2：实现临终准备状态与寻地任务

#### 触发窗口

增加低频 `LegacyPreparationSelector`。每月只检查：

- 已具备留道资格。
- 当前没有有效 `LegacyPreparationState`。
- 当前年龄已经进入最大寿命前 5 年。
- 不在战斗、突破、集体行动或长期不可中断任务中。

寿命判断直接使用原版 `getAge()` 与 `getMaxAge()`，不复制原版寿命公式。

#### 准备状态

准备过程由 `LegacyWorldState.Preparations[ActorId]` 持有：

```text
LegacyPreparationState
  Stage
  TargetX
  TargetY
  RevisionId
  PreparedAt
  CompletedAt
```

阶段为：

```text
Selecting -> Travelling -> Sealing -> Completed
```

道统修订在开始准备时注册进 `LegacyWorldState`。完成封印时再次比较主修功法；如果人物已经改良出新修订，就更新当前准备状态引用。

准备状态只服务于连续运行的当前世界。切换到另一主世界、返回主菜单或 Mod 重载时，与其他机缘状态一起清除。

#### 选址

`LegacySiteLocator` 只选择角色真实可达的合法陆地：

- 不在液体、岩浆或世界边缘。
- 当前没有 Building，且满足遗府建筑 footprint。
- 不在城市建筑密集区。
- 与其他活跃遗府保持最小距离。
- 优先同一陆块、当前地理区域或所属宗门附近的荒野。
- 距离不能近到像城市附属建筑，也不能远到临终角色无法抵达。

选址完成后角色执行 `Cultiway.PrepareLegacyEstate`，使用 tile target 前往并停留一个月完成封印。此时只更新 `LegacyPreparationState`，不提前创建 Building、Runtime 或移动物品，因此主人死亡前不会出现可探索入口。

### 步骤 3：实现寿终后的完整洞府

死亡物权窗口把 `AttackType pType` 传给 `LegacyDeathService.TryCreateLegacy()`。当 `pType == AttackType.Age` 时，根据准备状态选择完整模板。

#### 已完成准备

1. 从 `LegacyWorldState.Preparations` 读取目标地点与 Revision ID。
2. 确认目标地块仍可建造；若环境已变化，在原目标附近重新选择合法地块。
3. 从角色当前个人物品中选择仍然存在、有稳定 `ItemId` 且具备已注册 portable transfer adapter 的遗物。
4. 创建 `Cultiway.LegacyEstate`、`LegacySiteState` 和 Template 为 `Cultiway.Legacy.PreparedEstate` 的常驻 `SubWorldRuntime`。
5. Generator 直接构造完整地图、封禁、容器和核心目标，并把完整度、道统语义与 `LegacyFounderValue` 作为当前 Runtime 参数。
6. 对选定遗物逐件执行“捕获 typed 值、移除 MainWorld 源物化、在 Runtime 容器创建同一 ItemId 目标物化”的同步转移。
7. 入口进入 `Hidden`，Runtime 保持低频更新，默认不对玩家和角色显露。

法宝、魔法卷轴与符箓分别按 `ContentRef<ArtifactInstanceSnapshot>`、`ContentRef<MagicScrollSnapshot>`、`ContentRef<TalismanSnapshot>` 的真实类型进入 Runtime。`LegacySiteState` 不持有物品事实。

#### 未完成准备

寿终者只要仍满足留道资格，就在死亡地块附近创建“临终洞府”：

- 使用死亡时完整功法修订。
- 完整度固定低于生前完成封印的洞府。
- 地点优先同一 GeoRegion 的可用荒地。
- 只转移死亡时仍属于个人、已有稳定 `ItemId` 且具备已注册 portable transfer adapter 的物品。
- 使用 `Cultiway.Legacy.LastMinuteEstate` 模板，房间更少、封禁较弱且外围容器容量较低。

这条规则保证元婴不会因为寻路尚未完成而完全失去道统，但生前完成准备仍具有更高完整度和更多遗物容量。

已经完成准备的角色即使后来战死，也只在预定地点创建完整遗府；战场可以留下普通材料或尸身，但不再生成第二份核心功法残卷。

### 步骤 4：实现战死后的残破遗地

注册第二个活跃建筑 `Cultiway.LegacyRemnant`。它使用残破石碑、断裂洞口或散落卷轴的画面，但交互期间仍保持 `BuildingState.Normal`；耗尽后才进入自己的 `ruin_0` 终态。

突然死亡满足留道资格且没有已完成准备时：

1. 在击杀者、城市和 `ActorExtend.Dispose()` 接管前完成唯一分配，排除宗门借物与明确交给击杀者的战利品，并选出仍属于死者个人遗产的 portable relic。
2. 捕获人物、修炼知识与遗物选择结果，生成残篇修订。
3. 在死亡地块或最近合法地块创建 `LegacyRemnant` 与 `LegacySiteState`。
4. 调用 `SubWorldManager.Create()`，使用 `Cultiway.Legacy.BattleRemnant` Template 立即生成破损入口、坍塌区、暴露残卷和由死亡类型决定的危险区域。
5. 将选定遗物从 MainWorld 同步转入 Runtime 容器；成功转移的 Item ID 不再进入后续击杀者、城市或 Dispose 路径。
6. `LegacySiteState` 只持有攻击类型、击杀者 ID、残篇完整度、`SubWorldId` 和对外摘要；内部布局、遗物与危险状态直接属于 Runtime。

战殁完整度由可解释事实决定：

- 原功法掌握越高，保留的知识越多。
- 死亡攻击越具破坏性，完整度越低。
- 已完成临终准备时不走残篇规则。
- 击杀者取得多少物品只影响遗物列表，不凭空降低知识完整度。

残篇至少保留一项有效修炼内容；无法形成有效功法或代表法术时不创建空遗地。

三种自然 Template 的 Generator 都逐格写入 `SubWorldTile` 的原版 terrain Asset ID：石室首版把 `soil_low` 写入 Main，把 `wall_ancient` 写入墙格 Top，没有 Top 的格子写空 `TopAssetId`。完整洞府、临终洞府与战殁残迹的差异来自布局、阻挡分布、交互对象、危险状态和独立 overlay/VFX。

每个 `SubWorldRuntime` 的 Grid 对每格直接解析并缓存原版 `TileTypeBase` 对象，ViewHost 的 Main/Top Tilemap 使用对应 `sprites.main`。自然遗产内容不注册基础 terrain，也不按 terrain ID 替换 Sprite 或 Material。

### 步骤 5：接入共享 typed 值与唯一物品转移

本阶段不新增机缘专属 item snapshot 或 transfer adapter。法宝、魔法卷轴和符箓分别使用 SubWorld 平台提供的 `ArtifactInstanceSnapshot`、`MagicScrollSnapshot`、`TalismanSnapshot`，并通过 `PortableItemTransferRegistry` 中各自已注册的 `IPortableItemTransferAdapter<TSnapshot>` 捕获和物化。

这些 typed snapshot 与稳定 `ItemId` 只是当前会话内跨 EntityStore 的值对象和身份合同。内部实体、Holder、Ground、容器关系与物品状态直接由 `SubWorldRuntime` ECS 持有，不建立平行物品记录。

两个技能载体只共享嵌套 `StoredSkillPayloadSnapshot { SkillBlueprint, Signature, Strength, PowerLevel }`：

- `MagicScrollSnapshot` 保留魔法资格、学习/施放与 `AliveTimer/AliveTimeLimit` 寿命数据。
- `TalismanSnapshot` 保留仙道资格、使用者力量换算与一次性施放语义。
- 两者都不复制 `SkillContainer` Entity 或 `CompiledSkillDefinition`。

原 `OwnerHistory` 语义收敛为通用 `ItemProvenance`。历任所有者、取得年份、来源地点和本次会话中的跨世界转移事件随 typed snapshot 传递，不属于机缘私有字段。

#### 可导出条件

遗物选择器调用共享 portable transfer adapter 的导出验证：

- 法宝能够完整表示为 `ArtifactInstanceSnapshot`，并保留原稳定 `ItemId`；器形、材料、品质、能力、操控参数、外观、器灵稳定成长状态和稳定资源 ID 储藏均由 transfer adapter 支持。
- 魔法卷轴能够完整表示为 `MagicScrollSnapshot`，包括嵌套技能 payload、资格和寿命数据。
- 符箓能够完整表示为 `TalismanSnapshot`，包括嵌套技能 payload、仙道资格和使用者力量换算所需的稳定数据；一次性施放是载体 handler 语义，不臆造使用次数。
- 当前装备关系、旧主人认主 Binder、冷却、充能中的短时活动、持续施法会话和未注册运行时组件不进入 typed 值。
- 存在未注册组件时，该物品不能进入遗府；不生成退化的普通法宝副本，也不改写原物品类型。

#### 同步所有权路径

自然遗府封存与参与者撤离共用 `PortableItemTransfer.Move()`：

1. 在源 EntityStore 中解析真实所有者，并按实际类型 Capture typed snapshot、稳定 `ItemId` 与来源 Holder。
2. 移除源 Holder、装备、工序和 Binder 关系，销毁源物化。
3. 在目标 EntityStore 调用同一 transfer adapter 物化相同 `ItemId`，再绑定显式目标 Holder。
4. 目标物化或 Holder 绑定失败时，销毁不完整目标并在源 EntityStore 重新物化原对象；返回失败时仍只有源对象有效。

死亡转入的目标是遗府 Runtime 容器。Projection 在内部拾取、转交或掉落物品时，只改变 ECS Holder/Ground 关系，不改变 Item ID，也不执行跨 EntityStore 转移。

Projection 从出口撤离时，目标是 MainWorld Actor 或指定接收容器。返回协调器先捕获其全部物品值，再逐件同步转移；后续物品失败时，已经移出的物品按逆序移回 Runtime，Actor 继续保持 `ExpeditionBinding`。全部物品成功后才应用伤势、资源与道统结果并销毁 Projection。

原角色、击杀者、宗门宝库、SubWorld 容器和返回后的新持有者之间始终只有一个有效物化与一个 Holder。`LegacySiteState` 不持有 snapshot、ItemId、ContentRef 或 Holder；地点 Tooltip 直接只读查询对应 Runtime ECS 的内容摘要。

### 步骤 6：修正死亡物权顺序

本步骤只修正直接影响遗产正确性的现有问题。

#### 城市转移错误

`ActorExtend.OnDeath()` 当前城市分支再次调用 `Base.GetExtend()`，得到死者自身扩展，剩余物品随后被 `Dispose()` 回收。应改为明确调用城市扩展的物品接收入口。遗府服务在城市接收前同步转移选定个人遗物，城市入口只接收未选物品。

#### 宗门借用法宝

带 `SectTreasureRelation` 的法宝属于宗门，不属于借用角色：

- `ActorExtend.NewKillAction()` 不得把它转给击杀者。
- 死亡时优先由 `SectTreasureService.ReturnBorrowedOnDeath()` 归还。
- 遗产选择器必须排除此关系。
- 宗门已经解散时，物品归属由后续宗门遗址规则处理，不自动变为个人遗产。

个人遗物也必须在 `ActorExtend.NewKillAction()` 接收前完成唯一分配。成功进入 Runtime 的 Item ID 加入当前死亡调用的排除集合，击杀者只处理未选且按原规则属于战利品的物品。

#### 特殊物品过滤

遗产与击杀转移都继续排除：

- `TagOccupied`
- `TagConsumed`
- `TagUncompleted`
- `TagRecycle`

原版装备、城市资源和普通 `ActorBag` 不进入本系统，继续由原版死亡流程管理。

### 步骤 7：补齐表现与当前会话历史

#### 历史记录

生前准备完成时只向 `LegacyWorldState.HistoryEntries` 添加私密事件，不发公开 WorldLog，避免玩家从日志直接得知秘密位置。

遗府被发现后，公开日志可以说明：

- 遗府来自哪位已故修士。
- 该修士是寿终、战死还是古修来源。
- 地点是完整洞府还是战殁残迹。

战殁遗地的 Tooltip 在玩家显露后展示击杀者姓名值，但不要求击杀者仍然存活。

#### 地点命名

完整洞府优先使用祖师姓名、道统语义和 GeoRegion 名称组合，例如“青玄真人遗府”“赤霞剑洞”。战殁残迹使用“某某遗痕”“断法战场”等差异化词干。名称生成只影响展示，不作为 Site ID。

#### 会话清理

切换到另一主世界、返回主菜单或 Mod 重载时，`LegacyWorldState.Preparations`、自然道统修订、遗府地点、死亡历史和所有自然遗府 Runtime 与其他机缘状态一起清除。上一世界的 Actor ID、Revision ID、Site ID 与 SubWorld ID 不再有效。
