## 具体说明

### 交付边界

先在两个仅安装旅行核心的原版玩法世界之间，让一名普通文明人物往返。提供开发入口完成操作，第2阶段接游戏界面。先支持本地可写存档，创意工坊世界通过建立本地副本加入。

本阶段交付的数据约定继续供星图、模组接入、飞船和飞升使用。

### 编号与世界副本

| 编号 | 用途 |
| --- | --- |
| 星图编号 | 区分各套独立世界群 |
| 世界编号 | 星图内识别一个世界，不随名称、文件路径变化 |
| 分支编号 | 区分复制、另存和旧版本继续发展出来的世界 |
| 保存版本编号 | 指向一次已经写完的完整世界保存 |
| 永久人物编号 | 旅客身份，跨世界不变，写入人物的旅行专用附加字段 |
| 旅程编号 | 区分每次出发，用于抵达去重和恢复 |

加入存档时建立受管副本，在世界附加字段记录身份。原版人物编号继续由当前世界分配。所有旅行人物和可携带物品在目的地重新获得本地编号。

同一存档重复加入时，界面显示已有记录。玩家需要独立副本时显式创建分支；保留人物历史来源，同时使用该分支的独立人物身份范围。手动导入旧文件时先核对版本与人物位置，禁止把一个旧版本直接覆盖成当前世界。

永久编号及各类附加字段使用旅行模组自己的名称前缀。未知模组的自定义字段保存在原始资料区，只有被声明为可携带的字段才写入目标人物。

### 人物资料

人物包采用普通数据文件，记录格式版本、游戏版本、来源环境、个人资料和模组数据段。文件中保存数据和引用编号；运行中的人物对象、图像对象和对象指针由目标环境重新建立。

| 数据 | 保存内容 | 抵达处理 |
| --- | --- | --- |
| 身份 | 永久编号、姓名、性别、收藏、故乡和旅行记录 | 保留身份，分配新的本地人物编号 |
| 身体 | 种族资源标识、外观、亚种及其必要定义 | 检查目标资源；受支持的亚种重新创建或匹配 |
| 成长 | 本人实际年龄、等级、经验、击杀和个人经历 | 保留数值，按目标时钟重算出生时间与年龄字段 |
| 当前状态 | 生命比例、饥饿、体力等可携带状态 | 目标计算属性上限后恢复对应状态，避免跨界免费治疗 |
| 特质 | 特质标识和归属模组 | 存在则按规则恢复，缺失则交给兼容处理 |
| 持续效果 | 可携带效果的剩余时长、冷却剩余时长 | 相对目标时间重新计时，旅行不会清空冷却 |
| 装备和背包 | 物品完整定义、数量、归属及相互引用 | 新建本地物品编号后重新绑定，装备和背包不能各复制一遍 |
| 社会关系 | 故乡的国家、城市、父母、伴侣等来源引用 | 记录故乡经历；目标本地关系按抵达规则建立 |
| 模组资料 | 提供方标识、数据版本、活动或封存状态 | 第3阶段按接入规则处理 |

亚种、语言、文化和宗教等属于世界级对象。首版给普通人物建立合法的目标本地关联，故乡资料进入人物历史；若承诺原样携带，必须额外导出相应定义并重新分配编号。界面需要说明采用哪一种方式。无法安全转换的身体或特殊亚种先阻止旅行。

源世界中的首领、军队、家庭等关系按离境处理：解除需要本地人物存在的活动引用，让原版正常补位；记录可供回乡恢复的来源引用。原版关系的清理由旅行核心负责，其他模组拥有的关系由其接入部分负责。回乡只尝试恢复仍然有效的关系，已消失的城市或已更替的职务不强行恢复。

人物正在死亡、变身、施法、乘坐原版交通工具等未支持状态时，出发入口显示具体原因。持续伤势和负面效果需要可携带规则；不能为了允许出发而直接清除。

### 保存结构

建议放在 `Application.persistentDataPath/WorldTravel/<星图编号>/`，具体名称在建模组时确定。

```text
catalog.json                    当前有效的世界版本、人物位置与旅程状态
catalog.json.bak                上一次完整总目录
working/                        当前会话的工作副本，供原版流程使用
worlds/<世界>/<分支>/<版本>/
    原版存档文件                 通过原版保存流程生成
    travelers.json              该世界旅客的附加资料与封存数据
    providers/                  已接入模组提供的世界附加保存文件
    manifest.json               本版本文件清单、校验值、身份与完成标记
transfers/<旅程>/
    party.json                  本次人物与物品资料
    manifest.json               来源、目标、格式版本与资料校验值
```

各世界版本写好后保持不变。保存时先在新目录生成完整文件，读回验证原版世界标记、旅客、物品和附加资料，再以临时文件替换的方式提交总目录。总目录里的世界版本、旅客位置和旅程状态一起更新，使它们只有一个共同的生效点。

核对实际文件内容是必要步骤：本地原版 `saveMapData` 会捕获部分写入错误，返回对象本身不足以确认成功。世界快照还需包含参与模组声明的附加文件；只备份一个 `map.wbox` 不能代表所有模组状态。

加载世界时使用工作副本，原版的当前保存路径指向工作区；保存入口将完整状态写入新的世界版本。原版手动保存和自动保存都不能覆写已经提交的版本目录。

受管世界的普通保存和自动保存也走这套提交规则。处于导出、切换和导入中的自动保存合并到本次操作，避免写下半完成状态。同一星图由文件锁保证只有一个游戏进程写入。

旅行核心可以参考本仓库已有的文件替换、备份和数据校验做法。作为独立模组时，核心保存能力由自己提供，修仙接入复用修仙内部已有的资料获取方式。

保存版本需要有保留上限。建议每个世界保留最近3个普通检查点，同时始终保留当前总目录、备份总目录和未完成旅程引用的版本。只有确认没有任何引用后才清理旧版本。已完成旅程保留精简历史，完整人物包按恢复保留规则处理，避免自动保存使磁盘用量持续增长。

### 旅行步骤

| 步骤 | 操作 | 该步失败后的有效状态 |
| --- | --- | --- |
| 1. 检查 | 暂停世界，检查人物、目标世界环境、落点和支持的数据类型 | 人物仍在源世界 |
| 2. 保存出发前状态 | 为源世界建立完整检查点；准备人物包并读回核对 | 保留源世界检查点，不允许离境 |
| 3. 准备离境版本 | 按非死亡流程卸下人物及随身资产，处理关系并生成新源世界版本 | 总目录仍指向出发前版本 |
| 4. 提交出发 | 一次更新总目录：源世界指向离境版本，人物位置改为旅途中 | 人物包托管旅客，源世界已无活动副本 |
| 5. 打开目标 | 按原版流程加载目标有效版本，等待整张世界和所需模组准备完成 | 继续停留在旅途中，可重试或返航 |
| 6. 准备抵达版本 | 暂停目标世界，建立新人物、物品和关系，写入旅程回执并保存新版本 | 目标旧版本仍有效，人物仍由旅途托管 |
| 7. 提交抵达 | 一次更新总目录：目标指向抵达版本，人物位置改为目标世界，本次旅程完成 | 目标世界正式拥有旅客 |
| 8. 开始活动 | 刷新人物属性和选中状态，恢复玩家此前的暂停选择 | 使用正常世界保存规则 |

离境清理要调用或补齐原版对象管理和模组关系清理，避免走击杀、掉落、死亡成就等流程。具体调用点先用原版普通人物验证；直接删除人物列表一项不足以完成离境。

表中的失败状态指磁盘上的有效状态。离境准备过程中失败时，保持暂停并重载源世界的有效版本，再恢复游玩；不能让只完成一半清理的运行中世界继续模拟。

分步加载结束后还要验证世界编号、分支、预期保存版本和模组准备状态。`loadWorld` 调用返回或 `loadActors` 完成，都不能单独作为抵达信号；加载失败新生成的世界不能接收旅客。

### 中断恢复与返航

恢复只依据已经提交的总目录和对应完整世界版本：

- 出发尚未提交：加载源世界的有效版本，未提交文件不生效。
- 已出发、未抵达：人物包继续托管，玩家可重试目的地或返航。
- 目标版本写好、抵达尚未提交：继续停留在旅途中，可以验证已有准备结果或重新生成抵达版本。
- 抵达已经提交：加载目标有效版本，以旅程编号核对回执，重复请求只定位已有旅客。
- 总目录损坏：恢复可校验的完整备份及其引用的世界版本；不能随意拼接不同时间的单颗星球。

返航同样走“人物包导入世界”的步骤，先确认目标抵达尚未提交。目的地是否收到人物存在疑问时，先核对提交记录。不要直接把出发前整张世界覆盖回去，因为源世界可能已经有后续活动。

正常死亡作为当前世界状态随保存提交，已完成旅程的人物包不能当作复活入口。导入失败产生的临时对象在暂停状态下清理，目标旧保存版本继续有效。

第一版格式只接受明确支持的数据版本。遇到较新且无法理解的版本时保留文件并停止导入，不自动删字段或降级写回。

### 验收场景

| 场景 | 预期结果 |
| --- | --- |
| A 到 B 再回 A，两边原版人物编号有重合 | 永久身份不变，本地编号不同，关系不会错连 |
| 两世界年份相差很大 | 年龄、伤势、冷却不被重置或放大 |
| 带装备、背包、货币和同类叠加物品 | 数量、归属正确，源世界无重复资产 |
| 人物是首领、有伴侣或隶属军队 | 离境后源世界正常补位，目标不继承无效对象编号 |
| 在每个提交前后退出游戏 | 根据总目录恢复到对应有效状态 |
| 写入失败、磁盘空间不足或目标文件缺失 | 无错误提交，人物保留在有效世界或旅途中 |
| 目标加载失败并触发原版生成新世界 | 拒绝抵达，可继续恢复旅程 |
| 连点出发、重复导入同一旅程 | 只产生一次离境和一次抵达 |
| 抵达后正常保存、退出并重开 | 人物及随身物品恢复，封存资料完整 |
| 导入旧世界副本或恢复旧版本 | 显示分支选择，不在同一星图悄悄复活已离境人物 |

以上需要在游戏中验证。本阶段实现前核对当时实际的游戏和加载器版本，不以本次源码阅读代替运行验证。
