# 第3阶段-表现与验证

本阶段不增加新的玩法分支。目标是让夺舍全过程能够被玩家稳定观察和解释，并处理选中、控制、领袖、物权、目标失效和重复死亡等边界，最终完成构建与游戏内验证。

## 具体说明

### 步骤 1：完善世界日志与本地化

新增三类世界日志：

| 日志 | 核心文本信息 | 点击目标 |
| --- | --- | --- |
| 元婴出逃 | 夺舍者姓名、肉身毁坏原因 | 当前元婴 Actor |
| 夺舍成功 | 夺舍者姓名、宿主姓名、宿主种族 | 成功后的夺舍者 Actor |
| 夺舍失败 | 夺舍者姓名、宿主姓名 | 幸存宿主 Actor |

日志使用独立 `WorldLogAsset`，归入现有修炼历史组。文本替换只读取稳定参数，不在本地化字符串中拼接未翻译的资产 ID。

本地化落点：

- `Locales/actors.csv`：元婴形态名称。
- `Locales/status_effects.csv`：元婴出逃、神魂入侵、肉身不合、神魂创伤。
- `Locales/histories.csv`：三类世界日志。
- `Locales/tasks.csv`：寻主、接近、夺舍中的真实任务文本。
- `Locales/ui.csv` 或 `core_formations.csv`：元婴页中的休眠种子状态文本。

所有剩余时长使用原版日期/时间格式化，不手写“秒”或“月”的复数字符串。

### 步骤 2：扩展元婴详情页与状态反馈

不新增独立窗口。扩展现有 `YuanyingPage` 的模型和详情视图，在元婴形成信息下增加一个紧凑区块：

- 当前境界：肉身下层修炼 / 元婴出逃 / 活动元婴 / 肉身不合。
- 休眠元婴：原元婴品阶、转数、强度和唤醒条件。
- 出逃剩余时间，只有 `YuanyingSoulState` 存在时显示。
- 当前锁定宿主姓名，未锁定时显示“寻主中”。
- 已完成夺舍次数。
- 上次宿主姓名与肉身种族。
- 神魂年龄，由夺舍者不变的 `data.created_time` 计算；原版 `getAge()` 仍表示当前肉身年龄。

页面只读取 presentation model，不直接执行 ECS 查询或业务命令。现有 `CoreFormationDetailView` 若没有稳定扩展槽，只在元婴页拥有者内增加功能族区块，不修改公共 Foundation 以承载夺舍类型。

状态 Tooltip 必须解释实际规则：

- 元婴出逃：剩余时间、只能尝试一次、被击杀会真正死亡。
- 神魂入侵：当前正在遭遇夺舍，过程可被打断。
- 肉身不合：主要属性惩罚、恢复时间、期间不能再次出逃。
- 神魂创伤：失败夺舍留下的 MaxSoul 与 DivineSense 惩罚。

### 步骤 3：完成元婴角色与过程视觉

元婴使用专用低分辨率像素角色资源，不把 GhostFire 当作最终资源。视觉要求：

- 轮廓能看出缩小的人形婴灵，而不是普通火焰或鬼魂。
- 主色由角色 Yuanying 形成的元素构成动态着色；底图保持中性灰白。
- idle 有轻微悬浮，walk 表达快速遁行，death 表达光点溃散。
- 不显示手持武器、盔甲、睡眠躺姿和普通生育表现。
- 出逃瞬间复用元婴 aura/indicator，肉身位置保留短暂破碎或光散效果。
- 引导期间使用细线或粒子流，不能遮住双方血条、状态图标和选择轮廓。
- 成功时效果由宿主向夺舍者当前位置收束，随后刷新为宿主外形。
- 失败时元婴效果向外破碎，宿主显示短暂神魂震荡。

渲染颜色来自现有 Realm/Element 颜色解析，不在表现代码中另建一套紫色常量。

### 步骤 4：处理身份、控制、修炼和物权边界

#### 选中、收藏与玩家控制

同一 Actor ID 保证选中和收藏可自然延续。进入元婴形态时：

- 若当前被玩家附体控制，结束原版附体控制，避免专用 AI 与玩家输入竞争。
- 保持 SelectedUnit 和镜头跟随，玩家可以继续观察。
- 成功后不自动恢复玩家附体控制。
- 元婴被击杀或超时时，按正常死亡清除选中。

#### 城市、国家与领袖

首版不把宿主的城市、国家、职业或职位复制给夺舍者。夺舍者原社会身份保留：

- 元婴出逃的短期内仍属于原国家、城市和宗门。
- 若其原本是国王、城主或宗门领袖，不在肉身毁坏时提前触发死亡继任。
- 只有元婴真正死亡时才走原版和宗门死亡继任。
- 成功后继续原职位；具体视觉外形变化不改变职位 ID。

若实测原版职业任务会绕过高优先级寻主工作，元婴 ActorAsset 必须禁用对应能力，而不是临时移除社会关系。

#### 当前修炼与元婴种子

成功换体后必须同时展示两个状态，避免玩家误以为原主仍处于元婴境界：

- 当前境界、炼气、仙基、金丹和 Wakan 显示宿主版本。
- 主修功法、掌握度、已学技能和实践记录显示夺舍者版本；技能实际使用受当前宿主境界限制。
- 原元婴显示为休眠 `YuanyingSeed`，包含原名称、品阶、转数和唤醒条件。
- 宿主金丹九转后，进阶按钮/任务显示为“唤醒原元婴”，而不是“重新结婴”。
- 唤醒后移除 seed，详情页恢复活动 `Yuanying` 的正常三、六、九转进度。

宿主死亡时，其姓名、关系、下层修炼组件和肉身特质按宿主流程结束；夺舍者的功法、技能和 seed 不随宿主组件一起清除。

#### 物权

- 原肉身的原版武器和护甲只释放一次。
- Mod 特殊物品和绑定法宝继续属于夺舍者，不触发 `ActorExtend.OnDeath()`。
- 宿主真正死亡时，其物品只走一次原死亡物权。
- 成功换体不得调用默认武器生成，避免凭空新增装备。
- 失败或超时时，夺舍者真正死亡后再处理仍由神魂持有的特殊物品与宗门借物。

#### 身体与精神特质

用固定特质组集合决定肉身迁移，不建立逐 trait ID 清单：

```text
肉身组：body, physique, health, appearance, protection
其余组：保留夺舍者，不从宿主复制
```

复制前先快照两个角色的 trait 集合，再执行移除和添加，避免遍历过程中修改容器。添加肉身特质时不让 opposite 规则删除夺舍者精神特质；若出现明确跨组冲突，再修正该特质资产的分组或策略，不添加通用兜底。

### 步骤 5：验证失败原子性与清理

针对以下提交窗口做定向验证：

- 宿主在接近中死亡。
- 宿主在引导最后一帧死亡或离开世界。
- 元婴与宿主同时受到范围致命伤。
- 元婴在 `Resolving` 时被 Divine 删除。
- HostBodySnapshot 的 ActorAsset 或 Subspecies 在提交前失效。
- 换形后统计刷新抛出异常。
- 宿主死亡回调触发宗门、法宝、遗产和击杀物权。
- 场景重载或 Mod Reload 时存在 `Seeking`、`Resolving` 或恢复期状态。

提交必须保持以下不变量：

- 任一时刻最多有一个人物继续代表夺舍者身份。
- 宿主未死亡时，夺舍者不能永久保留宿主肉身。
- 宿主死亡后，夺舍者必须已经拥有完整可用的新肉身。
- 一次正式对抗最多产生一个随机结果。
- 一次肉身毁坏最多释放一份装备。
- 一个人物真正死亡最多调用一次 `ActorExtend.OnDeath()`。
- 任何失败都不能产生重复 Actor ID、重复物品或半复制 ElementRoot。

清理入口集中在 `YuanyingPossessionService.Terminate()` 与 `Complete()`，行为、系统和 Harmony 回调不各自复制清理步骤。

### 步骤 6：完成构建和游戏内矩阵

先运行：

```bash
dotnet build Cultiway.csproj -c Debug
```

随后在本地 WorldBox 按矩阵验证：

| 类别 | 场景 | 预期 |
| --- | --- | --- |
| 基线 | 非元婴受到战斗、寿终、环境致命伤 | 原死亡行为完全不变 |
| 顺序 | 元婴的灵胎/归墟成功保命 | 不进入元婴出逃 |
| 顺序 | 雷铸神兵成功保命 | 不进入元婴出逃 |
| 出逃 | 元婴战死、寿终 | 进入同一出逃流程 |
| 排除 | Divine、Metamorphosis | 不进入元婴出逃，其余沿用既有规则 |
| 寻主 | 半径内无目标 | 12 个月后真正死亡 |
| 寻主 | 最近目标失效 | 重新评分，不消费机会 |
| 成功 | 夺舍凡人、炼气、筑基、金丹宿主 | 当前境界和下层修炼字段来自宿主，身份、功法技能和元婴种子来自原主 |
| 唤醒 | 宿主重修到金丹九转 | 唤醒原元婴，不重新随机结婴，品阶和转数保持 |
| 失败 | 对抗失败 | 原主死亡，宿主存活并受神魂创伤 |
| 打断 | 引导中元婴被杀、封禁或推离 | 不掷骰，若仍存活则重新寻主 |
| 身份 | 夺舍者为国王、城主、宗门领袖、师父、亲属 | 成功后关系仍指向同一 Actor ID |
| 物权 | 双方都有原版装备、法宝、宗门借物 | 无复制、无吞物、归属符合规则 |
| 控制 | 夺舍者被选中、收藏、玩家附体 | 观察延续，控制安全结束，无输入冲突 |
| 重复 | 成功后仍处于肉身不合恢复期 | 再次致命时真正死亡，不连续出逃 |
| 重复 | 休眠 seed 尚未唤醒且恢复期结束 | 再次致命时可继续使用同一 seed 出逃 |
| 重复 | seed 唤醒后恢复期结束 | 活动元婴可按正常规则再次出逃 |
| 清理 | 元婴形态被杀或超时 | 只执行一次死亡和 Dispose |

对成功案例至少记录并比对：Actor ID、姓名、asset、subspecies、sex、外观、年龄、ElementRoot、宿主 `Xian`/`XianBase`/`Jindan`/`PowerLevel`、原主功法技能、`YuanyingSeed`/`Yuanying`、宗门、师徒、亲属、城市、国家、装备与特殊物品。
