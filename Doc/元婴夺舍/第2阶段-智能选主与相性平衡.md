# 第2阶段-智能选主与相性平衡

本阶段建立在已可玩的最小闭环上，不改变“原主身份延续、一次机会、低于元婴宿主”的合同。重点是让 AI 的宿主选择可解释，让不同肉身和神魂的差异真实影响收益与风险，并给世界中的其他角色留下反制窗口。

## 具体说明

### 步骤 1：建立低频宿主索引与评分

寻主不得每帧遍历 `World.world.units.units_only_alive`。使用包含 `ElementRoot` 与 `ActorBinder` 的冻结 ECS Query 取得候选，只在以下时机重新评分：

- 刚进入元婴形态。
- 当前目标失效。
- 每经过 1 个月且仍未锁定有效目标。

单次评分先按 120 格距离和合法性过滤，再计算：

```text
CandidateScore = SuccessChance × BodyValue
               - DistanceCost
               - SocialCost
               - ImmediateDangerCost
```

`BodyValue` 由以下可解释项组成：

- 宿主剩余寿命比例与绝对剩余寿命。
- 宿主 ActorAsset 和 Subspecies 提供的最大生命、速度与生育能力。
- 元婴形成与宿主灵根的相性。
- body、physique、health、appearance、protection 组中的正负肉身特质。
- 宿主当前伤势；濒死肉身价值显著降低。

`SocialCost` 只影响偏好，不形成硬禁止：亲属、师徒、同宗、同城、同国依次增加代价。绝境下元婴仍可能夺舍熟人，但通常优先选择陌生人或敌人。

`ImmediateDangerCost` 考虑宿主附近敌对单位和元婴当前剩余生命，避免元婴飞入明显无法完成引导的战团。

评分返回分项明细，调试日志能说明“为什么选择此人”，不只输出总分。

### 步骤 2：完善神魂对抗的解释性数值

保持第 1 阶段的 Resolver 边界，完善以下修正：

| 因素 | 作用 |
| --- | --- |
| 元婴 DivineSense | 提高进攻值 |
| 元婴 MaxSoul | 提高可承受的神魂冲突规模 |
| Yuanying.strength 与品阶 | 提高进攻值，是高品质结婴的长期收益 |
| 宿主 DivineSense 与 MaxSoul | 提高抵抗值 |
| 宿主境界和实际战力 | 提高抵抗值，但也提高部分肉身价值 |
| `strong_minded` 与强心智标签 | 提供明确抵抗加成 |
| 元婴形成与宿主 ElementRoot 相性 | 同时影响成功率和成功后的永久强度损失 |
| 元婴当前生命比例 | 只小幅影响进攻，避免残血必败 |

Resolver 必须满足单调性：只提高源神识时成功率不能下降；只提高宿主魂量时成功率不能上升；相性变好时成功率不能下降。对零值、极大值和缺失统计使用同一显式下限，不在多处重复兜底。

增加开发调试输出：

```text
source=<id> target=<id>
attack=<value> defense=<value>
compatibility=<value> chance=<value>
bodyValue=<value> candidateScore=<value>
```

日志只在开发模式或选中调试单位时写出，避免正常世界刷屏。

### 步骤 3：实现可观察且可打断的夺舍引导

元婴抵达宿主后不立即掷骰，进入持续 1 个月的 `Resolving`：

- 元婴停止普通移动并保持在宿主附近。
- 宿主获得短时“神魂入侵”状态，停止普通工作但仍可被外界攻击。
- 元婴和宿主之间显示复用元婴色的细线或粒子流。
- 元婴被击杀、封禁或离开接触范围时，引导中断并退回 `Seeking`。
- 宿主死亡或被移除时，引导中断并重新寻主。
- 正式调用 Resolver 前的中断不消耗唯一机会。
- Resolver 只在预检通过后调用一次，并在同一同步调用中立即进入成功提交或失败死亡，不保留可重复结算的中间状态。

封禁状态使用现有 `Imprisoned`、`Silence` 和控制标签，不新建一套控制系统。是否中断由统一判定函数决定，AI 行为与状态表现共用该结果。

### 步骤 4：实现元婴种子唤醒与宿主后续进阶

夺舍成功后不保留原主的当前元婴境界。活动 `Xian`、炼气状态、仙基和金丹全部切换为宿主版本；原主元婴以 `YuanyingSeed` 休眠。主修功法、掌握度、已学技能和 `CultivationPracticeState` 仍属于原主，但技能实际可用性和施法预算按宿主当前境界计算。

宿主沿自己的路线继续修炼：

```text
宿主炼气/筑基/金丹
-> 使用宿主的下层组件和资源正常进阶
-> 金丹九转且 Wakan 满值
-> xian.form_yuanying 进入种子唤醒分支
```

唤醒分支不能调用现有 `ResolveYuanying` 重新组合。它应当：

1. 校验 `YuanyingSeed`、宿主金丹九转、满 Wakan 和肉身不合状态。
2. 深拷贝 seed 中原主的 `CoreFormationSnapshot`。
3. 保留原元婴的名称、品阶、元素构成、原子、转数、谱系和代表法术。
4. 使用宿主当前金丹强度、宿主灵根和元婴相性计算承载系数。
5. 将 seed 物化为活动 `Yuanying`，把当前 `Xian.level` 切换为 `XianLevels.Yuanying`，并直接恢复 seed 保存的元婴 `PowerLevel`。
6. 移除 `YuanyingSeed`；宿主的 `XianBase` 与 `Jindan` 可以作为当前人物的下层历史保留，但不覆盖元婴的原始谱系。

唤醒时不能使用只取更大值的 `UpgradePowerLevel()`，必须显式把 `PowerLevel` 替换为 seed 保存的元婴基准；否则当前境界切换为元婴后，战斗系统仍可能保留宿主或原主的错误战力值。

唤醒是原元婴已经形成后的重新承载，不再进行一次新的结婴随机判定。当前强度按以下结构计算：

```text
AwakenedStrength = SeedStrength
                 × HostJindanSupport
                 × RootCompatibility
                 × PossessionLoss
```

永久损耗只作用于 seed 或唤醒后的 `Yuanying.strength`，不修改 formation 的品阶和结构：

```text
LossRatio = Lerp(35%, 10%, Compatibility)
Yuanying.strength *= 1 - LossRatio
```

宿主金丹可以在唤醒后作为当前人物的下层历史继续保留，但元婴页的“金丹谱系”仍读取 seed 中原主元婴的 `source_name` 与 `source_signature`；两者不合并成一条新的形成谱系。

唤醒后恢复正常元婴同境精炼。当前代码已经有 3、6、9 转的形成演化节点，但没有元婴小进阶过渡；应新增 `xian.refine_yuanying`，使用 `ProgressionKind.Minor`，在 `Yuanying -> Yuanying` 内推进 `formation.refinement`。进阶判定使用 DivineSense、MaxSoul、元婴强度和当前肉身承载度，不能只读取宿主 intelligence。

首版把元婴内部进阶限制在 0 至 9 转。达到九转后等待未来的化神大境界，不复制金丹的 10000 层空进阶上限。

唤醒后的 `BodyDisharmony` 持续 1 年，降低当前肉身的速度、伤害和 DivineSense，并禁止在恢复期再次出逃。恢复期结束后，若活动元婴再次死亡，可以正常进入出逃流程。

在种子尚未唤醒的重修期，`YuanyingSeed` 本身仍可触发出逃。再次成功夺舍时只替换宿主肉身和宿主下层修炼数据，继续使用同一份 seed；每次成功都追加相性损耗，不得生成新的 `Yuanying` 或重置转数。

### 步骤 5：增加世界反应与反制

首版反制只使用已有角色能力和清晰状态：

- 元婴形态可被正常攻击和控制。
- `Divine` 与 `Metamorphosis` 不触发元婴出逃；其他既有保命规则仍按自身合同结算。
- 高 DivineSense、MaxSoul、境界和强心智提高宿主抵抗。
- 引导期间击杀、封禁或推离元婴可救下宿主。
- 同宗、师徒和亲属若在附近，仍按现有敌我关系行动；本阶段不新建救援集体任务。

失败后的 `SoulTrauma` 持续 2 年，降低 MaxSoul 与 DivineSense，但不改变宿主当前下层修炼、功法技能或人格。它既是失败代价，也是世界中可见的夺舍痕迹。

成功后保留夺舍者原国家、城市和宗门关系。宿主原社会关系随宿主死亡结束。伪装和身份识破继续留在范围外，日志会直接说明夺舍事实。

### 步骤 6：用真实样本完成首轮平衡

在开发世界收集以下分布，不凭单个角色调常量：

- 元婴 DivineSense、MaxSoul、Yuanying.strength 和品阶。
- 凡人、炼气、筑基、金丹宿主的 DivineSense 与 MaxSoul。
- 候选数量、最近候选距离、最优候选距离。
- 按宿主境界分组的预测成功率与实际成功率。
- 出逃后超时、途中被杀、夺舍失败和夺舍成功的比例。
- 成功后 1 年内再次死亡的比例。

首轮目标区间：

| 场景 | 目标结果 |
| --- | --- |
| 强元婴对普通炼气宿主 | 通常高成功率，但不超过 95% |
| 普通元婴对优质金丹宿主 | 有吸引力但风险明显，成功率约处于中段 |
| 受创元婴对强心智金丹宿主 | 通常不应成为最高评分目标 |
| 半径内存在多个候选 | AI 应偏向高期望收益，而不是永远最近或永远最高境界 |
| 无候选或候选持续失效 | 最终超时死亡，不产生高频全图扫描 |

只在参数集中类中调整权重。若公式结构本身无法满足单调性或目标分布，再修改 Resolver，不添加特例成功率。
