# 第1阶段-最小夺舍闭环

本阶段必须直接交付可玩的端到端闭环，不先建设独立半成品框架。完成后，元婴修士可以在常规保命失败后出逃，自动寻找最近合法宿主，并通过一次神魂对抗成功换体或真正死亡。

## 具体说明

### 阶段完成定义

以下流程必须在同一版本中全部可用：

```text
元婴受致命伤
-> 常规保命均未生效
-> 原 Actor 进入元婴形态
-> 最近合法宿主
-> 接近并结算一次
-> 成功采用肉身 / 失败真正死亡
```

若某一步无法安全提交，系统不得吞掉原致命伤。进入元婴形态失败时，单位继续按原逻辑死亡。宿主肉身快照和全部可恢复检查必须在随机对抗前完成；前置检查失败时继续寻主且不消耗机会。随机对抗一旦结算就永久消耗唯一机会，后续不得因表现或技术错误重新掷骰。

### 步骤 1：建立运行时状态与固定规则

新增两个职责分离的运行时组件：

```text
YuanyingSoulState
  ExpiresAt
  ChannelStartedAt
  TargetActorId

YuanyingSeed
  formation             原元婴 CoreFormationSnapshot 深拷贝
  source_power_level    原元婴活动战力基准
```

`YuanyingSoulState` 只表示当前出逃过程，成功或真正死亡时移除。首次成功夺舍时，把活动 `Yuanying` 深拷贝到 `YuanyingSeed`，再切换当前修炼组件。神魂出生时间继续使用始终不改写的 `Actor.data.created_time`。

`YuanyingSeed` 在宿主重新结婴前不参与当前境界属性，但仍然让 `CanEscape` 成立；重修期间再次成功夺舍时更新同一 seed 的强度，不创建第二个元婴。

新增集中规则类保存 12 个月存续时间、120 格寻主半径、概率上下限和恢复比例。首版不加配置页面，不把数值散落在行为、状态和 UI 中。

新增纯值 `HostBodySnapshot`，在正式提交前一次捕获：

- ActorAsset 与精确 Subspecies。
- sex、head、phenotype_index、phenotype_shade。
- 宿主当前 `getAge()`，不复制其 `created_time`。
- 肉身特质 ID 集合。
- ElementRoot 值。
- 宿主当前 `Xian`、炼气状态、`XianBase`、`Jindan`、Wakan、`CultivationResourceState` 和 `PowerLevel` 快照。
- 宿主 Actor ID 与姓名，仅供历史和日志。

另捕获宿主的功法技能不覆盖源数据：主修功法、掌握度、已学技能和 `CultivationPracticeState` 继续使用夺舍者版本。

Snapshot 不保存 Actor、City、Sect 或 Entity 引用。

### 步骤 2：接入最终伤害并进入元婴形态

在 `FinalDamageStage.Survival` 后增加 `LastResort`。`YuanyingPossessionService.Init()` 把出逃处理器注册到该阶段。

处理器按以下顺序执行：

1. 判断最终伤害是否仍会致命。
2. 判断活动 `Yuanying` 或休眠 `YuanyingSeed`、恢复期、死因和重入状态。
3. 捕获出逃所需值并预检元婴 ActorAsset。
4. 取消当前攻击、任务、移动目标和主动施法状态。
5. 安全释放旧肉身的原版装备，并移除旧肉身特质组。
6. 将同一 Actor 转换为元婴形态并写入 `YuanyingSoulState`。
7. 设置元婴当前生命为最大生命的 50%，刷新统计与图形。
8. 所有步骤成功后才令 `damage = 0`。

进入元婴形态时不调用 `Actor.die()` 和 `ActorExtend.OnDeath()`，因为人物尚未真正死亡。核心形成活动状态、战斗部署和肉身临时状态由出逃服务显式中断；宗门借物、主修功法、已学技能、Mod 特殊物品和社会关系继续属于原人物。

以下情况不出逃：

- `AttackType.Divine`、`AttackType.Metamorphosis`。
- 已有 `YuanyingSoulState`。
- 当前不是 `BodyDisharmony` 恢复状态。
- 活动 `Yuanying` 和 `YuanyingSeed` 均无效。
- 原始出逃前不具备有效元婴，且当前也没有有效休眠种子。

### 步骤 3：处理旧肉身与元婴生存期

元婴形态使用专用 `Actors.YuanyingSoul`，而不是复用 GhostFire：

- 可飞行、无饮食、无繁殖、无普通装备槽表现。
- 保持可被选中、收藏、攻击和玩家观察。
- 不提供随机灵根，不触发新修炼体系准入。
- 普通工作永远被元婴寻主工作覆盖；原主技能关系保留，但技能可用性和施法预算按当前活动境界限制。
- 初次出逃期间仍使用活动 `Yuanying`；成功换体后才把它转为 `YuanyingSeed`。
- 不移除原 Actor 的国家、城市、氏族、亲属、宗门或师徒关系。

旧肉身的原版武器和护甲交给当前地块城市；无合法接收者时沿用原版死亡物权。不得调用完整死亡流程，也不得触发击杀计数、宗门领袖死亡或人物遗产。

增加低频 `YuanyingSoulLifetimeSystem`：

- 世界时间达到 `ExpiresAt` 时立即执行真正死亡。
- 元婴形态受到致命伤时不再出逃，直接进入正常死亡流程。
- 真正死亡继续使用现有 `ActorExtend.OnDeath()`、宗门清理、物权和 Dispose 流程。
- `Actors.YuanyingSoul.skip_save = true`；首版不保存或恢复出逃过程。

### 步骤 4：注册高优先级寻主任务

注册 `ActorJobs.YuanyingPossession` 与对应任务，并通过 `ActorJobSelectionRegistry` 以高于普通、修炼和组织工作的优先级强制选择。

第一阶段候选过滤固定为：

- 目标不是自己，存活、未销毁、有当前地块。
- `isSapient()` 且 `asset.has_soul`。
- ActorExtend 拥有 `ElementRoot`。
- 没有 `YuanyingSoulState`。
- 没有 Xian，或 Xian 当前境界低于 `XianLevels.Yuanying`。
- 不在船内、建筑内部或其他不能接近的隔离状态。
- 与元婴距离不超过 120 格。

第一阶段从合法候选中选择最近者，目标只以 Actor ID 写入状态。每次行为执行都重新解析并校验 ID；目标失效时清空 ID 并重新搜索，不消耗唯一夺舍机会。

接近目标后进入 `Resolving`，固定等待 1 个月。等待期间目标死亡、失效或离开范围则退回 `Seeking`；等待完成才进行正式对抗。

### 步骤 5：实现一次神魂对抗

新增无副作用的 `SoulContestResolver.Resolve(source, target)`。Resolver 返回：

```text
SoulContestResult
  AttackScore
  DefenseScore
  Compatibility
  SuccessChance
```

进攻值读取当前活动 `Yuanying` 或 `YuanyingSeed` 的 DivineSense、MaxSoul、strength 和品阶；休眠种子阶段不把元婴形成属性叠加到当前宿主，只用于对抗计算。抵抗值读取宿主 DivineSense、MaxSoul、战力等级，以及 `strong_minded` 或等价强心智统计标签。灵根相性读取元婴形成构成与宿主 ElementRoot。

概率使用摘要中的比值公式并限制在 10% 至 95%。正式结算前先捕获 `HostBodySnapshot` 并完成步骤 6 的全部前置检查；检查失败则重新寻主。检查通过后，行为层在同一次同步调用中只执行一次 `Randy.randomChance(result.SuccessChance)`，随后立即进入成功提交或失败死亡，不保留可再次掷骰的中间状态。

失败时：

1. 给宿主施加两年的 `SoulTrauma`，降低 MaxSoul 与 DivineSense。
2. 写入夺舍失败日志。
3. 立即移除出逃状态并执行原人物真正死亡，不能重新寻主。

### 步骤 6：原子提交宿主肉身

成功路径由 `YuanyingPossessionService` 内部统一提交，AI 行为不得在外部逐字段修改两个 Actor。

提交前置检查：

- source 仍为元婴形态。
- target 仍为同一 Actor ID、存活且满足宿主条件。
- HostBodySnapshot 中的 ActorAsset、Subspecies 和 ElementRoot 有效。

同一主线程提交顺序：

1. 使用随机对抗前已经验证的 `HostBodySnapshot`。
2. 深拷贝当前活动 `Yuanying` 及其原活动 `PowerLevel` 到 `YuanyingSeed`；若 source 已经持有休眠种子，则更新同一 seed，不创建第二份核心。
3. 深拷贝宿主的 `Xian`、炼气状态、`XianBase`、`Jindan`、Wakan、`CultivationResourceState` 和 `PowerLevel`，作为夺舍后的活动修炼数据。
4. 保留夺舍者的主修功法、掌握度、已学技能和 `CultivationPracticeState`；这些知识不因当前境界降低而丢失，但由当前宿主境界限制实际可用性。
5. 确保夺舍者不再带有 body、physique、health、appearance、protection 组的旧肉身特质。
6. 对夺舍者采用宿主 ActorAsset、精确 Subspecies、外观和性别；保留夺舍者 `created_time`，按宿主当前年龄重算 `age_overgrowth`。
7. 复制宿主肉身特质组与 ElementRoot，写入宿主当前 `Xian.level` 和 `PowerLevel`；若宿主没有仙道，则初始化为炼气期，不让休眠元婴直接提供元婴境界属性。
8. 刷新飞行、阴影、图形、统计和城市公民缓存；禁止触发随机亚种、出生特质、默认武器和修炼体系重新准入。
9. 确认夺舍者新肉身和活动下层修炼数据有效后，再让宿主走一次有明确死亡归因的正常死亡流程。
10. 将当前 Wakan 校正为新活动体系最大 Wakan 的 10%，按相性永久损失 10% 至 35% 的元婴种子强度，施加一年 `BodyDisharmony`。
11. 移除活动 `YuanyingSoulState`，保留 `YuanyingSeed` 并写入成功日志。

`PowerLevel` 必须直接替换为宿主快照值，不能调用只取最大值的 `UpgradePowerLevel()`；否则当前境界虽然显示为宿主境界，战斗和技能仍会沿用原主元婴战力。

休眠种子不参与当前炼气、筑基或金丹的属性合成；当前属性只来自宿主下层修炼组件和肉身。

所有可预期失败必须在随机对抗前返回。随机结果产生后，同一调用只会进入成功提交或失败死亡；提交阶段若仍发生未预期异常，则结束原人物并记录错误，不允许重新掷骰。

宿主死亡后，其姓名、关系、下层修炼组件和非肉身特质随宿主人物结束；夺舍者的功法、技能、元婴种子和 Actor ID 不变。

### 步骤 7：补齐最小反馈与闭环验证

最小反馈只包括：

- 元婴出逃世界日志。
- 夺舍成功世界日志，包含夺舍者与宿主姓名。
- 夺舍失败世界日志。
- 元婴形态头顶现有元婴指示光效。
- 元婴出逃状态 Tooltip，显示剩余时间。
- `BodyDisharmony` 与 `SoulTrauma` 状态图标和说明。

本阶段不修改元婴详情页结构，不新增窗口。

必须验证：

- 普通人、炼气、筑基、金丹受到致命伤仍正常死亡。
- 元婴的现有 Survival 效果成功时不出逃；效果未触发或处于冷却时才出逃。
- 寿终会出逃，Divine 和 Metamorphosis 不会出逃。
- 无候选时 12 个月后真正死亡。
- 目标中途死亡会重新寻主，不消耗机会。
- 成功后 Actor ID、姓名、宗门、亲属和师徒不变，功法和技能仍来自夺舍者。
- 成功后当前 `Xian.level`、炼气、仙基和金丹数据来自宿主；种族、亚种、外观、年龄、ElementRoot 和肉身特质也来自宿主。
- 成功后原 `Yuanying` 变为 `YuanyingSeed`，不参与当前低境界属性。
- 宿主在重修期间再次死亡时，休眠种子仍可出逃，成功后不产生第二个元婴。
- 失败后宿主存活且原主只死亡一次。
- 元婴形态被击杀不会再次生成元婴形态。
- 构建命令 `dotnet build Cultiway.csproj -c Debug` 通过。
