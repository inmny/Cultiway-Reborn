## 具体说明

2026 年 11 月 10 日完成本阶段实现，结果和实际画面见[验收记录](第4阶段-验收记录.md)。自然城市的长期运营和实际高倍率长时间稳定性继续按第 3 阶段的剩余项目验收。

实施落点为 `RailwayTradeService`、共用的 `TrainTransportSystem`、`Content/UI/Railways/`、`RailwayMapOverlay` 和 `WorldfallModelIntegration.Trains.cs`。金币直接使用原版车头背包，窗口只读取当前记录，不保存第二套运营状态。

### 贸易运营

城市在已有可用客运能力、存在许可贸易目标且资源充足时，可补足货运能力。先检查能否为归属站内的空闲列车加挂货运车厢；不合适时再新建“1 个火车头＋1 节货运车厢”的默认贸易编组。按实际新增部件支付造价，具有货运能力的列车每站最多 1 列，混合列车也计入。

纯货运编组只承担货运任务；具有载客车厢的混合列车可以同时服务客运。乘客只进入载客车厢，贸易载荷与所得收益使用货运部分，不因另一类车厢空着而互借容量。

目标是同一铁路网内有合法线路、能正常使用、与本国不敌对且具备运营许可的其他城市车站。同一城市的两个站不构成贸易；本国其他城市可以成为目标，不要求必须跨国。

`停放 → 选择目标 → 申请线路 → 抵达目标站 → 停站交易 → 返己方车站 → 收益入库 → 停放`

没有可用贸易目标就停放，不循环刷空车。往返都使用实际线路和区间占用。发车选择预计完整周转时间，优先较少服务过的可用目标，不让最近的车站被同一辆车无限瞬时重复访问。

线路竞争顺序低于事故疏散、军令和已等候旅客。贸易运行后不被强行中途挪走；新的优先级在下一站重新选择时生效。

混合列车只接受与既定客运停站顺序一致的贸易目标。整列只推进一份运行行程，到站时分别完成上下客和交易，不为贸易再启动一套独立移动，也不为交易临时增加客运绕行。

### 收益与中断处理

参照原版商船：完成一次外站停留后，向列车背包加入 5 金币，返己方车站后调用城市资源入库流程。对方城市库存不扣减，也不凭空同时奖励两城。

收益按本次贸易行程结算，不按火车头、货运车厢数量或乘客人数重复发放。加挂更多货运车厢增加可用载货量，不自动把一次访问的 5 金币翻倍。

列车保存本次贸易编号、起终城市、目标停留是否完成、收益是否已产生及结算归属。背包仍使用原版 `ActorData.inventory`，不能再保存第二份“待领取金币”并重复兑现。

到站生成收益和标记已完成在同一次逻辑操作内完成。读档只恢复未完成的动作，不重新发放已经生成的金币；返站入库与清空对应背包同样只执行一次。结算必须先确认城市仍可接收，不能在没有有效城市时调用会清空背包的卸货流程。

| 中断 | 行为 |
| --- | --- |
| 去程目标失效 | 取消本次交易，选择返站或停驶，不产生收益 |
| 已交易但回程断轨 | 保留车上金币，等待修复或改走许可线路，不直接记入城市 |
| 归属站被毁 | 可转交同国其他许可站，收益进入当前接管列车的有效城市 |
| 车站易主或国家变化 | 撤销旧贸易目标和结算承诺，按车辆归属规则处理；不同时向新旧国家结算 |
| 车辆被毁 | 交由明确的原版资源掉落或损失规则结算车上金币，不能给城市补发 |
| 去程、交易后、返程或入库后读档 | 收益与背包一致，不重复增加 5 金币 |

货运部分的下一次交易需等待本次返站结算完成，并至少经过 10 个模拟秒的周转等待。混合列车在此期间仍可执行客运，不让贸易等待拖住乘客。这个初始限制与实际路程共同约束短线收益，后续根据游戏内收入与城市造价再调平衡。

### 信息展示

优先扩展现有单位与建筑信息入口，不要求玩家先开一个线路管理器。具体页面使用 `Source/Content/UI/Railways/`，遵守 `Prompts/UI.md`。

| 对象 | 必须可见的信息 |
| --- | --- |
| 列车 | 名称、归属城市与车站、按顺序显示的火车头和各节车厢、当前站和下一站、生命、当前状态 |
| 载客部分 | 每节载客车厢及整列的已乘人数 / 座位数、候车人数、下一站预计时间；乘客列表可定位个人 |
| 货运与贸易部分 | 每节货运车厢及整列的载货量 / 容量、目标城市、本次是否交易、车上收益、预计返站时间 |
| 车站 | 归属、是否完工、上下客点、归属车辆与位置、候车人数、可达站点 |
| 线路 | 两端车站、是否可运营、长度、预计耗时、当前占用、施工或维修进度 |
| 停运 | 清楚显示“没有可用列车”“列车维修中”“线路受损”“无通行许可”“下一段有车”等具体原因 |

玩家可从车站查看并定位列车、目标站和断点。首期只提供信息与定位，不增加手工时刻表或车辆编组编辑器。

铁路覆盖显示区分可运营、施工、受损和外交暂停；颜色同时配合图标或文字，不只靠颜色表达原因。默认只显示选中车站所在网络，避免把整张地图盖满。

所有内容使用玩家能理解的名称，不向产品界面暴露请求对象编号、内部状态名称和存档键。固定小图标可提供提示，整行列表不绑悬停提示，保留滚轮操作。

### 刷新与日志

窗口打开时读取一次快照，状态改变时更新相关项；列车预计时间等动态字段低频刷新。关闭界面不继续扫描全网，重复打开不重复订阅事件。

公共外观、滚动容器、筛选、按钮与空状态复用已有 UI 基础设施，铁路领域数据不放进公共控件层。长车站名、没有车、孤立站和已失效选择都有完整显示。

删除列车每次移动的普通日志。现有列车日志分类只记录造车、分配、出站、到站、断轨、维修、取消、毁车和贸易结算；必要的连续位置采样留给显式调试。

### 验收

| 场景 | 通过条件 |
| --- | --- |
| 同国两城往返贸易 | 车在外站获得 5 金币，返站后城市入库，造车费与收益分别可核对 |
| 对方库存为空 | 简化贸易仍按既定收益工作；不修改对方木材等库存 |
| 四个贸易时点保存读档 | 每次实际外站访问只产生一次收益，入库后背包不残留同一笔金币 |
| 回程断轨、归属站消失、毁车 | 金币位置或损失可解释，不瞬时补发到城市 |
| 客车与商车竞争交叉线路 | 遵守同一占用与排队规则，不发生穿车 |
| 混合列车同站上下客并交易 | 两类任务只推进一份行程，客货容量分开，贸易不改变已承诺客运站序 |
| 一节与多节货运车厢进行同一次贸易 | 一次有效外站访问仍只产生 5 金币，增加车厢不重复发放 |
| 空站、满载、无车、长名称与断线 | 信息完整，玩家能定位问题，无文本和按钮相互遮挡 |
| 多次开关界面、缩小分辨率、二三维切换 | 滚动、事件订阅、布局与列车位置一致 |
