# 现状核查与船舶对照

核查范围为当前仓库的火车、铁路、通用运输请求和寻路接入，以及本机原版船舶源码。下表中的风险根据代码路径判断，复现步骤用于后续游戏内验证。

本页保留实施前的基线；2026 年 11 月 9 日起的实现与验收进度见[方案摘要](../火车系统完善-摘要.md#实施进度)。

## 目前已有的流程

| 环节 | 当前行为 | 依据 |
| --- | --- | --- |
| 建站 | 城市领袖谋划，可与同国或关系好的邻城共同建站，直接添加车站建筑 | [Plots.cs](../../Source/Content/Plots.cs) 的 `BuildTrainStation` |
| 铺轨 | 在邻城车站之间按坐标方向生成格子并铺设，登记站对连接 | [Plots.cs](../../Source/Content/Plots.cs) 的 `BuildTrainTrack`、旧 `TrainTrackPathHelper.cs`（第 2 阶段已移除，现行选线见 [RailTrackRoutePlanner.cs](../../Source/Content/Railways/RailTrackRoutePlanner.cs)） |
| 铁路维护 | 格子改变时标记受损，定时补轨，失败后尝试重画；根据站对连接更新可达车站 | [TrainTrackRepairTickSystem.cs](../../Source/Content/Systems/Logic/TrainTrackRepairTickSystem.cs)、[PatchAboutTrain.cs](../../Source/Content/Patch/PatchAboutTrain.cs) |
| 请求与合并 | 寻路使用车站入口，请求可在现有站序中合并或向后延长 | [PortalManager.cs](../../Source/Core/Pathfinding/PortalManager.cs) |
| 发车与停靠 | 每个请求生成一辆列车，等客、运行、停靠；终止后释放乘客并销毁列车 | [TrainTransportSystem.cs](../../Source/Content/Systems/Logic/TrainTransportSystem.cs) |
| 移动与外观 | 沿缓存轨道计算车头位置；定义了车头、客车、货车，但创建时只有一个车头 | [Train.cs](../../Source/Content/ActorComponents/Train.cs) 的 `create`、`update` |
| 运营参数 | 5 秒聚客、3 秒基础停靠、7 秒额外等待、5 秒发车间隔；定时空车默认关闭 | [TrainConfig.cs](../../Source/Content/TrainConfig.cs) |

目前没有找到独立的火车设计文档。本组方案作为铁路玩法的总览与实施依据。

## 必须先解决的问题

| 问题 | 源码依据与影响 | 游戏内验证方式 |
| --- | --- | --- |
| 未登车者被下客逻辑搬走 | `DropPassengers` 对 `ToUnload` 中的存活者都调用 `spawnOn`；是否在 `Carrying` 中只决定清不清标记 | 两人同程，让一人赶不上车；到站后迟到者应仍在原处 |
| 迟到者仍留在后续下客名单 | `IgnoreLatePassengers` 只从当前 `ToLoad` 删除；后续 `ToUnload` 未同步删除 | 检查迟到者在整段请求中不再有席位或下客记录 |
| 乘客承载关系不完整 | `BoardPassengers` 只写 `is_inside_boat`、`transportID` 和本地集合，没有设置 `inside_boat` 或原版乘客集合；原版 `Actor.die` 会访问 `inside_boat.removePassenger` | 车内乘客死亡时，正确减员，不出现空引用或占着座位 |
| 下车遗留运输编号 | 正常下客和 `DestroyRide` 没有将 `transportID` 清为 -1 | 下车后保存、读档，不应再次被当作车内乘客 |
| 列车本体被排除在存档外 | [Actors.cs](../../Source/Content/Actors.cs) 从 `crabzilla` 克隆，仅改归属和外观；原版模板设 `skip_save=true`，[SavedMap.cs](../../.GameSource/Scripts/Assembly-CSharp/SavedMap.cs) 明确跳过此类单位 | 载人途中保存再读档，列车与乘客关系应同时存在 |
| 不能只打开保存开关 | [SaveManager.loadBoatStates](../../.GameSource/Scripts/Assembly-CSharp/SaveManager.cs) 会通过运输编号获取载具的 `Boat` 组件；当前列车没有该组件 | 确认读档先给列车安装承载组件，再恢复车内乘客 |
| 巨兽模板带入无关行为 | 原版 [ActorAssetLibrary.cs](../../.GameSource/Scripts/Assembly-CSharp/ActorAssetLibrary.cs) 的巨兽包含专属受击、死亡回调，包括核爆动作；火车未主动清理 | 受击与毁车只执行铁路定义的伤害、疏散和效果 |
| 铁路连接与行程未保存 | 线路存在静态 `Links`，行程存在 `_rides`，没有对应存档写入和恢复；车站类型也未配置重建回调 | 已有两站铁路读档后能再次发车，在途行程能继续 |
| 实际格子未随列车移动 | `Train.update` 只赋值 `actor.current_position`；存档坐标来自 `current_tile`，乘客跟随补丁也使用该格 | 检查列车、乘客、地图格、存档坐标和受击位置一致 |
| 断轨仍可被寻路选择 | `MarkTileDamaged` 将连接改成待修，但没有立刻要求重建可达连接 | 损毁一格后，新乘客当轮起不再选用该连接 |
| 缓存路线跨过缺口 | `TryGetPath` 过滤非铁轨格而不验证相邻；运行只检查是否到终点，不检查路况 | 毁掉前方轨道或淹没地块，列车应停在缺口前 |
| 修复可能覆盖新地形与建筑 | `TryRefill` 直接补轨；`TryRebuild` 仍调用方向画线，没有完整陆地和建筑规则 | 用海水、山体或建筑替换轨道，不能被定时修复强行覆盖 |

## 运营和寻路方面的缺项

| 缺项 | 当前依据 | 设计要求 |
| --- | --- | --- |
| 车辆没有城市运营身份 | 创建不绑定归属车站、城市或国家；结束统一 `die(true)` | 城市建造有限车辆，结束行程交回空闲池 |
| 车辆与请求的对应不完整 | 火车创建后未写 `request.Driver`；通用检查会把没有载具的 `Driving` 请求改回等待 | 一个执行中的请求只对应一辆列车；完成和取消分别给出结果 |
| 没有实际容量 | `BoardPassengers` 不限制人数，也未创建客车车厢 | 有座位才登车，超员者保留独立需求 |
| 车站毁坏后不应搬移候车者 | `PortalRequest.RemoveDeadBuildings` 会把上下客名单并入下一站 | 铁路按乘客是否在车内分别处理，不沿用这种并站规则 |
| 发车间隔不能代替占线 | 冷却在发车后设置，准备时检查；没有出站时的统一占用检查 | 在真正出站时同时检查间隔与物理线路冲突 |
| 估时与移动规则不一致 | 铁路估时为格数×0.5，等待固定为 1；实际移动为速度属性×0.01，另有聚客和停靠 | 同一换算计算实际行车与预计耗时，把候车和接车时间算进去 |
| 多站选择缺少统一的时间比较 | `PortalManager` 按最少站数找路径；`PortalAwarePathGenerator` 的一次选择只比较入口的直接连接 | 发布可执行的多站耗时与站序，避免两处得出不同路线 |
| 缺少旅客通行条件 | 请求合并主要比较入口类型和站序，没有核对旅客国家与列车归属 | 合并、接单和登车都检查运营许可 |
| 缺少运营反馈 | 列车移动逐次输出 `LogInfo`；没有完善的车站与列车状态说明 | 记录有意义的状态变化，界面解释无车、满载、断轨等原因 |

## 复用边界

直接复用原版乘客承载组件和上下车方法。列车初始化时通过原版 `addChildSimple(new Boat())` 安装精确的 `Boat` 类型，以兼容原版按类型读取组件的方式；列车资产仍保持 `is_boat=false`。不能靠打开船只标记安装组件，因为原版会让陆地上的船受损。

火车自己的服务负责轨道移动、车站归属、任务和安全下客。对 `Boat` 中的死亡、落地及取消移动回调，只在载具确实是火车时转交铁路处理；普通船舶照旧。不能直接调用依赖海域、码头和水格的船舶调度。

沿用现有通用运输入口。Core 层增加的能力应是“查询乘客行程”“完成或取消请求”“传入许可条件”等通用操作，铁路的国家、站台、造价和维修规则留在 Content 层。

## 资源核对

本机 `.GameSource/Assets` 目录不存在，原版导出资源实际位于 `.GameSource/Resources`。已核对码头的 `buildings/civ_main/<种族>/docks_<种族>/` 结构和 `ui/icons/iconBoat`、`iconClock`、`iconArrowDestination`、`iconCityInventory` 等资源，实施时以实际加载键为准。

模组车站位于 `buildings/civ_general/Cultiway.TrainStation/`，不能照其他模组建筑误写成 `buildings/Cultiway.TrainStation/`。现有铁路是顶层地块，会占用该格原有顶层内容，选线必须把覆盖规则写清楚。
