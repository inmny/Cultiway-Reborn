## 落地情况

2026 年 11 月 10 日完成本阶段核心实现，构建零错误，游戏内 53 项检查通过，详见[验收记录](第2阶段-验收记录.md)。

目前按城市领袖谋划建站和立项；车站至少需要 50 人，各城各付本站费用。选线复用现有导航地形和优先队列，农田、树木及其他建筑统一绕开。每两秒最多推进三项工程，每项每批最多 16 格；取消后保留已付费轨道。

站内采用隐藏存车，车节沿轨逐节进出，车尾全部入站后才释放站外占用。站口从既有城市建筑外围检查步行连通，读档后城市中心重选不会使站口失效；附近道路、建筑和地形改变会更新上下客点。

当前估时按请求式调度、默认两节车厢和基础停站时间计算。常驻车辆的数量、可派车等待和不同编组估时，在[第 3 阶段](第3阶段-城市造车与运输调度.md)接入。完整原版模拟循环、长时间运行和画面检查继续列入后续验收。

## 具体说明

### 建站与出入口

继续使用城市领袖谋划。默认每城一站，城市人口、资源和潜在邻城满足[摘要中的建议参数](../火车系统完善-摘要.md#建议初始参数)后才能建设；候选邻城也必须满足建站条件或已有可用车站。避免孤立城市反复建造无用途设施。

手动发起只检查城主身份和建站条件，不要求自动谋划继承的等级、个人金币或国家声望。本站需要至少 50 人，城市库存达到木材 40、石头 20、普通金属 5、金币 20。当前沿用原版同类谋划互斥：世界中已有建站谋划进行时不能再发起。按钮悬浮说明显示实际人口、库存和首个未满足条件，点击失败时顶部显示具体原因。

建筑占地仍为 10×5，但必须明确三种位置：建筑占地、居民可步行到达的上下客点、列车可进入的站内轨道端点。它们不必是同一格。禁止使用被过滤掉的建筑中心格代替真实进站路径。

选址保留原版允许建设的分区和城市规划限制，再检查分区内各个候选位置。普通草地、空地和道路允许占用，农田、树木及其他建筑绕开；不能因为一个候选位置不合适就放弃整个分区。此项与发起失败提示于第 4 阶段之后补充，当前仅完成构建检查，详见[补充记录](第4阶段-验收记录.md#建站发起问题的补充修复)。

至少存在一个可连接城市外侧陆地的轨道方向才允许选址。候选上下客点须能与城市道路相通，不能把居民要求到墙内、水格或建筑不可站立的位置。

建站检查和扣费由一个建设入口完成，谋划只发起请求。成功创建站点才扣费，失败不收费。每个参与城市支付自己的站点费用，不能由一次联合谋划免费给所有城市铺开。

### 铺轨与工程费用

`RailTrackRoutePlanner` 读取已有导航格子信息，按四向相邻的工程代价选择路线。人物寻路仍由人物寻路器负责，不把角色能飞、能游泳或能破墙当作铁路可建的理由，也不另建一份全世界地形缓存。

| 地块 | 首期规则 |
| --- | --- |
| 安全平地、普通草地 | 允许，优先较短的路线 |
| 已有铁路 | 优先复用；计入线路共享，不重复收费 |
| 普通道路 | 允许共用，轨道必须继续允许居民步行通过 |
| 海水、河流水格、熔岩、山体、阻挡格 | 禁止；不存在陆地路线就暂停该工程 |
| 住房、政厅、宗门建筑、码头及其他重要建筑 | 禁止拆除或穿过，车站自己的专用轨道入口除外 |
| 农田、树木与其他专用表层 | 绕开，不自动清理 |
| 敌国或没有许可的领土 | 禁止新建；建设双方本土及允许通行的友好领土才可选用 |

先得到完整合法路线，再创建工程记录。记录两站编号、路径、待铺部分、预算、已施工进度和出资城市。由发起城市支付轨道费用，目标城市不被自动扣款；资源不足时暂缓。

轨道费用按整条工程中新铺格子计算，每 8 格消耗木材、石材、普通金属各 1，向上取整。分批施工前检查本批地形仍合法，将已铺格子的累计费用与已付费用比较，只扣增加的部分；失败部分不收费，共用部分不重复收费。

施工过程保存进度。未完成的线路不向寻路发布。中途取消保留已付费铺出的轨道，不自动退费；以后复用时只为新增部分付款。每轮限制施工格数，建议从每工程最多 16 格起调，防止一个谋划铺完整张地图。

不自动连接所有邻城：已有可运营通路满足需要时不重复立项；没有通路时优先最近的一个许可邻城，再根据真实运输需求决定是否补线。

### 线路记录与运营连接

线路保存有序轨道格，起点是本站轨道端点，终点是另一站轨道端点。全程四向连续，包含合法站内部分；不能把不属于铁轨的格子删掉后声称仍然连通。

区分“施工、可用、受损待修、维修中、暂停运营、已撤销”。暂停需要保留原因，例如外交封锁或维护资源不足。受损和外交变化当轮就撤下相应运营连接，不能等若干秒后的维修结果再处理。

物理轨道相交不自动生成上下客站或新的商业线路。首期只在车站换乘；共用或交叉的格子仍受同一占用规则约束。

创建、完工、毁坏、重建及读档均更新站点索引。为 `Portals.TrainStation` 补齐重建回调；只重建受影响的线路和网络，不为一个站点遍历所有人物。

### 断轨与维修

轨道顶层变化、地形变成水或山、重要建筑占用、车站毁坏或易主，都使相应线路重新检查。不能只监听“顶层不再是铁轨”，因为底层地形变化也会让轨道失效。

运行中的列车逐段检查本次将经过的格子，并保留最后安全位置。缺口在前方时停在缺口前；列车脚下已经变成危险地形时立即疏散。等待维修期间不会继续占用新的区间。

维修沿用现有低频处理入口，建议每 2 秒最多处理 3 条受损线路。首轮重试和后续失败延迟分别采用 5 秒、10 秒起调；失败 3 次后暂停自动重试，等待地形、资源或车站状态发生实际变化再激活。

只有原路径仍是合法陆地且没有新建筑阻挡时，才允许补回缺失轨道，并支付新补部分的工程成本。海水、山体和合法建筑不能被自动修复覆盖。

原路径不可修时，可以重新申请一条合法绕行工程。新线完工前维持停运，不把旧行驶进度直接套到新路径上；停在旧线上的车辆先处理乘客，再沿剩余可用路径回站。没有回站路径时保持停驶，不瞬移归位。

2026 年 11 月 11 日补充：受损、暂停或已撤销的连接允许再次发起“连接铁路”。已有中断记录时重新激活同一条工程，由本次发起城市承担后续修复费用；原线可用就补轨，原线受地形、建筑或途经领土限制就寻找合法绕行。旧线尚有列车占用时等待撤离，不更换其运行路径。正在施工、维修的工程及实际可运营的直达或间接通路仍阻止重复立项。两端车站之间失去通行许可时仍不能强行连接。

### 废弃轨道的自然衰退

取消工程、车站失效或改线后，失去所有线路和工程引用的旧轨道成为废弃段，恢复原版道路的随机自然衰退。仍用于其他线路的共用轨道、暂停待修的线路和被实际列车占用的旧线继续受到保护；列车离开或被毁后解除占用保护。读档按恢复的工程和实际列车占用重新判断，不另建废轨清理计时器。

清理沿用原版道路的分区抽样、随机概率和城市道路文化规则，因此没有固定的废轨消失期限。运行或施工中的轨道不会因道路自然衰退被清除。

### 区间占用

首期采用整段保守占用：车辆从一站驶向下一站之前，一次申请该段所有轨道格及冲突交叉格的使用权。申请完整成功才离站，失败则留在站内；不拿一半线路再等待另一半。

同一格不能同时属于两辆运行列车的占用范围，因此对向、同向追车、两条不同线路的交叉和共用轨道都能被挡住。每次只申请下一站，不提前锁住整张铁路网。候车、贸易与返站使用相同规则。

到站时，列车尾部进入站内范围后才释放站外占用。站内停车与站外运行分开：归属车辆停在站内存车位置，不长期霸占到发位置；有站内空间才允许接车。首期可采用站内位置偏移表达，不要求玩家修建信号设备。

排队按首次申请时间、列车编号决定，避免两个方向轮流抢占。整个申请在一次逻辑操作中完成；没有运行中间途抢占、硬让车或列车相互穿过。

列车被毁、取消、世界切换及读档恢复都处理占用释放。读档先根据仍在区间内的列车重建实际占用，再开放新发车，不能把轨道一律当作空闲。

### 寻路与验收

对外发布可运营连接与预计耗时，估时包括走到站点、接车等待、基础停靠、行驶和下车后的步行。已经无车可派且等待不可估时，暂不向新旅客提供该运营连接；已有可造车需求可以唤起城市造车判断。

铁路多站路线按预计耗时选择，结果要携带实际停站顺序，由调度沿用。不能让人物按时间选了一条路，运输请求又按最少站数换成另一条路。第 3 阶段加入国家和车辆许可后，对同一物理网络发布相应可用的运营选择。

| 场景 | 通过条件 |
| --- | --- |
| 海峡、山脉、城墙和建筑挡住两站 | 绕行或无法开工，不毁掉障碍后直铺 |
| 资源不足、施工失败和联合建站 | 不透支；各城费用正确；完成线路只收费一次 |
| 已有轨道共用、工程取消再续建 | 共用格不重复收费；进度和费用读档后连续 |
| 前方断轨、底层淹水、维修中又损毁 | 及时停止新连接和运行，不自动填海或压过新建筑 |
| 两车对向、十字交叉、同轨追车 | 占用冲突时有车在站内等候，车尾离段才放行 |
| 车辆在交叉段读档 | 原有占用先恢复，不与新车同时驶入 |
| A—B—C 与另一条更快的多站路线 | 实际停站顺序和寻路估时选择一致 |
