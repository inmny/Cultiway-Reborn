## 具体说明

### 车辆与承载组件

保留 `Cultiway.Train` 资产编号和现有外观资源。改为独立配置机械载具，移除对螃蟹巨兽模板的依赖，明确保存、生命、速度、受击和死亡行为。取消巨兽专属死亡、受击回调及其专属状态；不以“只改一个保存开关”完成此项。

一列车使用一个原版载具单位代表火车头，载客车厢与货运车厢是它按顺序持有的车节，不各自创建独立人物单位。本阶段的客运行程至少创建一节实际载客车厢；完整自动编组和容量规则在第 3 阶段接入。

列车保持 `is_boat=false`。在单位初始化期间通过 `addChildSimple(new Boat())` 安装原版承载组件，确保早于 `SaveManager.loadBoatStates`，并纳入原版子组件生命周期。使用精确的 `Boat` 类型，因为原版按类型查询，不会把自定义子类自动当作它。

`Boat.getPassengers()` 是“实际在车内”的唯一名单，删除 `RideState.Carrying` 的平行所有权。车站候车名单和各人的下车站只是行程信息，不能成为判断某人已经上车的依据。

乘客的原版运输编号指向火车头单位，铁路行程另记所属载客车厢和座位。整列承载关系仍只有一份，不能为每节车厢再建一套互相竞争的原版乘坐关系。

火车的死亡、落地和取消移动，由铁路服务统一释放请求、乘客及运行状态。原版 `Boat` 对应回调仅在火车上转交此服务，避免它绕过铁路清理或把乘客直接丢在危险地形。保留普通船舶的原有处理。

### 乘客行程

乘客依次经过“前往车站、等车、已预留座位、车内、到站完成”，也可以在上车前取消。车站把“已到站人数”与“仍在路上的人数”分开统计，车辆没有就位时不启动 10 秒上车等待。

上下客点取车站占地外最近的安全陆地，距离相同时按格子编号选择，寻路、候车与下客共用这个点。原版 `getConstructionTile()` 随机返回建筑占地内的施工格，不能用来定义固定站台。

登车条件同时满足：乘客仍存活、仍需要这段旅行、没有在其他载具中、已到合法上下客点、列车正在该站停靠。座位容量在第 3 阶段启用。登车统一调用 `Actor.embarkInto`，不要分别写几个标志位。

| 事件 | 必须执行的处理 |
| --- | --- |
| 正常到站 | 核对属于本车，调用 `disembarkTo`，移除本车乘客记录，确认 `transportID=-1`、`inside_boat=null`、乘坐标志已清除 |
| 迟到或主动取消 | 从本人所有候车、预留座位、后续下客记录中移除；本人留在原地，释放座位并重新选择出行方式 |
| 乘客死亡 | 原版承载集合减员，删除本人行程和预留座位；不影响其他乘客 |
| 出发站消失 | 未上车者在原处取消候车；已经在车内的人按当前可达线路处理 |
| 目标站消失 | 车内乘客去最近的许可车站下车；没有可达站时执行安全疏散 |
| 车辆被毁 | 先疏散乘客，再释放运行状态；未上车者取消本次分配，保留重新出行的机会 |
| 行程结束 | 分别通知成功到达、取消、线路失效等结果；不能统一调用 `Cancel` 代替成功 |

铁路不采用“坏掉的车站把上下客名单并入下一站”的规则。通用请求需要允许内容层提供站点失效处理；船舶与传送阵维持各自的语义。

上车前保存最终目标格、目标城市以及原任务必要的标识。上车时停止步行，不宣布已经通过跨站路段；下车后才结束运输步骤，并从实际下车点重新请求剩余路径。原版上下车会切换乘坐和短移动任务，因此业务任务应重新确认，而不能假定它会自行恢复。

### 请求与车辆的对应

原版字段 `Driver` 在这里指执行请求的载具。分配列车时同时设置 `request.Driver`，车辆也记录当前行程编号；结束时一并解除。运行中的列车不能再领取第二个请求。

通用请求增加区分成功与取消的结束原因，并提供按乘客查询、移除个人行程、绑定载具和完成请求的操作。上车后仍能查到本人当前行程，不能只在 `ToLoad` 里查找。

请求派生的上下客列表不再由多个系统直接增删。取消某人、销毁站点和完成行程都通过上述操作更新关联列表，避免只删掉一端。Core 层只处理这些通用关系，铁路规则通过内容层的回调传入。

### 位置与时间

由逻辑更新推进沿轨距离，同步车头的实际世界坐标、所在格、区域及地图分块信息，再让车厢跟随同一条轨迹。使用原版移动所需的位置更新流程，不能只赋值 `current_position` 或 `current_tile`。

每次换区间从实际站内位置连续驶出，不能通过重置进度直接跳过一段与列车总长相等的轨道。车厢间距和站内轨道采用相同的世界单位，车尾尚未到站时不能提前整列下客。

`Train.cs` 接收已确定的逻辑位置并显示车头、车厢；渲染更新不再额外推进一次行程。看不见列车、关闭画面或高倍率运行，都不能改变运输完成时间。

暂停、候车、超时和移动统一使用模拟时间。当前移动里的 `速度×0.01` 与寻路估时中的 `格数×0.5` 应归并为一套明确换算。停站只控制显示及运动状态，不关闭整个组件对象来承担业务暂停。

本阶段同时拒绝有缺口的路径。按顺序验证各格合法且四向相邻，任一格缺失就报告线路不可用，不能过滤缺格后继续连接两端。每次移动检查本次经过的格子，高倍率也不能跨过缺口。

### 保存的数据

数据随当前世界的原版单位与建筑存档保存，使用 `BaseSystemData` 已有的自定义字段。不要把铁路写进跨世界共用的 `ModSaveManager`。

| 保存位置 | 数据 | 规则 |
| --- | --- | --- |
| 车站 `BuildingData` | 相邻站编号、有序轨道格编号、线路状态和修订号；第 3 阶段加入站内闲置车厢列表 | 每条线路只由编号较小的端点保存一份；闲置车厢不能同时挂在列车上 |
| 列车 `ActorData` | 有序车节列表、各节编号与类型、行程编号、停站顺序、当前区间与方向、沿轨进度、最后合法位置、剩余停靠时间 | 保留原编组，容量按车厢配置计算；不序列化原版对象、组件或请求引用 |
| 乘客 `ActorData` | 起终站、最终目标、当前出行状态、所属行程、载客车厢和座位 | 实际登车关系以原版 `transportID` 为准，不根据候车名单恢复登车 |
| 原版已有字段 | 单位编号、归属城市与国家、归属建筑、生命、背包、乘客运输编号 | 沿用原版保存，常驻归属在第 3 阶段正式启用 |

在原版 `Actor.prepareForSave`、`Building.prepareForSave` 的适当接入点写入本次快照，统一使用 `cw.railway.*` 键。只保存必要状态；候车剩余时间保存时长，读档后按新的模拟时间恢复截止点。

存档期间不让车辆驶向车站、临时下客或重新生成车辆。世界快照应来自同一轮已完成的逻辑状态，不能出现乘客记录已上车、列车记录仍未分配的中间状态。

### 读档顺序

1. 原版创建列车单位时安装承载组件，按保存的类型和顺序恢复车节，不覆盖已保存的列车数据。
2. 原版创建建筑与国家、城市等对象后，按编号读取铁路记录，验证轨道并建立站点索引。
3. 原版 `loadBoatStates` 根据 `transportID` 恢复乘客；此时列车的 `Boat` 组件必须已经存在。
4. 在开始世界模拟前，按车辆与乘客记录重建运输请求，恢复 `Driver`、站序、进度和剩余停靠时间。
5. 最后发布可运营线路。前面尚未完成时，不让寻路发出新的铁路行程。

重建请求只是恢复运行时索引，不创建第二辆列车，也不再次收费。保存的线路与当前合法轨道不符时，车辆停在记录的最后合法位置，按断线规则处理，不能套用新路线后跳到别处。

记录指向不存在的载具或站点时，解除该次乘坐关系并从记录的实际位置重新规划。安全疏散优先使用最近的合法下车点，其次是沿已走轨道回查的安全陆地；附近没有安全陆地时，让乘客在事故实际位置退出载具并交回原版环境规则，不远距离传送或强造陆地。

新建世界和切换存档时，经现有世界清理流程清空请求、静态线路索引和列车引用。不要对旧版本缺失的铁路记录添加猜线、补造车辆或迁移分支。

### 验收

| 场景 | 通过条件 |
| --- | --- |
| 两人同程，一人迟到 | 实际上车者到达；迟到者没有移动到目的站，也没有残余下客记录 |
| 上车、行驶、停站、下车后分别保存读档 | 无重复车辆、重复乘客或幽灵乘坐；行驶能从原进度继续 |
| 车内死亡、毁车、取消、车站摧毁 | 无空引用，乘客和请求解除完整，其他旅客可继续处理 |
| 列车行驶较长距离后存档 | 列车和乘客坐标对应实际地点，不回到始发站 |
| 运行中删除前方轨道 | 列车停在缺口前，不沿过滤后的路径跨越 |
| 暂停与不同倍率 | 暂停时位置和截止时间不推进；相同模拟时长得到相同进度 |
| 连续切换两个世界 | 车辆、乘客和线路索引不串到另一个世界 |
| 原版船舶与传送阵 | 原有上下客、毁船、读档和传送流程仍成立 |

实现后先做一次构建检查，再在游戏内覆盖上述场景；本方案不把文档核对当作游戏实测。
