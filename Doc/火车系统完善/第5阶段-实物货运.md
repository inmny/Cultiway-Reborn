## 具体说明

### 城市供需

首批只运木材、石材和普通金属，不马上涵盖装备、人物物品、食物保鲜或跨国买卖。两座城市属于同国、都有许可线路，且一方超过保有量、一方低于补给目标时，才生成实际运输需求。

保有量依据城市已有建设与消费需求计算，不能为了铁路一次搬空粮仓或建筑材料。已有建设规则能提供需求时直接使用，不在铁路内重做一套城市经济。

本期保有量和补给目标取同一个值：通过原版 `CityBehBuild.canUseBuildAsset` 检查当前允许的建设项目，逐项材料保留最高单项造价的两倍，最低木材 40、石头 40、普通金属 20。不调用原版会修改待建列表的计算入口。仅输出高于此值的部分，仅向低于此值的城市补给，避免在两个库存区间之间反复搬运。同一轮选货按城市复用计算结果，不保存另一套世界经济数据。

首期为同国城市补给，不收买卖价款。跨国交易需要另行明确价格、通行与结算后再扩展，不能沿用“关系好”就直接拿走对方库存。

一城可输出量为当前库存减去本城保有量及其他已预留任务。目标需求量减去已经在途的同类补给，避免多车同时给一个城市运来重复补给。

### 装载与数量守恒

复用每站最多 1 列的具有货运能力的列车，可以是纯货运或客货混合编组，不因为开通实物货运再免费增加火车头或车厢。每节货运车厢建议按 40 单位资源总量计算，整列货位为实际货运车厢容量之和；木、石、普通金属初始均按每件 1 单位占用。

载客车厢不提供货位，货运车厢不提供客位。乘客与货物分别预留容量，到站各自处理。混合列车只接受符合当前停站顺序的补给任务，不为货物拖延已经承诺的旅客行程。

任务顺序为：

`确认供需 → 预留源城资源 → 派车到源站 → 核对库存并实际扣除 → 加入车上背包 → 实际沿轨运输 → 到目标站入库 → 清除预留与在途数量`

预留不是实际搬走。装货时才从源城扣除并放入列车背包，两步在同一次逻辑操作内完成。资源已经被其他城市行为消耗时，缩减或取消装运，不能生成负库存或凭空补足。

卸货时把背包中的实际数量加入目标城，再清除车上对应资源。预留和在途数据是任务索引，不能在读档时再次从它们生成一批货物。

原版整列背包保存唯一的实际货物数量，铁路记录只分配各货运车厢占用的容量和资源批次，不给每节车厢复制一份背包。保存并恢复车厢排列与货物分配，不能读档后把货物装进载客车厢。

每节货厢的显示份额按原版背包、实际货厢顺序和稳定的材料编号顺序计算，相同存档恢复相同分配。材料的硬上限沿用原版资源 `maximum`；采集工作的停止阈值 `storage_max` 不是运输硬容量。入库逐仓调用原版增加资源入口，以库存前后差额计算实际接收量，再扣背包，剩余空间不足时保留余货。贸易金币入库也使用同一处理。

每种资源均应满足：

`源城与目标城库存之和 + 车上资源 + 明确保留的掉落物 + 已记录损失 = 原有数量 + 生产量 − 实际消耗量`

测试静态场景时关闭额外生产与消费，公式应直接守恒。实物运输不同时产生第 4 阶段的 5 金币收益；货运部分可以在没有补给任务时承担简化贸易，但一趟行程的货运只选定一种结算方式。载客部分可以同时运人，仍只使用载客车厢座位。

### 中断与保存

| 情况 | 处理 |
| --- | --- |
| 装货前取消 | 只撤销预留，实际库存没有变化 |
| 装货后取消 | 货物继续留在车上，返源城或改送同国其他仍有需求的车站 |
| 目标被毁或易主 | 重新核对接收方，不能把同国补给直接卸给新敌国 |
| 路线中断 | 货物在车上等待修复或改道，列车不沿新路径跳跃 |
| 车辆毁坏 | 记录车上实际损失后销毁全部资源，不掉落、不退款、不结算；释放在途需求 |
| 城市灭亡 | 撤销城市预留，车上货物仍按实际存在处理，不恢复到不存在的城市 |
| 读档 | 先恢复城市和列车实际库存，再据已保存行程重建预留与在途索引，不重复扣货 |

已装余货优先送原目标，目标缺口已满足或目标失效时改送可达的同国需求城市，再退回源城或同国归属站。原目标仍有需求但仓库暂时无法接收时留车等待。列车持续无法返站达到已确认的五分钟期限时，沿用先下客、再销毁实物的自爆规则。

只增加货物行程所需数据：源城、目标城、各资源数量、装货是否完成、实际接收城市和任务进度。沿用前四阶段的线路、占用、车辆、世界存档和异常处理，不另造货运调度器。
