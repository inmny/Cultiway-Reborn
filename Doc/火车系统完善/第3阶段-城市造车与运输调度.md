## 具体说明

2026 年 11 月 10 日完成核心调度，游戏内 49 项检查通过，见[验收记录](第3阶段-验收记录.md)。三维车厢画面和正常暂停在第 4 阶段补验，见[第 4 阶段验收记录](第4阶段-验收记录.md)。自然城市的长期运营和实际高倍率长时间运行仍待验收，因此最后一项保持待办。

当前用原版军队和城市攻击区域记录真实军令；移动命令取将军目标。每次目标或进攻状态改变会递增批次，批次人数随军队保存。危急车辆先在安全站应急修复至四分之一生命，再返回归属站完整维修；普通维修只消耗模拟时间。

### 城市造车与归属

车站完工、存在至少一个可运营的目标站、城市资源足够时，自动补足 1 辆客运列车。首次造车不要求先存在乘客请求，避免“没有车不发布线路，没有线路又没有请求”的循环等待。

沿用原版城市建设的资源检查与支出方式。造价采用[摘要建议值](../火车系统完善-摘要.md#建议初始参数)，造车成功才扣费，两次造车至少间隔 10 个模拟秒。

每列车的火车头绑定归属站、城市和国家；用原版 `homeBuildingID`、城市与国家字段保存归属，有序车厢、维修及调度状态放在铁路车辆数据中。载客与货运能力从实际车厢推导，不用固定用途字段代替。数量统计包含正在运行、接客、停放和维修的整列车，不能只数站内看得见的车。

每站具有载客能力的列车最多 1 列，第 4 阶段开放具有货运能力的列车最多 1 列；一列客货混合列车同时占两类名额，不据此再补造两列专用车。建造检查在一次逻辑操作中预留名额，防止两个系统同时判定缺车。车辆毁坏后，城市仍须重新支付造价，不免费补回。

当前按请求创建车辆、结束时销毁车辆，以及定时发空车实验入口在本阶段删除。常驻车辆只保留一套分配和状态更新。

### 编组与席位

列车的数据结构为“1 个火车头＋有序车厢列表”，每节车厢明确是载客车厢还是货运车厢。火车头负责牵引，不提供座位和载货容量；载客车厢建议每节 20 人，货运车厢建议每节 40 单位货物。客货容量分别求和，不能把货厢空位当作客位。

默认客运编组为“火车头＋2 节载客车厢”，共 40 人；“火车头＋1 节载客车厢＋1 节货运车厢”则为 20 人和 40 单位货物。固定数量只是自动建造的起始搭配，容量始终来自实际编组。

乘客分配到具体载客车厢和座位；货物按货运车厢分配容量。所有车节跟随同一运行行程，原版承载与货物背包仍由整列统一维护。车节的分配记录不生成第二份乘客或货物。首期整列共用生命，不增加独立车厢生命或行驶中解挂。

车厢间距、列车总长、站内停放和区间占用使用相同的世界单位。车头从真实端点起步，尾部位于站内轨道，不能用“总长”直接把车头进度跳到线路前方。无法容纳整列车的短区间不开放运营。

席位分为预留和已占用。预留席位只发给仍在站点候车范围内、满足登车条件的人；已到站者优先于仍在远处的人。未到站者不长时间锁住全车容量。

满载后，剩余旅客继续等待其他可派车辆或下一轮服务，不能把全部请求成员藏入没有容量的车头。迟到者从本车完整移除，但仍可以重新申请下一班。

基础停靠 3 秒；仍有已接近站点的本次旅客时最多再等 7 秒。满载或已到齐可以结束额外等待；无人实际登车且没有后续载客需求时，取消本次载客任务。混合列车仍有合法货运任务时可以继续出发，没有其他任务才交回空闲调度。

### 自动编组与站内调整

城市按运输需求选择纯客运、纯货运或混合编组，正常运行无需玩家逐节配置。第 3 阶段先启用载客编组，第 4 阶段启用货运车厢及混合编组的贸易用途，第 5 阶段让货运车厢装载实际资源。

车站缺少某类能力时，优先检查归属站内的空闲火车头能否加挂相应车厢；没有合适车辆，或加长后线路与站内轨道无法容纳，才新建另一列。每次只为实际新增的部件扣费，增加车厢不重新购买整列车。

调整仅在归属站内、乘客和货物都已卸下、没有预留座位及执行中的行程时进行；调整完成后一起更新有序车节列表、容量、车长和用途名额。拆下的完好车厢记为本站库存供以后复用，不凭空消失或自动折现，库存车厢随本站保存。

站内库存车厢不提供运营容量，也不占整列车名额；只有实际挂到火车头后才参与派车判断。车站毁坏时，尚未挂接的库存车厢随设施损失，不自动转移到其他站点。

一列混合列车只有一份运行行程和停站顺序。乘客与货物任务附在同一行程上，到站分别上下客、交易或装卸；贸易不得延长已经承诺的客运站序。客位与货位各自预留、各自判断是否满载。

### 调度与接客

车辆状态按下列顺序运行：

`站内空闲 → 领取需求 → 沿轨前往接客站 → 停站候车 → 申请下一段线路 → 行驶 → 到站上下客 → 继续行程 / 新需求 / 返站维修`

没有需求时停在当前许可车站的存车位置；需要回归属站结算或维修时才返站。空驶同样占线，不在始发站重新生成一辆车，也不把远处的车传送过来。

调度先检查需求是否合法，再从同国、可达、未维修的空闲车辆中选择预计最早到接客站的一辆。计算接车时间时考虑当前站点、排队和沿途耗时，不能只比较两点直线距离。

请求在候车期间可以合并同国、同向且不改变已承诺站序的旅客。出站时冻结本次停站顺序；不在运行中不断向后扩展路线。中途站只接受本车尚有空位且下车站已经在剩余站序中的人，其他人等待后续行程。

真正出站的同一轮操作内，重新核对站点与外交、发车间隔、实际乘客、下一段轨道和占用许可。准备阶段检查过冷却不代表已经取得发车权。

寻路接入沿用 `PortalRegistry` 与现有标量快照。铁路服务按国家许可发布耗时与可执行站序，Core 只读取通用的许可数据。后台寻路线程不读取城市、国家或 Unity 对象。

无法派车时显示有原因的等待，并重新比较步行、船舶等出行方式。取消或失败后暂时排除同一条失败连接，直到路况、车辆或许可实际变化，避免人物在同一车站反复提交相同请求。

### 旅客与军队

普通客运先服务有城市归属的文明居民。人物已有其他乘坐关系、正在战斗、受玩家直接控制或原任务不允许中断时，不被车站强行拉去乘车。修士等快速单位仍按自己的步行、飞行等耗时选择，不能强制搭车。

采用同国乘客配同国列车的规则。物理线路可以连接友好城市，但不自动允许不同国家旅客混乘同一请求。

| 情况 | 首期规则 |
| --- | --- |
| 同国车站和领土 | 正常客运、运兵与贸易 |
| 建线双方关系友好且没有战争 | 允许民用列车使用约定线路；途经站也需具有相同许可 |
| 非敌对但不满足既有友好条件 | 不新增跨境铁路，也不默认开放运营许可 |
| 友好关系取消或宣战 | 撤下跨境连接，取消未出发的跨境行程；在途列车先找最近的非敌对许可站疏散并返站 |
| 车站被占领或所属城市改变 | 重新核对本站和途经许可，不能沿用旧行程把人送进敌站 |

跨境许可在选路、分配、登车和每次出站时核对。军队仅在本国许可车站之间运输，首期不因民用友好线路获得穿越外国的运兵权。列车将士兵送到己方铁路终点后，原军令继续指挥陆路行动，不承担敌站登陆。

军队使用实际载客车厢的容量与同一套轨道规则，每个运输批次记录军队和当前命令编号。超过本车座位数时按到站情况分批，默认两节载客车厢为 40 人，不能为了等全军而无限延长停靠。军队成员、指挥和城市归属不因上下车而改变。

到站后核对军令是否仍有效，再从实际下车点继续；撤军、改目标、和平或军队解散时，取消对应待乘批次，在车内者在下一安全站下车。将军不要求与全军在同一车厢，但整个批次的完成进度须可查询。

派车顺序为事故疏散、军令运输、民用客运、普通空驶；贸易在第 4 阶段加入。除事故疏散外，连续完成 3 次优先任务后，应服务最早等待的可执行普通需求，避免长时间战争使居民永远坐不上车。

### 返站与维修

生命低于 80% 时不接新单。已经在车内的旅客先送到最近许可的安全站，再沿合法铁路回归属站维修；低于 25% 或当前位置危险时，优先停车疏散，不继续执行远途。

维修参考原版靠港修复，按恢复量消耗模拟时间，完成后恢复空闲。首期只增加维修时间，不新增燃料与零件消耗。维修中的车占归属名额，但不占站外区间。

归属站被毁或易主时，先取消旧任务并安全下客，再寻找同国、沿轨可达且有名额的新站接管。不得瞬移回站或自动把原国家车辆交给敌国。无站可去时停驶；国家消失后按原版失去国家的语义退出运营。

2026 年 11 月 11 日确认补充：列车连续无法返站达到 5 分钟游戏时间后自爆。停驶、卡轨、外站无合法返站路或失去可接管母站时开始累计；行驶中的车辆按实际轨道进度检查两端能否继续返站。正常长途行驶及有合法返站路的站内排队不因离站时间长而销毁。恢复返站能力后清零，暂停不计时，游戏倍速同步加快计时，保存读档保留已累计的时间。

自爆通过现有毁车入口先解除行程、释放实际乘客与区间占用，再销毁列车。乘客保留原单位，在附近安全地块下车；车上全部资源及未入库贸易收益销毁，不入库、不退款。爆炸仅播放原版小型效果，不附加范围伤害。毁车后释放整列名额，后续补车仍需按原规则支付费用并等待造车间隔。

本车请求的失败不能触发车辆自毁。只有实际伤害、玩家删除等世界事件才走毁车流程；名额调整等主动退役须先下客并清理背包和占线。

### 验收与实现落点

| 场景 | 通过条件 |
| --- | --- |
| 无乘客但两站已经连通 | 资源足够的城市能自动造出首辆客车；没有资金时不免费生成 |
| 一辆车连续完成多次运输 | 车辆编号不变，只有首次建造扣费，行程结束留在世界 |
| 默认两节载客车厢，65 名旅客同时候车 | 首车最多 40 人，剩余者后续运输，没有重复登车 |
| 火车头＋1 节载客车厢＋1 节货运车厢 | 客位为 20、货位为 40，货厢不接客；两类任务共用一份行驶进度 |
| 站内加挂、拆下及读档 | 部件收费正确，有载荷时拒绝调整，车厢顺序、站内库存、容量与车长恢复一致 |
| 车辆远在另一站 | 先沿轨到接客站，接车等待进入估时，不能瞬移 |
| A—B—C 多站与途中追加需求 | 已有站序不被运行中修改，中途上下客遵守空位与终点 |
| 大军运输中改令、阵亡或宣战 | 批次可取消，人数与军队归属正确，已在车内者安全结束乘坐 |
| 站点毁坏、易主、车辆受损 | 原任务停止或改为安全下客；返站遵守路线与名额 |
| 多次读档及高倍率运行 | 车辆计数、容量、发车间隔与占线不重复或漏失 |
| 步行更快或火车当前不可用 | 人物选择合理的其他方式，不在坏站无限请求 |

主要服务放 `Source/Content/Railways/`：车辆建造、任务分配及运营规则分清职责；`TrainTransportSystem` 负责推进已分配行程，现有城市行为入口触发造车检查。不要同时再让列车原版 AI 任务推进同一段运行。

低频造车和选单可复用 `ThrottledSystem`；行驶逐次更新，站点与外交变化使相关索引失效。不要逐帧遍历全世界居民寻找乘客。
