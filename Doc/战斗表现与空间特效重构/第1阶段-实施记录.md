## 这批改动解决什么

将主体几何、运动轨迹与原版的平面绘制拆开，让两种视角读取同一招的状态。第一批使用实际长枪突刺、地刺和剑形、钟形组合法宝检查这条路线。它们已经有清楚的空间来源，无需先做一套万能技能编排器。

| 对象 | 已实现 | 本轮边界 |
|---|---|---|
| 近战武器 | 读取真实装备精灵、实际运动姿态和高度；原版保持现有运动体，三维按像素轮廓挤成薄实体 | 没有重做完整角色骨架、第一人称手臂动作或所有武器模型；握持高度和近景可读性仍需适配 |
| 近战轨迹 | 两种视角读取同一段未投影的运动历史；收窄枪芒与柔光；使用世界时间，暂停不消散 | 三维先使用线段，尚未完全复现原版的扫掠面与枪芒材质 |
| 地刺 | 第 0 变体改为三簇硬边岩刺，按原有阶段长出和收回；每处消散时最多产生五块几何碎屑，全帧最多 64 块 | 其他三个变体保留原有显示，不删除或重排存档中的变体编号 |
| 组合法宝 | 直接读取原始组合几何、材质色、模型大小和部件锚点；钟模型竖轴转到世界高度方向 | 本轮先验证主体与挂点，能力的完整释放、连接和接触反馈仍需接入 |
| 可选三维显示 | 接入本机 Worldfall 0.9.8 场景收集，追加共用模型和轨迹；第一人称近战期间去掉重复静态持物 | 仅针对该包验证，不代表其他版本或全技能已经兼容 |
| 镜头与清理 | 原版远景不再清空三维快照；按完整边界裁剪；世界清理释放几何视图、运动历史及转换缓存 | 后续仍需验证更多地形、身体动作与长期区域能力 |

## 代码落点与维护约定

- `Source/Core/Visuals/SpatialVisualMesh.cs` 保存位置、朝向、大小、逐面颜色和线段；没有施法、命中或独立计时。
- `SpatialNativeMeshView.cs` 负责原版投影，`SpatialSpriteMesh.cs` 负责缓存实际武器的薄实体。
- `Source/Content/Combat/CombatSpatialVisualSystem.cs` 读取已有近战、地刺、法宝状态。主体几何不依赖一次性随机数；暂停、切换视角不会重新生成一次作用。
- `Source/Content/Compatibility/Worldfall/WorldfallVisualBridge.cs` 负责可选接入。核心层不引用 Worldfall 类型或路径。
- 法宝原有外观目录增加可选的空间朝向与底面对齐字段；没有修改世界存档格式，也没有新增需要玩家手动转换的数据。

Worldfall 当前使用内部 `FirstPerson.SceneCollector.Collect` 收集场景，兼容层在其完成后追加本模组资料。第一人称通过 `FirstPerson.Core.Hands.PlaceItem` 避免重复静态持物。由于这不是已确认的稳定外部接口，入口结构变化时停止本次三维接入并报告原因，原版能力继续运行。参考包、反编译产物及素材均未加入仓库。

## 复现方式

使用 [实机脚本说明](../../Scripts/CombatVisualTests/README.md)，在独立测试进程中读取已提交的正式格式验收世界。脚本不会覆盖输入世界。

场景中的法宝通过正式库存与装备入口建立，包含祭炼归属、调度和实际能力资料。录像遇到运行错误或未推进完整时长时直接判为失败。

先检查几何和原版，再在冻结的同一次施放中打开三维外部观察与第一人称。每次记录世界时间、目标生命、剩余斗气；恢复后跟踪真实武器结算入口，检查支付、命中和收尾。性能测量另用暂停中的 64 个实际地刺显示对象，避免将绘制测量冒充完整交战测量。

本批验收记录归档于本机 `artifacts/combat_visuals/验收记录/`，常速与慢放视频位于 `artifacts/combat_visuals/`；原始游戏截图由 DebugToolbox 保存在用户游戏数据目录的 `DebugToolbox/Captures/`。

构建检查通过：`dotnet build Cultiway.csproj -c Debug --no-restore`，0 个错误、12 个既有警告。NML 已重新编译并加载这批源代码。

| 检查 | 结果与范围 |
|---|---|
| 旧地刺变体 | 4 个变体编号与原有帧资料保留，只有第 0 变体启用新主体 |
| 法宝几何与锚点 | 指定剑形、钟形模型均进入实际三维场景；检查握柄底部与钟口锚点，平面转向不改变其高度，钟的竖轴正确 |
| 法宝高度 | 抬高两格，三维高度增加约 1.99999976 格；没有把旧坐标中的高度再加一次 |
| 支付与暂停 | 正式破甲突刺消耗 5 点斗气；暂停 35 帧后世界时间、动画进度、目标生命、斗气与路径数量不变 |
| 视角切换 | 原版、三维外部观察和第一人称读取同一施放；切换期间的时间、目标生命与斗气不变 |

| 第一人称持物 | 原有两只手臂仍显示，离手运动期间不再画重复的静态武器；此项不代表完整握持和身体动作已经验收 |

### 绘制预算

每种情况取 60 个显示帧，记录本模组转换与追加 Worldfall 场景的耗时。它不包含 Worldfall 实际绘制、角色模拟或完整帧时间，也不能据此承诺大战帧率。

| 暂停中的显示负担 | 实际提交模型数（包含原场景样板） | 中位数 | 95% 样本不超过 |
|---|---:|---:|---:|
| 64 个地刺主体 | 71 | 1.52 毫秒 | 1.90 毫秒 |
| 同时消散，保留全部 64 个主体、最多 64 块碎屑 | 135 | 2.78 毫秒 | 3.10 毫秒 |

最初不设总量限制时，64 处地刺会追加 320 块碎屑，实测场景追加中位数约 10.62 毫秒。当前据此限制装饰碎屑数量，地刺主体、动画阶段和伤害结算不受预算影响。后续继续扩展粒子和法术前，还需测完整帧、地表采样与绘制负担。

## 下一步与缺口

1. 补齐这三类样板的完整作用反馈，尤其是法宝能力信号、真实接触和不同结果；当前主体可见不能替代完整招式验收。
2. 补齐第一人称武器握持高度、手部与运动体的绑定，检查近景接触位置和可读性。当前只验证了不重复持物与手臂保留，不能将其称作完整第一人称战斗兼容。
3. 验证薄光束、受击面、贴地边界和半透明；另测坡面、水边、近处遮挡与飞行高度，再确认哪些绘制资料可以共用。
4. 进入第二阶段时优先做无兵器拳掌样板，同时加入持续通道、区域、防御和辅助。它们分别使用身体动作、连续连接、边界及状态表达，不能退回统一光球投射。
5. 按[技能形态清单](第1阶段-技能形态清单.md)逐项扩展到各玩法来源。67 项只统计基础技能实体定义，骑士、法宝、妖兽器官等来源还需按各自能力登记核对。

本批没有引入镜头震动、停顿或慢镜头。普通交战先保证主体、方向与接触清楚，关键交锋的强调放在具体完整招式里实现。
