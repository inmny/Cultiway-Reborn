## 具体说明

### 步骤1：按来源建立全量接入清单

清单每行对应实际能力或明确的一组共用定义，记录稳定编号、作用形式、原有变体、真实执行入口、原版完成度、Worldfall 完成度和剩余缺口。“已迁移”应表示实际能力可用，不能仅表示已经登记一个视觉配置。

| 能力来源 | 接入检查重点 |
|---|---|
| 修炼法术与万法阁蓝图 | 不同元素、轨迹、变体与组合参数保留意义；近身与非投掷形式同样有清单 |
| 法宝主动、被动、御器与剑阵 | 本体运动、能力发射点、命中、回收、耐久或失控分别保留原有逻辑 |
| 骑士与其他近身战技 | 当前真实装备、身体动作、位移会话、武器伤害与反击不重复触发 |
| 符箓、卷轴与施法物品 | 消耗物、持有者、支付者、实际载体与效果来源没有混淆 |
| 元婴、元神、分身与离体技能 | 所有者仍用于归属，表现与空间跟随实际行动载体；本体死亡等规则沿用现有实现 |
| 妖兽器官及组合生灵能力 | 口、角、爪、尾等实际作用部位；器官外观变化后锚点同步更新 |
| 召唤物与独立显化实体 | 出现、攻击、退场各自正确；不能把召唤物的全部能力挂在召唤者身上 |
| 治疗、净化、增益、诅咒 | 实际目标、真实作用事件、状态持续与驱散一致 |
| 部署、阵法、长期领域 | 识别玩法实体与装饰，核对保存恢复、跨区域及卸载行为 |
| 地形、天气、生长等世界能力 | 直接复用已存在的世界视觉入口，效果跟随实际地块修改进度 |

同一技能可有多个形式，不因共用颜色或元素而合并丢失差别。独有形式先补充样板，再接入该组能力。

### 步骤2：完成长期资料与旧资源迁移

维持 [正式存档约定](../可升级世界存档-摘要.md)。既有技能和法宝稳定编号不因重构随意更名；蓝图的旧动画变体需要映射到当前表现，不能直接重排索引。

| 资料类型 | 处理要求 |
|---|---|
| 技能、蓝图、法宝能力和外观资料 | 稳定编号继续有效；新增持久化字段或编号变更时提供相邻版本转换 |
| 旧动画变体 | 逐项保留、映射或正式淘汰；明确新旧对应，不静默落到无关外观 |
| 持续状态、部署和长期实体 | 核对其真实保存约定；恢复后重建显示，不把玩法主体当作一次性粒子删除 |
| 短暂施放与一次性反馈 | 沿用现有保存策略；不自动增加跨读档继续播放的承诺 |
| 绘制句柄、粒子池与临时缓存 | 不入档，进入世界后由当前玩法状态重建 |
| 无法转换的内容 | 保留原档，提示并丢弃受影响部分，其余内容继续加载；不静默改写原档 |

保留确有用途的旧贴图，替换已接入新表现的调用后，再删除无引用资源与过时执行路径。资料转换用于维护旧档，不保留两套长期运行的战斗实现。

验收包含正式格式旧档的实际读取与再保存，以及蓝图导入、物品携带、法宝部署、载体切换后的表现。可沿用既有存档测试工具和样本，新增检查只覆盖这次改变的资料与行为。

### 步骤3：验证实际载体、锚点与清理

覆盖换装、变体切换、法宝组合部件变化、妖兽器官变化、离体与回归、载体死亡、目标失效、世界切换和进入其他世界等事件。

检查可独立继续的弹丸、区域和友军状态不被错误取消；应该结束的未发生攻击、连接线、近战动作与附着粒子及时移除。二维与 Worldfall 的显示缓存分别清理，玩法状态只有一份。

长时间运行后，活动表现数量应回落，而不是持续增长。普通的载体消失应走正常结束流程，不用新增层层异常捕获掩盖状态管理问题。

### 步骤4：验证混战、远近与三维遮挡

| 场景 | 核对内容 |
|---|---|
| 单挑与近身多段交锋 | 动作、接触、招架和反击可辨，正常速度下不会只剩连续闪光 |
| 多修士与多法宝混战 | 主体、来源、危险边界仍可读；装饰先简化，真实结算不减少 |
| 高数量剑阵与持续区域叠加 | 实体与残影不混淆；区域边界、透明层和音效不无限叠加 |
| 原版远景与近景 | 远处不铺满亮斑，近处主体和边缘没有失控放大 |
| Worldfall 第一人称与外部观察 | 近身武器不过度遮挡视线，光束不随视点乱翻，护盾内外和雾层可读 |
| 坡面、水边、空中与不同体型 | 地面、离地高度、身体局部点和模型比例没有重复偏移 |
| 暂停、加速、视角切换与重进世界 | 不重播、不重复扣费或命中，无孤立轨迹、声音或模型 |

使用第一阶段同一机器和场景比较，记录帧耗时、可见表现数量和长期回收情况。只在有新变化、失败或未解决问题时补充检查，不反复重复整套审查。

### 步骤5：整理最终覆盖与兼容说明

公开说明实际支持的 Worldfall 版本、接入方式、未覆盖效果与显示限制。原版完整可用和三维覆盖率分别记录；部分特效只能平面显示时，写清具体范围。

同步更新相关玩法文档、资源清单和正式存档变更说明。若存在需要用户操作的情况，写出具体步骤；正常逐版本升级能够自动完成时，不要求用户重新开档。

## 资源说明

| 资源 | 具体设计与收尾要求 |
|---|---|
| 元素与材质变体 | 保留火、水、雷、冰、土、风等运动和轮廓差别，整理为可复用的样式资料 |
| 近身动作与身体锚点 | 记录人物、妖兽与不同器官可支持的动作和部位；近似作用点单独标注 |
| 法宝模型与部件 | 检查原始几何、材质、发光和锚点完整；二维烘焙结果与三维模型来源一致 |
| 符箓、卷轴与神魂显化 | 仅补充来源独有的施放、交接和退场部件，攻击主体复用对应形态 |
| 小贴图、程序形状与声音 | 清点实际引用和来源；删去完成替换后的无用资源，不分发参考模组内容 |
| 旧整张动画 | 记录继续使用、已映射替换和可删除三类实际结果，不以目录存在作为迁移完成 |

## 验收条件

实际能力清单没有被“普通法术”或“其他技能”掩盖的空白；每项具有明确状态。正式旧档能按约定升级，玩法归属、支付、冷却和作用次数不因换显示而改变。

全量接入完成与三维兼容完成分别依据清单判定。只有声明支持的形式、载体和 Worldfall 版本均通过实际游戏验证后，才将相应目标标为完成。
