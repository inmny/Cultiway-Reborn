## 一、从完整招式出发

目标是让观战者看懂“谁以什么方式发动，力量往哪里去，什么时候接触，产生了什么结果”。强度感主要来自清楚的轮廓、速度变化、方向和接触时刻，不能只靠加亮、放大、堆粒子或震屏。

一招可以组合身体动作、法宝运动、形状变化、粒子、声音和受击反馈。组合中的各部分必须有关系。例如拳上聚力应跟随出拳，震荡从实际接触处展开；不能在角色身旁同时播放几个互不相关的特效，就算完成了组合。

不强制所有招式拥有同样的五段动画。瞬发雷击可以很短，持续喷吐需要可延长的作用过程，护盾需要等待真实受击，召唤物出现后需要自己的行为。

## 三、按作用形式组织，而不是留下一个“普通法术”大类

能力来源回答“谁提供这招”，形式回答“这招如何发生”，元素回答“具有什么性质”。三者可以交叉；法宝也能近战、喷吐、放光束或布阵，妖兽器官也能产生其中多种形式。

下表是设计覆盖清单，不表示每个例子都已有实现。新增作用方式需要单独确认玩法；只替换表现时维持原有命中与作用规则。

| 形式 | 主体与动作 | 内部组合及真实反馈 | 空间要求 |
|---|---|---|---|
| 拳、掌、肘、踢、爪、尾击 | 重心或朝向变化，接触部位沿短距离轨迹运动 | 短蓄势 → 接触动作 → 接触处压缩、火花或震荡 → 回收；隔空掌另按远程攻击处理 | 身体局部位置；没有肢体绑定时明确使用近似位置 |
| 刺、斩、劈、砸 | 当前真实武器决定主体，轨迹区分直刺、横扫和下砸 | 武器先动，轨迹随动；命中、招架和落空分别收尾 | 握持点、武器尖端与边缘；不凭空复制另一把武器 |
| 冲锋、突进、跃击、坠击 | 实际行动载体沿路径移动 | 起步、途中、终点分别表达；经过伤害与落点伤害各随原有结算 | 路径、落点、地面和表现高度分开 |
| 弹丸与离体飞刃 | 火团、针、岩块、冰棱等具有不同轮廓 | 成形 → 飞行变化 → 接触或穿透 → 残留；拖尾不能淹没主体 | 世界位置、朝向和实际路径 |
| 连续光束与瞬时射线 | 起点和终点之间的窄通道 | 起点聚焦、主干、端点、真实命中脉冲；瞬时与持续攻击有区别 | 两端锚点、截断点、宽度和持续时间 |
| 扇面喷吐与扩散流 | 口部、手部或器口向外喷出有厚度的流 | 发射口压缩、前缘推进、内部颗粒、边缘消散；不缩成一颗弹丸 | 锥形或扇形覆盖、方向、有效长度 |
| 连锁、束缚、牵引 | 分段连接目标，或连接两个持续移动的端点 | 连锁按真实跳跃次序亮起；牵引区分绷紧、松弛和断开 | 两端跟随、分段路径；装饰分叉不额外命中 |
| 落雷、陨落物、地刺 | 从高处落下或从地面生长 | 落点预兆、纵向发生、接触爆发、残留碎片；地刺可以沿地面依次突起 | 地表采样、竖向、落点；不改成从施法者飞往目标 |
| 浪潮、移动风暴、毒雾 | 宽前缘、旋转体或体积层向前推进 | 前缘、内部流动、经过反馈和消散相互配合 | 覆盖面、推进方向与边界；雾不能遮住全部角色 |
| 墙、领域、阵法、持续区域 | 墙有厚度，区域有边界，阵法有结构 | 建立、低强度维持、实际作用脉冲、结束；边缘与中心不是同一种光环 | 墙的法向与厚度、区域平面、阵眼和节点 |
| 护盾、招架、反射 | 表面、局部防守动作或拦截实体 | 待机克制；受击处变化，区分吸收、弹开、破裂；反射跟随真实反射事件 | 接触点与表面方向；能力只减伤时不暗示实体拦截 |
| 附着、强化、治疗、净化、诅咒 | 身体、武器或目标上的局部状态 | 施加提示、持续标记、实际生效反馈、移除；敌我和增减益可辨 | 跟随目标或部位；远景可简化，不能全身持续泛白 |
| 召唤、分身、神魂显化 | 出现过程与独立载体 | 入口、成形、交接控制、退场；之后攻击复用相应招式形式 | 所有者与实际载体分离；不能继续挂在本体上 |
| 地形、天气、生长等世界能力 | 地面、植被或天气本身变化 | 引导提示 → 实际变更 → 简短反馈；无修改时不展示成功结果 | 对应真实地块与变化进度 |

## 四、法宝必须有自己的身体和作用部位

法宝共享上述形式，但不能被简化成一个会放技能的光点。主体外观、运动和能力发射位置需要一同表达。

| 法宝示例 | 应当如何组合 | 首先要确认的规则 |
|---|---|---|
| 飞剑、刀刃、针类 | 主体瞄准、刺出或绕行，尖端发力，边缘拖尾，命中后回收或穿过 | 使用实际运动和命中状态，保留回收与失控规则 |
| 印、锤、重器 | 主体抬升、压下，底面接触，再从落点向外震荡 | 砸中、范围震荡和余波是否分别结算 |
| 钟、铃、鼓类 | 主体局部振动，波面逐层传播，目标在真正生效时响应 | 波是装饰、即时范围提示，还是实际传播中的作用体 |
| 扇、幡、旗、阵盘 | 主体展开、挥动或立阵，作用从扇缘、幡面或阵眼发生 | 主体是否移动，区域是否跟随，节点是否可破坏 |
| 镜、珠、葫芦、容器 | 镜面聚焦、珠体蓄积、器口吞吐，目标端反馈与之对应 | 反射、储能、吸取和释放是否已有对应玩法 |

这些是形态覆盖示例，不据此承诺新增所有法宝玩法。没有相应玩法时，不用装饰动画制造已经反射、吞噬或挡住攻击的假象。

三维显示直接使用组合几何中的部件和原始锚点；二维显示允许投影和像素化。当前从烘焙图片反推的锚点偏移不能当作三维局部坐标。

## 五、一招内部如何组合

组合描述的是一次施放中各部分的因果关系，而非元素反应系统或任意技能拼装编辑器。

| 组成 | 负责的内容 | 不承担的内容 |
|---|---|---|
| 原有能力与执行状态 | 支付、冷却、目标、真实移动、命中、持续作用、中断 | 不依赖镜头是否正在绘制 |
| 招式表现编排 | 读取开始、阶段变化、真实接触、结束等状态，协调动作、形状、声音 | 不自行再扣费、造成伤害或延长能力有效期 |
| 共用空间描述 | 主体、路径、表面、锚点、颜色、经过时间、表现随机种子 | 不保存具体绘制对象，不绑定某个镜头 |
| 各视角的绘制适配 | 二维投影、三维模型与粒子、遮挡、远近简化 | 不二次推进技能，不从绘制回调触发结算 |

开始、维持、接触和结束可以使用同一组部件，也可以更换。允许顺序、并行、跟随和根据真实结果分支；先通过具体招式实现必要组合，不预建任意嵌套的通用流程语言。

动作与命中必须共用经过时间或同一个进度来源。已经成立的玩法时点优先；确实需要调整近战命中窗口时，把动作和原有结算一同修改、验证，不能只把画面延后。

举例：贴身掌击可以“收势 → 掌前压缩 → 接触 → 短震荡 → 回收”；持续光束可以“聚焦 → 通道建立 → 端点跟随 → 实际作用脉冲 → 收束”；地刺可以“地面开裂 → 刺体生长 → 真实作用 → 碎屑落下”。三者共享空间部件和反馈方式，执行逻辑各自保留。

### 接触结果与结束原因

命中、闪避、吸收、招架、反射、击破、击杀和落空应能选择不同反馈。接触不必然有伤害；吸收可以有接触闪光，但不能播放已经贯穿目标的终结动画。

死亡、失去载体、换装、失去行动能力、目标失效和自然结束，按各能力原有规则终止或继续。发射后已独立存在的弹丸、已授予友军的状态，不因统一视觉清理而被错误删除；已经取消的未发生攻击，也不能靠残余动画继续命中。

## 六、空间、时间与载体的共同约定

1. 使用“地图平面位置 + 独立高度 + 局部方向与尺寸”描述空间；显示层最终怎么投影，由各自适配处理。方向不能只保存为二维画面的旋转角。
2. 地形高度、角色离地高度、身体局部偏移和镜头投影分别计算，避免原版已经抬高的显示位置又加一次高度。现有 [坐标工具](../../Source/Core/SkillLibV3/Visuals/SkillVisualCoordinates.cs)说明了此类重复偏移问题。
3. 锚点区分所有者、实际行动载体、武器或法宝部件、目标、固定地点和已确定的落点。元神离体、召唤物和器官攻击跟随实际载体；目标失效后是否保留落点由能力决定。
4. 原版角色不保证具有可用的骨骼或拳、掌、口部节点。首轮可按身体尺寸和朝向设置近似作用点，明确其精度；有真实部件数据时再读取对应节点。不得声称已经具备完整肢体动画。
5. 同一施放只推进一次。暂停冻结招式进度，变速沿用游戏时间；多个视角只读取当前状态。镜头切换不重播起手、不重复声音、不再次命中。
6. 装饰随机与战斗随机分开。需要连续观感的路径和粒子使用同一表现种子或共享状态，不能在每个绘制视角里随机重建整招。
7. 当前战斗仍按既有平面规则结算。三维中的上扬、坠落和体积首先是空间表现；是否增加按高度命中，需要独立设计与平衡验证。

原版缺少身体动作时，先用已有角色动作、朝向、真实武器轨迹和接触部位表达招式。若仍无法看清拳脚动作，应将“补充身体动作能力”列为实际缺口，不能堆粒子掩盖。

## 七、效果制作路线与资源说明

主体用可控形状和运动保持稳定；粒子负责流动、破碎和余势；少量小贴图用于材质和局部细节。允许保留合格的序列帧，但不再让一整张动画决定方向、大小、接触位置和所有层次。

| 资源或部件 | 具体设计 | 生产与组合方式 |
|---|---|---|
| 近战与飞行轨迹 | 突刺窄、横扫成面、重击沿接触方向展开；头尾和速度变化明确 | 连续路径生成窄带或扫掠面，读取真实部位位置 |
| 光束主干与喷流 | 光束有主干与薄外层；喷流有发射口、宽前缘和疏散边缘 | 线段、曲线、带厚度的表面与少量粒子组合 |
| 地刺、岩块、冰棱 | 轮廓、硬边和朝向稳定，生长或碎裂沿明确方向 | 简单几何或可控轮廓；二维投影，三维保留体积 |
| 波面、墙和护盾 | 波面传播清楚，墙有厚度；护盾以局部受击变化为主 | 环面、弧面、薄壳或面片，透明度分层 |
| 阵法与地面边界 | 阵眼、节点、连接和边缘可辨，不铺满高亮底色 | 可组合线形与少量符号贴片；需要符合地形 |
| 火花、碎屑、尘、烟、水滴 | 方向、速度、寿命和重力有区别，尺寸与游戏单位相称 | 共用小粒子形状，按材质和作用方式配置 |
| 接触闪光与裂纹 | 集中在接触位置，短而清楚，裂纹不冒充永久地形修改 | 少量确定绘制的小贴图或程序形状 |
| 附体与辅助标记 | 贴近相应部位，持续期低亮；施加与移除有区别 | 简单轮廓、局部粒子与现有状态显示组合 |
| 法宝主体 | 复用组合模型的面、材质、发光部位和锚点 | 同一外观数据分别生成二维和三维显示 |
| 声音 | 起手、运动、接触和结束各有职责，群体作用不重复叠响 | 先核对并复用原版合适声音；缺少时单独列出制作需求 |

制作小贴图前先核对 .GameSource/Assets 的原版资源与命名。尺寸和过滤方式以实际单位大小、近景和远景试样确定，不先批量铺设大分辨率动画。

火、雷、水、土、风等不能只有颜色差别：火有上升与燃尽，雷有短促折线和瞬间主干，水有连续流向与滴落，土有块状重量，风以轮廓和沿流线运动表达。细节密度随距离降低，主体差别仍保留。

音效和局部受击动作先于全局镜头效果。停顿、震动与慢镜头只在可见的关键交锋中评估；设置强度和间隔，并验证不会干扰 Worldfall 操控。既有骑士“自动战斗不震屏”等更严格限制继续有效，改变前单独讨论。

## 八、Worldfall 兼容方案与未决风险

参考包版本 0.9.8 使用自己的场景收集和绘制流程，包含自己的粒子与绘制资料类型。已检查的路径会转换部分原版特效，但尚未证实能自动收集本模组创建的任意 Unity 粒子或模型。

拟采用“共享招式空间状态，分别绘制”的方式。二维侧保持原版画风，三维侧消费模型、路径、表面和粒子状态；不把整个招式压成始终朝向镜头的一张图片。

| 项目 | 已知情况 | 验证与处理 |
|---|---|---|
| 接入入口 | 0.9.8 通过内部场景收集补丁接入，尚未发现稳定的外部注册入口 | 首批样板已实机接入；其他版本需重新核对，不能视为稳定插件约定 |
| 地面与高度 | Worldfall 使用自己的地表高度采样 | 建立唯一坐标转换，验证坡面、水边、飞行单位和不同大小单位 |
| 实体模型与锚点 | 我们有法宝原始几何，当前显示主要为烘焙精灵 | 验证面朝向、尺寸、材质、遮挡和锚点一起旋转 |
| 光束、薄壳与半透明 | 三维中有交叠、背面和深度顺序问题 | 实测光束、护盾、雾和贴地阵法，不能只以飞剑可见作为通过 |
| 近身动作 | 原版角色动作与三维显示之间尚无完整绑定验证 | 第一人称及第三人称检查武器、手部近似点和接触位置 |
| 视角生命周期 | 切换、退出或暂不可用时需要回收视图 | 技能继续按原有规则运行；清理绘制对象，不清理玩法对象 |

优先使用作者提供的扩展方式；若当前包无此入口，再评估小范围、注明适用版本的接入补丁，或与作者讨论扩展接口。不得把尚未验证的接入视为完成，也不先将整个框架绑定到某个内部类。

接入不可用时保留原版能力和画面，并报告具体兼容状态。真正的三维形态尚未完成时应明确标为未覆盖，不能因为显示一张平面图就宣称全兼容。适配代码独立放在内容层，核心技能代码不直接引用 Worldfall；不分发参考包的代码、素材或反编译产物。

## 十、存档与验收原则

保留现有能力、蓝图和法宝的稳定编号。[技能蓝图](../../Source/Core/SkillLibV3/Blueprints/SkillBlueprint.cs)已经保存动画变体编号，不能通过删除或重排变体让旧技能指向另一种表现。新增表现编号或合并旧变体时提供明确映射，必要时通过正式逐版本转换处理；不凭猜测匹配。

持久化保存技能、法宝、长期状态等玩法资料；绘制对象、粒子缓存、镜头资料和临时锚点缓存不入档。短暂施放是否跨读档延续，沿用当前存档约定并逐项核对，不因视觉重构擅自增加恢复承诺；长期法宝部署、召唤物、状态和区域则必须逐项分类，不能统一当作特效清空。

验收以真实游戏为准：正常速度能看懂动作和结果，慢放时接触与作用对应；切换视角不重播、不重复结算；多人交战仍能分清主体与危险边界。性能不足时先减烟尘、装饰分叉和远处细节，保持主体、作用位置和重要接触反馈；具体数量上限由第一阶段测量后确定。

### 待讨论的推进调整

上一批主要验证了空间显示与同步。下一批需要用完整招式检验轮廓、速度变化、方向和接触反馈是否足够，再决定还缺哪些共用能力。

建议使用模型、曲面、少量图案贴图与粒子共同组合：实体和明确意象承担主体轮廓；曲面与轨迹表达刀光、掌缘和连续通道；粒子补充碎屑、火星、烟尘及消散。钟体、符纹、声波和局部受击变化应分别可控，最终仍共同服从实际招式进度与结算。

法宝按用途展开动作：钟形法宝可振动并泛出声波，印类可下压并形成镇压范围，葫芦可从口部喷吐或吸纳，幡旗可展开持续作用区域。以上是表现提案，不表示这些新能力已经存在。拳掌则需要身体准备、出手与真实接触；远处巨掌或法相属于另一种招式形式。

框架继续复用施法序列、法宝运行状态和作用结果，进一步核对四项共用能力：同一招的共同进度、身体与法宝挂点、多个表现部件之间的跟随关系，以及真实结算后的局部反馈。当前专门采样地刺、武器和法宝的验证代码需要由完整样板推动整理，不能长期在同一个方法中不断加入新技能分支。

建议讨论下一批的三个完整设计：近身掌击、定点雷法、钟形护体。先明确每招的主体、运动、作用与收尾，再继续实现；它们可分别检验近身动作、非投掷式法术和非飞剑形式。此处尚未替换原有阶段计划，也未作为新增玩法定案。
