# 功能规划设计约束

## 规划过程

需要与用户进行充分讨论，包括设计方案的各种细节

## 规划产物

将文档输出到 `Doc` 文件夹下，并简要回复用户。

对于一个比较复杂的系统或者功能（尤其是需要分多个阶段实现的规划），在`Doc`文件夹下面先创建一个`<NAME>-摘要.md`作为简要的介绍和总览说明，具体的各个阶段的具体实现内容分别作为一个文件放在`Doc/<NAME>`文件夹下面。`<NAME>`的主体语言应该是中文。

每个阶段的具体实现内容应该以大致这样的形式组织：

```markdown
# 第x阶段-<NAME>

## TODO

- [ ] 步骤1, [具体说明](步骤1具体说明的目标章节)
- [ ] 步骤2, [具体说明](步骤2具体说明的目标章节)

## 具体说明

### 步骤1

### 步骤2

## 资源说明

表格
```

## 规划要求

- 如果涉及图像、动画等资源，应当单独作为一个章节，以表格形式分别列出每份资源的具体设计
