# 妖兽外观制作

运行：

```bash
~/.venvs/cultiway/bin/python -m Scripts.organ_gen --export --preview --check
```

`Content/CreatureVisuals/templates/` 保存字符矩阵源稿；使用 `Scripts/pixel_text.py` 编辑和预览。矩阵中的角、羽翼、膜翼、毛尾和甲壳具有各自的轮廓与色板。三尾和六尾的完整单尾源稿位于 `templates/parts/tails3/`、`templates/parts/tails6/`，每条尾都有未被其他尾裁掉的轮廓；整尾冠由这些同一部件合成。旧整张三尾、六尾源稿已移除，避免正常显示和动作分别使用两套形状。

`pipeline.py` 从原版 `.GameSource/Assets` 读取成体走路、游泳及龙的飞行帧，按真实身体轮廓找到头、背和臀部；每份部件按整数像素对齐后落盘。原版不具备适合位置的物种不画对应部件，例如蛇不直接长出一套兽尾或龟壳。

生成结果：

| 产物 | 用途 |
| --- | --- |
| `GameResources/cultiway/yao/appearance/<部件>/<物种>/<动作>.png` | 原版朝向的逐帧部件；四周留白让根点与主体像素对齐 |
| `Content/CreatureVisuals/catalog.json` | 游戏和预览共同读取的位置竞争、遮挡、显示优先顺序与帧尺寸 |
| `artifacts/creature_appearance/combinations.png` | 组合、等级与走路入水对照 |

运行时由 `CreatureAppearanceService` 选择最多三处可见变化，按“背后部件、身体、体表、正面部件”合成一张图片，再交回原版绘制。相同可见部件和原版主体帧共用图片，缓存上限为 2048 张。不同但看起来相同的身体不会重复创建图片；不显示的器官仍参与属性、技能和被动效果。

没有实际制作帧的身体、幼体和特殊皮肤保持原版显示。不会使用静态挂点、邻近动作或另一个物种的图片硬套。

新增器官外观时：先制作字符矩阵，再登记本文件旁 `pipeline.py` 中的位置、优先顺序、遮挡和适用身体；重新导出并查看画廊。游戏通过外观目录加载资源，预览不再维护一份 C# 注册数据的镜像。

雷角还导出逐帧 `Points.mount` 安装点和 `Points.cast` 出口。坐标相对未加留白的原身体图片左下角，单位为像素；像素中心带半格。模板中的出口在 `OUTLETS` 明确声明，缩小后选择离该点最近的实际角像素，随后与图片一起翻转。`--check` 直接核对落盘图片，确保出口仍落在真实角像素中。

器官等级用 `CastingLayerId` 引用实际外观层。肉身出口解析读取当前帧、枢轴、实际缩放、翻转和倾斜；延迟序列在每次真正释放时解析。没有该帧、身体尺寸不符或外观取舍未采用雷角时，不引用未显示的角尖，能力仍可从原有肉身默认位置施放；不因显示名额取消器官能力。未声明制作出口的其他器官仍保留原来的部位近似，不能算作已经完成挂点适配。

原版及三维器官的正式释放使用 [雷角复验](../SpellDemos/verify_organ_ability.py) 和 [妖兽战技复验](../SpellDemos/verify_beast_attacks.py)。器官模型按同一挂点资料核对实际接合。

独立控制使用目录中的 `FramesByRig.<身体>.<帧>.Parts`：每个稳定部件保留自己的图片、原身体尺寸和制作根点。单尾、三尾、六尾分别提供 `tail.0` 至实际尾数；两类翼提供 `wing.left`、`wing.right`。原版侧面站姿的两侧翼投影重合，但独立动作使用各自姿态，不能把一侧翼的控制套到整对翼上。正常合成和单独动作都读取这些实际部件，不从已遮挡的合成图切出残缺尾片。

`--export` 同时发布完整合成图和全部分件，`--check` 检查两者的实际文件、尺寸及制作根点。整层图仍供现有预览读取，游戏按分件合成并只排除正在独立动作的部分。三维使用既有网格的具名控制，`node Scripts/CombatModelStudio/publish_organ_controls.mjs` 从同一制作源更新命名绑定资料；只更新该资料时复用已有三平台网格与材质，几何发生改变仍须走完整资源构建。
