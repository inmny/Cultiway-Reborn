# 正式格式第一版样板

这些是 2026-10-20 用实际原版保存入口生成、退出游戏后重新读取通过的独立测试世界。统一格式及本轮登记的数据部分均为第 1 版，不是从预览旧档迁来的资料。

- `world-format-1/map.wbox`：128×128 主地图、45 名人物、186 个世界对象、2 个小世界；包含动态功法、丹方、书册、普通法术、来源技能冷却、法宝与克隆、宗门财产及师徒、半成品与材料、持续状态及元神。`actors.json` 保留五个样板人物和对应生命、魔力、体力、饱食。
- `train-format-1/map.wbox`：真实车站、铁轨、正在行驶的列车及一名车上乘客；`actors.json` 保留人物、车站编号和行驶距离。

提高数据版本时保留这些文件，在独立验收进程中把对应目录交给原版 `World.world.save_manager.loadWorld`，检查转换报告、实际数值和再次保存。转换会按正常规则备份原样板，故建议先复制到临时验收目录。不要用新版重新生成的世界覆盖旧版样板。后续正式格式也按版本保留新的样板。

`runtime/verify_full_world_restart.script` 与 `runtime/verify_transport_world_restart.script` 展示本轮的读取及检查过程，默认读取 `artifacts/full_world_save/` 下本轮生成的样本。未来转换需要比较当前玩法的实际结果；格式结构合法改变时，不要求新版输出和旧版原始文本相同。

## 资源通道历史样板

`resource-channels-v1-materials-v4.zip`保留游戏进程3444272实际保存的资源通道世界及当时的核对记录：构造区段第1版、世界材料第4版。包含真元、法力、体力、斗气和妖力使用者、自定义动态报价，以及已支付六点、尚未收束的独立材料。压缩包中的`save/`是完整原版存档，`restart-expected.json`是原进程的核对记录。

`Scripts/SpellDemos/verify_multiresource.py prepare`将它解到独立结果目录再加载，通过完整相邻转换链验证旧本金、已学关系和真实收束。保留此历史文件，避免依赖先前开发会话留下的临时存档；新的部分收束和多资源格式仍由验证脚本另行生成。

12.14 的 `Scripts/SpellDemos/verify_archive_resource_reload.py` 用同一历史世界复验更新资源后的重新编译、失败回退与正式读回。实际资源修改只发生在独立临时副本中。

## 技能升级复验样板（12.12）

本项固定三份已在原版实机使用的世界。复用 `world-format-1`，另保留 12.03 的当前档和 12.04 的无效轨迹档。各自的原文件校验值和原核对对象存入 `skill-archive-expectations.json`，坏档需包含原普通法术、单条已失效轨迹及仍可用的新构造。

限定复验核对旧档经相邻转换写成当前物件格式，当前档完整读回原人物掌握的不同构造，坏档报告局部失败且仍保存其他内容。三个样板均只读副本，写回另一目录。需要备份时，其世界文件也须与原读入文件字节一致。更广的世界反复切换归 12.13。

在独立游戏中运行 `dev.py exec --timeout 100 -- python3 Scripts/SpellDemos/verify_skill_archive_fixtures.py --case legacy`。使用 `--case current` 和 `--case partial` 分别复验另两份样板。输出包含另存的正式文件、实际恢复结果和需要时生成的原档备份路径。

同一独立原版游戏顺序读入三份样板。旧档的 128 份法术、实际轨迹和 1 号人物的学习顺序保持，世界物件升为第 3 版。当前档直接恢复两名修士各自的完整成品与已完成派生。坏档报告原对象及其引用两处失效，有效学习仍在，另存后只移除坏记录及其引用。原样板、输入副本和需要时保留的原档备份字节一致。结果索引在 `~/.local/state/cultiway-dev/evidence/skill-archive-fixtures-1212/delivery.json`。
