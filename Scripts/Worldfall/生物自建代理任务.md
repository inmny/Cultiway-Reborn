# 生物独立建模任务（2026-10-19）

用户要求完成修仙生物绘制，沿用最近建筑的Blender自行构形流程，不调用Tripo、Trellis或图片生成平台。原图主要特点和真实结构优先，可适当解构补全；不能把基础骨架稍微加几块装饰冒充独立造型。同一物体有旧参考、真实初稿或未完候选时，先查看并保留，按最新方式完成自己的模型。每物体独立代理，同时最多三个，禁止再派子代理。

2026-10-19追加要求：原19类已有正式生物也全部按当前风格重绘，全量134类。用户确认的骑乘/支撑结构优先于Seed类型和旧候选：不能凭Seed是双足就判定为步兵，须分清骑手与坐骑。树人须与对应普通树种的现有模型在树皮、颜色、树冠和叶形上保持一致，便于混入树林；此类可查看本树种的普通树模型作为明确授权的风格参照，不借用其他生物造型代码。三维文件本身无法还原的原生动作须如实记录。

## 范围与边界

只修改任务指定的 `Art/Worldfall/<ID>/native-unit-v1/`。先查看自己的 `GameResources/actors/species/other/Cultiway/<名称>/main/` 或任务指定原图、相关注册片段、`Art/Worldfall/Seeds/<ID>.json`；不得读其他物体的造型代码。原版 `.GameSource/Assets` 在本机不存在，不能猜原版资源或复制Worldfall几何。只可读取共用导出检查工具。不要改共享脚本、生产、总清单、C#或游戏；根代理统一检查发布。

## 造型与动作

- Blender 4.4 CLI，CPU检查，线程最多2；启动使用 `--background --factory-startup -t 2 --python <自己的build.py>`。工具在 `D:/Program Files/Blender Foundation/Blender 4.4/blender.exe`。
- 原图逐张看，静态正面及行走、游泳首尾帧都检查，先写 `original-inspection.json`：真实体形、部件、颜色与不可见补全。PNG必须实际查看，不能只按资产名猜。
- 坐标X左右、Y前后、Z向上，正面-Y；地面脚底0，灵体记录悬浮。尺度依据自己Seed的height和实际原图；三档同尺度同朝向，不按建筑宽1的约定重缩放。
- 保留自己Seed的全部原部件名字、顺序、父子及转轴；必要的关节位置调整要有理由，三档同步。基础几何全部重新构形；保持身体、肩、髋、头、尾在运动时衔接，肩髋连接留合理重叠。额外细节并到真正所属部件。
- 人物动作可参考人类，但通用双足骨架当前没有独立肘膝，不能在说明里称新增关节已获支持。四足、鸟、翼龙、蛇、八足等用自身骨架。`wing_r`对双足生物是右手臂，不能挂不相关部位。可更换原生武器不焊进身体，原图特有且不是装备的器官可保留。
- 原图、比例、脸、手足、关节和前后厚度必须真实完成，不用一排盒子、一个球或平面拉厚概括复杂物体。人形脸和有机体适当使用真实平滑曲面；最终法线必须写入运行数据Nrm及实际GLB，不能只平滑Blender预览。
- 面数参照任务预算和Worldfall已统计的相关模型，近中远分别做，不把同一份复制三档。特征先于小饰件，不自动抬预算。
- 薄翼膜和薄片必须处理上下两面的实际几何，不能靠预览默认双面材质遮掩开孔。共享检查的正侧背、同机位三档与全部动作图现均隐藏背面，并从实际GLB另渲染三档`preview/<档>/underside_culled.png`；必须实际看过全部视图及三张仰视，文件只用于检查，不改变GLB或运行网格。`reopen-check.json`中的`DefaultViewsBackfaceCulled`应为true。
- 原槽前缀保留，最多64槽。按原图取色，额外细节新增具名色槽；衣服国家色与皮肤分开。新自建模型由`finish`标记`cultiway_native_unit=1`，接入层保留整套绘制原色，避免泳姿水色等被误分配；旧的未标记模型仍会按`fur/fur_light/dark/accent/horn/wing/spots`取色。新增槽与真实材质用途单列。骨、肉、甲壳、晶体不得误用砖石4、木板3；自然岩石用Rock14，Stone4只用于确有砖砌结构的部位。树皮2、真实叶1、金属10按真实材料。

## 导出与交付

根代理已提供 `Scripts/Worldfall/unit_model_tools.py` 共用的可编辑导出、GLB、新进程检查和动作回放。使用 `blender_worldfall.Asset` 准备本物体的独立几何；共享工具不含任何物体造型。

现已可用：`from unit_model_tools import finish`，`finish(asset,HERE,{'near':预算,'middle':预算,'far':预算},notes,assumptions=[...])`。原图路径不在`other/Cultiway/<名称>/`时，必须传`sources=[真实Path列表]`（植物是`other/plant`、鼠人是`other/Skaven/<名称>`）。导出后用打包的`C:/Users/DELL/.cache/codex-runtimes/codex-primary-runtime/dependencies/native/powershell/pwsh.exe -NoProfile -File Scripts/Worldfall/export_unit_poses.ps1 -Folder Art/Worldfall/<ID>/native-unit-v1`取得实际骨架数据，再用新Blender `-b --factory-startup -t 2 -P Scripts/Worldfall/unit_model_tools.py -- check Art/Worldfall/<ID>/native-unit-v1`检查。实际GLB文件的浮点法线逐条与运行Nrm严格匹配，Blender导入时的内部法线量化误差另报；不为通过阈值随意改形。工具统一CPU两线程，不必写重复的渲染和导出工具。最多进行有具体可见缺陷依据的局部修正，避免反复微饰打磨。

原种子类型有误时，以实际原图和注册为准，先将证据和使用原生已支持动作的调整方案发给根代理。例如纳垢灵有落地短腿，不应继续沿用误分的Ghost；保留原部件前缀，追加原生四肢，并明确`finish(...,added_native_parts=['wing_l','wing_r','leg_l','leg_r'])`。检查仍严格保留原名/顺序/父子及槽前缀，并只准许显式列出的原生支持四肢；三档类型、关节、理由写`rig-adjustments.json`，原Seed文件保持不变。

堡垒机器人原图有三个落地构件，根代理已核对实际`CreatureRig`支持`leg_1`的侧转与小幅抬动，可在该物体明确追加`leg_l/leg_r/leg_1`，让中央支撑有自己的原生动作。检查白名单已加入`leg_1`；不能以此猜其他物体也有第三腿。

同时有双臂和背翼的妖精，可保留原`wing_l/r`双臂、明确追加`wing_l2/r2`独立背翼，并设置`flap=1;cultiway_back_wings=1`。此标记让接入层单独驱动背翼，双臂保持原生持物姿态；现有装备入口仍使用右臂。三档同类型和标记，姿态必须在根代理更新程序集后重新导出，不把背翼合进静态身体或混成持物臂。

必须保存 `build.py`、`model.blend`、`models.candidate.json`、三个最终GLB、原图判断和来源哈希、面数预算及限制。全部输出显式指向自己的native-unit-v1，禁止调用Asset.export默认生产路径。三个模型的全部部件都存在，不清空重要部位。

完成候选后，用常规Python运行`Scripts/Worldfall/audit_unit_winding.py --asset <ID>`检查本物体封闭片段的有向体积和相邻边朝向。负体积或相邻面反向是待检查处，须结合本物体的实际剔背图和源几何判断；不要自动翻转所有负数，真实内部空腔可有相反朝向。位置/法线与GLB匹配不能证明两份几何没有共同的朝内错误。实际核查并修正错误，回执列明检查文件。

导出之后用新的Blender进程重开可编辑文件并实际导入全部GLB，核对逐三角位置/绕序/材质槽、法线、总色槽、边界、动作部件与转轴。预览来自最终实导，包含正侧背、俯视、近中远同机位、静止/迈步/转向及原图游泳能力适用的离线姿态。离线回放不算实际游戏行为；悬浮、飞行、游泳按本物体分别说明。

实际查看导出后的图，再交付。回执 `receipt.json` 写candidate_sha256、triangle_counts、budget、source_glbs、editable_sources、inspection_files（均在本资产内，明确相对目录），以及限制和 `game_test=pending_user_manual`。原图就是本轮来源；没有独立高清参考/平台初稿就直说，不能虚构四阶段。

东人与鬼族为真正人形，保留各自Seed的普通男、普通女、男战士、女战士共12份近中远模型，不能只交3份。两者使用实际`PersonRig`与原16部件，含独立肘膝；共享导姿态入口会按`Humanoid=true`自动调用该骨架，不能套通用CreatureRig。原生允许空Walker用于离线回放，当前未模拟落脚锁定；摆臂检查也不能称为装备攻击通过。共享检查按base/fem/warrior/warrior_fem分别保存全部图与动作，不再覆盖同距离的其他外观。原图来源明确传入自己的civs目录；衣服、肤色、头发与国家色原槽和Flags保留，不能把人物配色当成固定怪物原色。种子12份的接口已实调72姿态，实际新网格仍须各自重开实导与看图。

完成后回复根代理：SHA、面数、文件、实际看过的图、动作及形体限制。不要发布生产或自行扩大到下一个物体。根代理会统一查看、发布和更新总览。
