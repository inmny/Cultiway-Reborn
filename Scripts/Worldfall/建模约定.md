- 独立目录：`Art/Worldfall/<资产ID>/`，写 `build.py`、可编辑的 `model.blend`、`validation.json` 和 `preview.png`。
- 编辑数据：`Content/Worldfall/Models/<资产ID>/models.json`；游戏运行资源为同目录的 `models.bin`。正式 `Asset.export()` 会同时更新两者；其他发布脚本复制或修改 JSON 后，运行 `python Scripts/Worldfall/compile_model_files.py`（可加 `--asset <资产ID>`）。打包会检查二者一致，并只包含运行文件。实验候选不参与转换。
- 工具：`D:\Program Files\Blender Foundation\Blender 4.4\blender.exe`，命令 `--background --factory-startup --python <build.py>`。通过普通命令受阻时使用需要审批的命令调用。
- 使用 `Scripts/Worldfall/blender_worldfall.py` 的 `Asset` 类读取本物体的动作部件、轴、材质槽和导出约定。新模型几何从本物体的真实 Trellis 初稿分部件适配，保留轮廓及识别特征；基础部件提供运行约定，保形减面流程不能用基础几何整体替换初稿。
- 尽量先用 `rg --files GameResources` 查本物体的原图。原版资源 `.GameSource/Assets` 在本机不存在时，记录这一点即可；不要下载或分发 Worldfall 的源码、模型和程序集。
- 坐标 X 横向、Y 前后、Z 向上；正面 -Y；单位脚底 Z=0，灵体可以保留明确的悬浮间距。建筑主体台基 X=[-.5,.5]，深度 `Depth/Width`，房屋入口 -Y；屋檐可以伸出台基。
- 保留原始材质槽顺序、部件名称、父子关系和转动轴。人物保留长袍、手臂和双腿骨架，异兽使用自己的身体骨架。扩展几何应并入合理的已有动作部件；辅助静态部件必须挂到正确父部件。
- 用户允许人物动作参考原版人类：双足角色参考待机、反相迈步、对向摆臂、转向与游泳的姿态关系，按各自真实肩髋和脚位置调整。原生人形骨架有独立肘膝，通用双足八部件骨架没有；保留实际使用的部件和动作轴，不把查看锚点写成已支持独立肘膝。四足、鸟类、树形与悬浮灵体按各自结构适配，游戏动作效果留到统一测试。
- 先核对原生隐藏部件规则，必要的帽、连续衣面和主体不能挂到会被皮肤开关隐藏的毛发部件。隐藏位按当前部件数组下标解释；东人/诡的 16 部件顺序里 `Hidden=80` 隐藏短发和胡须，不隐藏下摆。不要仅凭数字猜缺口原因，必须结合实际截图与部件几何。
- 动作回放使用模型全局 `Pivot` 和 `PartRotation` 的列矩阵：局部变换为 `A=R*scale`、`t=p-A*p+offset`，依次乘父部件，再乘实例的朝向与尺度。静止帧可能有原生呼吸、倾身姿态；真实游戏动作记录优先于自行给 Blender 骨骼设角度。
- 材质类别使用 Worldfall 1.0.0 的 `MeshKind` 常量：纯色 `Plain=0`、树叶 `Leaves=1`、树皮 `Bark=2`、木材 `Wood=3`、建筑石材 `Stone=4`、瓦顶 `Roof=5`、布料 `Cloth=7`、皮肤 `Skin=8`、头发 `Hair=9`、金属 `Metal=10`、自然石 `Rock=14`。不要与地面 `Surface` 的编号混用。国家色区域由 `kingdom_slots` 决定，与材质类别分别检查。类别还会让游戏着色器添加纹理：2026-10-14用户截图确认珊瑚误用 `Stone=4` 后出现砌砖纹，离线Blender不会复现这层效果。本批自建植被默认使用 `Plain=0`，珊瑚、骨骼、整块碑体、蜡体不能按名称误选建筑砖石或木板纹。已有真实木构和砖石建筑按其用途保留相应类别。修正错误类别时保持槽顺序、颜色和Flags，记录字段变更及游戏复测待办。
- 导出法线必须为有限数且长度接近 1，不能包含零向量。薄布和头发的正反面相反时，不能把相反法线平均成零。保留真实面方向，分开相反面的平滑组；只补无效法线时须核对顶点、面、颜色、UV、动作轴均未改变。东人已在真实游戏的显卡渲染中出现过零法线黑块，CPU 预览通过仍需要检查导出法线。
- 每个模型总颜色槽数最多 64，每面槽号为 0–63，包括原槽前缀。Worldfall 1.0.0.0 的显卡绘制只建立前 64 项，并把超出槽号截为 63；2026-10-11 已实测发现错误分色。真实 PNG 的附加色按剩余槽预算量化，各材质类别分别保留。CPU 预览和 byte 的 256 项容量都不能证明游戏允许更多槽；发布前检查三档及状态的总槽数与逐面槽号，保存后重开实导。白虎修正槽数后仍有白毛过暗，须另外按游戏光照调整本物体材质，不能把槽数通过等同于最终外观通过。
- 真实原图取色与适合游戏光照的艺术配色调整分别记录。带阴影的生成 PNG 直接再受游戏光照，可能压暗白色表面；调整须对照原图、参考图、实际 PNG 和游戏证据，保留原 UV/PNG，记录源 RGB 到调整 RGB 的关系。禁止把调整后的 RGB 宣称为未经处理的 PNG 字节，也不能用全体发光或改游戏照明掩盖材质问题。
- Blender 先写面槽号 `material_index` 和平滑标记 `use_smooth`，再创建逐面原色、艺术色等自定义属性；这两项可能延迟创建内置面属性，也会使旧句柄失效。全部属性创建完成后重新按名称取句柄再写值。保存后重开须分别核对原 RGB、艺术 RGB 与真实 UV，不能只检查运行资源散列；读取隐藏中远档的世界矩阵前，显式显示对象并更新场景，避免暂时读到单位矩阵。
- 每个资产至少近景、中景、远景三个版本。重要轮廓需要三档保留，细碎装饰只放近景。施工和废墟不增添完好的装饰；保留状态名字中的 `@`、`~`。
- 共享导出类会检查三角面、材质槽、父子顺序，并生成各版本统计。完成前实际执行 Blender、生成导出资源与可视预览，查看自己的一张预览。
- 原贴图包含几种肤色、衣色或城市配色时，网格保留识别特征，颜色仍允许 Worldfall 按当前皮肤取色。

最小脚本入口：

下面是生产导出示例。`Asset.export()` 默认写入 `Content/Worldfall/Models/<资产ID>/models.json`；实验候选阶段指定 `output_path='Art/Worldfall/<资产ID>/shape-preserving-v<版本>/models.candidate.json'`。显式候选路径也会让 `model.blend`、`validation.json` 和后续 `preview()` 保存到候选目录，不替换旧来源或生产资源。需要 `candidate-v<版本>.blend` 等检查包文件名时，再在本物体脚本中显式保存。

```python
import sys
from pathlib import Path
ROOT=Path(__file__).resolve().parents[3]
sys.path.insert(0,str(ROOT/'Scripts/Worldfall'))
from blender_worldfall import Asset
asset=Asset('Cultiway.资产ID')
# 在 Blender 中按物体特征建模；可用 asset.box/tube/ellipsoid/surface/transform_part。
asset.export('说明本物体的具体建模改进')
asset.preview()
```

`box(part, center, half, slot, parent=None, pivot=None, levels=('near','middle'), variants=True)` 等函数支持并入已有动作部件。`ellipsoid` 支持 `radii/sides/rings`；`tube` 支持 `start/end/radius/tip_radius/sides`；`surface` 接收顶点列表和面列表。对新增部件，明确父部件；对已有部件，会沿用其动作轴。`set_color` 只改自有槽的缺省颜色，不替代游戏内皮肤颜色。使用这些函数后调用 export 和 preview。
## 先参考图，再由 Trellis 生成并用 Blender 适配

- 每个物体分配一个独立子代理，同一物体的修正继续交回原代理。每批最多三个运行中的子代理，子代理不再派生子代理。主代理或本物体代理先使用内置 imagegen 按原贴图生成参考图，实际查看图片后再用 Trellis 生成，最后用 Blender 适配。
- 参考文件放在本物体的 `reference/` 目录：`turnaround-v1.png`、`prompt-v1.txt` 和 `reference-v1.json`。先用查看图片的工具实际看图，然后建模；不能只读提示词或凭模型名称猜测外观。
- 对照参考图的大形、比例、颜色分区和识别特征。参考图三个视角局部细节不一致时，以正面、原贴图和可实现的同一套几何为准。
- 参考图是设计依据。游戏模型仍需保留既有动作轴、材质取色、实际占地、近中远版本和建筑状态；这些运行约定优先于参考图中透视或光效。
- 已有第一版的物体也要按新参考图修整。检查记录写明参考图路径、实际调整的形体和仍有限制的部分，不能只增加“已参考”的文字。
- 本机 Trellis 2 单图入口使用 `reference/trellis-input-v1.png`，透明背景、一个完整物体。清晰主图先保持原图视角；四分之三输入从同一固定几何准备。三视图作为检查依据另存，不能拼接后直接送入当前单图入口。官方 TRELLIS 1 的实验多图能力需使用独立图片，与当前运行器区分。人物性别和服装分别用自己的单体输入图，不能把同一份男性网格算作四种生成结果。
- 用 `Scripts/Worldfall/trellis.ps1 -Mode Generate -AssetId <资产ID>` 实际生成。脚本按显卡任务锁排队；生成期间关闭测试游戏，Blender 预览使用不会挤占显存的方式。用法见 [Trellis使用](Trellis使用.md)。
- 保留原始 GLB、UV、PNG 贴图和导入后的 Blender 源。游戏格式按真实 UV 提取材质颜色；原材质槽前缀不能改变，细节颜色可以追加固定槽。先检查原始网格，再按实际部件和占地拟合，不用未经检查的固定切割参数冒充完成适配。
- 候选模型实际导出、预览和尺寸检查通过后才替换生产资源。游戏内待机、行走、转向、游泳、国家色、近远档和建筑状态另行实测。保留旧模型的有效变体，直到该变体真实生成、适配成功。
- 发布回执统一使用 `source_glbs` 和 `editable_sources`，其路径相对 `Art/Worldfall/<资产ID>/`；`production_resource` 明确相对仓库根目录。必须保存并核对当前 `production_sha256`，不能用错误的路径或不同键名让已有成果漏记。
- 非原生人形的双足单位不要把可更换武器烘焙进身体。接入读取实际装备，使用原生装备网格，并以 `wing_r` 的真实掌心跟随右臂动作；每次距离模型改变重新计算位置。缓存按装备真实编号、类型与图标刷新，不能只按对象引用判断，因为原生装备池会复用对象。遵循原生浸水隐藏规则；法杖和长矛已游戏实测，其他装备与攻击动作分别检查。
- 施工阶段的 `site_...@0` 等模型是 Worldfall 创建的状态副本。来源检查不能只查完整名字或对象引用；应核对副本部件与已导出基础施工模型的坐标、面、颜色槽和状态显隐，避免把正确副本误判为回退模型。
- 临时测试场地修改 Worldfall 地形缓存后，`TerrainCache.MarkChanged(x0,y0,x1,y1)` 要传区域两角坐标，右下角为不包含的终点，不是宽高。地面与水面切换后核对真实绘制已刷新；异常台阶或旧水面不能当作模型验收背景。

## 国家色区域

### 人物曲面与地下坑腔补充（2026-10-19）

人物面部、肩颈和四肢需要柔和曲面时，既要调整真实截面和衔接，也要把最终顶点法线写入模型的`Nrm`与GLB的`NORMAL`。只在Blender勾选平滑没有用；当前通用构形工具默认按三角面写法线，本物体若改平滑，应在自己的构形流程中保存，并在新进程实导后核对JSON与GLB的实际法线一致。金属硬边、王座和其他不相关模型继续保留各自约定。

地面深坑以Z=0为地面，负Z内壁及封底，上方开放。各距离和状态共用明确的坑口与坑底参数，不能整体抬高做成盆或山洞。普通地表会遮住负Z；当前仅斯卡文疫巢采用`WorldfallGroundPits`压低显卡上传副本，原地图高度、模型锚点、碰撞与寻路保持原样。坑缘必须盖住实际格点插值的坡面，实际上传数据与最终GLB一起复现查看。参数、恢复和检查方法见[第0阶段约定](../../Doc/修仙贴图三维化/第0阶段-Worldfall接口与模型规范.md)。离线复现不能代替用户游戏验收。

## 花草透明叶片交付
