# pixel_text：字符矩阵逐像素绘制

画像素图 = 写一个 txt（调色板 + 矩阵），渲染交给 `Scripts/pixel_text.py`。改图 = 改文本。所有迭代都在文本层面，往返像素级无损。只依赖 pillow，命令一律从仓库根运行。

## 命令

```bash
# 图 → 矩阵（自动生成颜色映射；不透明色超 56 种自动量化，--colors 可限制）
python Scripts/pixel_text.py to-text 图.png -o 图.txt [--colors 24]

# 矩阵 → 图（--scale 用最近邻整数放大导出）
python Scripts/pixel_text.py to-image 图.txt -o 图.png [--scale 4]

# 预览：默认 8 倍放大，输出 <名字>.preview.png（渲染后必须看）
python Scripts/pixel_text.py preview 图.txt
```

## 格式速查

```text
# 注释行以 # 开头
palette:
  . = transparent        # 按约定 . = 透明
  K = #1a1c1c            # 支持 #rgb / #rrggbb / #rrggbbaa / transparent
  W = #f8f4e8
grid:
KKKKKKKK
KWWWWWWK
KKKKKKKK
```

- 一个字符 = 一个像素；矩阵行数 × 行宽 = 图片高 × 宽，任意分辨率；
- 可用字符（防混淆集，共 57 个）：`.`、`a-z`（不含 l o）、`A-Z`（不含 I O）、`2-9`；**大小写敏感**；
- palette 段每个字符只能定义一次；grid 段每行**顶格、等宽**，行内字符必须都在 palette 里定义过；
- 校验报错带文件名和行列号，照着修即可。

## 画新图的工作流

1. 定尺寸和色板（像素画建议 ≤ 24 色、≤ 64px，色多必乱）；在文件头注释写下目标尺寸；
2. 手写 txt：先铺背景/轮廓字符，再逐行画主体；写 `palette:` 时想到换色可能性就用独立字符（比如高光、描边各占一个字母）；
3. `to-image` 渲染 + `preview` 出放大图 → **必须用看图工具自检**：剪影是否可读、轮廓是否闭合、有没有意外的透明洞、行有没有错位画歪；
4. 改矩阵/改调色板 → 重渲染 → 再看图。迭代 2~3 轮仍不满意就把预览图给用户看。

小例子（4x4 红点）：

```text
palette:
  . = transparent
  R = #d04030
  W = #f0f0f0
grid:
....
.RR.
.RR.
....
```

最容易犯的错是**行宽不一致**（比如某行多写或少写一个字符）——写的时候逐行数清楚，工具校验报错会直接给出行号和两行的宽度。

## 改现有图 / 换色

- **看一张现有像素图的构成**：`to-text` 导出，直接读矩阵；
- **改内容**：to-text → 改矩阵字符 → to-image；
- **换色**：只改 palette 里的色值，矩阵不动（一套矩阵多种配色变体的标准做法）；
- **加细节**：palette 加一个新字符（如 `F = #58c8f0`），再把矩阵里想要的像素改成它。

## 红线

1. 渲染后**必须看图**再交付，不许只看命令成功就完事；
2. 不要直接编辑工具生成的 PNG——所有修改回到 txt 再渲染；
3. 手写超过 64px 的矩阵不现实：大图从现有位图 `to-text` 导入再改，或分块让用户确认；
4. 矩阵行千万保持等宽——写完用校验报错（如果报了）逐行核对；
5. 交付到 `GameResources/` 前先确认目标路径的命名惯例（参考仓库 AGENTS.md），平时练习/迭代输出放 `Temp/`。
