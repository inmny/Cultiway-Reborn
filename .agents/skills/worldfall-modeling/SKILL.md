# Worldfall 单位与建筑建模

交付可追溯的模型：原始贴图、清晰参考图、真实三维初稿、减面候选和逐项检查结果。参考图漂亮、生成成功、文件导出正确、保形通过和游戏验收通过是不同结果，分别记录。

先读[建模约定](../../../Scripts/Worldfall/建模约定.md)。需要执行具体流程或处理失败时，读[建模流程与经验](../../../Doc/修仙贴图三维化/建模流程与经验.md)；只加载其中与当前阶段有关的章节。本技能属于 Cultiway 仓库，用户后续的范围与偏好优先。

## 开始一批模型

- 明确资产 ID、版本和本轮交付阶段。当前安排是先完成模型，再统一进行游戏测试；实验候选留在 `Art/Worldfall/`，游戏验收保持 `pending`。
- 本项目每个物体交给一个独立建模子代理，每批最多三个，子代理不再派生。同一物体的修正交回原代理；只提供该物体的原图、结构、参考图、初稿、预算和导出约定。
- 主代理统一版本、任务范围、面数参照和检查包。Trellis 使用现有显卡任务锁逐个运行，Blender 检查渲染使用 CPU。
- 从 `GameResources/`、资产注册代码、`Art/Worldfall/Seeds/<资产ID>.json` 核对外观、占地、原部件和颜色槽。原版资源优先查 `.GameSource/Assets`；缺失时记录，不凭名称猜造型。

## 从原图到初稿

1. 实际查看原图。标注部件数量、位置、开口、颜色、国家色和不可见部分；用 Blender 比例底模固定地面范围、深度、相机和遮挡关系。
2. 使用可用的 imagegen 技能与工具清晰化原图，原图负责外观，底模负责几何。保持原视角、轮廓、主要颜色与结构，不在参考图提示词里提前限制面数。图像编辑按原图和底模提供实际参考。
3. 对齐时只等比缩放和平移，不分别拉宽拉高。保存轮廓叠加与关键部件检查。本项目参考图目标为轮廓重合至少90%；一个像素容差内覆盖是另一项指标，不能代替它。未通过的图只能明确作为实验输入。
4. 检查视图来自同一个底模或固定网格。当前本机 Trellis 入口只接收一张完整单物体图，不能把正侧背拼图当成多视图输入；背面补全和厚度假设另记。
5. 核对 `Scripts/Worldfall/trellis-config.json` 和[运行说明](../../../Scripts/Worldfall/Trellis使用.md)，选未使用的版本实际生成。保存输入、参数、校验值、原始 GLB、UV、PNG 与 `source-locked.blend`，不覆盖初稿。

## 修正与保形减面

- 先检查初稿是否已错：背景板、纵深、开口、部件缺失属于生成问题。必要的局部修正另存 `source-corrected.blend`，展示修正前后；不能把修正后的形态说成原初稿本来如此。
- 从 Worldfall 面数报告选2–3个相关模型，先写近中远预算及理由。初稿面数和旧低面预览都不是通用预算。
- 保留本物体的真实初稿体量。重要孔、薄框、屋檐、冠饰、根须、脸、手脚和衣摆优先保护；基础几何可作比例底模，不能整体替换初稿并宣称保形减面。
- 静态建筑可先整体减面再归回部件，避免按细碎颜色切开后无法继续减面；人物保留真实动作关节和父子关系。
- 面数停滞时先查断开的碎片、贴图接缝复制点、薄壳和异常接触，不反复猜减面比例。体素重建只是一种可选准备手段，尺度由孔宽和薄件决定，不固定套用1/512。
- 准备网格另存并对修正高面来源检查。近中远分别从同一个固定来源制作；最终误差也对修正高面来源计算，不能改用已经变形的准备网格来提高分数。
- 每个新候选应针对已见缺陷并有停止依据。预算与保形无法兼得时，保留失败版本和较完整的候选，标明超预算或失形，不再无依据试参数，也不事后抬高通过线。

## Worldfall 适配与离线检查

- 坐标为 X左右、Y前后、Z向上，正面为-Y。建筑台基宽度归一为1，深宽关系按注册数据；不要拉宽棺体或新增台基来填满占地。单位脚底与明确的悬浮间距分别记录。
- 保留原部件名称、父子关系、转动轴、颜色槽前缀及状态名称。人物动作可参考原版人类的姿态关系，但须适配本物体真实关节；非人形保留自身骨架。
- 国家色按本物体原图和已确认分区处理：文明木构瓦顶变色，墙柱梁为固定木色；人物国家衣料与肤色分开。诡族保留浅绿中式风格，基础住宅是敞开空棺。紫色不能一概当国家色；本轮三个群系建筑为固定配色。
- 原 UV/PNG 保留，颜色按真实表面重投射。每个模型总颜色槽最多64，包含原槽前缀；几何指标不能证明符文、脸纹等逐面颜色细节保持完整。
- 检查最终三角面数、有效索引、有限位置、单位法线、颜色槽、父子与轴。分别列出参考图、预算、保形、关键部件、颜色细节和游戏状态的结果。
- 保存后用新的 Blender 进程重开，实际导入导出的 GLB/FBX，核对几何、UV、颜色和法线。预览从最终重开文件渲染，实际看正、侧、背、俯视和近中远图；只校验散列不能替代这些检查。
- 实验阶段写 `models.candidate.json`。共享类的 `Asset.export()` 默认写 `Content/Worldfall/Models/<资产ID>/models.json`；候选必须显式传入 `output_path`，例如 `Art/Worldfall/<资产ID>/shape-preserving-v<版本>/models.candidate.json`，模型与检查记录随之写到候选目录。没有显式候选路径的调用不能当作预览操作。

## 交付与后续

按物体整理四阶段文件和同相机对照，附可编辑来源、三档模型、预算、实测、重开结果、限制及日志。汇总简表的 `inspection_files` 记录 `original`、`reference`、`raw_preview`、`candidate_front` 四个实际路径，均相对本物体的 `Art/Worldfall/<资产ID>/`；`source_glbs` 与 `editable_sources` 同样使用本物体内的相对路径。原图用最近邻等比放大，其他图保持可比尺度；检查页链接须实际存在。

显存采样报告整卡峰值、背景范围和近似增量，不能把整卡数值当作进程独占值。本机量化512成功不能证明官方实现或1024档能运行。

生产替换按当前授权范围和实际检查结果执行；文件一致性通过不等于游戏效果通过。统一游戏验收时使用 `debug` 技能，检查无遮挡场景、有效截图、动作、近远景、状态、国家色、交互与可选 Worldfall 依赖；每项无实测仍记待验收。

本轮实测与例外见[三个样板执行记录](../../../Doc/修仙贴图三维化/参考图一致性与保形减面/2026-10-12-三个样板执行记录.md)。临时脚本仅作实现参考，先核对它们固定的资产、版本和输出路径，不直接当全资产通用工具。
